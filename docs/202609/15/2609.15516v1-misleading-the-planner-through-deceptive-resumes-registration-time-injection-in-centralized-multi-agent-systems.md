## 摘要
基于集中式 LLM 的多智能体系统（MAS）通过注册新的工作智能体来扩展其功能；这些工作智能体的描述会被规划器读取，以决定任务如何分解、由哪个工作智能体执行每个子任务，以及每个子任务需要什么。第三方描述由系统外部编写，却被规划器信任，从而形成了一条注册时注入通道。该载荷在任何用户指令到达之前就被植入，以规划器为目标，并通过生成的计划传播到良性工作智能体；即使这个精心构造的工作智能体从未被分配子任务或从未被调用，它也能生效。我们定义了四个工作智能体描述字段：功能、输入规范、输出规范和使用约束。在来自三个公开智能体市场的 32,000 条描述中，大多数省略了输入规范和使用约束，而至少 23.35% 包含这些字段之外的内容。我们构建了八种针对任务分解、能力锚定和子任务规范的描述操纵攻击策略，并在 GAIA 上对其进行评估。在最严重的情况下，单条被操纵的描述会使任务成功率从 84.31% 降至 37.25%，或使 token 消耗或执行时间增加超过 111%，而用户目标保持不变，工作智能体也忠实地执行生成的计划。这些影响在两种 MAS 实现、六种规划器 LLM、四种 LLM 评估器以及来自三个市场的真实描述中持续存在。我们进一步提出 DescGuard，一种注册时防御方法，它在描述到达规划器之前仅保留工作智能体范围内的接口信息。DescGuard 在不修改工作智能体实现、规划器或编排逻辑的情况下，将受影响的规划指标和下游性能恢复到其基线水平，并可与现有的隔离、权限控制和运行时机制组合使用。

## Abstract
A centralized LLM-based multi-agent system (MAS) extends its functionality by registering new worker agents, whose descriptions are read by the planner to decide how a task is decomposed, which worker executes each subtask, and what each subtask requires. Third-party descriptions are authored outside the system but trusted by the planner, creating a registration-time injection channel. The payload is planted before any user instruction arrives, targets the planner and propagates through the generated plan to benign workers, taking effect even when the crafted worker is never assigned a subtask or invoked. We define four worker-description fields: functionality, input specification, output specification, and usage constraints. Among 32,000 descriptions from three public agent marketplaces, most omit input specifications and usage constraints, while at least 23.35% contain content outside these fields. We construct eight description-manipulation attack strategies targeting task decomposition, capability grounding, and subtask specification, and evaluate them on GAIA. In the most severe cases, a single manipulated description reduces task success from 84.31% to 37.25%, or increases token consumption or execution time by over 111%, while the user objective remains unchanged and workers faithfully execute the resulting plan. These effects persist across two MAS implementations, six planner LLMs, four LLM evaluators, and the real-world descriptions from three marketplaces. We further propose DescGuard, a registration-time defense that retains only worker-scoped interface information before descriptions reach the planner. DescGuard restores the targeted planning metrics and downstream performance toward their baseline levels without modifying worker implementations, the planner, or the orchestration logic, and composes with existing isolation, permission-control, and runtime mechanisms.

# 论文总结：通过欺骗性“简历”误导规划器——集中式多智能体系统中的注册时注入

## 1. 核心问题与研究动机

- **背景**：集中式 LLM 多智能体系统（MAS）通过注册新的 worker agent 来扩展能力，规划器（planner）依据每个 worker 的自然语言描述来决定：任务如何分解、子任务分配给谁、每个子任务需要什么。
- **核心矛盾**：worker 描述由**系统外部的第三方**撰写（如 Google Cloud Marketplace、AWS Marketplace、GPT Store 等），却被规划器**当作可信的规划输入逐字读入**，未经清洗或与规划器自身指令分离。即“以文档形式书写，却以指令形式被消费”。
- **新攻击面**：这构成一条**注册时注入（registration-time injection）通道**——载荷在任何用户指令到达之前就被植入，一次注册可影响后续所有用户请求。
- **与既有 prompt injection 的关键差异**：
  - 载荷在用户请求之前植入，而非污染单次会话；
  - 攻击目标是**规划器**而非单个 worker；
  - 影响通过**生成的计划**传播，在首次 agent 间通信之前就已到达良性 worker；
  - 该通道位于隔离、沙箱、权限控制、运行时监控等**执行期防御的上游**，这些机制都不会检查计划。
- **攻击成立的极端条件**：被注入的 worker **无需被分配子任务、无需被调用**，损害由良性 worker 忠实执行被污染的计划造成。

## 2. 方法论

### 2.1 系统建模与计划的解析表示

- 将集中式 MAS 形式化为 $\pi = p(x, D)$，其中 $x$ 为用户请求，$D$ 为规划器可见的 worker 描述集合，$\pi$ 为生成的计划。
- 将计划解析为元组 $\pi = (S, E, g, U)$：
  - $S$：子任务集合；$E \subseteq S \times S$：子任务依赖关系；
  - $g: S \to A$：子任务到 worker 的分配函数；
  - $U = \{u_s\}_{s \in S}$：每个子任务的执行规范。
- 据此归纳三个规划决策维度：**任务分解**（$S, E$）、**能力锚定**（$g$）、**子任务规范**（$U$）。

### 2.2 四字段接口定义（Worker Descriptions as Planning Interfaces）

借鉴软件接口声明组件功能与调用需求的方式，定义 worker 描述应提供的四类字段：

- **Functionality（功能）**：能做什么工作；
- **Input Specification（输入规范）**：接受何种形式的输入；
- **Output Specification（输出规范）**：产出何种形式的结果；
- **Usage Constraints（使用约束）**：使用条件（如网络连接、可访问路径）。

**现实测量**：从三个公开市场采样 32,000 条描述（GPT Store 20,000、Coze 8,000、Wenxin 4,000），用 LLM-as-a-judge 判定：

- 功能几乎都声明，但输入规范缺失 ≥89.73%、输出规范缺失 ≥74.82%、使用约束缺失 ≥94.61%；
- 至少 **23.35%** 包含四字段之外的内容（无边界能力宣称、直接对规划器说话等），说明恶意描述可轻易混入主流风格。

**两条处理原则**：

1. 内容的保留或丢弃应依据**它描述的是谁的行为**；
2. 重述后的描述应**只为其命名的 worker 说话**。

并强调：防御重点在于**移除接口之外的越界内容**，而非补全缺失字段（缺失字段会导致规划信息不足，但对抗者的立足点在于越界内容）。

### 2.3 八种描述操纵攻击策略

威胁模型：用户请求良性；规划器、底层 LLM、worker 实现、工具接口、系统提示、运行时配置均可信；攻击面仅限**一个** worker 的规划器可见描述，形式为 $d'_i = \tau(d_i)$（保留原功能内容，追加策略性引导内容）。

| 类别 | 策略 | 机制 |
|---|---|---|
| **任务结构化（3种）** | Under-Decomposition | 把紧凑分解说成必要，诱导合并本可分离的操作 |
| | Over-Fragmentation | 把小子任务说成更易执行，诱导拆分整合性操作 |
| | Dependency Disruption | 把反复校验说成必需，诱导冗余验证子任务、额外依赖与自检 |
| **能力锚定（2种）** | Over-Assignment | 把某 worker 说成广泛适用/高可靠，诱导过度分配 |
| | Agent Exclusion | 把某 worker 说成不可靠/不适用，诱导规划器回避它 |
| **子任务规范（3种）** | Overworking | 强调穷尽式探索，抬高子任务工作量 |
| | Intermediate Output Suppression | 抑制中间产物（如文件路径）回报要求，破坏下游信息传递 |
| | Planner Prior Misguidance | 强调先验解释，使规划器在证据收集前就锁定某种解读 |

### 2.4 DescGuard 防御

- 目标：在注册时把第三方描述**约束到四个接口字段**，且不判断原始描述是否恶意、不验证其与实现的一致性、不补全缺失信息。
- 变换记作 $\tilde{d}_i = G(d'_i)$，仅替换该 worker 的描述，其余 $d_j$ 不变；规划仍为 $\tilde{\pi} = p(x, \tilde{D})$。
- **三阶段流水线**：
  1. **确定性预处理**：Unicode 归一化、移除不可见字符、剥离残留 HTML/XML 标记；
  2. **强调中和（Emphasis Neutralization）**：处理全大写、标点、Markdown 标记、强调词，标点仅保留逗号/句号/冒号；
  3. **接口字段抽取（Interface-Field Extraction）**：仅保留描述该 worker 且映射到四字段的内容，丢弃规定规划器如何规划、其他 worker 如何行动、MAS 如何运行的内容；混合语句只保留接口部分；原描述未提供某字段则留空；
  4. **Worker 范围重述（Worker-Scoped Restatement）**：把面向调用者的要求改写为客观接口陈述；无边界能力宣称直接丢弃而非收窄。
- **配套机制**：每个 LLM 变换阶段配一个独立 LLM 验证器；对不可信文本使用**新生成的随机分隔符**包裹；验证失败则带原因重试，直到通过或达到重试上限；未通过验证的输出既不转发也不暴露给规划器。
- **非侵入性**：不修改 worker 实现、规划器模型、编排逻辑，无需重训练，可与既有隔离、权限控制、运行时机制组合。

## 6. 主要结论与发现

- **攻击有效性**：
  - **Agent Exclusion** 最严重：WebSurfer 参与率从 60.38% 降至 3.77%，任务通过率从 **84.31% 跌至 37.25%**（不足基线一半）；token 降 87.28%、时间降 42.26%，说明系统是“省略了必要检索”而非更高效。
  - **Dependency Disruption**：DVTR 从 4.72% 升至 48.54%（超 10 倍），token 增 **111.93%**、时间增 96.18%，通过率降 27.45%。
  - **Over-Fragmentation**：AST 从 2.00 升至 6.30（+215.00%），执行时间增 **111.98%**，通过率降 15.68%。
  - **Over-Assignment**：TerminalManager 的 APR 从 1.89% 升至 13.21%，AMR 从 0% 升至 57.14%（过半分配超出其功能范围），通过率降 11.76%。
  - **Overworking**：EER 从 39.62% 升至 54.40%，token +34.57%、时间 +38.86%，通过率降 17.64%。
  - **Intermediate Output Suppression**：MIRR 从 19.61% 升至 55.56%，成本几乎不变，但通过率降 11.76%（信息传递被破坏）。
  - **Planner Prior Misguidance**：VCR 从 10.38% 升至 18.58%，成本反而下降，

但通过率仍下降（约 −11.76%），说明规划器在证据收集前锁定解释虽降低了探索成本，却以牺牲正确性为代价。
  - **Under-Decomposition**：AST 下降、依赖被压缩，通过率下降，表明合并本可分离的操作会掩盖中间错误、降低可调试性。
  - **共性规律**：八种策略均能在**不改变 worker 实现、不被调用**的前提下显著扰动规划器行为，且成本变化方向不一（有的暴增、有的骤降），因此**单纯以成本指标监控无法可靠识别攻击**。

### 6.2 防御有效性

- **攻击影响被显著抑制**：在 Over-Fragmentation、Agent Exclusion、Overworking 三个代表性策略上，启用 DescGuard 后各规划指标（AST、APR、EER 等）与通过率均向 Baseline 明显回归。
  - Over-Fragmentation：AST 从 6.30 回落到接近 2.00；
  - Agent Exclusion：WebSurfer 参与率与任务通过率基本恢复至基线水平；
  - Overworking：EER 回落至基线附近。
- **防御开销有限**：在干净描述下启用 DescGuard（Defense Overhead 组），规划指标与通过率与 Baseline 基本持平，token 与时间仅有小幅波动，说明约束接口字段并未破坏正常规划所需信息。
- **健壮性**：由于 DescGuard 采取"越界即丢弃"而非"判断恶意"，它对未见过的操纵表述具有先天泛化性；独立验证器 + 随机分隔符的组合进一步降低了防御自身被二次注入的风险。
- **非侵入性得到验证**：无需改动 worker 实现、规划器模型或编排逻辑即可生效。

### 6.3 泛化性

- **规划器无关**：在 6 种规划器 LLM（DeepSeek-V3.2、GPT-5、GPT-5-mini、Kimi-K2.5、Qwen3-Max、GLM-4.6）上，攻击引起的指标偏移方向一致，说明该攻击面源于"描述即规划输入"的架构范式，而非某个模型的特定缺陷。
- **评估器无关**：4 种 LLM 评估器（qwen、kimi、gpt-5、glm）交叉判定下，受影响指标的相对方向保持一致。
- **描述来源无关**：用三个真实市场（GPT Store、Coze、Wenxin）的实际描述替换人工撰写描述后，攻击仍有效，说明该通道在真实生态中可达。
- **MAS 实现无关**：在 OWL（基于 CAMEL）上复现三种代表性攻击，效果与 AutoGen 一致，表明结论不依赖特定编排框架。

### 6.4 案例研究

- 在"BERT 与 Transformer 编码器层数差"任务中，论文给出完整计划输出对比：被操纵描述下，规划器生成了明显偏离事实核查需要的分解与规范（如锁定先验解读、跳过必要检索），而启用 DescGuard 后计划回归合理结构。该案例直观展示了"污染在计划层传播、在通信前生效"的链条。

## 7. 论文贡献

1. **提出并刻画新攻击面**：将"第三方撰写的 worker 描述被规划器逐字消费"识别为**注册时注入**通道，明确其区别于会话内 prompt injection 的三个特征（前置植入、目标为规划器、计划层传播）。
2. **形式化规划接口**：用 $(S, E, g, U)$ 三元规划决策（任务分解、能力锚定、子任务规范）与四字段接口（功能、输入规范、输出规范、使用约束）建立分析框架，并以 32,000 条真实市场描述量化"接口越界"的普遍性。
3. **系统化攻击分类**：给出覆盖三个规划维度的八种描述操纵策略，并在真实 MAS 上量化其规划层与执行层后果。
4. **提出轻量防御 DescGuard**：以"约束到接口字段 + 范围重述 + 验证器"的非侵入方式在注册时阻断越界内容，兼顾有效性与低开销。
5. **多维度泛化验证**：跨 6 种规划器、4 种评估器、3 个真实市场、2 种 MAS 框架验证结论稳健性。

## 8. 局限性

- **注入源单一**：攻击实验固定以 PostgresManager 为唯一注入点，未系统研究不同 worker、注入位置或多 worker 协同注入的影响。
- **防御覆盖不全**：防御评测仅覆盖 8 种攻击中的 3 种，其余策略的防御效果未报告。
- **统计严谨性不足**：未披露 GAIA 任务子集规模、运行次数与置信区间；部分百分比变化较小，可能落入噪声范围。
- **评价器依赖**：多数规划指标由 LLM-as-a-judge 给出，作者亦承认其仅宜作相对比较，绝对数值可靠性有限。
- **缺乏横向对比**：未与 ACE、ToolHijacker 等既有元数据操纵攻击，以及 StruQ、SecAlign、IsolateGPT、SAGA、AgentSentinel、AttriGuard 等防御做定量对比，横向可比性受限。
- **算力与成本信息缺失**：未报告硬件、调用规模与推理成本，复现与效率评估受限。
- **防御边界**：DescGuard 只清除接口外内容、不验证描述与实现一致性，因此"在接口字段内部撒谎"（如夸大功能、虚构输入格式）仍是其设计上不覆盖的残余风险。

## 9. 启示与意义

- **架构层面**：只要第三方描述被当作规划器的可信输入，注册环节就是独立于执行期防御的**上游信任边界**；仅靠沙箱、权限控制与运行时监控无法覆盖计划生成阶段。
- **防御原则**：与其尝试判断"是否恶意"，不如以**接口契约**约束"描述可以说什么"——内容取舍应依据"它描述的是谁的行为"，重述结果应"只为它命名的 worker 说话"。
- **实践建议**：市场/平台方应在注册时对描述做字段化归一与越界内容剥离；系统方应将 worker 描述与规划器自身指令**显式分离**（如结构化字段、随机分隔符包裹），并保留可审计的规划日志以便追溯污染路径。
- **后续方向**：多注入点与多 worker 协同攻击、接口字段内部的虚假声明检测、防御与执行期机制的联合评估，以及更大规模、带统计检验的基准评测。
