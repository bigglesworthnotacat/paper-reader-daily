## 摘要
智能体技能为冻结的语言模型智能体提供了一种轻量级的方式，以装备领域知识和程序性指导，然而获取高质量技能仍然成本高昂且难以扩展。专家编写的技能需要大量人力。最近的技能自进化方法自动化了一个迭代循环，利用执行反馈来修订技能，但其启发式更新策略往往导致不稳定的优化和低迭代效率。我们识别出实现稳定且高效的技能自进化所面临的两个挑战。方向稳定性要求有效修正能够累积，而非被迭代局部的反馈所覆盖。更新自适应性要求每次修订的范围反映近期案例级改进的一致性。我们引入了SkillAdam，一个受Adam启发的框架，用于优化离散且不可微的技能文档。作为Adam一阶矩的功能类比，优化记忆记录了已识别的问题和先前解决方案尝试的结果，以稳定更新方向。作为Adam二阶矩的功能类比，波动驱动的编辑预算跟踪近期案例级改进的历史加权变化，并自适应地控制更新幅度。在覆盖短期和长期任务的七个基准中，SkillAdam以更稳定的优化动态实现了最先进的性能。它还在显著更少的优化迭代和更低成本的情况下获得更强的技能，相较于先前方法。代码仓库：https://github.com/ruc-datalab/SkillAdam

## Abstract
Agent skills provide a lightweight way to equip frozen language-model agents with domain knowledge and procedural guidance, yet obtaining high-quality skills remains costly and difficult to scale. Expert-written skills require substantial human effort. Recent skill self-evolution methods automate an iterative loop that uses execution feedback to revise skills, but their heuristic update strategies often yield unstable optimization and low iteration efficiency. We identify two challenges in realizing stable and efficient skill self-evolution. Direction Stability requires effective corrections to accumulate rather than be overwritten by iteration-local feedback. Update Adaptivity requires the scope of each revision to reflect the consistency of recent case-level improvements. We introduce SkillAdam, an Adam-inspired framework for optimizing discrete and non-differentiable skill documents. As a functional analogue of Adam's first moment, an optimization memory records identified problems and the outcomes of prior solution attempts to stabilize the update direction. As a functional analogue of Adam's second moment, a volatility-driven edit budget tracks the history-weighted variation of recent case-level improvements and adaptively controls the update magnitude. Across seven benchmarks that span short- and long-horizon tasks, SkillAdam achieves state-of-the-art performance with more stable optimization dynamics. It also obtains stronger skills with substantially fewer optimization iterations and lower cost than prior methods. Code repository: https://github.com/ruc-datalab/SkillAdam

## 一、论文的核心问题与整体含义

- **问题背景**：LLM 智能体在解决复杂实际任务（如网页交互、旅行规划、数据分析）中已有广泛应用，但在领域特定场景中，其通用能力难以满足长尾需求。为解决此问题，Anthropic 提出 **Agent Skills（智能体技能）**，即将指令与配套资源打包为模块化知识，用来增强智能体在特定领域的能力，而无需训练模型参数。
- **核心痛点**：尽管技能质量对智能体表现至关重要，但**高质量技能的获取成本极高**——专家人工编写非常耗时，而直接用 LLM 生成未经打磨的技能往往无效。
- **已有多数方案的问题**：现有技能自进化（skill self-evolution）方案（如 SkillAxe、SkillOpt 等）虽能自动迭代修订技能文档，但几乎全部依赖启发式规则，缺乏可靠的“改什么”（What to revise）和“改多少”（How much to revise）的控制机制，导致优化不稳定、迭代效率低。
- **SkillAdam 的思路定位**：将随机优化中的 **Adam（自适应矩估计）优化思想**功能移植到离散、不可微的技能文档优化空间，从而为技能自进化提供稳定的优化方向与自适应的更新幅度。

## 二、论文提出的方法论

### 核心思想：Adam 与离散技能空间的“功能性类比”

- 在 Adam 中，**一阶矩（m）** 用来累积历史梯度以稳定更新方向，**二阶矩（v）** 用来估算梯度数量的量级进而自适应缩放步长。SkillAdam 将同样的角色分配给两个离散技能空间的新组件：
  - **优化记忆（Optimization Memory）**：以 **Evolving Issue Tracker（EIT，演化式问题追踪器）** 落实，功能对齐 Adam 的一阶矩，用来跨迭代累积问题与历史尝试结果，稳定“修改方向”。
  - **波动驱动的编辑预算（Volatility-driven Edit Budget）**：跟踪近期案例级改进的离散度并控制后续修改幅度，功能对齐 Adam 的二阶矩，提供“自适应步长”。

### 关键技术细节

- **初始技能构建（Trajectory-Informed Initialization）**：先做若干次热身 rollout，利用执行轨迹与评估反馈生成一个较合理的初始技能，避免从全空或纯随机状态出发。
- **Evolving Issue Tracker（EIT）**：
  - EIT 维护一个结构化的 issue 列表：每个 issue 包含错误模式（pattern）、当前状态（status）和历史尝试（含结果的 prior solution attempts）。
  - 在每一轮候选技能评估后，通过基于 LLM 的更新函数 `UEIT` 对 issue 记录进行演化：合并已有 failure、新建 issue、记录尝试及效果，并在同类错误再出现时重新打开 issue。通过避免重复修正同一处问题，有效维持**方向稳定性**。
- **Volatility-driven Edit Budget（波动驱动的编辑预算）**：
  - 计算当前批次中，候选技能相对当前技能在每个 case 上的得分差异：
    δt,i = s(Eval[t,i]) − s(Eroll[t,i])
  - 计算该批次的方差（数据不充分时归零），并用指数滑动平均形式累积：
    Vt = β2·Vt−1 + (1 − β2)·V̂t
  - 将 Vt 映射为下一次迭代的编辑预算 σt，波动高 → 缩小修改范围，波动低 → 放宽修改预算。通过此机制实现**更新自适应**，避免宽泛修改覆盖有效约束。
- **技能更新流程**：
  在每一轮迭代中，当前技能 S(t−1) 在一个采样 mini-batch 上做 rollout，得到轨迹 Tt 与评估反馈 Froll。LLM patch Generator 根据「当前技能 + 轨迹 + 反馈 + EIT 记忆 + 编辑预算」生成候选补丁（SkillPatch gt），并只对当前技能施加小规模修改，从而得到候选技能 S̃t。
  随后在**同一批任务**上评估候选技能；若通过**基准特定的多指标接受门控（acceptance gate）**，则替换当前技能，否则保持原状。
- **显式的 Adam 对应关系表**（论文内 Table 1）：
  - 参数 θ → 当前技能
  - 批量损失 → 当前技能反馈
  - 梯度 → LLM 生成的语言空间 patch

  - 二阶矩 → 历史波动估计

## 三、实验设计

## 六、论文的主要结论与发现

- **核心结论**：
  1. 使用 Evolving Issue Tracker（优化记忆）可显式积累有效的历史修正，防止跨迭代覆盖问题，带来更稳定的更新方向。
  2. 使用 Volatility-driven Edit Budget 这种“语言空间的自适应学习率”，比固定相同批次的启发式均匀修订更稳健。
  3. 相较 SkillOpt 等最先进基线，SkillAdam 在短、长周期任务上均取得了最佳或并列最佳；在困难的长周期任务上差距尤其明显（DP-Travel 从 1.7% → 11.7%）。
  4. 训练成本（token 与请求数）相比 SkillOpt 约下降三分之二，以相当大的 Margin 高于性价比，同时不牺牲最终技能质量。
  5. 跨模型泛化效果更优：从 GPT-5.5 迁移到 GPT-5.4-mini 时，SkillAdam 在多数数据集保留更多任务性能（平均保留率 81.3% vs 76.2%）。
  6. 裁判模型技能质量评分上，SkillAdam 在全部 10 个评估切片中一致性优于 SkillOpt，平均分从 3.30 升到 3.88，二者不仅产出最终测试指标更高，技能文档本身也更可读可用。

## 七、优点

- **方法论启发式强**：将连续参数优化中的“梯度矩估计、方向整流、步长自适应控制”高效桥接到离散文本技能空间上，思想新颖但迁移逻辑一目了然，解释性好。

- **开源承诺**：提供完整代码仓库（GitHub），利于后续学者复现与扩展。

  技能质量的裁判模型打分是将六个维度汇总后展示，没有区分如“可操作性增强”或“认知负荷降低”具体是由哪个模块带来；裁判模型同样是 GPT-5.5，存在评分偏好偏置风险。
- **缺陷六：对边际任务与伦理安全边界讨论不足**
  旅行子任务的纯 0% 基线说明该子域极为难；SkillAdam 在此类“学习信号极其稀疏”的任务中表现出最优者偏差能有多大？长时间演化文档是否会引入有害指令或注入风险？文中没有讨论相关的限制与护栏。
- **缺陷七：算力统计不传统**
  全文没有包含 GPU 型号、数量、总机时等标准算力信息，只报告 API token 消耗；对于非 API 化本地部署或需要长期大规模训练的团队，成本可转移性较低。
