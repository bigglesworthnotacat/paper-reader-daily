## 摘要
自我进化智能体通过优化其“控制框架”——提示、技能、工具和执行逻辑——基于环境反馈，向自主性迈进。然而，这一范式受到三个挑战的阻碍：	extit{信用分配失败}，即最终成功/失败的反馈使得难以确定是哪一步导致了错误；	extit{捷径学习}，即智能体记忆任务特定模式而非获得可泛化的能力；以及	extit{灾难性遗忘}，即无保护的更新会降低先前获得的能力。在本文中，我们引入了HarnessEvolve，一个从参考轨迹中学习以实现可靠的智能体自我进化的自我进化框架。HarnessEvolve将执行智能体与进化流程解耦，将执行、评估、优化和门控分配给独立的智能体模块，从而实现可泛化和稳定的控制框架改进。具体而言，HarnessEvolve通过生成参考轨迹（在给定真实答案时产生的执行路径）并将失败执行与参考轨迹对齐以提取错误信号，从而克服信用分配失败，并对这些错误信号进行聚类以揭示系统性失败模式。为防止捷径学习和灾难性遗忘，候选控制框架更新必须通过两道门控：一道质量门控用于过滤数据泄漏和提示膨胀，一道性能门控用于在当前批次上有所改进且不降低近期批次性能时接受每次更新，并在保留集上于epoch结束时进行验证以选择性能最佳的已接受智能体快照。我们在涵盖开放领域和企业场景的多个基准上，使用不同模型和智能体框架进行了广泛实验。结果表明，HarnessEvolve在所有基准和设置中均持续优于最先进的基线，证实了其跨任务领域的可靠性。

## Abstract
Self-evolving agents advance toward autonomy by optimizing their harness---prompts, skills, tools, and execution logic---based on environmental feedback. This paradigm, however, is hampered by three challenges: \textit{credit assignment failure}, where terminal success/failure feedback makes it ambiguous which step caused the error; \textit{shortcut learning}, where agents memorize task-specific patterns rather than acquire generalizable capabilities; and \textit{catastrophic forgetting}, where unguarded updates degrade previously acquired competence. In this paper, we introduce HarnessEvolve, a self-evolving framework that learns from reference trajectories to achieve reliable agent self-evolution. HarnessEvolve decouples the execution agent from the evolutionary pipeline, assigning execution, evaluation, optimization, and gating to independent agent modules, enabling generalizable and stable harness improvements. Specifically, HarnessEvolve overcomes credit assignment failure by generating reference trajectories (execution paths produced when given the ground-truth answers) and aligning failed executions against them to extract error signals, which are clustered to reveal systematic failure patterns. To prevent shortcut learning and catastrophic forgetting, candidate harness updates must pass two gates: a quality gate that filters data leakage and prompt bloat, and a performance gate that accepts each update if it improves on the current batch without degrading recent batches, with epoch-end validation on a held-out set selecting the best-performing accepted agent snapshot. We conduct extensive experiments on several benchmarks spanning open-domain and enterprise scenarios, using different models and agent frameworks. Results demonstrate that HarnessEvolve consistently outperforms state-of-the-art baselines across all benchmarks and settings, confirming reliability across task domains.

### 二、论文提出的方法论

#### 核心思想

- 将执行智能体与进化流程分离开来，由四个独立的智能体模块协同工作：
  - **执行（Execution）**：执行智能体（Aexec）是优化目标，基于当前 Harness 运行训练任务。优化前，对每个训练查询同时提供问题和**真实答案（ground-truth answer）**，让 Aexec 最多尝试 Tatt 次，产生能够通向正确答案的执行路径——即参考轨迹。
  - **评估（Evaluation）**：评估智能体（Aeval）完成双重职责：
    - 在优化批次中评估 Aexec 的任务准确率，并识别失败轨迹作为后续诊断输入；
    - 校验生成的参考轨迹是否“真实过关”（genuine），即确实遵循了合理的推理链条、正确调用了工具、处理了中间观察，而非直接把给出的答案作为输出；只有通过校验的轨迹才能计入参考轨迹缓存 C。
  - **优化（Optimization）**：优化智能体（Aopt）对比失败轨迹与参考轨迹，生成结构化错误信号，再实施错误聚类，找出系统性失败模式，生成修改控制框架的候选更新。
  - **门控（Gating）**：门控智能体（Agate）对所有候选更新做质量与性能两道检查，防止数据泄漏和性能回退。
- 通过“参考轨迹对比”解决信用分配失败，通过“质量门”防止捷径学习，通过“性能门 + epoch 末验证”缓解灾难性遗忘。

#### 关键技术细节

1. **轨迹对比（Trajectory Comparison）**
   - 给定失败轨迹 τ⁻、查询 qi 和验证过的参考轨迹 τ⁺（若该任务有参考轨迹），Aopt 生成结构化错误信号 Fi = (si, mi, hi)，其中 si 为严重度、mi 为错误原因（如工具幻觉、参数遗漏、过早终止等）、hi 为自然语言修复提示。
   - 当参考轨迹可用时，Aopt 可识别出参考与失败轨迹的**第一个动作分歧点（first divergence point）** t*，把早期动作分歧作为根本原因（root cause），后续分歧视为级联效应而非新问题。
   - 当参考轨迹缺失时，则退化为仅基于失败轨迹的单独分析（无分歧点定位）。

2. **错误聚类（Error Clustering）**
   - 按错误原因 mi 将错误信号 Fi 聚类为 P = {C1, … , CK}，每一组包含聚合严重度、共享错误原因、代表性失败轨迹和修复方向。
   - 聚类遵循三项原则：
     - **按原因分组（Cause-Based Grouping）**：不以粗粒度严重性标签聚类，保证同簇对应用一个修复策略。
     - **根因优先（Root-Cause Priority）**：有参考轨迹时，以第一个分歧点为错误根因进行聚类，避免将级联症状当成根因。
     - **长尾保护（Long-Tail Protection）**：不同于 K-Means 等强制样本归属的聚类法，聚类过程保留单样本簇，避免少数重要的失败模式被吸收进多数簇里。聚类在 Algorithm 1（附录）中形式化。

3. **候选生成（Candidate Generation）**
   - Aopt 基于聚类 P，优先处理故障实例更多、严重度更高的簇，针对根因生成涵盖**提示、技能、工具和执行逻辑**的整套 Harness 编辑，得到候选更新集合 Δharness。

4. **质量门（Quality Gate）**
   - 防止捷径学习：检查候选更新里是否存在**数据泄漏**（用 LLM-as-judge 对 Harness 文件打分，超过阈值 ηleak 则拒绝）和**提示膨胀**（新注入的上下文示例数超过阈值 ηblo 则拒绝）。
   - 被拒更新可带着原因 ρ 退回给 Aopt 做修订，修订次数到达上限 Trev 即放弃该更新。
   - 门控代理作为独立仲裁者与优化代理脱离，防止自我服务式评估。

5. **性能门（Performance Gate）**
   - 已验证的更新 Δverified 被构建为候选智能体 Acandidate。评估基于当前批次 B_j 与最近的 R 个批次（replay buffer），候选只有在当前批次提升幅度达到 δ，且最近批次不劣化超过容忍度 ϵ 时才会被接受（接受条件见公式 (1)）。
   - 接受后快照存入快照池 V，并作为当前活跃智能体 Acurrent；连续被拒达 Pbatch 次则提前终止 epoch。

6. **Epoch 末快照选择（Epoch-End Selection）**
   - 每个 epoch 处理完所有批次后，在验证集 Tval 上对快照池 V 中所有快照做评估，将最佳者设为 Acurrent 和 A*（见公式 (2)），从而确保最终 agent“不比快照池中最优快照差”。
   - 流程循环多个 epoch，满足最大 epoch 数 E 或验证集连续不提升达 Pep 个 epoch 时终止。

#### 算法流程（文字说明）

- **Algorithm 1（参考引导的错误诊断与聚类）**：对当前批次的每个失败例子，先从全局缓存 C 查对应参考轨迹；若有，则分析失败轨迹与参考轨迹识别根因分歧点；若无，则退化为无参考单轨迹分析；随后将所有错误信号聚类成 P。
- **Algorithm 2（HarnessEvolve 自我进化主过程）**：初始化 active agent 与快照池（含原始 Aexec），对每个 epoch：随机排列训练集并分批；每批依次执行、评估失败、诊断聚类、生成候选、质量门过滤（失败可修订 Trev 轮）、性能门评估并决定是否接受；满足 batch patient 则提前结束；end of epoch 在 Tval 上选最优快照更新当前 agent；最终按 Ttest 报告精度。完整 HarnessEvolve 流程见论文 Algorithm 2。

  - 在 Wireless-QA + DeepSeek-V4-Flash 上达 92.8%，超过最强基线 ACE 90.1% 2.7 个百分点；
  - 在开源数据上，SearchQA 由 Base 86.5% 提到 92.9%、OfficeQA 由 62.8% 提至 70.9%、SpreadsheetBench 由 44.3% 提至 76.4%，均优于所有基线。
- 跨框架迁移结果：优化后的技能直接部署

## HarnessEvolve 论文详细总结（续）

跨框架迁移结果：优化后的技能直接部署至 Hermes、OpenCode、LAMAgent 与 DeepSeek Harness 后，相较各自 Base 仍有显著提升——例如 SpreadsheetBench 中 Hermes 从 40.1% 提至 69.5% 左右、OfficeQA 中 LAMAgent 提升约 8 个百分点；同时开销远低于重新走完整自我进化流程。这表明 HarnessEvolve 学到的技能并非过度耦合于 OpenClaw 的特定执行逻辑，具备一定程度的可迁移性。

- **消融结论**：完整模型的准确率最高。去掉参考轨迹（M1）后准确率大幅下降——印证“参考轨迹对比 + 分歧点定位”对信用分配问题的核心作用；去掉错误聚类（M2）后性能次降——印证根因聚类和长尾保护对系统性修复的必要性；去掉质量门（M3）后性能亦有回落，且论文指出该场景下会出现因数据泄漏导致的虚高训练精度与回退的验证精度——印证质量门对防捷径学习的价值。

- **鲁棒性与行为发现**：图 2 展示的进化曲线呈“阶梯式上升”而非平滑爬升，符合性能门只接受有实质提升候选的设计意图；拒绝/修订机制将部分更新的注入延后至后续轮次；epoch 末快照选择可挽回批次级门控的短视决策，最终选中的 Harness 往往并非训练精度峰值点，而是在验证集上综合最优的快照。

- **错误模式修复的代表性示例（图 3）**：HarnessEvolve 自主产出了人类可读、可审计的修复，例如在 skill.md 中补充“若 KPI 查询跨多表则必须先 JOIN”之类的执行约束、修正工具描述中的参数单位歧义、调整任务分解提示的步骤顺序、为电子表格公式生成补充边缘条件处理逻辑等。这说明优化产物不仅是数值提升，还包含可解释的 Harness 结构变化。

### 七、论文的工程贡献与系统设计意义

- **模块化架构作为核心贡献**：论文主张“自我进化的可靠性来自流程解耦，而非更好的单点优化器”。通过将执行、评估、优化、门控拆分为独立智能体并赋予不同职责，实现了对信用分配、捷径学习、灾难性遗忘三大挑战的**系统性而非算法性**回应。
- **两大门控形成“信任边界”**：质量门与性能门分别从静态内容（防泄漏/防膨胀）与动态行为（防回退/保提升）两个维度约束候选更新，使 HarnessEvolve 在无人工介入下仍能维持与手写基线相当甚至更优的安全性下限。
- **可审计性**：参考轨迹、错误信号、聚类结果、候选编辑、门控判定理由均以结构化语言记录，支持回溯——这对企业级部署（如云核心网、无线网络领域）尤为关键。
- **参考轨迹的思想价值**：将“任务附带真实答案”这一常见训练资源重新定义为“可验证的轨迹级监督信号”，而非仅仅作为最终答案标签使用——这一转换是解决远端信用分配失败的关键设计。

### 八、论文的潜在缺陷与改进方向（客观评述）

**潜在缺陷**

1. **性能指标单一**：全文只报告 Accuracy（%），未报告延迟、调用次数、Token 消耗、失败率分解等工程指标；考虑到 HarnessEvolve 需要生成参考轨迹、多轮门控评估、回放验证，其实际开销可能远高于基线，但论文未做“同等预算下的对比”，使“更优精度”的公平性打折。
2. **参考轨迹依赖任务真值**：方法假定训练任务存在可判定的正确答案，且答案可作为生成参考轨迹的引导信号。对开放式任务（如创意写作、对话策略、代码生成中无唯一答案的场景），该机制需要重新设计或退化为无参考模式，论文未讨论该边界。
3. **门控阈值需人工设定且无灵敏度分析**：ηleak、ηblo、δ、ϵ、Tatt、Trev、batch 容忍度等十余个超参在文中只给出一组值，缺乏系统敏感性分析；这些阈值是否跨数据集普适仍有疑问。
4. **LLM-as-judge 的可靠性未充分验证**：质量门依赖 LLM-as-judge 来判定数据泄漏，但论文未报告该 judge 自身的假阳性/假阴性率、与人类评判的一致性，也未提供 judge 失败时的兜底机制。
5. **灾难性遗忘缓解的验证较弱**：回放窗口 R=2 与性能门只保证“最近回放批不显著劣化”，而 epoch 末选择仅基于当前验证集选最优快照，并未直接测量早期能力是否在更长迭代后被覆盖；对“灾难性遗忘”的实证支持不如对前两大挑战充分。
6. **跨框架实验只迁移了技能层面**：如论文自述，跨框架部署仅使用优化后的技能描述文件，提示、执行逻辑、工具等并未整体迁移，因此不能断言“完整 Harness 跨框架泛化”。
7. **消融与统计力度有限**：全套消融仅在一个数据集的单一模型上进行；所有报告精度未提供多次随机种子下的均值±方差，无法判断提升是否统计显著。
8. **实验名称/版本身份识别存在模糊性**：文中出现 GEPA（2025）、ACE（2026b）等工作引用年份显示到 2026，作者所属机构未在正文给出，可能涉及预印本/未来标注问题；评审时需核实引用公信力。

**改进方向**

- 补充多模型 × 多数据集 × 多随机种子的完整消融，并报告置信区间；
- 引入“固定总预算（模型调用次数/Token）下的对比”以验证效率公平性；
- 对质量门阈值与回放窗口等超参做灵敏度分析，或提出自适应阈值机制；
- 拓展无真值/开放式任务的弱监督参考轨迹生成策略（如自一致性、奖励模型打分）；
- 设计更直接的遗忘度量（如旧任务回测矩阵），验证长程进化中的能力保持；
- 在跨框架迁移中尝试迁移完整 Harness（含执行逻辑与工具定义），并报告失败模式。

### 九、对我们研究的参考价值与可借鉴要点

1. **系统级设计思路**：在相似智能体自我进化课题中，可借鉴“将问题拆解为执行/评估/优化/门控四类独立模块”的架构，而非追求单一算法的全能优化。
2. **参考轨迹用于信用分配**：已有任务答案的 benchmark 中，可以模仿“先生成通过答案引导的参考轨迹，再做失败轨迹与参考轨迹的分歧点定位”，以较低成本提升错误归因质量。
3. **错误聚类的长尾保护**：对错误信号聚类时避免强制归类，保留单样本簇，能有效保留重要但低频的失败模式——该原则可迁移至其他故障诊断任务。
4. **质量门 + 性能门双闸门**：为自动优化流程设置“静态内容检查 + 动态性能回放验证”两道闸门，是在自动化系统中保障安全性的实用模式。
5. **可审计的中间产物**：保留错误信号（严重度、原因、修复提示）及门控判定理由的明文记录，既便于人工抽查，也为后续研究提供分析素材。
6. **需注意的坑**：单一精度指标、缺乏同预算对比、消融不完整、LLM-as-judge 未校准——在做类似研究时应预先补齐这些验证，避免审稿人质疑。

### 十、一句话总结

HarnessEvolve 通过将智能体自我进化重构为“执行、评估、优化、门控”四模块解耦的闭环系统，并借助可验证参考轨迹、根因错误聚类与双重门控机制，在多个开放域与企业级基准上显著提升了智能体控制框架的自主迭代质量；其思想价值在于用流程架构而非单一算法同时应对信用分配失败、捷径学习与灾难性遗忘，但其开销公平性、消融完整度与超参鲁棒性仍是后续研究需要补强的短板。
