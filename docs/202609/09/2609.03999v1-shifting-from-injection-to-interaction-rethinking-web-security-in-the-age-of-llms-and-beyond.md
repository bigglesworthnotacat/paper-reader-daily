## 摘要
大型语言模型（LLMs）正成为网络应用和浏览器代理不可或缺的一部分，它们在改变在线交互的同时，也引入了新的攻击向量并重塑了长期存在的网络漏洞。诸如跨站脚本（XSS）之类的经典威胁可以通过LLM介导的交互被放大，而LLM特有的漏洞可以在网络应用中传播，引入诸如提示注入等攻击。因此，保护现代网络系统需要理解传统威胁与LLM特有威胁在系统生命周期中的相互作用。与先前将网络和LLM安全分开处理的调查不同，本调查提供了一个统一的分析，考察LLM如何放大客户端、服务端和管道层中的网络漏洞，同时评估防御措施及其局限性。该分析探讨了将NIST和ISO/IEC人工智能安全框架扩展到支持LLM的网络环境的安全需求。确定了三个未解决的挑战：对抗性自然语言指令、自主代理安全，以及通过持续监控和适应实现部署后安全。提出了一种LLM感知的监控与控制框架，集成了语义输入验证、提示完整性保护、输出隔离、代理治理和运行时监控。这一统一视角刻画了不断演变的威胁格局，并为安全的AI赋能网络系统指明了未来方向。

## Abstract
Large language models (LLMs) are becoming integral to web applications and browser agents, transforming online interactions while introducing new attack vectors and reshaping longstanding web vulnerabilities. Classical threats such as cross-site scripting (XSS) can be amplified through LLM-mediated interactions, while LLM-specific vulnerabilities can propagate across web applications, introducing attacks such as prompt injection. Securing modern web systems therefore requires understanding interactions between traditional and LLM-specific threats across the system lifecycle. Unlike prior surveys treating web and LLM security separately, this survey provides a unified analysis of how LLMs amplify web vulnerabilities across client-side, server-side, and pipeline layers while evaluating defenses and their limitations. The analysis examines extending NIST and ISO/IEC AI security frameworks to the security needs of LLM-enabled web environments. Three unresolved challenges are identified: adversarial natural-language instructions, autonomous agent security, and post-deployment security through continuous monitoring and adaptation. An LLM-aware monitoring and control framework is proposed, integrating semantic input validation, prompt integrity protection, output isolation, agent governance, and runtime monitoring. This unified perspective characterizes the evolving threat landscape and outlines future directions for secure AI-enabled web systems.

## 1. 核心问题与研究动机
- **动机**：LLM 已被大规模集成到 Web 应用、浏览器代理（browser agent）与各类 API 中，在带来自动化与个性化便利的同时，也从根本上改变了 Web 安全威胁格局。现有研究要么只研究 LLM/Agent 自身安全（把 LLM 当作“攻击终点”），要么只研究传统 Web 漏洞，缺乏统一视角；而现实中，漏洞往往跨越客户端、服务端、LLM 流水线等多个层面传播。
- **核心主张**：LLM 不应被看作孤立的攻击目标，而是充当“中间传导层”——它能够继承、放大并重构传统 Web 漏洞（如 XSS、CSRF），同时带来提示注入等全新攻击范式。
- **研究问题**：
  - RQ1：LLM 安全风险在多大程度上放大了传统 Web 漏洞，并在客户端、服务端、流水线等层面传播？
  - RQ2：现有防御措施与安全框架（如 OWASP、NIST AI RMF、ISO/IEC 标准）是否足以缓解这些风险？
- **实际意义**：文章用“系统弹性的整体恶化”来解释：LLM 交互削弱了数据—指令分离（data–instruction separation）、信任边界（trust boundary）和执行控制（execution control）等传统安全边界。

## 2. 研究方法论、核心思想与技术细节
- **核心分析框架**：本文没有进行模型训练或算法实验，而是提出一套“三层”文献评估体系：
  - **OWASP LLM Top 10（2025）**：作为风险分类的高层框架（LLM_01—LLM_10）。
  - **本文自定义的 TRA（传统威胁参考架构，Traditional Threat-Reference Architecture）**：将 LLM 风险映射回传统 Web 漏洞类别（如 TRA_01 指令注入、TRA_02 信息泄露等）。
  - **MITRE CWE 分类法**：用于把风险和 TRA 表层映射为细粒度软件弱点根因，如 CWE-79（XSS）、CWE-89（SQL 注入）、CWE-1427（LLM 提示注入相关弱点）。
- **映射规则的标准化**：为避免随意类比，作者定义了四条判定准则，应用于全部十项 OWASP LLM 风险：
  1. Entry Point（攻击输入从何而来）
  2. Processing Mechanism（系统如何处理输入：语法执行 vs. 自然语言指令理解）
  3. Security Boundary Violation（被破坏的安全原则，如机密性、授权、数据—指令边界）
  4. Impact（最终影响：执行、泄露、误导、资源耗尽等）
- **系统性文献综述流程（Stage II）**：

## 6. 主要结论与发现
- LLM 的威胁不再只是“模型层威胁”，而是全栈威胁：LLM 集成通过语义处理重构经典攻击链，使传统的语法注入（syntactic injection）演变成一种更高级的“指令操作型”攻击（如提示注入即“指令注入”的演化）。
- Web 攻击的每一个经典类别在 LLM 环境下都找到了现代对应问题，以下是文中的核心映射关系示例：
  - “提示注入”对应 TRA_01、CWE-79/89/1427；
  - 敏感信息泄露可以绕过传统 CWE-200（信息暴露），通过记忆或隐含知识进行；
  - “过度自主权”（Excessive Agency）可产生 CSRF 风格/权限升级攻击，因为代理可以复用浏览器会话调用敏感系统 API；
  - 嵌入级弱点（embeddings）可将“侧信道推理”升级为“向量空间重建”，例如从被截获的语义向量中还原原始数据；
  - “不当输出处理”可将 LLM 生成的文本转换成可执行的 HTML/SQL/命令，导致 XSS 或 SQL 注入。
- 现有安全框架（NIST AI RMF、ISO/IEC 等）对对抗性自然语言指令、代理级决策失误、部署后的“行为漂移”应对能力不足。
- 三类核心挑战：对抗性自然语言指令、代智能体安全、以及需要持续监控与适应的部署后安全。
- 提出一个新框架：LLM-aware monitoring–control framework，将 NIST 监控维度与语义输入验证、提示完整性保护、输出隔离、代理治理与运行时监控结合起来。

## 7. 亮点与贡献
- 整合了 Web 与 LLM 安全：弥补了以往文献将 LLM 视为独立攻击对象/或者将 Web 与 AI 割裂分析的理论空白，建立了“全栈”视角。
- 映射体系非常突出：采用 OWASP Top 10 + 自建 TRA + CWE 三级标注体系，提升了分析的规范性，避免字面对比和空泛论述。
- 方法论较严谨：运用 PRISMA 风格的挑选标准、滚雪球式文献发现过程、结构化编码方案，对综述类论文而言算是系统化程度较高的设计。
- 对框架的落地扩展有实际意义：引入 LLM 感知的监控—控制框架，将抽象风险原则（如 NIST AI 800-4 的监控维度）转化为具体可操作的安全控制层（输入层—提示层—模型层—输出层—代理层—系统层）。

## 8. 不足与局限
- 缺少系统层“双向耦合”的实证数据：该研究提出用放大/统一框架描述 LLM 全栈攻击，但并没有在现实数据上量化 LLM 对不同攻击的“放大器特性”，也没有对同一负载逐项给出基准测试。
- 主观映射风险：对 OWASP-TRA-CWE 的映射虽然有一套明确的 4 项标准，但仍可能渗入个人判断，形成“框架偏好”导致的偏差（作者亦承认这一点）。
- 单一编码者问题：105 篇文献的筛选和编码由单一作者完成，缺少多编码员交叉验证，增加选择性偏差风险。
- 依赖未深入经过同行评审的预印本证据：部分关键论证依赖 arXiv 预印本文献，其可信度和稳定性存在不确定性，且部分结论可能随着正式论文发表而变化。
- 时间边界问题：该综述锚定在 OWASP LLM Top 10（2025）的版本，而 Web 和 LLM 攻击面更新极快，潜在风险包括出现十大风险之外的新攻击类别。
- CWE 覆盖不完整：对某些风险的 CWE 对应（例如 TRA_09 类角色：内容操纵/社会工程）并不存在明确的对应条目，导致映射在文中直接标记为“无直接 CWE 等价物”的空白。
- “有效性威胁”分析处理得比较真实但仍相对保守：没有提供针对漏检文献的正式量化指标（例如语言准确度统计或方法论质量评分），也没有对提出的新监控框架做实际企业实施或生态防攻击的真实测试。
