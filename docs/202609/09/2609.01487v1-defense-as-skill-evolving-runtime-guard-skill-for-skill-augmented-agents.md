## 摘要
技能增强型代理将可复用的技能加载为持久运行时上下文，这提升了任务性能，但也为恶意技能提供了影响未来行动的持久渠道。此类技能可能在具体用户任务和工作区状态使不安全行为看似有用之后，才泄露机密、破坏代码、绕过审批或为数据外传做铺垫。这使得安装前审查不足，需要运行时、任务条件化的保护。我们提出“防御即技能”这一防御范式，将运行时防护本身实现为可安装、可检查且可编辑的技能。我们的防护器SkillSonar与不可信的任务技能并行运行，并根据用户任务边界检查敏感操作，将每个操作路由至允许、重新规划或确认决策，而无需修改底层代理运行时。为研究这一设置，我们构建了SCOPE-R，一个覆盖6个风险族和21个子类别的任务条件化数据集，包含206个经攻击确认的恶意实例和43个良性任务。随后，我们利用运行时防护技能进化（一种蒙特卡洛树搜索过程，根据轨迹回放中的反馈进化磁盘上存储的防护技能）在SCOPE-R训练子集上改进SkillSonar。在Claude Code和OpenClaw上，进化后的防护器显著降低了攻击成功率，同时保持了良好的安全-效用权衡。在重复的GLM-5运行中，SkillSonar将ID ASR从0.482降至0.104，将OOD ASR从0.606降至0.115。进一步分析展示了跨受害模型、保留风险族和外部基准的迁移能力，以及对自适应攻击者的持续防护。消融研究进一步表明，明确的安全责任分配和技能原生的表示方式对观察到的收益都很重要。

## Abstract
Skill-augmented agents load reusable skills as persistent runtime context, improving task performance but also giving malicious skills a durable channel for steering future actions. Such skills may leak secrets, corrupt code, bypass approvals, or stage data for exfiltration only after a concrete user task and workspace state make the unsafe action appear useful. This makes pre-install vetting insufficient and calls for runtime, task-conditioned protection. We propose Defense-as-Skill, a defense paradigm that implements the runtime guard itself as an installable, inspectable, and editable skill. Our guard, SkillSonar, runs alongside untrusted task skills and checks sensitive actions against the user's task boundary, routing each action to an allow, replan, or confirmation decision without modifying the underlying agent runtime. To study this setting, we construct SCOPE-R, a task-conditioned dataset covering 6 risk families and 21 sub-categories, with 206 attack-confirmed malicious instances and 43 benign tasks. We then improve SkillSonar on the SCOPE-R training subset using runtime guard-skill evolution, a Monte-Carlo Tree Search procedure that evolves the on-disk guard skill from feedback on the rollouts. Across Claude Code and OpenClaw, the evolved guard substantially reduces attack success while maintaining a favorable safety-utility trade-off. On repeated GLM-5 runs, SkillSonar reduces ID ASR from 0.482 to 0.104 and OOD ASR from 0.606 to 0.115. Further analyses demonstrate transfer across victim models, held-out risk families, and external benchmarks, as well as retained protection against adaptive attackers. Ablations further show that explicit safety responsibility assignment and the skill-native representation are both important to the observed gains.

## 1. 核心问题与整体含义

**研究动机**：技能增强型代理（SAA，Skill-Augmented Agents）正越来越多地通过加载可复用的“技能”（skill）——即打包的指令、脚本、资源和工作流——来执行复杂任务。这一机制显著提升了代理的性能和可扩展性，但也引入了一个此前容易被忽视的安全问题——技能一旦被加载，就会在整个任务执行期间持续存在并影响代理的后续动作，从而为恶意技能提供了一个**持久且可被任务场景激活的引导通道**。

**关键问题**：传统安全措施（如预安装时的静态扫描、包仓库审查）无法应对此类风险，因为恶意技能**无需在安装时暴露恶意性**，它可以通过聪明的“延迟触发”方式，等待用户的具体任务与工作区状态令某个不安全行为“看似合理且有用”时，再诱导代理执行诸如泄露机密、篡改代码、绕过审批或为数据外传铺路等高危操作。

**Security Gap**：现有常见的运行时防御方案多依赖外部独立分类器、托管守卫模型或平台级权限门（如 Claude Code 的 AcceptEdits），这些方案往往不能像普通技能制品那样被无缝安装、审计、编辑和跨 SAA 工作流迁移，也无法以可度量的方式持续优化。这使得运行时防护在 SAA 生态中的部署与维护存在显著瓶颈。

**核心范式贡献**：论文提出了 **“防御即技能”（Defense-as-Skill）** 这一新范式，主张将运行时安全防护本身实现为一个普通技能制品——**可安装、可检查、可编辑、可演化**，在不修改底层代理运行时的情况下提供任务边界的策略层防护，为 SAA 的安全问题打开了“防护本身也可被优化迭代”的空间。

## 2. 方法论

### 2.1 核心思想
论文认为，与其对每一个技能做一次性永久的“信用判定”，不如在**执行流中持续检查每个具体的（可能敏感的）动作**是否仍处于用户任务意图的边界之内。进一步的创新在于，将这个检查机制做成一个技能，而非外部服务或底层的强制机制。

### 2.2 SkillSonar 运行时防护技能
- **安装与运行**：SkillSonar 如同一个普通任务技能一样被同一个代理（如 Claude Code/OpenClaw）加载，但它被分配了一个明确且持久的“安全责任”角色。
- **动作管线(triage mechanism)**：在可能敏感的操作发生前，守卫要求代理结合用户请求、已加载技能指令和执行上下文，判断动作是否接近或逾越任务边界。每一个动作最终会被**路由到 4 种决策之一**：
  - **Allow（放行）**：明确为任务所需且无实质风险。
  - **Narrow/replan（收窄/重规划）**：对一些处于灰色地带的行为，要求先缩小操作范围或调整执行路径。
  - **Require confirmation（要求确认）**：对高风险行为（如敏感数据或外部账户操作）要求明确的用户授权。
  - **Block（拦截）**：对明显越界或符合恶意行为模式（如隐蔽外传、伪造审批）的动作予以阻断。

### 2.3 显式安全责任分配协议（Guard Invocation Protocol）
论文发现普通能力技能可以依赖语义相关性被智能体发现并调用，但安全技能容易被忽视——任务本身可能不含任何“安全意图”的线索，所以不能依赖常规“任务-技能”匹配。作者明确规定：**在任务前附加指令，强制代理在执行任何动作前调用 SkillSonar 并遵循建议**。这是一种“软性责任分配”：代理仍有可能不读、不遵循守卫的指示，但它显著提升了安全技能的利用率和防护稳定性。

### 2.4 SCOPE-R 数据集构建算法
论文从 PinchBench 挑选 15 个任务并利用“技能创造者”技能生成初始良性技能，随后执行**闭环构建循环**：
1. **攻击者代理**（另一个 SAA 实例）接收任务、技能和风险元数据，对技能进行本地修改编辑（可增加隐藏指令、改脚本、改字段），使其在完成任务的同时触发目标恶意行为；
2. **受害者代理**在全新的对话中加载技能并完成任务，生成轨迹；
3. **裁判代理**根据元数据及可观察的成功判据，判断攻击是否成功；
4. 成功则保留实例；失败则向攻击者反馈失败模式并重新提炼，最多迭代若干轮。

### 2.5 运行时守卫技能进化的 MCTS 算法（MCTS-Guard-Skill Evolution）
每个守卫生效技能都被视为一个可优化的策略工件。

- **搜索空间**：一个蒙特卡洛搜索树，每一个节点代表一个候选守卫版本。
- **双轨评估**：将评估实例集划分为*廉价评估集*（用于快速估算，支撑 UCT 选择）与*完全评估集*（用于精评估精选，为每个节点只使用一次高保真评估，防止不同保真度的数据混杂）。
- **多维目标函数**：
  \[score(v)=(1-ASR_v) + \epsilon(\lambda_b U^{benign}_v + \lambda_m U^{malicious}_v - \lambda_q eC_v - \lambda_t eK_v)\]
  其中以 **ASR 为安全主导目标**，任务效用视为次要偏好，兼顾确认次数与 token 开销。
- **UCT 选择公式**：(bar{Q}_v^c + c√(ln(max(2,N_parent)/max(1,n_v))))
- **扩展与细化**：选用完全评估后的节点，基于裁判的依据（攻击成功原因、效用丢失原因等）生成 3 个“局部修正”的子代候选。
- **算法终止条件**：节点评估分数（对应 ASR≤5%）或消耗完迭代预算。

## 3. 实验设计

### 3.1 数据集与基准
- **SCOPE-R 数据集（自建）**：
  - 从 PinchBench 抽取 15 个任务 + 43 个良性任务；
  - **六类风险家庭**：Specification Integrity（说明完整性）、Capability Control（权限控制）、Operational Side Effects（副作用）、Privacy & Data Flow（隐私与数据流）、Execution Safety（执行安全）、Resource & Reliability（资源与可靠性），共 **21 个子类别**；

  - 划分方法：将 Capability Control 和 Privacy & Data Flow 两族作为**OOD 留存集**（训练时完全不可见），剩余族按比例划分为训练集和 ID 测试集（训练 95 个，ID 测试 52 个，OOD 测试 59 个）。
- **外部跨基准**：SkillSafetyBench、WildClawBench。

### 3.2 运行容器与受害模型
- **两个 SAA 容器**：Claude Code 与 OpenClaw。
- **主受害模型**：GLM-5；额外受害模型：GPT-5.4、Claude Haiku 4.5、Kimi-K2.6（用于迁移验证）。
- 使用固定的**留守裁判模型**：Qwen3.5-122B-A10B（不属于受害者集合）。

### 3.3 对比基线
- **No-guard（无防护）**
- **System prompt（系统提示注入安全文本）**
- **AcceptEdits**（Claude Code 内置权限机制：默认交互式确认文件编辑/工具调用）
- **AcceptEdits + allowlist（添加固定提权白名单命令）**
- **技能守卫基线**：AgentSpec（规则型运行时触发约束策略）、TS-Guard（ToolSafe 的基于外部语义模型对工具调用的判定）

### 3.4 主要指标
ASR（攻击成功率）、任务效用（Benign 和 Malicious 实例都报告）、确认次数、Token 成本；并有**攻击成功的裁判人工审计**（Construction Judge 94%平衡同意度、Evaluation Judge 98%平衡同意度）。

## 6. 主要结论与发现

- **显著降低攻击成功率**：在 10 次重复 GLM-5 运行上，SkillSonar 将 **ID ASR 从 0.482 ± 0.039 降至 0.104 ± 0.036**，**OOD ASR 从 0.606 ± 0.043 降至 0.115 ± 0.037**。
- **保住任务效用**：与严格的平台级权限系统（AcceptEdits）相比，SkillSonar 在同等或者更好的安全指标下保留了可观的良性任务完成率（例如在 GLM-5 ID 集上，守卫的效用 0.779 vs AcceptEdits 的 0.650）。
- **普遍跨容器与跨模型迁移**：同样一套守卫可同时在 Claude Code/OpenClaw 部署；在 GPT-5.4 上 ID ASR 降到 0.019；在 Claude Haiku 4.5 上也具显著防护效果；GLM-5 优化的守卫可以直接向 Kimi、Haiku、GPT 零样本迁移。
- **可泛化到未见风险族**：OOD 数据集整族留出（Capability Control、Privacy & Data Flow），ASR 显著下降，说明守卫学习到了比表层模式更普适的“权限边界”或“数据最小化”原则。
- **跨外部数据集有效**：在 SkillSafetyBench 与 WildClawBench 安全任务子集上也都优于基线。
- **显式安全责任是刚需**：如果只依赖任务-技能语义匹配来调出安全技能，守卫效用很差（ID ASR 还在 0.400），有了显式调用指令后才降到 0.104 以下。
- **技能原生表示优于文本平铺**：内容一致时，技能模块化表示方式比打成一个大而全的系统提示词方式处理得更安全——ASR 更低、任务效用更高、还少了约 21% 的 tokens。
- **对自适应攻击有残余鲁棒性**：尽管针对性迭代后的攻击集将守卫 ASR 重新提升至 22.9%，但相比无防护仍保留 22.2 个百分点的绝对降低。

---

## 7. 优点

1. **开创性的“可演化防御”视角**：将防护静态审查转化为运行时可演化的策略工件，不只是防御模型或外部 API，而是能用同一套代理机制被不断编辑、测试、优化——与近期“技能即代码/技能会自我演化”的研究脉络高度契合。
2. **数据集具有诊断能力**：SCOPE-R 不是简单返回“是否攻击成功”的标量，而是引入六类风险家庭和 21 个子类别。提供了攻击者和裁判的闭环判定逻辑，针对性很强，不仅包含恶意攻击可复现的轨迹，还有用于防误伤的良性任务控制组。
3. **把软约束作为一个部署的关键变量来研究**：论文明确指出“显式指令分配安全责任”属于部署配置的一部分，不做隐藏性的“实验操作便利”——不掩盖不完美，诚实且利于复现迁移。
4. **清晰的机制内定位与丰富的基线对拍**：对比了“机制级权限拦截”（AcceptEdits）、“提示级软约束”（System prompt）与“外部独立语义模型/基于规则”（TS-Guard/AgentSpec）等不同策略，让 SkillSonar 的安全-效用取舍得以准确落入设计空间。
5. **评估体系完整**：同时考虑攻击成功率、任务效用、确认截断与 token 开销，以及人工裁判审计——兼顾安全收益与使用体验，结论令人信服。

---

## 8. 不足与局限

1. **软性依赖模型遵循能力**：SkillSonar 不依赖强制白名单或 OS 沙箱，而是一种策略文本与技能结构；和论文强调的一样，一旦宿主模型不读取、不遵循或被恶意技能规则覆盖，防护仍然是可绕过的。Adaptive attack 后 22.9% 的 ASR 证实了这一点。
2. **跨模型泛化验证不够深**：GPT-5.4 与 Claude Haiku 4.5 只做了一次运行转储；无法评估平台切换时任务效用波动的稳定性（例如 OOD 集上 Haiku 的表现明显比 GPT 差）。
3. **自适应攻击深度有限**：迭代轮数和小规模样本限制了强度，更强的优化攻击器可能产生更严重的残余 ASR。
4. **生成环境的范围狭窄**：数据集聚焦于编码代理可能面临的场景，不覆盖通用助手、浏览器操作、多代理协作生态等更广泛的空间。跨基准外部评测虽已证明部分有效性，但文中自己也承认不足以无条件宣称对所有生态安全。
5. **搜索成本与预算**：MCTS 只允许至多 8 到 10 次完整评估，近似误差大；更大的预算本可能收敛到更优守卫，尤其在 OOD 部分（如第 8 轮后 ASR 又出现波动，见 Figure 3）。
6. **固有“双刃剑”风险**：详细披露如何构建恶意攻击实例本身可以作为制造更恶毒技能的指南。论文虽提出了缓解策略和脱敏发布原则，但需实际评估这种发布策略带来的引导性风险。
