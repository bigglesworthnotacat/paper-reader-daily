## 摘要
近年来，个性化大语言模型智能体越来越多地将记忆中保留的信息转化为压缩或结构化表示，我们称之为用户模型，以指导后续决策。当源文本从通过普通接口可达的状态中移除时，这些模型通常被认为更具隐私保护性，因为直接的内存提取攻击会失去其目标文本。然而，我们认为用户模型暴露了一个新的攻击面，因为即使源记录和后端状态不可访问，攻击者仍然可以从其影响下的个性化选择中恢复出私有信息。因此，我们提出了 UMPeek，一种基于假设引导的自适应探测的黑盒攻击，用于推断此类隐藏用户模型。它从请求中留下的开放选择中形成假设，在普通后续任务之间切换，并仅保留那些被可见行为支持且未被反驳的说法。我们针对不同的个性化任务和用户模型后端，与现有攻击进行了广泛的基准评估。我们进一步在真实世界系统中使用已确认被保留的信息验证了 UMPeek，并评估了针对其自适应探测的防御方法。总体而言，UMPeek 在基准测试和真实世界对比中均优于现有攻击，并在响应级防御下仍能恢复用户信息，这表明当保留的信息塑造可见行为时，使记录和后端状态不可访问并不能保证语义隐私。

## Abstract
Recent personalized LLM agents increasingly transform information retained in memory into compressed or structured representations, which we call user models, to guide later decisions. When source wording is removed from the state reachable through the ordinary interface, these models are commonly treated as more privacy-preserving because direct memory-extraction attacks lose the text they target. Yet we argue that user models expose a new attack surface because an attacker can still recover the private information from the personalized choices they shape, even when source records and backend state remain inaccessible. We therefore introduce UMPeek, a black-box attack based on hypothesis-guided adaptive probing to infer such hidden user model. It forms hypotheses from choices left open by a request, switches among ordinary follow-up tasks, and retains only claims supported and not contradicted by visible behavior. We conduct an extensive benchmark evaluation across diverse personalization tasks and user-model backends against existing attacks. We further validate UMPeek in real-world systems using information confirmed to be retained, and we evaluate defenses against its adaptive probing. Overall, UMPeek outperforms existing attacks in both benchmark and real-world comparisons and continues to recover user information under response-level defenses, showing that keeping records and backend state inaccessible does not guarantee semantic privacy when retained information shapes visible behavior.

### 研究动机与背景
- **个性化 LLM 智能体的普及**：LLM 智能体通过与用户的多轮交互完成多样化任务。为了在不同任务中保持一致和个性化，需要记忆模块来保留用户的偏好、历史交互等信息。

- **“压缩即隐私”的常见假设**：当源文本不直接出现在攻击者可达状态中时，直接针对文本的记忆提取攻击会失去攻击目标（例如现有研究表明关键事实摘要可以将伪造秘密的精确提取率降低 64%~76%）。因此，现有的提取类攻击无法有效处理用户模型，业界普遍认为这种设计能在个性化与隐私之间取得平衡。

### 核心问题
- 论文质疑上述假设，认为**用户模型暴露了一个全新的攻击面**：即便攻击者无法访问任何源记录或内部后端状态，只要保留的用户信息仍然持续塑造智能体的可见行为（回答、工具调用等），外部参与者就可以**通过观察普通任务请求的行为结果，反推出隐藏用户模型中保留的语义信息**。
- 一句话概括：**隐藏记录与后端状态并不能阻止攻击者从个性化行为中推断私有用户信息**。

## 2. 论文提出的方法论

### 整体框架：UMPeek
UMPeek 是一种**黑盒攻击**方法，基于**假设引导的自适应探测（hypothesis-guided adaptive probing）** 来推断隐藏用户模型中的用户信息。

### 核心思想与流程

**（1）构造行为假设（Constructing Behavioral Hypotheses）**
- 依据公开任务描述与接口定义，提取一个**“决策维度”空间**，例如饮食限制、住宿偏好、旅行兴趣等。
- 对每条请求，检查该请求是否已经显式固定了维度值（若固定，则观察行为不构成用户信息证据）；若该维度是**开放的**，并且模型在可观察的回复/行动中给出了具体选择，则将该选择与开放维度绑定，构成一个**候选声明（candidate claim）**。
- 通过“开放维度 → 可见选择 → 候选声明”的链条来避免把表面措辞、泛泛建议等误当作用户信息。

**（2）自适应测试假设（Adaptively Testing Hypotheses）**
- **重放（Replay）**：首先重复初始任务场景，验证某个候选选择是否在该任务内保持稳定（仅证明任务内一致性）。
- **切换任务（Task Switching）**：更关键的测试是用同一目标域、但改变具体任务形式且保持维度开放，看候选声明在新情境中是否继续预测一致行为；此类跨任务验证能区分“基于任务背景的偶然行为”与“由隐藏用户模型驱动的真实个性化”。
- **证据状态驱动调度**：根据哪些维度仍未被解决、哪些竞争解释仍需区分，从公共请求池中选择下一个请求；调度规则要求“一个后续请求能尽可能多地解决未决维度或区分相互竞争的取值”。

**（3）选择性恢复（Selective Recovery）**
- 每个假设被映射为公开决策维度 + 值的规范语义形式，跨回复的相同含义会被分组。
- 对每个候选声明评估三段证据：
  - **直接支持**：回复或行动中明示关联了用户信息；
  - **跨请求支持**：另一个开放维度的请求给出了兼容的选择；
  - **反驳**：同维度开放请求给出了与声明不相容的选择（请求预设值不构成有效反驳）。
- **接受条件**：至少与一条具体可见选择绑定、且在整个序列中没有出现反证；对于从隐式推荐中提出的声明，还必须经过重放或跨任务验证。
- 输出为人类可读的语义声明集合，而非后端字段、嵌入坐标或图结构等内部表示。

### 核心特点
- 完全黑盒：不访问源记录、用户账户、后端状态或系统提示词；
- 无需辅助信息或对底层 LLM 的认知；
- 通过任务切换将“某次单个选择”转化为“可归因的重现性证据”，从行为层面锁定隐藏状态的语义内容。

## 6. 论文的主要结论与发现

1. **用户信息在用户模型不可见时仍可被推断**：当保留信息影响可见行为时，仅隐藏记录与后端状态不能防止语义级的信息泄露。
2. **UMPeek 大幅优于现有攻击**：在基准测试中，UMPeek 的 UMR-F1 达到 0.619，而最强基线为 0.100（将近 6 倍差距）；HBPS 为 0.289 vs. 0.147。
3. **攻击面不依赖于某一特定后端**：无论在显式记忆检索、时间知识图谱还是记忆存储层之后，UMPeek 在全部 12 个 benchmark-backend 组合中均保持非零恢复（UMR-F1 介于 0.467~0.817）。
4. **优势主要来自自适应选取任务而非查询数量**：同样约 15 次请求，自适应选择达到 0.651 UMR-F1，而固定序列仅 0.281。
5. **语义恢复与行为预测是互补而非替代的能力**：LoCoMo 上 UMR-F1 较高但 HBPS 较低（以恢复的信息并不能预测每一次未见任务的选择），而 ETAPP 反之。
6. **真实世界独立系统同样受影响**：UMPeek 在 3 个托管管理服务上均取得最高恢复；即使所有方法都只允许 3 次请求，UMPeek 依然领先。
7. **响应级防御不够，状态反事实控制更有效但仍有残余泄露**：PrivacyChecker 与 Theory-of-Mind Defense 留下大量恢复空间；Stateful Counterfactual 将 UMR-F1 降至 0.187，同时显著削弱个性化任务效用，形成**隐私–效用两难**，揭示了一条难以完全封闭的通道。

## 7. 优点

- **攻击设定既恶劣又合理**：黑盒、无账号权限、无辅助用户信息、不能询问记忆或内部状态，仅发送任务类请求观察输出，切中真实协作/服务提供方场景。
- **“行为假设”思想清晰**：从“开放决策维度的可见选择”出发构造假设，用任务切换区分竞争解释，再用支持/反驳/未决三层证据积累与简明接受规则实现归因——整个过程不依赖底层表示类型。
- **跨系统、跨任务、跨防御的系统性评估**：12 个 benchmark-backend 组合 + 七个基线 + 三个真实平台 + 一个端到端代理 + 三类推理防御的矩阵式考核，给结论较强的说服力。
- **严格的消融分流**：区分了“额外询问”与“信息性任务选择”的贡献，以及接受规则在控制精度上的独立价值。
- **防御机理拆解**：对自行提出的 Stateful Counterfactual 做组件消融，区分跨请求证据跟踪与反事实比较各自的作用，为防御设计提供了针对性路线。
- **指标设计合理**：UMR-F1 测“是否找到隐藏在状态里的语义内容”，HBPS 测“恢复的内容是否能提前预测未见行为”，二者互补，避免单指标误导。
- **伦理与合规考虑较完善**：真实系统测试用合成身份与文档化接口，请求量小，获得机构伦理审批并给出 Artifact 开源的可用链接。

## 8. 不足与局限

- **决策维度依赖公共任务定义**：候选假设被限制在预定义的“决策维度 + 模板”中，如果接口没有显式可观察的任务选择，或系统输出的决策维度无法被枚举，UMPeek 可能矮化或遗漏某些用户模型内容。
- **有效性边界未被严格刻画**：论文未系统分析在哪些条件下（如自由度极高的开放式对话、无工具选择的纯闲聊式智能体、响应误差较高）攻击会快速退化，只给出了经验表格，缺少理论分析或更细粒度的边界探索。
- **语义推断与参考声明的匹配口径欠精细**：UMR-F1 采用确定的类别感知词法匹配（token 重叠 ≥ 0.72 等简单启发式），对于同义改写复杂、跨语言或抽象程度高的声明可能出现低估或误判；论文未与人工判定的相关性做核对。
- **真实世界验证仅覆盖“已保留”目标**：所有第三方平台实验有条件地只统计被确认保留的信息，因而马赛克式的数字反映的是“行为侧恢复的比例”而非该平台的绝对泄露率，普通读者容易误读为系统整体风险。
- **防御实验采用模拟平台及合成数据**：三大防御都在本地基准的后端上进行验证，没有在真实商用平台端到端部署实测；对 Stateful Counterfactual 的现实可实施性（需要无偏的个人化/非个人化对照输出）未做充分讨论。
- **可推广条件**：攻击假定同一用户信息会影响多个域内普通任务且系统采用贪心解码，对随机性较强的模型输出或高度多样化的提示词分布可能不满足；论文没有在多轮间提示分布改变时给出保证。
- **伦理双用途风险的自认**：论文在附录中承认该方法具有“双用途”，可用于真实用户系统性推断和行为画像；虽然做了大量合规约束，但其面向真实用户群体的潜在威胁尚未完全消解。
- **算力与成本数据缺失**：未报告每条攻击的平均请求数与计算开销、GPU 占用或成本，影响实际威胁建模中“攻击性价比”的判断。
