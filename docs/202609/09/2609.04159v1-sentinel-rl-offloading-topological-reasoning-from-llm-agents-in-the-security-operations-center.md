## 摘要
大型语言模型（LLM）代理越来越多地被提议作为自主SOC分析师，但两个限制使它们在企业规模下不可靠：有限的上下文窗口无法容纳包含数千台主机的认证图，而自由形式的生成无法保证推荐的安全遏制措施与其所操作的拓扑结构一致。我们提出了Sentinel-RL，一种将拓扑推理与语义推理解耦的代理型SOC架构：异构图注意力编码器将实时认证子图总结为固定维度的状态，近端策略优化（PPO）策略将该状态映射到一组受限的调查动作，LLM代理循环被限制为仅消费策略的推荐并产生由评论家门控的分析师可读叙述。我们在LANL综合多源网络安全事件数据集和印第安纳大学Quartz HPC集群上实例化了该系统，并报告了四项结果：（i）两阶段CREATE摄取模式在单个32核节点上以14.2分钟将24M边认证子图加载到Neo4j中，比基于MERGE的常规管道快约24倍；（ii）滑动窗口警报引擎在50次试验中可靠地在≤2.5秒内触发25事件/10秒阈值；（iii）PPO训练在200次迭代中收敛到平均情节回报8.74±0.31，在标记的红队事件上保持精确度0.91和召回率0.87；（iv）集成遏制循环在中位数6.3秒内完成完整的检测-调查-推荐-人工批准周期。我们贡献了可复用的工程模式（热节点死锁变通方案）、可移植的HPC部署模式（锚节点共置）以及涵盖误报经济学、可逆性保证、审计合规性和人工批准边界的企业准备度分析。

## Abstract
Large language model (LLM) agents are increasingly proposed as autonomous SOC analysts, but two limitations make them unreliable at enterprise scale: a finite context window cannot hold a multi-thousand-host authentication graph, and free-form generation offers no guarantee that a recommended containment action is consistent with the topology it operates on. We present Sentinel-RL, an agentic-SOC architecture that decouples topological reasoning from semantic reasoning: a heterogeneous graph attention encoder summarizes the live authentication subgraph into a fixed-dimensional state, a Proximal Policy Optimization (PPO) policy maps this state to a constrained set of investigative actions, and an LLM agent loop is restricted to consuming the policy's recommendations and producing analyst-readable narratives gated by a critic. We instantiate the system on the LANL Comprehensive, Multi-Source Cyber-Security Events dataset and the Indiana University Quartz HPC cluster, reporting four results: (i) a two-phase CREATE ingestion pattern loads a 24M-edge authentication subgraph into Neo4j in 14.2 minutes on a single 32-core node, roughly 24x faster than the canonical MERGE-based pipeline; (ii) a sliding-window alert engine reliably trips a 25-event/10-second threshold in <=2.5 s across 50 trials; (iii) PPO training over 200 iterations converges to a mean episodic return of 8.74+/-0.31, with held-out precision of 0.91 and recall of 0.87 on labeled red-team events; and (iv) the integrated containment loop completes a full detect-investigate-recommend-human-approve cycle in a median of 6.3 s. We contribute a reusable engineering pattern (the hot-node deadlock workaround), a portable HPC deployment pattern (anchor-node co-location), and an enterprise-readiness analysis covering false-positive economics, reversibility guarantees, audit compliance, and the human-approval boundary.

### 1. 论文的核心问题与整体含义（研究动机与背景）

- **核心痛点**：现代安全运营中心（SOC）面临海量告警（每日10⁴–10⁵条）且多为误报，而传统LLM充当分析师的方式暴露两大结构性问题：

- **研究主张**：需要将复杂的拓扑推理从LLM中剥离出来，转为图编码器+强化学习策略负责决策、LLM仅负责语义说明的神经符号混合架构。

### 6. 主要结论与发现

1. **认知卸载的正确性**：将拓扑推理从LLM中解耦后，架构整体响应质量极高，且能通过较简洁的 RL 控制策略取代“隐式理解”；LLM 被“限制”在表达和解释，降低了生成误动作的概率。
2. **工程上可实现**：24M边认证图 14.2 分钟内完成摄取（传统 MERGE 需 21,600 秒小时级），达到约 24 倍并发吞吐加速。
3. **速度可满足实战**：检测器在 ≤2.45 秒 (p99) 触发告警；端到端闭环仅需 6.3 秒中位延迟，其中 GPT 叙事生成耗时最大（约3.78秒，占60%）。
4. **策略质量**：PPO 200 轮稳定收敛至 8.74±0.31 平均累计收益（理论最优9.0）；放外检测精度 0.91，召回 0.87，F1=0.89，为组内最高的精确率。
5. **可落地的工程模式**：两阶段 CREATE、锚节点共享方案、安全防护表面，是既具学术意义又可迁移复用的设计蓝图。

### 7. 优点与亮点

1. **架构设计的“脱钩”思路**：将异构大型图结构建模从 LLM 上下文窗口中剥离，交由图注意力网络和 RL 规划，分工明确、逻辑清晰、很有前瞻性。
2. **强化学习 + 图神经网络的自主决策闭环**：将 LANL 认证图建模为 MDP 并应用受限 PPO，方案新颖，行动空间固定且可审查。
3. **大规模图的工程实践详尽**：两个高效模式（两阶段插入、A-node 负载均衡）在高并发、图级冷启动等场景均有较强的可复用价值。
4. **详尽的端到端测量与记录**：提供延迟分解、RLlib 超参数映射表（Table I），部署难点和解决过程透明。
5. **对企业级应用的细粒度风险分析**：对误报经济学、可逆性、回滚脚本、沙盒验证、审计合规性落地措施配置有较系统的考虑。
6. **坚持真实世界基准而非模拟器**：采用 LANL 公开真实事件数据集，工程实现又解决高并发HPC等实际约束。

### 8. 不足与局限

1. **检测为“召回率较弱”**：0.87 召回率明显低于 PIKACHU (0.95) 和 LMDetect (0.99)，对于漏报风险高的场景（红队事件）需加强。
2. **无法计算“全环境图”**：每次决策仅关注被标记节点的 2-hop 邻域，针对攻击者多跳跳板、跨多主机扩散的场景存在信息不完整性。
3. **训练及评估的算力覆盖面窄**：虽然未使用GPU，但训练具体时长未提供，也没有展示分布式横向扩展基准。
4. **缺少自博弈对抗验证**：对提示词注入、Critic绕过、策略被污染的情况，缺乏安全对抗性评估；护栏机制的验证以设计及代码层面的定性描述为主，不支持已覆盖真实对抗攻击的强证据。
5. **LLM 相关技术参数未知/未公开**：使用的具体LLM（如LLaMA 3 8B等）和具体版本未指明；对“Critic Agent”的提示词、判断失败如何影响最终输出均未分析。无法复现用该提示词组合的整套系统。
6. **agent 策略与具体域绑定**：SOTA对比所引用论文参数的统计数据大多基于不同时间窗整理（不同评估窗口对齐），直接跨纸对比前需谨慎。
7. **未讨论检测失败后的流程**：若策略给出的 TerminateAndOutputVerdict 错误，如何恢复、是否需要人工再检查，设计上一笔带过，实际应用可靠度有待演示。
