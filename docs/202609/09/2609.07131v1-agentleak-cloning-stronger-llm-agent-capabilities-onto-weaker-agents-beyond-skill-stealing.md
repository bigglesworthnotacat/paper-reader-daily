## 摘要
大型语言模型（LLM）智能体日益通过将基础模型与显式技能和通过执行获得的隐式程序知识相结合，来完成长期任务。由此产生的任务解决能力已成为宝贵的专有资产，引发了一个新的安全问题：一个能力明显较弱的攻击者控制的智能体能否通过有限的黑盒交互获得更强的专有智能体的能力？现有的技能窃取攻击能够恢复显式技能工件，但我们表明，工件泄漏并不一定能转移能力：较弱的智能体可能拥有相同的技能，但仍然失败，因为它缺乏由较强智能体隐式实现的程序化行为。我们的关键见解是，技能执行差距本身构成了泄漏面，缺失的行为通过受害者成功执行与攻击者失败执行之间的可观察差异而暴露。基于此，我们提出了AgentLeak，一种黑盒能力克隆攻击，它从这些执行差异中识别出能力关键行为，并将其整合到攻击者侧技能中，同时保持攻击者的模型、运行框架和工具不变。在包含600个实例、多种智能体系统和多个骨干模型的20个任务场景中，与直接技能重用相比，AgentLeak将任务通过率提高了超过40%，并恢复了超过80%的受害者-攻击者能力差距。我们的发现揭示了LLM智能体中的机密性风险：仅保护显式工件是不够的，因为可观察的执行行为会泄露在低能力和攻击者控制的智能体中重建专有任务解决能力所需的程序性知识。

## Abstract
Large language model (LLM) agents increasingly achieve long-horizon tasks by combining foundation models with explicit skills and implicit procedural knowledge acquired through execution. The resulting task-solving capabilities have become valuable proprietary assets, raising a new security question: can a substantially weaker attacker-controlled agent acquire the capabilities of a stronger proprietary agent through limited black-box interaction? Existing skill-stealing attacks recover explicit skill artifacts, yet we show that artifact leakage does not necessarily transfer capability: a weaker agent may possess the same skills but still fail because it lacks procedural behaviors implicitly realized by the stronger agent. Our key insight is that the skill execution gap itself forms a leakage surface, where missing behaviors are exposed through observable differences between successful victim executions and failed attacker executions. Based on this, we present AgentLeak, a black-box capability-cloning attack that identifies capability-critical behaviors from these execution differences and incorporates them into attacker-side skills, while keeping the attacker's model, harness, and tools unchanged. Across 20 task scenarios comprising 600 instances, diverse agent systems, and multiple backbone models, AgentLeak improves task pass rates by over 40% compared with direct skill reuse and recovers more than 80% of the victim--attacker capability gap. Our findings reveal a confidentiality risk in LLM agents: protecting explicit artifacts alone is insufficient, as observable execution behavior can leak the procedural knowledge required to reconstruct proprietary task-solving capabilities in low-capability and attacker-controlled agents.

- **核心问题**：**“直接窃取更强智能体的技能，能否将其任务解决能力迁移到明显较弱的智能体上？”** 论文通过动机实验给出了否定答案：仅复制技能到较弱智能体，任务通过率提升有限；即使将轨迹蒸馏成技能（Trace2Skill），也无法消除差距。由此引出能力泄漏与技能泄漏的根本区别。
- **整体含义**：论文发现了一个全新的安全泄漏面——**技能执行差距（skill execution gap）**。较强智能体在执行中隐式展现的任务分解、工具选择、反馈处理和结果验证等行为，虽然不在显式技能工件中，但会通过可观察的执行轨迹暴露出来。论文的核心论点是：**在“强到弱”场景下，保护显式工件（模型、提示、技能）本身不足以保证能力安全，可观察执行行为会泄漏重建专有能力所需的过程性知识**。

## 2. 论文方法论

### 2.1 核心思想

AgentLeak 的核心洞察是：**受害者智能体成功执行与攻击者失败执行之间的差异，暴露了攻击者缺失的能力关键行为**。通过把这些缺失行为外部化并编码为技能，较弱的攻击者可以在不更换模型、平台和工具的前提下弥补能力差距。攻击者只修改本地技能集，本身能力可以从无技能状态开始。

### 2.2 系统模型与威胁模型

- 智能体定义为 \(A = (M, H, U)\)——底层语言模型、智能体执行框架、外部工具。
- 任务通过率定义：\( Capa(A, K_s, D_s) = E[V_{s,i}(Exec(A, K_s, t_{s,i}), y_{s,i})] \)。
- 攻击者只具备黑盒交互能力（提交有限数量的实例并观察正常界的执行证据），不可以访问受害者私有技能、参数、隐藏推理或内部状态；只允许改动自己的技能集。

### 2.3 AgentLeak 四阶段迭代重构流程

采用“失败驱动迭代优化”机制，每轮对受害者与攻击者的轨迹进行对比分析，将发现的缺陷转换为技能更新：

1. **工作流抽象与技能映射（Workflow Extraction and Skill Mapping）**：从成功受害者轨迹中提取符合整体场景的可复用工作流技能 \(K^wf_s\)，由执行结构、验证标准、技能映射和后续调整指南四部分组成。为后续诊断提供执行参照，解决“相似技能但组织不好执行”的问题。
2. **差分能力缺陷诊断（Differential Capability-Deficit Diagnosis）**：以工作流为基线，将受害者的成功轨迹与多次攻击者的失败轨迹做对比，区分真正的能力缺陷和正常的任务变异。诊断输出的每一项缺陷都记录：受影响技能、失败症状、根因、重要性和统计频次，区分新缺陷与复发缺陷。
3. **行为原始抽取（Behavioral Primitive Extraction）**：将诊断得到的缺陷转化为带过程性的操作准则，说明应引入、强化或纠正什么缺失行为，并注明预期的能力改善效果。该步强调抽取可复用的程序化改进，防止直接复制专有轨迹中的任务特异性行为。
4. **结构化技能重写（Structured Skill Rewriting）**：生成局部的“补丁”，仅通过插入或替换两种操作修改对应技能片段，保留原有有效的技能内容，避免全量重建引起的回归。

迭代过程中，每一轮失败后重复步骤2—4；更新后的技能重新执行，直至实例成功或预算用尽（算法预算默认多轮），最终对已有实例做回归验证后得到技能集 \(K^*_s\)。

## 3. 实验设计

### 3.1 基准数据集与场景

- **场景构建基准**：选用 **SkillsBench** 中的 20 个任务场景，覆盖**6 个应用领域**（办公文书、软件工程、金融经济、自然科学、工业物理系统、数学与形式推理）。
- **扩展实例**：因为 SkillsBench 原始每个场景只有 1 个实例，不足以区分真实能力提升跟记忆单一实例。论文对每个场景构造 **30 个实例**，共 **600 个实例**。实例由 LLM 生成单/双属性变化，兼顾指令变化、环境参数、数据取值等因素，手工校验后保留，最大程度保持相同的任务核心要求。每个场景保留 1 个作为重建时的查询，另外 29 个用于测试集，测试实例在技能固定后才能用于最终评测。

### 3.2 受害者和攻击者设置

- **受害者（强）**：4 个系统——Claude Code + Claude Opus 4.8；Codex + GPT-5.5；OpenHands + DeepSeek-V4-Flash；OpenHands + MiniMax-M3。
- **攻击者（弱）**：OpenHands，分别使用 Qwen3.6-35B-A3B 与 Gemma 4-31B 两个弱开源模型（模型、框架、工具固定不变）。
- **辅助分析模型**：GPT-5.6 作为不参与执行的分析助手，仅用于离线分析和技能生成。

### 3.3 对比方法

- **No Skill**：无外部技能的弱智能体基线。
- **Raw Skill**：直接复用被窃取的原始技能集的弱智能体。
- **Trace2Skill**：代表“自演化型”技能的强基线——从攻击者自身轨迹提取技能学习改进。
- **Victim w/ Skill**：带原生技能的受害者原始能力上限。

### 3.4 评估指标

- **Instance Pass Rate（IPR）**：未见过任务实例的通过率，反映能力实际提升幅度。每个场景的每个测试实例独立执行3次取平均。
- **Capability Recovery Rate（CRR）**：恢复受害者与无技能弱智能体之间差距的比例：\(CRR_s = (IPR_{AgentLeak} − IPR_{NoSkill}) / (IPR_{Victim} − IPR_{NoSkill})\)。

### 充分性和共享性评估

实验设计较有诚意：

## 6. 主要结论与发现

- **发现一**：直接重用被窃技能无法把能力转移到弱小智能体，Raw Skill 在 Qwen3.6-35B 上仅恢复 17.38%–19.61% 的能力差距。
- **发现二**：现有单纯轨迹驱动的方法（如 Trace2Skill 自演化技能）也无法恢复隐式能力关键行为，IPR 约为 28.81%–34.96%。
- **发现三**：AgentLeak 在全部主配置下达到 70% 以上的 IPR，相比 Raw Skill 与 Trace2Skill，在通过率上提升超过35–40个百分点；按 CRR 度量恢复能力差距普遍超过 85%，甚至多个场景超过100%（比受害者表现还好）。
- **发现四**：重构出的技能具有跨模型、跨框架的迁移性，跨框架转出后IPR提升至约84.68%，说明学到的确实是可泛化的过程性知识而非记录观测特征。
- **发现五**：工件级防御（输入检测器、SkillGuard、语义过滤）不能阻断能力克隆；只有行为级信息控制（轨迹约减）的效果更显著但也不足以完全消除泄漏。
- **发现六**：防御结果表明保护 LLM 智能体的机密性应至少覆盖“执行行为”，而不止是显式工件。未来安全研究需考虑行为披露控制。

## 7. 论文优点

AgentLeak 的目标主要是演示一个新颖且概念上有深度的安全攻击，且有很强的实践指向性。可从以下视角审视其优势：

- **概念原创性：系统区分了“技能工件泄漏”与“能力泄漏”**。此项区别比此前泛泛而谈的“技能提取”更准确，直击专有LLM智能体真正价值所在——通过固定模型达到的高完成率。
- **威胁模型更贴近实际工业部署**：攻击者无需高额训练或对齐，仅黑盒查询一两个任务实例和修改技能文件即可实现能力克隆，揭示了比模型盗取更实际的高性价比途径。
- **结构性良好的四个组件**：工作流引导的差距诊断在整个过程中起基准线作用；结构化“补丁”小步修改减少了全局重写导致的脆弱性；组件缺失实验证明每一部分都不是装饰品。
- **评估覆盖面较大**：8组受害者/攻击者组合 × 20场景 × 600测试实例的规模在LLM智能体安全攻击工作中算充分；同时用3次重复执行做噪音平滑。
- **迁移和防御研究拓展了问题深度**：验证攻击显著迁移——几乎把能力推广问题做了系统化探索；工件级防御失效实验对未来防范机制研究很有指导意义。
- **成本分析清晰**。可以依此评估攻击的可行性，为后续防御研究提供量化基线。

## 8. 不足与局限

- **数据场景覆盖仍然偏窄**：虽然领域涵盖办公、金融、自然科学等，但多数场景都以文件处理、数值解析、软件工程内固定的确定性任务为主；缺乏需要持久记忆、实时网页交互、多智能体协作或个性化用户偏好的外部研究场景。
- **实例构造存在同类化风险**：虽然30个实例的目标是验证“归纳能力”，但大部分变化只是数值、文件名或内容变化，导致任务集本质上是单工作流的重复演绎，可能只验证“技能内调整”是否学习到，而不一定是真实的开放世界泛化能力。
- **指标口径具有一定偏向性**：IPR和 CRR 完全基于显式验证器返回的二值成败结果，未核算过程的质量或任务部分完成分数，操作类和模糊类任务上的实用能力提升程度并没有比较全面体现。
- **无法覆盖能力受物理或私有资源约束的场景**：对依赖私有数据库、感染者专属工具或内部知识的任务，AgentLeak不能重构，因为有可参考的真实轨迹也无法获得相应的关键信息。在完全黑盒但只有最终结果而不给轨迹的环境也不可行。
- **防御对查询与执行的区分证据不足**：论文只测试了少量既定检测/红action机制，没有进行更强大的“攻击意图识别”防御、随机轨迹采样防御等系统的对抗搜索。
- **未提供可复现性核心代码库和精确提示模板文本完整清单**，附录仅给出提示模板说明，不利于技术审计与复现设计验证。
- **绕过可能性存在未分析盲区**：攻击流程高度依赖弱模型将复杂技能准确应用到真实环境的动作水平，实验尚未说明多大程度的技能需要重新改写才能让弱模型真正遵守——现实中大指令集下，弱模型的遵守率可能会大幅下降。
