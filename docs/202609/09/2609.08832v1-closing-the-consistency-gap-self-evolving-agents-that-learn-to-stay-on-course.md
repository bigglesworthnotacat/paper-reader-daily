## 摘要
大型语言模型（LLM）驱动的智能体在平均表现上可能准确，但在实际生产中却不可靠，这种差异虽已被观察到，但在很大程度上仍未得到解决。当同一任务被重复执行五次时，使用GPT-4.1在AppWorld基准上的ReAct智能体在所有五次运行中全部成功的概率仅为53%，尽管其单次运行的平均通过率高达77%。我们将这24个百分点的差距称为一致性差距，并认为弥补这一差距是实现可信赖AI智能体部署的先决条件。我们提出了一种自进化智能体框架，通过识别智能体轨迹中不稳定、低一致性的步骤，并将其转化为未来运行中智能体可调用的情景记忆，从而缩小这一差距。其核心是一个一致性分析器，用于精确定位轨迹在执行过程中可能翻转的位置及原因；以及一个指导原则生成器，将诊断结果转化为有针对性的指导原则，存储到记忆中，并在未来类似任务的智能体执行中注入。在AppWorld上结合ReAct/GPT-4.1，我们的框架将全五次运行成功的任务比例提升了16个百分点（同任务评估）和13个百分点（相似任务泛化）。

## Abstract
Large language model (LLM)-powered agents can be accurate on average yet unreliable in production, a discrepancy that has been observed but remains largely unaddressed. When given the same task five times, a ReAct agent on the AppWorld benchmark using GPT-4.1 succeeds in all five runs only 53% of the time, even though its per-run pass rate averages 77%. We call this 24-point shortfall the consistency gap, and we argue that addressing it is a precondition for trustworthy AI agent deployment. We present a self-evolving agent framework that reduces this gap by identifying unstable, low-consistency steps in agent trajectories and converting them into episodic memory the agent can draw on in future runs. At its core is a Consistency Analyzer that pinpoints where and why a trajectory is likely to flip across executions, and a Guideline Generator that converts the diagnosis into targeted guidelines, committed to memory and injected into future agent executions on similar tasks. On AppWorld with ReAct/GPT-4.1, our framework raises the fraction of tasks that succeed in all five runs by +16 points on same-task evaluation and +13 points on similar-task generalization.

## 1. 核心问题与整体含义

论文聚焦 LLM 智能体在生产环境中的"平均正确但单次不稳定"问题：

- **现象**：同一智能体在执行同一任务时，多次运行结果不一致。例如在 AppWorld 基准上，ReAct/GPT-4.1 的单次平均通过率（Mean@5）为 77%，但同一个任务连续 5 次全部成功（Pass^5）的比例仅为 53%，两者相差 **24.4 个百分点**。
- **问题命名**：论文将这一差距正式定义为 **consistency gap（一致性差距）**，认为弥合此差距是智能体从"可演示"走向"可部署"的先决条件。

## 2. 论文提出的方法论

### 2.1 总体框架：自进化系统

框架基于"检测—生成—记忆—注入"四个环节构成两个闭环：

- **运行环（operational loop）**：智能体执行任务，可选地携带记忆库中检索出的准则；观测层记录完整轨迹。
- **离线分析环（offline analysis loop）**：分析已记录的轨迹，产出新准则，写入情景记忆。
- **核心创新**：在既有 trajectory-informed memory（Fang et al., 2026）基础上，新增一个**一致性导向的生成信号层**，不再仅依赖 LLM 对"成败"的自我判断，而是由步骤级一致性驱动指导原则的生成。

### 2.2 一致性分析器（Consistency Analyzer）

- 纯黑盒：不读模型 logits 或内部状态，只重发放记录过的 prompts，适用于任何托管 LLM 端点。
- 针对每个推理步骤 si，用同端点重采样 **N 次**（默认 N=30，温度 ≤ 0.5），得到响应集合，再计算步骤一致性 C(si)：
  - **自由文本/代码**：SBERT 编码后平均两两余弦相似度；
  - **分类值**：平均两两 Jaccard 相似度（含 API 名、参数对）；
  - **半结构化响应**（如 JSON）：按字段拆分后加权求和。
- 轨迹级一致性 C(T) 为步骤值的均值聚合。
- **关键技术动机**：即使温度=0 时，托管平台上的浮点噪声、批处理波动等可使接近平局的 token 分布翻转，因此贪心解码解决不了问题；一致性需通过重采样估算语义层分布的集中度。

### 2.3 指导原则生成器（Guideline Generator）

- 对 C(si) 低于阈值 θc = 0.85 且有决策路径影响的步骤进行标记；
- LLM 按三类语义生成准则：
  - **strategy**：高变异但方向正确——固化正确行为；
  - **recovery**：变异与失败相关——指导绕开风险步骤；
  - **optimization**：精简非必要的高变异步骤；
- 生成的准则带有类别/优先级/上下文来源等元数据，经查重后由向量相似度检索注入后续相似任务 prompt。

## 3. 实验设计

- **主基准**：AppWorld（Trivedi et al., 2024）test normal split，共 168 任务，分为 Easy/Medium/Hard（57/48/63 个）。
- **智能体**：ReAct；backbone 为 GPT-4.1（Azure 云端）与 GPT-OSS-120B（AWS 托管）。
- **评估指标**：Pass@5（至少成功一次）、Mean@5（平均成功率）、Pass^5（全部成功）与新提出的 Consistency@5=Pass^5/Mean@5；每个任务跑 k=5 次。
- **主要实验组**：
  - 基线（无准则）vs. Same-task guidelines（从同任务一条基线轨迹生成准则再重跑）；
  - Similar-task generalization：利用 AppWorld 场景分组，从 v1 变体生成准则注入 v2、v3，共 336 次评估；
  - 用 50 个 challenge 任务做 AUROC 分析，检验轨迹一致性分数与真实 pass/fail 的关联。
- 未做 ablations（未考察每种一致性度量独立贡献、未消融 N 值、阈值 θc 与重采样温度）。

## 4. 资源与算力

- 所有实验在**云端模型端点**上完成：GPT-4.1 on Microsoft Azure、GPT-OSS-120B on AWS；

已做实验：

- 2 个后端模型 ×（1 基线 + 1 同任务 + 1 相似任务）= 6 组完整对比，分 4 个难度细目；
- 同任务与相似任务共约 500+ 次任务的重复执行观测；
- 50 个 challenge 任务的 AUROC 评估；
- 难度维度（easy/medium/hard）与模型能力差异（GPT-4.1 高能力 vs. GPT-OSS-120B 低能力）均有覆盖。

不足点：

- 只有 AppWorld 单一基准、单一 ReAct 架构，无跨任务域、无跨智能体框架评估；对 CUGA 等架构仅提及未量化；

- 一致性与 pass/fail 的 AUROC 仅约 0.69，属于"可接受但有限"的预测强度。

## 6. 主要结论与发现

- **一致性差距事实**：GPT-4.1 绝对差距 24.4 pp，易→难单调上升（17.5/25.0/30.2）；GPT-OSS-120B 因难度均分太低，在难任务上差距反而受能力上限压缩，凸显出"归一化一致性 Consistency@k"指标的必要性。
- **框架有效性**：
  - GPT-4.1：同任务 Pass^5 由 53.0% → 69.0%（+16.0 pp），相似任务 → 66.0%（+13.0 pp），Mean@5 不降反升；
  - GPT-OSS-120B：同任务 Pass^5 +6.0 pp，相似任务 +8.7 pp；Hard 上归一化一致性从 0.00 升到 0.29；
  - 所有难度上一致性差距均有实质压缩。
- **轨迹级一致性可作为弱结果预测器**：AUROC ≈ 0.699，可在无 ground-truth 中辅助生成器判断成败。

## 7. 优点

- **问题定义清晰有力**：将"泛化/能力"与"可重复/可靠性"分开，用 Pass^5 归一化 Consistency@k 区分能力上限与变异，术语可复制性强。
- **方法架构上的通用性**：黑盒重采样 + prompt 级注入，不接触推理内核，不依赖梯度，适配于现有基于 API 的任意 LLM 智能体。
- **记忆与诊断解耦的设计合理**：把一个模糊的"失败"信号细分为具体"哪一步会在什么情况下翻转"，再生成微观、人类可读的准则。
- **对"为什么温度 0 不解决不一致性"的分析深刻**：追溯到概率分布扰动而非解码路径，抓住了云端端点非确定性的本质。
- **评估存在跨难度的证据精细度**：easy/medium/hard 各自报告，避免平均掩盖模式。

## 8. 不足与局限

- **基础假设不可控**：Pass^5 基线/实验对比依赖平台非确定性一致的前提，但作者明确称无法测量或控制。
- **分析器不是验证器**：只判断稳定性，不判断正确性;"自信但错误"的步骤会被视为一致，甚至被固化进 memory。
- **成本门槛高**：默认每次重采样 N=30 乘以每条轨迹的步数，token 成本最高放大 30 倍；未给出自适应算法。
- **泛化结论范围有限**：只在 1 个领域、2 个模型、1 种 ReAct 框架内定量;跨模型族、跨智能体架构（如已有 policy memory 的 CUGA）尚未开放验证。
- **同类工作的比较缺失**：文中仅与 Jha et al.(2026)和 Ye et al.(2026)进行范围性对比，缺少同行实验数据上的横向对比。
- **多准则干扰问题未处理**：准则累积会导致冗余甚至相互矛盾，虽然提到 Fang et al.(2026)的处理机制，但未单独量化和验证准入准则的有效性上限。
- **未报告智能体步数与开销结构的细节**，如步数和 token 分解、推理时间等生产化必要指标缺失。
