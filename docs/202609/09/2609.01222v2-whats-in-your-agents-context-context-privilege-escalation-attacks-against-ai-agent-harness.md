## 摘要
现实世界中备受瞩目的AI智能体框架通常依赖供应商专有或不透明的设计来进行上下文组装，导致组装上下文的来源和底层逻辑难以被理解，由此产生的安全风险也很大程度上未得到探索。在本文中，我们首次对现实世界AI智能体框架中的上下文组装设计进行了系统性分析。我们研究并揭示了智能体框架如何设计来从不同来源收集和组装上下文，并识别出这些设计所引发的一系列实际攻击向量。我们的分析揭示了现实世界框架的上下文组装中两类新颖的攻击：(1) 消息角色上下文特权提升（M-CPE），当源自低特权上下文的攻击者控制内容被并入更高特权的消息角色时发生。(2) 跨范围上下文特权提升（X-CPE），当攻击者控制的内容在引入它的上下文之外持续存在时发生。我们对包括Claude Code和Codex在内的12个现实世界智能体框架进行了CPE攻击的系统性安全分析。其后果包括全面智能体失陷、远程代码执行、拒绝服务以及被操纵的工具或技能调用等。

## Abstract
Real-world, high-profile AI agent harnesses often rely on vendor-proprietary or opaque designs for context assembly, leaving the sources and underlying logic of assembled context poorly understood and the resulting security risks largely unexplored. In this paper, we present the first systematic analysis of context assembly designs in real-world AI agent harnesses. We study and uncover how an agent harness is designed to collect and assemble context from diverse sources, and identify a set of practical attack vectors arising from these designs. Our analysis brings to light two novel categories of attacks in the context assembly of real-world harnesses: (1) MessageRole Context Privilege Escalation (M-CPE), which occurs when attacker-controlled content originating from a low-privileged context is incorporated into a higher-privileged message role. (2) Cross-Scope Context Privilege Escalation (X-CPE), which occurs when attacker-controlled content persists beyond the context in which it was introduced. We performed a systemic security analysis of the CPE attacks against 12 real-world agent harnesses, including Claude Code and Codex. The resulting consequences include full agent compromise, remote code execution, denial of service, and manipulated tool or skill invocations, etc.

# 论文详细总结

## 1. 论文的核心问题与整体含义

- **背景**：AI agent（如 Codex、Claude Code、Gemini CLI 等）在现代软件开发与自动化任务中广泛应用。一个完整的“AI agent”既包括大语言模型（LLM），也包括围绕模型的“agent harness”（智能体框架），后者负责收集、组装并维护每次提交给 LLM 的“上下文”（context）。
- **问题**：实际生产环境中的 agent harness 对上下文的组装机制往往是厂商私有或不透明的——哪些来源加载、何时按何种逻辑加载、赋予什么特权角色，用户甚至恶意行为者都难以看清。既有安全研究多关注单点数据源（如第三方工具输出、Web 页面）的间接提示注入，但缺少对 **agent context assembly（上下文组装）整体设计**的系统性安全分析。
- **整体含义**：本文提出并系统研究了两类新的攻击——**消息角色上下文特权提升（M-CPE）** 与 **跨作用域上下文特权提升（X-CPE）**。攻击者可通过使低特权上下文中的恶意内容传播到高特权或高持久性的上下文源，从而操纵 agent 决策、绕过沙箱、获取远程代码执行甚至完全控制主机。这项工作将挖掘对象从模型与提示本身转向了 agent 框架的上下文组装层，为构建安全的 agent 系统提供了新的认识。

## 2. 论文提出的方法论

- **形式化建模**：将 agent 的上下文视为多个“消息”子组件的集合，每个来源 \(S_k = (s_k, \rho_k, \sigma_k)\)，其中：
  - \(s_k\) 为内容；
  - \(\rho_k\) 为消息角色（\(r_0\)最高优先级到\(r_4\)最低优先级，映射自各 LLM 厂商的 role 体系，如 OpenAI 的 system/developer/user/assistant/tool，Anthropic 与 Google 的对应结构）；
  - \(\sigma_k\) 为作用域（\(\sigma_{user} > \sigma_{project} > \sigma_{session}\)，表示源的影响范围）。
- **攻击定义**：
  - **M-CPE**：当恶意内容从低角色来源 \(S_j\)（如 tool 输出）传播到高角色来源 \(S_k\)（如 memory 文件、skill 描述）时，\(\rho_j < \rho_k\) 且内容相似/相同。
  - **X-CPE**：当内容从低作用域来源（如一次性 session 内容）传播到更高作用域来源（如 project 或 user 级 memory），即 \(\sigma_j < \sigma_k\)。
- **攻击向量分类学**：提出 **16 种攻击向量**，分为三类：
  - **A 类：多样化上下文源**（如 A-1 各厂商特定 memory 文件、A-2 memory 搜索目录、A-3 运行时内存加载、A-4 技能搜索路径、A-5 运行时技能发现、A-6 环境信息加载、A-7 递归 memory 导入）。
  - **B 类：上下文标记语法**（B-1 标记标签插入、B-2 标记标签解释，用于混淆 agent 自定义的 XML 式边界）。
  - **C 类：上下文组装逻辑**（C-1 memory 加载优先级、C-2 skill 加载优先级、C-3 skill 同名冲突消解、C-4 配置自修改、C-5 上下文源内嵌动作、C-6 上下文刷新、C-7 无沙箱内置工具）。
- **分析工具**：提出了 **CORA（Context Risk Analyzer）**，一种 LLM-assisted 的自动化分析管线：
  1. **静态识别上下文源**：用 LLM agent 探索项目结构、定位初始化边界、分析 API 端点配置，输出候选上下文源及其角色与作用域，同时识别标记语法。
  2. **运行时验证**：对目标 harness 进行插桩（hook 发送到 LLM 端点的请求），通过 canary 随机值标记不同源，再利用差分测试（不同启动目录、多轮启动）确定角色的真实作用域与角色。
  3. **CPE 路径枚举与验证**：对低特权源与高特权源配对，生成注入指令并执行两轮攻击：第一轮确认传播与写入，第二轮（清理低特权源后）验证注入指令是否被加载并产生实际行为。

该方法注重“识别与验证分离”——LLM 只负责启发式发现，最终验证采用确定性 canary 匹配和容器化执行，从而减少误报/幻觉。

## 3. 实验设计

- **研究对象**：12 个开源的高知名度 agent harness：Codex、Claude Code、Gemini CLI、Qwen Code、Kimi CLI、Aider、OpenCode、Cline、Goose、Pi-mono、OpenClaw、Hermes Agent。
- **使用的模型**：
  - 主导模型：GPT-5.5（CORA 内部分析用）与 GPT-5.4-mini 作为被评估 harness 的后端。
  - 额外：Claude Code 用 Claude Sonnet 4.6 / Opus 4.6，Gemini CLI 用 Gemini 2.5 Flash / Pro。
- **Ground truth 数据集**：人工（约 40 小时）手动分析 Codex 与 Gemini CLI，建立 30 与 42 个上下文源的基准，用于评估 CORA 的精度与召回率（prec/recall）。
- **benchmark 形式**：CORA 自动验证上下文源及其角色、作用域；再枚举 M-CPE/X-CPE 路径；最终在各 harness 上运行两轮攻击验证。没有传统对比基线（因这是首篇在该方向上的工作），而是对比了上述不同 LLM 后端指令跟随效果。

## 5. 实验数量与充分性

- **上下文源识别**：CORA 识别 463 个源，通过运行时验证了其中 282 个（排除 161 个被合理过滤与 20 个环境构建失败）。
- **角色与作用域统计**：282 个有效源按角色、作用域分布做了详细统计（系统 r0 183 个，用户 r1 60 个，助手 r2 9 个，工具 r3 30 个；作用域：user 74 / project 181 / session 27）。
- **CPE 候选路径**：共得 1761 条候选路径，其中 M-CPE 940、X-CPE 640、两者兼而有之 181。
- **攻击验证实验**：对 12 个 agents×多个模型共执行大量端到端攻击：
  - GPT-5.4-mini：1284 路径加载（73%）、1028 路径行为验证（58%）；
  - GPT-5.5：1315 加载（74%）、1034 验证（58%）；
  - Claude Code：Sonnet 78% 加载与验证、Opus 71%/61%；
  - Gemini CLI：Flash 88%/64%、Pro 80%/64%；
  - 各 agent 有详细的分项表（如 OpenClaw 468 条路径、Goose 244 条等）。
- **工具精度评估**：Codex 识别 precision 100%/recall 93%；Gemini CLI precision 97%/recall 91%。此外对过滤源人工复核：161 个中 156 个过滤正确，5 个为误漏（如 Aider 的 LANG 环境变量）。
- **充分性评价**：实验覆盖了多样的开源 harness、多种厂商模型、多个攻击向量和大量端到端路径验证，实验规模较为充分。同时作者也承认实验自动验证结果是“下界”——更精密的攻击者可能组合多个攻击向量提高成功率，且模型对齐能力与指令跟随差异会影响成功率，这说明结果仍然保守但客观。

## 6. 论文主要结论与发现

- 12 个主流 agent harness 的上下文组装普遍由大量不透明、异构的来源构成，**平均每个 harness 有 23.5 个已验证上下文源**，大部分以 system（r0，64.9%）等最高权限进入上下文，并且项目级/用户级持久作用域占多数（约 90.4%），使攻击者注入点更多且影响更深远。
- 不同 agent 对类似的来源（如 memory 文件）分配的角色、作用域与加载顺序并不一致，这种“无标准、不透明”的设计会给防御造成困难。
- **M-CPE 与 X-CPE 均真实可行**且可并发发生，可导致：
  - 完整 agent 失陷；
  - 远程代码执行（Claude Code 中恶意 skill 触发 shell 执行）；
  - 持久化配置修改（Cline 中写全局配置及 .windsurfrules 等系统级记忆）；
  - 跨项目/跨会话的上下文污染（Gemini CLI 中项目内恶意指令被写入 user 级 GEMINI.md）；
  - 自动化代码审查被误导（Codex 中 AGENTS.override.md 覆盖正常规则，放行含漏洞 PR）。
- 自动分析工具 CORA 能有效识别与验证上下文源及攻击路径，为后续研究提供了基础工具与数据。

## 7. 优点

1. **新颖性与系统性**：首次对 agent harness 的上下文组装设计进行系统性安全分析，发现了两类此前未被揭示的结构性特权提升威胁。
2. **形式化清晰**：将信息源、角色、作用域建模为可比较与可推理的矩阵，使“特权提升”在数学上有明确定义，便于后续自动分析。
3. **工具自动化与验证确定性结合**：CORA 采用 LLM 辅助静态识别 + 确定性 canary/插桩验证分离，降低 LLM 幻觉带来的误报，同时能跨语言、跨框架适用。
4. **攻击覆盖全面**：识别出 16 种攻击向量并给出分类，且对每个向量几乎都给出了真实 agent 上的端到端案例，加深了对攻击机制的理解。
5. **威胁模型现实且克制**：考虑了两类通用攻击者（恶意第三方内容、恶意第三方组件），没有假设攻击者能控制宿主机或模型，提高了结论实用性。
6. **负责任披露与防护建议**：向所有受影响厂商报告；提出类似软件物料清单（SBOM）的“上下文清单（context manifest）”以增强透明度，对工程实践有直接价值。

## 8. 不足与局限

1. **未能覆盖全部潜在攻击源与路径**：一些上下文源因无法被环境构建而未被验证；手动过滤的 161 个源中仍存在 5 个误判漏报（如 Aider 通过环境变量注入），说明自动化系统仍可被绕过模型。
2. **实验受模型与提示影响**：攻击成功与否高度依赖模型对注入指令的守从性，论文报告行为验证率约为 53–78%（因模型而异），表明部分路径只是“内容传播成功”但未必能触发恶意行为；真实攻击者可能使用更复杂的提示或多向量组合提高成功率，但文中没有系统研究这种组合增益。
3. **缺乏真实的“人类参与会话”长尾评估**：端到端场景多为预设流程，且没有模拟用户干预/纠错机制下攻击的鲁棒性；仅部分描述提到需用户批准某些操作，但在每次工具批准交互下的成功率未被量化。
4. **评估范围限于开源 harness 或可得版本**：部分 harness（如 Claude Code 源码来自 npm source map）不是典型开源，且结果只针对快照版本；厂商后续更新可能导致结论迅速过时。
