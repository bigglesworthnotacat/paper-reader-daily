## 摘要
随着大型语言模型（LLM）能力的日益增强，AI系统的长期价值不仅取决于解决单个请求，还取决于将经验和积累的知识转化为持久、可复用的能力。我们介绍了SimSkill，一个围绕城市交通仿真（SUMO）构建的自我进化智能体。SimSkill识别能力缺口，生成并解决基于环境的任务，通过行动-评论循环验证解决方案，并将经验整合到情景记忆、程序性记忆和语义记忆中，而无需更新主干模型。通过自主探索，它构建了一个覆盖交通仿真工作流的可复用库。我们在两个留出基准上使用三个主干LLM和独立的基于工件的验证来评估SimSkill。SimSkill将已验证的完成率提高了最多25个百分点，而消融实验显示程序性记忆和语义记忆具有互补贡献。其收益仍依赖于主干模型和预算：记忆并非对所有模型都有改进，也并非统一降低推理成本。更广泛地说，SimSkill展示了一种设计范式，其中自然语言保存和组合计算能力，而可执行工具和代码则提供精确且可复现的执行。所有代码和实验数据公开于https://github.com/qiliuchn/SimSkill-V1。

## Abstract
As large language models (LLMs) become increasingly capable, the long-term value of AI systems depends not only on solving individual requests, but also on transforming experience and accumulated knowledge into durable, reusable competence. We introduce SimSkill, a self-evolving agent built around the Simulation of Urban MObility (SUMO) traffic simulator. SimSkill identifies capability gaps, generates and solves environment-grounded tasks, verifies solutions through an action--critic loop, and consolidates experience into episodic, procedural, and semantic memory without updating the backbone model. Through autonomous exploration, it builds a reusable library spanning the traffic-simulation workflow. We evaluate SimSkill on two held-out benchmarks with three backbone LLMs and independent artifact-based verification. SimSkill improves verified completion by up to 25 percentage points, while ablations show complementary contributions from procedural and semantic memory. Its benefits remain backbone- and budget-dependent: memory does not improve every model or uniformly reduce inference cost. More broadly, SimSkill illustrates a design paradigm in which natural language preserves and composes computational capabilities, while executable tools and code provide precise and reproducible execution. All code and experimental data are publicly available at https://github.com/qiliuchn/SimSkill-V1.

## 2. 方法论：SimSkill 的自进化框架

### 2.1 总体思想

SimSkill 是一个**围绕 SUMO 交通仿真工具构建的自进化智能体（self-evolving agent）**。其不更新 LLM 骨干权重，而是通过“行为-验证-记忆”的闭环，将经验沉淀为系统外的结构化记忆。其架构建模了类似人类的三种记忆：**情景记忆（episodic）**、**程序性记忆（procedural）** 和 **语义记忆（semantic）**。在这个框架中：

- **自然语言**负责保存、归纳与组合“计算能力”（即描述“怎么解决一类问题”的方法学知识）；
- **可执行代码与工具**则提供精确、可复现的执行，避免自然语言带来的歧义与幻觉。

### 2.2 算法流程（结合摘要推断的文字描述）

SimSkill 的工作流程可概括为以下四个循环往复的阶段（受摘要表述“识别能力缺口→生成并解决环境所锚定的任务→行为-批评循环验证→记忆整合”的启发，具体流程细节文中应有完整描述，但本文提供的文本未展开全部步骤，以下为忠实概括）：

1. **能力评估与缺口识别（Capability Gap Identification）**：
   - 系统先在 SUMO 环境或任务库上尝试完成一系列代表性任务；
   - 通过失败信号或批评模块，识别当前技能库中未覆盖的“能力缺口”，从而确定下一个需要掌握的子技能。

2. **任务生成（Task Generation, 估计）**：
   - 针对识别出的缺口，智能体**自动生成与该缺口对齐的具体仿真任务**（例如“搭建某类路网的仿真并统计拥堵指数”）；
   - 生成的任务需要“环境锚定”（environment-grounded），即可以用 SUMO 环境真实验收。

3. **求解与行动-批评循环（Action–Critic Loop）**：
   - 智能体基于当前已有记忆（先验知识）生成候选解决方案，动作通常体现为生成 Python/XML/配置脚本或调用工具；
   - “批评（Critic）”模块对结果进行检查、运行、评估，指出失败原因；
   - 若失败则回到（生成/修复）步骤，通过多次迭代使方案通过环境验证——直至在验证性任务上形成可靠技能。

4. **记忆巩固（Memory Consolidation）**：
   - 经过验证的成功经验按类型写入系统记忆：
     - **情景记忆**：记录完整的历史经验与案例快照；
     - **程序性记忆**：保存可直接使用的可执行流程、代码模板、工作流脚本（“知道怎么做”）；
     - **语义记忆**：提取抽象的概念性知识、领域规律与事实（“知道是什么/为什么”）；
   - 上述过程**不更新骨干模型权重**。

5. **积累与复用（Reuse）**：
   - 多次在环境中自主探索后，SimSkill 构建起一个**覆盖交通仿真全流程的可复用库**；
   - 面对新的留出任务时，SimSkill 通过检索记忆库辅助推理，直接复用已验证的程序性技能以避免重复试错。

该范式属于非常典型的“**外部记忆驱动的持续学习**”架构：模型权重固定不变，所有知识更新发生在环境之外。

## 6. 主要结论与发现

1. **技能外储可行**：一个固定权重的 LLM 完全可以通过外部记忆机制逐步在特定领域（交通仿真）中自主积累可复用的执行能力，无需微调。
2. **显著性能提升**：相比于直接使用骨干 LLM 完成任务，加入 SimSkill 后可将验证完成率显著提升（最高可 +25 个百分点），表明“经验固化”能带来实际收益。
3. **两种记忆类型互补**：语义记忆（抽象规则/知识）用于指导“怎么思考”与“为什么”；程序性记忆（代码/工作流）用于精确执行与保证结果可复现——二者都不是冗余，割掉任何一支都会损失整体能力。
4. **收益有边界/条件性**：这不是对每个骨干模型的免费午餐——不同的 LLM 对记忆的可利用程度不一；同时记忆在并不总降低推理成本，或在某些情况下虽提高了完成率，却可能需要更多推理轮次（成本上的交换比不固定）。
5. **设计范式启示（更广义贡献）**：作者通过本系统试图传达的更大图景是——**“将自然语言作为灵活的计算组合介质，将可执行代码工具作为精确执行底座”**是构建可持续 AI 能力的有前途的架构方向。
6. **可复现与开放**：代码与实验数据已开源（GitHub: `qiliuchn/SimSkill-V1`）。

## 7. 优点与亮点

- **目标针对性强且前沿**：瞄准 LLM 时代的关键痛点——“单次求解 vs 持续积累”，专注于让 AI 走出“永远从零推理”的循环。
- **无需更新权重**：在安全和成本上显著优于 RAG/重训练之外的另一条轻量持续学习路径。不需要庞大的微调集群；代码复用、文档化、检索决策的方式完全可追溯。
- **三型记忆结构合理**：episodic + procedural + semantic 并存的思路类似于认知科学里的记忆系统分工，既保存上下文实例，又提炼通用技能，且很自然地引入了一个“知识工人”行为：写文档（语义）＋ 写可执行 API（程序性）。
- **验证协议客观**：基于工件的验证比 agent 自评可靠得多——只有真正能在 SUMO 中跑通的解决方案才算成功，降低了自评导致的表面虚假繁荣。
- **结论客观克制**：不回避“有时无效、有时增加成本”的现象，讨论较诚实；这种对方法“失效边界”的坦诚说明对整个社区是有价值的经验。
- **场景务实**：交通仿真是一个有着清晰 toolchain 的真实复杂场景——不像纯文字问答那样主观，很适合做这类机制研究；做出来的库（SUMO 工作流覆盖）也许可以简单落地复用。

## 8. 不足与局限

- **信息不完整导致的评估有限性**：本提供的文本缺少论文正式正文的实验表、对比基线详情、任务例图等，因此难以复核各关键结论的精确量化与全流程细节。
- **任务局限（仅限仿真器）**：方法效应在 SUMO 环境中验证，其中环境能提供明确的是非验证（运行成功与否），这比大多数开放域应用对“正确性判定”要求宽松；无法直接推广至“无真值、无可执行验证”的领域。
- **探索的自增强循环风险**：因为是“自主发现缺口并生成问题”，系统可能一而再地生成较简单的任务去迎合已有能力，而疏于挑战硬骨头，设计上如果没有更强的主动探索策略，技能获取可能存在路径依赖。
- **效果强依赖基线模型**：实验中有些骨干模型下提升不明显，说明技能库利用度与 LLM 底座读取、组合外部知识的能力高度耦合；弱的读取能力模型在同样框架下受益有限。
- **预算与时间成本非对称问题**：虽然完成率提升，但在推理token层面成本并不总是下降，甚至可能在“批评-修改”的主循环中消耗大量仿真token与运行时间（特别在自探索阶段）；单一视角下可能减弱其实用价值。
- **未更新权重，是否可能触及“能力天花板”**：如果不更新骨干权重，所能习得的过程可能只受限于原模型的表达与推理范围，无法获得完全“全新”的概念能力。
- **长期可拓展性未充分揭示**：三个记忆类别如果膨胀到成千上万条技能记录，检索与冲突管理将是一个未来瓶颈，论文从摘要未能看出对该问题的研究深度细节。
- **没有横向对表**：文中看不到对同代 AutoGen/Voyager/Reflexion 等类似代理框架的泛工程形经验保留方案的性能比较，这弱化了“相对其他同类方法谁更好”的判断。
