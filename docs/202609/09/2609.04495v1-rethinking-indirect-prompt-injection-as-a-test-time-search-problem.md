## 摘要
我们将间接提示注入表述为对由环境、用户任务和注入任务引发的任务相关攻击面进行测试时搜索的问题。为实施这一表述，我们引入了一个具有专用搜索框架的智能体攻击者，该框架执行环境侦察、对攻击策略的结构化推理，以及利用受害者智能体反馈的自适应评估。在异构任务中，我们发现增加攻击者的测试时计算量可提高漏洞发现和利用能力，而消融实验表明，显式策略管理对于避免冗余搜索并在更大预算下维持收益至关重要。这些结果表明，智能体安全评估应同时刻画攻击者的搜索过程和计算预算，而非将攻击成功视为受害者与预算无关的属性。更广泛地说，我们的发现将攻击者对系统攻击面的自适应搜索识别为工具使用智能体面临的重要且尚未充分探索的安全风险。

## Abstract
We formulate indirect prompt injection as a test-time search over a task-dependent attack surface induced by the environment, user task, and injection task. To operationalize this formulation, we introduce an agentic attacker with a dedicated search harness that performs environment reconnaissance, structured reasoning over attack strategies, and adaptive evaluation using victim-agent feedback. Across heterogeneous tasks, we find that increasing attacker test-time compute improves vulnerability discovery and exploitation, while ablations show that explicit strategy management is important for avoiding redundant search and sustaining gains at larger budgets. These results suggest that agentic security evaluations should characterize both the attacker's search procedure and compute budget, rather than treating attack success as a budget-independent property of the victim. More broadly, our findings identify the attacker's adaptive search over the system attack surfaces as an important and underexplored security risk for tool-using agents.

## 1. 论文的核心问题与整体含义

本文针对大型语言模型（LLM）智能体系统面临的**间接提示注入（Indirect Prompt Injection, IPI）** 安全威胁，提出了一个全新的理论视角。核心问题在于：现有的 IPI 研究（如 AgentDojo、InjecAgent、WASP 等基准）普遍将攻击建模为**静态评估问题**，即认为攻击的成功率是受害者模型的一种固定属性，与攻击者的搜索策略和投入的计算资源无关。这种视角忽略了 IPI 攻击的关键特性——攻击面高度依赖于环境、用户任务和攻击目标的组合，且攻击者可以自适应地迭代攻击策略。

论文的整体含义在于：**间接提示注入本质上是一个测试时搜索（test-time search）问题**——攻击者需要在一个由环境、用户任务和注入任务共同诱发的"潜在攻击面"上，搜索可实现恶意目标的攻击载荷。这一视角将攻击成功与否从受害者模型的"固有弱点"转移为攻击者搜索过程与计算预算的函数，呼吁安全评估应同时刻画攻击者的搜索流程与计算预算，而非仅将其视为模型属性。

## 2. 论文提出的方法论

### 核心思想

间接提示注入被形式化为对任务依赖攻击面（task-dependent attack surface）的测试时搜索。用户任务和注入任务的每种组合都会产生一个不同的良性工具调用轨迹，从而暴露不同的可被利用渠道，这些渠道共同定义了一个潜在的攻击面。攻击者在此攻击面上迭代搜索最优注入策略。

### 关键技术：智能体攻击者与搜索框架（Search Harness）

该方法的具体实现是一个由三个核心模块组成的"搜索框架"，装备于攻击者智能体上：

1. **环境探索（Explore Environment）**：提供两类侦察工具，帮助攻击者理解目标系统和攻击注入位置：
   - *环境知识工具*：捕获目标系统与任务的上下文和领域特定信息（如读取邮件、日历、产品、消息等）。
   - *注入向量知识工具*：描述每个候选注入位置（injection vector）的上下文和约束（如 `injection_email_body__<email_id>`、`injection_products_<product_id>_reviews_<index>_text` 等）。

2. **推理与搜索（Reasoning and Searching）**：为提升搜索效率，引入两个结构化工具：
   - *Strategy*：将攻击者的策略组织成层次化语义结构，实现搜索方向的管理。
   - *History*：记录搜索过程的细粒度轨迹，支持跨试验记忆，避免重复已失败的方法。
   - 这些工具共同支持迭代子空间识别与剪枝，使攻击者能集中资源在最有前景的攻击面区域。

3. **评估与反馈（Evaluation and Feedback）**：通过 `evaluate_injection` 工具在临时环境中实例化候选攻击并运行受害者智能体，返回：
   - 安全性分数（security score：攻击目标是否被执行）
   - 效用分数（utility score：原始用户任务是否仍完成）
   - 受害者工具调用轨迹（揭示哪些向量被实际读取）
   - 失败模式（如 WRONG_ARGS、ATTACK_ONLY、BENIGN_FAILED 等）

### 攻击流程

攻击者首先进行目标解析和环境侦察，随后在策略管理工具的指导下筛选有前景的子空间，通过 `evaluate_injection` 迭代提交候选载荷并根据受害者反馈调整策略，直至找到安全性和效用性均为真的载荷或耗尽 token 预算。

## 3. 实验设计

### 任务套件（Benchmark）

- **Workspace 套件**：采用自 AgentDojo，包含 **40 个用户任务 × 6 个注入任务 = 240 个任务对**，覆盖邮件、日历、云盘等工具。
- **Retail 套件**：由 Prime-style 环境生成器合成，包含 **17 个用户任务 × 8 个注入任务 = 136 个任务对**，覆盖零售市场的收件箱、商品目录、商品问答、审核等工具。

### 攻击面来源

- Workspace 具有 3 个不可信渠道：邮件（49 向量）、日历（41 向量）、云端文件内容（18 向量），共 108 个注入向量。
- Retail 具有 7 个不可信渠道：收件箱消息、商品变体备注、商品评论、商品问答、提问回复、公开简介、评论线程，共 139 个注入向量。

### 受害者与攻击者模型

- **受害者模型**：Claude Opus 4.8 和 GPT-5.5（均配置高推理强度，工具调用智能体）。
- **攻击者模型**：GLM-5.2（高推理强度，通过 Together AI API 提供）。

### 评估方法

- **主要指标**：ASR@T（在攻击者消耗 T 个 token 时的攻击成功率），反映测试时计算预算对攻击成功率的影响。
- 辅助指标包括联合成功率 JSR（攻击成功且用户任务完成）。

### 对比方法

由于是首个将 IPI 作为测试时搜索问题的工作，其主要对比并非不同攻击方法，而是通过**消融研究（ablation study）** 评估各组件的作用：
- *No-Harness*：移除侦察与搜索工具，仅直接评估。
- *No-Strategy*：保留侦察工具但移除策略管理工具（Strategy）。
- *Full-Harness*：完整方法。

## 6. 论文的主要结论与发现

1. **ASR 随测试时计算增加而升高**：增加攻击者的 token 预算可以持续提高漏洞发现和利用成功率，这与"攻击成功率是受害者固有属性"的既有认知形成对比。
2. **不同模型防御力差异显著**：GPT-5.5 明显比 Opus 4.8 更容易受到攻击，GPT-5.5 在约 50K tokens 时出现明显退化，而 Opus-4.8 在 500K tokens 时 ASR 仅为 20.6%。
3. **任务邻近性决定攻击效果**：成功的攻击倾向于利用用户任务流程中受害者本就需要读取的路径，而非任意载荷搜索。"任务相邻表面"是安全评估的关键维度。
4. **策略管理不可或缺**：显式策略管理可避免冗余搜索、支持多样化探索，使攻击效果能随更大预算不断增强；缺少这些工具时（No-Harness、No-Strategy），攻击性能会停滞。
5. **注入目标的"语义难度"是独立变量**：在 Workspace 中，安全码/凭证类外泄被高度抑制（ASR 0–2.5%），而简单状态变更（删除文件/发邮件）即使破坏性极高仍可达到 95–97.5% 的ASR。
6. **良性工具广度与 JSR 存在取舍**：工具使用越多元化，ASR 增加但 JSR 反而下降，因为附加注入操作容易使受害者无法严格满足原始任务的效用验证器。

## 7. 优点

- **视角创新**：将 IPI 从静态模型弱点重新定义为攻击者搜索流程与计算预算的函数，为评估智能体系统安全制定了更务实的框架。
- **方法论完备**：搜索框架的三组件设计（探索、推理、评估）在概念上清晰，容易适配不同任务套件（suite 套件差异通过 overlay 工具实现），具有较好的可迁移潜力。
- **实验分析深入**：不仅报告聚合结果，而是通过案例分析展示**攻击成功的关键是改变因果关系结构**（框架/上下文重构建）而非单纯优化措辞；对搜索行为的各维度（策略演化、推理消耗、预算意识、失败模式）进行了详实分析，增强了结论的可信度。
- **与现有威胁模型紧密相连**：实验验证了"注入目标与良性任务越兼容越容易成功"这一直观假设，并用自己的框架对不同类型的注入任务给出了"难度分层"。

## 8. 不足与局限

- **白盒假设限制**：攻击者可以访问整个环境（灰盒可见受害者工具知识），作者承认该设定"预期可迁移至黑盒设置但需更大计算成本"，然而并未系统验证这一迁移性。
- **合成环境有限**：实验使用两个合成任务套件，缺少真实生产环境的验证；合成数据可能高估或低估攻击的实际成功率。
- **模型覆盖不足**：仅使用两个受害者模型和一个攻击者模型，不同模型间的缩放趋势可能不能外推到其他 LLM 和智能体架构。
- **计算成本限制结论的统计强度**：800K token 预算在搜索中并不常见，且受成本限制没有进行充分的多次独立运行来量化不同任务对的随机误差；许多结论缺乏置信区间支撑。
- **预算截止效应**：多个失败任务对在 500K 预算耗尽时仍处于主动搜索阶段，意味着论文中的最终 ASR 低估了在更大计算预算下可能达到的攻击效果。
- **对防御策略的系统评估缺失**：研究侧重于攻击者角度，没有考虑或系统测试防御机制（如提示注入检测、MELON 等防御方法）的攻击下表现，因此对完整攻防格局刻画有限。
