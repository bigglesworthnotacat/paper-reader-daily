## 摘要
安全智能体也可能共同失效。多智能体LLM系统（MAS）在主体边界之间传递信息、状态、决策和权限，产生局部检查可能遗漏的失效模式。若无执行层面的视角，多智能体场景很容易被误认为存在真正多智能体安全效应的证据。因此，我们通过197篇文献的以执行为中心的分析，系统化梳理了MAS安全性，覆盖六种交互接口、四种对手位置、七类系统级风险及八条常见攻击路径。我们提出A-I-R框架，按对手位置、交互接口及由此产生的系统级风险组织攻击，统一了MAS中原本碎片化的攻击机制。我们通过涵盖路径目标、观察、干预、信任边界与恢复的五部分契约来组织防御，并指出路径闭合与恢复是关键挑战。我们审计了44项评估与基准工作，指出在隔离交互效应、设计可比且可诊断的指标、支持MAS设计间复用以及评估开放系统运行方面存在开放挑战。综合这些发现，我们倡导一种交互感知的MAS安全观：端到端追踪攻击，检验防御是否闭合这些路径，并借助适当的反事实评估系统级效应。

## Abstract
Safe agents can fail together. Multi-agent LLM systems (MAS) move information, state, decisions, and authority across principal boundaries, creating failures that local checks may miss. Without an execution-level view, a multi-agent setting can easily be mistaken for evidence of a genuinely multi-agent security effect. We thus systematize MAS security through an execution-centered analysis of 197 works, covering six interaction interfaces, four adversary positions, seven system-level risks, and eight recurring attack paths. We introduce an A-I-R framework that organizes attacks by adversary position, interaction interface, and resulting system-level risk, unifying otherwise fragmented attack mechanisms across MAS. We organize defenses through a five-part contract covering path target, observation, intervention, trust boundary, and recovery, and identify path closure and recovery as key challenges. We audit 44 evaluation and benchmark works and identify open challenges in isolating interaction effects, designing comparable and diagnostic metrics, supporting reuse across MAS designs, and evaluating open-system operation. Together, these findings motivate an interaction-aware view of MAS security: trace attacks end to end, test whether defenses close those paths, and evaluate system-level effects with appropriate counterfactuals.

## 1. 论文的核心问题与整体含义（研究动机与背景）

- **多智能体系统（MAS）存在独特的安全问题**：单个使用时安全的智能体（agent），在组合为一个MAS时可能一起失效。失效源于信息、状态、决策和权限在多个**主体（principal）** 之间跨越边界传递，这是单智能体场景中不存在的现象。
- **现有研究缺乏执行级视图**：已有调查或围绕组件（模型、提示、记忆等）组织，或聚焦通信、信任、拓扑等治理概念，但都未清楚回答一个核心问题：**攻击如何穿过整个MAS**——从哪里进入、经由哪些交互接口、最终导致何种系统级失效。
- **最严重的误区**：仅因观察到多智能体环境中的失效，就误认为该失效依赖于智能体间的交互。没有合适的对照实验，无法区分失效是继承的、交互放大的、组合涌现的、还是结构上多智能体特有的。
- **本研究的目标（SoK任务）**：通过对197篇文献做系统化、以执行为中心的分析，建立统一描述性框架，涵盖攻击、防御与评测，推动研究社区走向“交互感知”的安全评估规范。

## 2. 论文提出的方法论：核心思想、框架与细节

### 2.1 核心思想：以“端到端执行”为分析单元
将一条完整的MAS执行追溯作为分析单元，追踪对抗性影响从起始位置、穿过若干交互接口、最终到达系统级安全失效的完整过程。基于此模型，作者提出并使用了多个相互配套的形式化概念：

### 2.2 A → I → R 框架
- **A（对手位置，Adversary position，4类）**：A1外部对手（控制系统外内容或服务）；A2用户级对手（通过授权用户界面）；A3成员对手（控制一个或多个参与主体）；A4基础设施对手（控制协调器、共享状态、路由器、遥测或防御面的共同组件）。
- **I（交互接口，Interaction interface，6类）**：I1准入（外界的输入/主体/数据进入MAS的入口）；I2消息传递（主体间消息传输）；I3状态传播（信息写入共享/长期状态并影响后续执行）；I4权限转移与行动（委托或使用特权能力）；I5集体承诺（局部输出汇聚为组级决策）；I6检测与干预（安全监控与响应）。
- **R（系统级风险，Risk family，7类）**：R1遏制失败（影响从进入点逃逸到其他主体）；R2独立性丧失（本应独立提供证据的主体间产生策略性/统计性依赖）；R3集体决策完整性失效（对抗影响改变受保护的投票/共识）；R4轨迹与目标完整性失效（交互将目标/执行轨迹引向未授权方向）；R5跨主体机密性泄露；R6传递性授权失效（状态/指令/授权链条超出原始范围使用）；R7可用性与资源隔离失效。
- **8条典型攻击路径（P1–P8）**：P1准入与组合注入；P2传播与持久化；P3路由与角色操纵；P4对抗性协调与集体操纵；P5同伴/状态中介诱导；P6跨主体信息泄露；P7委托与权限升级；P8共享资源与管控面干扰。

### 2.3 防御侧方法论：五部分防御契约 + 四种干预原语
- **五部分契约用于刻画/评估防御**：
  1. **路径目标（Path target）**：打断哪条系统级风险或路径；
  2. **观察（Observation）**：能观测到执行的哪一部分（消息、边、共享状态、全轨迹等）；
  3. **干预（Intervention）**：能改变什么、何时干预（执行前/执行中/执行后）；
  4. **信任边界（Trust boundary）**：哪些组件和条件必须保持可信才使防御有效；
  5. **恢复（Recovery）**：预防与遏制失败后，还能否清除/回滚/修复残余影响。
- **四种控制原语**：D1身份/策略/权限执行；D2信任与交互结构控制；D3检测、归因与遏制；D4状态/溯源/信息流治理；外加跨原语的自适应防御分配策略（如MESA、SafeSieve）。

### 2.4 评测侧方法论
对44项评测作品进行系统审计，按A/C/I/P/R维度逐项编码，同时记录其观察深度（最终输出、回合结果、主体事件、全程轨迹）、对照设计（攻击/组件对照、匹配单主体对照、关系聚焦对照）、成员设置（固定/动态）和工件可获得性。

## 6. 论文的主要结论与发现

- **核心结论**：多智能体安全应当以“端到端交互执行”为分析单元，而非以单个消息、单个智能体或最终输出为单元；安全属性可能只存在于主体间交互之中。
- **攻击面在交互中而非仅在内容中**：路由、角色分配、聚合方式和委托链条本身即是攻击面；即使消息内容不变，改变关系/拓扑也能改变安全结果（如MESA优先保护高风险通信边）。
- **失效具有持久性**：注入内容被写入共享状态、派生子体或已授权能力后，清除原始来源并不能恢复系统——传播（P2）之外的**恢复问题**严重缺乏研究。
- **受保护对象超越最终输出**：独立性、拓扑保密性、私有上下文与委托权限可能在最终答案看起来正常的情况下失败。
- **防御三层缺陷**：(1) 局部防护不能闭合整条路径（一条路径被阻断不代表全部路径关闭）；(2) 防御效果取决于干预点时机与观测覆盖（局部观察者看不到全链路）；(3) 遏制不等于恢复（已复制/变换/授权的状态难追溯与回滚）。
- **评测四缺口**：隔离交互效应、设计可比诊断指标（ASR命名不透明、缺溯源因果图）、组件可配置/可扩展治理、以及对开放动态系统的评估。当前评测证据不足以支撑多数“交互导致XX失效”之类声明。

## 7. 优点（方法/实验设计的亮点）

1. **统一简洁的A→I→R执行框架**：将原本分散的MAS攻击研究用同一条坐标轴（对手位置→交互接口→系统风险）映射，显著改善对比性，可以作为今后MAS安全论文的共享描述语言。
2. **以执行为单元的分析视角具原创性**：天然衔接“结构上多智能体效应”与证据需求（何时需单主体对照、何时需去除关系后的对照），指导实证设计的反事实逻辑，是大多数既有综述未触及的深度。
3. **风险-路径-证据分层清晰**：R1–R7风险家族与P1–P8路径明确区分（路径是机制，风险是后果），在表2给出每条路径的代表性及新兴证据并标注配置维度，便于后续研究者定位空白。
4. **防御评估的五部分契约**（路径目标/观察/干预/信任边界/恢复）使防御声明可被分解与实证核查，不只按机制名称罗列防御；同时识别了“路径闭合与恢复”两大共性挑战。
5. **评测审计细致且有数据支撑**：对44个工作逐项给出A/C/I/P/R编码、观测深度、对照设计、成员设置、工件可获得性等七项属性，且明确列出比较记录和判定统计，保证审计可复核、可复用。
6. **开放科学意识**：有意区分实验证据与部署普遍性、不使用实际攻击负载、并预告释放语料与编码——伦理和方法学层面较为严谨。

## 8. 不足与局限（实验覆盖、偏差风险、应用限制）

1. **SoK综述固有限制——无新实验**：不提供任何新的攻击/防御/评测数据，因此其结论是在第二手证据之上的综合推断，验证强度取决于所引用文献自身的质量。
2. **部分攻击路径证据极为稀疏且明显不均衡**：作者自行承认P5（同伴/状态诱导）、P8（资源与控制面干扰）直接证据稀缺（P5“Sparse”、P8“Sparse”），R4（轨迹目标完整性）与R7（可用性）的直接证据也弱于传播/集体操纵类风险；基于如此薄弱的底层证据做综合时，相关结论应被视为临时性假说而非确定性定论。
3. **开放系统与运行时动态覆盖不足**：42/44个评测作品固定成员，P3等路径的运行时准入、路由重配与角色再分配研究均少；作者指出的“威胁模型需跟踪成员变化、状态谱系、可及权限”仍缺乏对应的实证或评测工具。
4. **评测质量平均水平偏低（按作者自身审计标准）**：多数benchmark未做关系聚焦对照（24/36），全轨迹记录多未解析出因果依赖图（仅1/20），指标命名（ASR）不一致且不具跨基准可比性——说明当前社区普遍存在“评测技术债务”，本文的审计只是诊断并未提供修复范式。
