## 摘要
大语言模型（LLM）智能体越来越多地通过外部工具执行长时程工作流，使得不可信输出能够影响后续动作并超出用户授权范围。现有防御方法要么隔离注入内容，要么通过预定义计划和静态策略约束执行，但这些方法在动态工作流下较为脆弱，且难以扩展到可扩展的工具生态系统中。在这项工作中，我们提出ActGov，一个运行时执行框架，在LLM提出的每个工具动作产生外部影响之前对其进行验证。ActGov-Policy组件建立在授权、动作、运行时上下文和安全约束的统一语义模型之上，从工具规范、良性任务和观察到的失败轨迹中迭代构建策略集，并通过基于SMT的反例检查验证每次更新。在运行时，ActGov-Runtime将每个工具调用抽象为有限策略记录，并且仅当该调用保持在任务范围的授权边界内并满足所有适用策略时才允许执行。这种逐动作执行机制在长时程、动态分支的工作流中始终保持授权。我们在多个模型和攻击配置下，在AgentDojo和AgentDyn基准上评估ActGov。结果表明，ActGov在保持任务效用的同时，持续降低间接提示注入攻击的成功率，显著优于现有防御方法。这些结果表明，ActGov能够对动态智能体执行实施细粒度授权，而无需依赖底层LLM正确识别恶意指令。

## Abstract
Large language model (LLM) agents increasingly execute long-horizon workflows through external tools, allowing untrusted outputs to influence subsequent actions and exceed user authorization. Existing defenses isolate injected content or constrain execution with predefined plans and static policies, but these approaches are brittle under dynamic workflows and scale poorly across extensible tool ecosystems.   In this work, we present ActGov, a runtime enforcement framework that validates each LLM-proposed tool action before it causes external effects. Built on a unified semantic model of authorization, actions, runtime context, and security constraints, the ActGov-Policy component iteratively constructs a policy set from tool specifications, benign tasks, and observed failure traces, with each update verified through SMT-based counterexample checking. At runtime, ActGov-Runtime abstracts each tool call into finite policy records and permits it only if it remains within the task-scoped authorization boundary and satisfies all applicable policies. This per-action enforcement preserves authorization throughout long-horizon, dynamically branching workflows.   We evaluate ActGov on the AgentDojo and AgentDyn benchmarks across multiple models and attack configurations. It shows that ActGov consistently reduces the success rate of indirect prompt-injection attacks while preserving task utility, significantly outperforming existing defenses. These results demonstrate that ActGov can enforce fine-grained authorization over dynamic agent executions without relying on the underlying LLM to correctly identify malicious instructions.

- **现有防御的三点不足**：

## 二、方法论

### 2.1 核心思想

- 将非结构化运行时上下文映射到**有限二维记录空间 R**，使策略可被精确表达、确定性执行并经形式化验证。
- LLM 仅被用作**有界语义解析器**（提取预定义的布尔/枚举值），授权判定由确定性解释器完成，从而严格限制 LLM 推理幻觉造成的错误空间。
- 架构上分离：计算昂贵的 Z3 求解放在**离线** ActGov-Policy 阶段，运行时只做低延迟、确定性的记录—策略评估。

### 2.2 形式化模型

- 将受 ActGov 保护的智能体建模为有限状态机：**M = (H, C, R, P, V, T)**，其中 H 为执行历史状态空间，C 为候选工具调用空间，R 为有限记录空间，P 为策略集。
- 求值函数 **V : R × P → {allow, deny}**，状态转移函数 **T : H × C × V → H**；当且仅当裁决为 allow 时外部工具才执行。

### 2.3 正交二维记录模式

- **形成层级轴（值如何产生）**：
  - L1 确定性：直接由显式结构化系统状态计算，无需自然语言处理。
  - L2 有界语义：需语义理解从非结构化文本提取，LLM 仅做解析，映射到预定义有限值域。
  - L3 组合：由 L1/L2 值经标准布尔逻辑（AND/OR/NOT）组合，捕捉组合或时序依赖。
- **语义范围轴（描述何种授权相关属性）**：action、permission、parameter、history、binding、external、domain 共七类。
- 每条记录唯一归属于一个形成层级和一个语义范围（如 `pending_obligation` 属 L1 + History），将上下文抽取约束到固定模式与有限值域，防止对抗性指令直接影响策略求值。

### 2.4 分层授权策略

- **P = P_TP ∪ P_HI ∪ P_PO**：
  - **Task-Permission（P_TP）**：将可信用户任务绑定到最小必需的工具与资源，生成基线授权边界 perm，越界即阻断。
  - **Hard-Invariant（P_HI）**：全局安全属性，如阻止源自不可信注入内容的出站网络动作，不受任务范围限制。
  - **Procedural-Obligation（P_PO）**：处理超出智能体自主处理权限的情形（如目标绑定薄弱、参数来源不确定），以条件规则形式要求满足前置条件或上下文约束后方可执行。

### 2.5 验证门控的策略演化（ActGov-Policy）

- 输入三类数据源：**工具规范**（能力与风险约束）、**良性任务轨迹**（识别过度限制规则）、**观察到的攻击失败**（识别缺失安全条件）。
- LLM 仅作为策略提议者起草候选规则，不直接修改运行时监视器。
- 对任意预定义安全断言 A_sec，Z3 在有限记录域中搜索满足策略语义但违反断言的反例：
  - **∃r, v. Domain_R(r) ∧ P_sem(r, v) ∧ ¬A_sec(r, v)**
- SAT 结果暴露策略缺口或冲突，触发策略精化；**全部查询返回 UNSAT 时方可部署**，数学上保证更新后的策略保持预定义安全不变量。
- 迭代收敛后，草拟规则交管理员确认；最终冻结策略束。

### 2.6 运行时执行（ActGov-Runtime）

- 部署于智能体 LLM 与外部工具接口之间，拦截候选调用 c_i。
- 解析基线任务权限 perm 后，将环境抽象为策略记录集：**r_i = α_R(τ, perm, H_i, c_i)**。
- 依据二维模式填充记录；LLM 仅被限制为特定记录的孤立特征抽取器（如判定参数来源类别），不做端到端安全判断。
- 动作被允许当且仅当：**处于 perm 边界内且不违反任何安全策略**。

## 六、主要结论与发现

- **RQ1 有效性**：ActGov 在 AgentDyn 上将 ASR 限制在 **≤ 0.007**（四模型），在 AgentDojo 上达到 **0.000**，显著优于 Progent、DRIFT、CaMeL、ACE。
- **RQ2 效用保持**：在抑制攻击的同时保持有竞争力的 Clean/Attacked Utility，例如 Qwen3.6-Flash 在 AgentDyn 上为 0.667/0.586（无防御为 0.667/0.650），AgentDojo 上 Qwen3.6-Flash 与 MiniMax-M2.5 保持顶尖效用。
- **基线对比规律**：CaMeL 与 ACE 以结构性限制获得低 ASR 但效用损失巨大（AgentDyn 上为 0）；Progent 与 DRIFT 在结构化程度更高的 AgentDojo 上表现较好，但在轨迹更长、工具集更大、跨应用交互更动态的 AgentDyn 上明显退化，且对后端 LLM 能力敏感。
- **稳定性来源**：ActGov 跨模型更稳定，原因是 LLM 仅用于有界记录抽取，授权判定由部署策略确定性计算。
- **RQ3 策略生成动力学**：
  - 相同 50% 训练子集下，各生成器均能达到近零 ASR（≤ 0.007），但效用差异显著：DeepSeek-v4-pro 最高（Clean 0.533 / Attacked 0.429），Qwen3.6-flash 与 MiniMax-M2.5 生成的策略更保守。
  - 训练数据从 50% 降至 25%，Clean Utility 仅从 0.533 降至 0.500，ASR 保持 0.007，说明生成 LLM 能力与训练集覆盖度共同决定策略质量。
- **跨域迁移**：生成策略对完全未见环境泛化能力有限。双向迁移下 ASR 均为 0.000（绝对安全），但效用骤降——用 AgentDojo 训练的策略在 AgentDyn 测试集上 Clean Utility 从无防御的 0.767 跌至 **0.100**，体现"陌生任务下默认采取严重保守行为"的设计取舍。

## 七、优点

- **LLM 角色最小化**：把 LLM 严格限制为有界语义解析器，授权逻辑交由确定性解释器，从架构上抑制幻觉对安全决策的影响。
- **离线验证 + 在线确定性执行**：将 Z3

求解等重计算放在离线策略生成阶段，运行时只保留低延迟、确定性的记录—策略评估，兼顾形式化保证与在线可用性。

- **授权来源与数据来源严格区分**：通过二维记录模式把"内容来自哪里"与"谁有权授权"显式分离，避免把不可信工具观察误当作授权凭证，这是对 IPI 威胁模型的直接对症设计。
- **验证门控的演化闭环**：以"全部安全断言查询返回 UNSAT 才可部署"作为硬门槛，把策略自动演化从"LLM 自由生成"变为"有反例驱动的精化过程"，同时保留人在回路确认，兼顾可扩展性与可控性。
- **不依赖底层模型识别恶意指令**：安全属性由策略不变量保证，而非寄希望于智能体"看懂"注入内容，使防御在模型替换时具有稳定性。
- **评测设计较为规范**：训练/测试攻击对严格切分、跨四个后端验证、保留无防御上界参照，并明确否定"零 ASR 零效用"的平凡解。
- **提供完整附录材料**：记录模式目录、可执行策略规则目录与提示模板公开，提升了方法的可审计性与部分可复现性。

## 八、不足与局限

- **评测基线的公平性存疑**：CaMeL 与 ACE 在两张主表中 Clean Utility 均为 0.000，这种"完全失效"更可能源于适配方式（如守卫式流水线改造）而非方法原生的能力上限，作者未给出适配细节或原生复现验证，削弱了横向结论的强度。
- **缺少与最接近工作的直接对比**：VeriGuard 因代码未开源被排除，而它恰是同样主张形式化验证的策略类防御，导致"形式化验证路线内部孰优"的问题未被回答。
- **资源与成本完全未报告**：无硬件、无耗时、无 API 调用成本，而方法本身依赖强 LLM 作为策略提议者与记录抽取器，实际部署开销难以估计。
- **统计严谨性不足**：未报告多次运行的方差、置信区间或显著性检验；AgentDyn 的 560 个用例按 50%/25% 切分后，单格结果可能对抽样波动敏感，尤其是效用指标的绝对差异。
- **消融不充分**：仅消融生成器 LLM 与训练数据比例，未逐层消融 P_TP / P_HI / P_PO 的边际贡献，也未分析二维记录模式中不同形成层级（L1/L2/L3）或不同语义范围的必要性——而这恰是该方法最核心的设计主张。
- **人在回路假设较强**：主实验依赖 10 轮精化加管理员审查，若换到真实高变更环境，人工确认的可持续性与策略漂移问题未讨论。
- **泛化能力受限且取舍极端**：跨域迁移时 ASR 为 0.000 但 Clean Utility 跌至 0.100，说明策略对未见环境过度保守；论文将其解释为设计取舍，但未给出缓解路径（如策略组合、环境识别或在线学习）。
- **记录抽取仍依赖 LLM**：虽然被约束为有界解析，但 L2 记录的判定（如参数来源类别、目标绑定强弱）本身仍是语义判断，对抗性文本能否稳定地把抽取器推向错误但"合法"的枚举值，缺少针对性攻击实验。
- **威胁模型覆盖有限**：主要针对间接提示注入，未讨论工具本身被攻陷、多智能体互注入、策略记录被污染等更广的攻击面。

## 九、结论与启示

- **核心结论**：ActGov 通过在"动作提议—执行授权"之间插入经形式化验证的确定性策略门控，在 AgentDojo 上实现 0.000 ASR、在 AgentDyn 上 ≤ 0.007 ASR，同时保持有竞争力的任务效用，并在四个后端上表现稳定，验证了"LLM 只做有界解析 + 策略确定性裁决"这一架构选择的可行性。
- **方法学启示**：对 LLM 智能体的安全防护，与其追求让模型"更懂意图"，不如把安全属性外移到可验证的确定性组件中；LLM 的能力应被用在语义抽取与策略起草等"可被人工与求解器复核"的环节。
- **工程启示**：离线重验证 + 在线轻执行的分离，是形式化方法在延迟敏感智能体场景中落地的一条可行路径；但前提是记录模式设计得当，能覆盖授权相关的关键上下文属性。
- **开放问题**：如何降低跨域迁移的效用损失、如何为自动生成的策略提供可扩展的人工审查接口、如何在记录抽取层本身加固以抵御针对解析器的对抗性诱导，是后续工作的重点方向。
- **总体评价**：论文问题定位准确、形式化刻画清晰、验证门槛设计严谨，实验在主要指标上结论明确；但基线适配公平性、消融深度与资源报告方面的欠缺，使其"优于现有防御"的强结论仍需更中立的复现来支撑。
