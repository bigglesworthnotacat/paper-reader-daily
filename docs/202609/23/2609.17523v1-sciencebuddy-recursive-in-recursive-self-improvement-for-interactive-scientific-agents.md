## 摘要
我们介绍并发布 ScienceBuddy，一个交互式科学研究工作空间，将持续改进的科学智能体引入研究人员的日常工作流程。ScienceBuddy 支持研究人员执行科学任务，同时将其请求、反馈和执行证据转化为用于持续学习的任务与评估量规。其核心是递归嵌套式自我改进，这一范式将执行框架演化与模型强化学习相结合：内层递归在模型固定时改进执行框架，而外层递归在改进后的执行框架下训练模型。执行框架演化塑造训练经验，模型学习则为执行框架自适应创造新机会。我们展示了关于研究人员交互、执行框架改进和模型学习的案例研究，基准案例涵盖四个科学任务族。通过将 ScienceBuddy 作为研究产品发布，我们使这一范式可供科学界使用，并朝着发现智能迈出一步：一种通过与研究人员持续协作而进步、并与其所支持的研究共同演化的科学 AI。网站：http://science-buddy.io

## Abstract
We introduce and release ScienceBuddy, an interactive scientific research workspace that brings continually improving scientific agents into researchers' everyday workflows. ScienceBuddy supports researchers in carrying out scientific tasks while transforming their requests, feedback, and execution evidence into tasks and evaluation rubrics for continual learning. At its core is recursive-in-recursive self-improvement, a paradigm that couples harness evolution with model reinforcement learning: the inner recursion improves the harness with the model fixed, while the outer recursion trains the model under the improved harness. Harness evolution shapes training experience, and model learning creates new opportunities for harness adaptation. We present case studies of researcher interaction, harness refinement, and model learning, with the benchmark cases spanning four scientific task families. By releasing ScienceBuddy as a research product, we make this paradigm available to the scientific community and take a step toward discovery intelligence: scientific AI that advances through sustained collaboration with researchers and evolves alongside the research it supports. Website: http://science-buddy.io

## 2. 方法论

### 2.1 系统构成（科学工作空间与可插拔 Harness）

- **工具与环境**：224 个工具、22 个功能模块，覆盖基因组学、分子与肿瘤生物学、药理学、生物成像、文献检索与数据库查询；运行时支持 Python / R / Bash；在线数据库接口 + 本地 data lake（只读挂载）；研究者上传的文档、表格、序列、图像进入**持久化工作空间**。
- **执行范式**：ReAct 式"推理—动作—观察"循环；界面提供 Chat 视图（对话）与 Trajectory 视图（事件时间线 + 单事件 Summary/Payload/Result 详情），以及 Compute / Results 面板，支持研究者检视执行记录与产物。
- **架构解耦**：harness（指令、技能、上下文管理过程）与平台基础设施（交互管理、任务执行、持久存储）分离，通过统一执行接口对接，因此**程序性改动是可编辑、可评估的**，而工具、评测器、基础设施保持固定。

### 2.2 交互形式化与学习信号

- 记研究请求与输入为 $x$，任务模型为 $\pi_\theta$，harness 为 $H$，历史 $h_t=(x,a_0,o_1,\dots,a_{t-1},o_t)$。
- 动作 $a_t$ 可为可执行代码、工具调用或面向研究者的回复；观察 $o_{t+1}=(e_{t+1},u_{t+1})$ 含环境输出 $e_{t+1}$ 与可选的研究者回复 $u_{t+1}$（缺失时为 $\bot$）。**纯工具观察不构成一次用户反馈轮次**。
- harness 构造模型上下文 $C_H(h_t)$，并可能插入确定性调度动作 $d_H(h_t)$，于是联合策略与轨迹为
  $\mu_{\theta,H}(a\mid h_t)=\delta_{d_H(h_t)}(a)$（若有调度）或 $\pi_\theta(a\mid C_H(h_t))$；$\tau=(x,a_0,o_1,\dots,a_{T-1},o_T)$。
- **从协作到任务与量规**：把相关轮次围绕一个科学目标合并、把可独立求解的目标拆分；重建的任务指令只保留最终要求与输入，**不导入历史答案**；量规由完整协作轨迹构造：$\mathcal{C}(x)=\mathrm{ConstructRubric}(\tau^{\text{collab}}_x; I_x, A_x)$，覆盖任务范围、方法学要求、证据与期望产物；冲突要求先消解再评分，**历史答案与研究者认可不被自动当作科学真值**。
- **Harbor 任务包**：$\mathcal{P}_x=(I_x, A_x, E_x, \mathcal{C}(x))$，以 `instruction.md / task.toml / environment/ / assets/ / tests/test.sh` 形式组织；同一任务支持两条后训练路径——SFT（拒绝采样保留量规合格轨迹）与 RL（新采样的 on-policy rollout，以量规得分为奖励）。

### 2.3 内层递归：反馈引导的 Harness 改进

- 外层第 $k$ 轮中，任务模型参数 $\theta_k$ **冻结**；使用独立的固定辅助模型（GPT-6 Astra）做轨迹诊断与编辑。
- **诊断**：辅助模型审阅近期轨迹与量规评估，指出未满足的判据并引用相关动作/观察，映射为一个候选程序性编辑；任务专属答案与新事实保持局部化。
- **有界修订**：$\tilde{H}_{k,j+1}=U(H_{k,j},E_{k,j};\theta_k)$，每次只**新增/删除/修改一个作用域技能、编辑一条指令或改动一个暴露的上下文设置**，其余组件不动；schema 校验强制编辑范围与规模预算；工具、执行基础设施、量规与评测器固定；任务模型与辅助模型均**不接收梯度**。
- **配对评估与接受准则**：父代与候选在**相同开发任务、种子与执行预算**下用冻结量规评估，$\bar{S}_k(H)$ 为平均归一化量规分，$\mathrm{Valid}(H)$ 表示是否合规，$\Delta_{k,j}=\bar{S}_k(\tilde{H}_{k,j+1})-\bar{S}_k(H_{k,j})$：
  - 若 $\mathrm{Valid}(\tilde{H})\wedge \Delta_{k,j}>0$ 接受子代，否则保留父代；**平局保留父代**；评估包含此前成功的任务以捕捉回归；被拒编辑与分数变化保留在优化器历史中。
  - 迭代至提议预算或外层收集边界耗尽；开发任务与策略训练任务、最终留出测试集严格分离。

### 2.4 外层递归：持续模型强化学习

- **环境增广与难度校准**：随 harness 演化，原本困难的任务可能变简单，故用当前模型 + 选定 harness 做先导执行以校准难度，通过变化科学输入、分析条件或延长计算步骤依赖来增广研究者派生任务，再由验证过的环境提供新 RL rollout。
- **任务自适应量规奖励**：每条判据有非负重要性权重 $w_c(x)$（在 rollout 评估前分配）与满足度 $v_c(x,\tau)\in[0,1]$，可用可执行检查处用之，需科学解释处用固定 judge：
  $R_x(\tau)=\dfrac{\sum_{c\in\mathcal{C}(x)} w_c(x)v_c(x,\tau)}{\sum_{c\in\mathcal{C}(x)} w_c(x)}$，且 $\sum_c w_c(x)>0$。
- **模型更新**：$\max_\theta J_k(\theta)=\mathbb{E}_{x\sim q_k}\mathbb{E}_{\tau\sim\pi_{\theta,H^\star_k}(\cdot\mid x)}[R_x(\tau)]$，采用 **GRPO**（轨迹级终末奖励共享至所有生成 token；组相对优势 $\hat{A}_i=(r_i-\text{mean})/(\text{std}+\delta)$；带 clip 与采样 KL 代理的 token 级目标，见式 (S1)–(S3)）。
- **再评估与循环闭合**：得到 $\theta_{k+1}$ 后，因 harness 有效性依赖其与任务模型的交互，需在更新模型下重新评估 harness 再部署，$H_{k+1}=H^\star_k$；研究者的后续交互为下一轮内外循环提供证据。

### 2.5 协调机制

- **嵌套调度 + 异步在线服务**：在固定收集区间内以 $(\theta_k,H_k)$ 服务研究者，交互与反馈触发后台更新周期（先固定 $\theta_k$ 做 harness 改进，再在选定 harness 下做模型 RL），**后台更新与在线服务并行，服务不中断**。
- **跨周期经验**：所有 harness 版本与任务环境均保留供后续演化；继承的 harness 在部署或复用前须在新模型下重新评估。Algorithm 1 给出完整流程。

  - **统计强度偏弱**：缺少多次随机种子重复与置信区间/显著性检验；RQ2 仅有 3 个周期、RQ3 为单条编辑轨迹，**无法区分"方法有效"与"某次编辑恰好有效"**；pass@4 只报告覆盖率，未同时报告 pass@1 或方差，掩盖了稳定性差异。
  - **对照不足**：没有外部 SOTA 的定量对照，也没有关键消融——例如"去掉外层 RL 只做内层"、"去掉内层只做 RL"、"编辑不做配对评估而直接接受"、"去掉难度校准"、"去掉量规加权"等消融均未系统报告，因此**两个递归层次的各自贡献与耦合增益无法被量化归因**。
  - **人机交互评估薄弱**：RQ1 是两例定性案例，缺少研究者盲评、可用性量表或"研究者满意度/采纳率"等主观指标，而论文的核心主张恰恰是"协作驱动学习"。
  - **验证集使用**：harness 选择基于验证准确率，但未报告验证–测试的差距（泛化间隙），难以判断是否存在对开发任务的过拟合。

---

## 6. 主要发现与结论

- **内层递归（harness 自我改进）可带来可测的性能提升**：在任务模型完全冻结的前提下，仅通过有界、单点、作用域受限的程序性编辑，H24 相对 H0 在冻结量规上取得更高分数，说明**"执行程序"本身是可被自动优化的独立能力维度**，且提升不依赖权重更新。
- **外层递归（模型 RL）在固定 harness 下同样有效**：H0 固定时，RL 后模型在 pass@4 上优于 RL 前，说明量规奖励可把协作轨迹中的隐性标准转化为可学习的策略信号；约 2 小时的训练时长表明该信号在小模型上较易被利用。
- **耦合共演化优于单一层次**：3 周期 RinR 中，harness 与策略交替改进，且每轮更新后需在新模型下**重新评估 harness** 才能部署，说明二者互为条件——harness 的有效性依赖任务模型的分布，反之亦然；这构成论文对"递归嵌套"必要性的核心论证。
- **协作轨迹可同时充当任务定义与评估标准**：从交互中重建的指令（去除历史答案）与量规（覆盖范围、方法学、证据、产物）被证明能支撑 SFT 与 RL 两条后训练路径，且**研究者认可不被直接当作科学真值**这一保守设定降低了把人类错误固化为奖励的风险。
- **异步嵌套调度可保证服务不中断**：在线服务与后台更新并行，研究者交互不因训练或 harness 搜索而阻塞，这是面向真实科研工作空间而非离线基准的关键工程结论。
- **总体结论**：ScienceBuddy 证明了"发现智能"的一条可行技术路线——**把协作从一次性纠错升级为跨任务的程序学习 + 策略学习双循环**，且该路线可在 4B 级模型与小时级算力上运行。

## 7. 局限与批判性评估

- **算力与可复现性**：未报告 GPU 型号、数量、显存、总机时、batch size、组大小、rollout 总量；仅"约 2 小时"一处时间线索。**外部复现难度高**。
- **外部对照缺失**：与 Reflexion / GEPA / ACE / SIA / HELIX 等仅在 Related Work 定性区分，无定量实验，**无法判断相对增益**。
- **评估主体依赖 LLM judge**：量规中需科学解释的判据由固定 judge 打分，存在 judge 偏差、长度偏好与自我一致性风险；虽有可执行检查兜底，但覆盖比例未报告。
- **任务规模与领域边界**：895 任务集中于基因组学/分子生物学相关的四类任务，**能否迁移到物理、化学、材料或工程领域未知**；工具集（224 个）与数据湖为该领域定制，跨领域成本未讨论。
- **人类反馈的简化建模**：RQ3 中研究者由固定 Qwen3.8-27B 模拟，**模拟用户与真实研究者的分布差异**可能系统性高估或低估方法效果；真实交互中的模糊、矛盾、隐含偏好是否被充分覆盖存疑。
- **量规构造的稳定性**：$\mathcal{C}(x)=\mathrm{ConstructRubric}(\tau^{\text{collab}}_x; I_x, A_x)$ 依赖协作轨迹质量与冲突消解过程，但消解规则、权重分配策略、判据去重机制描述不足，**可能引入不可控的评估漂移**。
- **编辑空间的保守性**：单点、作用域受限、平局保留父代，提升了稳定性但**可能限制长程结构性改进**（如重构整体工作流）；论文未讨论该上界。
- **回归风险**：虽提到评估包含此前成功任务，但未报告回归率随更新次数的变化曲线，长期累积编辑是否导致能力遗忘不明。
- **安全性/科学诚信**：从协作中学习可能固化研究者偏见或错误假设；论文以"研究者认可≠真值"作为防线，但缺少对失败案例（如被接受却科学错误的编辑）的分析。

---

## 8. 启示与展望

- **方法论启示**：将"智能体能力"拆为**程序（harness）**与**策略（权重）**两个可分别优化的层次，并用配对评估 + 严格划分数据来控制耦合风险，这一范式可迁移到代码智能体、实验自动化、临床决策支持等需要长期协作的场景。
- **工程启示**：harness 与基础设施解耦、统一执行接口、版本化保留所有 harness 与环境，是支持"可编辑、可评估、可回滚"自我改进的前提。
- **评估启示**：把协作轨迹同时用作任务重建与量规构造，是缓解"奖励从何而来"难题的一条实用路径；但需配套 judge 校准、冲突消解协议与回归监控。
- **待补方向**：多次种子重复与置信区间；内层/外层/配对评估/难度校准的消融；真实研究者参与的盲评与长期使用研究；跨领域迁移实验；更大模型与更长共演化周期的缩放律；以及针对"被接受但错误"编辑的失效分析。

---

## 9. 一句话总结

ScienceBuddy 提出并初步验证了 **RinR（递归嵌套式自我改进）**：内层在冻结模型下用协作反馈做有界 harness 编辑，外层在选定 harness 下用量规奖励做模型 RL，二者交替共演化，把研究者的一次性纠正沉淀为跨任务可复用的程序与策略能力；其核心贡献是**范式与系统**，主要短板是**算力细节缺失、外部对照与消融不足、真实人类评估薄弱**。
