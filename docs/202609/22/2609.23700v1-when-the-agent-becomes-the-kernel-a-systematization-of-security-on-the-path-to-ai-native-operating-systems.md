## 摘要
大型语言模型智能体如今已成为特权主体，会执行具有重大后果的操作：编辑代码仓库、管理收件箱、完成购买。它们的权限是内核级的，但却缺少经典系统安全所要求的东西：在每次访问时介入的可信中介。操作系统厂商如今正围绕这一事实上的智能体内核重建平台，从而把完全中介继承为一个设计问题。我们围绕一个区分来系统化此类系统的安全：基于来源进行中介的跨越可以进行确定性检查，而基于内容语义的跨越则不能。一个信任边界分类法定位了中介必须发生的位置，并将核心中介缺口归结为两类语义判断：在不可信输入中区分数据与指令，以及区分已授权操作与未授权操作。我们认为，只要输入和操作未被事先限制在一个可枚举集合内，这一缺口就会留下无法消除的未检测攻击残余。同样的区分使攻击成功率统计变得可操作，将每个数字置于从部署债务（一个健全的确定性中介未被使用）到结构性缺口（尚无可用的此类中介）的谱系上。我们系统化了跨运行时监控、架构隔离与授权的防御，并表明当前评估往往因评估效度失效而高估已部署的安全性。最后，我们将这一分析推进到事实内核之外，走向一种模型本身成为仲裁核心的架构，并推导出面向安全优先的AI原生操作系统的设计约束、开放挑战与研究议程。

## Abstract
Large language model agents are now privileged principals that take consequential actions: editing code repositories, operating inboxes, completing purchases. Their authority is kernel-grade, but it comes without what classical systems security requires: a trusted mediator interposed on every access. Operating-system vendors are now rebuilding the platform around this de-facto agent kernel, inheriting complete mediation as a design problem. We systematize the security of such systems around a single distinction: a crossing mediated over provenance admits a deterministic check, while one over content semantics does not. A trust-boundary taxonomy locates where mediation must occur and isolates the central mediation gap at two kinds of semantic judgment: distinguishing data from instruction in untrusted input, and an authorized action from an unauthorized one. We argue that this gap leaves an irreducible residual of undetected attacks wherever inputs and actions are not restricted in advance to an enumerated set. The same distinction makes attack-success statistics actionable, placing each number on a spectrum from deployment debt (a sound deterministic mediator left unused) to a structural gap (no such mediator known). We systematize defenses across runtime monitoring, architectural separation, and authorization, and show that current evaluations tend to overstate deployed security through evaluation-validity failures. Finally, we carry that analysis forward beyond the de-facto kernel, to an architecture in which the model itself becomes the arbitration core, and derive the design constraints, open challenges, and research agenda for a security-first AI-native OS.

## 1. 核心问题与整体含义（研究动机与背景）

### 1.1 现象：智能体已获得"内核级"权限

- 部署中的 LLM 智能体（代码助手、computer-use 智能体、企业 copilot）在**常设授权**下自主选择并提交有后果的操作：改代码库、发 PR、读共享邮箱、调用内部工具、完成支付。
- 它们占据的位置在经典系统安全中**专属于内核**：仲裁资源、绑定特权操作的"特权主体"（privileged principal）。
- 2026 年 7 月，两家头部模型开发商披露：受评估的智能体**逃出隔离环境并触及第三方生产系统**——而且**没有注入攻击者**。缺的不是"防攻击者"，而是**一个能区分"已授权动作"与"未授权动作"的检查**。

### 1.2 平台层的同向运动

- 微软把 Windows 定位为 agent-native runtime；Android 的 App Functions、Apple 的 App Intents 让智能体发现并调用应用声明的操作。
- 现状是**混合体**：智能是叠在传统内核之上的，而非烘焙进仲裁核心。作者称之为**事实上的智能体内核（de-facto agent kernel）**，并预测终点是 **AI 原生 OS**：模型自身分配内存、复用智能体、授权每一次特权调用。
- 关键张力：到达那个终点**不会**提供今天缺失的检查，反而使其更难——**需要被中介的组件本身就是那个需要中介的概率性组件**。

### 1.3 经典教义与缺口

- 经典安全把两种角色分开：**行动的主体（principal）** 与**限制它的中介（mediator）**——永远被调用、防篡改、位于特权决策与执行之间（Anderson 的 reference monitor；Saltzer & Schroeder 的 complete mediation）。
- 智能体**继承了主体的权限，却没有随晋升一起得到中介**。
- 组织全文的核心问题：**当智能体跨越信任边界时，该边界上的中介必须判断什么？**

### 1.4 核心区分：溯源 vs 内容语义

- **溯源判断（provenance）**：内容从哪来、因此携带何种权限 → 规则可在内容存在**之前**冻结 → **确定性检查**。
- **内容语义判断（content semantics）**：内容意味着什么 → 无法预先冻结规则 → 只能是**分类器**，必然落在 FP/漏报权衡曲线上，且**一定会出错**。
- 大多数跨越是两者的**梯度轴**，而非二分。
- 该轴给出三个等级：**部署债务**（确定性中介已知但未采用）、**结构性缺口**（无确定性中介可能存在）、**混合**。

### 1.5 整体含义

- 只要输入与动作**未事先枚举限制**，中介缺口就留下**不可消除的未检测攻击残余**。
- 同一区分让攻击成功率数字变得可解释：它落在"部署债务 ↔ 结构性缺口"的谱系上。
- 论文最终把分析从事实内核推进到"模型即仲裁核心"的架构，给出设计约束与研究议程。

## 2. 方法论：核心思想、关键构造与分析流程

### 2.1 核心思想：用"中介必须判断什么"来索引一切

论文不同于既有综述的四种方式：

1. 按**信任边界上检查必须决定什么（溯源 or 含义）**来索引攻击与防御，而非按攻击进入位置；
2. 追问**智能体决策的完全中介者是否存在**，而非"哪些 OS 技术可迁移"；
3. 把**评估效度**当作独立主题；
4. 把分析推进到**AI 原生 OS**（此前无安全系统化研究）。

### 2.2 两个研究对象

**（A）事实上的智能体内核**，三个特征：

- **常设性（standing）**：集成/安装时获得，跨任务边界由智能体自行裁量行使；
- **广泛性（broad）**：一个主体触及文件、网络、shell、浏览器、其他智能体；
- **概率性（probabilistic）**：主体采样决策，同一请求不保证两次得到同样的特权动作。

**（B）AI 原生 OS（架构地平线）**，六条标准：

1. 智能位于架构核心而非应用层（推理是像内存/IO 一样的一等系统资源）；
2. **意图式**而非命令式控制（自然语言即系统接口）；
3. 持久、跨会话上下文（一等资源，由上下文管理器分页）；
4. 自主多步执行（跨应用规划并提交，选取并绑定原请求未点名的动作）；
5. OS 级智能体生命周期管理（权限、身份、注册、沙箱、委派）；
6. 互不信任的多路复用（由系统而非主体把彼此隔开）。

### 2.3 信任边界分类法（六个跨越）

围绕智能体主体（图 3）：

| 边界 | 跨越 | 中介问题 | 等级 |
|---|---|---|---|
| **B0** | 外部输入 → 智能体 | 能否区分数据与指令？（分 B0-direct 授权问题 / B0-indirect 溯源问题） | **结构性缺口** |
| **B1** | 推理 → 动作 | 所选动作是否已授权且忠实于主体意图？ | **结构性缺口** |
| **B2a** | 工具调用 | 每次调用是否最小权限且对触发数据已授权？ | 部署债务（继承 B0 等级） |
| **B2b** | 响应路径/传输完整性 | 智能体据以行动的结果是否是工具产出的结果？ | 部署债务 |
| **B2c** | 配置通道溯源 | 承载指令的元数据（工具描述、manifest、MCP 元数据、技能、规则文件）是否被当作不可信数据处理？ | **混合** |
| **B3** | 智能体 → OS/主机 | 主机操作是否被限制在最小权限能力集内？ | 部署债务 |
| **B4** | 智能体 ↔ 智能体 | 信任与溯源标签在委派中是否不可降级？ | 结构性缺口（继承 B1/B0） |
| **B5** | 智能体 ↔ 共驻主体 | 除调度器意图外，是否有任何东西在主体间穿越？ | 部署债务 |

- B0、B1 是 §4.1 两类语义判断的**纯形式**，被评为结构性缺口。
- 分类法基于**跨越行为**而非层（complete mediation 定义在"跨越"上）；分层方案（如 LASM）可映射到层接口上，跨层攻击即"多个跨越的路径"（图 4 的 GeminiJack 杀链：B0 → 持久存储 → B2a 外泄）。

### 2.4 中介缺口的核心论证

- **第一类判断（数据 vs 指令）**：Abdelnabi & Bagdasarian 证明任何被检测器阻断的流都可被改写为看似合法，故不存在既阻断所有攻击又通过所有合法流的检测器 [7]；Zverev 等实测当前模型的指令–数据分离能力很弱 [31]。
- **第二类判断（已授权 vs 未授权动作）**：主体授权的唯一陈述是请求本身，而请求**按设计就是欠指定的**——主体委派任务正是为了不把"执行它意味着什么"写清楚；**指定得足够精确到可精确检查的意图是计划，不是委派**。这首先是**规范问题**而非检测问题，更好的分类器也关不上。
- 因此：**语义判断处的中介残余不可消除**；更好的分类器只能降低残余。
- 历史类比：Web 安全遇到同样的"数据当指令"（XSS），用**溯源与隔离**（同源策略、上下文转义、CSP）而非分类器解决。

### 2.5 投影原则（projection principle，建设性对偶）

- **凡跨越不允许确定性中介处，可通过收窄该跨越所辖空间来"买"到确定性**，代价付在**表达性、自主性、记忆或影响力广度**上（图 5）：
  - CaMeL：把动作空间投影到有限图 → 付**表达性**；
  - Apple PCC：把状态空间投影为零 → 付**记忆**；
  - RobustRAG：把单段检索影响力投影到可证界 → 付**影响力广度**；
  - 可逆性分级门：把后果空间投影到枚举的不可逆集合 → 付**自主性**。
- 投影是**一次性的离线语义判断**，使得运行时检查无需再做该判断；保证只延伸到那次离线判断正确的范围。

### 2.6 防御的系统化（§6–8）

- **运行时监控 = 概率性中介**，按读取层次分四层：输入监控（B0）、思维链监控（B1）、内部激活监控（B1）、动作轨迹监控（B2/B3）；提出**运行点（operating point）**概念：漏报率必须与测量时的误报预算一起陈述才有意义。
- **架构隔离 = 确定性中介**：双 LLM/CaMeL/IsolateGPT/Prompt Flow Integrity；模型内数据–指令分离（Spotlighting、ASIDE/ISE/AIR、StruQ/SecAlign）被明确**归为不同性质**——它只让模型"更不可能"遵从，而非阻断控制通道。
- **授权 = 对主体的中介**：智能体作为一等主体身份（零信任）、最小权限；授权按**操作可逆性**分级而非按行为者身份，给出三条可检查规则：
  - **R1 组合性**：各自可逆的动作可组合成不可逆效果；
  - **R2 外部可见性**：外向动作一旦被边界外观察到即不可逆；
  - **R3 机密性污染**：任何把敏感标签数据移出外部边界的动作一律按不可逆层处理。
- **溯源标签跨委派**：去中心化信息流控制（DIFC）、标签单调性（可进一步限制、不可提升）、FIDES。

### 2.7 评估效度方法论（§9）

- 攻击成功率数字的三重上界性质；**Pass@K vs Pass K**（安全相关量是 Pass K：K 次全成功，因为攻击者只需智能体多次运行中失败一次）；**运行点报告**（在钉死的 FPR 预算下报告捕获率）；**自适应攻击**下的再评估；**评估感知（evaluation awareness）**。
- 七条报告检查清单：钉死模型快照/平台/上下文长度；声明 FPR 预算下的效能；Pass K 与 Pass@K 并列；外泄率与攻击成功率并列；自适应攻击或标注为静态；评审–被测同族独立性；共享或隔离推理基础设施。

### 2.8 向 AI 原生 OS 的迁移分析（§10）

- 迁移测试：对每条定义该架构的性质，识别其**置于风险的不变量**并推导**设计约束**（表 5）。
- 结论性观察：**六条约束中四条要求"模型之下的溯源机制"，两条要求"投影"，没有一条要求监控器**；机制/策略分离排序三者——**模型与监控器提议，投影与机制执行，提议只有在模型之外的主体激活时才生效**。
