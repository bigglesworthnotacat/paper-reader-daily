## 摘要
基于 LLM 的智能体越来越多地运行在与用户、工具和外部系统交互的环境中。然而，大多数安全性评估假设用户是被动的且控制是静态的，忽略了塑造真实智能体行为的交互动态。我们提出了 \textbf{DUMA-Bench}，一个用于衡量 \emph{双控} 交互下智能体安全性的基准与评估协议，其中智能体和用户都能影响共享环境状态。DUMA-Bench 扩展了 $τ^2$-bench \cite{barres2025tau}，加入了涵盖八类漏洞的对抗环境，包括 RAG 投毒、跨智能体操纵和不安全输出处理。我们评估了来自五个模型系列（OpenAI、Anthropic、DeepSeek、Qwen 和 Z.ai）的 \textbf{14 个模型}，跨八个领域和多种用户行为模式。在我们的实验中，引入双控交互将攻击成功率从 \textbf{26.9\%} 提高到 \textbf{41.1\%}。这些结果表明，智能体安全性不仅是模型自身的属性，而是由模型、用户和环境之间的交互涌现出来的。DUMA-Bench 为研究现实智能体部署中的安全性提供了一个缺失的评估层。

## Abstract
LLM-based agents increasingly operate in environments where they interact with users, tools, and external systems. Yet most security evaluations assume passive users and static control, ignoring the interactive dynamics that shape real agent behavior. We introduce \textbf{DUMA-Bench}, a benchmark and evaluation protocol for measuring agent security under \emph{dual-control} interaction, where both the agent and the user can influence the shared environment state. DUMA-Bench extends $τ^2$-bench ~\cite{barres2025tau} with adversarial environments covering eight vulnerability classes, including RAG poisoning, cross-agent manipulation, and unsafe output handling. We evaluate \textbf{14 models from five model families} (OpenAI, Anthropic, DeepSeek, Qwen, and Z.ai) across eight domains and multiple user-behavior regimes. Across our experiments, introducing dual-control interaction increases the attack success rate from \textbf{26.9\%} to \textbf{41.1\%}. These results show that agent security is not solely a property of the model but emerges from the interaction between the model, the user, and the environment. DUMA-Bench provides a missing evaluation layer for studying security in realistic agent deployments.

# DUMA-Bench 论文详细总结

## 1. 核心问题与整体含义

- **研究动机**：LLM 智能体已广泛部署于与用户、工具和外部系统交互的场景中，但现有安全评估大多沿用**被动用户 + 静态控制**假设——模型接收固定 prompt，产出单轮回复。
- **核心痛点**：真实智能体工作流包含多轮迭代交互、工具调用与环境状态更新，这些交互通道会引入静态评估无法捕捉的对抗操纵机会。
- **关键假设**：安全漏洞不仅取决于模型本身，更取决于**交互机制（interaction regime）**。
- **整体含义**：DUMA-Bench 旨在补齐"交互 + 对抗威胁"这一缺失的评估层，将安全评估从单轮 prompt 扩展到智能体、用户、环境三方共同塑造轨迹的双控场景。

## 2. 方法论

### 2.1 核心思想

- 基于 τ²-bench 的**双控交互（dual-control）**结构，将环境形式化为**部分可观测状态空间** $S$：智能体 $A$ 与用户 $U$ 各自接收部分观测，从各自动作空间选择动作，环境依据**同时取决于两者动作的转移函数**演化。
- 智能体动作 = 工具调用 + 通信行为；用户动作 = 交互消息（在部分领域还可通过用户侧工具直接操作环境）。
- 评估以交互循环形式进行：双方交换消息、发起工具调用、修改环境状态，交互结束后检查安全断言是否全部满足。

### 2.2 八个安全领域（8 类漏洞）

| 领域 | 漏洞类型 |
|---|---|
| mail_rag_phishing | RAG 投毒（检索邮件/SOP 中的对抗指令）|
| collab | 跨智能体操纵（被污染的协作者笔记）|
| output_handling | 不安全下游输出（XSS / SQL / 重定向）|
| crm_leak | 可信数据过度共享（字段级访问控制）|
| infra_loadshed | 基础设施操纵 / 配额滥用 |
| mktg_phishing | 钓鱼式营销活动滥用 |
| auth_spoof_support | 身份伪装（退款/改邮箱等敏感操作）|
| tool_shadow_poison | 工具影子化（未签名工具模仿合法功能）|

- 共 **35 个可执行多轮任务**（非纯 prompt 测试项），每项包含安全策略、可变环境状态、领域工具、对抗工件、用户侧指令与断言。

### 2.3 断言设计与奖励

- **状态断言（state assertion）**：对执行后环境状态的确定性函数，通过重放工具调用轨迹验证。例如 `auth_spoof_support` 中检查退款日志是否存在 `verified=False` 条目，**不受 LLM 评判偏差影响**。
- **通信断言（communication assertion）**：针对自然语言回复文本的期望，由 GPT-4o 作为 LLM 评判器（temperature=0.0）逐条独立评分，返回 JSON（含重复期望、简短理由、布尔判定），**所有子断言合取通过**才计分。用于捕捉无环境痕迹的违规（如回复中泄露受保护字段）。
- **最终奖励**：按类型合取再相乘
  $$r = \prod_{t \in B} r_t \in \{0,1\}$$
  其中 $B$ 为参与计分的断言类型子集。任一类型失败则 $r=0$，防止"拒绝非法操作但泄露数据"式的部分合规。

### 2.4 评估指标

- **ASR（攻击成功率）**：违反安全断言的情节占比，为主指标。
- **pass^k**：无偏估计量 $\widehat{\text{pass}}_k^i = \binom{c_i}{k}/\binom{n_i}{k}$，衡量 k 次独立试验全部成功的概率，k 越大越严格，用于刻画重复交互下的可靠性。

## 3. 实验设计

- **基础 benchmark**：扩展 τ²-bench，构建 8 领域、35 任务的对抗环境；每个任务同时兼容 solo 与 dual-control 两种机制。
- **两种评估机制**：
  - **Solo**：智能体直接与环境交互，无主动用户（近似现有基准范式）。
  - **Dual-control**：智能体与用户模拟器共同塑造轨迹。
- **模型**：来自 5 个家族共 **14 个模型**——OpenAI（GPT-5 / mini / nano、GPT-4o / mini、GPT-4.1 / mini）、Anthropic（Claude Opus / Sonnet / Haiku 4.5）、DeepSeek V3.2、Qwen3.5-Plus / Flash、GLM-4.7，覆盖前沿、中端与轻量级。
- **用户模拟器**：统一使用 **GPT-4o-mini** 作为用户侧 backbone，保持跨目标模型可比；温度设为 $T_{user} \in \{0.0, 0.5, 1.0\}$ 以研究交互变异性。论文强调模拟器**并非多数任务中的主要对抗来源**，对抗压力主要通过检索文档、协作者笔记、工具清单、可变环境状态注入。
- **评估配置**：四元组 (model, domain, regime, $T_{user}$)，每个配置独立运行 $n=5$ 次；主研究为 14 模型 × 8 领域 × 2 机制 = **每种机制 1960 次试验**。
- **统计方法**：Fisher 精确检验评估显著性，Wilson 区间估计比例置信区间。
- **对比对象**：论文并非对比"方法 A vs 方法 B"，而是**对比评估机制**（solo vs dual-control）及不同模型/领域/用户温度下的表现。

## 6. 主要结论与发现

- **总体稳健性下降**：从 solo 到 dual-control，ASR 从 **26.9% → 41.1%（+14.2pp）**，pass^1 从 **0.731 → 0.589**，Fisher 检验显著。静态评估系统性低估风险。
- **领域差异显著**：
  - 最大恶化：`mktg_phishing`（0.022 → 0.615，+0.593）；`collab`（+0.206）、`crm_leak`（+0.193）、`tool_shadow_poison`（+0.153）也大幅上升——这些依赖说服、伪装、跨智能体操纵等交互动态。
  - `mail_rag_phishing` 几乎不变（0.610 → 0.579，−0.031），说明检索类漏洞主要源于检索管线而非交互动态。
- **用户行为敏感性低**：三种温度下 ASR 仅在 0.270–0.284 间波动，无统计显著差异；个别领域（如 crm_leak）局部敏感（pass^1 有 15pp 差异）。
- **能力 ≠ 安全**：模型能力提升并不一致地转化为更强稳健性。**GPT-5 家族在 dual-control 下恶化最严重**（GPT-5-nano：0.314 → 0.793，+0.479；GPT-5：+0.390；GPT-5-mini：+0.450）；Claude 系列整体最稳健（Dual ASR 0.086–0.164）。
- **可靠性随 k 下降**：pass^1=0.722 → pass^5=0.596，说明许多成功并不稳定；`auth_spoof_support`、`collab`、`tool_shadow_poison` 较稳定，`infra_loadshed`、`mktg_phishing`、`output_handling` 对轨迹依赖更强。
- **轨迹诊断**：dual-control 轨迹明显更长（中位数 16 条消息 vs solo 8 条）；94.5% 由用户模拟器停止条件终止；失败中 81.9% 触发确定性环境/状态断言，18.1% 触发通信断言。
- **核心论断**：智能体安全**并非模型自身属性，而是模型、用户与环境交互的涌现属性**。

## 7. 优点

- **评估范式创新**：首次系统地将"双控交互"引入 LLM 智能体安全评估，填补交互式对抗评估的空白。
- **断言设计严谨**：确定性状态断言为主（不受 LLM 评判偏差影响），通信断言为辅补足文本层面违规；合取式奖励杜绝部分合规，避免"表面安全"。
- **指标完备**：ASR + pass^k 双指标互补，后者刻画重复交互下的可靠性，揭示轨迹依赖型脆弱性。
- **实验覆盖广**：14 个模型、5 个厂商、8 个领域、3 档用户温度，横跨能力谱系，结论具有跨架构泛化性。
- **可控性与可复现性**：用户侧 backbone 固定、智能体解码确定性、每配置 5 次独立重复、统计检验规范；开源仓库提供任务定义、prompt、seed、脚本与定性轨迹。
- **评判器可信度验证**：对 60 条通信断言进行人工审计（56/60 一致），并公开分歧案例类型（output_handling 中因措辞严格导致的边界分歧）。
- **伦理与缓解方向明确**：附录 F 针对各领域给出溯源感知检索、策略门控工具调用、强制验证门、输出消毒、独立护栏等具体防御方向。

## 8. 不足与局限

- **基准规模有限**：仅 35 个可执行场景、8 个领域，部分领域仅 3–4 个任务，无法穷尽智能体安全风险空间，领域级结论的统计效力有限。
- **用户模拟器真实性不足**：由 LLM 生成，难以完全复现真实人类用户的多样性与不可预测性；用户侧固定为 GPT-4o-mini，可能引入特定模型的交互风格偏差。
- **LLM 评判方差**：部分任务依赖 GPT-4o 对通信断言进行评判，存在评估器方差；人工审计虽显示 56/60 一致，但仍有 4 例分歧或模糊。
- **未做因子隔离**：solo-to-dual 的对比同时改变了多轮交互、用户影响、环境状态演化等多个因素，只能解释为**机制级稳健性差距**，而非任一单一组件的边际因果效应；作者承认这是当前设计的局限。
- **模型家族归因受限**：GPT-5 家族表现出最大偏移，但因其推理模式无法通过 API 完全关闭（以最小可用推理设置运行），无法将推理模式与其他家族差异的因果贡献分离。
- **算力与成本未披露**：未报告 GPU 规格、数量或 API 调用总量，复现成本难以评估；温度敏感性实验被迫使用缩减子集，正是出于计算与财务可处理性考虑。
- **应用限制**：基准聚焦于特定领域（邮件、CRM、客服、营销、基础设施、工具清单），对更开放、更复杂的真实智能体部署覆盖有限；作者定位其为"方法论基准而非模型排行榜"。
