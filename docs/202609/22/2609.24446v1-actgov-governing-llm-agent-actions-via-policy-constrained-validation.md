## 摘要
大语言模型（LLM）智能体日益通过外部工具执行长时程工作流，这使得不可信输出能够影响后续动作并超出用户授权范围。现有防御措施隔离注入内容，或通过预定义计划和静态策略约束执行，但这些方法在动态工作流下较为脆弱，并且难以扩展到可扩展的工具生态系统。在这项工作中，我们提出ActGov，一个运行时强制实施框架，在LLM提出的每个工具动作造成外部影响之前对其进行校验。基于授权、动作、运行时上下文和安全约束的统一语义模型，ActGov-Policy组件从工具规范、良性任务和观察到的失败轨迹中迭代构建策略集，并通过基于SMT的反例检查验证每次更新。在运行时，ActGov-Runtime将每个工具调用抽象为有限策略记录，并且仅当该调用保持在任务范围的授权边界内且满足所有适用策略时才允许其执行。这种逐动作的强制实施在整个长时程、动态分支的工作流中维持授权。我们在AgentDojo和AgentDyn基准上，跨多个模型和攻击配置评估ActGov。结果表明，ActGov在保持任务效用的同时，持续降低间接提示注入攻击的成功率，并显著优于现有防御方法。这些结果表明，ActGov能够对动态智能体执行实施细粒度授权，而无需依赖底层LLM正确识别恶意指令。

## Abstract
Large language model (LLM) agents increasingly execute long-horizon workflows through external tools, allowing untrusted outputs to influence subsequent actions and exceed user authorization. Existing defenses isolate injected content or constrain execution with predefined plans and static policies, but these approaches are brittle under dynamic workflows and scale poorly across extensible tool ecosystems.   In this work, we present ActGov, a runtime enforcement framework that validates each LLM-proposed tool action before it causes external effects. Built on a unified semantic model of authorization, actions, runtime context, and security constraints, the ActGov-Policy component iteratively constructs a policy set from tool specifications, benign tasks, and observed failure traces, with each update verified through SMT-based counterexample checking. At runtime, ActGov-Runtime abstracts each tool call into finite policy records and permits it only if it remains within the task-scoped authorization boundary and satisfies all applicable policies. This per-action enforcement preserves authorization throughout long-horizon, dynamically branching workflows.   We evaluate ActGov on the AgentDojo and AgentDyn benchmarks across multiple models and attack configurations. It shows that ActGov consistently reduces the success rate of indirect prompt-injection attacks while preserving task utility, significantly outperforming existing defenses. These results demonstrate that ActGov can enforce fine-grained authorization over dynamic agent executions without relying on the underlying LLM to correctly identify malicious instructions.

# ActGov 论文总结

## 1. 核心问题与研究动机

- **背景**：LLM 正从文本生成器演变为可规划、调用工具、观察环境并执行多步动作的自主智能体（邮件、日历、文件系统、代码仓库、金融账户等）。安全边界随之改变：模型输出可直接触发高风险操作（修改、删除、授权）。
- **核心风险**：不可信外部内容（工具观测结果）被误当作"用户意图"，导致智能体执行未授权动作，即**间接提示注入（IPI）**。工具结果与后续动作之间存在动态依赖，因此需要在**每次工具调用层面**做授权，而非输入/输出级过滤。
- **现有防御的三点不足**：
  - 缺乏统一语义框架来表示智能体动作，容易混淆数据来源与授权来源；
  - 对长时程、动态分支的工作流鲁棒性差——预定义计划、期望工具轨迹、静态参数清单要么过度限制合法自适应行为，要么在执行偏离假设时失效；
  - 策略构建难以在规模化与安全保障间兼顾——自动生成策略缺少检测遗漏、冲突、意外权限的严格机制；形式验证方法（如 VeriGuard）常把策略逻辑与具体运行时状态割裂验证。
- **整体含义**：ActGov 主张将"动作提议"与"执行授权"分离——LLM 可自由提议动作，但任何外部效果产生前必须通过经过形式化验证的策略校验，从而不依赖底层 LLM 正确识别恶意指令。

## 2. 方法论

### 2.1 核心思想与形式化模型

- **统一语义抽象**：把非结构化运行时上下文映射为**有限二维记录空间 R**，两个维度为正交的：
  - **形成层级（Formation Level）**：`L1 确定性`（直接从结构化系统状态计算）、`L2 有界语义`（需 LLM 作为语义解析器从非结构化文本抽取到有限值域）、`L3 组合`（由 L1/L2 经布尔逻辑组合，表达组合/时序依赖）。
  - **语义域（Semantic Scope）**：7 类——`action`、`permission`、`parameter`、`history`、`binding`、`external`、`domain`。
- **有限状态机建模**：智能体被建模为
  `M = (H, C, R, P, V, T)`
  其中 H 为执行历史状态空间，C 为候选工具调用空间，R 为有限记录空间，P 为策略集；评价函数 `V: R × P → {allow, deny}` 产生确定性裁决 `v_i`；状态转移 `T: H × C × V → H`。**当且仅当 `v_i = allowed` 时外部工具才被执行**。

### 2.2 ActGov-Policy（策略生成与迭代）

- **输入三源**：工具规范（能力与风险约束）、良性任务轨迹（识别过度限制的规则）、观察到的攻击失败轨迹（识别缺失的安全条件）。
- **LLM 角色限定**：仅作为"策略提议者"与"有界语义解析器"，不承担授权判定；候选规则须经形式化检查与管理员复核。
- **三层策略**：`P = P_TP ∪ P_HI ∪ P_PO`
  - **Task-Permission（P_TP）**：把可信用户任务绑定到最小必需工具与资源，生成基线授权边界 `perm`，越界动作被阻断。
  - **Hard-Invariant（P_HI）**：全局安全属性，如禁止源自不可信注入内容的外发网络动作，与任务范围无关。
  - **Procedural-Obligation（P_PO）**：条件性规则，针对目标绑定弱、参数来源不确定等超出智能体自主处理权的情形，要求先满足前置条件（如 `REQUIRE_APPROVAL` / `ESCALATE`）。
- **验证门控演化（Z3/SMT）**：对任一预定义安全断言 `A_sec`，求解器在有限记录域中搜索满足策略语义却违反断言的反例：
  `∃r, v . Domain_R(r) ∧ P_sem(r, v) ∧ ¬A_sec(r, v)`
  - **SAT** → 暴露策略缺口或冲突，触发策略精化；
  - 所有查询均为 **UNSAT** → 才允许部署，数学上保证更新后的策略维持既有安全不变量。
- **架构分工**：把昂贵的 Z3 求解完全放到离线阶段，运行时无需在线策略合成或求解器调用。

### 2.3 ActGov-Runtime（上下文抽象与策略检查）

- 部署于 LLM 与外部工具接口之间，拦截候选调用 `c_i`。
- **记录抽象**：`r_i = α_R(τ, perm, H_i, c_i)`，按二维模式填充记录集。
- **判定逻辑**：先由 `P_TP` 给出基线权限边界 `perm`，再在边界内对 `P_HI`、`P_PO` 求值；动作被允许当且仅当**位于 `perm` 内且不违反任何安全策略**。
- **防注入设计**：LLM 只做局部上下文特征抽取（如判断参数来源是否为不可信），输出布尔/枚举值，避免其进行端到端安全推理或幻觉决策。
- **记录与规则示例**：L1 记录如 `has_outbound_tag`、`tool_allowed`、`pending_obligations_open`；L2 记录如 `arg::<arg>::provenance`、`arg::<arg>::target_role`；L3 记录如 `same_site_download_link`、`contextual_binding_currently_valid`。规则库含 `TASK-PERM-001`、`KERNEL-HI-OUTBOUND`、`HI-INJECTED-DOWNLOAD-NO-FILE-AUTHORITY`、`REFINE-UNTRUSTED-TARGET`、`KERNEL-PO-MODEL-GENERATED` 等，效果类型包括 `DENY / REQUIRE_APPROVAL / ESCALATE / ALLOW`，且 DENY/REQUIRE_APPROVAL 优先于 ALLOW。

### 2.4 威胁模型

- 初始用户指令可信；攻击者通过下游工具观测注入内容，诱导 LLM 提出未授权动作。
- 攻击者可控制外部内容并操纵动作提议，但**不能修改可信用户任务，也不能修改 ActGov 执行层**（工具规范与已部署策略）。
- 假设：任何动作若不先通过 ActGov 的执行前校验，就无法产生外部效果。

## 6. 主要结论与发现

- **防御有效性**：AgentDyn 测试集上，ActGov 在四个模型上将 **ASR 限制在 ≤ 0.007**；AgentDojo 测试集上 **ASR 达到 0.000**，同时保持有竞争力的 clean/attacked utility。
- **效用保持**：如 Qwen3.6-Flash 在 AgentDyn 上 ActGov 保留 0.667 / 0.586（无防御为 0.667 / 0.650），下降幅度有限；AgentDojo 上表现最优。
- **对比优势**：CaMeL 与 ACE 通过结构性限制获得低 ASR，但在 AgentDyn 上效用损失严重；Progent 与 DRIFT 在结构化的 AgentDojo 上表现较好，但在长轨迹、大工具集、跨应用动态交互的 AgentDyn 上退化，且对后端 LLM 能力敏感。ActGov 更稳定，因为 LLM 仅做有界记录抽取，授权判定为确定性计算。
- **RQ3 发现**：策略生成 LLM 的能力显著影响效用（DeepSeek

…-v4-pro 作为策略生成器时表现最佳，Qwen3.6-flash 等较弱模型生成的策略在覆盖度与松紧度平衡上更差）；训练数据规模从 50% 缩减到 25% 时，安全性能仍可维持，但效用与策略覆盖度出现可见下降，说明 ActGov-Policy 对训练轨迹的数量与多样性存在一定依赖。
- **跨域迁移（表 5）**：把在一个基准上学到的策略直接迁移到另一个基准时，效用显著下滑，说明策略中隐含了域特定的工具语义与资源命名，泛化到结构差异较大的环境需要重新精化，作者据此将跨域策略复用列为开放问题。
- **总体结论**：将"动作提议"与"执行授权"解耦、把安全判定收敛为对有限记录空间的确定性求值，是在不牺牲（过多）合法自适应能力的前提下压制 IPI 的有效路径；LLM 只作为有界语义解析器而非授权主体，是该方法对后端模型能力不敏感、跨模型稳定的关键原因。

## 7. 局限性

- **安全以效用为代价**：在动态开放的 AgentDyn 上，ActGov 的效用低于无防御配置（如 0.600/0.511 vs 0.767/0.729），说明硬性不变量与程序性义务会拦截部分合法但边界模糊的动作。
- **依赖策略质量**：安全性由策略集的完备性决定，而策略由 LLM 提议、经形式化验证与人工复核产生；验证只能保证"不违反给定安全断言"，无法保证断言集合本身覆盖了所有攻击面。
- **威胁模型假设较强**：假定执行层（工具规范、已部署策略）不可被攻击者篡改，且初始用户指令可信；对能直接污染工具规范、策略库或运行时组件的攻击者不适用。
- **语义解析仍是薄弱环节**：L2 记录依赖 LLM 判断参数来源、目标角色等语义属性，若解析错误（把不可信来源误判为可信），确定性判定也会基于错误记录放行。
- **评估覆盖有限**：未与 VeriGuard 对比；未测试越狱、工具投毒、多轮自适应对抗等攻击形态；未报告延迟、吞吐、Z3 求解耗时等工程指标；跨域迁移性能下降明显。
- **可复现性信息缺口**：论文未披露任何算力/显存/训练时长数据，也未给出运行时性能开销，第三方复现与部署评估存在障碍。

## 8. 贡献与启示（评价）

- **理论贡献**：提出"形成层级 × 语义域"的二维有限记录空间，为异构、非结构化的智能体运行时上下文提供了统一的、可被形式化工具处理的语义抽象；并把智能体执行建模为带确定性裁决函数 `V` 的有限状态机，使"只有通过校验才产生外部效果"成为可证明的性质。
- **工程贡献**：给出"离线 Z3 验证 + 在线确定性判定"的分工架构，运行时无需调用求解器，兼顾了安全保证与可部署性；ActGov-Policy 以工具规范、良性轨迹、攻击失败轨迹三源驱动策略迭代，并用 SAT/UNSAT 作为部署门控。
- **方法论启示**：不要求底层 LLM"识别"恶意指令，而是把 LLM 降级为有界特征抽取器，是绕开"用模型防模型"这一脆弱范式的可行思路；对智能体安全研究而言，把安全属性写成可被 SMT 求解器反驳的断言，比写成自然语言策略更易于审计与维护。
- **适用边界**：方法最适合工具集与资源命名相对稳定、可枚举的环境（如企业 workspace、银行、差旅、Slack 类应用），在高度开放、工具动态注册、跨域组合的场景中，策略的维护成本与迁移损耗会显著上升。
