## 摘要
大语言模型智能体日益依赖自然语言技能来解决复杂的工具使用任务。然而，此类任务往往存在多条有效的求解路径，因此通过强制失败轨迹去匹配某条固定的成功轨迹来改进技能并不合适。此外，失败轨迹很少完全错误：智能体可能先收集到有用的证据并取得实质性进展，但随后偏离为一段错误的后续路径。因此我们认为，技能自演化应当识别有效的问题求解在何处开始失效，而不是对整段失败进行粗粒度的反思。基于这一洞见，我们提出SkillPivot，一个由偏差点引导的技能自演化框架。SkillPivot利用执行有效性、目标进展和动作多样性来检测从有用前缀到错误后缀的转变。随后，一个更强的教师模型从同一前缀继续，并在相同的交互历史下生成一条成功的替代路径。通过对比学生模型的失败后缀与教师模型的成功后缀，SkillPivot在保留已有效指导的同时生成局部化的技能更新。在ToolQA、LogicBench和WildClawBench上的实验表明，SkillPivot持续优于其他技能演化方法，能够提升多种智能体模型，并产生紧凑且可迁移的技能更新。

## Abstract
Large language model agents increasingly rely on natural-language skills to solve complex tool-use tasks. However, such tasks often admit multiple valid solution paths, making it inappropriate to improve skills by forcing failed trajectories to match a fixed successful trajectory. Moreover, failed trajectories are rarely entirely wrong: an agent may first collect useful evidence and make meaningful progress, but later deviate into an erroneous suffix. We therefore argue that skill self-evolution should identify where productive problem solving begins to break down, rather than reflect coarsely over the entire failure. Based on this insight, we propose SkillPivot, a deviation-point-guided framework for skill self-evolution. SkillPivot detects the transition from a useful prefix to an erroneous suffix using execution validity, goal progress, and action diversity. A stronger teacher then continues from the same prefix and produces a successful alternative under the same interaction history. By contrasting the student's failed suffix with the teacher's successful suffix, SkillPivot generates localized skill updates while preserving already effective guidance. Experiments on ToolQA, LogicBench, and WildClawBench show that SkillPivot consistently outperforms competing skill-evolution methods, improves multiple agent models, and produces compact, transferable skill updates.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体（Agent）在真实场景中通过自然语言"技能库"（skill corpus）获得程序性知识——何时调用工具、如何构造参数、如何解释观测、何时验证中间结果、如何从异常工具反馈中恢复。然而即使是高质量技能也常不完备，会遗漏边界情况、恢复策略或工具特定约束。
- **核心问题**：能否让智能体从**自身交互失败**中演化已有技能库（skill self-evolution），而不是从头生成技能？
- **现有方法的缺陷**：
  - 复杂工具任务往往存在**多条有效解路径**，用"强制对齐单条成功轨迹"的方式改进技能并不合理；
  - 已有方法（全轨迹反思、成功轨迹模仿、开放式技能重写）默认**整条失败轨迹都是错的**；
  - 但失败轨迹通常是"**局部错误**"：智能体先完成了有用的探索、收集证据、缩小解空间，之后才在某个点开始重复无效调用、过早停止或错误解读观测。
  - 因此对整条轨迹做粗粒度反思，会把**有用前缀与有害后缀混在一起**，产生噪声大、范围过宽或过度实例化的技能更新。
- **核心主张**：技能自演化应定位"有效求解在何处开始崩坏"，以该**偏差点（deviation point）**为锚点生成**局部、条件化、可审计**的技能增量，同时保留原本有效的指导。

## 2. 方法论：SkillPivot 框架

### 2.1 问题形式化

- 设第 r 轮技能库为 $S^r=\{s^r_1,\dots,s^r_M\}$，任务集 $D^r=\{x_i\}$；学生智能体产生 ReAct 式轨迹 $\tau_i=(x_i,h_{i,1},a_{i,1},o_{i,1},\dots,y_i)$，由评估器 $E(\tau_i,x_i)\in\{0,1\}$ 判定成功与否，分为成功池 $T^+$ 与失败池 $T^-$。
- 目标是学习更新算子 $\Phi$，产生技能增量 $\Delta S^r=\Phi(S^r,T^+,T^-)$，并得到 $S^{r+1}=\text{Update}(S^r,\Delta S^r)$。
- 优化目标：在未来任务上最大化期望成功率，**同时约束**在 $S^r$ 下已可解任务上的回退（bounded regression）。即技能演化被建模为"**带约束的维护问题**"，而非单纯的失败修补。

### 2.2 五阶段流程

1. **学生 Rollout**：学生带着当前技能库执行任务批次，保留完整交互轨迹（最终答案之外的失败往往只能从轨迹看出，如命令层级错误、参数来源错误、忽略空返回、未验证环境状态就停止）。成功轨迹进入成功池（用于后续回归检验），失败轨迹进入失败池。
2. **偏差点检测（Deviation Point Detection）**：为每一步计算"进展势能"分数
   $$\hat V_t = 0.4\,\text{Exec}_t + 0.3\,\text{Prog}_t + 0.3\,\text{Div}_t$$
   - $\text{Exec}_t$：基于确定性规则的执行有效性（动作合法性、工具执行状态、返回观测可用性）。
   - $\text{Prog}_t$：观测与任务目标（用 ground-truth 作为任务目标的语义表示，经 all-MiniLM-L6-v2 编码）的余弦相似度，且**只计相对历史最优的增量**：$\text{Prog}_t=\max(0,\ \text{sim}(o_t,y)-\max_{j<t}\text{sim}(o_j,y))$，避免重复证据被反复计分。
   - $\text{Div}_t = 1-\max_{j<t}\text{sim}(a_t,a_j)$：动作多样性，低值表示重复此前策略。
   - 先取 $\hat V_t$ 最低步作为候选偏差点，再要求其**形成明显低谷且后续步骤持续低分**，才确认为真正的偏差点，以防过早截断仍有用的前缀。
3. **教师 Rollout**：更强的教师模型从**同一前缀**继续（而非从头重做），输入包括任务、当前技能库、学生的偏差前轨迹前缀，以及完整失败轨迹（作为"应避免什么"的参考）。使用**内联 reflector**：每步后生成简短提示加入教师 scratchpad，但**不写入保存的原始轨迹**，避免污染后续对比。教师续写通过评估器才被接受，否则丢弃或从同一偏差点重试（上限 3 次）。
4. **成对后缀对比与技能生成**：
   - 单案例轨迹摘要器分析每个"教师纠正成功"的配对案例，识别学生的错误、教师的纠正、技能中缺失/不完整的指导，以及总体演化方向，输出**结构化案例分析**而非直接改写技能；
   - 技能增量生成器聚合多个结构化分析，提出候选增量，可选三种动作：`improve_skill`（更新技能内容）、`optimize_description`（细化描述或触发条件）、`skip`（证据不足时不动）。
5. **回归门控技能更新（Regression-Gated Update）**：LLM 编辑器先把增量套用到原技能得到暂定技能 $s'$，再由 LLM 审查器按两条标准打分（均归一化到 $[0,1]$）：
   - **no_regression**：是否保留原技能中的有效规则，未无理由地删除、弱化、覆盖或矛盾；
   - **generalizable rule**：新增指导是否为可复用的程序性原则，而非针对触发案例的一次性补丁。
   - 仅当 $r_{reg}\ge\theta$ 且 $r_{gen}\ge\theta$（实现中 $\theta=0.5$）才接受并入技能库；被拒则保留原技能，增量仅作为候选记录。该门控使演化"保守化"：每次部署的更新都必须修复已观测失败且不牺牲已有能力。

## 6. 主要结论与发现

- **RQ1（有效性与跨组泛化）**：技能演化在全部 6 个目标组上均优于 Non-evo，最终累积技能库把 ToolQA 平均成功率从 **53.18% 提升到 59.36%**，且增益不局限于演化来源组，说明学到的是**跨组可复用的失败模式与局部规则**，而非实例级补丁。
- **RQ2（方法对比）**：SkillPivot 以**相对紧凑的技能长度（1338 字符）**取得最高准确率 59.36%；AutoSkill 改动最大（8965 字符）但收益有限（53.85%），因为它把技能改写成通用 prompt 模板，稀释了关键操作规则；SkillClaw（54.85%）、SkillForge（53.95%）仅做局部约束/启发式补充，缺乏系统性恢复流程。结论是**技能演化效果取决于"是否把失败转化为可复用程序性指导"，而非改动量**。
- **RQ3（跨模型迁移）**：演化后的技能对全部 5 个模型均有正增益，甚至使部分较弱模型在原技能下的更强模型面前变得有竞争力，说明技能库沉淀的是**可执行的任务策略**而非模型特定修正。
- **RQ4（偏差点可靠性）**：SkillPivot 的偏差点一致性 70.81%、续写成功率 56.18%、平均续写步数 5.95、无效调用率仅 2.93%，显著优于 Random Intervention（一致性 13.32%、无效调用 29.68%）与 From Scratch；LLM 定位法虽一致性高（约 70–72%），但续写成功率（45

…% 左右）明显低于 SkillPivot，说明"能指出哪里出问题"与"能真正接着做对"是两种能力，LLM 定位法容易停在"看起来可疑"的步骤而缺乏可恢复性；Step-wise LLM Verifier 虽逐句核验，但缺少"低谷+后续持续低分"的序列级证据，容易把仍在推进的正常步骤误判为偏差点；From Scratch 教师从头重做时平均步数最长、无效调用率最高，因为丢失了学生已获得的环境状态与证据。结论：**偏差点的价值不只在"定位"，更在于保留可复用的有效前缀**，使教师只需在局部重新决策。
- **RQ5（更新证据形式消融）**：四种策略中 SkillPivot 最优。Whole-Trajectory Reflection 因把有用前缀与有害后缀混在一起反思，产出泛化而空洞的规则；Failure-only Reflection 只看到失败面，容易写成针对该案例的一次性规避条款（过度实例化）；Teacher-only Imitation 直接模仿教师轨迹，隐含"只有教师的路径才对"，与多解路径的任务特性冲突，且丢失了学生的错误信号，无法解释"为什么错"。只有**成对后缀对比**同时提供了"错误的具体形态"与"正确的替代行为"，生成的规则既具体又可迁移。
- **RQ6（回归门控消融）**：去掉 review 后，演化初期成功率可能上升更快（因为增量更激进、更贴合当前失败），但随轮次累积出现明显回退，跨组差异矩阵显示某些目标组出现负增益；加入 review 后曲线更平缓但单调，长期累积收益更高。说明门控的核心作用不是提升单轮收益，而是**抑制多轮演化中的漂移与能力侵蚀**，验证了把技能演化建模为"带约束的维护问题"的必要性。
- **RQ7（跨 benchmark 迁移）**：在 LogicBench 与 WildClawBench 上，SkillPivot 同样优于三种对比方法，且增益模式与 ToolQA 一致（紧凑技能 + 稳定累积提升）。WildClawBench 上因技能覆盖更全、任务更开放，绝对增益略小，但相对优势保持，说明方法**不依赖特定工具接口或特定评估器**，具备一定域外可迁移性。

## 7. 局限性与可改进之处

- **偏差点检测依赖"进展势能"这一启发式加权**：$\hat V_t$ 的权重（0.4/0.3/0.3）与"低谷+持续低分"的确认规则未见敏感性分析，也未报告在无 ground-truth 目标（真实部署场景）时 $\text{Prog}_t$ 如何定义——而真实场景通常拿不到任务的标准答案，这限制了方法在开放式任务上的直接可用性。
- **教师续写成功率仅约 56%**：意味着近一半的失败案例无法转化为有效技能增量，论文未分析失败续写案例的分布（是任务本身不可解、偏差点定位错误，还是教师能力不足），也未说明这些被丢弃案例是否造成了系统性偏差（只学到"容易修"的失败模式）。
- **评估器被当作可信真值**：成功/失败判定、教师续写是否被接受、门控是否通过，都建立在评估器与 LLM 审查器之上，未报告评估器噪声、误判率或对最终结论的影响；LLM 评审的偏差点一致性也非人类标注。
- **成本与效率未量化**：作为推理时多模块（学生 rollout + 定位 + 教师续写 + 摘要 + 生成 + 门控）方法，其 token 消耗与延迟显著高于 baseline，但论文既无成本数据，也无与收益的权衡讨论，难以判断在工业场景中的性价比。
- **技能长度与技能数量的管理**：论文关注单条技能的增量更新，但多轮累积后技能库的规模、冗余、冲突消解机制未讨论；SkillPivot 技能长度（1338 字符）较紧凑是一大优点，但长期演化的膨胀趋势未见分析。
- **未与参数层方法对比**：未与微调、RL、记忆/经验库类方法（如带经验回放的智能体）比较，因而无法判断"技能自演化"相对"参数更新"的边界与适用场景。

## 8. 总体评价与启示

- **核心贡献**：把 LLM 智能体的技能自演化从"整条轨迹的粗粒度反思/模仿"重构为"**偏差点锚定的局部后缀对比 + 回归门控的保守更新**"，并形式化为带约束的维护问题。这一视角的转换比具体模块更重要：它同时解释了为什么已有方法会产出噪声大、过宽或过度实例化的技能，也给出了可操作的对策。
- **方法论亮点**：
  - "只续写、不重做"——最大化利用学生已有的有效前缀，既降低教师负担，又天然保留了多解路径的合理性；
  - "成对对比"——用同一前缀下的错误后缀与正确后缀构成最小对照，是产生可迁移规则的关键证据形式；
  - "门控而非重写"——把更新当作需要审计的提案，而非直接覆盖，与工程上的"变更管理"思路一致。
- **可迁移的启发**：
  - 任何"从失败中学习"的系统，都应先回答"**从哪里开始失败的**"，再决定"学什么"；
  - 细粒度反馈的获取成本通常远低于细粒度反馈的质量收益，值得在流水线中显式设计"定位"环节；
  - 演化型系统需要**回退约束**，否则短期收益会被长期漂移吞掉。
- **适用边界**：适合有多步工具调用、存在多条有效解路径、且有可靠评估器的任务；对单步问答类任务、无评估器的开放任务、以及评估器本身不可靠的场景，需谨慎使用或改造偏差点信号。
