## 摘要
大型语言模型（LLM）智能体常常处理一系列相关任务，但标准执行框架却反复要求模型在每个任务的上下文中重新构建相同的控制决策。我们研究任务反馈是否能够转而将重复出现的控制转化为可复用的可执行代码，同时将 LLM 调用保留给任务特定的语义推理。我们提出 Growing Harness，一种由失败引导的训练范式，它从一个无策略脚手架中学习智能体执行框架本身；该脚手架暴露固定的模型与工具接口，但不编码任何任务求解控制器。函数级执行轨迹将每个失败定位到一个有界代码表面，优化器联合修复一个失败窗口，而成功优先的留出集门控会回滚那些损害先前能力的修复序列。被接受的编辑会累积在一个共享执行框架中，使其控制结构能够从任务反馈中涌现。在 BrowseComp-Plus 和 WebArena-Verified 上，使用参数规模从 4B 到 120B 的三个部署模型时，Growing Harness 在六种基准-模型设置中的五种取得最高平均成功率，在第六种中比最佳平均值低 0.7 个百分点。相对于工具调用智能体，它将 LLM 调用次数减少 76.0-91.8%，并将部署智能体的推理成本降低 74.4-98.6%。在 WebArena-Verified 上，其成功率在不同模型规模下保持在 44.7-45.3%，而工具调用在 4B 模型上降至 6.7%。消融实验表明，轨迹局部编辑、联合修复和基于门控的回滚各自都能提升最终成功率。这些结果表明，持续的程序生长可以将重复出现的控制从模型上下文中移出并转入低成本代码，从而产生可复用的专家智能体，使其在更小的部署模型上仍然有效。

## Abstract
Large language model (LLM) agents often handle streams of related tasks, yet standard harnesses repeatedly ask the model to reconstruct the same control decisions inside each task's context. We study whether task feedback can instead turn recurring control into reusable executable code, while reserving LLM calls for task-specific semantic reasoning. We introduce Growing Harness, a failure-guided training paradigm that learns the agent harness itself from a strategy-free scaffold that exposes fixed model and tool interfaces but encodes no task-solving controller. Function-level execution traces localize each failure to a bounded code surface, an optimizer repairs a window of failures jointly, and a success-first held-out gate rolls back repair sequences that harm prior capability. Accepted edits accumulate in one shared harness, allowing its control structure to emerge from task feedback. Across BrowseComp-Plus and WebArena-Verified with three deployment models from 4B to 120B parameters, Growing Harness achieves the highest mean success in five of six benchmark-model settings and trails the best mean by 0.7 pp. in the sixth. Relative to a Tool-Calling agent, it reduces LLM calls by 76.0-91.8% and deployed-agent inference cost by 74.4-98.6%. On WebArena-Verified, its success remains 44.7-45.3% across model scales, whereas Tool-Calling falls to 6.7% with the 4B model. Ablations show that trace-local edits, joint repair, and gate-based rollback each improve final success. These results show that persistent program growth can move recurring control out of model context and into low-cost code, yielding reusable specialist agents that remain effective with smaller deployment models.

## 二、方法论：Growing Harness

### 1. 核心思想

- 从一个**无策略脚手架** \(h_0\) 出发：只暴露任务入口、固定 LLM 接口与固定工具接口，不包含 ReAct 式工具调用循环或任何完整控制器。
- 固定模型 \(M\) 与工具集 \(T\)，只学习 harness 代码 \(h\)。
- 通过失败引导的持续程序增长，使控制结构从任务反馈中自然涌现，而不是预先规定。

### 2. 关键流程

- **函数级执行轨迹**：每次任务执行记录执行图 \(G_i=(V_i,E_i)\)，节点包括 harness 函数调用、LLM 调用、工具调用、返回与错误；边表示动态调用作用域。
- 每个失败任务形成轨迹 \(\tau_i=(x_i,G_i,y_i,o_i,u_i)\)，其中 \(o_i\) 为成功/失败结果，\(u_i\) 记录 token、成本、运行时间。
- 提取失败涉及的 harness 函数集合 \(F(\tau_i)\)，用于把失败定位到有界代码表面。

- **失败窗口课程**：
  - 维护容量为 \(K\) 的当前失败窗口 \(W_t\)。
  - 每个条目包含任务、最新轨迹、修复尝试次数。
  - 优化器联合修复窗口内所有失败，以鼓励学习跨任务可复用行为。
  - 已解决任务离开窗口；未解决任务保留新轨迹并增加尝试计数；达到 \(R_{\max}\) 后退役。
  - 窗口更新近似为：\(W_{t+1}=\{x_i\in U_t:a_i<R_{\max}\}\cup F_t\)。

- **轨迹引导的函数级优化**：
  - 优化器只能修改入口函数 `main` 以及失败轨迹中调用过的函数：\(A_t=\{\text{main}\}\cup\bigcup_{x_i\in W_t}F(\tau_i)\)。
  - 允许新增可复用辅助函数，但不得修改未被轨迹覆盖的已有函数。
  - 设置函数级编辑预算 \(L\)，限制修改/新增函数数量。
  - 候选必须保持函数签名与运行时接口，不得删除已有函数，不得编码任务 ID、标准答案或固定解。
  - 优化器被引导将确定性、可复用控制写成代码；LLM 调用保留给语义解释、综合、模糊比较和答案生成。

- **候选评估与接受**：
  - 候选 harness 在完整失败窗口上重新执行。
  - 只有修复数量达到阈值 \(Q\) 才进入门控验证；否则回滚。
  - 有效候选成为临时 harness，解决任务离开窗口，未解决任务继续保留。

- **成功优先的留出集门控与事务回滚**：
  - 在留出集 \(G\) 上评估当前 harness，若 \(SR_G(h_t)\ge SR_G(h_{\text{gate}})\) 才接受。
  - 若门控成功率下降，则回滚自上一个检查点以来的整条修复序列。
  - 回滚不仅恢复代码，还恢复任务游标、失败窗口、计数器与训练记录。
  - 规则是“成功优先”：在线成本降低不能补偿门控成功率下降。
  - 最终在未见过的测试集 \(D_{te}\) 上只评估一次。

### 3. 算法概括

- 从 \(h_0\) 开始，循环执行：
  1. 在未见任务上运行当前 harness，收集失败与轨迹，填满失败窗口；
  2. 优化器基于轨迹生成完整可执行候选；
  3. 在窗口内重新执行候选，统计修复数；
  4. 修复不足则回滚；门控成功率下降则回滚；
  5. 接受候选，更新共享 harness；
  6. 更新窗口、尝试计数与任务游标，直到训练流耗尽。
- 最终得到可复用的学习 harness \(h^\star\)。

## 六、主要结论与发现

- **成功率领先**：在 6 个 benchmark–model 设置中，Growing Harness 在 5 个取得最高平均成功率；在 BrowseComp-Plus + gpt-oss-20b 中比 Tool-Calling 低 0.7 个百分点。
- **大幅降低调用与成本**：相对 Tool-Calling，LLM 调用减少 76.0–91.8%，部署智能体推理成本降低 74.4–98.6%。
- **跨模型规模稳定**：在 WebArena-Verified 上，成功率在不同模型规模下保持在 44.7–45.3%；而 Tool-Calling 从 gpt-oss-120b 的 30.0% 降至 Qwen3.5-4B 的 6.7%。
- **小模型收益最大**：可复用代码为小模型提供了原本需要在线重建的重复控制，因此模型越小，相对提升越明显。
- **任务族塑造控制器**：相同无策略种子在不同任务族上生长出不同结构——BrowseComp-Plus 形成共享检索与证据验证流水线；WebArena-Verified 形成包含确定性解析器、专门控制例程、通用浏览器循环与完成状态验证器的分层控制器。
- **消融结论**：
  - 去掉函数级指导：成功率从 36% 降至 18%，且前期门控进展停滞。
  - 去掉门控验证：门控成功率升至 30% 后跌至 16%，说明回滚对防止能力退化必要。
  - 去掉失败窗口、仅单失败修复：成功率降至 28%，说明联合修复有助于学习跨失败共享行为。
  - 三个机制互补，完整方法达到 36%。

## 七、优点

- **问题视角新颖**：把 harness 本身而非 prompt、工作流或技能库作为持久学习对象，提出“从无策略脚手架生长控制器”的范式。
- **低先验承诺**：不从 ReAct、Self-Ask 等预设控制器出发，允许可执行结构由任务反馈决定。
- **上下文结构性管理**：不是单纯压缩 prompt 或路由模型，而是把重复控制移入代码，从根本上减少在线推理与上下文压力。
- **函数级轨迹定位**：将任务级失败映射到有界函数集合，使每次优化只依赖活跃执行切片，而非整个程序，缓解程序增长带来的搜索空间膨胀。
- **成功优先门控与事务回滚**：针对持续优化中“局部修复损害旧能力”的风险，提供明确回滚机制。
- **实验覆盖较广**：两个任务族、三个模型规模、多个强基线、三次独立运行与 bootstrap 置信区间，主结果可信度较高。

## 八、缺点与局限

- **离线优化成本未量化**：论文只报告在线部署成本，未报告优化器调用次数、token 消耗、墙钟时间与总费用。由于优化器使用的是 GPT-5.6-terra、GPT-5.4 等强模型且推理强度为 High，离线开销可能相当可观，全生命周期摊销后的成本优势存疑。
- **算力与复现信息缺失**：未报告 GPU 型号、数量、训练总时长与总 token，难以评估方法的可复现性与资源门槛。
- **消融证据薄弱**：消融仅在单一 benchmark、单一部署模型、单一优化器下进行，且每个配置只运行一次、只优化 10 步，缺少置信区间与多次重复，结论的统计稳健性不足。
- **缺少与同类 harness/工作流优化方法的实证对比**：未与 AutoHarness、Meta-Harness、AFlow、ADAS 等直接比较，难以判断“程序增长”相对“工作流搜索/技能库学习”的边际增益。
- **门控集可能被间接优化**：虽然最终测试集只评估一次，但门控集在优化循环中被反复使用来决定接受/回滚，存在对门控集过拟合的风险，而论文未报告门控集与测试集分布漂移的分析。
- **失败窗口与超参敏感**：窗口容量 \(K\)、修复预算 \(R_{\max}\)、编辑预算 \(L\)、修复阈值 \(Q\) 等超参的选择依据不充分，缺少敏感性分析。
- **函数级编辑约束的副作用**：只允许修改失败轨迹中调用过的函数，可能抑制跨函数的全局重构；当失败根因位于未被轨迹覆盖的共享函数时，修复可能被局限在局部。
- **“不得编码任务 ID、标准答案或固定解”的约束**：该约束依赖优化器自律或事后检查，论文未说明如何自动验证候选是否真正满足这些语义约束，存在“变相硬编码”的隐患。
- **任务族覆盖有限**：仅两个 benchmark，且 WebArena-Verified 只取 shopping、reddit、map 三类网站，结论向其他任务族（如代码、科学推理、长程规划）的外推能力未知。
- **结构分析偏定性**：对最终 harness 的结构抽象主要是事后定性描述，缺少可量化的结构度量（如函数复用率、控制分支覆盖率、代码行数增长曲线）。
- **单次失败的负结果**：在 BrowseComp-Plus + gpt-oss-20b 上成功率略低于 Tool-Calling（-0.7 个百分点），说明方法并非在所有设置下都严格占优。

## 九、启示与展望

- **范式启示**：论文提示了一条不同于“提示工程”“工作流搜索”“技能库积累”的路线——把控制逻辑本身当作可持久化、可增量演化的软件工件，这为智能体系统的长期自我改进提供了新视角。
- **成本结构重构**：通过把一次性在线推理转化为可复用的离线代码，方法改变了智能体的成本曲线形状，对小模型与资源受限部署尤其有意义。
- **未来可探索方向**：
  - 报告并优化全生命周期成本，包括离线优化器开销的摊销分析；
  - 引入自动化约束检查，确保候选代码不硬编码任务标识或答案；
  - 在更多任务族与更长优化步数上验证结构生长的可扩展性；
  - 研究门控集与测试集之间的分布漂移，以及更稳健的验证协议；
  - 与 harness/工作流优化方法进行直接、公平的实验对比；
  - 探索多任务族共享 harness 的组合与迁移，以及 harness 的可读性、可维护性与人工审计机制。

## 十、总体评价

- 论文提出了一种有吸引力的智能体自改进范式：在固定模型与工具的前提下，让可执行 harness 通过失败驱动的程序增长逐步承担重复控制，从而把 LLM 保留给任务特定语义推理。
- 其核心贡献在于问题视角的转变与“函数级轨迹定位 + 失败窗口 + 成功优先门控回滚”这一套机制设计，而非单纯的性能数字提升。
- 主实验在成功率与效率上展现了较一致的帕累托改进，尤其对小模型收益显著；但离线成本不透明、消融偏弱、缺少同类方法实证对比，使其结论的普适性与可复现性仍需后续工作补强。
- 综合来看，这是一项**方向价值高于当前实证完备度**的工作：若能在成本核算、约束验证与更广泛任务族上进一步验证，其“harness 作为可学习程序工件”的思路有望对资源受限智能体部署产生实质影响。
