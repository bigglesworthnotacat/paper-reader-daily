## 摘要
LLM 智能体被部署到赋予其广泛主机权限的基础设施中，然而现有的智能体安全基准与防御几乎完全在应用遥测层运作：所服务的工具清单、用户提示以及模型的消息。然而，某些威胁会将恶意指令和操作偷运过应用边界，使其在该层不可见。在本工作中，我们弥合这一缺口，将应用层智能体遥测与内核级系统调用跟踪配对，首次给出面向智能体安全的内核级信号与应用层信号的配对证据刻画。为了量化增强遥测的价值，我们引入 Agent Cross-Layer Evidence（ACE），一个配对会话语料库，包含 4,047 个会话和 17 个威胁模型，覆盖六个投递向量家族以及 OWASP LLM 与智能体威胁类别 25 个中的 14 个，并组织为 12 种攻击机制，且对每种机制刻画最具判别力的证据所在。在四个不同的检测器家族上，我们发现内核证据本身具有判别力，且将其与应用层证据组合通常优于任一单层视角，揭示出单层分析可能遗漏的互补信号。我们进一步证明了对未见攻击家族的泛化能力以及对另一智能体运行时的迁移能力。总之，这些发现确立了跨层证据对智能体安全的价值。

## Abstract
LLM agents are deployed into infrastructure that grants them broad host authority, yet existing agent-security benchmarks and defenses operate almost exclusively at the application telemetry layer: the served tool manifest, the user prompt, and the model's messages. Some threats, however, smuggle malicious instructions and actions past the application boundary, leaving them invisible to that layer. In this work, we bridge that gap by pairing application-level agent telemetry with kernel-level syscall traces to present the first paired-evidence characterization of kernel-level versus application-layer signal for agent security. To quantify the value of the enhanced telemetry, we introduce Agent Cross-Layer Evidence (ACE), a paired-session corpus of 4,047 sessions and 17 threat models spanning six delivery-vector families and 14 of the 25 OWASP LLM and agentic threat categories, organized into 12 attack mechanics with per-mechanic characterization of where the most discriminative evidence lies. Across four distinct detector families, we find that kernel evidence is discriminative on its own and that composing it with application-layer evidence generally outperforms either single-layer view, revealing complementary signals that single-layer analyses can miss. We further demonstrate generalization to unseen attack families and transfer to an alternate agent runtime. Together, these findings establish the value of cross-layer evidence for agent security.

## 一、核心问题与整体含义（研究动机与背景）

- **部署现实**：LLM 智能体已被接入生产基础设施，能够读文件、调 API、执行 shell 命令，权限等价于一个完整用户 shell。Model Context Protocol（MCP）成为承重的插件面（JSON-RPC，`tools/list` 返回工具清单，`tools/call` 调用工具），2026 年中已有 2 万+ 第三方服务器；生产部署日益容器化。
- **核心缺口（Evidence Gap）**：现有智能体安全基准与防御几乎只工作在**应用遥测层**——所服务的工具清单、用户提示、模型消息。但部分威胁把恶意指令与动作偷运过应用边界，在该层完全不可见。
- **三种重叠攻击者模型**：
  - 包篡改（第三方 MCP 服务器被投毒）；
  - 针对内置工具的间接注入（文件 / 网页 / 检索语料 / 持久记忆文件中的载荷）；
  - 用户直接恶意提示（以良性任务为掩护）。
- **防御者设定**：事后审计者，观察单个已完成会话的内核系统调用轨迹、所服务的 `tools/list` 清单与智能体转录。对应生产 EDR 与审计流系统的部署形态，限定于单智能体单会话的回顾式检测。
- **两个候选证据流**：容器内工具进程树的系统调用轨迹（**内核证据 / Kernel-View**）与所服务的协议面（**应用层证据 / App-View**，即 `tools/list` + 智能体转录）；两者特征级拼接为 **Cross-View**。
- **整体含义**：此前两条证据线基本被孤立地插桩（AgentSight、ActPlane、Agent-Sentry、AuthGraph、FlowGuard 等均为执行或可观测系统，且无跨多入口向量捕获的配对会话语料）。本文首次系统测量：内核视角是否携带针对智能体形态攻击的判别信号，以及跨层组合是否优于任一单层视角。

## 二、方法论：核心思想、关键技术与流程

### 2.1 核心思想

- 构建**配对会话语料 ACE（Agent Cross-Layer Evidence）**，把内核侧系统调用轨迹、所服务的 `tools/list` 清单快照、智能体完整转录三者按会话同步对齐，在同一基底上比较内核层与应用层的判别力。

### 2.2 语料构建与威胁模型

- **规模**：4,047 个会话、17 个威胁模型、6 个投递向量家族（篡改 MCP 服务器、基于文件的间接注入、基于网页的间接注入、用户直接、基于记忆、检索/多步链），对齐 OWASP LLM Top 10 v2025 与 Agentic AI Threats and Mitigations v1.0 的 25 个类别中的 14 个（含 3 个部分覆盖）。
- **会话为分析单元**：一次 (威胁模型, 提示, 变体) 执行，运行在全新 Docker 容器中，容器启动到销毁界定，所有产物附于该粒度，所有检测器在该粒度打分。
- **捕获流水线**：Claude CLI（`claude-haiku-4-5` 作为智能体，非评判者）在全新 Docker 容器内运行，容器内 `strace` 传感器附着于工具进程树，覆盖 15 个 tracepoint（进程生命周期、文件系统 I/O、网络 I/O、传感器完整性），每会话平均约 3,500 个传感器事件；每会话持久化四类产物（元数据、完整转录、`tools/list` 清单快照、含完整 argv 与路径字符串的完整系统调用轨迹）。
- **归属（Attribution）是设计约束**：采用「单会话容器内单一 strace」——每个会话在自己的 Docker 容器内运行，恰好一个 strace 附着于容器根进程树。由两个内核性质保证按构造归属：(i) Docker PID 命名空间限定进程后代；(ii) 各容器自带 strace 写各自日志，无共享写目标。经验验证：10 轮 × 3 并发会话（共 30 会话、8,240 事件），跨会话污染事件为 0，会话级归属精度 100%。容器**隔离（Containment）明确不在范围内**，安全由内容级边界（合成凭据、TEST-NET 保留 IP、回环监听、静态补丁校验器）保证。

### 2.3 攻击机制分类

- 按**传感器可观测的执行机制**（而非投递向量或危害内容）组织：17 个威胁模型映射到 12 种攻击机制，再归入 7 个 OWASP 对齐的留出折（Fold A–G），用于 OOD 评估。
- 12 种机制包括：Bash 命令注入、凭据直接读取、静默日志外泄、资源耗尽、审计日志投毒、Schema 形状篡改、元数据提示注入、检索引用注入、输出指令写入、网络重定向外泄、偏好操纵、多阶段持久化。

### 2.4 任务形式化与特征

- 会话 $s=(\tau_k,\tau_a)$，$\tau_k$ 为内核轨迹、$\tau_a$ 为应用层证据。每补丁带**触发谓词** $f:s\to\{0,1\}$，由读内核的原子子句与读应用的原子子句经 AND/OR 组合（141 个恶意补丁设计中 57 个含应用层子句、70 个纯内核、14 个按构造无签名）。
- **四类标签**：Benign（y=0）；Malicious（补丁生效且谓词匹配，y=1）；Dormant（恶意变体运行但目标工具未被使用，y=0）；Latent（目标工具被使用但谓词未匹配；其中无签名的 66 个为 y=0，带签名的 396 个作为结构歧义从评分中剔除）。
- **特征化**：每会话映射到 **86 维数值向量** = 57 个内核层特征（会话总量、14 个 tracepoint 的每系统调用计数/对数计数/速率、8 个结构性系统调用对比例、IP/路径基数）+ 29 个应用层特征（提示结构、Schema 结构、工具调用/结果轨迹、结果新颖性）。特征只观察**结构性计数与基数，不读身份**（不按名称读机制特定哨兵串），故对重命名不变。
- **三个视图**：App-View（29 维）、Kernel-View（57 维）、Cross-View（86 维，特征级拼接）。

### 2.5 评估制度与检测器家族

- **两种折设计**：
  - 5 折分层（ID，分布内）：每种机制按比例同时出现在每折训练与测试中，测量「拟合语料」的上限。
  - 7 折 OWASP 对齐（OOD，分布外）：每折完整留出一个 OWASP 锚定攻击家族，训练行与 LLM 示范中完全缺席该家族，并施加**按主机匹配的良性**（贡献留出攻击的同一主机的良性行也留出），测量部署相关的泛化数。
- 报告均值 ± 每折按补丁聚类的 bootstrap 标准误（1,000 次重采样，恶意按攻击夹具聚类、良性按主机聚类）。
- **四类检测器 + 一个规则基线**：
  - 经典：AdaBoost、XGBoost（200 棵树，深度 3 /
