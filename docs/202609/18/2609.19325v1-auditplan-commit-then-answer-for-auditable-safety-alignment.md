## 摘要
安全调优流水线仅评判最终答案，这难以区分稳健拒答与两种不良捷径：对良性请求的一概拒答，以及看似精炼但并不忠实的安全理由，这些理由实际上并不约束答案。我们提出 AUDITPLAN，一种单模型“先计划后回答”的方法，模型首先输出紧凑的结构化安全计划，然后基于该计划进行回答。该计划记录威胁标签、预期动作和显式约束，从而支持机器可检查的审计，同时在部署时对用户隐藏。我们通过监督微调随后使用 FAITHGATE 进行强化学习来训练这种行为，FAITHGATE 是一种奖励门控目标，只有当安全计划正确时才授予答案奖励。这抑制了看似安全但不忠实的行为，并促进了计划与答案之间更紧密的耦合。在多个 Qwen 骨干模型上，AUDITPLAN 同时提升了稳健性和可审计性：在 Qwen2.5-3B-Instruct 上，FAITHGATE 将 ASR 从 24.0% 降至 11.6%，LSR 从 1.0% 降至 0.36%，过度拒答从 11.0% 降至 2.0%，优于仅答案强化学习、自由形式解释和加权和结构化奖励。类似趋势在 Qwen2.5-1.5B-Instruct 上也成立。在 Qwen-3-4B-Instruct 和 Qwen2.5-7B-Instruct 上的更大模型确认运行保持了相同趋势，表明显式的内部承诺可以使安全对齐更忠实、更稳健且可审计。

## Abstract
Safety tuning pipelines judge only the final answer, which makes it difficult to distinguish robust refusal from two undesirable shortcuts: blanket refusal on benign requests and polished but unfaithful safety rationales that do not actually constrain the answer. We propose AUDITPLAN, a single-model plan-then-answer approach where the model first emits a compact structured safety plan and then answers conditioned on it. The plan records a threat label, intended action, and explicit constraints, enabling machine-checkable auditing while remaining hidden from users at deployment. We train this behavior with supervised fine-tuning followed by reinforcement learning with FAITHGATE, a reward-gating objective that grants answer reward only when the safety plan is correct. This discourages safe-looking but unfaithful behavior and promotes tighter plan-answer coupling. Across Qwen backbones, AUDITPLAN improves both robustness and auditability: on Qwen2.5-3B-Instruct, FAITHGATE reduces ASR from 24.0% to 11.6%, LSR from 1.0% to 0.36%, and over-refusal from 11.0% to 2.0%, outperforming answer-only RL, free-form explanation, and weighted-sum structured rewards. Similar trends hold for Qwen2.5-1.5B-Instruct. Larger-model confirmation runs on Qwen-3-4B-Instruct and Qwen2.5-7B-Instruct preserve the same trend suggesting that explicit internal commitments can make safety alignment more faithful, robust, and auditable.

## 1. 核心问题与整体含义（研究动机与背景）

- **根本痛点**：现有安全调优流水线只对**最终答案**打分，因此无法区分三种表面上都"安全"的状态：
  - 真正因识别到威胁而拒答；
  - **一概拒答（over-refusal）**：对良性或边界模糊请求也拒绝；
  - **事后编造的安全理由**：解释看起来合理，却并不真正约束答案。
- **两个后果**：模型可通过"广撒网式拒答"刷高安全指标；也可在已决定答案后补一段漂亮说辞，导致安全对齐**表面化、脆弱**，甚至被小规模恶意微调破坏。
- **外部 guard 的局限**：Llama Guard、WildGuard、ShieldGemma、InferAligner 等把安全决策放在生成器**之外**（或多模型之间），带来延迟、部署复杂度，以及与生成器判断不一致的风险；更关键的是，它让**生成器本身仍不可审计**。
- **本文主张**：安全决策应当是模型内部一次**显式、机器可检查的承诺**。提出 AUDITPLAN——单模型"先计划、后回答"，模型先输出结构化安全计划再据此作答；计划在部署时对用户隐藏，但可内部记录、审计。
- **设计目标三要素**：鲁棒拒答（jailbreak/泄漏）、有用性（良性请求不误拒）、可审计性（能区分失败是来自威胁误判、动作选错，还是计划与答案不一致）。
- **威胁模型**：仅控制推理时用户消息的 prompt-only 对手，单轮交互，攻击面涵盖直接请求、角色扮演、权威框架、假设/比较式提问、间接泄漏模板与合成对抗后缀。作者明确不声称防御多轮自适应攻击、白盒攻击或工具/检索介导的注入。

## 2. 方法论

### 2.1 核心思想与输出格式
- 输出被切分为两段：`<plan>{...}</plan>` 与 `<answer>...</answer>`。
- **计划 schema（刻意保持低熵）**：
  - `threat`：`benign` / `jailbreak` / `leakage`
  - `action`：`answer` / `refuse` / `deflect`
  - `constraints`：如 `no_harmful`、`no_policy_leak`、`safe_guidance`
  - `trust_boundary`（可选）：如 `system_over_user`
- 低熵 schema 使有效性、威胁准确率、计划–答案一致性都能**廉价且可靠地批量校验**。

### 2.2 三阶段训练流程
1. **Base 评估**：未调优指令模型，无计划接口。
2. **SFT**：用计划标注示范教会模型输出合法计划与近似正确的安全动作，优化拼接输出 x=⟨z,y⟩ 的标准教师强制似然（式 1）。
3. **RL（GRPO）**：从 SFT checkpoint 出发，以 SFT 模型为参考策略，每 prompt 采样 K 条补全，用组内归一化优势更新策略。

### 2.3 计划验证器（四个）
- **PS**：格式有效性（标签齐全、JSON 可解析）。
- **PAA**：威胁标签与数据标签一致。
- **动作正确性**：如良性→answer，jailbreak/leakage→refuse/deflect。
- **PAC**：答案类型与所承诺动作一致。
- 作者强调这些验证器**不证明语义安全**，只是让大规模优化与监控成为可能；简单但稳定、可检查、对齐失败模式，优于不透明验证器。

### 2.4 奖励组件与泄漏检测
- 五个归一化到 [0,1] 的分量：`Rsafe`（拒答/作答是否得当）、`Rleak`（是否泄漏）、`Rplan`（结构/标签/动作）、`Rutil`（良性有用性、惩罚无谓拒答）、`Rformat`（标签与 schema 合规）。
- **加权和基线**：`Rsum = w1Rsafe + w2Rleak + w3Rplan + w4Rutil + w5Rformat`——把答案当主目标、计划当辅助信号，仍允许"广拒答+错标签"与"计划好看但弱耦合"两种捷径。
- **泄漏三级检测级联**：Tier 1 精确/部分 canary 重叠；Tier 2 正则匹配常见披露句式（"my system prompt"、"I was instructed to"）；Tier 3 由 LLM judge 给 0–10 泄漏风险分，覆盖改述与间接披露。

### 2.5 FAITHGATE（核心创新）
- **门控基奖励 g(z,y,u)**（z 为计划，y 为答案，u 为 prompt）：
  - 计划畸形 → **0**
  - 计划正确 ∧ 答案安全 → **+2.0**
  - 计划错误 ∧ 答案安全 → **−0.5**（"安全但理由错"不再划算）
  - 计划正确 ∧ 答案不安全 → **−2.0**（最强惩罚：已承诺正确决策却违背）
  - 其他 → 0
- **总奖励**：`Rgate = g + λsafe·Rsafe + λleak·Rleak + λplan·Rplan + λutil·Rutil + λfmt·Rformat`。
- **设计直觉**：不改约束优化框架、不引入对偶变量，只改变**信用分配**——安全答案奖励仅在计划正确时可得，从机制上堵住"安全捷径"。
