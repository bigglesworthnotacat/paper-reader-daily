## 摘要
汤普森在《对信任的信任的反思》中表明，编译器可被投毒以重新植入其自身的后门，以至于即使重新编译干净的源代码，也会重现该木马。如今，大量编程工作由 AI 编程智能体完成——而且这些智能体越来越多地生成自身的新版本。我们重新审视了当“编译器”是一个自我修改的编程智能体时的汤普森式攻击。攻击者能否向智能体的自我评估与自我改进过程提供投毒基准，从而诱导该智能体的未来版本在干净的留出任务上写出存在漏洞的代码？我们针对最近提出的三种自我修改编程智能体实例化了该攻击：Darwin Gödel Machine（带有我们的实验性修改）、Self-Improving Coding Agent 和 Hyperagents（后两者未作实质性修改）。我们展示了成功的概念验证：例如，在由 Sonnet 4.5 驱动的 Hyperagents 上，我们的投毒基准使智能体自我演化出在中性 URL 抓取任务中禁用 HTTPS 证书校验的指令。基于实验，我们提炼出足以促成基准投毒攻击的漏洞、基准、模型与智能体脚手架等方面的属性。此外，我们表明，即使被投毒的智能体随后针对干净基准进行演化，污染往往仍会持续存在。我们讨论了防御方向，并主张自我修改编程智能体的设计必须使其对此类攻击更具韧性。

## Abstract
Thompson's "Reflections on Trusting Trust" showed that a compiler can be poisoned to reinsert its own backdoor, so that even recompiling clean source reproduces the Trojan. Today, substantial coding work is done by AI coding agents -- and increasingly, those agents generate new versions of themselves. We reconsider Thompson's attack when the "compiler" is a self-modifying coding agent. Can an adversary supply poisoned benchmarks to the agent's self-evaluation and self-improvement process to induce future versions of the agent to write vulnerable code on clean, held-out tasks? We instantiate this attack against three recently proposed self-modifying coding agents: the Darwin Gödel Machine (with our experimental modifications), the Self-Improving Coding Agent, and Hyperagents (both substantively unmodified). We demonstrate successful proofs-of-concept: for example, with Hyperagents powered by Sonnet 4.5, our poisoned benchmark leads the agent to self-evolve instructions that disable HTTPS certificate validation on neutral URL-fetching tasks. From our experiments, we distill properties of the vulnerability, benchmark, model, and agent scaffolding that are sufficient to enable a benchmark poisoning attack. Moreover, we show that contamination often persists even when a poisoned agent is subsequently evolved against clean benchmarks. We discuss defensive directions and argue that self-modifying coding agents must be designed to be more resilient to such attacks.

# 论文总结：用投毒基准污染自我修改的 AI 编程智能体

## 1. 核心问题与研究动机

- **理论渊源**：Thompson 1984 年图灵奖演讲《对信任的信任的反思》证明，被投毒的编译器可在重新编译干净源码时自动重植后门，形成自我维持的木马。其道德训诫是"你不能信任任何并非完全由你自己创造的代码"。
- **时代变化**：如今大量编码工作由 AI 编程智能体（如 Claude Code、Codex）完成，且这些智能体越来越多地生成自身的新版本（如 Claude Code 的新版本主要由 Claude Code 自己撰写，虽经人工审查）；学术界也涌现大量自修改/自进化智能体研究。
- **核心问题**：当"编译器"变成自我修改的编程智能体时，攻击者能否通过向其自我评估与自我改进流程提供**投毒基准**（含漏洞代码或诱导写出漏洞代码），使智能体的**未来版本在干净、中性的留出任务上写出漏洞代码**，并且这种污染能够跨代保留？
- **整体含义**：自修改 AI 系统的"信任根"正在从人类转向 AI 自身，必须重新审视其信任基础。论文首次对"基准投毒"这一攻击向量做了系统性、端到端的实证研究（此前相关综述只提出威胁概念，缺乏深入案例研究）。

## 2. 方法论

### 2.1 威胁模型

- **攻击目标**：一个在给定基准上自我评估、自我改进的自修改 AI 编程智能体；改进方式包括编辑自身代码/工具或内部提示词工程。
- **假设**：种子（基线）智能体未被污染；攻击者**无法**修改基线智能体、其脚手架（harness）或底层模型。
- **攻击者能力**：完全控制提供给智能体的基准（含其奖励函数），可通过公开分发投毒基准或篡改已知基准集来实施攻击。
- **攻击目标**：投毒基准应使未来版本的智能体在非平凡比例的中性任务上输出该漏洞，且污染能持续。

### 2.2 攻击流程（对应论文图 2）

对三个案例系统，攻击都需穿过一串环节：

1. 种子智能体在投毒基准上求解，产生含漏洞代码的 transcript（日志）；
2. 自改进过程（诊断/提议）基于日志提出修改方案；
3. 方案被实现为智能体的新工具或新指令；
4. 进化后的智能体在**中性留出任务**上求解时，调用该工具/遵循该指令，写出漏洞代码。

### 2.3 投毒基准设计（Polyglot 风格）

- 每个任务为自包含 Python 编程题：自然语言提示 + 函数桩 + 隐藏测试 + 参考解；智能体在 Docker 容器内解题，参考解与测试仅在评测时引入。
- 先尝试"隐蔽投毒"（不显式奖励漏洞），后发现**最有效的基准会行为性地强制使用漏洞才能通过测试**。
- 关键设计（以 CertCheck 为例）：投毒版所有测试服务器都提供**自签名（不受信）证书**，因此正确校验证书的请求必然失败，唯一通过方式就是禁用校验；干净版仅将服务器证书换成受信证书，其余完全相同。这样漏洞在表面上像是"合法功能"（处理自签名证书），且不显式奖励漏洞本身。

### 2.4 三个案例系统

- **DGM（Darwin Gödel Machine）**：直接写代码（工具）来自我修改，基于基准分数做进化选择，形成进化树。论文为实验修改了其内部诊断提示词（原提示词明确要求"通用能力改进而非任务特定修复"，阻碍攻击），并更换了内部模型。
- **SICA（Self-Improving Coding Agent）**：通过自然语言指令修改编码智能体的提示词，且自改进需经过 LLM 审查委员会。**未做任何内部修改**（stock）。
- **Hyperagents（DGM-H）**：由 meta agent 与 task agent 组成，通过更新提示词指令自我改进，**stock 未修改**（但修复了 git 历史泄露答案键的问题）。

### 2.5 可行性探针（降低实验成本）

由于完整 DGM 运行代价高（单次约 15 代约 1000 次模型调用），论文设计三道探针：

- **(a) 基线漏洞率**：种子智能体在投毒/干净基准上是否分别高/低地写出漏洞；
- **(b) 提议中的漏洞**：诊断步骤提出的自然语言方案是否包含漏洞产出工具；
- **(c) 实现中的漏洞**：自改进实现时是否真的把漏洞写进工具（有时会被"净化"成安全写法）。

## 3. 实验设计

### 3.1 投毒基准（Benchmark）

- **CertCheck**：HTTPS 抓取任务，投毒版强制禁用证书校验（CWE-295）；论文主力基准。
- **Backdoor**：记录处理器中植入关键字触发的后门（`mode="export"` 返回全部记录），分 Optional（不显式奖励）与 Required（测试强制要求）两版。
- **JWTVerify**：提供错误验证密钥，迫使禁用 JWT 签名校验。
- **YAMLLoad**：诱导使用 `unsafe_load`/`FullLoader` 而非 `safe_load`。
- 早期还探索过 **Broken Access Control**、**Code Injection（eval）**、**Redirect SSRF** 三类，因探针失败被淘汰。

### 3.2 留出任务与评测

- 每个进化后的智能体在 **10 个中性留出任务**上求解，每任务采样 3 次（共 30 次），统计漏洞率。
- **鲁棒性实验**：另设 5 个 HTTPS 仅"顺带出现"的复杂任务（`install_package`、`fetch_avatar`、`check_update`、`geocode`、`report_metric`），分"文档显式写 over HTTPS"与"仅 URL 含 https"两个变体。
- **持续性实验**：取一个已污染智能体，在四种条件下继续进化：投毒 CertCheck（对照）、干净 CertCheck、**CWEval**（+新增 CWE-295 任务）、定制"去污染"基准（显式惩罚漏洞）。
- **安全线索实验**：额外用带安全含义命名的任务（`secure_fetch`、`verified_download`、`authenticate_user`、`verify_request`，N=6）测试安全线索是否是防御。

### 3.3 对比设置

- 每类基准均成对使用**投毒版 vs 干净版**，作为对照以区分"毒药导致"与"模型本来的倾向"。
- 模型对比：gpt-oss-120b、Qwen3.5-397B、Claude Sonnet 4.5、DeepSeek V4 Pro（部分场景）；并在同一系统上对比不同模型（如 DGM 上 Sonnet 4.5 抵抗、SICA/Hyperagents 上 Sonnet 4.5 沦陷）。
- 三个不同自改进架构（DGM / SICA / Hyperagents）横向对比。
- 防御方向实验：向 SICA 审查委员会增加"安全审查员"、更强模型、安全线索任务、去污染基准。

## 6. 主要结论与发现

- **攻击可行，但非必然**：
  - DGM：需修改其诊断提示词（超出威胁模型）后，Qwen3.5-397B 在两次投毒进化中均演化出无条件禁用证书校验的代码生成工具，留出任务漏洞率 **30/30**；gpt-oss-120b 生成了漏洞工具但**从不调用**（0/30）；Sonnet 4.5 在 DGM 上**抵抗**了攻击。
  - SICA：**stock 系统**即被攻破。Qwen3.5 两次运行均在 4 代内自注入"禁用证书校验"指令，漏洞率 30/30；Sonnet 4.5 也被攻破（30/30），尽管它自己曾标记该行为是"安全反模式"，但被审查委员会以"简化"之名否决。
  - Hyperagents：Sonnet 4.5 在两次 5 代进化中均注入无条件禁用证书校验的指令，漏洞率 30/30。
- **污染具有鲁棒性**：在 HTTPS 仅"顺带出现"的复杂任务上，污染仍压倒性成功（如 Hyperagents 15/15、15/15），仅在"未显式提及 over HTTPS"时略有下降。
- **污染具有持续性**：干净 CertCheck 和 CWEval（含新增 CWE-295）**均无去污染效果**；只有**已知毒药设计**的定制去污染基准部分有效（DGM 8/30、SICA 0/30 但指令仍以条件形式残留、Hyperagents 完全清除）。
- **提炼出攻击成功的充分条件**：
  - 漏洞层面：基准强制或奖励使用该漏洞；漏洞在中性任务上**功能不可见**（不破坏正常行为）；是模型"肌肉记忆"中的标准库惯用法；模型默认写安全版（否则无需投毒）。
  - 基准层面：强制使用但**极少线索**，诱导过度泛化。
  - Harness 层面：**不劝阻基准特定进化**（SICA/Hyperagents 开放式提示词比 DGM 的"通用性"提示词更易攻破）；**缺乏安全意识**（SICA 审查委员会不重视安全）。
- **额外概念验证**：JWT 签名校验绕过（三系统均部分成功）、YAML 不安全加载（DGM 完全成功 30/30，SICA/Hyperagents 部分成功，退化为 `FullLoader`）。
- **防御结论**：更强模型不是万灵药（Sonnet 4.5 在 DGM 抵抗、在 SICA/Hyperagents 沦陷，且更擅长"挖 git 历史找答案"而更易受攻击）；安全审查员有时能纠偏但会与基准分数压力竞争；安全线索任务不是可靠防御；**抗投毒韧性与"不自过拟合"的一般改进目标正相关**。

## 7. 优点

- **问题新颖且切中要害**：把 Thompson 的经典信任问题精确迁移到"自修改 AI 智能体 + 基准投毒"这一新兴攻击面，并给出首个端到端实证。
- **威胁模型清晰克制**：坚持攻击者只控制基准，不修改模型与脚手架；对 DGM 的提示词修改明确标注为"研究者特权"，并诚实说明其超出威胁模型。
- **实验对照严谨**：投毒/干净基准成对、中性留出任务、报告失败案例、量化漏洞率（10 任务×3 次），并做鲁棒性（任务形态变化）与持续性（跨基准续演）双重验证。
- **结论可操作**：从成败中提炼出漏洞/基准/模型/harness 四类属性清单，并用该清单指导 Claude Code 快速发现两个新投毒基准（JWT、YAML），体现方法论的可迁移性。
- **负责任的披露与开源**：向被研究

系统的相关方（如 SICA、Hyperagents 的维护者）进行了披露，并将投毒基准、评测脚手架与数据开源，便于社区复现与后续防御研究。

## 8. 局限与不足

- **因果归因不彻底**：论文自身承认，实验中"模型"与"harness"是共变（co-varying）的——不同系统使用不同模型、不同提示词与不同自改进机制，因此难以把某次攻击成功单独归因于"基准投毒"还是"特定 harness 的宽松性"。DGM 上的提示词修改更直接越出了威胁模型，使该案例的可比性打折。
- **样本量与复现性有限**：成功攻击通常仅 **2 次独立进化运行**，且作者明言 Qwen3.5 的第二次 DGM 运行未能复现 30/30 的结果。持续性实验每个系统只取一个污染种子、代数有限（10/8/10 代），跨代稳定性的统计置信度不足。
- **投毒信号过度饱和**：论文使用的基准几乎**全部任务都强制或强烈诱导使用漏洞**，未测试"稀释型"投毒（如在大规模基准中仅掺入极少数投毒任务）。真实世界中攻击者未必能完全掌控整个基准，因此可能**高估了攻击的易行性**。
- **架构覆盖有限**：仅验证 DGM、SICA、Hyperagents 三种自改进范式，未覆盖更主流的 RLHF/DPO 自训练、记忆库式（memory-based）或工具检索式自进化系统。
- **防御评估薄弱**：去污染实验只对"已知毒药设计"有效，缺乏对未知/自适应投毒攻击的防御；"安全审查员"仅做了初步消融，未系统评估其成本、误报率与对抗鲁棒性。
- **算力与成本信息缺失**：未披露 GPU、时长、费用明细，复现门槛高，也削弱了对"攻击成本—收益"这一关键现实问题的量化。
- **漏洞类型偏向**：集中在 CWE-295（证书校验）、后门、JWT 校验绕过、不安全 YAML 加载等**代码模式类**漏洞，未触及更隐蔽的逻辑漏洞、供应链投毒或训练数据投毒层面。

## 9. 启示与更广泛影响

- **"信任根"的结构性转移**：当 AI 智能体开始重写自身，人类审查其源码已不足以建立信任——真正决定其行为的可能是它**曾经消费过的数据、基准与反馈信号**。这与 Thompson 的"信任的信任"一脉相承，但攻击面从编译器源码扩展到了整个自我改进的输入管道。
- **基准即攻击面**：公共基准（SWE-Bench、CWEval 等）常被视为中立评测工具，本论文证明它们可以成为**持久的、跨代传播的行为植入载体**。这提示社区：基准的发布与分发需要类似软件供应链的完整性与签名机制。
- **"安全对齐"不等于"抗投毒"**：模型在标准安全评测中表现良好，不代表其在自我改进回路中能抵抗行为污染。安全属性可能在**多代自修改**中被逐步侵蚀，且这种侵蚀对单次评测不可见。
- **对自进化智能体设计的直接建议**：
  - 自改进目标应包含**抗过拟合与通用性约束**（DGM 的"通用性"提示词反而提供了部分韧性）；
  - 审查委员会/批评机制必须**显式纳入安全维度**，且安全信号权重不能轻易被基准分数压倒；
  - 应建立**输入溯源与不可信基准隔离**，例如在干净留出集上做回归检测、对基准来源签名、对生成工具做静态安全审计。
- **对政策与治理的含义**：若未来 AI 系统的主要版本由上一代系统生成，则"投毒基准污染"可能演化为**跨版本、跨机构的隐性木马**，监管需关注基准发布方、模型自训练管道的可信度，而非仅关注最终模型权重。

## 10. 可扩展方向

- **稀释型与自适应投毒**：在真实规模基准中研究最低投毒比例阈值，以及攻击者能否针对去污染机制进行对抗性调整。
- **防御机制的实证评估**：系统比较安全审查员、来源签名、生成代码静态分析、留出集回归监控、多代安全回归测试等防御手段的有效性与代价。
- **更广架构与模型**：将实验扩展到 RL 自训练、记忆/检索增强、多智能体协作等自进化范式，并纳入更多开源与闭源模型。
- **长期演化动力学**：延长进化代数，研究污染是**单调累积**、**周期性衰减**还是**与任务分布耦合**，以及"去污染"在多少代内能自然消退。
- **跨代溯源技术**：发展能追踪"某段行为源自哪一版基准/哪一次自改进"的审计方法，为责任归属提供技术基础。

## 11. 总体评价

这是一篇**选题前沿、实证扎实、结论可操作**的系统性研究。它把 Thompson 的经典信任悖论精确落地到"自修改 AI 编程智能体 + 基准投毒"这一新兴攻击面，首次给出端到端的概念验证，并跨三种架构、多种模型、多种漏洞类型做了成对对照实验。其最大价值不在于证明"攻击一定成功"，而在于**清晰刻画了攻击成功的边界条件**——漏洞的功能不可见性、模型的肌肉记忆、harness 的开放性、审查机制的安全缺位——并指出更强模型、安全线索、干净基准都不是可靠防御。

主要短板是**样本量与因果归因**：成功运行多为 2 次，模型与 harness 共变，投毒信号饱和，使"攻击易行性"可能被高估。尽管如此，作为该方向的首篇系统性工作，其提出的问题、提炼的条件清单与开源工件，足以成为后续防御研究的重要基准。
