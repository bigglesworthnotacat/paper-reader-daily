## 摘要
智能体系统需要在多个协作智能体之间安全、高效地委派权限。现有方法可分为两类。一类方法将用户身份直接传播到智能体，导致问责性模糊，并造成持续性的过度权限风险，而 AI 智能体的非确定性行为会放大这一风险。另一类方法依赖与中心化身份与访问管理（IAM）提供方的持续同步，从而引入额外延迟和通信开销。我们提出 CAPMAS，一种用于多智能体系统中安全端到端查询执行的新型架构。CAPMAS 创新性地将基于对比学习的语义作用域流水线与富有表达力的基于 Macaroon 的令牌相结合：前者在执行前将自然语言查询映射为有界权限集，后者支持跨智能体的离线、可防篡改且权限单调递减的委派。通过将身份验证和委派执行与智能体推理解耦，CAPMAS 在强制执行严格的最小权限保证的同时，支持实用的智能体执行。通过消除与 IAM 的同步委派交换，与 OAuth 2.0 Token Exchange（RFC 8693）相比，CAPMAS 的委派操作快 30 倍，委派相关延迟减半，带宽使用量最多降至三分之一。其语义作用域流水线在包含超过 3,100 个端点的企业级 API 模式上，能在 17 毫秒内实现超过 90% 的完美权限包检索，同时与将所有用户权限传播给智能体的系统相比，将不必要权限减少 99.5%。

## Abstract
Agentic systems require secure and efficient delegation of privileges across multiple collaborating agents. Existing approaches fall into two categories. Some propagate user identities directly to agents, obscuring accountability and creating persistent over-privilege risks that are amplified by the non-deterministic behaviour of AI agents. Others rely on continuous synchronization with a central Identity and Access Management (IAM) provider, introducing additional latency and communication overhead.   We present CAPMAS, a novel architecture for secure end-to-end query execution in multi-agent systems. CAPMAS newly combines a contrastive learning-based semantic scoping pipeline that maps natural-language queries to bounded privilege sets before execution with expressive Macaroon-based tokens that enable offline, tamper-evident delegation with monotonic privilege reduction across agents. By decoupling authentication and delegation enforcement from agent reasoning, CAPMAS enables practical agentic execution while enforcing strict least-privilege guarantees.   By eliminating synchronous delegation exchanges with the IAM, CAPMAS yields 30 times faster delegation operations, 2 times less delegation-oriented latency and up to 3 times lower bandwidth usage than the OAuth 2.0 Token Exchange (RFC 8693). Its semantic scoping pipeline achieves over 90% perfect privilege-bundle retrieval within 17 milliseconds on enterprise-scale API schemas containing over 3,100 endpoints, while reducing unnecessary privileges by 99.5% when compared to systems that propagate all the user's privileges to agents.

## 一、核心问题与整体含义

- **研究背景**：基于大语言模型（LLM）的 AI 智能体被广泛部署以代表用户跨个人与企业服务执行任务，多智能体系统已成为复杂 AI 应用的标准架构——智能体之间像人类用户一样相互查询，将大目标分解为可消化的子任务，提升指令遵循能力、降低上下文复杂度并增强可扩展性。

- **核心问题**：多智能体协作中权限委派面临两难。
  - **身份直接传播**：现有 JWT 等身份令牌将用户全局身份与全部授权范围绑定，直接传递给每个智能体会掩盖问责性，并造成持续性过度授权；LLM 的非确定性（幻觉、设计缺陷）会放大这一风险，任何局部幻觉都可能暴露整个服务生态。
  - **中心 IAM 同步瓶颈**：OAuth 2.0 Token Exchange（RFC 8693）虽支持委派，但每一步委派都需向中心 IAM 发起网络请求重新铸造令牌，随着委派深度与智能体数量增长，IAM 成为运营瓶颈，并带来延迟与带宽开销。
  - **协议与智能体工作流不匹配**：传统协议假设确定性软件组件请求结构化 API 范围，而智能体工作流由非结构化、不可预测的自然语言（NL）发起，由非确定性 LLM 执行，需要严格边界来约束幻觉。

- **整体含义**：CAPMAS 旨在将自然语言意图转化为严格有界的最小权限集，并支持跨任意数量协作智能体的离线、防篡改、权限单调递减的能力型委派，在消除中心化瓶颈的同时强制执行严格的最小权限保证，为安全的大规模多智能体生态提供架构基础。

## 二、方法论

### 2.1 核心思想

- **解耦认证/委派执行与智能体推理**：将安全强制执行从智能体 LLM 中剥离，使授权逻辑独立于非确定性的推理过程。
- **能力型令牌 + 语义范围界定**：以 Macaroon 能力令牌实现离线本地衰减，以对比学习语义检索管道解决"哪些权限才是查询真正需要的"这一最小权限推导问题。
- **默认拒绝、权限取交集**：采用严格许可式（default-deny）授权语言，最终授权范围是所有累积 `permit` caveat 的严格交集，任何失败都导致拒绝而非权限升级。

### 2.2 关键技术细节

**（1）Macaroon 令牌实例化**

- Macaroon 由明文 payload（caveat 列表）与基于 HMAC 的链式签名组成；任何一方可本地追加新 caveat 并推导出有效签名，但无法篡改或删除已有 caveat。
- HMAC 链式构造（root_secret 仅由 IAM 持有）：
  - `sig₀ = HMAC(root_secret, "rid=123")`
  - `sig₁ = HMAC(sig₀, "domain=Projects")`
  - `sig₂ = HMAC(sig₁, "op=read")`
- 三类操作：`CreateMacaroon(secret, rid)`、`M.AddCaveat(caveat)`、`M.Verify(secret)`。

**（2）两类 Caveat 设计**

- **确定性可验证 caveat**（刚性安全强制）：
  - `rid`（请求标识）、`iss`（签发者）、`exp`（过期时间）、`aud`（预期接收者）、`agent_id`（记录委派链中每个智能体身份）、`permit`（声明保留给下游的权限子集）。
  - 采用严格许可式语言：智能体不能删除先前限制，必须显式重新声明要委派的权限；IAM 在验证时计算所有 `permit` caveat 的严格交集。
  - 与 JWT 映射关系：`iss`/`exp`/`aud` 对应 JWT claims，`rid`/`permit` 对应 `jti`/`scope`；`agent_id` 与 `query` 为新颖增补。
- **推理与可追溯性 caveat**：
  - `query` caveat 不可变地绑定根用户意图与中间智能体推理，提供两项安全属性：为缺乏精确 API 端点的任务保留语义粒度；支持 IAM 的语义异常检查（如智能体试图用宽泛读权限获取 CEO 薪资时检测语义不匹配并阻断）。
- **可选扩展 caveat**：`ttl`（每跳递减，限制最大委派深度）、`nr_requests`（限制同一 rid 的执行次数，缓解重放攻击）。

**（3）Macaroon 传播与状态隔离**

- 每次委派创建令牌的本地副本，确保针对子智能体的衰减隔离于特定执行分支，不改变父智能体保留的令牌或其他分支。
- 示例：Orchestrator 用根令牌 M 分别克隆出 M′（Projects 分支）与 M*（HR 分支），互不干扰。

**（4）完整请求流程（三步验证协议）**

- Step 1：用户 `login(credentials, query)` 认证并提交查询。
- Step 2：IAM 运行语义范围界定 `getReqScopes(user, query)`，生成 secret 与 rid，创建根 Macaroon M，追加 `exp`、`permit`、`aud`、用户 id 与 query 等 caveat。
- Step 3–8：令牌经用户传至协调智能体，各智能体在 agentic loop 中决定子任务，克隆令牌并追加 `permit`、`aud`、`agent_id`、`query` caveat 后委派或调用服务。
- Step 9–10：服务调用前咨询 IAM 执行三步验证：
  - **10.1 密码学验证**：识别 rid、取回根 secret、重算 HMAC 链，比对签名确保令牌与 caveat 未被篡改。
  - **10.2 确定性 caveat 验证**：检查所有智能体是否追加了强制 caveat、`exp` 是否过期、`aud` 与 `agent_id` 是否构成连贯委派链，最关键的是检查服务动作是否位于所有 `permit` 子句的交集内，且对所有列出的 agent_id（含用户）均获许可。
  - **10.3 语义检查**：基于 LLM 的异常检测，评估原始用户意图与最终服务动作是否语义一致，作为对抗提示注入与逻辑漂移的启发式防御。
- Step 11–21：验证通过后服务执行，结果沿原路径返回；协调智能体使用未衰减的根令牌 M 发起第二个并行子任务。

**（5）语义令牌范围界定管道**

- 将初始令牌范围界定形式化为语义检索任务，返回至多 k 个权限。
- 使用对比学习训练文本编码器，将 NL 查询与权限（服务域、函数或 API 端点 + 描述文本）嵌入共享语义空间；离线预计算权限描述嵌入，运行时嵌入查询并做最近邻相似度搜索。
- 检索到的 top-k 权限翻译为 caveat（如 `permit:P,HR`）嵌入根 Macaroon。
- **Siamese 架构**：查询与 API 描述共享同一编码器（而非双塔），因二者 NL 分布相似，可共享表示空间并减半参数量。
- **训练损失**：标准 InfoNCE 损失，批内负样本防止表示坍缩并提升权限区分度。
- **静态 top-k 截断 + 肘部下降启发式**：用静态 top-k 保证固定最大权限数；当排序相邻权限的余弦相似度下降超过阈值 α（α=0.2）时提前终止检索，降低简单任务的过度授权。
- 评估采用两种数据划分：**Closed Room**（训练时可见全部 API 描述，模拟企业静态 schema，需泛化到未见查询）与 **Strict Zero-Shot**（训练/测试工具完全不重叠，衡量真正泛化）。

**（6）安全属性**

- **动态最小权限范围界定**：攻击面被限制在至多 k 个权限，即使用户恶意提示注入也无额外收益；为整个工作流建立权限上界。
- **权限交集**：每个追加 caveat 经链式 HMAC 计算，智能体只能追加限制、不能删除或削弱约束；委派权限严格单调收窄。
- **防篡改、可追溯与撤销**：任何对 caveat 顺序、权限范围或路由路径的修改都会破坏 HMAC 链；IAM 可关联最终服务调用与累积历史，检测提示注入、逻辑漂移或幻觉任务扩展；因最终执行必经 IAM 验证，可通过使 rid 失效实现即时撤销。

**（7）恶意智能体扩展**

- **身份操纵**：冒充（插入更高权限智能体标识）或静默转发（中继发给其他 aud 的令牌并留在通信路径上观察）。缓解：将 caveat 注入从应用层移至基础设施层（如服务网格 sidecar 代理）；开放环境用 Biscuits 或 PKI 支持的签名意图链（"Signed Nested"），但引入更高延迟。
- **查询路由篡改**：共谋智能体可临时修改明文历史影响中间智能体推理，再在 IAM 验证前恢复原状。缓解：要求每个智能体追加其观察到的令牌状态哈希。

## 三、实验设计

### 3.1 数据集

- **ASTRA**（El Helou 等，2025）：将合成用户任务映射到来自 TOUCAN 的 MCP 服务器端点，清洗重格式化后含 7,722 个用户任务与 1,217 个唯一端点。
- **XLAM**（Liu 等，2024）：评估自主智能体工具调用能力，过滤掉需要超过 3 个端点的查询后，含 60,000 个任务与 3,176 个唯一端点。

### 3.2 实验场景（共 3 组主实验）

1. **端到端原型演示**：实现图 2 的多智能体工作流，10 次执行测量端到端时延。
2. **密码学令牌衰减微基准**：在本地 Apple M3 上测量创建令牌、追加 caveat、验证的延迟与令牌大小（N=1/5/10/100）。
3. **语义范围界定评估**：评估对比检索器在 ASTRA 与 XLAM 上的权限检索效果。

### 3.3 Benchmark 与对比方法

- **对比基线**：
  - **RFC 8693**（OAuth 2.0 Token Exchange）：每跳向 IAM 请求重新铸造令牌。
  - **Signed Nested**：基于 Ed25519 非对称签名的嵌套签名委派链。
  - **Basic Agent**：GPT-oss-120B 驱动的 LLM 智能体，两阶段（先识别相关域，再输出精确所需权限）直接推断所需 caveat。
  - **编码器变体**：Bi-Encoder（双塔）vs Shared Encoder（Siamese）；预训练未微调模型 vs 对比学习微调模型。
- **评估指标**：
  1. Perfect Bundle Capture（完美权限包捕获率 / 成功率）
  2. Complete Miss Rate（完全遗漏率）
  3. Relative Over-privilege（相对过度授权）
  4. Absolute Over-privilege（绝对过度授权）
- **数据划分**：Closed Room 与 Strict Zero-Shot 两种模式。

### 3.4 关键实验设置

- k 阈值扫描：k = 3, 5, 10, 20, 40, 60（ASTRA，α = 0.2）。
- 肘部下降阈值 α = 0.2。
- 委派深度扩展性：N = 1 到 25 的非分支委派链，固定 20 ms 网络跳延迟。
