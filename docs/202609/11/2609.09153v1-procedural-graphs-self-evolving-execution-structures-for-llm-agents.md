## 摘要
大语言模型正日益被部署为能够在长时间跨度上进行规划并通过外部工具采取行动的智能体。大多数智能体通过在不断累积的历史上进行无约束生成来选择动作，这使得关于做什么、以何种顺序做以及在何种条件下做的程序性知识保持隐含。随着轨迹变长，智能体可能会偏离目标、以错误顺序调用工具，并重复无效动作。我们提出过程图：正如知识图谱将事实性知识组织为用于回答“是什么”问题的（实体，关系，实体）三元组，过程图将程序性知识组织为用于回答“该做什么”问题的（过程，关系，过程）三元组。在每个决策步骤，该框架定位智能体的活跃节点，并由一个引导模型将周围子图转化为步骤级情境引导，以偏置求解器的下一步动作而不对其加以规定。该图是自演化的：一个LLM精炼器将失败轨迹与成功轨迹进行对比，并编辑图的拓扑与属性；它提交那些能够保持或提升留出验证性能的编辑，同时保留被拒绝的编辑以抑制重复。从最小骨架开始，该循环构建出的图能够匹配或超越人工设计的图。它还能修复有缺陷的专家先验。在多个数据集、任务类型和LLM上，过程图相较于基于记忆的基线带来了一致的增益，而自演化无需人工工程即可进一步提升性能。

## Abstract
Large language models are increasingly deployed as agents that plan over long horizons and act through external tools. Most agents select actions through unconstrained generation over an accumulating history, leaving implicit the procedural knowledge of what to do, in what order, and under which conditions. As trajectories lengthen, agents can lose track of their objectives, invoke tools out of order, and repeat unproductive actions. We introduce the Procedural Graph: just as a knowledge graph organizes factual knowledge into (entity, relation, entity) triplets for what-is questions, a Procedural Graph organizes procedural knowledge into (procedure, relation, procedure) triplets for what-to-do questions. At each decision step, the framework localizes the agent's active node, and a guidance model translates the surrounding subgraph into step-level situational guidance that biases the solver's next action without dictating it. The graph is self-evolving: an LLM refiner contrasts failed trajectories with successful ones and edits the graph's topology and attributes, committing edits that preserve or improve held-out validation performance while retaining rejected ones to discourage repetition. Starting from a minimal skeleton, the loop builds graphs that match or surpass hand-designed ones. It can also repair a flawed expert prior. Across multiple datasets, task types, and LLMs, the Procedural Graph delivers consistent gains over memory-based baselines, and self-evolution further improves performance without manual engineering.

  - 丢失目标（drift）；
  - 工具调用乱序（planning hallucination）；

- **整体含义**：论文主张智能体需要一种**既可编辑、又结构化到能规避无效行为、又足够灵活保留推理自由、还能随执行进度动态响应并从经验改进**的程序性知识表示。

## 2. 方法论

### 2.1 核心思想：从知识图谱到"过程图"

- 类比知识图谱用 (entity, relation, entity) 三元组回答"是什么"问题，**过程图（PG）** 用 **(procedure, relation, procedure)** 三元组回答"该做什么"问题。
- 形式化：有向带属性图 `G = (V, R, E, Φ)`，`E ⊆ V × R × V`；边 `e = (u, r, v)` 表示在关系 `r` 下节点 `v` 是节点 `u` 之后可采纳的步骤。
- 节点抽象工具函数、技能、内部推理步骤或任务状态；边属性映射 `Φ` 携带三个文本字段：`condition`（何时适用）、`guidance`（如何执行）、`pitfalls`（需避免什么）。
- 关系词表 `R` 含四类：`LEADS_TO`、`TRIGGERS`、`PROVIDES_INPUT_FOR`、`CONVERGES_TO`。

### 2.2 在线推理：生成式过程图引导（三步：locate → extract → generate）

- **定位**：用最近一次动作（如工具调用）与节点做精确匹配得到活跃节点 `u_t = Match(a_{t-1}, V)`。
- **抽取**：取 `u_t` 的 h 跳有向邻域 `G_t = N_h(u_t)`；匹配失败时回退到整图 `G`。
- **生成**：引导模型 Ψ 结合局部子图、用户查询 `q` 与最近 w 步轨迹窗口 `T_{t-w:t}`，把静态边属性翻译为步骤级情境引导：
  `g_t = Ψ(G_t, q, T_{t-w:t})`
- **软整合**：引导以提示形式附加，求解器仍自由决策：`a_t ~ P_solver(· | q, T_t, g_t)`，即"偏置而非强制"。
- 实现默认 `h=2`、`w=3`。

### 2.3 离线自演化：四步闭环（Algorithm 1）

1. **诊断式 Rollout**：用保留图 `G_{k-1}` 在训练批次 `B_k` 上运行，记录轨迹与评分 `E_k`，对比高分与低分轨迹。
2. **反馈驱动变异**：LLM 精炼器识别失败轨迹中的重复错误循环与成功轨迹中的多步捷径，输出结构化编辑集 `ΔG_k`：
   - 拓扑操作：`Add`（补缺失验证节点/边）、`Delete`（删致错节点/边）；
   - 属性修订复用同一接口：先删后以更新属性重加；
   - 候选图 `G_cand_k = G_{k-1} ⊕ ΔG_k`（含环修复）。
3. **验证门控**：结构校验通过后，在独立验证集 `D_val` 上评估，满足下式才提交（并列也算通过）：
   - `G_k = G_cand_k` 若 `S_val(G_cand_k) ≥ S_val(G_{k-1})`；否则 `G_{k-1}`。
4. **拒绝记忆**：被拒候选图、编辑、训练轨迹与验证结果写入 `H_rejected`，作为下一轮负证据：`ΔG_{k+1} ~ P_refiner(· | G_k, C_{k+1}, H_rejected)`，抑制重复无效编辑。
- 轨迹上下文超出 `L_max` 时丢弃开头、保留结尾（保留轨迹终局而非前缀）。
- 结构校验要求：边端点合法、每个节点存在指向终止节点的有向路径、符合环策略。

## 7. 局限性

论文自身承认与实验暴露的局限包括：

1. **依赖闭源强模型**：求解器、引导模型、精炼器三位一体，全部通过商用 API 调用，未验证在开源或小规模模型上是否成立；弱模型的图编辑质量可能显著下降，导致自演化退化为噪声注入。
2. **无迁移性验证**：未测试跨求解器、跨工具接口、跨任务域的图复用。当前流程为每个基准独立演化一张图，若换求解器需重新演化，成本与通用性存疑。
3. **图规模偏小**：除 BFCL v3（131 节点 / 265 三元组）外，多数基准图仅 7–17 节点、7–27 三元组。这种规模下"结构化"的收益容易被质疑为等同于少量提示词，尚不清楚图在数百节点量级时是否仍能保持定位与抽取的准确性。
4. **统计效力不足**：EnterpriseArena 每 split 仅 20 个 episode，论文自承单次接受/拒绝由一两个 episode 决定，应读作搜索轨迹而非显著性检验；HotpotQA 上部分模型的增益区间跨越零点。
5. **验证门控的保守性**：`S_val(G_cand) ≥ S_val(G_{k-1})` 的接受准则在验证集噪声较大时可能过早停止演化，或依赖并列判据勉强通过，缺乏对验证方差的自适应处理。
6. **算力与成本未量化**：论文未报告 GPU、训练时长或 API 费用，虽然自演化不更新权重，但迭代式 rollout + 精炼的调用成本对实际部署仍是关键约束，缺少成本–收益曲线。
7. **失败模式分析不足**：附录给出若干案例，但未系统统计"图编辑引入的错误""定位匹配失败回退整图的频率""环修复对性能的影响"等，诊断粒度可再细化。

## 8. 方法亮点与启示

- **概念迁移干净**：把知识图谱的 (entity, relation, entity) 类比到 (procedure, relation, procedure)，用同一套图操作（增删边、改属性）统一了"加新步骤"与"修正旧步骤"，接口极简且可解释。
- **软整合设计克制**：引导以提示形式附加、求解器仍自由采样，既保留了 LLM 的推理灵活性，又通过结构化先验压制了漂移与循环，避免了硬状态机常见的脆弱性。
- **拒绝记忆机制**：把被验证门控拒绝的候选图与编辑写入 `H_rejected`，作为下一轮的负证据，是自演化系统中防止"重复无效编辑"的实用设计，可迁移到其他 LLM 自改进框架。
- **验证门控 + 返回图报告**：以独立验证集决定是否提交，并明确拒绝报告搜索过程中的最佳单轮测试成绩，改为报告返回图，体现了对"在测试集上选型"这一常见陷阱的自觉规避。
- **长程场景的机制解释**：EnterpriseArena 上"提前募资"的发现表明，过程图的真正价值在于编码**时间延迟与前置条件**这类难以从单步奖励中学到的程序性知识，为长程智能体设计提供了可复用的洞见。

## 9. 总体评价

这是一篇**问题定义清晰、方法简洁、实验覆盖面广且公平性处理规范**的工作。它把"程序性知识如何表示与自演化"这一模糊命题，落成了可操作的三元组图 + 定位/抽取/生成三步推理 + 诊断/变异/门控/拒绝记忆四步演化，并在 7 个基准、4 个 LLM 上取得了方向一致的优势，尤其在 BFCL v3、GDPval、τ-bench 与 EnterpriseArena 等强调顺序、条件与长程韧性的场景中增益明显。

其主要短板在于**验证深度的不均衡**：基准图规模小、长程场景样本少、无开源模型与跨域迁移验证，使得"结构化"相对"精心设计的提示"的边际价值尚需更强证据支撑；同时成本与失败模式的量化缺位，削弱了工程可用性的说服力。

尽管如此，论文的**核心命题——智能体需要一种可编辑、结构化、动态响应且能从经验中改进的程序性知识表示——已被实验较好地支撑**，局部子图 + 生成式引导优于全图注入、从零演化可修复坏先验、拒绝记忆可抑制无效编辑等发现，对后续长程智能体与自演化记忆研究具有明确的参考价值。
