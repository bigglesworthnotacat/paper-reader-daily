## 摘要
我们提出 FrogNano，一个 4B 编程智能体，旨在即使在资源受限的环境中也能高效且有效地解决软件工程（SWE）任务。它完全通过强化学习（RL）在约 1,500 个带有合成任务的 SWE 环境中进行后训练。提升性能的一个关键要素是在线任务合成流水线，它生成与当前检查点可学习性前沿相匹配的任务。本报告提供证据表明，有竞争力的小型编程智能体可以仅用合成任务训练，而无需传统的从更大模型蒸馏，并且生成处于当前智能体可学习性前沿的任务很重要。我们报告了训练方法、跨多种环境的评估以及深入分析的细节，为我们在轻量但有能力、可在极低硬件上运行的编程智能体方面的持续探索奠定基础。

## Abstract
We present FrogNano, a 4B coding agent designed to tackle software engineering (SWE) tasks efficiently and effectively, even under resource-constrained environments. It is post-trained exclusively via RL on around 1,500 SWE environments with synthetic tasks. A key ingredient for improving performance is an online task synthesis pipeline that creates tasks calibrated to the frontier of learnability for the current checkpoint. This report provides evidence that competitive small coding agents can be trained with synthetic tasks alone, without traditional distillation from larger models, and that generating tasks at the learnability frontier of the current agent is important. We report details on the training methodology, evaluations across diverse environments, and in-depth analyses, serving as a foundation for our ongoing exploration of lightweight yet capable coding agents that can run on minimal hardware.

## 2. 方法论

### 2.1 总体框架

- 从 Qwen3.5-4B 初始化策略 π(0)，交替进行**任务生成与校准**阶段和**RL 训练**阶段，共 5 轮迭代，得到 π(1)…π(5) = FrogNano。
- 每次策略在验证集上饱和后，用表现最好的 checkpoint 生成并校准下一轮任务，形成**任务分布与策略共同演化**的闭环。

### 2.2 TaskPilot：策略引导的在线任务合成

- **起点**：从 SWE-rebench 的真实仓库快照出发，由任务生成模型产生「问题陈述 + gold patch + 隐藏的 fail-to-pass（F2P）测试」。
- **可执行性验证**：候选任务需满足 F2P 测试在原快照上失败、应用 gold patch 后通过，且既有 pass-to-pass（P2P）套件保持稳定。gold patch 仅用于任务验证，对求解器完全隐藏；生成的 F2P 测试及其结果在交互期间同样隐藏。
- **策略校准**：对每个可执行候选，用当前 4B Leaf 策略做 N 次 rollout，估计解决率
  - p̂_policy = (1/N) Σ_{j=1..N} R_j，其中 R_j ∈ {0,1} 表示第 j 条轨迹是否通过全部评分测试。
- **可学习区域与目标带**：
  - 广义可学习区域为 0 < p̂ < 1（混合成功/失败，能同时提供正负样本）。
  - 迭代 1–4 使用原生成模型，目标 p̂ = 0.5。
  - 初始第 5 轮沿用同一方案收益变弱，故修订版第 5 轮改用**更强的任务生成模型**并将目标带下移到 0 < p̂ ≤ 0.5。
  - p̂ = 1 视为饱和、p̂ = 0 视为过难；落在目标外的候选会被**改写、重新评估或丢弃**，而非简单过滤固定池。
- **闭环结构**：generate → evaluate（策略 rollout）→ refine → re-evaluate，可重复多轮。
- **任务改写示例（图 5）**：同一仓库快照、gold patch、评分测试保持不变，仅改写问题陈述——
  - 欠规约版（0% 解决率）：区间闭合性、端点包含、宽度含义等契约细节缺失；
  - 期望版（50%）：精确陈述行为契约（闭区间、端点计入覆盖、零宽度区间），但**不泄露实现位置**；
  - 过度规约版（100%）：点名类/方法、给出失败输入与异常，实质等于定位修复点。
  - 结论：校准调整的是**语义清晰度与「定位解法的信息量」**，而不是单纯的 prompt 长短。

### 2.3 Leaf harness

- 暴露 **5 个类型化工具**：`read`、`write`、`edit`、`glob`、`bash`，命名与 schema 参照 Claude Code 工具子集（实现参考 SLIME 的公开 Anthropic adapter）。
- 刻意省略规划模式、权限对话、提醒、用户特定上下文与辅助工具。
- **终止规则简单**：返回含工具调用的响应继续 episode；不含工具调用的响应视为最终答案并终止。结束后收集仓库变更，用任务测试评分。
- **效果**：R2E-Gym harness 下 Qwen3.5-4B 约 96% 轨迹触及轮次上限；换用 Leaf 后 SWE-bench Verified 从 **8.3% → 37.2%**。而更大的 MiniMax-M2.5 对 harness 变更不敏感（两种 harness 均为 66.5%），说明接口兼容性对紧凑模型尤其关键。
- 训练与评测使用**同一 Leaf harness**；训练时模型生成的推理、答案文本与工具调用计入 loss，任务 prompt 与工具输出保留在上下文中但被 mask。

### 2.4 RL 训练配方

- **算法**：DPPO + 异步 rollout（PipelineRL 式）+ 组相对优势：
  - A_ij = (R_ij − R̄_i) / (std(R_i) + 1e-6)，按任务分组标准化；丢弃零优势组（因任务已校准到可学习区，极少被丢弃）。
  - 轨迹级优势广播到该轨迹所有模型生成的 token；工具观测 mask 出 loss。
- **异步策略滞后修正（非对称轨迹重要性采样）**：
  - p_t = π_θ(a_t|s_t)，q_t = π_roll(a_t|s_t)，ρ_t = p_t/q_t，Δp_t = p_t − q_t。
  - 正优势 token 在 Δp_t > 0.2 时丢弃；非正优势 token 在 Δp_t < −0.2 时丢弃，保留集记为 K。
  - 目标函数：L_policy = −(1/|T|) Σ_{t∈K} A_t ρ_t。
- **稳定性来源**：不使用 reference-model KL、无 asymmetric-TIS KL 辅助项、无熵 bonus；依靠 DPPO mask、较小的策略版本滞后与梯度裁剪。
- **效率奖励（成功门控对数长度惩罚）**：
  - R(N) = 1（n ≤ N）；= 1 − α·ln(n/N)（n > N），n 为 assistant 生成 token 数（含推理、自然语言与工具调用 token，不含工具观测）。
  - 只惩罚**已完成且成功**的轨迹，按效率对正确解排序，不额外惩罚失败的探索；零方差过滤仍用原始任务奖励而非惩罚后奖励。
- **截断部分奖励**：因上下文长度、单轮 token、轮数或时间上限而截断但实际解出任务的轨迹给 0.5；所有失败轨迹为 0。禁用常规的线性超长惩罚与超长 loss masking。
- **迭代设置**：每轮 200 次 update，权重跨轮延续，优化器与随机数状态每轮重置。

## 4. 资源与算力

- **训练硬件**：**单节点 8 × NVIDIA B200 GPU**。
  - 2 张 GPU 做策略训练（context parallelism = 2），6 张单 GPU 推理引擎（SGLang）生成轨迹。
  - 最多 256 条并发轨迹，策略滞后（policy lag）为 1 或 3。
- **批次规模**：每次 update 32
