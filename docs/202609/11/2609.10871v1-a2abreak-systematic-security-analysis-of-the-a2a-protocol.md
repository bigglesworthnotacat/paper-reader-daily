## 摘要
Agent2Agent（A2A）协议现由 Linux 基金会管理，是一项开放标准，使自主 AI 智能体能够跨组织边界相互发现、认证并委派任务。A2A 旨在补充用于工具集成的模型上下文协议（MCP），正迅速成为多智能体生态系统的横向通信层。然而，该协议的安全性尚未得到系统性分析。本文提出 A2ABreak，这是对 A2A 协议首个严格的系统性安全分析。我们引入一种新颖框架，利用 LLM 辅助直接从自然语言规范中提取经过验证的有限状态机，从 929 条形式化陈述中生成包含 37 个状态和 76 个转移的统一模型，然后在完全合规假设下对该模型进行系统性推理，通过对抗性验证发现协议级漏洞。我们的分析揭示了 11 个新漏洞，每个都可被符合规范的对手利用，且无需任何实现缺陷。这些发现包括：通过未受保护的上下文标识符进行跨客户端上下文注入；在委派链中通过多跳身份丢失进行凭据窃取；以及通过宣称未经证实的能力声明的恶意智能体进行数据外泄。在独立专家评审下，A2ABreak 达到 73.3% 的精确率和 84.6% 的 F1 值，而基于同一规范的零样本 LLM 基线产生零个已确认发现，这表明显式形式化基础对于可靠的协议安全分析至关重要。

## Abstract
The Agent2Agent (A2A) protocol, now governed by the Linux Foundation, is an open standard that enables autonomous AI agents to discover, authenticate with, and delegate tasks to one another across organizational boundaries. Designed to complement the Model Context Protocol (MCP) for tool integration, A2A is rapidly emerging as the horizontal communication layer of the multi-agent ecosystem. Yet the protocol's security has received no systematic analysis.   This paper presents A2ABreak, the first rigorous systematic security analysis of the A2A protocol. We introduce a novel framework that utilizes an LLM-assisted extraction of a verified finite-state machine directly from the natural-language specification, producing a unified model of 37 states and 76 transitions from 929 formalized statements, and then systematically reasons over this model to discover protocol-level vulnerabilities through adversarial verification, under a full-compliance assumption.   Our analysis uncovers 11 new vulnerabilities, each exploitable by a specification-compliant adversary without requiring any implementation flaw. Among the findings are cross-client context injection through unprotected context identifiers, credential harvesting via multi-hop identity loss in delegation chains, and data exfiltration through rogue agents advertising unattested capability claims.   A2ABreak achieves 73.3% precision and 84.6% F1 against independent expert review, while a zero-shot LLM baseline operating over the same specification produces zero confirmed findings, demonstrating that explicit formal grounding is essential for sound protocol security analysis.

- **背景**：Agent2Agent（A2A）协议由 Google 于 2025 年 4 月提出，2025 年 6 月移交 Linux 基金会治理，是面向自主 AI 智能体跨组织、跨厂商边界的开放标准（基于 HTTP/HTTPS），定义智能体发现、认证、任务委派与结果交换。A2A 与 Anthropic 的 MCP 互补：MCP 管理"智能体—工具/数据源"的**纵向**关系，A2A 管理"智能体—智能体"对等体的**横向**关系，二者共同构成多智能体生态的通信栈。
- **核心风险来源**：
  - **不透明执行（opaque execution）**：客户端无法看到远端智能体的内部推理、工具调用与中间状态，因此无法验证远端智能体对委派任务、累积凭据与返回产物的实际处理。
  - **非强制性安全姿态**：规范中关键安全控制多以 SHOULD / MAY 表述，而非 MUST；发现阶段唯一的智能体身份验证原语（AgentCard 签名）完全可选。
- **研究空白**：现有工作多为描述性综述（与其他互操作协议并列调查）、高层安全架构建议，或仅关注 token 生命周期隐私（Louck 等），**尚无任何工作对 A2A 做规范级的形式化建模与系统性漏洞挖掘**。
- **方法学约束**：A2A 无开源参考实现，因此静态分析、模糊测试、符号执行等实现级手段不可用；只能做"仅规范"分析。而作者实验表明，零样本 LLM 分析（Claude Opus 4.6 + 扩展思考）在两次运行中生成 9 个候选攻击，**全部在对抗性验证中被否决**（攻击轨迹违反了模型未纳入考虑的规范性要求）。
- **论文定位**：提出 A2ABreak，**首个针对 A2A 协议的严格系统性安全分析框架**，在"完全合规假设"下寻找协议设计本身的漏洞（而非实现缺陷）。论文被 ACSAC '26 接收。

## 2. 方法论：核心思想与关键技术细节

### 2.1 总体思想
将自然语言协议规范转化为**经过验证的有限状态机（FSM）**，再在该形式上系统推理漏洞，并用对抗性验证保证每个发现的**可靠性（soundness）**。核心主张：显式形式化基础是可靠协议安全分析的必要条件。

### 2.2 形式化定义
- **规范语料**：规范分节 D = {d₁,…,d_M}，每节解析为陈述序列，去重后得全语料 C（|C| = N）。
- **协议 FSM**：F = (S, s₀, T, Σ, S_f)，其中 S 为状态集、s₀ 为初始状态、S_f 为终态集、Σ 为事件字母表、T ⊆ S × Σ × G × S 为带守卫条件的转移关系；单条转移 τ = (s, σ, g, s′)。
- **协议漏洞**：V = (π, ρ, φ)，即一条可行攻击轨迹 π = ⟨τ₁,…,τ_k⟩、被违反的安全属性 ρ、以及其缺失导致该违反的**缺失原语 φ**。轨迹"可行"意味着每个转移都存在于 T 中，且每个守卫都能被完全合规方满足。

### 2.3 三大挑战与对应方案
- **C1 自然语言规范无法直接语义解释**（同一句话可能同时表达前置条件、规范要求与数据类型约束，缺乏句法区分）→ **S1 双通道语义分离**：独立执行结构提取通道与行为提取通道，各自使用为该类内容优化的抽取模式，最后再对账，避免定义性语义与行为性语义交叉污染。
- **C2 开放式模型生成无法校验正确性**（无参照模型、错误静默向下游传播；人工标注成本极高，如蜂窝协议规范约需 2,800 人时）→ **S2 输入缩减 + 扩展思考**：把无约束的综合问题拆解为一系列**有界、可单独验证**的决策；例如 929 条陈述中仅 283 条（30%）携带转移结构进入 FSM 构建。
- **C3 自动漏洞分析的可靠性（soundness）** → **S3 领域专用约束语言**：在所有提示中嵌入形式化约束，抽取阶段强制使用形如 `s1 --c/a--> s2` 的转移模式（守卫、触发、后置条件以 `&, |, !`、点限定属性等逻辑记号表达），拒绝自由文本；分析阶段定义"何为有效发现"（缺陷必须存在于规范**未说**之处；含糊委派不算有意排除；只有结果要求而无机制即为缺失原语）。

### 2.4 三阶段流水线
**Stage A：规范形式化（A1–A4）**
- A1 **结构抽取**：产出 FSM_STATE（生命周期状态，标注初始/中间/终态）、CONSTRAINT（全局数据不变式）、IMPLICIT_TRANSITION（由定义表与流程图隐含、无 RFC 2119 关键词的状态变化），每条陈述分配稳定 ID 并标注所属协议阶段。
- A2 **行为抽取**：独立扫描，仅针对含 RFC 2119 关键词的句子，编码为 BEHAVIORAL 转移陈述，并保留规范强度（must/shall/should/may）；刻意不重复抽取定义表与枚举，保证两套语料语义不相交。
- A3 **对账**：合并两个通道输出，识别并折叠精确/近似重复项为规范形式，同时保留双方来源 ID 以便溯源；模糊情形由 LLM 解析并**强制人工复核**。
- A4 **规范验证**：逐条对照原始规范文本核验字段，自动检测幻觉状态、错配的规范性关键词、源文本中不存在的守卫条件；失败者修正或删除，产出验证报告并构成进入 Stage B 的**强制人工检查点**。

**Stage B：FSM 构建（B1–B4）**
- B1 **输入过滤**：确定性的、无 LLM 的过滤，按协议阶段分区，仅保留具有足够转移结构的陈述，输出 6 个按阶段的输入包。
- B2 **分阶段 FSM 综合**：为 6 个协议阶段各建一个完整 FSM；去重状态、剔除非会话状态、推断隐含状态；为每个状态标注 `actor` 字段（client / server / shared / unknown），**shared-actor 状态标记信任边界，是 Stage C 的重点目标**；缺口处查询实时规范，无法解决者记入诊断清单形成人工检查点。
- B3 **跨阶段转移解析**：识别连接各阶段 FSM 的跨阶段边（含 Task Execution ↔ Interruption 的双向循环），给出触发事件与守卫条件；只产出跨阶段转移，不修改阶段内图。
- B4 **统一 FSM 装配**：确定性合并 6 个分阶段 FSM 与跨阶段边，随后两轮去重：
  - **D1 确定性去重**：命名归一、跨阶段重复状态合并、删除阶段化建模产生的恒等转移、合并语义等价转移，并做结构校验，启发式标记 meta-state、absence-state、不可达的非协议状态；
  - **D2 语义去重（LLM）**：分诊候选，删除抽象 meta-state 并重分配其行为、折叠平凡直通状态、丢弃协议操作不可达的部署生命周期状态、依据状态的规范溯源为孤立子生命周期补充入边。
  - 输出：**37 个状态、76 条转移**的完全连通 FSM，无孤立状态、引用完整性完好。

**Stage C：安全分析（C1–C2）**
- **完全合规假设**：所有 MUST / SHOULD / MAY 均被各方满足，实现正确、传输层安全已建立；因此任何存活的发现都是协议设计本身的缺陷。
- C1 **漏洞发现**：在统一 FSM 上寻找与已知漏洞相关的结构性质（敏感转移缺少授权守卫、阶段边界缺少检查、可绕过必需前驱到达的状态、事件字母表缺口允许非预期消息序列）。报告前施加两道过滤：攻击轨迹必须完全在 A2A 协议内可执行（不得依赖带外机制）；必须通过网络检索原始规范确认该缺口是**真实的缺失原语**而非有意设计选择。C1 多次独立运行以提升召回，候选合并后进入 C2。
- C2 **对抗性与人工验证**（四步）：① 在统一 FSM 中落地轨迹，无法由合法状态与转移重建者丢弃；② 在完全合规下逐步执行以确认可利用性，并确认无任何现存的任一强度规范规则可阻止该攻击；③ 全面检索规范，确认该原语确实缺失而非定义在别处；④ 由领域专家独立人工复核 FSM 轨迹与规范证据。失败者降级为 inconclusive 或丢弃并记录理由，最终输出 confirmed / discarded / inconclusive 的完整审计链。

## 3. 实验设计

- **数据集 / 基准**：
  - **A2A v1.0 规范**（自然语言 + Protocol Buffers 数据模型 + JSON-RPC 2.0 / gRPC / HTTP+JSON 三种绑定）作为唯一证据基础，抽出 **929 条**经验证的形式化陈述。

  - RQ2 正确性验证（FSM 构建 + 漏洞分析两个层面）；
  - RQ3 各流水线阶段对 FSM 精炼的贡献；
  - RQ4 规范复杂度在各协议阶段的分布；
  - RQ5 执行成本。
- **主要场景**：6 阶段协议生命周期——Discovery、Authentication、Initiation、Task Execution、Interruption、Termination；威胁模型中的对手可为客户端、服务端或**同时扮演两种角色的中间人**（多跳委派链），完全认证且完全合规，其优势完全来自协议未定义之处。

    - FSM 正确性仅在 **TCP 单一代理基准**上评估，TCP 与 A2A 在协议生命周期、状态抽象粒度上差异显著，外部效度受限；
    - 4 个假阳性说明自动发现的精度约为 **11/16 ≈ 69%**（在专家复核口径下），论文未进一步给出每类假阳性的成因分布；
    - 全部实验基于**单一规范版本（v1.0）**与**单一 LLM 家族（Claude 4.6 系列）**，未做跨模型、跨规范版本的敏感性分析；
    - 无消融实验直接量化 S1/S2/S3 三大方案的**各自独立贡献**（RQ3 只追踪了 FSM 精炼的逐阶段计数，而非三方案的对照消融）。

## 6. 主要结论与发现

- **零样本 LLM 分析不可靠**：Claude Opus 4.6 在两次独立运行中生成的 9 个候选攻击**全部在对抗性验证中被否决**，其轨迹均违反了模型自身未纳入考虑的规范性要求。这直接支撑论文核心主张——**仅凭 LLM 无法可靠地对协议规范做安全推理**。
- **形式化流水线可行且有效**：A2ABreak 将 929 条规范陈述压缩为 283 条结构承载陈述，最终装配出 **37 状态 / 76 转移**的统一 FSM，且验证报告无孤立状态、引用完整性完好。
- **A2A 协议存在系统性设计漏洞**：在"完全合规、实现正确、TLS 已建立"的假设下，仍确认 **11 个真阳性漏洞**，说明这些缺陷**根植于协议设计本身**，而非实现缺陷或配置错误——即任何合规实现都无法通过"更小心的编码"规避。
- **漏洞的本质是"缺失原语"**：被确认的漏洞均源于规范**未规定**的机制（如缺少授权守卫的敏感转移、缺失的阶段边界检查、可绕过必需前驱的状态、事件字母表缺口），而非规范明确允许或禁止的行为。
- **成本可控**：单次端到端流水线成本约 **$40.97**，其中机械步骤（B1/B4/D1）零成本，为后续协议安全分析提供了可复用的成本基线。

## 7. 局限性

- **仅规范级分析**：受限于 A2A 无开源参考实现，无法做实现级分析（静态分析、模糊测试、符号执行），因此不覆盖实现缺陷、依赖库漏洞或配置错误。
- **完全合规假设的边界**：假设所有 RFC 2119 强度要求均被满足，这意味着**发现的是设计缺陷而非实现缺陷**；但同时也可能**遗漏那些"因实现普遍不合规才可被利用"的问题**。
- **LLM 依赖与可复现性**：流水线大量依赖商用 LLM API（Claude Sonnet 4.6 / Opus 4.6），未披露 token 数、调用次数与墙钟时间，跨模型迁移性未知；模型版本更新可能改变输出，影响可复现性。
- **基准代理性**：FSM 正确性以 TCP/PSMBench 为代理，与 A2A 协议形态不同，评估结论需谨慎外推。
- **候选发现的召回未量化**：无法证明 5 次 C1 运行已穷尽所有漏洞，可能存在未被发现的缺失原语。
- **静态快照**：分析针对 A2A v1.0 规范，协议演进后需重新形式化与验证。

## 8. 贡献与意义

- **首个 A2A 协议的系统性安全分析**：填补了"无实现级手段可用时，如何对互操作协议做严格安全分析"的方法学空白。
- **提出可复用的三阶段流水线（A→B→C）**：将自然语言规范转化为经验证的 FSM，再在形式上系统挖掘漏洞，并用对抗性 + 人工验证保证可靠性。
- **三大方法学贡献**：
  - **S1 双通道语义分离**——解决自然语言规范中定义性语义与行为性语义的交叉污染；
  - **S2 输入缩减 + 扩展思考**——将有界决策分解，把不可校验的综合问题变为可单独验证的步骤；
  - **S3 领域专用约束语言**——在所有提示中嵌入形式化约束，从机制上抑制 LLM 幻觉与自由文本漂移。
- **实证价值**：确认 11 个 A2A 协议设计漏洞，为 A2A 规范修订、多智能体生态的安全部署提供直接依据；同时以 9/9 被拒的零样本基线，量化了"仅用 LLM 做协议安全分析"的不可靠性。
- **可迁移性**：方法学不依赖 A2A 特有细节，可推广至 MCP 及其他由自然语言规范定义的互操作协议。
