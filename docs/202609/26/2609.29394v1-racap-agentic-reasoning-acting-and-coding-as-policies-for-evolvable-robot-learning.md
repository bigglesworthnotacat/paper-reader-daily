## 摘要
通用机器人智能体必须从经验中学习、迁移到新任务并高效行动。代码即策略（CaP）方法在运行时生成和修复程序，这会带来延迟，并将可复用机制与任务特定决策纠缠在一起。我们提出 RACaP，一个智能体框架，将编码移至演化阶段，并在部署时使用推理-行动（ReAct）循环调用冻结的、带类型的策略 API。一种两阶段策略将能力课程学习与自主自我演化相结合，以改进 API、ReAct 执行框架和经验记忆。这些 API 编码可复用的物理机制，同时暴露参数以实现运行时自适应。ReAct 结合任务特定的工作记忆、长期经验记忆和视觉反馈，以选择动作、验证结果并从失败中恢复，而无需修改源代码。RACaP 在 LIBERO-90 上达到 54.4% 的成功率，在零样本 LIBERO-PRO 上达到 45.0%，在 LIBERO-Long 上达到 46.0%；相比之下，CaP 基线在长时程任务上最高仅为 4.0%。在 LIBERO-PRO 上，其成功率是 CaP 基线的 2.5 倍，策略耗时中位数加速 1.9 倍。为实现在机器人上的高效部署，采用拒绝采样微调将 GPT-5.6 的 ReAct 决策蒸馏到 Qwen3-VL-8B-Instruct 中，使每次决策推理加速 13.2 倍，并将重复物理调用从 16 次减少到 4 次。这些结果表明，将可复用代码与运行时决策分离，有助于持续演化、有效迁移和高效的长时程控制。

## Abstract
General-purpose robot agents must learn from experience, transfer to new tasks, and act efficiently. Code as Policies (CaP) methods generate and repair programs at runtime, incurring latency and entangling reusable mechanisms with task-specific decisions. We introduce RACaP, an agentic framework that moves coding to evolution and uses a Reasoning-and-Acting (ReAct) loop to call frozen, typed Policy APIs at deployment. A two-phase strategy combines capability curriculum learning with autonomous self-evolution to improve the APIs, the ReAct harness, and experience memory. The APIs encode reusable physical mechanisms while exposing arguments for runtime adaptation. ReAct combines task-specific working memory, long-term experience memory, and visual feedback to select actions, verify outcomes, and recover from failures without modifying source code. RACaP achieves 54.4% success on LIBERO-90, 45.0% on zero-shot LIBERO-PRO, and 46.0% on LIBERO-Long, compared with at most 4.0% for CaP baselines on long-horizon tasks. On LIBERO-PRO, it achieves 2.5 times the success rate of CaP baselines and a 1.9-fold speedup in median policy time. For efficient on-robot deployment, rejection-sampled fine-tuning distills GPT-5.6 ReAct decisions into Qwen3-VL-8B-Instruct, yielding a 13.2-fold per-decision inference speedup and reducing repeated physical calls from 16 to 4. These results show that separating reusable code from runtime decisions supports continued evolution, effective transfer, and efficient long-horizon control.

- **研究动机**：通用机器人智能体需要从经验中学习、迁移到新任务，并在物理执行中高效适应。Code as Policies（CaP）通过生成可执行机器人程序提供灵活性，但把“编码”放在运行时执行路径上，导致每次编码迭代耗时 6.8–23.8 秒，多轮试验耗时 60.8–113.6 秒。

- **已有自改进 CaP 的不足**：
  - RATS 通过“新颖性/可学习性”的 play 目标收集程序，但不保证对下游任务有正收益。论文受控研究中，LIBERO-90 上的 play 使 RATS 域内成功率从 21.1% 降至 11.1%，零样本 LIBERO-PRO 从 17.8% 降至 8.3%。

- **核心研究问题**：CaP 系统应如何划分“演化时代码”与“运行时决策”，从而既能持续演化、跨任务迁移，又能适应当前物理状态？
- **整体含义**：论文提出 **evolution-to-execution** 问题，并给出答案——把编码移到演化阶段，运行时保留 ReAct 循环中的可操控函数调用。代码负责存储跨任务有效的物理机制，ReAct 负责场景相关选择（动作顺序、函数参数、恢复、停止）。接口需足够强以执行可靠控制，又足够灵活以暴露新场景中会变化的决策。

## 2. 方法论

- **总体框架**：可部署策略表示为  
  \(\Pi = (A_\theta, \pi_\phi, M)\)
  - \(A_\theta\)：带类型接口的 Policy API 库，实现参数为 \(\theta\)；
  - \(\pi_\phi\)：运行时 ReAct 策略，由 harness 参数 \(\phi\) 定义；
  - \(M\)：长期经验记忆。
- **核心思想**：演化阶段优化 API、ReAct harness 与经验记忆；部署阶段冻结源码，只允许 ReAct 改变工具选择与可读参数，不生成、编译或修复 Python 代码。
- **API 目标（式 2）**：候选 API \(\theta'\) 与当前父代 \(\theta\) 在相同任务、种子、预算下配对评估，选择使开发集上配对净增益最大的候选：
  \[
  \theta^* = \arg\max_{\theta'} \sum_{\tau \in D_{dev}} [S(\tau,A_{\theta'},\pi_\phi,M)-S(\tau,A_\theta,\pi_\phi,M)]
  \]
  即奖励跨任务泛化：只有配对增益超过配对回归的机制才被保留。
- **ReAct 目标（式 3）**：API 固定后，以字典序选择 harness 参数与记忆：
  \[
  (\phi^*,M^*) = \arg\text{lex}\max_{\phi',M'} \left(\sum_\tau S(\tau,A_{\theta^*},\pi_{\phi'},M'), -\sum_\tau T(\tau,A_{\theta^*},\pi_{\phi'},M')\right)
  \]
  先最大化成功率，仅在成功率打平时才比较 ReAct 轮数，避免“更快但更不成功”的智能体胜出。
- **两阶段演化策略**：
  - **Phase 1：能力课程学习**。在 S0–S6 阶段逐步建立执行、恢复、技能广度与编排能力。例如 S0 直接运输、S1 运输 ReAct 恢复、S2 有界放置、S3a–S3d 插入/堆叠/关节操作/紧凑控制、S4 工具路由、S5 因果组合、S6 效率。在 41 任务运输队列上，成功率从 13/41（31.7%）升至 28/41（68.3%）；全 90 任务从 40/90（44.4%）升至 48/90（53.3%）。
  - **Phase 2：自主自演化**。系统聚类失败、分析视觉 critic 摘要、让编码智能体提出单一修改（API、参数暴露、工具报告、ReAct 路由或记忆），候选代码须通过语法编译与基本测试，再在相同任务、种子、预算下与冻结父代配对验证；仅当原生成功率严格更高才晋升，平局与回归归档。
- **运行时结构**：
  - **Policy API 库**：`pickplace`、`insert`、`stack`、`push`、`articulate`、`actuate_control`，接受抓取类型、间隙、目标解释、偏航、接触模式等参数，返回可读状态、测量值和最新图像。
  - **两级 ReAct**：Full ReAct 解析完整指令、排序目标、检查语义状态并跨六个 API 路由；Transport ReAct 作为子控制器处理单源到单目标子任务，使用 `pickplace`、`insert`、`push`、`look`、`check`、`done`。
  - **双记忆**：工作记忆维护当前 episode 的任务目标、剩余子目标、近期 API 调用与视觉结果；长期经验记忆提供可复用先决条件、恢复经验与 API 能力边界，不存储任务答案、绝对场景坐标或评估器状态。
  - **六个类型化 prompt 角色**：`task_plan`、`task_plan_review`、`state_preflight`、`state_decide`、`transport_decide`、`transport_reflect`，输出 schema 校验的 JSON。
- **RFT 蒸馏**：用拒绝采样微调（RFT）将 GPT-5.6-sol 教师的 ReAct 决策蒸馏到本地 Qwen3-VL-8B-Instruct 学生。只保留原生成功、满足 schema 约束、含有效视觉证据的教师 rollout，得到 54 条接受、40 条拒绝决策；训练角色特定 LoRA 适配器，冻结基座模型与视觉编码器。
