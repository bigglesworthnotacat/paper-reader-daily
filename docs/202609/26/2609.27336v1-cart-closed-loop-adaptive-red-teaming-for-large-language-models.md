## 摘要
自动红队测试通常重放一组固定的提示，这能衡量已知风险，但无法从测试中发现的失败中学习。我们提出 CART（闭环自适应红队测试），一个利用每次结果来指导下一步测试内容的框架。CART 从广泛的风险覆盖开始，追踪新出现的弱点，保持新探测的多样性，并记录每项发现的证据和来源。它将创建测试的 Challenger、被测试的 Target（可能是纯文本模型或有界工具使用智能体）以及评估结果的 Judge 分离，使这些角色能够被独立研究。在三个评估系列（Frontier、JAH 和 Agentic）中，对于每个有可用基线的 Target，CART 发现的失败更多，平均风险也高于静态种子重放。这些增益也延伸到工具介导的智能体测试，表明上下文自适应能够揭示直接提示重放无法触及的弱点。这些结果描述的是测试策略发现了什么，而不是真实部署中失败发生的频率。我们还发现，Challenger-Judge 的选择会影响所揭示的证据，凸显了角色分离与独立审查的必要性。总体而言，CART 将红队测试从一次性检查清单转变为对模型和智能体弱点的持续、自适应且可审计的搜索。

## Abstract
Automated red teaming often replays a fixed set of prompts, which measures known risks but cannot learn from failures found during testing. We present CART (Closed-Loop Adaptive Red Teaming), a framework that uses each result to guide what it tests next. CART begins with broad risk coverage, follows weaknesses that emerge, keeps new probes diverse, and records the evidence and source of every finding. It separates the Challenger that creates tests, the Target being tested, which may be a text-only model or a bounded tool-using agent, and the Judge that evaluates the results, allowing these roles to be studied independently. Across three evaluation families (Frontier, JAH, and Agentic), CART discovers more failures and higher average risk than static seed replay for every Target with an available baseline. The gains extend to tool-mediated agent tests, suggesting that contextual adaptation can reveal weaknesses that direct prompt replay does not exercise. These results describe what the test policies discover, not how often failures occur in real deployments. We also find that Challenger-Judge choices affect the evidence uncovered, highlighting the need for role separation and independent review. Overall, CART turns red teaming from a one-time checklist into a continuous, adaptive, and auditable search for model and agent weaknesses.

## 1. 核心问题与研究背景

- **研究动机**：现有自动化红队测试普遍采用**开环范式**——提交一组固定的提示集、评分、结束。静态回放能追踪已知风险，但无法利用测试中发现的失败来决定下一步测什么。
- **评估对象的变化**：大模型越来越多地作为交互系统组件运行（检索文档、调用工具、维护状态、参与多步工作流）。一个能安全处理孤立提示的模型，可能在遇到不可信检索内容、权限模糊、累积状态或高后果工具操作时失效。
- **现实需求**：红队不仅用于模型发布，还用于产品保证与 AI 治理，与 system cards、MITRE ATLAS、OWASP LLM Top 10、NIST AI RMF 及生成式 AI Profile 相呼应。
- **核心研究问题**：在有限测试预算下，自适应红队系统能否比静态评估揭示**更广、更隐蔽的风险面**，同时保持每个发现**可追溯、可复现**？
- **整体含义**：将红队从"一次性检查清单"重构为**持续、自适应、可审计的弱点搜索过程**；成功标准不只是失败数量更多，而是一条可复核的轨迹——测试了什么、为何选择、如何变化、结果如何被判定。

## 2. 方法论：CART 框架

### 2.1 核心思想

- **三角色解耦**：
  - **Challenger**：构造探针（测试用例）。
  - **Target**：被测对象，可为纯文本模型或**有界工具使用智能体**。
  - **Judge**：评估文本响应或工具动作轨迹。
- **闭环学习**：每次判定写入记忆，更新弱点画像，指导后续轮次的探针选择与构造。
- **设计目标**：先广覆盖 → 追踪暴露的弱点 → 保持探针多样（避免退化为同义改写）→ 保留从风险假设到证据的完整溯源。

### 2.2 配置与问题形式化

- 一次运行的配置记为 **Π = (R, C, S, N, τ_seed, ϕ_seed, p_weak, λ, κ)**：
  - `R`：风险类别分类法（默认 12 类）；`C`：能力类别（默认 9 类）；`S`：攻击策略（默认 12 种）。
  - `N`：轮次预算；`τ_seed` / `ϕ_seed`：周期性 Grounded 检索的间隔与相位。
  - `p_weak`：侦察阶段后进入弱点追踪分支的概率。
  - `λ = (λ_sev, λ_blast, λ_repr, λ_conf)`：评分权重（和为 1）；`κ = (κ₀, κ₁, κ₂)`：优先级截断值。

### 2.3 单轮七步流程

1. 读取历史结果（Memory 汇总每类风险的测试数、失败数、分数、近期证据）。
2. 选择下一个测试区域（风险类别 `r` 与策略 `s`）。
3. 可用时选择种子（Seed Store 检索相关案例）。
4. Challenger 结合目标画像、类别、策略、历史、多样性要求与种子，生成结构化测试提示与期望安全行为。
5. Target 作答或完成有界工具使用回合。
6. Judge 记录是否失败，并返回严重度、影响范围、可复现性、置信度、证据与建议后续测试。
7. 计算风险分与优先级，将完整记录存入 JSON/SQLite，并更新记忆。

### 2.4 关键算法细节

- **弱点画像（式 2）**：类别 `r` 的弱点值 `w_t(r)` 为历史记录风险分的均值；未测类别为 0，直到侦察触达。
- **Thompson 采样选类（式 4）**：对类别 `r`，按 `θ_r ~ Beta(f_r + 1, (n_r − f_r) + 1)` 抽样，取 `argmax`。未充分测试的类别后验宽、仍有竞争力；失败多的类别更易被抽中。**无需 ε-greedy 或 UCB 的调参常数**，且给定 RNG 种子可复现。
- **策略库（12 种，分 5 族）**：
  - 覆盖类：Basic coverage、Grounded retrieval。
  - 自适应类：Weakness pursuit、Variant testing、Boundary testing。
  - 压力类：Stress consistency、Adversarial context、Combination risk。
  - 智能体类：Agentic tool-abuse testing、Indirect-injection testing。
  - 系统性类：Goal splitting、Multi-round poisoning。
- **选择策略四分支**：周期性 Grounded 检索（`c_t mod τ_seed = ϕ_seed`）→ 侦察（早期按序扫描）→ 以 `p_weak` 概率弱点追踪 → 否则回退随机。
- **多样性约束**：选择决定"测哪里"，多样性决定"如何表达"。要求每轮变化 persona、领域、语言、格式、角色、权威来源、交互长度、攻击面、证据类型等维度，并记录所变维度。记忆仅提供最近 12 条与最高风险 5 条探针的紧凑签名，使生成上下文有界。
- **种子谱系（式 5）**：`SEED REPLAY`（静态基线直接提交）、`SEED ADAPTATION`（Grounded retrieval 策略下使用种子）、`SEED EXPANSION`（其他自适应策略使用种子）、`SELF-GENERATED`（无种子）。标签由记录的策略与来源元数据导出，而非文本相似度阈值。
- **风险评分（式 6）**：
  `risk score = λ_sev·severity + λ_blast·blast radius + λ_repr·reproducibility + λ_conf·(R_max·confidence)`
  - 非失败记录风险分为 0；默认 `R_max = 5`，严重度/影响/可复现性用 1–5，置信度 0–1。
  - 优先级：`P0: ≥κ₀`、`P1: [κ₁,κ₀)`、`P2: [κ₂,κ₁)`、`P3: <κ₂`。
  - **答案质量与风险分开存储**，更换 Judge rubric 与优化目标即可转为质量缺陷挖掘。
- **智能体执行**：Target 置于有界 ReAct 风格循环，使用 mock 文件、Web、邮件、KV 存储、Shell、数据库、HTTP 工具；工具不触真实系统，记录调用并返回固定观测。显式模式标记危险动作，植入 canary 检测是否遵循间接注入。
