## 摘要
智能体集成软件（AIS）将智能体嵌入传统应用，同时支持人类操作和智能体动作。人类操作让用户进行精确更改并检查结果，而智能体动作执行常规或多步任务。这些互补角色使共存成为许多软件系统可能的长期特征。人类操作和智能体动作影响相同的软件状态，并可以使用彼此的结果。因此，安全策略必须在两条路径上都保持有效。我们认为，AIS 安全必须在整个软件系统层面进行评估。分别保护智能体和传统软件核心并不能证明它们在一起是安全的。为指导对 AIS 整体的安全分析，我们将这种共存引发的问题归纳为四类：上下文误用、授权违规、执行控制和效果完整性。利用这些类别，我们考察当前实践如何应对 AIS 中的安全问题，以及其保护在哪些方面仍然有限。在此分析基础上，我们识别出在保留信息溯源、跨操作路径执行策略、随时间维持有效授权，以及管理持久效果与恢复方面的研究机会。由此形成的视角为理解和改进 AIS 的安全性提供了一个概念框架。

## Abstract
Agent-Integrated Software (AIS) embeds an intelligent agent in a conventional application, supporting both human operations and agent actions. Human operations let users make precise changes and inspect results, while agent actions carry out routine or multi-step tasks. These complementary roles make coexistence a likely long-term feature of many software systems. Human operations and agent actions affect the same software state and can use one another's results. Therefore, security policies must remain effective across both paths. We argue that AIS security must be assessed at the level of the whole software system. Protecting the agent and the conventional software core separately does not establish that they are secure together. To guide security analysis of AIS as a whole, we organize the problems arising from this coexistence into four categories: context misuse, authorization violation, execution control, and effect integrity. Using these categories, we examine how current practices address the security problems in AIS and where their protection remains limited. Building on this analysis, we identify research opportunities in preserving information provenance, enforcing policy across operation paths, maintaining valid authorization over time, and managing persistent effects and recovery. This resulting perspective provides a conceptual framework for understanding and improving the security of AIS.

### 1.1 背景
- **AIS（Agent-Integrated Software，智能体集成软件）** 被定义为：在传统应用（conventional application core）中内嵌一个智能体，同时支持两类操作路径：
  - **人类操作（human operations）**：用户自行选择并执行，用于精确修改、检查结果、处理不愿委托的工作。
  - **智能体动作（agent actions）**：智能体面向用户给定目标自主选择并执行操作，承担常规或多步任务。
- 两类角色互补，作者判断"共存"将成为许多软件系统的**长期特征**，涵盖分离、交替、重叠三种使用形态。

- 人类操作与智能体动作**作用于同一软件状态、共享资源、并可使用彼此的结果**：
  - 用户提供的信息可能包含重定向智能体行为的指令（间接提示注入）。
  - 智能体产生的结果可能被用户后续编辑或分享。
- 由此引出论文的核心立场（position）：
  > **AIS 安全必须在整个软件系统层面评估。分别保护"智能体"和"传统软件核心"并不能证明二者合在一起是安全的。**

## 2. 方法论：核心思想与关键概念

### 2.1 系统边界与安全假设（Section 2.1）
- **纳入 AIS 范围的三个条件**（三者需同时满足）：
  1. 用户仍能通过软件界面执行操作；
  2. 智能体能面向目标选择并执行操作，且这些操作在软件安全策略下使用软件资源（含读取受保护信息与修改数据）；
  3. 内嵌智能体不必与软件核心同进程，也不必持有不受限的凭证。
- **边界情形（Table 1）**：
  - 在范围内：支持人类操作 + 智能体使用受限域 API 的应用；仅做受保护检索的受限智能体（检索本身仍需访问与披露控制）。
  - 不在范围内：只生成文本供用户复制的聊天控件；仅由外部自动化控制无关应用；纯智能体服务或无可变人类操作的固定工作流。
- **信任与对手模型**：
  - 受保护资产包括个人信息及其在智能体上下文、记忆、日志中的副本，其他机密数据、软件对象与工作流、配额资源、授权与结果记录。
  - 对手能力：在普通账户权限内提交请求、编辑其可控内容、提供检索到的外部内容；**不含**对可信执行组件的任意篡改。
  - 规划器与其读取的内容**不能授予权限**；被信任的组件负责认证决策与执行权限检查。
- **操作/效果的术语学**：
  - operation（操作尝试）→ request（提议执行）→ **admission（服务接受）** → **effect（披露/状态变更/资源占用）** → **commitment（效果被视为已发生）** → observed outcome（凭证/证据确认的结果）。
  - 关键区分：服务接受请求 ≠ 效果已发生 ≠ 请求者知晓结果。

### 2.2 四类安全问题的推导逻辑（Section 2.2）
论文从 AIS 架构中**四个"局部检查不足以保证全局安全"的关系**推导出四类问题：

| 架构关系 | 对应类别 | 核心含义 |
|---|---|---|
| 信息 → 决策（information to decision） | **上下文误用** | 有权读取内容 ≠ 该内容有权指挥智能体 |
| 意图 → 实际行使的权限（intent to exercised authority） | **授权违规** | 有权访问某工具 ≠ 有权执行该工具的所有操作 |
| 初始授权 → 后续执行（initial authorization to later execution） | **执行控制** | 初始批准可能不再覆盖后续动作 |
| 操作 → 持久效果（operation to persistent effect） | **效果完整性** | 检查单次操作 ≠ 保护组合效果或后续效果 |

- 强调：四类**既非攻击阶段链，也非穷尽性分类**；单次失败可能同时涉及多类（如未授权导出 = 恶意上下文 + 过度委托权限）。用户隐私贯穿四类。

### 2.3 IIA：意图级交互抽象（Intent-Level Interaction Abstraction）
- 引用 Yu et al. [38]，用于描述用户如何在**任务层面**表达、审查与重定向委托工作。
- 涵盖：目标与相关资源、提议的动作、需批准的决定、用户干预、已知结果。
- 核心作用：区分"用户要求智能体**达成什么**"与"用户**授权它做什么**"（例如"准备报告"不等于"授权发布"）。
- 软件需为每个任务关联以下信息以执行策略：
  - 请求者身份与执行身份（requester / execution identity）
  - 目标（goal）
  - 资源与接收者范围（resource and recipient scope）
  - 允许的效果（allowed effects）
  - 保留的决策（reserved decisions）
  - 有效条件（validity conditions）
  - 控制权（control rights）
- **IIA 只描述交互需求，强制执行仍由软件负责**。

### 2.4 四类问题的具体内涵
- **上下文误用**：智能体以策略不允许的方式使用信息（把人类提供的内容误当指令；把受保护数据传给无权接收的模型/工具）。即使另有授权检查阻止披露，上下文误用仍可独立发生。涉及上下文采集最小化、传输目的地限制、记忆/缓存/日志的保留与删除。
- **授权违规**：人类操作或智能体动作超出权限；某路径禁止的操作不能因切换路径而变得可行。涉及**混淆代理（confused deputy）**与**不完全中介（incomplete mediation）**、服务凭证权限 ≠ 任务权限、复合工具（compound tool）在完成前已产生的披露与状态变更、以及"只读"工具仍可能产生敏感工件。
- **执行控制**：委托任务跨越时间，规划、工具选择、批准、调度、提交、完成可能发生在不同时刻与不同组件。涉及 TOCTOU、使用权控制（usage control）、租约（leases）、版本化授权、撤销（revocation）与已接受操作的不可撤回性、以及真实的人类干预语义（暂停/撤销/接管必须改变系统**允许什么**，而非仅改变计划文本或状态显示）。
- **效果完整性**：包括组合效果（两次单独允许的操作可能共同超预算、违反职责分离）、生成工件继承输入的敏感性、恢复（recovery）需在当前权限下进行、外部效果的不可逆与结果不确定性（超时不能证明失败，重试可能重复执行）、以及审计记录本身的访问控制、完整性保护与最小化保留。

### 2.5 贯穿案例（Section 2.7）
构造一个企业文档应用：请求者要求智能体为已批准接收者组准备季度报告；准备被允许，**发布需单独批准**且批准绑定到"已审查的报告版本 + 组成员名单"。检索到的源文件包含"附上内部记录"的注入指令 → 上下文误用；导出适配器使用宽泛服务凭证 → 授权违规；管理员随后更改接收者组 → 执行控制；已接受的外部发布无法通过本地恢复撤回 → 效果完整性。

## 6. 主要结论与发现

### 6.1 关于 AIS 安全的核心结论
1. **必须整体评估**：保护智能体与保护传统软件核心各自成立，不蕴含二者组合安全；软件必须在人类操作与智能体动作**两条路径**上执行其安全规则——权限可以不同，但每个操作必须留在其被授权的范围内。
2. **四类共存问题的框架成立**：上下文误用、授权违规、执行控制、效果完整性，分别对应信息→决策、意图→权限、初始授权→后续执行、操作→持久效果四条关系。
3. **现有实践有实质局限**（Table 3）：
   - 上下文误用：需限制个人数据采集与传输、保留来源限制、控制记忆保留；
   - 授权违规：需让任务与工作流限制**穿过每一条通往受保护效果的路径**；
   - 执行控制：需按**实际资源与接收者**核对批准，并在执行中执行停止与撤销决策；
   - 效果完整性：需覆盖外部效果、依赖工作与隐私友好的结果记录。
4. **撤销的语义边界**：阻断新请求 ≠ 取消已接受的操作（Figure 3）；停止确认不得暗示本地或远程副本已被擦除。
5. **恢复的权限边界**：恢复操作本身需要**当前**权限；回滚可能破坏后续已授权工作或恢复不应再适用的共享策略；本地恢复无法使已发送文档变得"未被看见"。
6. **审查时机的安全价值取决于时机**：若文件写入即触发 watch task，事后审查 diff 已太晚（Figure 4a）。
