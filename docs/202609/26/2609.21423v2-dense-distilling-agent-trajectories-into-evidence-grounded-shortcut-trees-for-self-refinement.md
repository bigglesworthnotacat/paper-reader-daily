## 摘要
在线智能体部署会产生大量执行轨迹，而针对特定任务的验证与专家标注难以规模化。这一差距引出一个问题：在没有执行后奖励或正确性标签的情况下，我们能从轨迹本身中提取哪些有用经验？为高效利用这些信息，我们提出 DENSE（Distilling Evidence from Nested Subtask Executions），它将轨迹证据组织成基于证据的嵌套捷径树。DENSE 压缩重复尝试，跟踪已解决的问题，并在保留未完成需求的同时保留有用步骤。为评估反馈如何帮助智能体重试同一任务，我们提出 REFIT，它比较相对于初始尝试的任务成功率变化。在无外部结果监督的测试方法中，DENSE 在 Terminal-Bench 2.1 上于四个智能体模型中取得最高严格通过率。与初始尝试相比，严格通过率提升 7.12–15.64 个百分点，同时新尝试期间观察到的智能体 token 用量降低 19.0–43.6%。在一项探索性的困难任务扩展中，DENSE 在四个模型上经过多次反馈迭代后的累积通过率也优于 Self-reflection 基线。这些发现表明，DENSE 有潜力在无需外部标注或执行后结果监督的情况下实现智能体的持续自我改进。

## Abstract
Online agent deployments produce abundant execution traces, while task-specific verification and expert annotation are costly to scale. This gap raises a question: without post-execution rewards or correctness labels, what useful experience can we extract from the trajectories themselves? To efficiently use this information, we introduce DENSE (Distilling Evidence from Nested Subtask Executions), which organizes trajectory evidence into evidence-grounded nested shortcut trees. DENSE condenses repeated attempts, tracks resolved problems, and preserves useful steps alongside unfinished requirements. To evaluate how feedback helps agents retry the same task, we introduce REFIT, which compares changes in task success rates from the initial attempt. Among tested methods without external outcome supervision, DENSE achieves the highest strict pass rate across four agent models on Terminal-Bench 2.1. Compared with the initial attempts, strict pass rate increases by 7.12-15.64 percentage points, with 19.0-43.6% lower observed agent token use during the new attempts. In an exploratory hard-task extension, DENSE also outperforms the Self-reflection baseline in cumulative pass rate after multiple feedback iterations across all four models. These findings suggest DENSE's potential for continual agent self-improvement without external annotations or post-execution outcome supervision.

## 2. 方法论

### 2.1 核心思想
- DENSE（**D**istilling **E**vidence from **N**ested **S**ubtask **E**xecutions）把散乱的动作–观测序列组织为**基于证据的嵌套捷径树（evidence-grounded nested shortcut trees）**，每个"捷径（shortcut）"记录：尝试过的方法、有效步骤、支撑观测、未完成需求。
- 信息边界（post-hoc outcome blindness）：生成器只能看到任务 x 与可见轨迹 τ₀，**不得**使用执行后奖励、隐藏验证器输出、参考答案、人工正确性标签（唯一例外是被显式标记为 privileged 的 Verifier Feedback 参照）。

### 2.2 关键技术流程
**阶段一：自底向上构建嵌套子任务树**
- 将动作–观测配对为叶子 ℓᵢ=(aᵢ,oᵢ)，放入时间有序队列 Qₖ。
- 分析模型识别语义边界 b，把前缀 G=(u₁,…,u_b) 归为一个服务单一目标的子任务，生成父节点 v（含动作诊断、子任务摘要），放入 Qₖ₊₁；重复直至形成根层级。每层保持时间顺序与来源覆盖。

**阶段二：捷径压缩 → 问题调和 → 反馈渲染**
- **A. 压缩尝试为捷径**：自底向上融合同一父节点下连续尝试，保留失败路径（dead-end）、最短可行路径（working-path）+ 支撑观测、局部最终结果、来源引用；融合不跨父边界、不重排来源。
- **B. 通过恢复证据调和问题**：早期问题可能被后续子任务修复，父节点需重新审视继承问题。形式化表示为
  (T*ᵥ, σᵥ, Iᵥ) = Reconcile( T̃ᵥ, {(σᵤ, Iᵤ)}_{u∈child(v)} )，
  其中 T̃ᵥ 为压缩后局部子树、σᵥ 为状态摘要、Iᵥ 为剩余问题。**关闭一个继承问题必须有具体恢复证据**；恢复、子任务完成、整体完成在各自作用域内独立判定。语言模型做语义判断，确定性检查约束来源覆盖、证据引用、问题更新与关键动作保留。
- **C. 渲染未完成需求**：完成的枝节只给简短摘要；未完成/失败/缺乏证据支撑的枝节展开其捷径、问题与观测。选定的关键写操作与最终响应内容保持原文。整体反馈有界（树反馈 ≤180 KiB，总预算 200 KiB），截断按完整语义块进行。

### 2.3 评估框架 REFIT
- 固定智能体 A、任务分布 D、工具与执行预算；所有方法分析**同一 τ₀（run0）**，各自生成反馈 f_g，并在**重置环境 s₀ + 全新模型上下文**下执行 run1：τ₀=A(x;∅,s₀)，f_g=g(x,τ₀)，τ₁^g=A(x;f_g,s₀)。
- 反馈效用：U(g|A,D)=E_{x∼D}[ y(x,τ₁^g) − y(x,τ₀) ]，即严格通过率（reward 恰为 1）的配对变化，用**百分点（pp）**度量。
- 反馈是两次执行之间唯一的信息通道；验证器结果只用于事后评估，不回流到反馈生成。

## 3. 实验设计

- **Benchmark**：Terminal-Bench 2.1（容器化终端环境、长程多步工具交互），89 个任务，覆盖软件工程、文件与数据处理、科学计算。
- **接收方模型（recipients，4 个）**：MiniMax-M2.7、DeepSeek V4 Pro、GPT-5.5、Kimi K2.6；其中 MiniMax/GPT/Kimi 用全部 89 任务，DeepSeek 用其文本端点支持的 81 个任务（排除 8 个需图像/视频输入的任务）。
- **反馈生成模型**：统一使用 Gemini 3 Flash Preview（固定生成模型以比较信息输入与抽取流程）。
- **执行设置**：每个任务×接收方做 3 次配对重复；同一重复内所有方法共享同一 run0；run1 使用相同任务指令、工具与预算。
- **对比方法**：
  - Advisor：仅凭任务描述给建议（任务先验对照）
  - Self-reflection：直接把原始轨迹交给下一轮智能体自我总结（基线）
  - All-at-once：一次调用对全轨迹做动作级评估
  - Step-by-step：按决策时刻前缀逐动作评估（隐藏该动作结果与后续事件）
  - **DENSE（本文方法）**
  - Verifier Feedback（VF）†：额外提供初始轨迹 + 最终 reward + 验证器测试输出（**特权参照**，唯一使用执行后信号的方法）
- **指标**：严格通过率 P、配对变化 ΔP、观测到的接收方 token 用量（含 cache 读写）、pass@3（覆盖率）与 pass^3（三次一致性）、估计 USD 成本。

## 6. 主要结论与发现

- 在无外部结果监督的方法中，**DENSE 在全部四个接收方上取得最高严格通过率**：52.43% / 67.08% / 75.66% / 50.94%（MiniMax / DeepSeek / GPT / Kimi），相对共同基线分别提升 **+7.87 / +15.64 / +7.12 / +11.61 pp**。
- 观测到的接收方 token 用量分别下降 **19.0% / 20.0% / 43.6% / 23.7%**，即"更多任务、更少 token"。
- 在 MiniMax 上，DENSE 是唯一获得正增益的非特权方法，且**超过特权方法 VF 达 7.49 pp**；分解显示其优势主要来自**保留更多历史成功**（VF 在 119 个成功源上回归率 31.09%，DENSE 仅 7.56%），VF 的 37 次回归中 32 次为零工具调用。
- 在 GPT/Kimi 上 VF 仍优于 DENSE，说明结果信息的收益随智能体而异，特权信息不构成性能上界。
- 消融支持"嵌套子任务分析 + 捷径压缩与问题调和"的**组合必要性**（各去掉一项分别掉 3.37 / 3.00 pp）。
- 困难任务迭代扩展中，经过 3 轮反馈，DENSE 的累积通过率分别比 Self-reflection 高 **3.3 / 7.8 / 6.7 / 10.3 pp**（GPT / MiniMax / Kimi / DeepSeek）。
- 覆盖率与一致性：DENSE 在 MiniMax/GPT/Kimi 上 pass@3 与 pass^3 双指标均超基线；DeepSeek 上 pass@3 最高但 pass^3 略低于 Self-reflection。
- 案例显示：DENSE 能把"局部发现"连接到"未完成交付要求"（如 password-recovery 中 3 次工具调用完成任务，而其他条件用 25–47 次调用仍未写出文件）。

## 7. 优点

- **问题设定有价值**：明确划定"无执行后监督"的信息边界，把"能否从无标签轨迹中提炼可复用经验"作为可检验的科学问题，而非仅做工程优化。
- **方法结构清晰且可解释**：嵌套子任务树 + 捷径 + 问题调和的层次化表示，天然区分局部成功与全局完成、历史状态与当前状态；关闭问题需引用具体恢复证据，抑制了"乐观总结"。
- **评估框架 REFIT 设计严谨**：共享 run0、重置环境与上下文、反馈生成与验证器评估分离、配对变化度量，较好控制了自校正文献中常见的重采样与特权信息偏差。
- **多维指标**：同时报告严格通过率、配对变化、token 消耗、pass@3/pass^3 覆盖率与一致性、以及 USD 成本，兼顾效果与效率。
- **含特权基线对照**：设置 Verifier Feedback 作为上界参照，并发现其并非不可超越（MiniMax 案例），增强了结论的说服力与讨论深度。
- **案例分析与机制解释细致**：对 MiniMax 上 VF 的失败模式做了定量分解（保留/回归/修复转移矩阵）与零工具调用的可观测诊断，并诚实标注"不能隔离单一因素"。

## 8. 不足与局限

- **实验覆盖窄**：仅在 Terminal-Bench 2.1 上评估，缺少网页、桌面、深度研究等其他环境的验证；跨 benchmark 与跨任务迁移性未知。
- **无独立重试对照**：迭代扩展中 run0 以上的提升无法完全归因于反馈本身，DENSE 相对 Self-reflection 的比较也仅是描述性（three-round horizon 内）。

- **消融无法分离多因素**：`w/o S&R` 与 `w/o hierarchy` 同时改变了表示层级、压缩/调和机制、反馈长度与显著性，完整 DENSE 相对基线的提升不能唯一归因于“嵌套树”或“捷径+问题调和”中的某一项；论文也仅在一个接收方（GPT-5.5）上做消融，跨模型的可迁移性未验证。
- **反馈生成器单一**：所有非特权方法统一使用 Gemini 3 Flash Preview 生成反馈，这有利于控制“信息输入与抽取流程”的变量，但结论是否依赖该生成模型的长上下文能力、指令遵循与语义判断质量尚不清楚；换用更弱或更强的生成器可能改变方法排序。
- **案例选择的事后偏差**：论文自述案例是在观察结果后挑选的，虽用于机制说明合理，但不能作为无偏性能证据；缺少预注册案例或随机抽样案例的验证。
- **统计不确定性报告不足**：主要结果以点估计和百分点差呈现，未系统给出置信区间、显著性检验或多次重复下的方差分解；在任务数有限、任务难度异质的设定下，若干 pp 级差异的稳健性仍需谨慎解读。
- **严格通过率的指标局限**：`reward == 1` 的二值指标只捕捉最终是否完全成功，忽略部分完成度、步骤效率、错误恢复质量与中间交付物质量；某些反馈可能显著改善过程行为却未反映在最终通过率上。
- **反馈预算与截断策略未充分消融**：树反馈 ≤180 KiB、总预算 200 KiB，长轨迹下按完整语义块截断虽优于粗暴截断，但关键证据仍可能被丢弃；不同预算、不同截断粒度对效果与 token 成本的影响没有单独实验。
- **特权信息边界依赖人工设计**：Verifier Feedback 被显式标为 privileged，DENSE 则被限制为 post-hoc outcome blind；但 run0 轨迹中若自然包含验证器输出、日志中的成败信号或环境反馈，是否构成隐性泄漏、如何审计，论文未展开讨论。
- **成本估算的适用范围有限**：USD 估算基于公开 API 基础文本费率，不含缓存折扣、长上下文附加费、失败重试与并发调度开销；不同供应商价格、批量折扣与自托管成本会显著改变经济性结论。
- **泛化与长期稳定性未知**：仅 Terminal-Bench 2.1 一个 benchmark，未覆盖网页、桌面、深度研究、多智能体协作等环境；迭代精炼只在 hard 子集上做 4 轮，长期自我改进中是否会出现错误经验累积、反馈漂移或记忆污染，缺少证据。
- **安全与伦理讨论不足**：从无标签轨迹中蒸馏经验可能固化错误操作、偏见或危险命令；渲染时保留关键写操作与最终响应原文，也可能在反馈复用中泄露敏感文件内容、凭据或环境细节，论文未给出相应的脱敏与安全审计机制。
