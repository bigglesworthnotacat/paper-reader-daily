## 摘要
大语言模型的快速进展正将 AI 从被动的内容生成拓展到工程与科学发现的主动工作流中。这一转变引出一个引人深思的问题：AI 能否既是开发对象，又是构建下一代 AI 系统的积极参与者？我们在一个闭环 AI-for-AI 框架内构建 Qwen-Planner-Agent 来探索这一问题，以实现可扩展的开发和迭代改进。移动规划为该路径提供了严苛的检验：复杂的长时程任务挑战智能体的可靠性，而代价高昂的真实设备交互限制了开发的可扩展性。该框架通过共享的动作-反馈-验证契约连接数据生产、模型训练和部署。(i) AI for Data 构建了一个人工把关的智能体数据飞轮，其中专门的智能体构造任务、收集交互轨迹、整理并平衡训练数据，并利用训练反馈指导后续数据生成。(ii) AI for Training 将监督式规划冷启动与混合环境在线智能体强化学习相结合，其中我们引入能力感知的奖励与优势工程（CARE），以在保持任务性能的同时降低推理和工具使用成本。(iii) AI 通过执行证据驱动的循环推动模型与运行框架协同演化，该循环在运行时编排记忆、技能和工具，并将结构化的动作反馈和保留的失败轨迹反馈回协调的模型与运行框架适配中。Qwen-Planner-Agent 在 MobilePA-Bench 上取得了所有评估模型和系统中最优的总体性能，并在工具使用、记忆、技能和子智能体协调方面相较其基础模型有所提升。对我们模型的进一步评估表明，其在非移动智能体基准上取得改进，同时基本保持通用能力。

## Abstract
The rapid progression of large language models is extending AI from passive content generation into the active workflows of engineering and scientific discovery. This shift raises a compelling question: can AI be both the object of development and an active participant in building next-generation AI systems? We explore this question by building Qwen-Planner-Agent within a closed-loop AI-for-AI framework for scalable development and iterative improvement. Mobile planning offers a demanding test of this approach: complex, long-horizon tasks challenge agent reliability, while costly real-device interaction limits development scalability. The framework connects data production, model training, and deployment through a shared action-feedback-verification contract. (i) AI for Data builds a human-gated agentic data flywheel in which specialized agents construct tasks, collect interaction trajectories, curate and balance training data, and use training feedback to guide subsequent data generation. (ii) AI for Training combines a supervised planning cold start with hybrid-environment online agentic reinforcement learning, where we introduce Competence-Aware Reward-and-Advantage Engineering (CARE) to reduce reasoning and tool-use costs while preserving task performance. (iii) AI drives model--harness co-evolution through an execution-evidence-driven loop that orchestrates memory, skills, and tools at runtime and feeds structured action feedback and preserved failure traces back into coordinated model and harness adaptation. Qwen-Planner-Agent achieves the best overall performance among all evaluated models and systems on MobilePA-Bench, improving over its base model across tool use, memory, skills, and sub-agent coordination. Further evaluations of our model show improvements across non-mobile agentic benchmarks while largely preserving general capabilities.

## 2. 方法论

### 2.1 核心思想

- 以共享的**动作—反馈—验证契约**连接数据、训练与部署三个阶段。
- 框架包含三条闭环：
  1. **AI for Data**：智能体驱动的数据飞轮。
  2. **AI for Training**：规划导向冷启动 + 混合环境在线智能体强化学习。
  3. **AI for Harness**：模型与运行框架协同演化。
- 关键原则：模型参数在服务期固定；离线更新经过验证、版本控制与人工审核；开发集反馈用于指导后续数据、训练和 Harness 修订。

### 2.2 任务形式化

- 用户请求为 \(x\)，环境初始状态为 \(s_0\)，策略不直接观测底层状态，而是通过环境接口获得观测 \(o_t\)。
- Harness 根据请求、检索记忆 \(m_t\)、加载技能 \(K_t\)、历史观测与动作构造上下文：
  - \(c_t = H_\eta(x, m_t, K_t, o_{\le t}, a_{<t})\)
  - \(a_t \sim \pi_\theta(\cdot \mid c_t, A_t)\)
- 环境执行动作后产生下一状态和观测：
  - \(s_{t+1} \sim P_{\text{trans}}(\cdot \mid s_t, a_t)\)
  - \(o_{t+1} \sim P_{\text{obs}}(\cdot \mid s_{t+1}, a_t)\)
- 任务验证器根据请求、交互历史和执行证据判断完成：
  - \(v_{t+1} = V(x, \xi_{t+1}, \tau_{\le t+1})\)
- 动作空间包括结构化工具调用、记忆访问/更新、技能选择/加载、澄清/拒绝、任务完成声明等；主要不是像素级 GUI 操作。

### 2.3 混合移动环境基础设施

- **程序化沙盒**：通过预定义程序逻辑执行类型化工具调用，确定性高、可复现、吞吐高，但覆盖受限于已实现工具与状态转移。
- **LLM 模拟环境**：用语言模型生成长尾交互响应，扩大场景覆盖，但可能不一致，需要任务级验证。
- **真实设备环境**：在真实设备会话中执行动作，捕获 OS 权限、认证服务、跨应用依赖和运行时变化，但成本高、并行差、重置难。
- **混合策略**：可复现任务主要用沙盒；长尾交互用 LLM 模拟；依赖真实设备/服务行为的任务选择性使用真机。所有后端通过统一智能体接口进入共享数据与训练流程。

### 2.4 AI for Data：智能体驱动数据飞轮

- **任务构建**：
  - 任务构建智能体将目标能力转化为可执行任务规格，包含用户目标、可用资源、初始条件、目标能力和完成标准。
  - 不规定唯一参考轨迹，允许不同有效计划。
  - 同时考虑场景覆盖与能力覆盖：信息获取、工具路由、参数落地、多步依赖、状态跟踪、恢复、验证完成等。
- **轨迹收集**：
  - 自动 rollout 在匹配后端中执行多步交互，记录动作、环境反馈、中间结果、错误、重试、恢复尝试、完成证据和最终结果。
  - 成功轨迹作为监督候选；失败和不完整轨迹也保留用于诊断。
- **数据集组成**：
  - 任务完成验证与数据质量评估分离。
  - 自动清洗、去重、模式一致性检查、证据支持检查。
  - 保留任务来源、后端、生成策略、能力标注、结果、失败归因等元数据。
  - 分为移动数据与非移动数据；移动数据为核心，非移动数据包括通用智能体轨迹、编码任务、推理与指令遵循数据。
  - 维护两类训练资产：用于冷启动的已验证轨迹，以及用于在线 RL 的可重置任务实例。
  - 按移动/非移动、能力、难度、来源配置采样权重，而非按原始语料规模采样。
- **反馈驱动数据精炼**：
  - 任务级：已掌握任务降采样；不稳定任务加权；工具路由、参数、状态跟踪、恢复、过早终止等失败组成修复集；模糊或弱支持样本退回整理。
  - 能力级：结合开发集结果与轨迹失败分布，判断是调整采样比例还是构造新任务。
  - 人类审核后冻结下一轮数据与采样配置，保留版本化历史。

### 2.5 AI for Training：能力自适应智能体优化

- **规划导向冷启动**：
  - 在整理后的数据上做监督微调，学习任务分解、动作排序、工具使用、状态条件重规划与恢复。
  - 对轨迹整理中识别为错误的模型动作轮进行掩码，保留执行反馈上下文，但监督已验证恢复轮。
  - 掩码交叉熵目标：
    - \(L_{\text{SFT}}(\theta) = -Z^{-1}\sum_{i,j} \mathbf{1}\{j \notin E_i\} \log \pi_\theta(y_{i,j} \mid h_{i,j})\)
- **混合环境在线智能体 RL**：
  - 从冷启动策略出发，在程序沙盒、LLM 模拟和选择性真机环境中在线 rollout。
  - 使用验证器反馈改进任务完成与鲁棒性。
- **CARE：能力感知奖励与优势工程**：
  - 核心原则：任务成功可靠后，逐步强调推理和工具使用效率；始终以验证成功为主要目标。
  - 对每个任务采样 \(G\) 条轨迹，组成功率 \(\bar{s}\) 作为能力信号。
  - 三种奖励机制：
    - **进展塑形**：低成功率组，\(R_i = s_i + \lambda_{\text{prog}}R_{\text{prog},i}\)
    - **结果巩固**：中等成功率组，仅用 \(s_i\)
    - **效率精炼**：高成功率组，\(R_i = s_i - \lambda_{\text{eff}}e_i\)
    - 统一形式：
      - \(R_i = s_i + \begin{cases}\lambda_{\text{prog}}R_{\text{prog},i}, & \bar{s}\in[0,p_{\text{low}})\\0, & \bar{s}\in[p_{\text{low}},p_{\text{high}})\\-\lambda_{\text{eff}}e_i, & \bar{s}\in[p_{\text{high}},1]\end{cases}\)
  - **AI 辅助调度配置**：
    - 有界 LLM 控制器每 \(N\) 步根据训练统计与开发集反馈配置 \(\phi = \{\lambda_{\text{prog}},\lambda_{\text{eff}},p_{\text{low}},p_{\text{high}}\}\)。
  - **质量保持优势校准**：
    - 标准 GRPO 组内归一化会在成功饱和组中放大小效率差异。
    - 对效率精炼组在分母上施加成功导出的下限：
      - \(\sigma_{\text{anchor}} = \sqrt{p_{\text{high}}(1-p_{\text{high}})}\)
      - \(\hat{A}_i = \frac{R_i-\bar{R}}{\sigma_R+\epsilon}\) 或 \(\frac{R_i-\bar{R}}{\max(\sigma_R,\sigma_{\text{anchor}})+\epsilon}\)
  - 最终优化使用裁剪组相对目标：
    - \(J_{\text{RL}}(\theta) = \mathbb{E}[\frac{1}{G}\sum_i \frac{1}{T_i}\sum_t \min(\rho_{i,t}(\theta)\hat{A}_i, \text{clip}(\rho_{i,t}(\theta),1-\epsilon_{\text{low}},1+\epsilon_{\text{high}})\hat{A}_i)]\)

### 2.6 AI for Harness：模型—运行框架协同演化

- **统一运行时**：
  - Harness 连接 Planner Model、外部资源与执行环境。
  - 组装对话历史、工具规范、场景适配器指导、持久记忆证据、运行时约束。
  - Executor 执行动作并返回工具结果、状态变化或错误。
- **技能与记忆**：
  - 技能描述工具依赖、操作流程、多轮交互要求。
  - 记忆包括用户模型、情景记忆、长期记忆、前瞻记忆，具有不同访问与信任边界。
  - 记忆生命周期：捕获、验证、索引、检索、巩固、修订。
  - 检索结合语义与关键词匹配，并考虑相关性、新近性、重要性和多样性。
  - 记忆作为证据提供给 Planner，不授权执行工具或改变外部状态。
- **隐私保护记忆安全**：
  - 区分私人用户记忆与共享智能体经验。
  - 共享前去除用户特定和敏感细节。
  - 访问控制、溯源、版本检查、删除与撤回权限。
  - 当前实现使用服务级认证令牌和管理员凭证；用户级访问依赖上游可信服务。
- **执行反馈驱动精炼**：
  - 部署轨迹记录工具/技能配置、检索记忆及来源、动作与参数、Executor 响应、状态证据、错误、验证结果。
  - 模型侧失败：任务分解、路由、参数落地、状态跟踪、恢复、任务收尾等。
  - Harness 侧失败：技能缺失/冲突、工具暴露不当、检索错误、记忆过时、反馈格式不完整等。
  - 候选更新经规则检查和版本控制，低置信、冲突或发布关键决策交人工审核；不在服务中自主应用。
- **协同演化形式化**：
  - 目标：\(\max_{\theta,\eta} J(\theta,\eta) = \mathbb{E}_{x\sim D, \tau\sim p_{\theta,\eta}(\cdot|x)}[R_x(\tau)]\)
  - 交替更新：
    - \(\theta^{(k+1)} = U_M(\theta^{(k)}; B^{(k)}, \eta^{(k)})\)
    - \(\eta^{(k+1)} = U_H(\eta^{(k)}; F(\theta^{(k+1)}, \eta^{(k)}))\)
  - 论文强调这是开发路径，而非已实现持续自主协同演化。
