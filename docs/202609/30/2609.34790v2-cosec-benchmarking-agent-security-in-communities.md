## 摘要
LLM 智能体在持久化的协作环境中运行，这些环境涉及多个用户、社区、记忆、文件和工具。社区边界可能保持固定，也可能随着成员身份、角色、构成和关系的变化而演变。智能体必须完成合法任务，并防止未经授权披露受保护信息。现有评估并未充分考察智能体系统中的这些风险。我们提出 CoSec，一个可执行基准，用于评估在社区内部及跨社区运行的 LLM 智能体系统中的隐私与授权执行情况。CoSec 包含 208 个典型场景，涵盖固定边界与演变边界、属于智能体所有者或其他参与者的受保护信息，以及通过对话、环境内容、持久记忆和组合工作流实施的攻击。CoSec 执行具有持久会话、记忆、文件和工具的完整智能体系统。它利用执行轨迹和产物，根据当前授权状态验证信息流。在不同的运行框架和模型配置中，智能体经常完成良性任务，却违反隐私和授权边界。隐私行为因运行框架、攻击面和社区状态而异，揭示了记忆、文件和工具以及工作流如何能够将受保护信息携带到其授权范围之外。这些发现表明，任务效用并不意味着隐私或授权合规，并且社区环境中的授权仍然是持久化 LLM 智能体尚未解决的安全挑战。

## Abstract
LLM agents operate in persistent collaborative environments involving multiple users, communities, memories, files, and tools. Community boundaries may remain fixed or evolve with changes in membership, roles, composition, and relationships. Agents must complete legitimate tasks and prevent unauthorized disclosure of protected information. Existing evaluations do not fully examine these risks in agent systems. We introduce \textbf{CoSec}, an executable benchmark for evaluating privacy and authorization enforcement in LLM agent systems operating within and across communities. CoSec contains 208 canonical scenarios spanning fixed and evolving boundaries, protected information belonging to the agent owner or other participants, and attacks through dialogue, environmental content, persistent memory, and composed workflows. CoSec executes complete agent systems with persistent sessions, memory, files and tools. It verifies information flows against the active authorization state using execution traces and artifacts. Across harness and model configurations, agents frequently complete benign tasks but violate privacy and authorization boundaries. Privacy behavior varies across harnesses, attack surfaces, and community states, revealing how memory, files, tools, and workflows can carry protected information beyond its authorized scope. These findings show that task utility does not imply privacy or authorization compliance and that authorization in community settings remains an unresolved security challenge for persistent LLM agents.

## 1. 核心问题与研究动机

- **背景趋势**：LLM 智能体正从孤立任务助手演变为多用户社区中的持久化代表，参与群组对话、组织和在线社区。在这些场景中，参与者之间的利益、数据所有权和权限可能各不相同。
- **核心安全风险**：社区参与引入了涉及多主体和跨上下文信息流的风险。例如，个人智能体同时参与健康支持社区和工作群组，在健康社区获知的信息可能保留在其历史、记忆或工作区中，但不应向工作群组的请求者披露。单个看似有益的操作可能组合成用户或社区之间不被允许的信息流。
- **现有评估的不足**：
  - 智能体安全基准（如 InjecAgent、AgentDojo、ASB、LITMUS）多聚焦于单一用户或单一任务，而非跨重叠社区的多个参与者。
  - 智能体社区基准（如 SOTOPIA、MultiAgentBench、AgentSocialBench）研究社交互动与协作，但缺乏受控的安全评估。
  - 多主体隐私研究（如 MAGPIE、AgentLeak、Got a Secret?）表明社区上下文和社会暴露会影响披露行为，但对**完整智能体系统**在持久化数据、记忆、工具和变化社区状态上的受控安全评估仍然有限。
- **论文主张**：仅评估对孤立请求的最终响应，会遗漏决定安全性所需的**所有权、来源、持久性和预期受众**信息。任务效用并不蕴含隐私或授权合规。

## 2. 方法论：核心思想与关键技术

### 2.1 核心思想
- CoSec 是一个**可执行基准**，用于评估在社区内部及跨社区运行的完整 LLM 智能体系统的隐私与授权执行情况。
- 它运行完整的命令行智能体系统（OpenClaw、Hermes、Codex），每个系统使用其**原生会话、记忆、文件操作、工具和工作区效果**，而非仅测试骨干模型。
- 每次试验将目标智能体置于受控的参与者与社区上下文中，测试完整系统是否遵守由数据所有权、来源和社区范围决定的边界。

### 2.2 社区安全模型
- 将社区建模为持久协作范围，包含用户、智能体身份、社区数据、交互历史、工具和访问规则。
- 目标智能体代表一个用户行动，同时与其他参与者交互，其数据和权限可能不同。
- 社区会话和可见历史按场景、目标智能体和社区进行范围限定；智能体还保留持久记忆和对共享工作区的访问，其中社区和私有产物占据不同的逻辑命名空间。
- **授权状态表示**：$E_t = (U, C, G_t, M_t, R_t, D, P_t, A, H_t)$，其中 $U$、$C$ 为用户和社区，$G_t$、$M_t$、$R_t$ 编码社区间关系、成员关系和角色，$D$ 为数据对象集合，$P_t$ 为适用策略，$A$ 和 $H_t$ 为智能体接口和可见历史。
- **授权预言机**（对智能体隐藏）：$Auth_t(u, a, d, \ell) = \mathbb{1}[P_t(u, a, d, \ell, G_t, M_t, R_t, o(d), c(d)) = \text{allow}]$，其中 $o(d)$ 和 $c(d)$ 为对象所有者与来源社区。
- **关键原则**：扩大协作的变化本身并不授权披露先前受保护的信息。

### 2.3 威胁模型
- 对手控制指定的请求者消息，以及取决于攻击家族的选定文档、元数据、记忆条目或工作流输入。
- 对手**不能**修改授权预言机或隔离运行时。
- 评估的是**语义信息边界的行为执行**：受保护信息可能在技术上可被智能体触及，但对特定行动或目的地未被授权。

### 2.4 四类攻击压力源
- **A1 用户注入**：通过请求者消息直接施压（虚假授权、冒充、紧迫性、安全摘要请求）。
- **A2 间接注入**：在文档、引用消息、元数据或工具观察中嵌入未授权指令。
- **A3 记忆投毒**：在持久上下文中放置虚假、过时或过宽的授权声明。
- **A4 能力组合**：将单独看似合理的文件、工具或工作流操作组合成未授权信息流。

### 2.5 评估指标
- **PVR（隐私违规率）**：受保护内容通过智能体生成的输出被披露的比例。
- **CCPVR（跨社区隐私违规率）**：社区间未授权信息流的比例。
- **BCR（良性完成率）**：独立于安全性的任务完成率。
- **STCR（安全任务完成率）**：同时要求无已验证安全故障的任务完成率。
- 验证流程：确定性提取器 + LLM 评判器，每个记分卡保留决策与支持证据。

## 6. 主要结论与发现

- **任务效用与隐私保护的巨大鸿沟**：13 种配置中 12 种 BCR 超过 85%（唯一例外为 Hermes + Qwen 3.8 Max 的 78.85%），但整体 PVR 从 29.33%（OpenClaw + Gemini 3.1 Pro）到 96.15%（Hermes + DeepSeek 4.1 Flash）不等。Code

Codex 配 GPT 5.6 Sol 的表现介于两者之间，说明隐私违规并非单一模型能力问题，而是与运行框架和系统配置强相关。

- **跨社区泄漏比社区内泄漏更严重**：CCPVR 普遍高于同套件内的社区内 PVR，表明当信息需要跨越社区边界时，智能体更容易把"当前会话可见"误当作"当前行动被授权"。这一结果直接支持论文的核心论点——最终响应正确并不蕴含信息流合规。
- **攻击家族难度分层明显**：直接的 A1 用户注入相对容易被拒绝，而 A3 记忆投毒与 A4 能力组合构成主要失败来源。前者通过把虚假或过宽的授权声明写入持久上下文，使后续看似正常的请求获得"合法外观"；后者则不依赖任何单一恶意指令，而是把多个各自合理的文件读取、工具调用与转发操作串联成未授权信息流，因此难以通过关键词或意图过滤拦截。
- **动态社区状态是薄弱环节**：在 Dyn96 中，成员加入/移除与角色升级/降级后，智能体往往仍按历史会话中形成的权限印象行事；社区合并/拆分与关系开始/结束则带来范围判定错误。论文对 795 个动态安全故障的分类显示，失败主要集中在"沿用过期授权"、"混淆对象所有者"和"未重新校验接收者"三类模式上，而非模型完全无视安全指令。
- **框架效应显著**：在 5 个共享骨干模型上，Hermes 与 OpenClaw 的 PVR 存在系统性差异；GPT 5.6 Sol 在 Hermes 与 Codex 上的表现也不同。由于两者接收相同的参与者轮次、工作区种子和社区状态，差异只能归因于会话管理、记忆写入策略、工具暴露方式与上下文组织方式，即**安全是完整智能体系统的属性，而非模型权重单独决定的属性**。
- **单轮安全指令收益有限**：防护栏实验显示，首轮附加统一安全指令能够降低 PVR，但降幅有限且伴随 BCR 下降，说明"提示层对齐"无法替代运行时的权限校验与信息流控制；对 A4 类组合攻击的抑制尤其不明显。

## 7. 结论与启示

- **核心结论**：当前完整的 LLM 智能体系统普遍具备高任务效用，却缺乏与之匹配的隐私与授权执行能力；把智能体从单用户助手扩展为社区成员，会在不改变任何单条指令合法性的情况下，制造新的跨主体、跨上下文信息流风险。
- **方法论启示**：
  - 安全评估必须覆盖**完整系统**（会话、记忆、文件、工具、工作区），仅评测骨干模型或单轮响应会系统性高估安全性。
  - 评估需要引入**隐藏的授权预言机**，将"技术上可访问"与"对特定行动和接收者被授权"区分开。
  - 动态社区事件应作为一等评测维度，权限撤销与角色变更后的行为才是真实部署中的高风险区。
- **工程启示**：持久记忆需要携带来源与授权元数据，并在每次对外行动前重新校验；工具调用应受目的与接收者约束，而不仅是资源可读性约束。

## 8. 客观评述

- **主要贡献**：首次把社区、多参与者、持久状态与动态权限变化整合进可执行的安全基准；威胁模型与四类攻击压力源划分清晰；验证器经 192 例人工审计，组合方案召回率 100%、FNR 0.0%，且明确标注确定性验证偏保守（精确率 100%、召回率仅 33.3%），报告方式诚实。
- **可信度优点**：场景预先冻结、不针对被评估系统调整；参与者消息为冻结种子，避免请求者模拟器偏差；多框架、多模型、多套件的交叉设计使结论具备一定泛化性。
- **局限**：
  - 场景为合成构造，社区规模与交互复杂度低于真实在线社区；
  - Dyn96 每种攻击家族仅用一种对齐策略，动态维度的覆盖不如静态套件充分；
  - 主评估未启用可选攻击者模拟器，攻击强度可能被低估；
  - 试验限于 8 轮脚本化交互，长期记忆演化与多轮渐进式渗透未被充分刻画；
  - 论文未报告等效算力总量，成本分析仅覆盖 API 开销与墙钟时间，复现时需自行估算资源。
- **总体判断**：CoSec 的结论是"任务效用高、授权执行弱"这一差距在完整智能体系统中稳定存在，且不能通过单轮安全提示消除。其价值主要在于把隐私与授权从模型行为问题重新定义为**系统级信息流治理问题**，并提供了可复用的评测装置与失效模式分类。
