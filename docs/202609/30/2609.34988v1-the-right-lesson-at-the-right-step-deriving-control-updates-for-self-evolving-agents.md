## 摘要
自演化智能体通过复用过往经验来改进未来行为，这些经验通常以全局提示、记忆或反思的形式存在。然而，这些机制很少控制经验在何处生效。在长流程的工具使用工作流中，同一条经验可能纠正某个决策，却干扰另一个决策，这使经验复用成为一个局部化控制的问题，而不仅仅是记忆问题。我们提出 EvoCUE（Evolution through Control Updates from Evidence，基于证据的控制更新实现演化），一个从已完成的智能体执行中学习可复用控制程序更新的框架。EvoCUE 将智能体表示为一个显式的状态机控制器，其节点执行模型调用或工具调用，其边定义控制权接下来传递的位置。这使工作流可在精确位置被编辑，因此每个学到的更新都能指定添加什么、在何处起作用以及何时适用。基于已完成的轨迹，EvoCUE 利用残余目标与观测到的执行轨迹，提出局部化的指令或技能编辑。每个候选编辑都在其将起作用的位置被评估：从同一检查点恢复父控制器与编辑后的控制器，并比较它们的最终结果。被接受的编辑会与适用性规则一同编译，在留出任务上得到确认，并被后续执行所继承。我们在长流程工具使用环境中评估 EvoCUE，这些环境中习得的约定必须抵达正确的执行步骤。从一个不含基准特定引导指令的最小 AppWorld 控制器出发，EvoCUE 学到了缺失的任务完成约定，并在 Test-Normal 与 Test-Challenge 上显著提升成功率。在 PAST-Bench 办公工作流上，EvoCUE 将组织要求从先前回合迁移到后续任务，提升了任务执行质量。这些结果表明，自演化智能体应将经验置于控制流之内，而非仅将其存储为文本。

## Abstract
Self-evolving agents improve future behavior by reusing past experience, typically as global prompts, memories, or reflections. Yet these mechanisms rarely control where experience takes effect. In long tool-use workflows, the same lesson may correct one decision but distract another, making experience reuse a problem of localized control rather than memory alone. We introduce EvoCUE (Evolution through Control Updates from Evidence), a framework for learning reusable control-program updates from completed agent executions. EvoCUE represents the agent as an explicit state-machine controller, whose nodes perform model or tool calls and whose edges define where control passes next. This makes the workflow editable at precise locations, so each learned update can specify what to add, where it acts, and when it applies. From completed trajectories, EvoCUE uses residual goals and observed execution traces to propose localized instruction or skill edits. Each candidate is evaluated at the point where it would act by resuming the parent and edited controllers from the same checkpoint and comparing their final outcomes. Accepted edits are compiled with applicability rules, confirmed on held-out tasks, and inherited by later executions. We evaluate EvoCUE on long tool-use environments where learned conventions must reach the right execution step. From a minimal AppWorld controller without benchmark-specific onboarding instructions, EvoCUE learns the missing task-completion convention and substantially improves success on Test-Normal and Test-Challenge. On PAST-Bench office workflows, EvoCUE transfers organizational requirements from prior episodes to later tasks, improving task-execution quality. These results show that self-evolving agents should place experience inside the control flow, rather than only store it as text.

## 1. 核心问题与整体含义

- **背景**：自演化智能体（self-evolving agents）在模型与工具固定的前提下，通过复用过往经验（全局提示、记忆、反思、技能库）改进未来行为。Reflexion、ExpeL、AWM、ACE、Dynamic Cheatsheet、Voyager、ReasoningBank 等均属此列。
- **被忽视的维度**：这些方法主要解决"存什么"，而"经验在何处生效"通常由设计固定（系统提示或某个检索步骤）。作者主张，在长流程工具使用任务中，经验复用本质上是一个**局部化控制（localized control）问题**，而非单纯的记忆问题。
- **动机实例**：机票预订助手完成了所有请求操作，但因未获批准就支付超 1000 美元机票导致报销被拒。"支付前先获批"这条教训只有抵达支付决策点才有用；若只在下一趟行程开头展示，可能完全不影响后面的支付步骤。
- **量化证据**：在 AppWorld 上，同一条关于任务完成约定的指令放在第一步只解 5/16 个开发任务，放在后续步骤则解 14/16。
- **第二个难点——如何度量编辑是否有效**：局部编辑会影响后续大量动作，而反馈只在任务末尾出现；从任务开头重跑会把编辑效应与编辑前执行的无关变异混在一起。
- **整体含义**：自演化需要同时学习"保留什么"和"它在控制流的哪里起作用"；经验应嵌入控制流内部，而非仅作为文本存储。

## 2. 方法论：EvoCUE

### 核心思想
把智能体表示为一个**显式状态机控制器**，使工作流可在精确位置被编辑，从而让每条学到的更新都明确"加什么、在哪里生效、何时适用"。

### 关键组成
- **控制器定义**：`C = (G, π, Ω)`
  - `G`：图，节点调用模型或工具，边传递控制并可携带指令（目标节点经该边被进入时收到）。
  - `π`：路由策略，从可观测执行状态选择下一条边。
  - `Ω`：可执行技能库，类似强化学习中的 option，有启动条件、把多步操作作为一步执行、返回成功/失败。
- **位置的关键性**：同一节点可从不同入口进入（如 AppWorld 的 `prepare` 节点：从 `start` 进入一次，从 `route` 重复进入）。挂在"首次进入"的指令只见一次，挂在"重复进入"的指令每一步都见到。**边既固定了教训生效的位置，也固定了测试的起点。**
- **残余目标（residual goals）**：由语言模型从公开指令与轨迹中估计出"尚未被公开历史证明满足"的任务要求，并标注支持证据。当所有要求都显示已观测但得分为 0 时，失败位于"如何完成任务"环节。
- **初始控制器 C₀**：不修改模型、工具、观测接口；AppWorld 中为 6 节点控制器，只有通用编码指导与一句完成提示，缺少官方 onboarding 指令。

### 编辑提案
- 候选编辑 `δ` 指定：**内容 + 位置（边）+ 作用域（当前调用/技能调用/下一动作）+ 预期效果**。
- 两类编辑：
  - **指令编辑**：在某条边上向节点追加文本。
  - **结构编辑**：在边上插入 1–6 个原语的技能，含前向分支与显式成功/失败返回。
- 提案前有合法性检查：只用已有节点、尊重待执行动作的草稿状态、算子输入有效；并向提案者反馈"每个算子读写什么、附件能到达哪些入口"。

### 成对试验（Paired Trial）—— 在生效点测试
- 从检查点 `j`（编辑生效前）恢复环境状态、公开历史、控制器状态与剩余预算，分别把**父程序 C** 与**编辑后程序 C⊕δ** 跑到任务结束。
- 效应定义：
  `d_tj(δ; C) = Y_tj(C⊕δ) − Y_tj(C)`
  其中 `Y` 为最终任务得分。由于两次执行共享前缀，比较排除了编辑生效之前的一切变异。
- 试验记录包含：类型、双方得分、编辑生效前状态特征、编辑是否被抵达/应用、观测到的动作变化；区分"未抵达、被跳过、尝试失败、已应用、执行未解决"，并把"缺失分数"与"零分"分开。
- 若从任务开头而非检查点运行，则记为 task-start trial，单独保存且不带检查点特征。

### 适用性规则
- 在编辑生效前的**分类状态特征**（执行阶段、草稿有效性、残余目标状态、进度、重复、可见完成证据等）上枚举最多两个等值测试组成的规则。
- 选择目标：`q̂_δ ∈ argmax_q [ p̂_Sδ(q)·d_δ,q − λ|q| ]`，其中 `p̂` 为规则覆盖的采样任务比例，`d` 为平均效应，`|q|` 为等值测试数，并列时偏好更短规则；`λ = 10⁻³`。
- 通过条件：至少覆盖 2 个任务、`d_δ,q̂ > 0`、且 `p̂·d − λ(|q̂|+|δ|) > 0`（`|δ|` 计编辑操作数，仅出现在通过条件中）。
- 空规则 = 只要抵达位置就应用；task-start 证据只能支持空规则。
- 该设计借鉴"估计干预效应随干预前状态如何变化"的思路（Athey & Imbens, 2016）；因试验少时规则估计偏乐观，故必须经独立确认。

### 编译、确认与继承
- 通过的指令被编译为指定边上的条件调用（仅当规则成立时运行）；通过的技能被编译为内部节点、启动条件与显式返回。同一位置的后续修订替换早先版本；合并两条指令需作为新候选重新提案。
- 候选更新编译为 `C′`，在与本轮提案/试验任务**不相交**的确认批次上，从任务起点比较 `C` 与 `C′`；满足预设接受准则（AppWorld：确认任务平均成对增益为正；PAST：平均增益为正 + 至少 2 个任务改善 + 去掉最大改善后总增益非负）才被继承。
- **试验记忆**：接受与拒绝的试验都长期保留，供后续提案修订内容或位置、避免重走失败方向。

### 算法流程（Algorithm 1，一轮学习）
选任务与不相交确认集 → 索引公开轨迹/残余目标/历史试验 → 提案带内容、位置、作用域、证据的编辑 → 对每个候选采样检查点跑成对试验并记录 → 拟合适用性规则 → 编译 → 在确认集上从任务起点比较 → 满足准则则继承。

## 3. 实验设计

### 数据集与场景
- **AppWorld**（主基准）：9 个模拟 app、457 个 API 的多步交互编码任务；90 训练 / 57 开发 / 168 Test-Normal / 417 Test-Challenge；官方 checker 判定，场景需全部子任务成功才算成功。学习只用 32 任务训练子集，成对试验的检查点恢复也只在训练任务上。
