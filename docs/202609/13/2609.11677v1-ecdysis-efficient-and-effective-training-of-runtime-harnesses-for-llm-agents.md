## 摘要
自演化的运行时框架能够显著提升大语言模型（LLM）智能体的能力，并为优化智能体执行提供了一种有前景的范式。现有的框架演化方法通常依赖迭代搜索，基于任务实例的执行反馈反复评估和修改候选框架。尽管这一范式能够持续优化框架，但由于重复的智能体执行和代码修改，会带来大量时间开销，并可能对已观测任务和特定失败模式过拟合，导致对未见任务的泛化能力下降。我们将缺乏有原则的失败诊断视为框架演化的关键瓶颈：观测到的失败可能反映模型特有的缺陷，也可能反映系统性的框架缺陷，而直接针对单个失败进行优化可能导致不必要的模型特化适配。因此，我们提出 Ecdysis，一个高效且有效的框架，它区分模型特化适配与框架层面的修复，并通过识别重复出现的跨任务失败模式，将适配偏向系统性的框架缺陷。Ecdysis 采用批次级跨实例失败聚合范式，联合分析来自多个任务实例的失败证据，并进一步引入失败驱动的协同精炼（Failure-Driven Collaborative Refinement），以诊断失败原因并迭代细化框架修改规格。通过结合跨实例失败分析与多角色诊断，Ecdysis 能够以更低的训练时间实现更有效的框架演化。实验表明，与现有框架演化方法相比，Ecdysis 在框架训练中最高可实现 1.84 倍加速，同时使所得框架的推理准确率提升 18.56%。

## Abstract
Self-evolving runtime harnesses can substantially improve the capabilities of large language model (LLM) agents and provide a promising paradigm for optimizing agent execution. Existing harness evolution methods typically rely on iterative search, repeatedly evaluating and revising candidate harnesses based on execution feedback from task instances. While this paradigm enables continuous harness optimization, it incurs substantial time overhead due to repeated agent executions and code modifications, and may overfit to observed tasks and specific failure patterns, resulting in degraded generalization to unseen tasks. We identify the lack of principled failure diagnosis as a key bottleneck in harness evolution: an observed failure can reflect either model-specific deficiencies or systematic harness deficiencies, and directly optimizing against individual failures can lead to unnecessary model-specific accommodation. We therefore propose Ecdysis, an efficient and effective framework that distinguishes model-specific accommodation from harness-level repair and biases adaptation toward systematic harness deficiencies by identifying recurring cross-task failure patterns. Ecdysis adopts a batch-level cross-instance failure aggregation paradigm to jointly analyze failure evidence from multiple task instances and further introduces Failure-Driven Collaborative Refinement to diagnose failure causes and iteratively refine harness modification specifications. By combining cross-instance failure analysis with multi-role diagnosis, Ecdysis enables more effective harness evolution with lower training time. Experiments show that Ecdysis achieves up to a 1.84x speedup in harness training compared with existing harness evolution methods, while improving the reasoning accuracy of the resulting harnesses by 18.56%.

  - **效率问题**：每次 harness 更新都需要额外的智能体执行、代码修改与结果验证，训练时间与 API 成本高企。
  - **泛化问题**：演化过程会逐渐特化于已观测任务与特定失败模式，导致"演化漂移"，对未见任务泛化下降。
- **核心洞察（关键瓶颈）**：论文指出真正瓶颈是**缺乏有原则的失败诊断（principled failure diagnosis）**。同一个观测失败可能来自：
  - **模型特异缺陷** → 需要"模型特化适配"（model-specific accommodation）；
  - **系统性框架缺陷** → 需要"框架层面修复"（harness-level repair）。
- **概念分解**：作者把一轮演化产生的聚合更新分解为
  - ΔH = t·ΔH_model + (1−t)·ΔH_harness，t ∈ [0,1]
  - 其中 t 既是"模型适配类决策占比"，也是整体更新中模型适配分量的权重。t 越大越能快速消除当前失败，但越容易过拟合当前模型与训练任务。
- **研究问题**：跨任务实例的失败证据，能否区分模型特化适配与系统性框架修复，从而引导更可泛化的 harness 演化？

## 2. 方法论

### 2.1 核心思想

- 提出 **Ecdysis** 框架，包含两大组件：
  1. **批次级跨实例失败聚合（Batch-Level Failure Aggregation）**：把一轮内多个任务实例的失败证据联合分析，而非把每个失败当作独立修改信号。
  2. **失败驱动的协同精炼（Failure-Driven Collaborative Refinement, FDCR）**：用多角色诊断将聚合失败证据转化为结构化的 harness 修改规格。
- **职责分离**：FDCR 负责"诊断 + 规划修改规格"，编码智能体（coding agent）负责"实际改代码"，二者解耦。
- **归纳偏置而非因果证明**：论文明确说明，跨任务复现性被用作**归纳偏置**，而非失败归因的严格证明。

### 2.2 算法流程（Algorithm 1）

- **输入**：固定的任务模型 θ、运行时环境 E、训练任务集 D_train、初始 harness H_base、失败阈值 λ、演化轮数 R、精炼轮数 K。
- **输出**：冻结的最终 harness H_F。
- **主循环（i = 1…R）**：
  1. **执行**：用当前 harness H_{i−1} 在 D_train 上执行任务，收集执行轨迹 T_i。
  2. **失败判定**：对每条轨迹 τ 计算任务分数 S(τ)，二值失败信号为
     - **f_λ(τ) = I[S(τ) < λ]**，即分数低于阈值即判为失败。
  3. **聚合**：把失败轨迹转为结构化记录（含任务 ID、失败判定、终止原因、工具调用历史、执行上下文），构成失败证据集 B_i；若 B_i 为空则保持 H_i = H_{i−1} 并跳过本轮。
  4. **分组**：将 B_i 组织为失败模式组 G_i；**优先处理覆盖 ≥2 个不同任务的分组**，仅含单一任务的分组作为辅助证据保留。失败组是"诊断证据"而非"必须修复的目标"。
  5. **FDCR**：角色集 A = {Analyst, Critic, Engineer}，执行 K 轮迭代，每轮各角色读取当前失败组 G_i 与共享记录 M_i，顺序执行并追加输出，形成累积转录。
  6. **仲裁**：Moderator 读取失败证据与完整转录，输出结构化修改规格 q_i。
  7. **实现**：编码智能体依据 q_i、相关执行证据与当前 harness 源码，修改 H_{i−1} 得到候选 H^c_i。
  8. **验证与接受**：仅当 **J_train(H^c_i) > J_train(H_{i−1})** 时接受候选，否则回滚：
     - H_i = H^c_i（若改进），否则 H_i = H_{i−1}。
     - 注意：该准则只约束**训练集整体分数**，不要求每个训练任务都改善。
- **终止**：R 轮后冻结 H_F = H_R。
- **全程固定**：任务模型参数 θ 与运行时环境 E 在训练期间保持不变，只更新 harness。

### 2.3 FDCR 的角色分工

- **Analyst**：识别潜在 harness 缺陷，提出最小化、有针对性的更新建议。
- **Critic**：对照失败证据评估建议，检查风险——触发条件过宽、误封合法行为、违反运行时契约、对已成功任务的回退。
- **Engineer**：追踪共识与未决分歧，标出需在后续精炼中澄清的问题。
- **Moderator**：保守仲裁，整合建议、消解分歧，优先处理**跨任务复现的失败模式**，避免不必要改动。
- 关键效果：把修改偏向"可复用的行为改进"（如状态更新后重新查询状态、副作用操作前消解歧义实体、调用下游工具前校验依赖信息），而非任务特定答案。

### 2.4 效率来源（调用次数不等式）

- 设第 i 轮失败记录数为 n_i，串行方法需 n_i 次编码智能体调用；Ecdysis 每轮非空时只调用一次：
  - **N_round = Σ_{i=1}^{R} I(n_i > 0) ≤ Σ_{i=1}^{R} n_i = N_serial**
  - 只要某轮含多条失败记录，不等式严格成立。
- 概念上，Ecdysis 的目标是把模型适配分量从 t 衰减为 **t′ = β·t，β ∈ (0,1)**。

- **Harness 基础框架**：Life-Harness（成熟且结构良好的 harness 框架）。
- **五种配置对比**：
  1. **Direct**：仅保留 τ²-Bench 所需的基础 agent loop、消息处理与工具接口，关闭所有 harness 层（最小基线）。
  2. **Human-Aug.**：人工优化后的固定 harness，不演化（强基线，且作为三种演化方法的**共同初始 harness**）。
  3. **Self-Evolution (SE)**：实例级串行更新，每个失败记录独立调用编码智能体，修改顺序累加为轮级候选。
  4. **Ecdysis (w/o FDCR)**：轮级聚合失败证据，构造单一修改计划并调用一次编码智能体。
