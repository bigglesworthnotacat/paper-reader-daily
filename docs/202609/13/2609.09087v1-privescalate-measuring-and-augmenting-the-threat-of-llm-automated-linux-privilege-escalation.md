## 摘要
随着大型语言模型（LLM）智能体日益自动化网络杀伤链中的攻击性操作，其在复杂本地后渗透任务中的效能仍未被充分量化。其中，Linux 权限提升是初始访问与完全系统失陷之间的关键步骤。然而，针对该任务的现有评估受限于样本规模小（少于 15 个场景），缺乏在可执行验证下比较模型能力的规模。为解决这一问题，我们提出 PrivEscalate，一个面向 Linux 权限提升的大规模基准，包含 531 个 Docker 化场景，涵盖 14 个子类别。我们还额外推导出 329 个参数化变体，以测量对环境干扰项的敏感性。在三种智能体架构下评估六个 LLM 揭示出：（i）模型能力在不同漏洞类别间具有异质性，没有任何单一模型在高发类别上占据主导，这促使进行多维风险评估；（ii）LLM 的成功对环境扰动敏感，因此配置轮换可以干扰某些利用尝试，但并不能消除所测量的风险；以及（iii）智能体架构能够实质性改变成功率并重新排列模型排名，尽管其幅度依赖于具体模型。利用这些见解，我们开发了 PrivEscAgent，一个领域专用封装器，通过确定性枚举、类别匹配和步骤规划来增强通用 ReAct 智能体。PrivEscAgent 在无需修改底层 LLM 的情况下，优于先前的 Linux 权限提升智能体基线。我们将 PrivEscalate 作为开源、Docker 化的测量工具发布，支持 LLM 智能体评估、防御工具验证和红队训练。

## Abstract
As Large Language Model (LLM) agents increasingly automate offensive operations across the cyber kill chain, their efficacy in complex local post-exploitation tasks remains inadequately quantified. Among these, Linux privilege escalation is a key step between initial access and full system compromise. However, existing evaluations for this task are limited by small sample sizes (fewer than 15 scenarios), lacking the scale to compare model capabilities under executable verification. To address this, we present PrivEscalate, a large-scale benchmark for Linux privilege escalation, comprising 531 Dockerized scenarios spanning 14 sub-categories. We additionally derive 329 parameterized variants to measure sensitivity to environmental distractors.   Evaluating six LLMs across three agent architectures reveals: (i) model capability is heterogeneous across vulnerability classes, with no single model dominating across the high-prevalence classes, motivating multi-dimensional risk assessments; (ii) LLM successes are sensitive to environmental perturbation, so configuration rotation can disrupt some exploit attempts but does not eliminate the measured risk; and (iii) agent architectures can materially change success rates and reorder model rankings, though the magnitude is model-dependent. Leveraging these insights, we develop PrivEscAgent, a domain-specialized wrapper that augments a generic ReAct agent with deterministic enumeration, category matching, and step planning. PrivEscAgent improves over prior Linux privilege-escalation agent baselines without underlying LLM modifications. We release PrivEscalate as an open-source, Dockerized measurement instrument supporting LLM agent evaluation, defensive tool validation, and red-team training.

## 2. 方法论：核心思想与关键技术细节

### 2.1 PrivEscalate 基准构建

- **分类法（Taxonomy）**：基于 MITRE ATT&CK 经四步流程构建——① 枚举 Linux 相关技术/子技术；② 过滤 Docker 不可复现项；③ 用 GTFOBins 与 Exploit-DB 交叉验证；④ 连续性检查（确保兼容 hackingBuddyGPT）。最终形成 **14 个子类别、5 个大类**：
  - 配置错误（Misconfig.）：SUID/SGID、Sudo、Capabilities、Polkit、D-Bus、弱文件权限
  - 环境（Environ.）：PATH 劫持、LD_PRELOAD 劫持
  - 计划任务（Sched.）：Cron、Systemd
  - 凭据（Cred.）：密码泄露、SSH 密钥注入、DB 凭据提权
  - 容器（Cont.）：Docker/容器逃逸

- **自动化多智能体构建流水线**（以 Claude Opus 4.6 为后端 LLM）：
  - **DataIngester**：将 GTFOBins / Exploit-DB 的自由文本条目转换为统一的 `ScenarioSpec` 模板；含可行性分类器与 LLM 解析器；并实现"参考反馈循环"与"全覆盖发现"。
  - **Scaffolder**：生成一对仅在漏洞注入与否上不同的 Dockerfile（vulnerable / fixed），先做基础加固以确保注入漏洞是唯一提权路径，再由 LLM 生成并解决依赖。
  - **Exploiter**：按确定性规则在三种模式（检索 Retrieval / 适配 Adaptation / 生成 Generation）下产出 ground-truth 利用脚本。
  - **Verifier + Manager 反馈环**：三重验证——① 构建检查；② 利用差分检查（vulnerable 提权成功、fixed 失败）；③ 一致性检查（枚举探测排除非预期路径）。失败时由 Manager 调度定向修复，重试上限 3 次。

- **参数化变体（329 个）**：沿五个变换轴扰动环境但保留漏洞机制：
  - ① 凭据（用户名/密码/root 密码）；② 系统身份（hostname）；③ 枚举噪声（3 个非可利用 SUID、2 个诱饵账户、2 个无害 cron，最具区分度）；④ 上下文噪声（MOTD、误导性 shell 历史）；⑤ 环境指纹（预装额外网络/文件检查工具）。

### 2.2 PrivEscAgent（领域专用增强智能体）

- **设计思想**：作为通用 ReAct 智能体的轻量封装，针对四大瓶颈（盲目枚举、领域知识缺失、多步分解失败、策略固着）各设一个模块。
- **四个模块**：
  - **PrivEnum**：无 LLM 的确定性枚举脚本，单次往返收集分类法对齐的提权证据。
  - **CategoryMatcher**：两层分类，规则知识库精确匹配 + LLM 回退，输出排序后的候选策略。
  - **StepPlanner**：仅在多步利用时激活，将利用分解为可验证步骤（定位目标→注入载荷→等待触发→验证 root），失败可回滚。
  - **StrategySelector**：按置信度 × 各类别 SR 先验排序候选策略，执行失败自动转向下一候选而无需重启。
- **运行方式**：四模块作为预处理流水线，产出的利用计划交由 wintermute 的 ReAct 循环执行；**不修改底层 LLM**。

## 6. 主要结论与发现

- **Finding 1**：多模型并集（329/531 = 62.0%）显著高于最佳单模型（GPT-5.4 的 40.9%），单模型评估会低估实际暴露面。
- **Finding 2**：失败中"方法选择错误"（Wrong-method，81.6%）远多于"未尝试利用"（No-attempt，14.1%），说明瓶颈在于领域知识而非漏洞识别。
- **Finding 3**：失败运行的命令预算被重复枚举主导（枚举命令占比 57.8%）。
- **Finding 4**：多数模型失败后固着于同一策略类别（4/6 模型固着率 81–99%），需要自动转向机制。
- **Finding 5**：环境扰动移除 21.8–41.0% 的既有成功；保留率从 59.0%（GPT-5.4）到 78.2%（Claude Haiku 4.5），配置轮换只能部分缓解、无法消除风险。
- **Finding 6**：智能体架构可实质性改变能力并**重排模型排名**（HackSynth 下 Claude Sonnet 4.6 的 66.5% 反超 GPT-5.4 的 47.3%），且效果依赖模型。
- **Finding 7**：成功运行通常很短（Claude Haiku 4.5 平均 7.3 步，29.4% 在 ≤3 步完成），压缩了运行时检测窗口。
- **Finding 8**：每成功 token 成本强依赖智能体架构，而非仅取决于底层模型。
- **Finding 9**：策略提示的使用依赖模型；更强遵循可保留验证策略，但过度僵化可能限制适应性。
- **核心结论**：自动化提权威胁由**模型、环境、智能体架构**三者共同塑造，而非单纯由原始模型能力决定；PrivEscAgent 在全部 6 个模型上超越两个基线，最大提升 +34.3 pp（Claude Sonnet 4.6），并将最弱模型（Qwen-Plus，10.2% → 39.5%）提升至最强 wintermute 基线水平。

## 7. 优点

- **规模与可复现性**：531 个 Docker 化场景 + 329 变体，远超此前 13 场景的规模；全流程开源（GitHub: yxsec/PrivEscalate），Docker 化保证可复现。
- **可执行验证**：三重验证（构建、利用差分、一致性检查）结合基础加固，确保注入漏洞是唯一提权路径，方法严谨。
- **细粒度分类**：14 个子类别映射 ATT&CK，支持按类别分离常见趋势与类别特异行为。
- **扰动敏感性测量**：参数化变体设计沿五个轴系统扰动，并引入"保留率"作为主要扰动指标，弥补了既有基准的空白。
- **多维度评估**：同时考察模型、架构、成本、步骤效率、失败模式、策略固着，并辅以 McNemar 统计检验。
- **务实的增强方案**：PrivEscAgent 不修改底层 LLM，仅通过确定性枚举 + 类别匹配 + 步骤规划即显著提升，且降低每成功成本。
- **防御可操作性**：给出配置加固、行为检测、架构控制、运维扫描四层防御建议，并映射到测量发现。
- **伦理考量完善**：所有场景基于公开知识、无零日披露、容器隔离无外网、遵循负责任发布。

## 8. 不足与局限

- **分类覆盖的固有排除**：仍排除内核漏洞、NFS root squashing、服务特定 CVE、进程注入、启动/登录触发等子技术（部分因 Docker 单容器限制）；弱文件权限仅由 2 个专家场景代表。
- **类别分布不均衡**：Sudo（55%）与 SUID/SGID（38%）主导，多个子类别仅 1 个场景，类别级结论统计效力弱，聚合结果主要反映公开可复现材料。
- **运行次数有限**：多数元组仅评估一次，未做多次重复；仅 wintermute 做了单次可重复性检查，运行间方差未被充分刻画。
- **变体相关性**：同一模板内的变体固有相关，原语料 SR 与扰动保留率需分开解读。
- **步数上限约束**：20 步上限沿用前人工作以保可比性，但可能高估简单场景、低估长链场景。
- **智能体框架覆盖有限**：仅评估 3 种代表性架构，控制循环不透明或不可配置的框架未纳入；StrategySelector 使用从早期测量得到的类别先验，存在潜在循环依赖（消融中已部分处理）。
- **未说明算力细节**：论文未给出 GPU 型号/数量/训练时长，仅提供 API 成本，且成本基于官方定价估算，可能随价格变动。
- **人类对比缺失**：研究定位为 LLM 智能体间的相对比较，未与人类渗透测试者对比。
- **双重用途风险**：公开利用成功率与智能体架构可能被攻击方利用（作者已声明遵循负责任发布并映射防御方向）。
