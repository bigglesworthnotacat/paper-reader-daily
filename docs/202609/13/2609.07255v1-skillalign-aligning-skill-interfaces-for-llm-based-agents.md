## 摘要
语言模型智能体日益依赖技能：用于推理、工具使用和交互的可复用过程性知识。现有研究考察了技能如何被获取、检索、压缩或组合，但往往假设一旦选定某个技能，其面向智能体的接口便是固定的。我们认为，这忽视了技能效用的一大关键来源：同一个技能可能因暴露方式不同而产生帮助、干扰或误导。我们提出 SkillAlign，一个与提供方无关的框架，它将候选技能表示为多视图过程卡片，并通过不同的暴露接口来呈现，包括完整指令、提示、压缩摘要、工作流或不暴露。这使得能够进行反事实评估：任务、智能体和候选技能保持不变，仅改变暴露接口。在 ALFWorld 和 SkillsBench 上，我们表明暴露形式会显著影响任务成功率和渲染上下文成本，并且紧凑的 top-k 暴露可以优于全库注入。我们进一步在 ALFWorld 上进行基于回放的策略学习分析，表明自适应暴露包含可学习信号，但仍远不及 oracle 选择。我们的结果表明，技能增强的智能体不仅应优化使用哪些技能，还应优化这些技能的呈现方式。

## Abstract
Language-model agents increasingly rely on skills: reusable procedural knowledge for reasoning, tool use, and interaction. Existing work studies how skills are acquired, retrieved, compressed, or composed, but often assumes that once a skill is selected, its interface to the agent is fixed. We argue that this overlooks a key source of skill utility: the same skill can help, distract, or mislead depending on how it is exposed. We propose SkillAlign, a provider-agnostic framework that represents candidate skills as multi-view procedural cards and renders them through alternative exposure interfaces, including full instructions, hints, compressed summaries, workflows, or no exposure. This enables counterfactual evaluation where the task, agent, and candidate skills are fixed while only the exposure interface varies. Across ALFWorld and SkillsBench, we show that exposure form substantially affects task success and rendered context cost, and that compact top-k exposure can outperform full-library injection. We further conduct a replay-based policy-learning analysis on ALFWorld, showing that adaptive exposure contains learnable signal but remains far from oracle selection. Our results suggest that skill-augmented agents should optimize not only which skills to use, but also how those skills are presented.

# SkillAlign 论文总结

## 1. 核心问题与研究动机

- **背景**：LLM 智能体日益依赖「技能」（skills）——可复用的过程性知识，用于推理、工具调用与交互。现有研究覆盖了技能的表示、获取、检索、压缩、组合与演化等完整生命周期。
- **被忽视的维度**：绝大多数工作默认「技能一旦被选中，其面向智能体的接口就是固定的」，即只优化"选哪些技能"，而忽略"技能如何被呈现"。
- **核心论点**：同一技能可能因暴露方式不同而产生**帮助、干扰或误导**三种截然不同的效果。技能应被视为「外化的过程性先验」，其效用不仅取决于内容，还取决于它用来条件化智能体的接口。
- **核心问题重构**：问题不只是"应该选择哪个技能"，而是"被选中的技能应该以什么形式暴露给智能体"。

## 2. 方法论：SkillAlign 框架

### 2.1 核心思想
- 将**技能选择（selection）**与**技能暴露（exposure）**解耦：上游提供方决定有哪些候选技能，SkillAlign 决定这些技能如何条件化智能体。
- 暴露本身被建模为一个可控决策变量，而非装饰性格式选择。

### 2.2 关键形式化
- 给定任务上下文 $x$、智能体上下文 $a$、候选技能集 $S_x = \{s_1,\dots,s_k\}$，选择暴露接口：
  $$m = \pi(x, a, S_x), \quad m \in \mathcal{M}$$
- 渲染为面向智能体的上下文：$r = \mathrm{Render}(S_x, m; x, a)$。渲染结果**不替换、不修改**原始技能工件。
- 主要接口集合：$\mathcal{M} = \{\texttt{none}, \texttt{full}, \texttt{hint}, \texttt{compressed}, \texttt{workflow}\}$。

### 2.3 多视图过程卡片
- 每个原始技能被表示为一个多视图卡片：$c(s) = \{v_{full}, v_{hint}, v_{comp}, v_{flow}, \eta\}$
  - `v_full`：原始技能全文（含脚本、参数、假设、边界情况，**非 LLM 生成摘要**）
  - `v_hint`：一句话动作提示，作为弱激活信号
  - `v_comp`：压缩的可操作性视图，涵盖触发条件、输入/状态、核心动作、期望输出、失配风险
  - `v_flow`：有序步骤 + 校验点 + 停止条件
  - `η`：元数据（skill id、来源、routing summary 等）
- 各视图在**语义角色**上不同，而不仅是长度不同。

### 2.4 反事实评估协议
- 固定策略 $\pi_m(x,a,S_x)=m$，对同一任务与候选集运行所有接口，得到 $\{\tau^m_x : m \in \mathcal{M}\}$。
- 由于任务、后端、候选技能全部固定，性能差异可归因于接口本身。
- **负迁移（negative transfer）**定义：无暴露成功但暴露 $m$ 失败，或标量奖励下降。

### 2.5 探索性暴露策略学习
- 效用函数：$U_x(m) = R_x(m) - \alpha C_x(m) - \beta T_x(m)$（奖励 − 归一化上下文成本 − 归一化轨迹长度）
- 最高效用接口作为 SFT 标签 $m^*_x = \arg\max_m U_x(m)$；效用差距足够的接口对作为 DPO 偏好样本。
- 在 Qwen3-4B 上训练轻量 LoRA 适配器，仅用于验证自适应暴露的可行性。

## 3. 实验设计

### 3.1 数据集与 Benchmark
| 基准 | 内容 | 规模 |
|---|---|---|
| **ALFWorld** | 纯文本具身家务环境（ReAct 风格） | 140 个评测回合，最多 30 步 |
| **SkillsBench** | 真实技术任务 + 人工整理技能（数据分析、科学计算、金融建模、工程流程） | 94 个容器化任务，Harbor + Terminus-2 执行框架 |
| **ScienceWorld** | 仅用于生成暴露策略的辅助反事实数据 | — |

### 3.2 技能库与候选来源
- 技能库：`skills_1000` 为主，扩展性分析用 `skills_200 / 500 / 1000 / 2000`。
- 候选来源（provider）：
  - `none`：无技能上下文（对照）
  - `all`：整库不加过滤地提供
  - `vector-top k`：语义检索（text-embedding-3-large），ALFWorld k=5，SkillsBench k=8
  - `Graph-top k`：结构化提供方 Graph-of-Skills（仅验证暴露效应是否在结构化选择下依然存在）

### 3.3 对比条件
- **5 种暴露接口**：`none` / `full` / `hint` / `compressed` / `workflow`
- **3 个智能体后端**：`minimax-m2.7`、`gpt-5.3-codex`、`glm-5`
- **指标**：成功率 SR（ALFWorld）/ 平均奖励 AR（SkillsBench），以及渲染技能上下文成本 $C$（千 token）

### 3.4 补充实验
- **人工保真度审计**：60 个随机任务（ALFWorld 30 + SkillsBench 30）× 3 种视图 = 180 个实例，2 位独立标注者，检查遗漏、扭曲、矛盾、误导性添加。
- **长度匹配的通用摘要对照**：在 Vector-top k 与 Graph-top k 下，用相同模型/解码参数、约等渲染长度对比 `Compressed` 与通用自由摘要，覆盖 12 个「基准–提供方–后端」组合。
- **任务级 bootstrap**（10,000 次重采样）报告 95% 置信区间。

## 4. 资源与算力

- 文中明确说明：LoRA 策略训练使用 **1 块 NVIDIA A100 GPU，总计约 50 GPU 小时**（含试错实验）。
- 策略模型为 **Qwen3-4B**，使用 LoRA；SFT 5 epoch、DPO 2 epoch，学习率分别为 2×10⁻⁴ / 5×10⁻⁶，DPO β=0.1，bfloat16，per-device batch size 1，梯度累积 16 步。

- **规模**：2 个主基准 × 4 类候选来源 × 5 种接口 × 3 个后端，加上 4 档技能库规模（200/500/1000/2000）、1 组人工审计、1 组长度匹配对照、1 组策略学习回放实验，总计数十个配置组合。

  - 反事实设计严格固定任务、后端与候选技能，仅改变接口，因果归因清晰。
  - 报告了任务级 bootstrap 95% 置信区间，并对紧密相邻的数值明确提示"不应过度解读"。
  - 用长度匹配摘要对照剥离了"单纯缩短上下文"这一混淆因素。
  - 用人工审计排除视图生成质量对结论的污染。
- **公平性/客观性**：同一配置下 Full / Generic Summary / Compressed 使用相同候选 skill id 与顺序、相同生成模型与解码设置，对照公平。
- **仍显不足**：
  - 策略学习仅做**离线回放（replay）**评估，未做在线交互验证，且训练数据来自 ScienceWorld，评测在 ALFWorld，跨域迁移的公平性存疑。
  - 置信区间普遍较宽且大量重叠，许多排名差异并不具统计显著性。
  - `All + Full` 的退化被作者自己承认为"诊断性压力条件"，未做上下文长度/相关性/顺序的独立控制实验。

## 6. 主要结论与发现

- **暴露形式是一等条件化变量**：在候选技能固定的情况下，仅改变接口即可带来显著性能差异（如 `all` 下 ALFWorld MiniMax 从 47.9 到 72.1，GLM 从 70.7 到 82.1）。
- **紧凑暴露往往更高效**：`hint` 与 `compressed` 以远低于 `full` 的成本（如 0.08K / 0.30K vs 4.7K tokens）取得更好或相当的效果。
- **候选质量与暴露形式互补**：检索减少无关技能质量，SkillAlign 控制剩余先验的呈现方式；`Vector-top k + Compressed` 在多个后端居首。
- **全库注入可能有害**：`All + Full` 在 skills_1000 下反而低于多个紧凑接口，作者归因于截断/拒绝、注意力稀释、无关先验与指令冲突的复合作用，但未做单因素解耦。
- **暴露效应在结构化提供方下依然存在**：Graph-top k 下 `Compressed` 通常最优，`Full` 更贵且并不稳定更好——更好的检索不能消除暴露问题。
- **库规模放大暴露问题**：库增大时 `full` 急剧退化（skills_1000 降至 47.9），`compressed` 更稳定（72.1）；skills_2000 因噪声与成本再次下降。
- **自适应暴露存在可学习信号但远未解决**：SFT 76.4、+DPO 78.6，对比 oracle 92.9（Vector-top k）；oracle 标签分布多样（none 8%、full 23%、hint 42%、compressed 26% 等），说明**没有单一接口普遍最优**。
- **视图生成保真度较高**：任务相关遗漏率仅 3.3%（Hint）、5.0%（Compressed）、6.7%（Workflow），扭曲/矛盾/误导性添加均很少。
- **缩短并非全部收益来源**：在同等上下文预算下，`Compressed` 普遍优于通用摘要，但 `Full` 在某些设置中仍更强，说明"合适接口是场景依赖的"。

## 7. 优点

- **问题提出新颖且具普遍性**：把"技能如何暴露"从隐式格式选择提升为显式、可评估、可学习的设计变量，切入角度清晰且有实际价值。
- **反事实实验设计严谨**：固定任务/智能体/候选技能、只变接口，使因果归因干净；同时以负迁移率刻画风险。
- **提供方无关（provider-agnostic）**：核心抽象只假设通用的任务/智能体/候选技能对象，可对接穷举、向量检索、图检索、oracle 等多种上游，工程上易于集成。
- **多维评估**：同时报告性能与渲染上下文成本，给出 cost–performance 权衡图，兼顾效果与效率。
- **方法论自我审查意识强**：
  - 人工保真度审计区分"合法压缩"与"有害遗漏"；
  - 长度匹配摘要对照排除"单纯变短"这一替代解释；
  - 明确将 `All + Full` 定位为诊断条件而非机制结论；
  - 明确区分 oracle 是分析上界而非可部署策略。
- **诚实报告不确定性**：任务级 bootstrap 置信区间 + 明确提示重叠区间不可过度解读，学术态度克制。

## 8. 不足与局限

- **接口空间受限**：仅 5 种手工设计的固定接口，未覆盖可能的技能表示设计空间；未尝试直接生成任务自适应视图或学习更丰富的接口。
- **策略学习过于初步**：SFT/DPO 仅为可行性探针，与 oracle 差距巨大（78.6 vs 92.9）；标签分布显示策略存在明显偏置；未使用在线强化学习（作者解释为避免混淆探索与策略学习）。
- **离线回放评估的偏差风险**：策略在 ALFWorld 上通过查表固定接口轨迹评估，而非真实在线交互，可能高估或低估实际部署表现；训练数据来自 ScienceWorld，跨域泛化未经充分验证。
- **统计显著性有限**：置信区间较宽且大量重叠，多个"最优/次优"标记的排名差异可能并不显著。
- **机制未解耦**：`All + Full` 的退化被归因于截断、注意力稀释、无关先验、指令冲突等多个可能机制，但缺少对上下文长度、相关性、排序的独立控制实验。
- **不替代检索**：框架明确是检索的补充，候选质量差会限制对齐接口的收益；未给出联合优化检索与暴露的端到端方案。
- **评测覆盖有限**：仅 2 个主基准（140 + 94 个实例），技能库虽扩展到 2000 但主要在 ALFWorld + MiniMax 单后端上做规模分析，结论外推需谨慎。
- **应用限制**：紧凑视图存在少量执行/安全相关的保真失败（虽罕见），安全敏感场景需额外保真校验与回退到 Full 的机制。
- **成本信息不完整**：仅报告策略训练算力（1×A100、约 50 GPU 小时），主实验的多后端 API 调用开销未量化，影响复现与成本评估。
