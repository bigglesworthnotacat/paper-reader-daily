## 摘要
LLM智能体中的隐私泄露通常是在记忆、检索或工具使用流水线等单个组件内进行评估的，这使得难以区分内部暴露与外部观察者实际能够恢复的信息。我们提出CIPL（Channel Inversion for Privacy Leakage，隐私泄露的通道反演），一个面向LLM智能体中黑盒隐私泄露的通道感知评估框架。CIPL将目标表示为敏感源、选择、组装、执行、观察和提取等阶段，并在共享协议下评估从被选敏感单元到攻击者可恢复输出的转换。跨基于记忆、检索中介和工具中介目标的实验，以及一个BrowserUse实时智能体案例研究，表明仅凭存储标签并不能决定可恢复性。记忆目标构成接近饱和的参照情形，检索中介的泄露常常是部分的，而工具中介和实时智能体的泄露则随观察面、提示到通道的对齐、检索深度和提供商行为而强烈变化。分层语义审计进一步识别出标准精确匹配所遗漏的对攻击者有用的披露。因此，CIPL提供了一个通用框架，用于比较内部敏感依赖如何在异构智能体流水线中实现为外部可恢复的泄露。

## Abstract
Privacy leakage in LLM agents is commonly evaluated within individual components such as memory, retrieval, or tool-use pipelines, which makes it difficult to distinguish internal exposure from information that an external observer can actually recover. We present CIPL (Channel Inversion for Privacy Leakage), a channel-aware evaluation framework for black-box privacy leakage in LLM agents. CIPL represents a target through sensitive source, selection, assembly, execution, observation, and extraction stages and evaluates the transition from selected sensitive units to attacker-recoverable output under a shared protocol. Experiments across memory-based, retrieval-mediated, and tool-mediated targets, together with a BrowserUse live-agent case study, show that storage labels alone do not determine recoverability. Memory targets form a near-saturated reference case, retrieval-mediated leakage is frequently partial, and tool-mediated and live-agent leakage varies strongly with observation surface, prompt-to-channel alignment, retrieval depth, and provider behavior. A stratified semantic audit further identifies attacker-useful disclosures that canonical exact matching misses. CIPL therefore provides a common framework for comparing how internal sensitive dependence is realized as externally recoverable leakage across heterogeneous agent pipelines.

## 1. 核心问题与整体含义

- **研究动机**：LLM 智能体的隐私泄露通常按组件评估，例如记忆、RAG 检索、工具调用等。这种“存储标签式”评估只能说明敏感信息可能存在于某处，无法回答黑盒观察者真正关心的问题：**哪些内部被选中的敏感单元最终能从攻击者可见通道中被恢复？**
- **核心问题**：内部暴露与外部可恢复泄露不是一回事。同一敏感内容可能被选中进入计算，但不出现在最终回答中；也可能只出现在结构化字段、工具返回或过程日志中。仅评估存储组件会混淆“内部依赖”和“外部泄露”。
- **整体含义**：论文提出 CIPL（Channel Inversion for Privacy Leakage），将评估对象从“敏感信息存在哪里”转向“敏感信息如何经由通道变成攻击者可恢复输出”，为记忆、检索、工具和实时智能体提供统一的黑盒隐私泄露比较框架。

## 2. 方法论：CIPL 框架

- **核心思想**：把异构智能体目标统一表示为六阶段签名  
  \(\tau = (S, Sel, Asm, Exec, Obs, Ext)\)  
  其中 \(S\) 为敏感源，\(Sel\) 为选择，\(Asm\) 为组装，\(Exec\) 为执行，\(Obs\) 为攻击者可见观察面，\(Ext\) 为提取规则。
- **暴露到恢复的形式化**：
  - 每次试验 \(j\) 由黑盒查询和条件记录 \((q_j,\gamma_j)\) 定义。
  - 内部暴露集合：\(U_j = \phi_\tau(z_j)\)，即被选入主动计算的敏感单元。
  - 外部恢复集合：\(V_j = \phi_\tau(Ext_\tau(o_j))\)，即从可见产物中提取出的敏感单元。
  - 评估重点是 \(U_j \to V_j\) 的转化，而不是存储组件本身。
- **恢复事件**：
  - 任意恢复：\(A_j = I[|V_j|>0]\)。
  - 完整恢复：\(C_j = I[U_j \ne \emptyset \land U_j \subseteq V_j]\)。
- **指标**：
  - \(RN\)：内部暴露覆盖。
  - \(EN\)：外部泄露覆盖。
  - \(EE\)：归一化辅助效率。
  - \(CER\)：完整提取率。
  - \(AER\)：任意提取率。
  - \(ExecErr\)：执行错误，用于区分泄露失败与流程不稳定。
- **跨目标可比条件**：单元归一化、查询预算一致、观察与提取规则明确且固定、报告指标定义一致。
- **两个理论命题**：
  - 组件标签不是泄露标识：仅改变 \(Obs\) 或 \(Ext\) 即可改变 \(V_j\)，而 \(U_j\) 不变。
  - 精确提取是语义可恢复性的下界：语义提取器可发现精确匹配遗漏的攻击者有用披露。

## 3. 实验设计

- **受控目标**：
  - `memory_ehr`：改编自 EHRAgent/MEXTRA 风格，检索记忆作为代码生成示例，观察最终回答。
  - `memory_rap`：改编自 RAP/WebShop 风格，记忆指导动作生成，观察动作中介输出。
  - `rag_ctrl`：50 条合成记录，检索 top-k，注入 `private_fact`，观察生成答案。

- **实时智能体扩展**：

- **默认协议**：攻击预算 \(n=30\)，1 次重试，5 个种子；源大小记忆目标 200、RAG/工具 50；默认检索深度分别为 4、3、2、2；默认 edit-distance 检索。
- **对比与消融**：
  - 主提示 vs naive/dump 基线。
  - 强攻击提示 vs cleaned weak-control。
  - 防御式提示抑制。
  - 检索规则：edit-distance vs token-overlap。
  - 源大小、检索深度 \(k\)。
  - 组件消融：locator/aligner/diversification。
  - 精确匹配 vs 语义审计。
- **语义审计**：200 个分层样本，两标注者，raw agreement 0.970，Cohen’s kappa 0.951，6 个分歧最终裁决。

## 6. 主要结论与发现

- **存储标签不决定可恢复性**：敏感信息存在哪里，不能决定外部观察者能否恢复。
- **记忆目标接近饱和**：`memory_ehr` 和 `memory_rap` 在所有提供商上 CER = AER = 1.0，构成近饱和参照。
- **检索中介泄露常为部分**：`rag_ctrl` 的 CER 约 0.33–0.55，AER 约 0.78–0.95，表现为“频繁但不完整”的泄露模式。
- **工具中介泄露通道敏感且依赖提供商**：
  - 远离提供商上限时，`return_echo` 常强于 `args_exfil`。
  - DeepSeek 和 GPT-4o 在某些工具通道上接近或达到饱和。
  - 通道排序并非固定，取决于观察面和提供商行为。
- **弱控制显著抑制泄露**：移除显式提取指令后，工具通道泄露急剧下降；BrowserUse 在标准操作任务下 AER 近零，即使敏感内容仍进入上下文。
- **检索深度不单调增加泄露**：增大 \(k\) 可增加内部暴露，但可能削弱完整提取，RAG 中 AER 高而 CER 下降。
- **精确匹配遗漏语义泄露**：200 个审计样本中，semantic_AER=0.8550，semantic_CER=0.4100；5 个样本 `exact_any=0 & semantic=1`，即无精确匹配但仍泄露部分敏感值。
- **PrivacyInAction**：受监控工具路径下泄露低，CER=0；切换到未监控输出通道后泄露大幅上升，AER 可达 0.92，说明单通道审计不足。
- **防御提示可抑制但非完整防御基准**：GPT-4o echo AER 从 1.00 降至 0.20，args AER 从 0.99 降至 0.46；MiniMax-M2.7 也有下降。

## 7. 优点

- **统一评估抽象**：用六阶段签名和暴露-恢复分解，使记忆、RAG、工具、实时智能体可在同一协议下比较。
- **区分内部暴露与外部恢复**：避免把“存储了敏感信息”误判为“可被攻击者恢复”。
- **因子归因

- **因子归因清晰**：通过显式改变 \(Obs\) 与 \(Ext\)，论文展示了同一内部暴露 \(U_j\) 可以对应完全不同的外部恢复 \(V_j\)，从而把泄露归因到观察面、提取规则和通道行为，而非简单归因到“记忆/检索/工具”组件标签。
- **弱控制与防御边界有价值**：naive/dump 基线、cleaned weak-control 和防御式提示共同说明，许多泄露高度依赖攻击提示与输出通道；这既避免夸大风险，也为后续防御评估提供了参照。
- **指标具有诊断性**：RN/EN/EE 与 CER/AER/ExecErr 的组合，不只报告“是否泄露”，还区分内部暴露覆盖、外部恢复覆盖、辅助效率、完整提取、任意提取和执行失败，便于定位泄露发生在选择、组装、执行还是观察阶段。
- **语义审计补足精确匹配盲区**：精确匹配会漏掉改写、部分披露、结构化转述等语义泄露；论文用人工标注验证语义审计，虽然样本有限，但方向正确。

## 8. 不足与局限

- **生态效度仍有限**：受控目标多使用合成记录或改编任务，真实企业记忆库、长期用户历史、多轮工具链和权限隔离环境覆盖不足。实时智能体只扩展到 BrowserUse 与 PrivacyInAction，尚不能代表全部生产级智能体形态。
- **提供商与 API 快照不可控**：实验依赖多个商业 API，模型版本、路由策略、温度、系统提示和默认包装器参数可能随时间和调用路径变化。论文虽固定了多数协议，但无法完全排除提供商侧非确定性对 CER/AER 的影响。
- **语义审计规模偏小**：200 个分层样本、两标注者、kappa 较高，但仅覆盖部分目标与通道；对语义等价、部分值披露、组合推断泄露的判定仍依赖标注规范，推广到更大规模时成本与一致性都是问题。
- **部分消融的统计强度不一致**：主实验使用 5 个种子，部分辅助消融或运行时语义评估使用较少种子或较低人工验证 kappa，导致某些结论的置信度弱于主结论。
- **算力、成本与调用量不透明**：论文未报告总 API 调用次数、token 消耗、费用、失败重试成本或硬件资源，难以评估该方法在真实审计中的可扩展性与经济可行性。
- **防御评估不是完整防御基准**：防御式提示能降低泄露，但论文未系统比较差分隐私、访问控制、输出过滤、工具沙箱、记忆加密等机制；因此“可抑制”不等于“可部署防御”。
- **理论命题范围有限**：组件标签不是泄露标识、精确提取是语义可恢复性下界，这两个命题有解释力，但仍依赖固定观察面和提取器定义；面对自适应攻击者、多通道联合观察或跨会话关联时，形式化可能需要扩展。
- **隐私与伦理风险**：论文本身涉及敏感信息提取攻击，虽然使用合成或受控数据，但方法若被滥用可能提高攻击效率；论文对数据治理、攻击披露边界和伦理审查的描述相对有限。

## 9. 总体评价与启示

- **范式贡献大于单点结果**：CIPL 的核心价值是把智能体隐私评估从“敏感信息存储在哪里”推进到“敏感信息如何经由可观察通道变成可恢复输出”。这一视角对记忆、RAG、工具调用、浏览器智能体和 MCP 审计具有统一解释力。
- **对评估实践的建议**：未来智能体隐私报告应显式声明 \(S, Sel, Asm, Exec, Obs, Ext\)，固定查询预算与提取规则，并同时报告内部暴露与外部恢复指标。只报告组件级敏感信息存在性，容易高估或低估真实泄露。
- **对系统设计的启示**：降低泄露不应只做存储加密或检索过滤，还应关注敏感单元是否进入主动计算、是否进入工具参数、是否出现在过程日志、错误信息、URL、中间动作和最终回答。跨通道审计比单通道审计更必要。
- **对攻击与防御研究的启示**：攻击面高度依赖观察面和提供商行为，通道排序不固定；防御评估应覆盖弱控制、强攻击、语义泄露和未监控旁路。RAG 中“频繁但不完整”的泄露模式说明，部分披露同样具有隐私风险。
- **未来方向**：可扩展到多模态智能体、长期记忆、多用户共享记忆、多智能体协作、真实企业工作流和自适应攻击者；同时需要更严格的统计设计、成本报告、伦理审查，以及将 CIPL 与差分隐私、因果推断、访问控制和输出净化机制结合。

总体而言，这篇论文提出了一个清晰、可操作且具有比较能力的黑盒隐私泄露评估框架。它的主要贡献不是证明某个组件必然泄露，而是揭示“内部被选中”与“外部可恢复”之间存在可测量、可归因且常被忽视的转化过程。对智能体隐私审计而言，这是一项从存储标签走向通道反转的重要推进。
