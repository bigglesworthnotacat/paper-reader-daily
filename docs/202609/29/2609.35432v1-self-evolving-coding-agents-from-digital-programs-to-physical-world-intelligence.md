## 摘要
视觉-语言-动作（VLA）与世界-动作（WAM）模型将观测和指令直接映射为机器人动作。这种直接性将策略与训练绑定：轻微的布局或视角变化就会导致失败，且指令泛化能力很差。根源在于表示：任务需求、条件、进度和故障恢复被隐式编码在动作序列中，使其难以检查或修改。数字编程智能体提供了一个先例：LLM 以可执行代码的形式调用工具、验证结果，并根据反馈进行修正。显式状态、可控执行和可修正流程这一相同的工作模式，是物理世界中泛化与长时程执行的基础，使物理经验能够以可复用程序、记忆或证据的形式回流。我们提出物理编程（Physical Coding），将任务状态与执行表示为代码。代码即世界（Code as World）记录对象、关系、约束和进度；代码即策略（Code as Policy）组织规划、验证、恢复和执行。我们构建了 HexaAnything，它调用感知、规划和控制工具（包括 VLA/WAM 策略），并基于外部反馈进行在环决策。经过验证的轨迹成为数据和记忆，使演化成为可能：从工具和 Harness 到模型权重、架构，最终到硬件和任务设计。在 RoboCasa365 上，HexaAnything 在 Composite-Unseen 和总体成功率上优于 XR-1 VLA，其经 Harness 训练的 HexaModel 在每个数据划分上都超过基线，表明代码轨迹内化了物理执行。在 PhyBench 和双臂 AgileX 机器人上，该智能体自主完成物理实验和大多数桌面任务，且通常比已发表结果更快。我们观察到数据、模型和工具的自演化；未来工作目标包括权重内化、对架构、语言、表示和任务的自主重新设计，以及在制造业和科学中的部署。

## Abstract
Vision-language-action (VLA) and world-action (WAM) models map observations and instructions directly to robot actions. This directness ties a policy to training: minor layout or viewpoint changes cause failure, and instructions generalize poorly. The root cause lies in representation: task requirements, conditions, progress, and failure recovery are implicitly encoded in action sequences, making them difficult to inspect or revise. Digital coding agents offer a precedent: LLMs call tools, verify results, and revise from feedback as executable code. The same working pattern of explicit state, manageable execution, and revisable procedures underlies generalization and long-horizon execution in the physical world, letting physical experience return as reusable programs, memory, or evidence. We propose Physical Coding, representing task state and execution as code. Code as World records objects, relations, constraints, and progress; Code as Policy organizes planning, verification, recovery, and execution. We build HexaAnything, which calls perception, planning, and control tools, including VLA/WAM policies, and makes in-the-loop decisions from external feedback. Verified traces become data and memory, enabling evolution from tools and Harness to model weights, architectures, and ultimately hardware and task design. On RoboCasa365, HexaAnything improves Composite-Unseen and overall success over XR-1 VLA, and its Harness-trained HexaModel beats the base on every split, indicating code traces internalize physical execution. On PhyBench and a dual-arm AgileX robot, the agent autonomously completes physics experiments and most tabletop tasks, often faster than published results. We observe data, model, and tool self-evolution; future work targets weight internalization, autonomous redesign of architectures, languages, representations, and tasks, and deployment in manufacturing and science.

## 1. 核心问题与整体含义

- **研究动机**：VLA（视觉-语言-动作）与 WAM（世界-动作）模型将观测和指令直接映射为机器人动作。这种端到端直接性把策略与训练数据绑定，导致布局或视角微变即失败，指令泛化能力差。
- **根因诊断**：任务需求、条件、进度和失败恢复被隐式编码在动作序列与停止信号中，无法被检查或修改。论文用指令屏蔽实验量化该问题——QwenGR00T 在 LIBERO 上屏蔽指令训练仍达 92.3%，指令条件化版本为 96.2%，差距最多 6.0 个百分点，说明策略主要在做“场景→轨迹”的拟合。
- **已有工作缺口**：
  - 闭环系统（Inner Monologue、ReAct）把验证与恢复放在程序之外，验证依赖模型自身判断。
  - Code as Policy 类工作（CaP-X）中感知被信任而非验证，错误沿程序链复合，改进只能作用于原语组合，且测试时收益不持久。
  - 具身 Harness（Zetta、SHAPER、Harness VLA）虽可演化 critic、技能与恢复规则，但学习内容存储在模型之外，推理模型固定，能力受检索与上下文上限约束。
- **整体含义**：提出 **Physical Coding** 范式，把物理世界的任务状态与执行过程都表示为可执行、可验证、可版本化、可回滚的程序，使物理执行经验回流为可复用程序、记忆与证据，进而支撑数据、模型、工具乃至架构与硬件的自演化。

## 2. 方法论

### 2.1 核心思想

- 物理世界默认缺少软件世界中“状态可读、动作有返回值、完成由测试判定”的媒介。Physical Coding 为物理任务补上这一媒介，使观察、动作、反馈共享同一可执行表示。
- 两个耦合的可执行构件：
  - **Code as World**：记录任务相关对象、关系、观测、状态变量、约束与进度谓词（如 `inside(bread, oven) = False`）。
  - **Code as Policy**：组织规划、工具调用、动作执行、验证、恢复与重规划；节点类型包括观察、动作、VLA 调用、判断、验证、恢复、分支、序列、循环。
- 两者缺一不可：无世界程序则无法表达“香肠是否还在碗里”；无策略程序则无行动、中断与恢复机制。
- **核心原则**：独立验证器检查世界程序、策略程序或其编辑是否有证据支持；模型自报“完成”不算成功。

### 2.2 形式化定义

- Harness 定义：`Ht = (Ot, Tt, Vt, Rt, Mt, Γt)`，其中 O 为观察接口，T 为工具注册表，V 为验证器，R 为恢复算子，M 为带溯源记忆，Γ 为执行契约、权限、预算与安全门。
- 策略步与调度：
  - `nt = πθt(z, Wt, Pt, O≤t, Mt)`
  - `ut = Dispatch(nt, Tt)`
- 环境转移与世界更新、验证：
  - `xt+1 ~ E(xt, ut)`
  - `Wt+1 = UpdateWorld(Wt, Ot+1, yt)`
  - `qt = Vt(Wt+1, yt, z)`
- 完整轨迹：`ξ = {z, W0:T, P0:T, O0:T, u0:T, y0:T, q0:T, M0:T}`，是归因与后续更新的单元。
- 验证器返回类型化判定：`PASS`、`FAIL`、`INSUFFICIENT EVIDENCE`、`BLOCKED`、`SAFETY STOP`。

### 2.3 自演化循环

- 演化单元为版本化 artifact bundle：`av = (Wv, Pv, Hv, Dv, Mv, Ev)`。
- 七步流程：Specify（冻结任务分布/种子/预算/评测协议）→ Execute（记录类型化 trace）→ Verify（独立评测）→ Diagnose（定位限制因素）→ Propose（有界编辑）→ Evaluate（静态检查、回归测试、canary、held-out）→ Select & Commit（接受或回滚）。
- 形式化：`ξv ~ Execute(Pv; Wv, Hv, e, z)`，`ov = Vv(ξv, z, e)`，`av+1 = Select(Evaluate(Propose(av, ov)), Tholdout)`。
- **四个耦合演化目标**：Harness（工具/工作流/验证器/恢复）、数据与环境、模型与算法、具身与计算；表示与接口演化横跨四者。
- **证据阶梯**：E0 可运行 → E1 oracle 可完成 → E2 能区分策略 → E3 训练提升新 checkpoint → E4 迁移到真实机器人或分布偏移。
- **三阶段路线**：Stage 1 Harness 引导；Stage 2 模型–Harness 协同演化；Stage 3 物理反馈与部署。
- **执行契约**：GoalContract（用户原始任务文本不可变）、类型化策略表示、ObservationEnvelope（观察溯源）、TrialOutcome、ExperimentSpec；恢复采用 fail-closed，歧义状态不静默提升为成功
