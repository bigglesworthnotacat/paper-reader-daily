## 摘要
智能体技能演化旨在通过迭代修订，改进大语言模型（LLM）智能体可复用的流程性指导。现有方法主要基于执行轨迹或反馈进行每次修订，这使得跨任务反复出现的行为需求保持隐含，并将修订与当前技能的行为绑定。我们提出 SkillFocus，它将反复出现的任务需求分解为一个在技能演化过程中保持固定的能力空间，从而将任务所需与当前技能的行为方式分离开来。SkillFocus 将当前任务结果映射到该空间，以识别导致最多任务未解决的能力，然后利用该能力确定需要修订的内容以及应使用哪些证据。在涵盖异构任务的四个基准上，SkillFocus 在全部四个基准上取得最佳留出准确率，平均比最强的对比结果高出 5.7 个百分点，同时平均比最接近的迭代基线少用 24% 的演化 token。控制实验进一步表明，由反复出现的任务需求所推导出的能力优于任务语义和由执行推导的替代方案，而随机化任务—能力分配会使最终准确率最多下降 20.2 个百分点。在优先修订下，将证据与所选能力相匹配可使候选增益提高 4.4 个百分点。

## Abstract
Agent skill evolution seeks to improve reusable procedural guidance for large language model (LLM) agents through iterative revision. Existing methods base each revision mainly on execution trajectories or feedback, leaving recurring behavioral requirements across tasks implicit and tying revision to the behavior of the current skill. We introduce SkillFocus, which decomposes recurring task requirements into a capability space that remains fixed as the skill evolves, separating what tasks require from how the current skill behaves. SkillFocus maps current task outcomes to this space to identify the capability that leaves the most tasks unresolved, then uses that capability to determine what to revise and which evidence to use. Across four benchmarks spanning heterogeneous tasks, SkillFocus achieves the best held-out accuracy on all four, outperforming the strongest competing result by 5.7 points on average while using 24\% fewer evolution tokens on average than the closest iterative baseline. Controlled studies further show that capabilities derived from recurring task requirements outperform task-semantic and execution-derived alternatives, while randomizing task--capability assignments reduces final accuracy by up to 20.2 points. Matching evidence to the selected capability increases candidate gain by 4.4 points under prioritized revision.

## 一、核心问题与整体含义

- **背景**：LLM 智能体可借助 *Agent Skills*（可复用的流程性指导，用于推理、工具使用与任务执行）提升表现；由于技能是文本、无需更新模型参数，因此可通过反复执行任务来迭代改进，即"技能演化"（skill evolution）。
- **核心痛点**：当一个共享技能被复用于异构任务时，修订必须同时服务多个不同但相互重叠的流程性需求。现有方法（Trace2Skill 蒸馏轨迹、SkillGrad 诊断失败、SkillOpt 基于评分 rollout 等）几乎都以**执行证据**为修订依据，只能反映"当前技能做了什么"，而执行证据本身随技能变化而改变，无法揭示**哪些流程性需求在任务间反复出现**。
- **另一条歧路**：以"任务"为修订单元也不成立——一个任务可能包含多个流程，同一流程也可能横跨许多任务。
- **关键概念**：作者将"可由技能修订改善的、反复出现的流程性需求"定义为 **capability（能力）**。
- **中心问题**：能否在**执行之前**从任务规格中提取反复出现的需求，并据此同时决定"修订什么"与"使用哪些执行证据"？
- **整体含义**：把技能演化从"行为驱动"转为"能力驱动"，将"任务要求什么"与"当前技能表现如何"解耦——前者固定不变，后者随演化更新。

## 二、方法论

### 2.1 问题形式化
- 共享技能演化：固定非技能组件 `A`（模型、工具、环境），技能空间 `S`，当前技能 `S_t`，任务池 `D = {τ_i}`。
- 每个任务有归一化评分 `Y_i(S) ∈ [0,1]`；候选技能 `S'_t` 仅在通过验证时才替换当前技能（式 1），最多运行 `T_max` 轮。

### 2.2 能力空间（演化前冻结）
- 从**任务规格、输入结构、环境契约**中提取流程性需求，**不使用任何执行结果**；当同一份可复用技能指导能同时处理多个需求时即合并。
- 得到能力集合 `C = {c_d}` 与任务–能力矩阵 `Q ∈ {0,1}^{N×K}`（式 2），条目记录"需求"而非"结果"；一个任务可含多个能力，一个能力可覆盖多个任务。
- 二者构成**能力空间 (C, Q)**，在演化开始前冻结、全程不变，使不同轮次的技能可在同一需求基准上比较。
- 附录 C.1 流程：抽取需求 → 三种独立视角（Requirement-centric / Intervention-centric / Boundary-centric）各自提出能力 → 共识合并 → 需求指派 → 支持度过滤（`n_min = 3`）→ 冻结。

### 2.3 能力引导的修订
- **数据划分**：演化前将任务池切分为训练集 `D_tr`（提供修订证据）与选择集 `D_sel`（仅用于候选检查）。
- **能力打分**：`q_d^t` = 训练集中需要 `c_d` 的任务的平均当前得分（式 3）；`π_d` = 该能力在全池的支持占比。
- **选择依据**：未解决任务质量 `m_d^t = π_d (1 - q_d^t)`（式 4），取候选集中最大者 `d*_t = argmax m_d^t`（式 5）。既避免"罕见但差"的能力，也避免"常见但已好"的能力。
- **可行动能力集 U_t**：需同时满足①在 `D_tr` 中存在可诊断失败（因任务逻辑而非环境故障）；②在 `D_sel` 中至少有一个支撑任务。
- **证据匹配**：仅保留 `Q_{i,d*}=1` 的训练任务，组成证据包 `E_t`——包含该需求下的执行记录、相关技能内容、历史 `H_t` 中同一能力的修订记录；有成功执行时与失败并置对比。从而"从与该需求相关的执行中诊断一个需求"，而非混合全部执行。
- **提议修订**：仅当证据能把"所选需求—观测执行—可编辑技能内容"三者联系起来时才提出修订，否则放弃并考虑下一能力；复制任务特定实体（任务 ID、文件名、单元格坐标等）的编辑在执行前被丢弃。诊断与生成各用 `J_D = J_G = 3` 个独立视角 Explorer + 1 个 Integrator。

### 2.4 候选验证
- **选择集构建**：演化前一次性贪心构建，优先级为①能力覆盖（用同一 `π_d` 加权）；②任务特征多样性（任务族、输入结构、环境契约）；③改进机会（初始执行中可诊断失败比例）。另保留初始技能已解任务的"回归可见"储备，并保证每个能力在训练集中至少留一个支撑任务。
- **整体技能验证**：由于能力重叠、每次修订都改动共享技能，候选可能在修复一个需求时损害其他需求，因此不做"仅目标能力任务"的检查。定义配对变化 `Δ_X(S',S)`（式 6），**仅当选择集与训练集的配对变化同时为正**才接受（式 7）。
  - 选择集轨迹不参与候选生成，起"未见过证据"的检验作用；训练集重评估提供下一轮的执行记录与能力分数。
- **Algorithm 1** 概括完整循环：能力诱导 → 初始执行 → 构建选择/训练集 → 每轮打分选能力 → 收集匹配证据 → 诊断与编辑 → 选择集+训练集双重验证 → 接受/拒绝 → 更新历史。

每轮诊断、编辑与双重验证的全部模型调用）；同时报告相对初始技能的绝对/相对提升、候选接受率与所需演化轮数，以衡量"同等预算下的技能质量"与"达到同等质量所需的成本"两个维度。

## 四、实验结果

### 4.1 主结果
- **技能质量**：SkillFocus 在四个异构基准上均取得最高留出测试准确率，且相对 No Skill 与 One-shot Skill 的增益稳定；相比最接近的迭代基线 SkillOpt，优势在 SpreadsheetBench 与 IFBench 上最为明显——这两者的任务间流程重叠度高、单一共享技能最容易被"局部修补"所拖累，说明能力引导的修订定位确实缓解了跨任务干扰。
- **演化成本**：SkillFocus 的累计 token 消耗低于或与 SkillOpt 相当。原因在于其每轮只围绕一个被选中的能力收集**匹配证据**（`Q_{i,d*}=1` 的训练任务），证据包规模远小于"全量 rollout 一起喂给优化器"的做法；同时"证据不足则放弃该能力、转下一能力"的早停机制避免了无效的生成与验证开销。
- **与提示演化基线对比**：GEPA 依赖反思式提示演化但缺少显式的需求分解，其改进集中在少数高频任务族，跨基准方差较大；Trace2Skill 从轨迹蒸馏出的技能在 SearchQA 上尚可，但在需要精确环境契约（单元格坐标、指令约束）的任务上迁移性差。
- **增益分布**：提升并非均匀来自所有能力。报告显示，贡献最大的往往是被多个任务共享、且初始得分处于中低区间的能力（即 `m_d^t = π_d(1-q_d^t)` 较大的能力），这与选择准则的设计意图一致。

### 4.2 接受率与轮数
- 由于采用"选择集 + 训练集配对变化同时为正"的严格判据，候选接受率偏低，但被接受的候选几乎不出现"修好一个需求、弄坏另一个需求"的回退；被拒绝的候选多集中在能力重叠密集的区域，印证了"共享技能的整体验证"这一设计的必要性。
- 多数基准在 2–3 轮内达到最佳技能，之后边际收益递减，说明能力空间中的"高价值未解决需求"是有限且可被快速消耗的。

## 五、分析与消融

- **去掉能力空间（改为按任务或按全量证据修订）**：性能显著下降，且轮次间波动增大。这直接支持核心论点——以任务为修订单元会被"一任务多流程"和"一流程多任务"双重错配所惩罚。
- **去掉选择集验证（仅用训练集配对变化）**：训练集分数继续上升，但留出测试下降，出现典型的过拟合到证据包的现象；选择集作为"未见过证据"的检验环节是泛化的关键。
- **去掉证据匹配（用全部训练执行作为证据）**：诊断噪声上升，修订容易偏离所选能力，产生与目标需求无关的编辑。
- **能力支持度阈值 `n_min`**：过低会引入一次性、不可复用的需求，使技能偏向个别任务；过高则丢失长尾但真实的需求。`n_min = 3` 在覆盖与稳健之间取得折中。
- **多视角 Explorer（`J_D = J_G = 3`）+ Integrator**：相比单视角，能减少对单一失败模式的过度归因，提高诊断与编辑的一致性。
- **任务特定实体的过滤**：丢弃复制任务 ID、文件名、单元格坐标等编辑，是防止"技能被写成任务答案"的必要约束，消融后测试性能下降。
- **成本–收益**：能力诱导与选择集构建是一次性开销，可被多轮演化摊销；轮数越多，相对基线的单位改进成本优势越明显。

## 六、结论、贡献与局限

### 6.1 主要贡献
1. **概念层面**：提出 **capability** 作为"可由技能修订改善、在任务间反复出现的流程性需求"，并把技能演化重构为**能力驱动**而非行为驱动，将"任务要求什么"（演化前冻结）与"技能现在做得如何"（随演化更新）解耦。
2. **方法层面**：给出可操作的流水线——从任务规格/输入结构/环境契约诱导能力空间 `(C, Q)` 并冻结；用 `m_d^t = π_d(1-q_d^t)` 选择待解决能力；按 `Q_{i,d*}=1` 匹配证据；以选择集与训练集的**双重配对变化**整体验证候选。
3. **实证层面**：在四个异构基准、统一评测协议与同一目标模型下，一致优于提示演化与技能演化基线，并在优化 token 上不占劣势。

### 6.2 局限与未来方向
- **能力空间的静态性**：`(C, Q)` 一旦冻结便不随演化更新，若初始诱导遗漏了关键需求，后续轮次无法补救；如何在不破坏可比性的前提下有限度地增补能力，是开放问题。
- **诱导依赖模型判断**：从任务规格抽取需求仍需 LLM 判断，可能存在漏抽与错并；对规格本身模糊或缺失的任务（如开放式任务）适用性受限。
- **证据充分性**：当某能力在训练集中可诊断失败稀少时会被判为"不可行动"，可能长期搁置真实但难触发的需求。
- **验证代价**：双重验证需要重新执行选择集与训练集，任务池很大时成本上升；如何用更少的配对样本获得同等判别力值得研究。
- **适用边界**：方法假设存在一份可被多任务共享的技能、且任务可按能力分解；对高度特化、几乎无流程重叠的任务集合，能力引导的相对优势会缩小。

### 6.3 一句话总结
SkillFocus 把"改技能"这件事从"看当前执行哪里错了"推进到"先弄清任务反复要求什么、再只拿与这一要求相关的证据去改"，用一份冻结的能力空间为不同轮次的技能提供统一的需求基准，从而在异构任务共享同一技能时实现更稳、更省、更少回退的演化。
