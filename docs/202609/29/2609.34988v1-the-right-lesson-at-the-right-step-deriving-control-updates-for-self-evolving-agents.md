## 摘要
自演化智能体通过复用过去经验来改进未来行为，这些经验通常以全局提示、记忆或反思的形式存在。然而，这些机制很少控制经验在何处生效。在长程工具使用工作流中，同一条经验可能纠正某一决策，却干扰另一决策，这使经验复用成为一个局部控制问题，而不仅仅是记忆问题。我们提出 EvoCUE（Evolution through Control Updates from Evidence，基于证据的控制更新演化），一个从已完成的智能体执行中学习可复用控制程序更新的框架。EvoCUE 将智能体表示为一个显式的状态机控制器，其节点执行模型或工具调用，其边定义控制接下来传递到何处。这使得工作流可在精确位置被编辑，因此每个学到的更新都能指明添加什么、作用于何处以及何时适用。基于已完成的轨迹，EvoCUE 利用残余目标与观测到的执行轨迹，提出局部化的指令或技能编辑。每个候选编辑都在其将要作用的位置进行评估：从同一检查点恢复父控制器与编辑后的控制器，并比较它们的最终结果。被接受的编辑会与适用性规则一起编译，在留出任务上得到确认，并被后续执行继承。我们在长程工具使用环境中评估 EvoCUE，在这些环境中，学到的约定必须到达正确的执行步骤。从一个不含基准特定入门指令的最小 AppWorld 控制器出发，EvoCUE 学到了缺失的任务完成约定，并显著提升了在 Test-Normal 与 Test-Challenge 上的成功率。在 PAST-Bench 办公工作流上，EvoCUE 将组织要求从先前回合迁移到后续任务，提升了任务执行质量。这些结果表明，自演化智能体应将经验置于控制流内部，而非仅将其存储为文本。

## Abstract
Self-evolving agents improve future behavior by reusing past experience, typically as global prompts, memories, or reflections. Yet these mechanisms rarely control where experience takes effect. In long tool-use workflows, the same lesson may correct one decision but distract another, making experience reuse a problem of localized control rather than memory alone. We introduce EvoCUE (Evolution through Control Updates from Evidence), a framework for learning reusable control-program updates from completed agent executions. EvoCUE represents the agent as an explicit state-machine controller, whose nodes perform model or tool calls and whose edges define where control passes next. This makes the workflow editable at precise locations, so each learned update can specify what to add, where it acts, and when it applies. From completed trajectories, EvoCUE uses residual goals and observed execution traces to propose localized instruction or skill edits. Each candidate is evaluated at the point where it would act by resuming the parent and edited controllers from the same checkpoint and comparing their final outcomes. Accepted edits are compiled with applicability rules, confirmed on held-out tasks, and inherited by later executions. We evaluate EvoCUE on long tool-use environments where learned conventions must reach the right execution step. From a minimal AppWorld controller without benchmark-specific onboarding instructions, EvoCUE learns the missing task-completion convention and substantially improves success on Test-Normal and Test-Challenge. On PAST-Bench office workflows, EvoCUE transfers organizational requirements from prior episodes to later tasks, improving task-execution quality. These results show that self-evolving agents should place experience inside the control flow, rather than only store it as text.

## 1. 核心问题与整体含义

- **研究动机**：自演化智能体（self-evolving agents）通常把过去经验以全局提示、记忆库或反思文本的形式复用，但这类机制**几乎不控制经验在何处生效**。

- **实例佐证**：旅行预订任务中"付款前先申请审批"这条教训，只有到达付款决策步才起作用；AppWorld 上一个真实的任务完成约定，若只在第一步给出只能解决 16 个开发任务中的 5 个，放到后续步骤可达 14 个。
- **第二个困难**：局部编辑的影响会传播到后续许多动作，而反馈通常只在任务结束才出现；从头重跑会把编辑效果与早期执行的无关联波动混在一起。
- **整体含义**：论文主张自演化智能体应把经验**嵌入控制流**（学到"改什么、在哪生效、何时适用"），而不仅是存为文本。

## 2. 方法论（EvoCUE）

**核心思想**：把智能体表示为一个显式状态机控制器，使"位置"成为可学习对象；用同检查点续跑的配对试验在编辑真正起作用的地方测量其效果。

- **控制器定义**：$C=(G,\pi,\Omega)$
  - $G$：图，节点执行模型或工具调用，边传递控制并**可携带指令**（目标节点经该边进入时接收）；
  - $\pi$：路由策略，从可观测状态选择下一条边；
  - $\Omega$：可执行技能库（类似 RL 中的 option，有启动条件、可多步执行、返回成功/失败）。
  - 例：AppWorld 六节点控制器 `start → prepare（生成动作）→ pre-commit → commit → execute&observe → route`；`prepare` 有"首次进入"和"循环进入"两条入口边，指令挂在不同入口边即决定其生效位置。
- **残余目标（residual goals）**：由 LLM 从公开指令与轨迹中估计出"公开历史尚未显示为满足"的任务要求，并标注证据；它把失败**定位**到可编辑位置（如缺少审批 → 指向付款步）。当所有要求都已观测但得分仍为 0 时，问题出在"如何完成任务"。
- **提出局部化编辑**：
  - 候选编辑 $\delta$ 需指定**内容、位置（边）、作用范围（本次调用/技能调用/下一步动作）、预期效果**；
  - 指令编辑：在某条边上给节点附加文本；
  - 结构编辑：在某条边上插入 1–6 个原语操作的技能（含前向分支与成功/失败返回）；
  - 编译前做合法性检查（节点存在、pending 动作状态兼容、算子输入有效等）；提案器会收到"每个算子读写什么、附件能到达哪些入口"的控制器说明，但**看不到任务本身**。
- **配对试验（paired trials）**：对提案引用的任务采样检查点 $j$（在编辑位置被到达之前），恢复环境状态、公开历史、控制器状态与剩余预算，然后同时跑父程序 $C$ 与编辑程序 $C\oplus\delta$ 至任务结束：
  $$d_{tj}(\delta;C)=Y_{tj}(C\oplus\delta)-Y_{tj}(C)$$
  两条轨迹共享前缀，因此差异排除了编辑起作用之前的所有变异。试验记录包含执行状态（未到达/被跳过/失败/已应用/未解决），缺失分数与 0 分区分对待；任务起点试验单独记录且不含检查点特征。
- **适用性规则拟合**：在编辑作用前的**类别特征**（执行阶段、草稿有效性、残余目标状态、进度、重复、可见完成证据等）上枚举至多两个等式测试的规则 $q$：
  $$\hat q_\delta \in \arg\max_{q\in Q}\ \hat p_{S_\delta}(q)\,d_{\delta,q}-\lambda|q|$$
  其中 $\hat p$ 为规则覆盖的采样任务比例，$d$ 为平均效果，$\lambda=10^{-3}$；平局偏向更短规则。**通过条件**：至少覆盖 2 个任务、$d_{\delta,\hat q}>0$、且 $\hat p\,d-\lambda(|\hat q|+|\delta|)>0$。空规则表示"到达位置即应用"。
- **编译、确认与继承**：
  - 编译：通过的指令+规则变为指定边上的条件调用；通过的技能变为内部节点、启动条件与显式返回；同位置的新修订替换旧修订（合并指令须作为新候选重新测试）。
  - 确认：把通过编辑合并为候选程序 $C'$，在**与本轮提案/试验任务不相交**的确认批次上从任务起点与 $C$ 比较；满足预设接受准则（AppWorld：配对分数差均值为正）才被继承。
  - 试验记忆：接受与拒绝的试验全部保留，供后续提案修订内容/位置或避开已失败方向。

## 3. 实验设计

**基准与场景**

- **AppWorld**（Trivedi et al., 2024）：9 个模拟应用、457 个 API 的多步任务；90 训练 / 57 开发 / 168 Test-Normal / 417 Test-Challenge；官方 checker 判定，场景需全部子任务成功。学习只用训练任务，**用 32 个训练子集**；配对试验只在训练任务上恢复检查点；冻结程序只在测试集评测一次。
- **PAST-Bench**（Xue et al., 2026）：模拟办公任务序列（工单处理、数据共享请求等），要求通过先前回合揭示。收集 16 个历史回合、写 8 张知识卡、用 8 个后续任务学习，在 16 个后续 pilot 任务上评测冻结程序；另做**未见任务族**实验（4 个族、8 个任务）。
- **六个附加领域**：τ²-bench、EvoClawBench、MBPP、HumanEval、MATH、HotpotQA。

**对比方法（基线）**：GEPA、AFlow、AWM、MaAS，均使用同一模型、工具、观测接口与预算，从**同一最小提示**出发，且每个方法保留自己的初始程序；在 AppWorld 上基线从全部 90 个训练任务学习（EvoCUE 只用 32 个）。

**模型与预算**：deepseek-v4-flash（自托管端点），temperature 0、top-p 1、低推理强度、4096 thinking budget、输出上限 32768；AppWorld 每任务 40 次环境动作、400 控制器步，PAST pilot 为 900 控制器步。
