## 摘要
近期研究通过联合进化智能体的运行框架（harness）与模型来提升智能体，但往往采取一种“大杂烩”式方法，将新工具、新决策过程以及模型对进化后运行框架的适应统统打包在单一的“智能体提升”概念之下。在本文中，我们转而研究智能体如何改进其决策过程。具体而言，我们提出 EvoIn，一个连接进化与内化的智能体微调框架。EvoIn 首先分析智能体的执行轨迹，通过在运行框架中临时实例化新的决策过程，来演化并验证这些决策过程。经过验证的决策过程引导智能体生成改进的推理轨迹。随后，这些轨迹被改写为自包含的推理轨迹，移除对运行框架指令的显式引用，同时将所诱导出的决策逻辑表达为模型自身的推理。最后，EvoIn 在改写后的轨迹上微调模型，将这些决策过程内化，使得改进后的决策能力在推理时无需进化后的运行框架也能持续存在。我们在多种基准上评估 EvoIn，发现它能够持续使智能体学到更强的决策过程，在域内将通过率提升 10.9 个百分点，在域外提升 9.2 个百分点。结果进一步表明，内化后的决策过程能够泛化到未见任务。案例研究表明，智能体可以学会在解决任务之前决定如何解决任务，例如通过检查文档长度，在完整阅读和搜索之间做出选择。EvoIn 也具有广泛的适用性，在另一个模型系列上也展现出持续改进。

## Abstract
Recent work has explored improving agents by jointly evolving their harnesses and models, but often takes a ''potpourri'' approach that bundles together new tools, new decision-making procedures, and model adaptation to the evolved harness under a single notion of agent improvement. In this paper, we instead investigate how agents can improve their decision-making procedures. In particular, we propose EvoIn, an agent fine-tuning framework that bridges evolution and internalization. EvoIn first analyzes agent execution traces to evolve and validate new decision-making procedures by temporarily instantiating them in the harness. The validated procedures guide the agent to generate improved reasoning traces. These traces are then rewritten into self-contained reasoning traces, removing explicit references to harness instructions while expressing the induced decision logic as the model's own reasoning. Finally, EvoIn fine-tunes the model on the rewritten traces, internalizing these procedures so that the improved decision-making persists without the evolved harness at inference time. We evaluate EvoIn on diverse benchmarks and find that it consistently enables agents to learn stronger decision-making procedures, raising the pass rate by 10.9 points in-domain and by 9.2 points out-of-domain. Results further show that the internalized decision procedures generalize to unseen tasks. Case studies show that agents can learn to decide how to solve a task before solving it, for example by checking a document's length to choose between reading it in full and searching it. EvoIn is also broadly applicable, showing consistent improvements on another model family.

# EvoIn：连接进化与内化以实现智能体微调 — 论文总结

## 1. 核心问题与研究动机

- **背景**：语言智能体可形式化为「模型 M + 运行框架（harness）H」的组合，决策流程（decision-making procedure）决定其规划、工具使用与验证行为，既可显式写在 harness 中，也可隐式由模型承载。
- **现有三条路径的局限**：
  - **模型微调** (M, H₀)→(M*, H₀)：harness 固定，改进全部压入权重，决策流程只能作为梯度更新的副产品，无法被显式提出、比较与验证。
  - **Harness 进化** (M, H₀)→(M, H*)：改进是外部的，必须携带指令/技能/代码才能生效，无法沉淀为模型自身推理。
  - **模型–harness 协同进化** (M, H₀)→(M*, H*)：把新工具、决策流程与模型适配捆绑在同一目标下，训练与评测都在 H* 下进行，无法区分「模型真正变强」还是「模型只是更适配进化后的 harness」。
- **核心问题**：如何单独改进智能体的决策流程，并让这种改进不依赖进化后的 harness 而持久保留？
- **整体含义**：EvoIn 提出第四条路径 (M, H₀) —进化→ (M, H*) —内化→ (M*, H₀)，把 harness 当作「临时发现与验证空间」，最终把可复用的决策逻辑写回模型，推理时回到原始 harness。

## 2. 方法论

- **核心思想**：让智能体先在 harness 中显式提出、执行验证并筛选更好的决策流程，再把这些流程诱导出的推理改写为不依赖 harness 的自包含轨迹，最后用 SFT 内化，从而将「流程学习」与「harness 特定适配」解耦。
- **五个阶段**：
  1. **Procedure Proposal（流程提案）**：提案智能体分析当前 harness、上一轮反馈与执行轨迹，提出候选 harness 更新（可改 system prompt、workflow、工具描述、middleware 等）；每个候选需通过静态校验（编译、工具绑定、配置加载）与运行时校验（端到端跑通一个样本）。
  2. **Procedure Evaluation（流程评估）**：候选 harness 配同一目标模型 Mθ，在留出集 D_dev 上评测；分析智能体同时总结成功/失败模式作为下一轮反馈。多轮迭代后保留 D_dev 上得分最高的 H*。
  3. **Procedure-Guided Sampling（流程引导采样）**：用 H* 与 Mθ 在 D_train 上收集轨迹，仅保留任务满分且最终答案有效的轨迹 {τ*ᵢ}。
  4. **Rewriting（改写，TAILOR 流水线）**：将轨迹改写为「本可在 H₀ 下自然产生」的自包含轨迹，移除对 H* 指令、工具名、模板、阈值、步骤编号的显式引用，但保留其诱导的决策逻辑；随后在 H₀ 下重放，做确定性检查（无效工具调用、残留模板、引用行号不符、截断却声称完整阅读等），失败者做一次定向修复后再次重放；最后独立检查模型验证答案由可见证据支撑。
  5. **Procedure Internalization（流程内化）**：恢复 H₀，在改写轨迹 {τ̃ᵢ} 上做全参数 SFT，损失仅施加于模型生成的回合，得到 Mθ*，最终形态为 (Mθ*, H₀)。
- **关键机制**：改写是内化的必要条件——原始轨迹常引用 H* 独有指令或工具，直接训练会让模型在 H₀ 下复现这些不存在的前提。

## 3. 实验设计

- **数据与场景**：
  - **域内（ID）**：23 个任务类别，归为 7 个任务组（多文档键检索、证据锚定问答、结构化数据推理、日志与对话追踪、上下文学习、文档锚定生成、复杂指令遵循）；每类 100 条用于进化、100 条不相交用于进化测试（ID 测试集），共 2,300 条。
  - **域外（OOD）**：6 个基准共 2,064 条——AA-LCR、BrowseComp-LongContext、LongBench v2、MRCR、Oolong、Table-Longer（后两者之一为自建、不可公开）。
- **种子 harness**：任务无关，提供 `scan`、`grep`、`read_lines`、`bash`、`notepad`、`complete_task` 六个动作，最多 30 回合；所有评测均在种子 harness 下进行。
- **模型配置**：目标/学生模型 Qwen3.5-35B-A3B；Claude Opus 4.7 担任分析智能体与提案智能体（每类 10 轮进化、每轮 3 个候选）；GLM-5.2 担任 TAILOR 的改写与检查模型。
- **对比方法/控制组**：
  - Base（未微调）
  - Seed-harness SFT（同规模成功轨迹，去掉 harness 进化）
  - EvoIn w/o Tailor（同规模原始轨迹，去掉改写）
  - All-Qwen（用目标模型自身充当提案者与改写模型）
  - Qwen rollout vs GLM-5.3 rollout（同一 1,752 任务配对，比较更强 rollout 模型的示范质量）
  - Gemma-4-31B-it（另一模型族，独立流水线与评测协议）
- **指标**：Pass（满分样本百分比）与 Score（rubric 得分×100，允许部分分）。

## 6. 主要结论与发现

- **主结果**：EvoIn 在 2,300 条 ID 样本上 Pass 从 35.96% 升至 46.83%（+10.87，相对 +30%）；在 2,064 条 OOD 样本上 Pass 从 18.99% 升至 28.20%（+9.21，相对 +48%）；ID Score +11.82，OOD Score +23.47。7 个 ID 任务组全部提升，6 个 OOD 基准全部提升，单项最高 +19.69（Table-Longer）。
- **进化必要**：仅用种子 harness 成功轨迹做 SFT，ID Pass 只 +1.87，OOD Pass 反而无提升（18.36 vs 18.99），说明增益主要来自 harness 进化带来的更好示范。
- **改写必要**：不做改写时 ID 变化不大（45.00 vs 46.83），但 OOD Pass 掉回 19.67（接近 Base）；未改写模型会在测试时引用不存在的「step 0 强制结构探测」、调用 H₀ 没有的工具，OOD 上 19.4% 样本耗尽 30 回合（EvoIn 仅 6.1%）。
- **可自驱动但有限**：All-Qwen 取得主系统约 56% 的 ID 增益（42.04 vs 35.96），但 OOD 仍停留在 Base 水平。
- **更强 rollout 更优**：GLM-5.3 示范把 ID Pass 提到 52.43、OOD Pass 提到 25.68，但 OOD Score 基本持平（49.65 vs 49.36），部分优势不迁移。
- **跨模型族有效**：Gemma-4-31B-it 上 ID Pass 49.61→53.04，OOD Pass 49.08→50.10。
- **学到的具体流程**：11/23 类别的最佳 harness 学会「先查文档长度，再决定全文阅读还是检索/分块阅读」；Faithfulness Verification 中形成短/中/长三档路由策略；模型还能对未见任务生成任务适配的决策流程，而非简单回放。
- **边界情况**：23 个类别中 21 个 Score 上升，Needle QA（−6.00）与 Long-Source Deliverables（−1.77）下降；复杂指令遵循提升最小，且 Pass 始终低于 10%。

## 7. 优点

- **问题切分清晰**：把「决策流程学习」从「工具/流程/适配的大杂烩」中剥离，用 (M,H₀)→(M,H*)→(M*,H₀) 的四范式框架明确区分于模型微调、harness 进化与协同进化，概念贡献明确。
- **评测设计严谨**：训练与评测都在原始 H₀ 下进行，直接回答「模型自身决策能力是否提升」而非「是否更适配 H*」，有效规避协同进化中的 harness 混淆。
- **改写机制工程扎实**：TAILOR 采用「稀疏编辑 + 重放 + 确定性检查 + 独立检查模型 + 一次定向修复」的闭环，明确禁止伪造工具调用与观测、禁止用 gold 作证据、要求引用行号与可见证据一致，并用 10 条固定轨迹做多轮迭代开发，质量控制可追溯。
- **泛化验证多角度**：同时验证域内、域外、跨模型族、更强 rollout 模型、目标模型自驱动，并用具体案例（Table QA 的排序与复核、长度自适应路由）展示学到的决策逻辑。
- **消融有针对性**：Seed-harness SFT 与 w/o Tailor 两个对照直接对应「进化」与「改写」两个核心组件，结论明确。

## 8. 不足与局限

- **尚未真正自提升**：进化仍由更强外部智能体（Claude Opus 4.7）引导，All-Qwen 变体虽能跑通但增益小、OOD 不迁移，离「智能体自主改进自身」还有距离。
- **只做一轮完整循环**：多轮流程进化后仅执行一次进化–内化循环，未验证递归自我改进（用更强的 M* 再进化再内化）是否有效。
- **任务覆盖偏窄**：实验集中在长上下文/文档推理场景，未覆盖软件工程、网页交互、长时程具身等环境，方法在工具密集、状态复杂场景下的适用性未知。
- **可复现性受限**：ID 训练数据与 Table-Longer 均不可公开，外部难以复现主结果；Gemma 运行使用独立协议，与 Qwen 结果不可直接比较。
- **评测偏差风险**：大量依赖 LLM judge，可能引入评审模型偏好；OOD Score 的巨大增益很大程度由 MRCR 的部分给分指标贡献，Pass 增益远小于 Score，指标解读需谨慎。
- **个别任务回退**：Needle QA 与 Long-Source Deliverables 出现下降，复杂指令遵循提升有限，说明内化并非对所有决策类型都同样有效。
- **算力信息缺失**：未报告 GPU 型号、数量与训练时长，成本与可扩展性无法评估。
- **方法边界讨论不足**：作者承认新工具、workflow、运行时组件无法完全被模型吸收，但仍缺乏对「哪些能力适合内化、哪些必须留在 harness」的量化判据。
