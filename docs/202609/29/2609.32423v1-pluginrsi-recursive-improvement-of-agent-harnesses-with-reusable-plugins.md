## 摘要
围绕语言模型的执行框架（harness）是智能体性能的核心决定因素。近期方法通过在完整程序空间中进行搜索来优化执行框架，但其中单个机制难以被分离和复用。我们提出 PluginRSI，它将执行框架表示为原子化插件的组合，并围绕这些插件组织执行框架的演化。各个插件被独立改进并累积到共享库中，然后在每次迭代时重新组合成新的执行框架。在软件工程、命令行交互和问答任务上，PluginRSI 优于现有的执行框架优化方法。所得的执行框架在无需进一步优化的情况下迁移到其他求解器模型时仍能保持其优势。演化后的插件库能够加速从初始执行框架开始的后续优化，从而有助于在未见任务上更快且更高程度地收敛。这些结果表明，累积可复用机制为持续改进执行框架提供了有效基础。

## Abstract
The harness surrounding a language model is a central determinant of agent performance. Recent methods optimize harnesses by searching over complete programs, where individual mechanisms are difficult to isolate and reuse. We introduce PluginRSI, which represents a harness as a composition of atomized plugins and organizes harness evolution around these plugins. Individual plugins are improved independently and accumulated in a shared library, then recombined into new harnesses at each iteration. PluginRSI improves over existing harness optimization methods across software engineering, command-line interaction, and question-answering tasks. The resulting harnesses retain their advantage when transferred to other solver models without further optimization. The evolved plugin library accelerates subsequent optimization from the initial harness, which helps faster and higher convergence on unseen tasks. These results show that accumulating reusable mechanisms provides an effective basis for continued harness improvement.

# PluginRSI 论文详细总结

## 1. 核心问题与研究动机

- **背景**：围绕语言模型构建的执行框架（harness，定义工具、角色、技能、记忆等交互机制及其协调方式）是决定智能体性能的核心因素。相比更新模型权重，优化 harness 无需训练成本即可适配智能体行为。
- **现有范式的问题**：近期的递归 harness 优化方法（如 DGM、Meta-Harness）把**完整 harness 程序**作为修改对象，通过执行反馈反复重写实现。这带来两个根本局限：
  - **机制探索受限**：多个机制耦合在同一实现中，难以独立探索新机制并评估其贡献，优化容易反复收敛到相似设计。
  - **有价值机制难以保存与复用**：重写可能覆盖掉有效的局部机制，改进无法跨迭代累积为可复用经验。
- **核心主张**：harness 演化应当以**发现新机制并在候选之间复用它们**为中心，而不是反复重写实现。为此作者提出 **PluginRSI**——面向"插件参数化 harness"的递归优化算法。
- **整体含义**：将现代插件化系统（如 DeepSeek Harness 的"一切都是插件"理念）与递归自我改进结合，使机制可被隔离、评估、累积与复用，为持续提升 harness 提供可积累的基础。

## 2. 方法论

### 2.1 核心思想
- 将 harness 表示为 **H = H(W, P)**：P 为选中的插件集合（实现角色/工具/技能/记忆等机制），W 为协调插件执行的 workflow，H 是把二者编译为可执行 harness 的确定性程序。
- 每个插件 = 标准化接口的 YAML 规格（输入输出 schema、prompt、rubric、元数据）+ Python 可执行实现，存放在版本化包 `<library>/<kind>/<name>/<version>/` 中。
- 维护**共享插件库 L**，保留经验上有效的实现，跨迭代累积并用于构造后续候选。

### 2.2 优化目标与形式化
- 目标：在固定策略模型 Θ 下最大化期望奖励
  J(H) = E_{x∼D, τ∼Φ(·|x,H,Θ)}[r(τ, x)]，求 H* ∈ arg max_H J(H)。
- 递归优化：第 t 轮，proposer Φ_proposer 基于当前最优 harness Ĥ_t 及其执行轨迹 T_Ĥt 生成新候选 H_t；proposer 与策略模型均固定不变。

### 2.3 算法流程（Algorithm 1）
每轮迭代包含两个阶段：
1. **插件变异（Plugin Mutation）**：
   - 并行生成 N 个变异候选，每个候选在 D_val 上单独采样一个**平衡 minibatch**（b 个任务，正确/错误各半），提供多样化反馈以鼓励机制多样性探索。
   - proposer 检查 H 及该 minibatch 的执行反馈，选择一个插件 p_i 并产出修改版 p'_i；其余插件与 workflow **保持不变**，重新编译为 H_i = H(W, (P \ {p_i}) ∪ {p'_i})。
   - 在该 minibatch 上评估 H_i，与 H 的同批得分比较；有经验增益的变体加入 L。
2. **Harness 重组（Harness Recomposition）**：
   - proposer 综合此前 harness 反馈与变异结果，从更新后的库中选择插件子集 P' ⊆ L，并修订 workflow W → W'（改变调用时机与信息流）。
   - 编译为 H' = H(W', P')，在完整 D_val 上评估；若得分更高则更新 incumbent。
- 运行 T 轮后返回 D_val 上最优的 harness；D_test 全程不参与优化。

## 3. 实验设计

- **问答（QA）**：来自 SuperGPQA、SciCite、FinanceQA、FrontierScience、OlympiadBench；每域采样 50 题（seed 50）。在 Olympiad-Math、SciCite、SuperGPQA-Economics 共 150 题上优化，在其余五个域（Finance、FrontierScience、Physics、Law、Medicine）共 250 题上评估。
- **指标**：SWE-bench / Terminal-Bench 用 resolve rate (%)，QA 用 accuracy。

### 3.2 对比方法
- **专家手工 harness**：ReAct（Zero-Shot / Few-Shot）、ACE（上下文 playbook 累积经验）。

### 3.3 模型设置
- Proposer：GPT-5.6 Terra、Kimi-K3（reasoning effort = xhigh）；Solver：GPT-5.6 Terra、Kimi-K3、GLM-5.2（reasoning effort = none/disabled）。

- 超参：T=15 轮，N=8 个变异候选/轮，minibatch b=20（10 解出 : 10 未解出），每轮 1 个重组候选，proposer 最大交互 40 轮、solver 20 轮、超时 360 秒，seed 42。

## 6. 主要结论与发现

- **跨场景有效性**：SWE-bench Verified 上，GPT 优化与 Kimi 优化分别达 held-out 65.00% 与 69.00%，超最佳基线 10.00 与 6.00 个百分点；Terminal-Bench 上 73.3% vs Meta-Harness 66.7%；QA overall 0.675 vs 0.638。
- **增益在未见任务上更大**：SWE-bench 上 held-out 增益（4.00/2.50 点）大于 held-in，说明发现的是可泛化机制而非任务特化。
- **跨模型迁移**：固定 harness 换 solver 仍保持优势（如 GPT 优化 harness 在 Kimi-K3 上 60.00%，GLM-5.2 上 52.00%），个别 held-in 交叉结果与基线持平。
- **优化效率更高**：以 solver rollout 数计，PluginRSI 更快达到 Meta-Harness 在预算内未达到的 held-in 水平，且 held-in 提升伴随 held-out 提升。
- **两阶段均必要**：去掉插件变异或 harness 重组，Kimi-K3 held-out 从 69.00% 降至 57.00% / 59.00%；而**仅提供插件库**（无论初始或空库）几乎无增益。
- **插件累积与复用**：库在 15 步内从 75 增至 132 个插件，候选代码量增至约 1300 LoC，但 workflow 保持 <300 LoC；复用演化库可显著加速从初始 harness 出发的后续优化（2 步 69%）。

## 7. 优点

- **问题建模清晰**：把"harness 演化"重构为"插件发现 + 累积 + 重组"，直接针对重写范式的两大痛点（耦合、不可复用）。
- **机制可隔离评估**：固定其余 harness 只改一个插件，使单个机制的因果贡献可被单独测量，避免了全局重写带来的贡献混淆。
- **可复用资产的显式沉淀**：插件库作为跨迭代、跨 harness、甚至跨起点的可迁移资产，并给出复用加速的量化证据。
- **评估协议较严谨**：held-in/held-out 严格分离、harness 在 held-in 上选择后冻结、跨 3 个 solver 迁移验证、相同 API 与沙箱，且对 GPT 系列 8 月底性能波动做了重跑以保公平。
- **附录翔实**：给出插件 schema、proposer 完整 prompt、初始 harness 代码、8 个具体变异案例（角色/技能/记忆/工具各一）与 token 成本，可复现性较强。
- **效率视角**：以 rollout 数而非迭代数比较，并披露额外 token 开销，权衡透明。

## 8. 不足与局限

- **实验覆盖有限**：仅在固定任务集上、有限迭代轮数（15 轮）内验证；任务分布随时间变化下的长期演化、以及插件库不断增长后的管理（去重、淘汰、检索）未探索。
- **迁移性受域与模型制约**：跨差异较大的 QA 域增益明显缩小（held-out 仅 0.568→0.588），数学推理发现的策略未必迁移到法律问题；held-out 与 held-in 共享仓库，未提供"未见仓库"的泛化证据（Seaborn/Flask 只出现在 held-in）。
- **变异评估的局部性偏差**：插件变异固定其余 harness，可能漏掉需要**插件间或插件-workflow 协同改动**才生效的机制；作者也将其列为未来工作。
- **算力信息缺失**：未报告 GPU 型号/数量/时长，仅给 token 与 rollout 口径，难以直接评估真实计算成本。
- **成本开销**：proposer 侧 token 增加（输出 +19.8%），插件库增长带来的存储与检索成本未量化。

- **伦理与应用限制**：自动演化的 harness 生成的代码与命令可能引入错误或非预期改动，作者建议在基准环境之外部署时需人工代码审查与执行权限控制。
