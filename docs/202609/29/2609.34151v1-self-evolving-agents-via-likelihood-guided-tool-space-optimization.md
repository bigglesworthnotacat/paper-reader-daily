## 摘要
自进化智能体能够持续改进其行为，而工具定义了它们与环境交互的可执行动作空间。然而，将完整工具库暴露给模型会引入大量无关上下文，并可能损害工具使用决策。我们研究工具空间自进化，其中每种反复出现的任务类型维护一个持久化工具空间，该空间由累积的输出经验构建而成。我们指出已有方法的三个局限：(1) 输出无感知的选择：它们主要依赖工具描述或模型先验，而非观测到的工具输出；(2) 跨请求无状态：它们为每个请求独立选择工具，未将先前的输出经验整合为持久化的任务特定状态；(3) 推理成本：对于同一任务的后续请求，它们会反复对候选工具进行搜索、排序或推理。我们通过输出感知的工具评分、持久化的任务特定工具空间、摊销式工具选择以及可跨模型复用的配置来应对这些局限。我们提出 LOTS（Likelihood-Only Tool Scoring，仅似然工具评分），它在保持模型参数固定的同时，从累积的输出经验中演化智能体的工具空间。在每个请求之后，LOTS 保留模型生成的答案，并通过测量移除某个工具所观测到的输出时答案似然的变化程度，来估计每个工具的贡献。这些贡献会在每个反复出现的任务内聚合，以对工具进行排序并更新其持久化空间。在三个基准上，LOTS 提升了任务性能，同时大幅减少了工具上下文。更重要的是，序列实验表明任务特定空间能够持续存在并随时间不断改进，而跨模型实验表明学习到的配置可迁移到不同模型。

## Abstract
Self-evolving agents can continually improve their behavior, while tools define the executable action space through which they interact with the environment. However, exposing the full tool library to model introduces substantial irrelevant context and can impair tool-use decisions. We study tool-space self-evolution, where each recurring task type maintains a persistent tool space which is constructed from accumulated output experience. We identify three limitations of existing methods: (1) output-unaware selection: they rely primarily on tool descriptions or model priors rather than observed tool outputs; (2) statelessness across request: they select tools independently for each request without consolidating prior output experience into persistent task-specific state; (3) inference cost: they repeatedly search, rank, or reason over candidate tools for subsequent requests of the same task. We address these limitations through output-aware tool scoring, persistent task-specific tool spaces, amortized tool selection, and reusable configurations across models. We introduce LOTS (Likelihood-Only Tool Scoring), which evolves an agent's tool space from accumulated output experience while keeping model parameters fixed. After each request, LOTS holds the model's generated answer and estimates each tool's contribution by measuring how much the answer likelihood changes when its observed output is removed. These contributions are aggregated within each recurring task to rank tools and update its persistent space. Across three benchmarks, LOTS improves task performance while substantially reducing tool context. More importantly, sequential experiments demonstrate that task-specific spaces persist and continue to improve over time, while cross-model experiments show that learned configurations transfer across different models.

# 论文总结：Self-Evolving Agents via Likelihood-Guided Tool-Space Optimization（LOTS）

## 1. 核心问题与研究动机

- **背景**：自进化智能体（self-evolving agents）能够从累积的交互经验中持续改进行为，而工具库定义了其可执行的动作空间。工具的说明与 schema 本身也构成推理时上下文的一部分。
- **结构性错配**：全局工具库会不断累积能力，但每个反复出现的任务（task type）通常只需要一个很小的、任务专属的工具子集。若每次请求都暴露完整工具库，无关工具会占用上下文，并扩大模型需要选择的候选集合，从而损害工具使用决策（论文 Figure 1 显示：注册表从 30 增至 240 个工具时，全量暴露的准确率从较高水平跌至 34.5%，而任务专属空间维持在 53.8% 以上）。
- **已有方法的三个局限**：
  1. **输出无感知（output-unaware）**：主要依赖工具描述或模型先验，在工具运行前做选择，未直接衡量工具的实际输出是否支持了最终答案。
  2. **跨请求无状态（statelessness）**：为每个请求独立选择工具，不把先前请求的输出经验整合为持久的任务级状态。
  3. **推理成本高**：注册表扩大后，每个新请求都要重复搜索、排序或推理候选工具，即使同一任务已被服务过很多次。
- **核心问题**：智能体能否从自身输出经验中演化出一个持久的工具空间，使后续请求被更准确、更高效地服务？论文提出 **LOTS（Likelihood-Only Tool Scoring）**，在**固定模型参数**的前提下实现工具空间自进化。

## 2. 方法论

### 2.1 核心思想
- 不训练、不修改模型参数 `pθ`，而是把**任务专属工具子集**作为持久化的部署状态（self-evolution through tool-space state）。
- 用「移除某工具输出后，模型已生成答案的似然下降多少」来估计该工具对本次执行的贡献，即**留一（leave-one-out）似然干预**。

### 2.2 请求级工具评分
- 对请求 `x` 与其已实现输出 `y_x`，记录上下文 `h_x`（含请求、工具文档、工具调用与观测输出）。
- 构造干预上下文 `h_x^{-s}`：移除工具 `s` 的输出证据。
- 定义贡献：
  `I_x(s) = Lθ(y_x | h_x) − Lθ(y_x | h_x^{-s})`，其中 `Lθ` 为答案 token 的平均对数似然。
- **两个关键设计**：
  1. 两次评分都**冻结同一个已生成答案**（teacher-forcing），不做新 rollout，只测工具证据对模型支持度的影响。
  2. 每次只移除一个工具，**其余工具仍在场**，从而保留组合式工具使用中的依赖关系（上游工具得分包含其经下游传播的效应）。
- 注：LOTS 不看正确性标签，衡量的是「模型依赖哪些工具证据」；实验显示正确与错误输出常给出相似的任务级排序。

### 2.3 任务级空间构建
- 任务级贡献：`Ī_t(s) = (1/|Q_t(s)|) Σ_{x∈Q_t(s)} I_x(s)`，其中 `Q_t(s)` 是暴露并可为 `s` 打分的请求集合（未暴露的请求不计为 0）。
- 按 `Ī_t(s)` 排序，取 top-K：`E_t = TopK_{s∈A_t} Ī_t(s)`。
- **理论支撑（Theorem 1）**：把 top-K 选择解释为对固定输出似然目标 `F(A)` 的加性近似 `F̂(A)` 的最大化；在二阶交互 `|Δ_{s,u}F(B)| ≤ β` 有界时，近似误差 ≤ C(r,2)β，选择差距 ≤ r(r−1)β（r = m − K），r ≤ 1 时精确。

### 2.4 持续演化与更新
- 任务空间持久保存，用于该任务后续所有请求；新任务到达时独立构建其空间：
  `E_{t-1} → E_t = E_{t-1} ∪ {E_t}`。
- 同一任务的新批次经验可继续修正空间：`E_t^{(k)} → E_t^{(k+1)}`。
- 运行分数用指数移动平均更新：`Ĩ_t(s) ← α·Ī_t^{(k)}(s) + (1−α)·Ĩ_t(s)`；未被暴露的工具分数不衰减。
- 有服务上限 `C` 时，以概率 ε 进行探索（当前空间 + 随机采样其他工具），这是空间外工具获得证据的唯一途径。
- 存储状态仅为**运行分数 + 工具名列表**，不存储模型参数或提示。

### 2.5 算法流程（Algorithm 1）
1. **Serve**：在候选空间下执行请求批次，记录轨迹 `(h_x, y_x)`；
2. **Score**：对每个暴露且可打分的工具计算 `I_x(s)`；
3. **Aggregate**：在任务内聚合得 `Ī_t(s)`；
4. **Prune**：取 top-K 形成 `E_t`（证据不足 K 时保留全部有证据的工具）；
5. **Deploy**：存储 `E_t` 服务该任务后续请求，有新证据时重复更新。

- **跨模型复用**：BFCL 上 10 执行模型 × 11 源模型的完整迁移矩阵（Table 5），以及主协议下 9 组源–执行对（Table 6，Figure 6 中 20 对里 18 对超过 Keep all）。
- **消融与分析**：固定预算对比（Table 9）、评分目标对比（Table 14）、删除操作对比（Table 18）、Shapley/LLM judge 对比（Table 15/17）、错误输出鲁棒性（Figure 18）、轨迹数量敏感性（Figure 19）、注册表规模扩展（Figure 21）、预算敏感性（Figure 8）、GTA-Atomic 全部 15 个工具对枚举（Table 16）。
- **充分性评价**：实验组数非常多，覆盖多基准、多模型、多消融，并给出置信区间/多种子与配对 bootstrap，**整体较为充分且客观**。但存在一些需要注意的点：
  - BFCL 与 GTA-Atomic 的评估集较小（40 条/类、112 条），单条答案即带来 2.5 个百分点波动。
  - TGB 为合成基准，请求由 family 模板生成，对聚类路由实验偏「有利」。
  - 预算 K 的选择在实验中使用了拟合标签（作者明确标注这一点），核心评分本身无标签。

## 6. 主要结论与发现

- **性能提升**：TGB 上 LOTS 在全部 8 个模型上超过 Keep all（3.8–25.0 个百分点），平均保留 2.8–6.8 个工具（均值 4.4/15）；BFCL 上 5 个模型中 3 个最优、另 2 个与最优差 0.21 点；GTA-Atomic 上 7 个模型中 6 个超过 Keep all。
- **空间质量**：TGB 上 LOTS 选出的空间普遍包含 gold 工具链（Qwen2.5-7B 上每个 family 都含链，5 个 family 恰好等于链）；likelihood 排序对参考链工具的 AUROC 在 71/72 个「模型–family」对上为 1.000 或 0.992。
- **持久演化有效**：跨任务到达流中 LOTS 始终高于 Keep all（如 0.87 vs 0.49），21 次运行全部胜出；任务内多次更新可持续改进不完整空间（冷启动 + 服务上限场景 0.27 vs 随机 0.01 / 并集 0.02）。
- **效率**：GTA-Atomic read_arith 上总 token 比 TTO 少 2.0–4.0×、比 Beam Search 少 4.4–9.5×；TGB 服务提示 token 减少 33–46%。
- **跨模型可迁移**：源模型拟合的排名在 18/20 个跨模型组合中优于目标模型的 Keep all，说明学到的是任务级偏好而非模型特异的怪癖。
- **机制发现**：输出证据的贡献排序与任务执行效用高度相关；即使输出错误，仍能保留有用证据；支持频率式保留比均值分数保留对答案污染更鲁棒。

## 7. 优点

- **方法层面**：
  - 用「冻结答案 + 留一似然」做工具归因，无需正确性标签、无需额外 rollout，思路简洁且有理论刻画（Theorem 1）。
  - 保留工具间的组合依赖（上游工具得分含下游传播效应），适合链式/组合式工具使用。
  - 把经验存成**可执行工具空间**而非文本记忆，是一个有价值的状态载体选择。
  - 摊销式选择：拟合一次、服务多次，显著降低重复选择成本。
- **实验层面**：
  - 三类差异较大的基准（合成组合、多轮函数调用、可执行 ReAct），结论一致性强。
  - 消融丰富：评分目标、删除操作、聚合规则、评分模型、LLM judge、Shapley、预算敏感性、注册表规模、轨迹数量等。
  - 报告了成本与摊销回收点，工程视角完整。
  - 跨模型复用实验设计巧妙，且明确区分「有标签」与「无标签」方法。

## 8. 不足与局限

- **方法依赖**：
  - 需要访问模型的**似然**，对只提供 API 的黑盒模型，只能在拟合阶段用开源模型代理（作者提出这是可扩展方向，但未实证）。
  - 需要任务归属（metadata 或聚类路由）；聚类实验显示「过分裂便宜、合并代价高」，路由质量直接影响效果。
  - 依赖每个请求的**可干预轨迹**：需要能移除工具输出并重放上下文（TGB 靠确定性重执行，BFCL 靠移除调用步，GTA-Atomic 靠删除单行），在真实复杂环境中未必总能干净地做留一干预。
- **实验覆盖**：
  - BFCL / GTA-Atomic 评估集较小，统计噪声不可忽略（作者也承认单条答案 = 2.5 点）。
  - TGB 是合成基准，请求由模板生成，任务可分性强，结论向真实请求流的外推需谨慎。
  - 跨模型复用虽显示迁移性，但排名仍按源模型拟合，最优配置往往是「自拟合」而非「迁移」。
- **应用与安全限制**：
  - 似然分数衡量的是「模型对自身答案的支持度」，**不保证答案正确，也不保证工具安全**；作者在 Ethics Statement 中明确指出实验未建立自主执行的安全性。
  - 需要适当的工具权限与人工监督。
  - 预算 K 的选择在实验中使用了拟合标签（虽非核心机制），完全无标签部署时预算选择需要另设规则。
- **成本**：虽然摊销后节省明显，但拟合阶段的打分成本随注册表规模增长较快（120 工具时约 8,158 秒/单卡），对超大工具生态的可扩展性仍有压力。
