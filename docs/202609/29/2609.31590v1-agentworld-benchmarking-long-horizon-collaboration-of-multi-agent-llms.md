## 摘要
现有的多智能体基准测试主要在竞争性环境、20步以内的短时程交互中进行，或仅汇总个体性能，未能分离并凸显基于LLM的智能体真正的协作能力。我们提出AgentWorld，一个包含100个人工标注任务（以及100个增强变体）的基准，用于评估长时程、多智能体协作。任务在丰富的MMORPG沙盒中跨越50+轮交互，需要3-20个具有非对称角色和能力的智能体，在黑箱设置下通过通信、联合规划和资源共享进行协调，其中每个智能体独立行动，无法访问其他智能体的内部状态。为在传统的二元任务成功之外量化协作有效性，我们提出因果协作有效性（Causal Collaboration Effectiveness, CCE），一种基于图的指标，追踪智能体动作之间的因果依赖，并衡量团队努力中实际对结果有贡献的比例。使用Gemini 3 Flash、Claude Haiku 4.5、GPT-5 Mini和DeepSeek R1-70B的实验表明，即使最佳模型也仅达到52.0%的任务成功率，并存在系统性失败模式，包括通信中断、角色混淆以及无法在轮次间维持共享计划。AgentWorld完全开源。

## Abstract
Existing multi-agent benchmarks primarily test in competitive settings, short-horizon interactions under 20 steps, or simply aggregate individual performance, failing to isolate and highlight genuine collaboration capabilities of LLM-based agents. We introduce AgentWorld, a benchmark of 100 human-annotated tasks (with 100 augmented variants) for evaluating long-horizon, multi-agent collaboration. Tasks span 50+ interaction rounds across a rich MMORPG sandbox and require 3-20 agents with asymmetric roles and abilities to coordinate through communication, joint planning, and resource sharing under a blackbox setting where each agent acts independently without access to others' internal states. To quantify collaboration effectiveness in addition to conventional binary task success, we propose Causal Collaboration Effectiveness (CCE), a graph-based metric that traces causal dependencies between agent actions and measures what fraction of a team's effort actually contributed to the outcome. Experiments with Gemini 3 Flash, Claude Haiku 4.5, GPT-5 Mini, and DeepSeek R1-70B show that even the best model achieves only 52.0% task success, with systematic failure modes including communication breakdowns, role confusion, and inability to maintain shared plans across rounds. AgentWorld is fully open-source.

# AgentWorld 论文结构化总结

## 1. 核心问题与研究动机

- **背景**：LLM 智能体已从单轮推理走向自主工具使用与多步规划，多智能体协作（MAC）成为关键能力；但系统评估该能力的基准仍严重不足。
- **现有基准的三大缺陷**：
  - **时程过短**：多数基准交互步数 ≤20 步，无法评估持续性协调；
  - **混淆控制与协作**：如 Minecraft 类环境迫使智能体消耗大量预算在精确 3D 导航、方块放置等低层控制上，协作能力难以对分数产生实质影响；
  - **缺乏可测目标**：Project Sid 等大规模社会模拟关注涌现社会行为，而非有明确可验证结果的协作任务。
- **论文含义**：提出 AgentWorld——一个基于 MMORPG 沙盒、面向**长时程、黑箱、非对称角色**多智能体协作的基准，并配套提出衡量"协作是否真的有用"的新指标 CCE，旨在把协作能力从个体能力与动作控制能力中剥离出来。

## 2. 方法论

### 2.1 环境设计（沙盒与接口）
- 基于开源 MMORPG 引擎 **Kaetram**：1056×768 tiles、9 种生物群系、380+ 物品、144 种怪物（Lv1–250+）、70+ NPC、1531 个可采集资源节点、8 种技能；仿真器支持最多 **1,000 个并发智能体**。
- **13 个高层 API 工具**（move、attack、harvest、craft、transfer、chat 等）：单次调用封装寻路、战斗、采集、掉落回收等完整多步机制，使智能体把决策预算花在"做什么、和谁协调"而非"怎么做"。
- **回合制轮询协议**：每轮每个智能体顺序接收新观测 → 选一个工具调用 → 等动作结算后再轮到下一个，保证确定性回合顺序，便于复现。
- **黑箱设置**：智能体无法访问他人内部状态、观测与动作历史，协调只能依靠经环境路由的显式 chat 消息。

### 2.2 任务设计
- 每个任务包含：主目标（必须多智能体协作完成）、智能体配置（非对称角色/技能/出生点/初始物品）、回合预算、任务特定上下文文档、Python 成功判定函数。
- 任务保证**任何单一智能体都不具备全部技能或资源**，需联合规划、资源共享与跨区域时序协调（如 Task 67 需 8 个智能体跨 3 个生物群系，Task 100 为 16 智能体全图调查）。

### 2.3 评估指标
- **SR（任务成功率）**：由每任务 Python 验证器检查最终游戏状态（物品计数、击杀数、存活等），必要时检查轨迹。
- **PSR（部分成功率）**：按检查点完成比例计算的软指标。
- **CCE（因果协作有效性）**：
  - 构建**因果动作图（CAG）** $G=(T,E)$，节点为所有动作（含 chat），有向边 $x \to y$ 表示 $x$ 因果使能 $y$；因因果只向前流动，图为 DAG。
  - 先由 LLM 识别直接达成目标的**成功动作集 $S$**，再从 $S$ 出发做 BFS 式**反向追踪**，逐轮询问"该动作是否因果使能了已确认的贡献动作"，累积得到贡献集 $C = S \cup \text{ancestors}(S)$。
  - $$\text{CCE} = \frac{|C|}{|T|}, \quad \text{PAC}_i = \frac{|C \cap T_i|}{|T_i|}$$
  - 失败任务 CCE = 0；CCE ≈ 1/N 表示只有单个智能体在做贡献；CCE ≈ 0 表示混乱失败。
- **关键设计取舍**：LLM 只做**二元因果判断**（"捕虾是否使能了后续转移虾"），不做主观质量打分（"协作打 1–5 分"），以提升跨评委模型版本的可复现性；采用**宽松包含策略**，边际有帮助的动作也算贡献，故 CCE 应读作"真正有用动作比例的上界"。
- **工程优化**：按资源类型/位置/通信通道剪枝、批量因果查询、时间窗口限制，避免 $O(|T|^2)$ 查询。

### 2.4 数据构建
- 5 名标注者按预定类别分布设计任务，含互补角色配置、带中间检查点的目标、Python 验证器与每智能体专属游戏文档；经两个 LLM 的 pilot 实验迭代，直到仅剩智能体错误为止。
- 回合预算（25–55）由 pilot 实验校准；另用 Claude Opus 生成 **100 个增强变体**（改变目标、出生点、初始物品），并做人工校验。

## 3. 实验设计

- **数据集/场景**：100 个人工标注主任务 + 100 个 LLM 增强变体，覆盖 8 类（combat、crafting、gathering、trading、exploration、survival、construction、coordination）；每任务 3–20 个智能体（多数为 3 个，长尾至 20），时程 25–55 轮（平均 38 轮）。
- **对比模型**：4 个前沿模型——Gemini 3 Flash、Claude Haiku 4.5、GPT-5 Mini、DeepSeek R1-70B（统一系统提示、用户提示模板与 API 工具定义）；另报告 Muse-Glimmer-30B（最终结果）与 Gemma 4 26B A4B（暂定结果，在 100 任务增强 v1 划分上）。
- **基线（Gemini 3 Flash）**：
  - random actions（无 LLM，仅 5.7% SR）
  - single-agent（全部角色/物品归一个智能体，28.6%）
  - no-communication（禁用 chat，22.9%）
  - shared-plan-no-communication（先给人类写的共享计划，17.6%）
  - oracle communication（一个智能体可见全部消息并协调全队，作为通信质量上界，60.0%）
- **消融（35 任务子集）**：去非对称角色信息、时程从 50 缩至 10 轮、随机出生点、去掉任务文档。
- **鲁棒性/验证实验**：3 个种子（42/819/314，temperature 0.7）重复运行；3 个 CCE 评委模型（GPT-4.1、Claude Sonnet 4、Llama-4 Maverick）；人类标注 84 条动作-贡献判断与 GPT-4.1 对齐度检验；Gemini 3 Flash 100 条轨迹的通信失败模式聚类（6 类）。

  - Gemma 4 结果为暂定、按已评分任务平均，Muse-Glimmer 的评测条件说明较简略；

## 6. 主要结论与发现

- **绝对性能低**：最佳模型 Gemini 3 Flash 仅 52.0% SR（PSR 71.5%，CCE 0.320）；Claude Haiku 4.5 45.0%/0.294；GPT-5 Mini 36.0%/0.206；DeepSeek R1-70B 20.0%/0.125。**27% 的任务无任何模型解决**。
- **大量动作无效**：即使最佳模型也有不到 1/3 的动作位于因果路径上；DeepSeek 近 88% 动作被浪费。
- **CCE 排序与 SR 一致但提供额外信息**：条件于成功任务时，Claude 的每任务协作效率最高（0.653 vs Gemini 0.609），GPT-5 Mini 最低（0.571），与其高动作数、过度闲聊一致。
- **沟通多 ≠ 协作好**：GPT-5 Mini 发消息最多（44.1 条/任务）但 SR 仅第三；DeepSeek 最少（7.5 条）且最差，首次发言平均延迟到第 5 轮；Gemini 适中（11.0 条）却最优，提示存在"最优沟通区间"。
- **类别难度分化显著**：survival 最易（跨模型 50–100%），coordination（0–50%）、construction（0–60%）、trading（8–46%）最难，反映紧密同步与协商的困难。
- **增强集普遍大幅下降**（Gemini 52→24%，DeepSeek 20→10%），且需要更多轮次与动作。
- **基线对照**：random 5.7% < shared-plan-no-communication 17.6% < no-communication 22.9% < single-agent 28.6% < vanilla 52.0% < oracle 60.0%；共享计划反而略差，说明计划价值取决于执行中能否修订；即便 oracle 通信仍有 40% 失败，说明困难本质上来自长时程规划与资源分配。
- **消融**：去文档降幅最大（54.3%→29.4%），缩短时程次之（→37.1%），去非

（接上文）对称角色信息导致的降幅最小（54.3%→48.6% 左右），随机出生点的影响居中；说明**任务文档承载了关键的共享上下文与接口约定**，而时程长度与角色互补性是协作难度的重要来源，但对角色信息的显式披露相对不敏感——智能体可通过 chat 自行协商角色分工。

- **通信失败模式（6 类聚类）**：论文对 Gemini 3 Flash 的 100 条轨迹做错误聚类，可归纳为——① **无协调发起**（无人主动分配任务，各自为战）；② **消息被忽视**（有请求但收件方未读取或未响应）；③ **指代含糊**（"去拿那个东西"缺乏坐标/物品名）；④ **分工冲突**（多个智能体抢同一资源或重复制造同一物品）；⑤ **交接失败**（约定转移物品但转移动作未执行或对象错误）；⑥ **计划漂移**（前期约定在长时程中被遗忘或放弃）。这些模式共同指向"通信—执行"之间的落地缺口，而非单纯的语言表达问题。

## 7. 讨论与启示

- **协作瓶颈的定位**：oracle communication 上界仅 60%，且 single-agent（28.6%）低于 vanilla 多智能体（52.0%），说明**多智能体增益确实存在，但并非来自"人多力量大"，而来自角色互补与并行执行**；真正的天花板是长时程规划、资源分配与跨区域时序协调。
- **"最优沟通区间"假说**：消息数量与 SR 呈倒 U 型关系（DeepSeek 7.5 条/任务最差，GPT-5 Mini 44.1 条/任务次差，Gemini 11.0 条/任务最优），提示**高质量、低冗余、目标导向的通信**优于高频闲聊，也优于沉默。这一发现对多智能体系统的 prompt 设计与通信协议有直接指导意义。
- **CCE 的方法论价值**：将协作质量从结果指标中解耦，使"任务失败但协作良好"与"任务成功但靠单点英雄"可被区分；条件 CCE（仅统计成功任务）能进一步刻画"成功得是否经济"。作者强调 CCE 应读作有用动作比例的**上界**，适合做模型间相对比较而非绝对阈值。
- **黑箱与非对称设计的意义**：强制显式通信使评估聚焦"可观测的协调行为"，避免了共享内存/全局状态带来的作弊空间，也让基准更贴近真实分布式智能体部署场景。

## 8. 局限与未来工作

- **评测覆盖有限**：方差与消融分析仅在 35 任务子集、单一模型上完成；重复运行结果完全一致，无法支撑统计显著性主张，模型间差距的稳健性存疑。
- **指标依赖 LLM 判断**：CCE 与部分验证器依赖 LLM（GPT-4.1 等）做因果/成功判定，虽有人类标注（κ=0.64）与多评委一致性（κ=0.66）背书，但仍存在评委模型自身的偏见与版本漂移风险；宽松包含策略使 CCE 偏向高估。
- **环境单一**：仅基于 Kaetram 一个 MMORPG 沙盒，任务由 5 名标注者手工设计，类别分布与难度校准可能带有设计者偏好；LLM 生成的 100 个增强变体虽经人工校验，但多样性仍受主任务模板约束。
- **未量化的成本**：算力与 API 成本完全缺失，影响可复现性与后续研究的成本预估。
- **未来方向**：作者建议扩展到更多环境与模态、引入动态/对抗性智能体、开发更细粒度的协作诊断指标（如通信效用、交接成功率），并在多模型、多种子上做系统性统计检验。

## 9. 总体评价

- **贡献**：AgentWorld 填补了"长时程、黑箱、非对称、目标可验证"多智能体协作基准的空白；13 个高层 API 与回合制协议有效剥离了低层控制噪声；CCE 及其因果动作图方法为协作质量提供了可操作、可复现的量化工具，是该论文最具方法学新意的部分。
- **实证价值**：揭示了当前前沿模型在长时程协作上的系统性短板（最佳 52% SR、27% 任务零解、大量动作无效），并给出"通信量非单调有益""共享计划若无执行中修订反而不如无计划"等反直觉但有说服力的发现。
- **待改进**：统计严谨性（单模型、零方差）、算力透明度、指标上界偏差与评测成本披露是主要短板；建议读者将其结论视为**方向性证据**而非精确排名，尤其不宜据 CCE 绝对值做跨研究比较。
- **适用场景**：适合作为多智能体 LLM 系统的长时程协作诊断床、通信协议与角色分配策略的消融平台，以及 CCE 类因果贡献度量的方法参照。
