## 摘要
AI智能体将语言模型与能够修改文件、调用API或执行代码的外部数据和工具相结合。当对抗性内容改变智能体的工具使用，或周边软件包含路径遍历、命令注入等漏洞时，就可能出现安全失效。我们研究经授权的白盒部署前审计：审计者可以访问目标代码仓库和受控运行时，但成功攻击仍必须通过任务定义的攻击者接口实施，并由外部验证器确认。我们提出AgentXploit，这是一种双角色审计系统，将仓库级攻击路径发现与运行时利用分离。Analyzer Agent追踪攻击者可控输入到敏感操作的路径，并记录有代码支持的候选攻击路径；Exploiter Agent将这些路径转化为具体攻击，并利用运行时反馈对其进行修正。我们还提出AgentXploit-Bench，包含跨12个开源AI智能体系统和框架的72个可复现漏洞。在三次运行中，AgentXploit达到59.3%的端到端成功率，而Codex为38.4%。在token预算匹配的比较下，Codex达到46.3%。在提供注入点的AgentDojo上，Exploiter Agent达到79.2%的攻击成功率，而AgentVigil为52.7%。这些结果凸显了仓库发现与运行时利用是端到端智能体安全审计中两个不同的挑战。

## Abstract
AI agents combine language models with external data and tools that can modify files, call APIs, or execute code. Security failures can arise when adversarial content changes an agent's tool use or when the surrounding software contains vulnerabilities such as path traversal or command injection. We study authorized white-box pre-deployment auditing, where the auditor has access to the target repository and a controlled runtime, but successful attacks must still act through the task-defined attacker interface and be confirmed by an external verifier. We present AgentXploit, a two-role auditing system that separates repository-level attack-path discovery from runtime exploitation. The Analyzer Agent traces attacker-controlled inputs to sensitive operations and records code-supported candidate attack paths; the Exploiter Agent turns these paths into concrete attacks and revises them using runtime feedback. We also introduce AgentXploit-Bench, containing 72 reproducible vulnerabilities across 12 open-source AI-agent systems and frameworks. Across three runs, AgentXploit reaches 59.3% end-to-end success, compared with 38.4% for Codex. Under a token-budget-matched comparison, Codex reaches 46.3%. On AgentDojo, where injection points are provided, the Exploiter Agent reaches 79.2% attack success versus 52.7% for AgentVigil. These results highlight repository discovery and runtime exploitation as distinct challenges in end-to-end agent security auditing.

## 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：LLM 智能体（Agent）将语言模型与外部数据、工具（文件修改、API 调用、代码执行）结合，攻击面同时来自两侧：一是模型行为（对抗性内容诱导敏感工具调用，如提示注入），二是周边软件本身的传统漏洞（路径遍历、命令注入、SSRF 等）。
- **核心问题**：现有智能体红队方法大多**假设注入点或攻击面已知**，只关注"如何优化对抗输入"，而不回答"审计者能否从代码实现本身发现一条可行的攻击路径"。在仓库级智能体中，可行路径取决于：哪些输入真正被消费、值如何跨组件传递、影响了哪些模型/控制流决策、工具前置条件是否成立。
- **研究设定（威胁模型）**：经授权的**白盒部署前审计**——审计者可访问目标仓库与受控运行时，但攻击必须：
  - 通过任务定义的**攻击者接口**（API、用户查询、上传文件、外部数据源）实施；
  - 由**外部确定性验证器**确认成功（智能体不能自行判定成功，也不能读取/修改受保护目标状态）。
- **关键区分**：论文提出"仓库发现"与"运行时利用"是两个**不同性质的安全审计瓶颈**，并据此设计系统与基准。攻击路径进一步分为：
  - **直接路径（Direct）**：入口点可通过攻击者接口直接到达（如 API）；
  - **间接路径（Indirect）**：入口来自智能体后续消费的外部数据源（如检索文档、工具响应），攻击需先影响模型决策再影响下游操作。

## 2. 方法论：核心思想、关键技术与流程

### 2.1 总体架构：双角色 + 外部验证器

- **Analyzer Agent（分析智能体）**：在仓库中搜索，追踪攻击者可控输入到敏感操作，输出**机器可读的候选攻击路径记录**。
- **Exploiter Agent（利用智能体）**：读取该记录，只通过攻击者接口构造并执行具体攻击，依据运行时反馈迭代修正。
- **外部 Verifier**：位于两个智能体之外，检查受保护状态（文件、数据库、出站请求、命令副作用等），判定成功。
- **交接记录字段**：路径类型、具体入口点、敏感操作、支撑代码位置、必要前置条件、可选的利用提示。该记录在通过验证器前**只是假设**。

### 2.2 Analyzer Agent 控制流程（文字化算法）

1. 映射仓库结构，为外部接口、工具定义、敏感 API、相关配置创建初始 Explore / Search / Read 任务；
2. 执行最高优先级任务，调用目录浏览、文本搜索、文件读取、依赖分析、符号、AST、LSP 等工具；
3. 将新的代码位置、数据流关系、工具行为、未决链接写入**报告**（保存在模型上下文之外，后续步骤读取报告而非完整交互历史）；
4. 当证据足以支撑可行路径时，创建/更新候选攻击路径记录；Summarize 任务合并证据与当前候选；
5. 队列耗尽或达到分析预算时终止，将候选记录交给 Exploiter Agent。
- **优先级策略**：优先连接"外部值 → 敏感操作"或闭合候选路径中未决链接的证据。
- **特点**：不向 Analyzer 提供 ground-truth 入口点，需自行判断哪些值真正可控、如何被转换、在什么条件下可达敏感操作。

### 2.3 Exploiter Agent 攻击构造与修正

- 对实现层漏洞：遵循标准代码智能体循环——查看相关代码 → 构造输入 → 对目标执行 → 依据运行时报错修正。
- 对 LLM 中介型攻击：
  - **初始攻击选择**：维护注入种子语料库（含场景、攻击者目标、候选注入位置、载荷模式），模型选择匹配目标工作流的种子并**改写**而非原样重放；
  - **执行后修正**：下一轮提示包含上一轮载荷、目标响应与允许的执行轨迹，避免从无关提示重新开始；
  - **多注入点协调**：跨多个外部记录放置**相互一致**的指令（早期记录建立身份/触发线索，后续记录重复或激活同一攻击目标）。

## 3. 实验设计：数据集、Benchmark 与对比方法

### 3.1 AgentXploit-Bench（主基准）

- **规模与来源**：72 个可复现漏洞实例，来自 12 个开源 AI 智能体系统/框架，取自 2023–2025 年公开 CVE 与智能体安全问题（含 NVD 记录），经 LLM 辅助筛选 + 人工逐条核对。
- **保留标准（三条同时满足）**：① 具体安全影响（命令执行、未授权文件访问、数据外泄、SSRF 等）；② 可无专有基础设施地复现运行；③ 存在外部确定性验证器。
- **框架分布**：GPT_Academic 22（30.6%）、OpenClaw 10（13.9%）、AgentScope 9（12.5%）、LangChain 8（11.1%）、LobeChat 8（11.1%）、LlamaIndex 4（5.6%）、AutoGPT 3、DB-GPT 2、GPT-Researcher 2、MetaGPT 2、OpenHands 1、RAGFlow 1。
- **三种评测模式**（Table 2）：
  - **Analysis-only**：仅给仓库，不执行目标，衡量 ground-truth 攻击路径的恢复；
  - **Exploit-only（oracle）**：给出漏洞描述、敏感操作与攻击目标，衡量"已知路径下的利用构造"；
  - **End-to-end（主指标）**：给仓库与运行时，隐藏漏洞元数据，衡量发现 + 利用的联合成功。
- **信息隔离**：analysis-only 与 end-to-end 模式不提供 CVE/issue 编号、漏洞描述、目标函数、利用字符串、补丁讨论、目标特定成功条件；exploit-only 才提供 oracle 字段。
- **路径分布**：直接路径 59 条，间接路径 13 条。

### 3.2 AgentDojo（利用阶段独立评测）

- 4 个套件、629 个用户任务 × 注入任务组合，**注入点预先给定**，因此隔离"攻击构造"而非"仓库发现"。
- 每个任务最多 50 轮迭代；受害者智能体统一使用 GPT-4.1。

### 3.3 对比方法

- **Codex CLI（gpt-5.1-codex）**：端到端仓库基线，单智能体自主搜索/读码/用 shell/与目标交互，接收相同任务输入、仓库、攻击接口与成功判据，但不含隐藏元数据与 Analyzer 报告；三种预算条件（默认 1×、4×、token 匹配）。
- **AgentVigil**：自动化黑盒红队方法（AgentDojo 对比）。
- **Handcrafted 攻击模板**：AgentDojo 自带手工注入基线。
- **消融**：去除精选种子语料（换用 OpenPromptInjection / InjecAgent / AgentDojo / SecAlign 混合语料）、去除执行轨迹反馈（w/o Context-aware）、单一载荷跨注入点（w/o Multi-inject）。
- **代码变异鲁棒性实验**：重命名函数/类/局部变量、删注释与 docstring、移动实现文件并更新导入，保持语义、接口、验证器不变。
- **攻击质量诊断**：10 条 OWASP ModSecurity CRS v3.3 规则（路径遍历、RCE、执行函数、反引号注入）+ 攻击前后各 3 次良性 API 请求。

## 6. 主要结论与发现

- **端到端主结果**：AgentXploit 平均 59.3%，Codex 38.4%（差 20.8 个百分点）；间接路径差距更大（59.0% vs 28.2%，30.8 点）> 直接路径（59.3% vs 40.7%，18.6 点）。
- **算力匹配后**：Codex 提升至 46.3%（4× 为 45.8%），仍落后 AgentXploit 13.0 个百分点；token 匹配使 Codex 直接路径 +7.3、间接路径 +10.3，但差距仍为 11.3 与 20.5 点。
- **诊断结果**：Analyzer 恢复 71.8% 的 ground-truth 路径（直接 74.6%、间接 59.0%）；oracle 条件下 Exploiter 达 88.0%（直接 91.5%、间接 71.8%）。
- **失败定位**：初始端到端运行 29 个失败中，20 个（69.0%）属**分析阶段漏检**；5 个间接路径失败**全部**发生在利用之前 → 仓库发现是独立的、常被忽视的瓶颈。
- **框架不均衡**：GPT_Academic 占 22 实例，AgentXploit 19/22（86.4%）vs Codex 14/22（63.6%）；剔除后 AgentXploit 48.0% vs Codex 28.0%，说明整体均值掩盖了跨仓库差异。
- **AgentDojo**：Exploiter 79.2% vs AgentVigil 52.7% vs 手工 41.5%；分套件 Bank 0.750、Slack 1.000、Travel 0.754、Work 0.742。
- **消融结论**：种子语料影响最大（去掉后降至 49.6%）；执行轨迹反馈改善后期修正（79.2% vs 69.1%）；多注入点协调收益较小（74.9%）。种子决定初始搜索区域，轨迹改善迭代修正。
- **候选质量**：OpenHands 5 个候选中，2 个为范围内有效漏洞、1 个为范围外但安全相关、2 个假阳性 → 范围内精度 40%，安全相关率 60%，说明恢复率会掩盖分诊成本

- **代码变异鲁棒性**：在保持语义与接口不变的重命名、去注释、移动文件三类变异下，AgentXploit 与 Codex 的性能变化均在噪声范围内，说明其优势不依赖于特定标识符或注释线索，而是建立在数据流与控制流的结构性推理上；这也间接回应了"是否只是记住了训练中的 CVE 字符串"这一质疑——尽管作者仍不声称完全排除预训练污染。
- **攻击质量诊断（WAF 视角）**：在 OWASP ModSecurity CRS v3.3 的 10 条规则下，多数成功载荷并非"经典注入字符串"，而是语义化、贴合任务上下文的自然语言指令与合法 API 调用组合；这意味着传统基于签名/正则的边界防御对 LLM 中介型攻击的拦截能力有限。同时，攻击前后各 3 次良性请求未出现显著功能退化，说明利用过程本身对目标正常工作流的扰动较小，具备"低噪声"特征。
- **额外发现（非目标漏洞）**：在审计过程中额外发现 8 个未被基准收录的漏洞，覆盖 4 个项目、5 个类别，表明该流程具有一定的**零样本泛化发现能力**，而非仅对已知 CVE 的复现装置。
- **停止行为分析**：对 216 条 Codex 默认预算轨迹的逐条归类显示，基线常在"已接近可行路径但预算耗尽"或"在无关文件间反复搜索"处停止，而 AgentXploit 通过报告机制将证据外置、以任务队列驱动探索，减少了在上下文窗口内反复回溯造成的浪费——这解释了在 token 匹配条件下其仍能保持领先的原因。

## 7. 局限性与未来方向

- **模型家族单一**：全部实验基于 gpt-5.1-codex，未验证跨模型（如 Claude、Gemini、开源权重模型）的可迁移性；主干能力变化可能同时影响 Analyzer 的发现质量与 Exploiter 的构造能力。
- **基准规模与构成**：72 个实例中 22 个来自单一框架（GPT_Academic），且间接路径仅 13 条，统计效力有限；作者通过分层报告缓解，但未做严格的显著性检验。
- **人工判定环节**：analysis-only 的路径匹配与候选质量审计依赖人工规则，存在主观性；候选精度仅覆盖 OpenHands 一个仓库，难以外推到全基准。
- **预训练污染不可排除**：基准漏洞多来自公开 CVE，模型可能已在预训练中见过相关代码或讨论；作者明确不声称无污染，仅以代码变异实验作为间接证据。
- **威胁模型受限**：仅覆盖白盒、授权、部署前审计场景，不涉及黑盒远程攻击、多轮自适应对抗或防御方主动检测；也未评估在生产环境中引入额外监控后的效果变化。
- **未来方向**：扩展到多模型、多语言（非 Python）仓库、更大规模间接路径样本；将 Analyzer 报告与静态分析/符号执行工具结合以提升精度；研究针对"语义化载荷"的检测与缓解机制。

## 8. 整体评价与学术价值

- **核心贡献**：论文最有价值之处在于**将"仓库发现"从"利用构造"中显式解耦**，并用三种评测模式与失败归因数据证明前者是当前智能体红队的主要瓶颈（69% 的失败源于分析阶段漏检）。这纠正了以往研究默认"注入点已知"的隐含假设。
- **方法设计亮点**：双角色 + 外部验证器的架构把"假设生成"与"假设验证"分离，报告外置机制缓解了长上下文退化；机器可读的候选路径记录使分析结果可审计、可交接、可复用。
- **实验严谨性**：token 预算匹配、代码变异、框架分层、外部验证器与报告均值 ± 标准差等设计，在同类智能体安全研究中属于较高标准；消融覆盖种子、轨迹反馈与多注入点三个关键组件，归因清晰。
- **可复现性**：基准构建标准（三条保留准则）、验证器外置、信息隔离字段均有明确描述，具备较强可复现基础；但部分细节（如人工匹配的具体规则、攻击种子语料的完整清单）未完全公开，可能影响严格复现。
- **实践启示**：对智能体开发者而言，论文提示安全审计不能只依赖"已知攻击面"的模糊测试，而需在代码层面追踪攻击者可控输入的完整传播链；对防御方而言，WAF 规则对语义化载荷的失效意味着需要更靠近工具调用边界（如权限最小化、工具前置条件校验、出站请求白名单）的纵深防御。
- **潜在影响**：该工作为"智能体安全审计"提供了可量化的基准与分阶段诊断方法，可能推动后续研究从"攻击成功率"转向"发现率—构造率—验证率"的分解式评估范式。
