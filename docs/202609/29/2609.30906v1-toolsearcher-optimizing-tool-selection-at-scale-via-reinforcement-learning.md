## Abstract
Large language models (LLMs) excel at natural language processing but struggle to interact with external environments. Tool learning provides a promising way to extend LLMs into actionable agents, where tool selection is a critical prerequisite for successful tool use. Existing work often assumes a small or predefined set of tools, leaving large-scale tool selection underexplored. Real-world repositories contain a vast and diverse array of tools, making it difficult for LLMs to effectively search, distinguish, and compose tools under context-length constraints. We identify large-scale tool selection as a new challenge for agentic reinforcement learning, highlighting that existing RL methods for knowledge-based question answering are inadequate for selecting tools while considering compatibility. To address this challenge, we propose ToolSearcher, a novel RL framework for effective multi-turn search and fine-grained optimization in large-scale tool selection. Specifically, we introduce category-constrained tool discrimination to improve the model's ability to distinguish functionally similar tools, event-level search modeling to explicitly optimize the discovery of target tools during multi-turn search, and trajectory-aligned credit allocation to provide fine-grained reward signals for different stages of the search-selection process. Extensive experiments on large-scale tool selection benchmarks demonstrate that ToolSearcher consistently outperforms a set of strong baselines in challenging settings involving iterative search and complex tool composition.

- **两大技术难题**：
  1. 如何在**大规模工具库**上有效进行多轮搜索，区分功能/语义相似的候选工具，并推理接口兼容性；
  2. 工具选择涉及规划、搜索、决策多种能力，**联合学习与奖励设计困难**；传统轨迹级奖励稀疏且粒度粗，难以优化多轮过程中的细粒度行为。
- **整体含义**：论文主张现有面向知识检索的 RL 方法（如 Search-R1）不适用于工具选择，需要一个显式建模搜索过程、并针对不同阶段分配细粒度信用的新框架。

## 2. 方法论

### 2.1 任务定义与预备知识

- 给定用户需求 $q$、大规模工具库 $\mathcal{T}$ 和搜索引擎 $R$，目标是找到满足需求的工具集合 $T_s=\{T_1,\dots,T_n\}$，最大化 $P_\theta(T_s|q,\mathcal{T},R)$。
- 每个工具文档 $d_T=(f,I,O_t)$，包含功能描述 $f$、输入约束 $I$、输出模式 $O$。
- LLM 以结构化 JSON 调用搜索引擎（包裹在 `<tool_call>` 标签内），引擎返回检索结果作为外部反馈，据此进行下一轮搜索。

### 2.2 类别约束工具判别（CCTD）

- **核心思想**：把"全局检索"转变为"功能相似子空间内的类别约束检索"，人为构造强约束的挑战环境，迫使模型专注于区分功能相似的工具，而非仅优化查询语义。
- **实现**：每个工具按功能归入类别 $C$，搜索步骤形式化为 $D = R(C^*, Q \mid \mathcal{T}^{C^*})$，搜索引擎 schema 中增加 subcategory 搜索函数。
- **两阶段训练**：第一阶段用 30% 数据在子类别搜索设置下训练（学习区分相似工具）；第二阶段切换回全局搜索，学习细粒度语义检索。该渐进式策略兼顾"区分相似工具"与"大规模全局检索"。

### 2.3 事件级搜索建模（ESM）

- **动机**：工具存在依赖与接口约束，不兼容组合会导致工具链不可执行；而现有 RL 方法未显式建模搜索过程。
- **做法**：将搜索轨迹 $S$ 显式建模为搜索事件序列 $E=(e_1,\dots,e_k)$，其中 $e_k=(a_k, R(a_k))$，$a_k$ 为模型动作，$R(a_k)$ 为检索到的工具集。
- **关键设计**：
  - 对检索到的 token 施加**损失掩码**（loss masking），策略梯度只作用于 LLM 生成的 token，防止模型记忆检索文档内容。
  - 只优化**首次发现未覆盖目标工具**的事件集合 $E^*$：$T_{e_j}=M(e_j)\cap(T_s\setminus M(E_{<j}))$，避免重复优化已搜索过的事件。
  - 目标 $J_{\text{search}}(\theta)$ 采用 GRPO 风格的事件级优势优化，事件级优势 $\hat{A}_{i,e(t)}$ 取该事件首次检索到的目标工具集合 $T_{e(t)}$ 内的**最大归一化优势**；不属于 $E^*$ 的事件优势置 0。

### 2.4 轨迹对齐信用分配（TCA）

- **动机**：同一任务的不同轨迹进展阶段差异大——有的完成、有的搜到工具但选不对、有的还停留在早期搜索阶段，因此信用分配应匹配轨迹所处阶段。
- **做法**：
  - 对**选择事件** $e_s$：只有轨迹 $S_i$ 已搜索到全部目标工具（$M(S_i)\cap T_s = T_s$）时才计算选择奖励 $\hat{A}_{i,e_s}$，否则置 0——防止模型在工具尚未搜全时做不切实际的猜测。
  - 对**搜索事件**：对组内已掌握（已被其他轨迹成功搜索）的目标工具对应的搜索事件优势置 0，只奖励超越其他轨迹的搜索事件。
- **效果**：对处于不同进展阶段的轨迹，分别对搜索事件和选择事件分配匹配的奖励，实现细粒度、可量化的信用分配。

### 2.5 算法流程概览

对每个 prompt 采样 G 条搜索轨迹 → 计算事件级搜索优势（仅 $E^*$ 事件非零）→ 计算选择优势（仅搜全目标工具的轨迹非零）→ 按 token 级 PPO/GRPO 裁剪目标加 KL 正则更新策略 → 用 CCTD 两阶段数据调度。

## 3. 实验设计

### 3.1 数据集与场景

  - **I1**：单工具指令；
  - **I2**：同类别多工具指令；
  - **I3**：同 collection 多工具指令（最困难）。

  - 泛化评估分三级：Inst.（同工具集未见指令）、Tool（同类别未见工具）、Cate.（不同类别未见工具）。

### 3.2 评价指标

- 工具选择：**F1、Recall、Precision、Match**；搜索阶段用 **SRecall** 衡量目标工具召回。
- AppWorld 下游执行：**TGC**（Task Goal Completion）、**SGC**（Scenario Goal Completion），使用 FullCodeRefl + gpt-5-mini 生成并执行代码。

### 3.3 对比基线

- **RAG 范式**：RAG、RAG SFT（top-100 检索文档）。
- **搜索即工具范式**：Multi-turns（未训练）、Search-R1、GSPO、GDPO、MARAG-R1。
- **骨干模型**：Qwen2.5-7B-Instruct 和 Qwen3-4B-Instruct。
- **检索器**：Qwen3-Embedding-0.6B（对比 BM25、UniXcoder、GIST-Large、Arctic-Embed 2.0、Qwen-Embedding 系列后择优）。

### 3.4 关键设置

- 每轮检索 5 篇工具文档，最大交互轮数 8，每个 prompt 采样 5 条 rollout；训练 1 epoch（56 步），前 30%（17 步）在 CCTD 设置下训练后切回全局搜索。

## 6. 主要结论与发现

- **主结果**：ToolSearcher 在不同规模骨干上均取得一致提升。
  - Qwen2.5-7B：Overall F1 从 Multi-turns 的 9.8% 提升至 **51.3%**，Match 从 4.6% 提升至 **27.8%**；比次优方法 GDPO 高 1.7% F1。
  - Qwen3-4B：F1 从 40.8% 提升至 **53.1%**，Match 从 16.9% 提升至 **31.6%**。
  - 在最具挑战的 I3 场景，ToolSearcher 分别超过 GDPO / MARAG-R1 / GSPO / Search-R1 **6.6% / 8.3% / 9.8% / 10.0%**。
- **搜索与选择的平衡**：7B 模型 SRecall 高但最终选择弱，方法略降 SRecall 却大幅提升 Recall（I1/I2/I3 分别 +43.08%/+39.58%/+21.09%）；4B 模型则同时提升搜索与选择召回。
- **OOD 泛化**：在 AppWorld 上工具选择 F1/Recall/SRecall 全面领先；下游 TGC/SGC 平均最优（7B 上比 GDPO 高 5.7%，4B 上比 Search-R1 高 5.8%/2.9%）；在需最多 8 个 API 的 Difficulty-2 设置中，多数基线 SGC 近乎为 0，而本方法保持稳定。
- **消融结论**：
  - 三个组件缺一不可；**ESM 影响最大**（SRecall 在 StableToolBench 降 22.4%、AppWorld 降 39.4%），缺失 ESM 会使模型退化为结果导向、交互轮数从 4 降至 2；
  - **TCA** 缺失使 F1 从 51.3% 降至 46.1%，SRecall 从 68.0% 降至 53.8%；
  - **CCTD** 构造的强约束环境在基线上即导致指标大幅下降（如 4B 上 F1 0.265 vs 全局 0.408），证明其挑战性与训练价值。

## 7. 优点

- **问题定义有价值**：首次系统性地将"大规模工具选择"识别为 agentic RL 的新挑战，并清晰论证其与知识型 QA 检索的本质差异（工具可组合性/接口兼容性）。
- **方法设计针对性强**：
  - CCTD 用类别约束把"检索问题"转化为"判别问题"，构造渐进式课程（先难后全局），思路简洁有效；
  - ESM 用"首次发现目标工具的事件"作为优化单位，并配合检索 token 掩码，避免记忆检索内容，是对多轮搜索过程的显式建模；
  - TCA 按轨迹进展阶段分配奖励，避免"未搜全就猜选"和"已掌握能力的重复奖励"，信用分配逻辑自洽。
- **实验较为扎实**：2 个模型规模 × 2 个基准（in-domain + OOD）× 多场景 + 逐组件消融 + 训练曲线过程分析；训练配置对基线做了严格对齐，公平性意识较强。
- **实用性与可复现性**：
