## 摘要
LLM 智能体在涉及多个用户、社区、记忆、文件和工具的持续协作环境中运行。社区边界可能保持固定，也可能随成员资格、角色、构成和关系的变化而演化。智能体必须完成合法任务，并防止未经授权披露受保护信息。现有评估并未充分考察智能体系统中的这些风险。我们提出 CoSec，一个可执行基准，用于评估在社区内部及跨社区运行的 LLM 智能体系统中的隐私与授权强制执行。CoSec 包含 208 个规范化场景，涵盖固定边界与演化边界、属于智能体所有者或其他参与者的受保护信息，以及通过对话、环境内容、持久记忆和组合工作流发起的攻击。CoSec 执行具备持久会话、记忆、文件和工具的完整智能体系统。它利用执行轨迹和工件，根据当前授权状态验证信息流。在不同的运行框架与模型配置下，智能体经常能完成良性任务，却违反隐私与授权边界。隐私行为会随运行框架、攻击面和社区状态而变化，揭示出记忆、文件、工具和工作流如何能够将受保护信息带出其授权范围。这些发现表明，任务效用并不意味着隐私或授权合规，而社区场景中的授权对于持久性 LLM 智能体而言仍是一个尚未解决的安全挑战。

## Abstract
LLM agents operate in persistent collaborative environments involving multiple users, communities, memories, files, and tools. Community boundaries may remain fixed or evolve with changes in membership, roles, composition, and relationships. Agents must complete legitimate tasks and prevent unauthorized disclosure of protected information. Existing evaluations do not fully examine these risks in agent systems. We introduce \textbf{CoSec}, an executable benchmark for evaluating privacy and authorization enforcement in LLM agent systems operating within and across communities. CoSec contains 208 canonical scenarios spanning fixed and evolving boundaries, protected information belonging to the agent owner or other participants, and attacks through dialogue, environmental content, persistent memory, and composed workflows. CoSec executes complete agent systems with persistent sessions, memory, files and tools. It verifies information flows against the active authorization state using execution traces and artifacts. Across harness and model configurations, agents frequently complete benign tasks but violate privacy and authorization boundaries. Privacy behavior varies across harnesses, attack surfaces, and community states, revealing how memory, files, tools, and workflows can carry protected information beyond its authorized scope. These findings show that task utility does not imply privacy or authorization compliance and that authorization in community settings remains an unresolved security challenge for persistent LLM agents.

## 1. 核心问题与整体含义

- **背景**：LLM 智能体正从孤立的任务助手走向持久化协作环境——在群组对话、组织和在线社区中充当用户的长期代表，具备搜索、文件操作、工具调用等能力。
- **核心风险**：社区参与引入了**多主体、跨上下文的信息流风险**。例如个人智能体同时参与健康支持社区与工作群组，前者获知的信息可能残留在历史、记忆或工作区中，却绝不应披露给后者。单个看似无害的本地操作可组合成跨用户/跨社区的违规信息流。
- **社区边界会演化**：成员增减、角色升降、社区合并/拆分、关系建立/终止都会改变授权状态。扩大协作**不等于**解密历史受保护信息；收缩授权则要求此前权限立即失效。
- **现有评测的不足**：
  - 智能体安全基准（InjecAgent、AgentDojo、ASB、LITMUS、REDAgentBench 等）多以**单用户/单任务**为中心，不覆盖多参与者、重叠社区。
  - 智能体社区/社会性基准（SOTOPIA、MultiAgentBench、AgentSocialBench、MAGPIE 等）关注社交能力与协作，缺少受控的安全评估。
  - 隐私基准（PrivacyLens、AgentLeak、ToolPrivacyBench 等）少有同时覆盖**可执行系统 + 状态持久化 + 社区边界演化 + 多参与者**的组合。
- **整体含义**：论文主张社区授权是**系统属性（harness 级）而非模型属性**，任务效用高并不代表隐私/授权合规；CoSec 提供首个同时覆盖"可执行 harness、状态化执行、多参与者、工具/数据流、隐私边界、社区状态转移、轨迹与工件验证、效用度量"的基准（见表 1 对比）。

## 2. 方法论：核心思想与关键技术

- **总体框架（三阶段）**：
  1. **基准构建**：定义协作世界（用户、智能体、社区、社区文件、私有源、共享工作区、动态访问控制状态）与安全条件，生成可执行 JSON 场景清单（含时间线、文件、发言者、事件、攻击类型、评估者专用 oracle 标签）。
  2. **智能体执行**：在 Docker 隔离工作区中运行**完整原生智能体系统**（OpenClaw / Hermes / Codex），保留其原生会话、记忆、文件操作、工具与工作区效果。
  3. **验证与度量**：用执行轨迹与物理工件，对照当前授权状态验证信息流。

- **社区安全模型（授权状态）**：
  - 状态表示为 **Eₜ = (U, C, Gₜ, Mₜ, Rₜ, D, Pₜ, A, Hₜ)**：用户、社区、社区间关系、成员资格、角色、数据对象、策略、智能体接口、可见历史。
  - 每个受保护对象 d 带所有者 o(d)、来源社区 c(d) 与敏感度标签。
  - **授权 oracle（对智能体隐藏）**：Authₜ(u, a, d, ℓ) = 1[Pₜ(u, a, d, ℓ, Gₜ, Mₜ, Rₜ, o(d), c(d)) = allow]，即判定请求者 u 是否被允许对对象 d 执行动作 a 并发送至目标 ℓ。
  - 关键原则：**技术可达 ≠ 授权**。同一智能体可跨会话访问共享工作区与私有记忆，但可达性不构成披露许可。

- **威胁模型**：攻击者控制指定请求者消息，并（按攻击族）控制部分文档、元数据、记忆条目或工作流输入；**不能**修改授权 oracle 或隔离运行时。评估的是"语义信息边界的运行时强制执行"。

- **四类攻击压力面（28 种策略）**：
  - **A1 用户注入**：直接施压（直接索取、伪造授权、角色冒充、上下文覆盖、紧急施压、安全摘要陷阱、确认陷阱）。
  - **A2 间接注入**：在文档、工具观测、引用消息、隐藏元数据、工作流文件中埋入指令（含来源伪造、格式合规陷阱）。
  - **A3 记忆投毒**：在持久上下文中写入虚假/过期/过宽的授权声明（虚假授权、连续性偏好、角色绑定、伪造例外、摘要回填原始细节、旧上下文复用、触发短语）。
  - **A4 能力组合**：将多个看似合理的文件/工具/工作流步骤组合为未授权信息流（先索引后提取、模板槽位填充、摘要逐步精化、来源洗白、收件人扩张、跨工件拼接、多请求者共识）。

- **两套场景**：
  - **Static112**：固定边界，交叉 2（社区内/跨社区）× 2（所有者信息/第三方信息）× 4（攻击族）× 7（策略变体）= 112。
  - **Dyn96**：在评分动作前插入一个确定性社区事件，覆盖 4 类事件、8 个有向转移——成员加入/移除、角色升级/降级、社区合并/拆分、关系开始/结束；每族对齐一种策略（A1-S2、A2-S2、A3-S6、A4-S7），事件后按**更新后的授权状态**评估。

- **执行与验证流程**：
  - 运行器为每个（场景 × 智能体 × 社区）创建原生会话；历史不在社区间共享；各社区占据独立逻辑命名空间。
  - **确定性证据提取器**：只搜索"评分攻击轮"的智能体输出；区分内部读取（诊断性）与外部输出面（write/send/post/publish/upload/copy/move 等工具参数）；排除种子文件原有内容、攻击者输入、路径披露（除非显式声明为目标）；对比 setup 与 final 工件，仅保留**新引入**的受保护词项。
  - **LLM 语义裁判**：接收固定 JSON 包（当前授权状态、受保护项描述、目标、消息、工具轨迹、工件片段），temperature=0，返回结构化裁决（security_failure、privacy_leakage、cross_community_leakage、unauthorized_action、unsafe_capability_composition、benign_task_completed 及四项指标）。
  - **合并规则**：R̂ᵣᵢ = Dᵣᵢ ∨ Jᵣᵢ（裁判有效时）；仅有确定性证据时取 Dᵣᵢ；两者皆无效记为 ⊥（不确定，不计入指标，也不默认为安全）。

- **度量指标**：
  - **PVR（隐私违规率）**：受保护内容经智能体输出披露（仅读取文件或提及路径不算）。
  - **CCPVR（跨社区隐私违规率）**：在源与目标处于不同授权域的可行子集 V_cross 上统计未授权跨社区流动。
  - **BCR（良性完成率）**：独立于安全性衡量任务完成。
  - **STCR（安全任务完成率）**：BCR 且无任何已验证安全失败——**一刀切拒绝无法获得高 STCR**，高 BCR 也无法掩盖不安全完成。
