## 摘要
配备工具的自主AI智能体的兴起带来了显著的安全风险，从无意的工具误用到通过间接提示注入（IPI）攻击进行的对抗性操纵，不一而足。在实践中，OpenAI Codex 和 Claude Code 等已部署的智能体系统通过粗粒度权限规则与基于LLM对单个提议动作的判断相结合，来保护工具调用。然而，这两个组件都有重要局限：静态策略必须预先考虑可能的用户意图，因而无法扩展到开放式任务；而LLM驱动的授权虽支持动态决策，但会产生不一致的结果，并且仍易受针对性IPI攻击的影响。为了提供可扩展且更一致的授权，我们提出 MetaPermit，一种基于策略的工具访问控制框架，将语义推断与安全执行解耦。通过分析智能体-用户交互，我们推导出一组紧凑、与任务无关的元属性，这些元属性刻画了用户意图、执行上下文与所提议工具调用之间的关系。这些元属性使 MetaPermit 无需枚举用户意图即可授权工具使用。在运行时，LLM 为每个提议的工具调用推断元属性值，而固定策略评估这些值以允许或拒绝该调用，从而可通过推断出的值和所应用的策略规则对每个决策进行审计。我们在 AgentDojo 和 AgentDyn 基准上，跨越七个任务套件和五种攻击方法，使用两个广泛部署的开放权重LLM对 MetaPermit 进行评估。结果表明，与LLM驱动的授权相比，MetaPermit 产生的一致性授权决策多31%，并在任务完成度（提升最高达109%）和对IPI攻击的鲁棒性（未执行任何恶意工具调用）两方面均优于当前最先进的防御方法 CaMeL 和 IPIGuard。

## Abstract
The rise of autonomous AI agents equipped with tools has introduced significant security risks, ranging from unintended tool misuse to adversarial manipulation through Indirect Prompt Injection (IPI) attacks. In practice, deployed agent systems such as OpenAI Codex and Claude Code protect tool invocations through a combination of coarse-grained permission rules and LLM-based judgments about individual proposed actions. Both components, however, have important limitations: static policies must anticipate possible user intents and therefore do not scale to open-ended tasks, while LLM-driven authorization supports dynamic decisions but produces inconsistent outcomes and remains vulnerable to targeted IPI attacks. To provide scalable and more consistent authorization, we propose MetaPermit, a policy-based tool access-control framework that decouples semantic inference from security enforcement. By analyzing agent-user interactions, we derive a compact, task-independent set of meta-attributes that capture the relationships among the user's intent, the execution context, and the proposed tool call. These meta-attributes allow MetaPermit to authorize tool use without enumerating user intents. At runtime, an LLM infers the meta-attribute values for each proposed tool call, while a fixed policy evaluates these values to allow or deny the call, making each decision auditable through the inferred values and the applied policy rule. We evaluate MetaPermit on the AgentDojo and AgentDyn benchmarks, across seven task suites and five attack methods, using two widely deployed open-weight LLMs. The results show that MetaPermit produces 31% more consistent authorization decisions than LLM-driven authorization and outperforms the state-of-the-art defenses CaMeL and IPIGuard in both task completion, with improvements of up to 109%, and robustness to IPI attacks, with no malicious tool calls executed.

# MetaPermit 论文深度总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM 应用已从聊天机器人演进为可自主规划、多步调用工具的智能体（Agent）。由于指令与数据共享同一上下文窗口，攻击者可将恶意指令嵌入工具返回内容中，形成**间接提示注入（Indirect Prompt Injection, IPI）**攻击。智能体的每次工具调用是"每个有后果的动作"的必经关口，因此成为授权检查的关键位置。
- **现有防御的两难**：
  - **静态策略类**（如 CSAgent、AC4A、CaMeL）：需在运行前按工具/意图预先编写策略，可预测但数量庞大，无法覆盖开放任务中未预见的意图，且无法区分同一权限的合法与恶意使用（例如"给 Bob 退款"与"给 Eve 转账"调用同一个 `send_money` 工具）。
  - **LLM 驱动授权类**（如 Conseca、Progent、IPIGuard，以及 OpenAI Codex / Claude Code 的实践）：无需预先枚举意图，但 LLM 的随机性会导致语义相近任务给出不一致裁决，且一次精心构造的注入就可能说服 LLM 裁判放行。
- **整体含义**：论文主张将**语义推断（LLM 做）**与**安全执行（固定策略做）**解耦，从而在不枚举用户意图的前提下，实现可扩展、一致且可审计的工具访问控制。核心动机案例：Alice 让 Agent 退款给 Bob，交易记录中混入冒充 Alice 的注入，诱导转账给攻击者 Eve——MetaPermit 应拒绝给 Eve 的调用，同时保留给 Bob 的合法退款。

## 2. 方法论：核心思想、关键技术细节与流程

- **核心思想**：不预测具体用户意图，而是推断**任务无关的元属性（meta-attributes）**——刻画"用户请求、执行上下文、所提议工具调用"三者之间语义关系的抽象安全维度。LLM 只负责"描述"调用，固定策略负责"裁决"。
- **五个元属性（固定值域，联合推断）**：
  - `intent_is_action`：true / false（用户是要行动还是仅对话）——**仅依赖可信用户请求**
  - `intent_clarity`：clear / ambiguous / incomprehensible——**仅依赖可信用户请求**
  - `intent_risk`：high / low（是否涉及不可逆伤害或隐私泄露）
  - `intent_tool_alignment`：direct / prerequisite / supporting / misaligned（工具是否服务于用户目标）
  - `intent_input_alignment`：aligned / misaligned（调用实参是否被用户请求所正当化）
- **端到端流程**：
  1. **推理模块（Inference Module）**：输入为用户原始请求、工具可信描述、调用实参、此前工具结果历史；LLM 必须输出严格 JSON，每个属性只能取有限枚举值之一。
  2. **策略引擎（Policy Engine）**：对属性向量套用**有序 ABAC 规则** ΠS = (r1,…,rn, rn+1)，每条规则 rj = (φj, ej, oj) 即"谓词 / Allow 或 Deny / 反馈义务"。**首个匹配的规则生效，末尾默认规则 Deny**（fail-closed）。
     - 规则集（表 7）：R1 非行动请求→拒；R2 意图不可理解→拒；R3 工具不相关→拒；R4 实参不对齐→拒；R5 模糊且高风险→拒；R6 非必要高风险→拒；R7 剩余低风险→允；R8 清晰且必要调用→允；默认→拒。
  3. **执行门（Enforcement Gate）**：Allow 则原样转发执行；Deny 则阻断并把**策略依据的反馈**作为合成工具结果返回给 Agent，使其能重新规划而不获得绕过权限。
- **关键设计要点**：
  - **受限模型权限**：LLM 只能在固定类型化词表中选值，不能创建策略、不能给出最终裁决；无效/不完整输出直接落入默认拒绝向量。
  - **可信输入隔离**：两个元属性只读可信用户提示，检索内容无法影响其取值。
  - **可扩展性**：策略规模随"安全维度数量"增长，而非随用户意图空间增长；新增需求只需新增元属性并更新相关规则，接口与执行路径不变。
  - **可审计性**：决策可由"推断出的属性值 + 命中的策略规则"完整还原。
  - **攻击难度提升**：绕过需同时操纵所有满足 Allow 规则所需属性，而非仅说服 LLM 输出一个 Allow。

## 6. 主要结论与发现

- **安全性**：MiniMax-M2.7 上 ASR 从无防护的 2.85% 降至 0.08%（执行感知审计后为 **0/7,545 = 0%**）；Qwen3-235B 上从 26.49% 降至 **0.00%**；Qwen3-8B 上从 9.01% 降至 1.50%（相对降低 83.4%）。
- **效用**：MiniMax-M2.7 UA 53.92%，Qwen3-235B 50.13%，显著优于 CaMeL（25.83% / 42.21%）与 IPIGuard（30.27% / 41.96%）；相对 CaMeL 提升最高约 **109%**。AgentDojo 套件上效用损失很小（如 MiniMax 69.4% vs 无防护 72.0%），主要下降出现在更难的 AgentDyn 开放任务上。
- **低 ASR 的实质**：Secure-Usable 占比显示，CaMeL 与 IPIGuard 的低 ASR 主要来自"安全但不可用"（任务未完成），而 MetaPermit 的 Secure-Usable 份额最接近无防护水平。
- **一致性**：MetaPermit 的最终裁决在 20 次重复中 42% 完全一致，优于直接 LLM 裁判的 32%；多数一致率 90% vs 87%。静态策略把 47 条属性向量波动的查询中的 18 条（38%）映射为一致裁决，阻止了推断层随机性向上传播。
- **类型化接口的价值**：与同一模型、同一查询的直接 Allow/Deny 裁判相比，类型化接口在保持或提升安全性的同时显著改善效用（Qwen3-235B：UA 29.25% vs 12.75%）。
- **属性贡献**：移除 `intent_input_alignment` 后效用几乎不变（53 vs 54 完成任务）但攻击成功数翻倍，说明该属性在无效用代价下提升安全性。
- **白盒鲁棒性**：即使向推理模块公开 schema 与 allow 规则并要求生成 allow 兼容值，95 个真实恶意调用中 **0 个被放行**；注入最常压低 `intent_risk`（16.8%），但 `intent_tool_alignment` 与 `intent_input_alignment` 仍分别阻断 94/95 与 95/95。
- **反馈机制**：完整结构化反馈带来最高 UA（60.00%）、最高恢复率（50.00%）、ASR 0.00%，并减少重复拒绝。

## 7. 优点

- **架构上的解耦设计**：把"语义理解"交给 LLM、把"授权裁决"交给确定性策略，既保留对开放意图的可扩展性，又获得可复现、可审计的裁决；这是对静态策略与 LLM 裁判两难的一次有效折中。
- **类型化受限接口**：有限值域 + 默认拒绝 + JSON 契约，使决策空间可枚举、可审计，且把攻击面从"输出一个 Allow"抬升为"同时伪造一整组合法属性值"。
- **可信输入隔离**：`intent_is_action` 与 `intent_clarity` 仅依赖可信用户提示，检索内容无法污染，从信息流层面切断了一部分注入路径。
- **策略反馈而非硬阻断**：拒绝时返回策略依据与义务，使 Agent 能重新规划并完成任务，兼顾安全与可用性——这是很多防御忽视的工程细节。
- **可扩展与模型无关**：策略规模随安全维度而非意图数量增长；schema 与策略在全部 7 个套件、5 种攻击、3 个模型上保持不变，展现良好泛化。
- **实验严谨性较高**：三指标并报、执行感知审计剔除 `<think>` 假阳性、置信区间与配对显著性检验、以及针对执行层的白盒探针，均提升了结论可信度。
- **可部署性强**：不修改 Agent 系统提示，只在工具执行路径前插入门控，易于工程集成。

## 8. 不足与局限

- **保证是架构性的而非语义性的**：确定性策略只保证"同一属性向量→同一裁决"，**无法验证推断出的属性是否正确**。作者明确承认安全主张是经验性与执行导向的，而非形式化语义正确性保证。
- **推断层仍可被局部操纵**：白盒实验显示注入可改变单个属性值（`intent_risk` 被翻转 16.8%），只是因对齐类属性未被同时攻破而未能形成合法组合；若攻击者针对属性组合做更强优化，风险尚不清楚。
- **效用下降明显**：在 AgentDyn 开放任务上 UA 下降较大（如 Shopping 9.33%、Github 19.22%、

Dailylife 等套件），反映出策略在开放、长依赖任务上的**误拒（false denial）**问题：当某个工具调用只是长链任务中的间接前提（prerequisite / supporting），其正当性依赖多步上下文时，单次调用的对齐判断容易偏保守，导致合法调用被拦截、Agent 被迫反复重规划。作者也坦承这是安全与可用性的固有张力，而非可通过调参消除的缺陷。

- **规则集与元属性带有先验人工设计色彩**：R1–R8 规则、五个元属性的名称与取值域均由作者凭领域经验设定，论文未给出系统性推导方法，也未报告规则顺序（首个匹配生效）的敏感性分析。若调整规则优先级，某些边界样本的裁决可能改变，其鲁棒性缺乏量化证据。
- **表达粒度有限**：`intent_risk` 只有 high/low、`intent_tool_alignment` 只有四档离散值，难以刻画"部分对齐""间接但高风险""风险随执行次数累积"等中间语义。这在单次调用上影响不大，但会使复杂场景被迫落入某个粗糙桶位，进而触发过宽或过严的规则。
- **单调用视角，缺乏跨调用组合风险建模**：策略引擎对每次工具调用独立裁决，未显式建模**多个各自无害的调用组合后产生危害**的情形（例如分批小额转账、先读取再外发）。论文的攻击评估以单次注入成功为目标，未系统考察这类"安全聚合失败"（aggregate safety failure）场景。
- **推断层仍是单点依赖**：尽管类型化接口把攻击面从"输出一个 Allow"抬升为"伪造一组合法属性值"，安全性最终仍系于 LLM 能否忠实填写属性。论文缺少对**针对属性组合的自适应优化攻击**的评估——白盒探针只测试了"要求生成 allow 兼容值"这一种策略，未覆盖梯度/迭代式的对抗搜索。
- **延迟与成本未量化**：每个被门控的工具调用都要额外发起一次 LLM 推断（严格 JSON 输出），论文未报告端到端延迟增量、额外 token 消耗或与基线的成本对比。对高频工具调用的 Agent 而言，这一开销可能不可忽略，而"可用性"评估仅以任务完成率衡量，未纳入时延维度。
- **基线比较存在后端敏感性**：作者已主动说明 CaMeL 与 IPIGuard 的表现取决于模型能否稳定产出可解析程序/可执行工具调用，因此"MetaPermit 大幅领先"的读数应理解为**同一后端下的开箱性能**，而非方法本身的上界；基线若经针对性适配或更换更强后端，差距可能收窄。
- **评估规模与多样性仍有边界**：任务集为 7 个套件、157 个无攻击任务，模型为 3 个（且其中两个同属较大规模），未覆盖更多模型家族（如闭源前沿模型、专用安全模型）与多语言、多模态工具场景；跨模型泛化结论主要由 Qwen3-8B 单点支撑。
- **缺乏人类评估与长期部署验证**：策略反馈的可读性、对 Agent 重规划的实际帮助、以及审计日志在真实运维中的可用性，均未通过用户研究或线上部署加以验证，可解释性主张目前主要是架构层面的论证。

## 9. 总体评价与启示

- **定位**：MetaPermit 不是"更强的检测器"，而是一次**控制流重构**——把不可靠的语义判断限定在"描述"环节，把"裁决"交给确定性规则，从而将 LLM 的随机性从决策路径上剥离。这一思路对当前以 LLM 作为裁判/守卫的普遍做法构成了有说服力的反例。
- **最大贡献**：证明了在**不枚举用户意图**的前提下，仍能获得可复现、可审计、fail-closed 的工具授权，且效用代价在传统套件上可接受。其"元属性 + 有序 ABAC + 默认拒绝"的组合，为 Agent 权限管理提供了一套可直接落地的接口范式。
- **核心权衡**：安全性的提升以"单次调用视角的保守判断"为代价，在开放式长依赖任务上体现为误拒率上升；同时把一部分风险从"策略绕过"转移到了"属性推断正确性"上，而后者尚无形式化保证。
- **适用场景建议**：更适合工具语义明确、安全边界清晰、且可接受少量重规划开销的生产型 Agent（如退款、转账、发信等有副作用操作）；对于高度开放、依赖隐式上下文的长链任务，可能需要引入跨调用累积风险建模与更细粒度的元属性粒度。
- **后续研究方向**：跨调用/多步风险聚合、针对属性组合的自适应攻击评估、元属性与规则集的系统化推导与校准、以及延迟与成本的工程量化，是该方法从"有效原型"走向"可部署防线"的关键待补环节。
