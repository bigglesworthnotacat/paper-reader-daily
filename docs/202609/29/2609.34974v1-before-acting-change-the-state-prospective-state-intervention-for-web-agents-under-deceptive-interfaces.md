## 摘要
基于 LLM 的 Web 代理能够自主完成用户任务，但欺骗性界面可能引导其走向与用户利益相冲突的结果。现有防御主要通过阻断、引导或重新规划来干预代理行为。我们识别出一种不同的失效模式：由于当前 Web 状态，一个任务有效的动作仍可能造成未经授权的后果。这促使我们将任务相关的 Web 状态本身视为运行时控制目标。我们提出 Veer，一种代理侧运行时防御，它将任务规划留给基础代理，并在所提议的动作会产生未经授权后果时干预 Web 状态。在修改实时环境之前，Veer 会构建一条通向安全且任务相关状态的前瞻性干预轨迹，并通过运行时接地与验证来执行它。在 TrickyArena 和 WebDecept 上，Veer 在所有三种评估设置中均实现了最高的安全任务完成率，在 TrickyArena-Single 和 TrickyArena-Multi 上分别比次优防御高出 15.9 和 25.0 个百分点，同时将 WebDecept 上的暗黑模式成功率降至 0.3%。这些增益在不同暗黑模式类型以及全部 12 种代理、模型和基准配置中均持续存在。消融实验表明，主动状态干预带来的增益最大，而前瞻性推演和时序证据则贡献了额外的改进。这些结果确立了任务相关的 Web 状态是一个有效的运行时控制目标，可用于保护 Web 代理免受欺骗性结果的影响。

## Abstract
LLM-based Web agents can autonomously complete user tasks, yet deceptive interfaces can steer them toward outcomes that conflict with users' interests. Existing defenses primarily intervene on agent behavior through blocking, guidance, or replanning. We identify a distinct failure mode: a task-valid action can still realize an unauthorized consequence because of the current Web state. This motivates treating task-relevant Web state itself as a runtime control target. We introduce Veer, an agent-side runtime defense that leaves task planning to the base agent and intervenes on Web state when a proposed action would produce an unauthorized consequence. Before modifying the live environment, Veer constructs a prospective intervention trajectory toward a safe task-relevant state and executes it with runtime grounding and verification. Across TrickyArena and WebDecept, Veer achieves the highest safe task completion in all three evaluation settings, exceeding the next-best defense by 15.9 and 25.0 percentage points on TrickyArena-Single and TrickyArena-Multi, respectively, while reducing dark-pattern success on WebDecept to 0.3%. These gains persist across dark-pattern types and all 12 agent, model, and benchmark configurations. Ablations show that active state intervention provides the largest gain, while prospective rollout and temporal evidence contribute additional improvements. These results establish task-relevant Web state as an effective runtime control target for protecting Web agents from deceptive outcomes.

## 1. 核心问题与整体含义

- **研究背景**：基于 LLM 的 Web 代理能够自主执行购物、预订、信息检索等多步任务，但欺骗性界面（dark patterns）会诱导代理做出违背用户利益的结果。已有研究显示，TrickyArena 中单个暗黑模式的平均诱导成功率约 41%，DECEPTICON 中超过 70% 的测试任务出现不良结果。

- **现有防御的局限**：当前运行时防御（如 DUDE、WebGuard、SafePred、SeerGuard）主要干预代理的**行为**——通过阻断、引导或重新规划来决定代理是否/如何继续下一步动作。然而，识别欺骗模式本身并不足以可靠地阻止不良行为。

- **核心失效模式**：论文识别出一种被忽视的情况——一个**任务有效（task-valid）的动作**，由于执行时所处的 **Web 状态**，仍可能产生**未经授权的后果**。典型例子：用户任务为"购买笔记本"，结账动作本身对购买是合理的，但购物车中被自动加入的延长保修改变了结账的后果。

- **核心命题**：将**任务相关的 Web 状态本身**视为运行时控制目标。在动作执行前，可以改变导致不良后果的状态，同时保留代理向用户任务的推进。核心研究问题：**运行时防御如何干预导致后果的 Web 状态，同时保持代理向用户任务的进展？**

- **三大挑战**：
  - ❶ 后果相关状态**稀疏且持久**：可能依赖界面的一小部分，或数个交互之前建立的状态，需要连接时序证据与常常欠规范的用户请求。
  - ❷ 安全干预可能需要**多个依赖性的状态转换**：直接尝试候选干预会修改正在规划中的实时应用，因此需要在执行前进行前瞻性推理。
  - ❸ **前瞻性转换可能与实时执行产生偏差**：动态内容、失败交互和隐藏应用行为可能使预期转换失效，需要每一步都进行接地与验证。

## 2. 方法论：Veer

### 2.1 核心思想

Veer 是一种**代理侧运行时防御**，位于基础代理与 Web 环境之间。它将任务规划留给基础代理，仅在所提议动作会产生未经授权后果时干预 Web 状态。三大耦合设计：

1. **任务接地的后果评估**（Task-Grounded Consequence Assessment）
2. **前瞻性状态干预**（Prospective State Intervention）
3. **受保护的轨迹执行**（Guarded Trajectory Execution）

### 2.2 关键技术细节

- **任务相关 Web 状态**：$S_t = G(o_t, L_t)$，结合当前观测 $o_t$ 与有效时序证据 $L_t$，保留跨交互的选择、设置和工作流状态。

- **任务授权表示**：$A_u = A(u)$，从原始用户指令导出且**固定不变**。运行时观测只能将授权引用接地到具体 Web 对象/事实，但**不能扩展**用户授权。授权表示包含四类任务证据：明确授权的终端结果、实质性约束、请求的信息输出、指定输出目标。

- **后果评估**：$(\hat{c}_t, y_t) = P(a_t, S_t, A_u)$，预测执行 $a_t$ 的任务相关后果 $\hat{c}_t$ 并判断是否授权，$y_t \in \{AUTHORIZED, UNAUTHORIZED, UNCERTAIN\}$。评估将**后果预测**与**任务条件授权**分离为不同 JSON 字段；显式记录动作语义、承诺边界、材料状态传播、因果关关系等。对于 UNCERTAIN，执行有界证据获取后重新评估；若无法在运行时界限内解决，则**不将不确定性视为授权**，执行安全回退。

- **干预目标**：当 $y_t = UNAUTHORIZED$ 时，构造 $I_t = (R_t, S^\star_t, P_t)$：
  - $R_t$：当前状态中导致未经授权后果的负责状态
  - $S^\star_t$：移除该贡献所需达到的目标安全状态
  - $P_t$：应保持不变的既有任务相关状态
  - 目标在规划与执行过程中**保持不变**，仅浏览器级实现可适应实时证据。

- **前瞻性干预轨迹**：$B_t = [\tau_1, \ldots, \tau_K]$，在发出任何状态改变动作**之前**完整构建。每个转换记录浏览器动作、预期任务相关效果、对先前转换的依赖。规划先于执行完成，因为直接尝试候选干预会修改正在规划的状态。执行前检查目标是否在界面中接地、依赖是否有效、计划效果是否与 $I_t$ 一致。

- **受保护的轨迹执行**：每个转换在得到实时证据支持前均为**暂定**。执行前重新接地目标并检查依赖；执行后观察结果状态并与预期效果比对。不匹配则使剩余轨迹失效（后续步骤可能依赖未建立的状态），停止当前轨迹、重新接地实际状态，并在同一目标下构建新轨迹。成功条件：$S^+_t \models S^\star_t \wedge S^+_t \models P_t \wedge \text{Resolved}(R_t, S^+_t)$，随后将控制权交还基础代理。

- **运行时算法流程**（Algorithm 1）：构造 $S_t$ 与 $A_u$ → 评估 $(\hat{c}_t, y_t)$ → UNCERTAIN 则有界获取证据并重评 → AUTHORIZED 则释放动作 → UNAUTHORIZED 则构造 $I_t$ → 前瞻规划 $B_t$ → 检查准入 → 逐步接地执行并验证 → 成功则返回控制权，失败则重规划或安全终止。

- **No-Defense**：无防御的原生基准代理。

### 3.3 评估指标

- **DPSR**（Dark Pattern Success Rate，↓）：欺骗性结果发生率。
- **TSR**（Task Success Rate，↑）：原始用户任务完成率。
- **STC**（Safe Task Completion，↑，主指标）：无任何评估暗黑模式结果的任务完成率，按 episode 级联合结果 $T_i(1-D_i)$ 计算，**不是** TSR × (1 − DPSR) 的乘积。

- **整体有效性**：Veer 在全部三种评估设置中取得最高 STC：

- **鲁棒性**：
  - 逐条件：TrickyArena-Single 中 21/22 个条件达到最低或并列最低 DPSR，20 个条件完全避免；WebDecept 平均场景 DPSR 0.3%，最差场景 2.2%。
  - 多模式：Veer 从 Single 到 Multi 的 DPSR 增幅最小（+10.2 pp，基线为 +19.8–33.0 pp），STC 降幅也最小（−17.6 pp，基线为 −19.9–36.0 pp）。
  - 12 种代理–模型配置中全部改善。

- **消融结论**：
  - **主动状态干预**贡献最大：替换为阻断使 STC 从 85.2% 降至 50.0%（−35.2 pp），TSR 从 86.4% 降至 51.1%。
  - **前瞻性推演**：替换为反应式干预使 DPSR 从 4.5% 升至 6.8%，STC 降至 80.7%（−4.5 pp），TSR 几乎不变。
  - **时序证据**：移除后 TSR 降至 80.7%、STC 降至 77.3%（−8.0 pp）。
  - **One-Step Intervention**：仅允许单步纠正使 STC 降至 61.4%（−23.9 pp），DPSR 升至 14.8%。

- **核心发现**：任务相关 Web 状态是一个有效的运行时控制目标；主动状态干预相比阻断能同时保住任务进展并消除不安全结果。

## 7. 优点

- **问题视角新颖**：首次明确识别"任务有效动作因当前 Web 状态而产生未授权后果"这一失效模式，将控制点从"代理行为"转向"Web 状态"。

- **方法设计精巧**：
  - 授权表示 $A_u$ 与 Web 状态 $S_t$ 分离，防止运行时内容扩展用户授权，安全性边界清晰。
  - 干预目标（做什么）与轨迹规划（怎么做）分离，目标固定而浏览器级实现可适应实时证据，兼顾安全意图稳定与执行灵活。
  - 前瞻规划先于实时修改，避免在规划过程中污染待规划状态。
  - 受保护执行逐转换接地与验证，不匹配时在同一目标下重规划，具备应对动态界面的鲁棒性。

- **评估严谨**：
  - 使用 STC 作为 episode 级联合指标，避免 TSR 与 DPSR 的乘积混淆。
  - 覆盖 471 个配置、多种欺骗机制、4 个领域、2 种代理实现、2 种模型。
  - 消融设计清晰，逐条件分析揭示增益非集中于少数有利条件。
  - 明确不向防御暴露基准标签、任务成功标签、隐藏评估器输出或后端状态。
