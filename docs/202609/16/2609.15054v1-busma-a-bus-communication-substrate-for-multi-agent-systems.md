## 摘要
多智能体（MA）系统能有效解决需要规划、工具使用以及综合多来源证据的复杂任务。现有系统通常采用分层管理者-工作者（HMW）或基于路由器的消息传递（RMP）结构作为其通信协议。然而，这些设计限制了智能体的自主性：工作者智能体无法直接咨询特定的“同伴”，并且错误路由的消息可能传播错误。受计算机系统中的总线架构启发，我们提出 BusMA，一种允许任意智能体通过共享通道（即总线）寻址其他智能体的通信框架。它由智能体注册、消息路由和共享内存管理组件组成。工作者智能体各自配备工具，拥有自己的本地记忆，并可通过发布带有特定意图的共享消息来进行推理、行动（使用工具）和通信。我们引入了四种意图：讨论、质疑、指导和请求解释，它们支持智能体之间的细粒度通信。一个主席（Chair）智能体监控共享内存，以协调交互并促进工作者之间的收敛。为评估 BusMA 的有效性，我们使用两个前沿 LLM 在涵盖视觉推理、数学推理和知识检索的 13 项任务上进行了大量实验，结果表明 BusMA 始终优于最先进的 HMW 和 RMP 方法。

## Abstract
Multi-Agent (MA) systems are effective at solving complex tasks that demand planning, tool use, and the synthesis of evidence from multiple sources. Existing systems typically adopt Hierarchical Manager-Worker (HMW) or Router-based Message Passing (RMP) structures as their communication protocol. However, these designs restrict agent autonomy: Worker agents cannot directly consult specific "peers", and misrouted messages can propagate errors. Inspired by bus architectures in computer systems, we propose BusMA, a communication framework that allows any agent to address other agents through a shared channel, i.e., the Bus. It consists of agent registration, message routing, and shared memory management components. Worker agents, each equipped with tools, have their own local memory and can reason, act (tool usage), and communicate by posting shared messages with specific intents. We introduce four intents: discussion, challenge, guidance, and request for explanation, which support fine-grained communication among agents. A Chair agent monitors the shared memory to coordinate interactions and facilitate convergence among Workers. To evaluate the effectiveness of BusMA, we conduct extensive experiments with two frontier LLMs across 13 tasks spanning visual reasoning, mathematical reasoning, and knowledge retrieval demonstrate that BusMA consistently outperforms state-of-the-art HMW and RMP methods.

## 1. 核心问题与研究背景

- **背景**：基于 LLM 的多智能体（MA）系统在数学推理、知识检索、工具使用等复杂任务上展现优势，其效果高度依赖智能体之间的通信质量与协调机制。

  - **HMW（分层管理者-工作者）**：由 Manager 分配任务、收集结果（如 AgentVerse、ChatDev、OctoTools、AgentOrchestra）。
  - **RMP（路由式消息传递）**：由 Router 中介全部消息交换（如 AutoGen、MASRouter、混合 AI 路由器）。
- **两大痛点**：
  1. **自主性受限**：Worker 沦为被动执行者，无法主动向特定"同伴"发起批评、质询或纠错，缺少 worker-to-worker 通信通道。
  2. **错误传播**：Manager/Router 成为"认知瓶颈"，所有信息被迫经过单一枢纽；一旦枢纽判断失误，错误会沿链式路由扩散。
- **核心思路**：受**计算机总线架构**（Patterson & Hennessy）与分布式系统 **Information Bus**（Oki et al., 1993）启发，提出 **BusMA**——让任意智能体通过共享通道（Bus）直接寻址其他智能体，而非被动等待派单或路由中介。

## 2. 方法论

### 2.1 整体架构（三大组件）

| 组件 | 职责 |
|---|---|
| **Worker Agents** | 配备工具，维护本地记忆，可 Reason / Act / Call |
| **Chair Agent** | Worker 的特例（`T_chair = ∅`，禁用工具），监控共享记忆、协调收敛、综合答案 |
| **Bus（总线）** | 智能体注册 + 消息路由 + 共享内存管理 |

### 2.2 工作流（按需协作，on-demand collaboration）

- 任务输入 Chair → Chair 推理后识别首个应联系的 Worker 并发起 `Call` → 随后进入共享记忆监控状态。
- 被激活的 Worker 执行迭代循环：**Reason（基于本地记忆）→ Act（调用本地工具）或 Call（向总线发消息）**。
- 发出 `Call` 后 Worker 挂起，**仅当收到以自己为目标的消息时被 Chair 重新激活**。
- Chair 被寻址时被唤醒，读取共享历史 H，更新全局视图，决定继续协调或提交。

### 2.3 Worker Agent 关键细节

- **上下文构造**：系统提示 `P_i` + 总线消息 `M_i` + 同伴描述 `N` + 工具集 `T_i`；通过改写 `P_i`/`T_i` 定制角色（检索/视觉/代码）。
- **ReAct 循环**：迭代 t 时 LLM 产生私有推理 `r^priv_{i,t}`，据此选择动作：
  - **Act**：执行工具 `τ_j(θ)`，得到输出 `o_t`，更新本地记忆：`K_i(t+1) = K_i(t) ∪ {r^priv_{i,t}, o_t}`。
  - **Call**：选择目标 `α_j ∈ N`，生成 `a_call_t = (α_j, m_{i→j})`，以 **JSON** 格式发到总线后挂起。
- **终止条件**：(1) 选择 Call；(2) 达到最大迭代 `T_max`（此时向最初激活自己的 agent 发送失败消息）。
- **四种通信意图**（扩展了传统"派单-回报"的通信空间）：
  - `discussion`：双向信息交换
  - `request for explanation`：澄清模糊上下文
  - `challenge`：质疑他人中间结果，触发重新审视（**纠错关键**）
  - `guidance`：提供专业指导

### 2.4 Chair Agent 关键细节

- **不做显式规划、不预先分解子任务**，仅发起协作并综合信息，定位为 **primus inter pares（同侪之首）**，避免信息瓶颈。
- **路由与综合解耦**：Worker 之间的点对点消息**完全绕过 Chair**。
- **两种模式**：
  - `P^COOR_chair`（协调模式）：推理任务、发起首个 Call、监控共享记忆；被唤醒时识别未解决分歧、缺失证据与未回答问题，发出针对性 follow-up；可输出含 `submit` 字段的 JSON 转入提交。
  - `P^SUBM_chair`（提交模式）：单步生成，综合任务描述与累积信息给出最终答案。

### 2.5 Communication Bus 三大模块

- **Agent Registration**：初始化时每个 agent 获唯一地址 `A_i`，形成注册表 `R = {(α_i, A_i)}`，使 agent 可作为消息接收者被寻址。
- **Message Routing**：每个 agent 维护 **FIFO 队列 `Q_i`**；消息发送时被总线增强为
  `m̂_{i→j}(s) = (m_{i→j}, ID, s, α_i)`
  其中 `ID` 为唯一标识、`s` 为路由索引、`α_i` 为发送者；按到达顺序严格消费，支持向多接收者并发投递且保持一致。
- **Shared Memory Management**：共享历史 `H` 按路由索引 `s` 升序追加全部共享消息；任一 Worker 向 Chair 发消息时，Chair 即可访问 `H` 做全局评估与综合。

### 2.6 三层信息粒度

1. **私有推理** `r^priv_{i,t}`：留在 Worker 本地记忆，默认不公开；
2. **共享消息** `m_{i→j}`：仅通过 Call 公开"可行动"的内容 + 意图 + 证据；
3. **全局视图** `r^glob_{chair,t}`：Chair 通过访问 H 获得。

论文假设该分离可**降低通信开销同时保持协调一致性**。
