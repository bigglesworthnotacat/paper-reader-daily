## 摘要
尽管由 LLM 驱动的智能体在复杂环境中解决多步任务的应用日益增多，现有基准很少检验状态保持、跨语言表现以及在现实、有根基场景中的适用性。为应对这些问题，我们提出 WorldBench：一个全面的、多语言基准，包含真实的、以人物设定为基础的日常流程，智能体可通过结构化动作在沙盒中执行。WorldBench 涵盖七种语言和八种文化中的 1,600 项任务，并通过具有语言和文化专门知识的人类标注者的反馈进行筛选和精炼。在评估方面，我们扩展了先前工作的指标，并引入约束任务成功（CTS），它结合自然语言指令和测试环境，通过确定性评估和 LLM-as-a-Judge 评估对任务完成、最小修改及其他互补指标进行评分。我们的实验表明，前沿模型仅达到 49.2% 的 CTS，所有模型在正确性与环境保持之间都表现出巨大差距。因此，我们表明当前智能体在多语言、智能体化场景中仍然脆弱，尤其是在长时程任务和状态保持约束下。

## Abstract
Despite the growing use of LLM-powered agents to solve multi-step tasks in complex environments, existing benchmarks rarely test state preservation, performance across languages, and application to realistic, grounded scenarios. To address these concerns, we present WorldBench: a comprehensive, multilingual benchmark of genuine, persona-grounded everyday workflows, where agents can act in a sandbox via structured actions. WorldBench comprises 1,600 tasks across seven languages and eight cultures, filtered and refined through feedback from human annotators with language- and culture-specific expertise. For evaluation, we extend metrics from previous works and introduce Constrained Task Success (CTS), which combines natural language instructions and testbeds to score task completion, minimal modification, and other complementary metrics through deterministic and LLM-as-a-Judge evaluations. Our experiments show that frontier models reach only 49.2% CTS, with all models demonstrating large gaps between correctness and environment preservation. We thereby show that current agents remain brittle in multilingual, agentic scenarios, especially for long-horizon tasks and under state-preservation constraints

# WorldBench 论文总结

## 1. 核心问题与整体含义

- **研究动机**：LLM 智能体越来越多被用于复杂环境中的多步任务，需要识别文件、理解上下文约束、调用工具，并在有效最终状态下停止。但现有智能体基准多聚焦网页导航、工具调用、编程或操作系统控制，存在三个未被充分探索的问题：
  - **上下文根基不足**：任务常为通用指令，而真实工作流受用户角色、地点、语言、工作习惯影响。
  - **状态保持缺失**：模型可能完成目标输出，却误改无关表格、删除文件或覆盖不应改动的记录；仅看正确性或目标完成会遗漏此类失败。
  - **多语言覆盖不足**：许多基准以英语为主再翻译，难以判断智能体在语言和文化特定场景下是否可靠。
- **整体含义**：论文提出 **WorldBench**，一个文化根基的多语言智能体基准，覆盖真实、以人物设定为基础的日常文件工作流；并提出 **Constrained Task Success（CTS）**，同时衡量任务正确性与非目标文件保持。实验显示当前前沿智能体仍很脆弱，最高仅 49.2% CTS。

## 2. 方法论

- **核心思想**：
  - 每个任务由 **人物设定（persona）+ 自然语言指令 + 沙箱测试环境 + 最终状态评估函数** 构成。
  - 智能体在沙箱中通过结构化动作与异构工具交互，执行后从最终状态评估任务完成度和环境保持度。
  - 任务不是从英语翻译而来，而是在目标语言和文化语境中直接生成、本地化并由专家人工审核。

- **基准构建流程**：
  - **种子驱动**：人类编写 persona seed、scenario seed、application-and-constraint seed。
  - **任务合成**：扩展为原生语言指令和所需工件规格。
  - **测试环境合成**：生成表格、PDF、文档、日历、邮件、文本文件等；每个测试环境包含约 **15–20 个干扰工件**，如相似文件名、重叠实体、过时版本。
  - **人工审核**：由具备语言和文化专门知识的标注者检查任务是否真实、文化适当、可解、文件信息是否合理；不合格任务被修订或删除。
  - **最终平衡**：每种语言—地区设置保留 **200 个任务、50 个不同 persona**，共 **1,600 任务、400 persona、7 种语言、8 种文化**。

- **工具环境**：
  - 包含 **Spreadsheet、Document、PDF、Messaging、Calendar、Shell、System** 七类工具族。
  - 操作包括读取/编辑表格、读写文档、读 PDF、查看/发送消息、创建日历事件、执行 shell 命令、切换应用和终止任务。

- **执行流程**：
  - 建模为转移系统：状态空间 \(S\)、动作空间 \(A\)、观察空间 \(O\)、转移函数 \(\delta: S \times A \to S \times O\)。
  - 每步智能体输出一个 JSON 动作；环境执行并返回观察；历史为 \(H_t = [(a_1,o_1),...,(a_{t-1},o_{t-1})]\)。
  - 执行直到智能体调用 `finish_task` 或达到迭代上限（默认 **30 步**）。
  - 连续 5 次相同动作触发 `got_stuck`；格式错误动作会重试一次，仍失败则记为 malformed。

- **评估指标 CTS**：
  - 对任务 \(t\)，`pass(t)` 表示所有任务特定评估函数在最终沙箱状态上成功。
  - `preserve(t)` 表示所有非目标文件在初始与最终状态之间保持不变、字节一致。
  - **CTS(t) = pass(t) ∧ preserve(t)**。
  - 同时报告 pass rate、preservation rate、平均步数、malformed actions、执行失败、迭代上限命中率、干净终止率等诊断指标。

- **评估函数**：
  - **确定性函数**：`contain`、`not_contain`、`excel_cell_value`、`file_exist`、`calendar_no_overlap`。
  - **LLM-as-a-Judge 函数**：`evaluate_email`、`evaluate_note`；先做关键词检查，再由 judge 在温度 0、最多 10 token 下输出 YES/NO。

## 3. 实验设计

- **Benchmark**：
  - 使用 **WorldBench**，包含 1,600 个任务，覆盖 **7 种语言、8 种文化设置**：
    - 英语（美国、英国）、意大利语、葡萄牙语、西班牙语、法语、德语、中文。
  - 每个语言—地区设置 200 个任务，主题涵盖财务与会计、日程与会议、通信、报告与文档、差旅与报销、记录与行政。
  - 任务参考解长度 2–5 步，平均约 3.3 步；测试环境含干扰文件，要求智能体精确选择目标并保持无关文件不变。

- **对比模型**：
  - 评估 **9 个 LLM 智能体**：
    - Gemini-3.1-Pro、Gemini-3.5-Flash、GPT-5、GPT-4o、Qwen-3-32B、Qwen-3-4B、Llama-3.3-70B、Llama-3.1-8B、EuroLLM-9B。
  - 语言结果表中还额外报告了 Gemini-2.5-Pro。
  - 所有智能体使用相同 prompt、动作 schema、环境和配置；每任务每模型运行一次。

- **实验类型**：
  - 主实验：CTS、pass rate、preservation rate、步数、malformed、迭代上限、干净终止。
  - 多语言鲁棒性：按语言/文化比较 CTS，并比较英语与非英语。
  - 应用与评估函数分析：按日历、文档、表格、PDF、消息、shell 等应用族，以及各评估函数比较 pass rate 与 CTS。
  - 任务复杂度分析：按参考解长度 2–5 步分箱。
  - 失败模式分析：错误输出、附带编辑、迭代上限、malformed loop、执行错误。
  - 步预算消融：迭代上限 10、20、30、40、50 步，在部分模型上重跑。
  - Judge 鲁棒性：3 个 judge 模型与人类参考在 400 个双标注项上比较，报告 Cohen’s kappa 和一致率。
  - 人工错误分析：检查 400 条失败轨迹，归纳 6 类错误模式。

## 6. 主要结论与发现

- **整体性能有限**：
  - 最强模型 Gemini-3.1-Pro 仅 **49.2% CTS**，GPT-5 为 48.8%，Qwen-3-32B 为 48.0%。
  - 最弱模型 EuroLLM-9B 仅 **10.8% CTS**。
  - 所有模型 CTS 均低于 50%。

- **存在显著“保持差距”**：
  - 每个模型的 pass rate 都高于 CTS，差距从 Gemini-3.1-Pro 的 **10.1** 到 Llama-3.3-70B 的 **16.8**。
  - 说明智能体常能完成目标任务，却修改了不应改动的非目标文件。

- **多语言差异明显**：
  - 英语设置通常得分最高，中文对多数模型最难。
  - Qwen 系列在中文上的下降较小，Qwen-3-32B 取得最高中文 CTS。
  - 非英语失败中，**locale mismatch** 占比显著上升，从英语的 6.8% 升至非英语的 21.4%，中文峰值 26.9%。

- **应用与评估函数差异**：
  - Calendar 和 Document 任务得分较高；Messaging 和 Shell 任务 CTS 较低、保持差距较大。
  - 确定性函数（如文件存在、表格单元格）通过率高于 email 和 note 的 judge 评估，开放式输出更难满足。

- **任务复杂度影响**：
  - 随着参考解长度增加，CTS 普遍下降。
  - 成功轨迹约需 7–8 步，远高于参考解平均 3.3 步，说明智能体大量预算用于探索。

- **失败模式**：
  - 强模型主要失败于“错误输出”，但“附带编辑”在所有模型中都很显著。
  - 弱模型更多命中迭代上限，EuroLLM-9B 可达 43% 失败为迭代上限。
  - 人工分析中，**distractor capture 24.6%**、**redundant inspection 19.1%**、**shell over-reach 17.8%**、**locale mismatch 15.2%**、**premature termination 13.7%**、**schema violation 9.6%**。
  - distractor capture 与 shell over-reach 合计 42.4%，且均属于保持失败，解释了 pass 与 CTS 的差距。

## 7. 优点

- **文化根基与原生多语言构建**：任务在目标语言和文化环境中直接生成和审核，而非从英语翻译，避免源语言假设污染。
- **CTS 指标设计有针对性**：将任务正确性与非目标文件保持结合，能揭示传统正确性评分忽略的“附带破坏”。
- **真实文件工作流**：覆盖表格、文档、PDF、邮件、日历、shell 等异构工具，接近办公室自动化场景。
- **强人工审核流程**：由语言和文化专家检查真实性、文化适当性、可解性和文件合理性，并提供自由文本反馈。
- **诊断指标丰富**：除 CTS 外，还报告 pass、preservation、步数、malformed、迭代上限、干净终止、失败模式和轨迹长度。
- **鲁棒性验证较充分**：对步预算和 LLM judge 做了额外分析，说明结论不单纯依赖单一预算或 judge。
- **可扩展性**：基于种子构建，可新增 persona、语言和任务模式，也便于在怀疑污染时生成新任务。

## 8. 不足与局限

- **环境与接口受限**：
  - 仅评估结构化、基于文件的沙箱工作流，固定动作接口。
  - 不包含视觉桌面控制、实时网页交互，限制了对更真实计算环境的覆盖。
- **执行次数有限**：
  - 每个任务每模型只执行一次，固定解码配置，未报告多次运行的方差。
  - 结果可能受随机性和 API 版本差异影响。
- **LLM judge 风险**：
  - 两个开放式评估函数依赖 LLM judge，虽与人类一致性较高，但 judge 略偏宽松，仍引入主观性和方差。
- **跨语言可比性限制**：
  - 各语言设置独立构建，不是逐项翻译对应；语言差距可能混合了多语言指令跟随、本地文档惯例、文化根基和残余任务差异，不能解释为语言的孤立因果效应。
- **任务与数据偏差风险**：
  - 使用合成 persona 和合成数据，虽避免隐私问题，但可能与真实工作流分布仍有差距。
  - 人工审核每任务仅一次标注，25% 双标注，仍可能存在未发现的偏差。
- **应用限制**：
  - 基准主要面向文件型办公与行政任务，不直接覆盖编程、网页浏览、实时协作或高风险决策场景。
  - 当前智能体在长时程、状态保持和多语言场景下仍脆弱

，因此 WorldBench 更适合被理解为诊断性基准：它不证明某模型已具备通用办公智能体能力，而是揭示在文化根基、状态保持和多工具协作下的系统性短板。

## 9. 对研究与实践的启示

- **评测范式层面**：CTS 将“目标是否完成”与“环境是否被保持”并列，适合推广到企业自动化、文件管理、多工具协作等场景。传统只看最终答案或目标完成度的评测，会系统性高估智能体的可部署性。
- **智能体设计层面**：结果提示，智能体需要显式维护“可写/只读”边界，在执行前识别目标文件与干扰文件，在结束前进行变更影响自检。仅提升推理或工具调用能力，未必能缩小 pass 与 CTS 之间的保持差距。
- **多语言与本地化层面**：英语表现较好并不意味着能力可无缝迁移。日期格式、货币、姓名、地址、文档惯例、邮件语气和日历规则等 locale 因素，会实质影响工具选择与状态判断。
- **部署与治理层面**：附带编辑、shell over-reach、distractor capture 等失败模式说明，智能体在真实办公环境中需要审计日志、回滚机制、最小权限和人工确认点，而不宜直接授予广泛写权限。

## 10. 未来工作方向

- **统计稳健性**：对同一任务进行多次采样，报告方差、置信区间和 pass@k / CTS@k，以区分能力不足与随机波动。
- **环境扩展**：在保持状态评估思想的基础上，引入视觉桌面、实时网页、跨应用拖拽、多人协作和动态外部事件，缩小沙箱与真实计算环境的差距。
- **保持指标细化**：当前 preservation 主要关注非目标文件是否字节一致，未来可区分“无害元数据变化”“格式重写”“语义等价修改”和“实质性破坏”，使评估更贴近真实风险。
- **抗污染与动态生成**：利用种子机制持续生成新 persona、新文件和新约束，降低 benchmark 被训练数据覆盖或记忆的风险。
- **评估函数改进**：对开放式输出可结合多 judge 投票、人类抽检和可验证约束，减少 LLM judge 的宽松偏差与主观性。
- **训练与提示方法**：探索让智能体显式学习任务范围、文件相关性判断、变更前预演和结束条件确认的方法，以直接优化 CTS 而非仅优化 pass rate。

## 11. 总体评价

WorldBench 的主要贡献不在于提出新的模型架构，而在于把“文化根基的多语言任务”“真实文件工作流”“异构工具环境”和“非目标状态保持”组合成一个可诊断的评测框架。CTS 指标抓住了当前智能体评测中容易被忽略但部署风险很高的一类失败：智能体可能完成了用户要求，却同时破坏了不应触碰的数据。实验结果表明，前沿模型在该设定下仍远未可靠，且不同语言、应用族和任务复杂度下表现差异明显。

其局限也较清晰：沙箱化、固定接口、单次执行、合成数据、LLM judge 依赖以及跨语言设置非逐项对应，都会限制结论的外推。但这些问题并不削弱其核心诊断价值，反而为后续基准扩展和智能体安全部署研究提供了明确方向。总体而言，WorldBench 适合作为评估“可靠文件工作型智能体”的重要补充，而不是通用智能体能力的唯一或最终标准。
