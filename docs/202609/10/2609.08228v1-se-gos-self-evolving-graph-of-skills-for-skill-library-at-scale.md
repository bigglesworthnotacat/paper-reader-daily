## 摘要
现代LLM智能体日益依赖可复用技能，然而当技能库扩展到数千条目时，有效检索成为瓶颈。技能图（Graph-of-Skills, GoS）通过利用依赖感知的图结构进行可扩展技能检索来应对这一挑战，而SkillDAG进一步表明，技能图可以在线累积由执行支撑的结构。然而，这些方法尚未解决以下问题：历史执行轨迹能否被系统性地提炼为一个可泛化到未见任务的更优检索图。我们提出自演化技能图（SE-GoS），一种免训练框架，它从执行轨迹中演化现有GoS图，同时保留原始检索流程。SE-GoS执行三种互补更新：拓扑演化，从执行证据中发现并剪枝技能关系；边权演化，基于历史有效性强化与检索相关的关系；描述演化，利用执行反馈优化面向检索的技能描述。在SkillsBench上的三个LLM上，SE-GoS相对于全量技能加载，持续提升任务奖励并减少输入token，且增益因模型家族而异。在一个代表性设置中，一轮演化将奖励从52.4%提升至59.4%，同时相对于全量技能加载将输入token减少约三分之一，并且所得图可迁移到一个不相交的留出划分，相比静态GoS基线提升5.4个百分点。这些结果表明，技能图可以从执行经验中得到改进，而无需模型训练、无需改变检索算法，也无需修改技能内容，从而将静态检索图转变为不断演化的检索基础设施。

## Abstract
Modern LLM agents increasingly rely on reusable skills, yet as skill libraries scale to thousands of entries, effective retrieval becomes a bottleneck. Graph-of-Skills (GoS) addresses this challenge by exploiting dependency-aware graph structure for scalable skill retrieval, while SkillDAG further demonstrates that skill graphs can accumulate execution-backed structure online. However, these approaches leave open whether historical execution traces can be systematically distilled into a better retrieval graph that generalizes to unseen tasks. We present Self-Evolving Graph-of-Skills (SE-GoS), a training-free framework that evolves an existing GoS graph from execution traces while preserving the original retrieval pipeline. SE-GoS performs three complementary updates: topology evolution that discovers and prunes skill relationships from execution evidence, edge-weight evolution that reinforces retrieval-relevant relationships based on historical effectiveness, and description evolution that optimizes retrieval-facing skill descriptions using execution feedback. Across three LLMs on SkillsBench, SE-GoS consistently improves task reward while reducing input tokens relative to full skill loading, with gains varying across model families. In a representative setting, one evolution round improves reward from 52.4\% to 59.4\% while reducing input tokens by approximately one-third relative to full skill loading, and the resulting graph transfers to a disjoint held-out split with a 5.4-point improvement over the static GoS baseline. These results show that skill graphs can be improved from execution experience without model training, changes to the retrieval algorithm, or modifications to skill content, turning a static retrieval graph into an evolving retrieval infrastructure.

## 1. 核心问题与整体含义

- **背景**：LLM 智能体通过调用外部工具与可复用技能完成复杂任务。当技能库从数十条扩展到数千条时，瓶颈从“是否使用技能”转移到“如何检索出足以完成任务的有界技能子集”。
- **现有方案的缺陷**：
  - **全量加载（Vanilla）**：token 成本线性增长，且上下文过载导致模型忽略关键技能。
  - **向量检索**：只选语义相似技能，忽略功能前置依赖，常返回高层求解器而遗漏语义弱但功能必需的解析/配置工具——即“前置依赖缺口”。
  - **Graph-of-Skills（GoS）**：用类型化有向技能图 + 反向感知 PPR 返回有界执行包，在 1000 技能 SkillsBench 上较全量加载提升约 25.6% 奖励、降低约 56.7% token；但图是**静态的**，构建一次后不再从执行反馈更新。
  - **SkillDAG**：可在线累积执行支撑结构，但其冷启动依赖约 200 次 LLM 调用（pair classifier + 双 embedding 视图），且关系判断来自模型先验。
- **核心问题**：历史执行轨迹能否被系统性提炼为更好的检索图，并泛化到未见任务？
- **整体含义**：论文主张经验应存放在**检索 harness（技能图）**这一层——而非模型权重或技能内容——因为它更新便宜、每次改动可检查、可逆，且被所有读取同一技能库的智能体共享。由此把静态检索图转变为可演化的检索基础设施。

## 2. 方法论

### 2.1 核心思想
- **SE-GoS**：免训练框架，保留原 GoS 检索流程完全不变，只演化其读取的图（边集 E、边权 w、节点描述 φ），节点集 V 与各关系权重 λ_r 固定。
- **关键机制**：PPR 的转移算子直接读取边权，因此重连/重加权图即可改变检索结果，而检索代码保持“固定消费者”；种子与重排阶段消费描述，故修改描述会改变语义种子分与匹配分。
- **冷启动图**：非 GoS 完整类型图，而是**确定性 semantic-only 相似图**（签名 token 重叠 top-k 近邻，无 LLM、无 embedding 服务）。主实验 k=1，1000 节点、863 条语义边。
- **经验信号**：单次 GoS 评估即产出轨迹 T_t = (q_t, r_t, B_t, U_t, tokens_t)，其中 r_t 为验证器奖励，B_t 为检索包，U_t 为轨迹中**实际使用**的技能集（可从 B_t 之外发现技能）。

### 2.2 三类互补更新（离线、按依赖顺序执行）

**(A) 拓扑更新（离散边集，改变边类型）**
- **Workflow 边**：成功轨迹中，检索种子 u 与被使用技能 v（u≠v）共现计数 c_uv 递增，权重 w_wf = min(0.9, 0.6 + 0.05(c_uv − 1))，即一次成功共现即连边，重复强化并封顶。
- **Dependency 边**：成功试验中 u 先于 v 使用，且 u 输出与 v 输入的 schema 重叠 ≥ ζ=0.6（与 GoS 离线阈值一致）时添加——schema 预测前置，轨迹认证。
- **Avoid 边**：失败试验中成对共现 ≥ θ_avoid 且从未在成功试验共现，权重为 0，对扩散算子不可见，仅在 bundle 组合时消费（丢弃与已选技能冲突的候选并补位）。本实验 k=1 轨迹下为空，k=8 下仅 1 条，报告但未实际启用。
- **不诱导 alternative 关系**：可互换性是反事实主张（关于未发生的执行），观测轨迹无法认证；而共载伤害可由失败共现直接见证。
- **剪枝**：对检索出现 ≥ θ_obs=2 次但从未被使用的 head 技能 v，其所有入向语义边权重 ×0.5，低于地板值则删除（软剪枝 + 离散删除）。

**(B) 边权更新（连续权重）**
- 对奖励 r_t > 0 的试验中每个被使用技能 v，所有指向 v 的边：w(u→v) ← w(u→v) + η·r_t，η=0.1。
- 即“检索 u 导致成功使用 v”的边被强化，失败试验贡献零正信用。单轮协议直接使用原始累积权重。

**(C) 节点更新（文本描述，单轮文本梯度）**
- 针对“被使用但未被良好浮现”的技能：在失败试验（r_t < r_succ=0.9）中被使用，且描述使其在检索包中排名低于 n_rank=3。
- 借用 ProTeGi 的文本梯度下降，做单轮、技能局部变体：
  1. **梯度**：LLM critic ∇ 检视查询 q、当前描述 d_s 与检索证据，产出自然语言批评 g_q；
  2. **编辑**：LLM editor δ 沿批评反方向修订，锚定原文，编辑预算 ≤50 token；
  3. **蒙特卡洛探索**：生成 p=2 个释义变体；
  4. **离线选择**：用 E(q,s;d)（描述 d 下 s 在 q 上的检索排名）离线评分，选使 Σ_q E(q,s;d) 最大的描述，平局取编辑距离最短者。
- 成本 O(|Q_s|·(1+p)) 次 LLM 调用/受影响技能，与库规模无关；默认开启 no-eviction guard，拒绝会把实际使用技能挤出 top-K 的改写。

### 2.3 演化后检索
- 检索过程与 GoS 完全一致：ξ=0 纯词法种子 → 反向感知 PPR（重启 α=0.2）→ 预算内重排与水化。
- 最终排序：ρ_i(q) = s*_i(q; G(T), w(T), d*) + μ·m_i(q; d*)，函数形式不变，只是读取的图已演化。
- **部署保障**：置信加权插值 w(e) = (1−λ_c(e))·w_0(e) + λ_c(e)·w̃(e)，λ_c = n_e/(n_e+n_0)，低证据边保留静态先验；单轮协议未启用，仅作为多轮/冷启动保障。

## 3. 实验设计

- **Benchmark 与场景**：
  - **SkillsBench**：87 个真实技术任务 + 官方 1000 技能库，主实验平台（保留提升空间）。
  - **ALFWorld dev split**：同协议跨域 sanity check；在 deepseek-v4-flash-0731 与 gpt-5.2-codex 上已接近饱和（图方法行在 88–94），仅作稳健性检查。
  - 任务按 50/37 分层划分做留出评估，**从不子采样**，每个任务在所有 regime 中使用。
- **模型（backbone）**：deepseek-v4-flash-0731（主，经 tcodex wrapper，每任务 2 次尝试，最多 8 并发 Docker）、minimax-m2.7、gpt-5.2-codex。
- **对比方法**：Vanilla（全库加载）、Vector retrieval、static GoS、SkillDAG（自演化对比；因官方实现需 embedding 服务与 LLM 冷启动，按本文协议重测而非引用数字）、SE-GoS。
- **评估协议**：
  - **部署效用协议**：全部 87 任务生成轨迹 → 演化一轮 → 全部 87 任务在演化图上重测（n=174 attempts）。
  - **留出评估**：仅在 50 训练任务上演化，在不相交的 37 评估任务上测量（n=74）。
  - **多轮演化曲线**：round 0–3 各自重新演化并重测全部 87 任务。
  - **2³ 因子消融**：{topology, edge, node} 的全部 8 个子集。
  - **检索接口消融**：同一演化图、同一排序下，融合 bundle 对比 SkillDAG 式三通道输出（matches / neighbors / conflicts），在更密的 k=8 子板上进行。
- **指标**：平均奖励 R（%）、平均每次尝试输入 token T（M）、agent-only 运行时 S（秒）。
- **噪声校准**：推断单位为任务（n=87），配对标准误约 3–3.6 奖励点，所有比较按 ±6–7 点带解读；带内差异视为未分辨。
