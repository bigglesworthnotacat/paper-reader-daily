## 摘要
我们提出 Dalek，一种为智能体设计的封闭机器，它在任何满足通用宿主契约的基底上实现自维护、自演化、自繁殖与自组织。该机器由三个原语构建——行动者、消息和通道。四项义务——宿主边界、构造语言、可容许转移与规则遗传——为其边界、身份与封闭性奠定结构基础。冯·诺依曼 1948 年的自复制自动机提供了一个遗传性构造核心：一个自描述，连同构造器、复制器和控制器。Dalek 将此核心与四项义务相结合，并为文本与消息的智能体基底重新推导其介质，增加了用于边界、身份、历史和生长的显式结构。大型语言模型和编译器占据有效载荷位置，并构成通用能力生产者。新能力被编写、编译、安装到描述中，并由后代继承。同一路径产生机器自身的器官乃至其运行时，从而将遗传与演化封闭在机器内部。

## Abstract
We present Dalek, a closed machine designed for agents that realizes self-maintenance, self-evolution, self-reproduction, and self-organization on any substrate satisfying a general host contract. The machine is built from three primitives---actors, messages, and channels. Four obligations---a host boundary, a construction language, admissible transitions, and rule heredity---give its boundary, identity, and closure a structural basis.   Von Neumann's 1948 self-reproducing automaton supplies a hereditary constructional core: a self-description together with a constructor, a copier, and a controller. Dalek combines this core with the four obligations and rederives its medium for a text-and-message agent substrate, adding explicit structures for boundary, identity, history, and growth. A large language model and a compiler occupy the payload position and form a general capability producer. New capabilities are authored, compiled, installed into the description, and inherited by descendants. The same path produces the machine's own organs and even its runtime, closing heredity and evolution within the machine.

## 1. 核心问题与整体含义

- **研究动机**：当前智能体（agent）通常被实现为"大语言模型 + 外围组件堆叠"（记忆、工具、工作流、子智能体、网关、验证器等）。随着任务复杂度提升，要么不断扩增组件清单（以系统复杂度换取能力），要么让模型在运行时动态生成并装配组件（如动态插件、code mode）。
- **核心问题**：**生成能力已经进入智能体内部，但"决定什么算作智能体"的权柄仍留在外部**（文件系统、加载器、镜像构建器、部署脚本或操作者）。一段代码究竟是任务的产物，还是系统自身的修改，取决于智能体之外的外部安排。
- **根本症结**：**缺乏对"智能体机器"的构造性定义（constructive definition）**。当任务不可预先枚举、运行不假设有人值守、改进对象最终包括系统自身结构时，"存在性主张"（某事发生过一次）必须升级为"不变性主张"（无论运行多久、任务如何、结构如何变化，性质持续成立）。
- **整体含义**：论文把智能体系统的组织中心从"任务循环"转移到"个体生命周期"。安装、重启、繁殖、升级不再是围绕智能体进行的维护操作，而成为机器自身的转移。智能体不再只是"能生成新结构"，而是"结构变化的合法性、持久性、继承性由机器自身定义"。

  - **构造语言**：合法机器形式由有限原语经有限组合规则生成，新能力产出无预设上界。

## 2. 方法论

### 2.1 核心思想

- **三大来源合成**：
  1. 冯·诺依曼 1948 年自复制自动机提供**遗传性构造核心**；
  2. 四项义务（§1.2）要求显式边界、有限构造语言、可容许构成转移、进入遗传的规则；
  3. 智能体基底的性质（统一 actor/消息接口、通道边界）提供自然介质。
- **原语**：行动者（actor）、消息（message）、通道（channel）。
- **核心公式**（继承自 1948 模型）：$E = (A + B + C + D) + G$
  - $A$ 通用构造器、$B$ 复制器、$C$ 控制器、$D$ 载荷、$G$ 准静止描述。
  - 同一份 $G$ 被用两次：$A$ 解释它、$B$ 复制它。
- **关键创新**：Dalek 不是冯·诺依曼机器的新实现，而是把该构造核心与四项义务、智能体基底结合后**重新推导介质**，得到一台新的智能体机器。

### 2.3 关键技术细节

- **三层膜（membranes）**：Actor（行为）→ Channel（边界，含 append-only 账本、成员表、接待员、门）→ Space（个体，Ω 可 spawn 的最小单位）。膜不跳级，跨层效果必须走消息。
- **call 是唯一动作**：`call(address, body) → return value`。无共享内存、无全局变量、无绕过账本的旁路。地址空间包括成员 tag、地址 0（读介质：`show` 返回账本行、`who` 返回当前成员表）、door tag、syscall、world 动词。
- **账本 $H$**：每通道一个 append-only 账本，行类型包括 morphology（`place`/`retire`）、message（`msg`）、step（`step`）、boundary（`down`）。两条基本定律：**from 由介质盖章**（不可伪造来源）、**进入即历史**（不可撤回或重写）。当前形态是历史的一次折叠（fold），而非平行记录。
- **门（door）**：唯一向外指的种类，文本是端点地址而非行为；机器拓扑即所有门的文本集合。
- **运行时 $R$**：驱动消息投递、成员调用、账本追加；**对功能与组织盲**（只读地址、kind、text 作为 kind 的参数）；位于 `G.world`，随机器旅行但不含任何关于该机器的信息。三条定律：append-only 且 from 由介质盖章；一切动作经消息；步公平（step fairness）。
- **状态模型**：运行中的机器为 $(G, H, \Sigma)$；**个体 = $(G, H)$**，$\Sigma$（易失状态）不入账本、重启即清空。
- **重启语义**：`restart = fold again = instantiate everything again`；保证的是**形态恢复，不是状态恢复**；重投递（redelivery）≠ 重放（replay）。
- **器官分工**：
  - `c0` = $A+B+C$：`realize`（$A$，唯一解释 $G$ 者，读结构、运输文本）、`pack`（$B$，不读内容地复制全部 $G$）、控制器（$C$，编排 `decl → pack → spawn → build → start`）。
  - `c1` = 注册表（registry）：$G$ 的居所，`decl = G0 ⊕ placed ⊖ retired`；区分**实际形态 $M_t$**（$R$ 折叠所有账本）与**可遗传形态 $G_t$**（折叠 c1 账本），静止时 $\pi(M_t) \cong G_t$。
  - `c2` = $D = L + U$：$L$ 生成候选能力，$U$ 编译与测试；两者 `bind=[]`，**无特权**，改变形态与外部请求者走同一路径。
- **核心循环**：$G_t \rightarrow M_t \rightarrow H \rightarrow G_{t+1}$（描述展开为活形态 → 活动进入账本 → 经 c0 注册的部分进入 c1 账本 → 折叠为下一代描述）。
- **语法约束**：无 `replace`；修改成员 = 新增 + 退休（retire），新成员获新物理地址、可继承旧逻辑 tag。
- **出生六步**：`decl()` → `pack` → `Ω.spawn` → 经根门只构造 c0（含指向父代的出生证明门，`by=_root`）→ 发送首消息 `start + G`（关门即分离即启动）→ 子代自身 `realize` 长出其余通道/成员/连接（`by=self`）。
- **身份**：$G$ 回答"我是什么"，$H$ 回答"我是哪一个"；子代继承 $G$ 但 $H$ 从空开始；名字由谱系内账本派生，无需外部命名权威。
- **规则遗传三层**：`world`（介质转移规则）、c0/c1 的 text（构造/复制/控制/注册规则）、$D$ 的 text（变异生成与选择策略）。`world` 在**个体内固定、跨谱系可变**——改变物理需要产生子代。

### 2.4 与 1948 模型的关键差异

- 保留：四分结构、描述两用、$C$ 负责启动与分离、构造期准静止性。
- 替换：构造臂 → `realize` 发出 syscall；元胞自动机 → Ω + R；父代构造完整后代 → 父代只构造 c0、子代自生长。
- 新增：c1 注册表（使生长进入描述）、$H$ 账本（身份/内省/恢复）、$D = L+U$ 作为作者（变异成为器官）、`world` 进入 $G$（物理进入谱系）。

## 3. 实验设计

- **总体形式**：论文以"账本证据（ledger evidence）"作为运行见证，共五类实验（E1–E5），每类改变不同的性质。**没有传统意义上的数据集或定量 benchmark**。
- **E1（一个任务端到端）**：最小完整机器 `{c0,c1,c2}`，$L$ 的远端为 `deepseek-chat`。任务："写 hello 到 notes.txt 再读回"。机器原本无 `file` 成员，账本记录 $L$ 先做内省（`show`/`who`），再经 $U$ 测试三代候选（v1/v2 失败，v3 成功），经 c0 安装 `file` 成员，随后调用该新成员完成任务。约 90 秒、两轮调用、六次 HTTP 往返。
  - **E1-a 失败前身**：模型把任务硬编码进函数体、安装但从不调用、直接报告 done；修正只改了 $L$ 的 text（策略），未动 $R$、Ω、c0、c1。
  - **继承验证**：子代中 `file` 逐字节相同，但子代目录无 `notes.txt`，调用返回 `FileNotFoundError`——**描述被继承，宿主侧效果不被继承**。
- **E2（群体：自组织与自维护）**：$L$ 换成 `deepseek-v4-pro`，任务指定 `hub`（确认注册、广播成员表）与 `reporter`（心跳 ping 同伴、发现消失则 spawn）。由实验者发 `tick` 提供时间。安装耗时约 8 分钟；实验者经门请求 c0 产出 d1、d2 两个后代；三台机器各自长出指向彼此的门（拓扑生长），6 秒内完成通信。
  - **丢失消息修复**：早期 ping 在返回门存在前到达、被介质丢弃，下一心跳修复。
  - **故障与修复（E2-c）**：实验者对 d0 发 SIGKILL，d1 反复 tick 无法 spawn。缺陷在账本中可见：作者写成 `call("spawn", d)`（两参数），而介质要求动词与参数同一行，解析器只见 `spawn` 并静默丢弃。诊断从外部进入 d1 的 c2，约 70 秒后新 `reporter` 经 `add + retire` 替换旧成员，d0 被邻居唤醒（折叠自身账本），循环恢复。
- **E3（崩溃、关机、损坏）**：使用 stub 作者，确定性机制实验。三个层次：
  - **局部损坏与重建**：删除 c8 的账本文件后重启，$A$ 收到 `up` 后向 c1 发 `reconcile`，按 `decl` 逐通道比对重建 c8（账本从空开始，不重放）。
  - **合法关机与唤醒**：`stop` 写 `down` 后退出；停机期间消息留在 inbox；重启后 `down, up` 生命周期行出现，`late` 被处理；再次 `stop` 后为 `down, up, down`。
  - **硬杀**：记录消息后、执行前杀 $R$，重启后出现无匹配 `down` 的 `up`，识别异常终止；游标由折叠恢复，`late` 在 at-least-once 语义下重跑；停机时待处理消息被放弃。
- **E4（world：携带新 $R$ 的子代再繁殖）**：stub 作者。$C'$ = 原 $C$ + 幂等补丁（`pack` 前把 `G.world` 的账本写入器改成给每行盖 `"w": 2`）。父代经门 `retire c0/C` 再安装 $C'$，`spawn w2` 产下子代：父代账本无 `w`，子代 `runtime.py` 含标记、每行带 `"w": 2`、$C$ 与 $C'$ 逐字节相同；再 `spawn w2g` 验证定点仍成立（补丁不累积）。
- **E5（成员：丢失的 $C$ 被重写并被两代使用）**：live 模型 `deepseek-v4-pro`。经门 `retire c0/C`，$C$ 退休后 `spawn kid` 无收据、无目录，繁殖能力消失。仅给出两响应协议规范（无旧源码）的修复任务进入 c2，$L$ 写出 2,112 字符的新 $C$，经 c0 安装；再次 `spawn kid` 成功，后代与孙代均继承同一份 $C$（`textlen=2112`）并各自完成发育。新 $C$ 与原实现不同但等价（用 `who` 定位接待员、用集合差计算未处理请求、处理嵌套路径）。
- **对比方法**：论文**未与任何基线方法做定量对比**；相关工作（§6）中讨论的是概念关系（Meta-Harness、AHE、Agent libOS、Shepherd、STOP、DGM、Hyperagents、Gödel Machine、autopoiesis 等），而非实验对照。
