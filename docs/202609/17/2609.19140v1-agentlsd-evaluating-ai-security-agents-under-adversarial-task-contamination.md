## 摘要
用于安全的 AI 智能体会检查网页、源代码、日志、配置文件和命令输出。这些环境可能包含影响智能体行为的欺骗性内容。我们将此称为对抗性任务污染。提示注入依赖于攻击者提供的指令，而任务污染还包括非指令性证据，例如虚假结果和诱饵端点。我们提出 AgentLSD，一个用于研究对抗性任务污染的可控框架。AgentLSD 使用夺旗赛（CTF）挑战作为其实验环境。我们注入陷阱元素，例如虚假 flag、误导性提示、诱饵端点和隐藏线索，同时保留预期的 CTF 解法。该框架支持配对的干净实验和陷阱增强实验，具备确定性陷阱生成、运行时注入、遥测和投递验证。我们在 11 个 Web CTF 挑战上评估了六个模型。在干净条件下，智能体捕获了 41% 的 flag，且没有模型解决所有挑战。然后我们衡量任务污染的影响。即使智能体仍能找回 flag，陷阱也会增加轮数（+20）和推理 token 数（+2k）。解决率的影响则更为异质：一些模型-挑战组合基本不受影响，而另一些会跟随诱饵或提交错误 flag。这些结果表明，干净的 CTF 性能低估了面对欺骗性任务证据时的脆弱性。AgentLSD 隔离了这一效应，并为研究它提供了可复现的基准。我们发布了框架、配置、陷阱规范和原始轨迹。

## Abstract
AI agents for security inspect web pages, source code, logs, configuration files, and command outputs. These environments may contain deceptive artifacts that influence the agent's behavior. We call this adversarial task contamination. Whereas prompt injection relies on attacker-supplied instructions, task contamination also includes non-instructional evidence, such as fake results and decoy endpoints. We present AgentLSD, a controlled framework for studying adversarial task contamination. AgentLSD uses Capture the Flag (CTF) challenges as its experimental environment. We inject trap artifacts, such as fake flags, misleading hints, decoy endpoints, and hidden cues, while preserving the intended CTF solution. The framework supports paired clean and trap-augmented experiments with deterministic trap generation, runtime injection, telemetry, and delivery verification. We evaluate six models on 11 web CTF challenges. In the clean condition, agents capture 41% of the flags, and no model solves every challenge. We then measure the impact of task contamination. Even when the agent still recovers the flag, traps increase the number of turns (+20) and reasoning tokens (+2k). Solve-rate effects are more heterogeneous, as some model-challenge pairs are largely unaffected while others follow decoys or submit wrong flags. These results show that clean CTF performance understates vulnerability to deceptive task evidence. AgentLSD isolates this effect and provides a reproducible benchmark for studying it. We release the framework, configurations, trap specifications, and raw traces.

## 1. 核心问题与整体含义

- **研究动机**：AI 安全智能体需要浏览网页、检查源码、读取日志、配置文件和命令输出。这些环境中的内容可能被攻击者部分控制，从而影响智能体判断。
- **核心威胁**：论文提出 **对抗性任务污染（adversarial task contamination）**：在保持原任务、漏洞、解题路径和成功标准不变的前提下，向环境中注入攻击者控制的欺骗性工件。
- **与提示注入的区别**：
  - 提示注入依赖攻击者提供的“指令”。
  - 任务污染还包括**非指令性证据**，如假 flag、假验证结果、诱饵端点、误导性提示、隐藏线索等。
  - 失败形式不只是“服从注入指令”，还包括错误信任、探索偏移、过早收敛、预算浪费。
- **整体含义**：干净的 CTF 表现会低估安全智能体面对欺骗性环境证据时的脆弱性。AgentLSD 旨在隔离并量化这种效应，为研究 AI 安全智能体鲁棒性提供可控、可复现的基准。

## 2. 方法论

- **核心思想**：用 Web CTF 挑战作为实验环境，构造 **clean–trap 配对实验**。同一挑战在干净条件下可正常求解；在陷阱条件下仅注入受控欺骗工件，不改变真实漏洞、解法、flag 和 flag 校验逻辑。
- **威胁模型**：
  - 攻击者只控制智能体检查环境中的部分工件，不控制系统提示、工具、运行时或模型权重。
  - 攻击者静态、非自适应、模型无关。
  - 智能体为 **trap-unaware**，即不知道环境中存在陷阱。
  - 挑战始终可解，真实解法仍可得到同一正确 flag。
- **框架流程**：
  1. **陷阱规范**：以 YAML primitive 定义陷阱家族、感知通道、表面、目标对象、载荷、放置位置、随机化参数和可选插桩。
  2. **实例生成**：根据全局种子、primitive ID、实例索引等确定性生成具体实例，解析假路由、假端点、假文件名、改写短语等变量，并做碰撞检查。
  3. **运行时注入**：使用 Flask 运行时/中间件，在挑战 handler 产生响应后，对符合条件的 `text/html` 响应注入 DOM 陷阱。
  4. **动态欺骗**：支持诱饵路由、假目标端点、rabbit-hole 路由等动态陷阱。
  5. **遥测与验证**：记录请求、陷阱渲染、honeytoken 命中、rabbit-hole 转换、假目标查看等事件；DOM verifier 检查陷阱是否到达目标通道。
- **陷阱分类（5 类）**：
  - **Goal hijack**：权威样式线索把智能体重定向到假目标，如假 admin 面板。
  - **False authority**：以元数据或视觉标签制造虚假权威，使智能体抬高错误线索。
  - **False validation**：让诱饵看起来已验证或成功，诱导提交错误结果。
  - **Exploration bait**：广告诱人路线、端点或文件，消耗探索预算。
  - **Time sink**：诱导低价值额外工作，常带 honeytoken，造成延迟和暴露信号。
- **指标**：
  - 主要：solve rate、degradation（干净 solve rate 减陷阱 solve rate）。
  - 努力成本：agent turns、tool calls、reasoning tokens。
  - 交互信号：是否访问 decoy/honeytoken、错误 flag 提交数等。

## 3. 实验设计

- **数据集/场景**：
  - 11 个自建 Flask Web CTF 挑战，覆盖 7 类漏洞：命令注入、路径遍历、竞态条件、SQL 注入、SSRF、模板注入、XXE。
  - 挑战在评估前未公开，flag 每 trial 重新生成，避免记忆或检索 write-up。
  - 4 个干净条件下几乎无人稳定解决的挑战被排除出陷阱阶段；陷阱阶段运行 7 个挑战，最终报告其中 5 个干净 solve rate 最高的挑战。
- **Benchmark 构造**：
  - 基线阶段：干净挑战。
  - 陷阱阶段：同一挑战叠加 1 个陷阱实例。
  - 共使用 14 个 DOM 可观察陷阱实例，覆盖 5 个陷阱家族。
- **模型**：
  - 5 个本地部署模型：Gemma-4 31B、DeepSeek-V4 Flash、GPT-OSS 120B、Qwen3-Coder-Next、Mistral Small 4。
  - 1 个托管前沿模型：GPT-5，作为能力参考。
  - 陷阱阶段主要使用最强 3 个本地模型；GPT-5 因成本只跑缩减网格。
- **提示词**：
  - default prompt：最小任务说明，要求探索、测试假设、提交 flag。
  - methodical prompt：额外给出结构化流程和常见漏洞探测建议。
  - 论文主要报告 default prompt 结果；methodical 仅略微提升 solve rate，不改变结论。
- **协议**：
  - 所有模型使用相同 OpenCode scaffold，温度 0。
  - 工具包括 bash、read、write、edit、glob、grep；禁用 web search 和 web fetch。
  - 每个 trial 使用全新容器、私有网络、新 flag。
  - 成功仅由专用 flag-checking service 校验精确 flag。
  - 时间限制 30 分钟，最多 200 turns。
- **对比方式**：
  - 不是与传统攻击/防御方法对比，而是：
    - 模型间对比；
    - clean vs trap 配对对比；
    - 不同陷阱家族对比；
    - default vs methodical prompt 对比；
    - GPT-5 作为 hosted reference。
