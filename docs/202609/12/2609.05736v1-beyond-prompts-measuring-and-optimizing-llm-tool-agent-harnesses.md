## 摘要
LLM 工具智能体无需重新训练即可通过修改围绕固定模型的运行时框架来改进：提示词、工具接口、中间件、状态处理与恢复逻辑。我们将这一设定研究为面向固定模型多轮工具智能体的资源受限框架选择，并将搜索面限定于提示词和工具边界中间件：编辑是在工具边界处受保护的拦截，而不是对智能体执行逻辑的任意重写。我们与优化器无关的协议报告平均留出提升、最差条件提升、可重复性、记录的成本诊断，以及 RelLift95(B)——对预算 B 下所选框架留出增益的保守估计。我们以仅提示词优化器和提示词加中间件优化器实例化该协议，其中包括 PRISM，它在 Pareto 搜索中对失败进行聚类，并将修复路由至提示词、工具边界中间件或联合编辑面。在 BFCL 多轮、tau2-Retail 和 tau2-Telecom 上，PRISM 取得 14.2、14.9 和 10.1 个百分点的平均留出提升，并在全部三个基准上获得正的经验 RelLift95；组件消融表明，这一优势主要归因于失败面路由和编辑模式约束。跨优化器的结果表明，某些搜索过程偶尔能找到大幅提升，但仍会选择脆弱的更新，因此所选框架的可靠性应与平均留出提升一同报告。

## Abstract
LLM tool agents can be improved without retraining by modifying the runtime harness around a fixed model: prompts, tool interfaces, middleware, state handling, and recovery logic. We study this setting as resource-bounded harness selection for fixed-model multi-turn tool agents, with the search surface scoped to prompts and tool-boundary middleware: edits are guarded intercepts at the tool boundary, not arbitrary rewriting of agent execution logic. Our optimizer-agnostic protocol reports mean held-out lift, worst-condition lift, repeatability, logged cost diagnostics, and RelLift95(B), a conservative estimate of the held-out gain of the harness selected under budget B. We instantiate the protocol with prompt-only and prompt-plus-middleware optimizers, including PRISM, which clusters failures and routes repairs to prompt, tool-boundary middleware, or joint edit surfaces within a Pareto search. On BFCL multi-round, tau2-Retail, and tau2-Telecom, PRISM obtains mean held-out lifts of 14.2, 14.9, and 10.1 percentage points and positive empirical RelLift95 on all three benchmarks, and a component ablation attributes the margin chiefly to failure-surface routing and the edit-pattern constraint. Across optimizers, the results show that some search procedures can occasionally find large gains but still choose brittle updates, so the reliability of the chosen harness should be reported alongside average held-out lift.

# 论文总结：Beyond Prompts: Measuring and Optimizing LLM Tool-Agent Harnesses

## 1. 核心问题与整体含义（研究动机与背景）

- **研究动机**：LLM 工具智能体（tool-agent）的部署不仅取决于模型本身，还取决于围绕固定模型的**运行时框架（harness）**——包括提示词、工具接口、中间件、状态管理与恢复逻辑。无需重训模型即可通过修改 harness 来提升智能体表现。
- **核心问题**：现有工作（如 OPRO、EvoPrompt、TextGrad、DSPy/MIPROv2、GEPA 等提示词优化，以及 ADAS、Meta-Harness、Trace 等智能体代码编辑）多只报告单次验证提升或最终分数，**无法回答一个部署团队真正关心的问题：自动 harness 搜索过程本身是否可信？**
- **部署张力**：更强的系统通常更可靠，但生产智能体还必须满足延迟与运行时成本约束。报告的一次增益可能依赖于搜索时使用的修复样本、随机优化器选择或智能体评估方差，并附带限制实用价值的搜索成本。
- **论文定位**：将 harness 改进形式化为**面向固定模型多轮工具智能体的资源受限 harness 选择问题**，搜索面严格限定为提示词（prompts）与**工具边界中间件（tool-boundary middleware）**——编辑被界定为工具边界处的受保护拦截，而非对智能体执行逻辑的任意重写。
- **四项评估轴**：有效性（effectiveness，留出提升）、修复分布鲁棒性、同协议可重复性、效率（预算下可靠获得的增益）。

## 2. 方法论：核心思想、关键技术与算法流程

### 2.1 优化器无关的评估协议

- **三类数据划分**：修复集 $D_{repair}$（提出并测试编辑）、门控集 $D_{gate}$（接受候选与最终预评分选择）、评分卡集 $D_{score}$（整个搜索过程从不触碰，仅用于最终报告一次）。开发数据 = 修复集 ∪ 门控集。
- **有效性指标**：留出评分卡提升 $\Delta_{i,m} = S_{b,m}(h_i, D_{score,i}) - S_{b,m}(h_0, D_{score,i})$（百分点），MeanLift 为跨运行配对平均。
- **稳定性指标**：WorstLift（最弱批次下的平均提升）、RepRate（达到阈值 $\delta$ 的运行比例，RR₀ 为正向提升比例）。
- **效率与预算化可靠提升**：给定预算 $B$ 与平均单次成本 $\bar{C}$，可负担运行数 $N_B = \lfloor B/\bar{C} \rfloor$；用预评分统计量 $G_i$ 选择运行 $i^\star(B) = \arg\max_{i \in R_B} G_i$，其留出提升为 $L_B$。
- **RelLift 指标**：$\text{RelLift}_\gamma(B) = Q_{1-\gamma}(L_B)$，即所选留出提升的 $(1-\gamma)$ 分位数，用 5000 次自助重采样估计；论文采用 5% 分位（RelLift95），作为部署方诊断量，**刻意置于优化器循环之外**，是经验下尾估计而非覆盖保证。
- **实现中的 $G_i$**：$G_i = \langle S_{gate}(h_i, D_{gate}),\ 1-\text{Stuck}(h_i, D_{gate}) \rangle$，即先按门控通过率排序、再按可靠性打破平局；超出资源包络的 rollout 计为 stuck。

### 2.2 PRISM 优化器

- **骨架**：GEPA 风格的进化搜索，种群上限 5、默认 10 代，运行于与所有基线相同的执行底座。
- **每代流程**：
  1. 选择最优可行前沿父代；
  2. **分析师 LLM 失败聚类**：基于工具调用序列、状态差异与错误轨迹，按根因分组失败案例，标注每个簇的修复面为 PROMPT、MIDDLEWARE 或 JOINT；
  3. **失败面路由**：将簇路由到三个面约束变异槽——联合槽（可编辑两表面）、提示词槽（仅限 1–2 条通用行为规则）、中间件槽（仅限三种编辑模式）；
  4. 在修复集与门控集上评估子代，当某子代解决了最优子代仍失败的案例时执行交叉（crossover）；
  5. 在**门控通过率**与**可靠性 $R = 1 - \text{Stuck}$** 两轴上更新 Pareto 前沿（支配需两轴不劣且至少一轴严格更优）。
- **跨代失败矩阵**：将每个案例标记为 NEW / RECURRING / PERSISTENT / FIXED；变异器优先处理复发案例、保护已修复案例、不重复已否决方案（除非有新角度）。
- **中间件编辑模式（三选一）**：
  - **静默修正**：在执行前重写畸形参数；
  - **错误阻断**：返回显式工具错误让模型重试；
  - **前置条件阻断**：在允许调用前检查对话或状态历史。
  - 该词汇表**不覆盖**需要跨调用协调、重试、异步状态或控制流变更的修复。
- **对照设计**：BH-PO 与 PRISM-PO 隔离“暴露中间件”的效果；GEPA-MW 与 MIPROv2-MW 在相同中间件面上隔离 PRISM 的搜索机制。

## 6. 主要结论与发现

- **PRISM-MW 在三个基准上均取得最强选择 harness 画像**：
  - BFCL：MeanLift 14.2 pp、WorstLift 11.0 pp、RelLift95 = 12.0 pp，RR₀=100%。
  - τ2-Retail：MeanLift 14.9 pp、WorstLift 5.4 pp、RelLift95 = 10.1 pp。
  - τ2-Telecom：MeanLift 10.1 pp、WorstLift 6.8 pp、RelLift95 = 7.8 pp。
- **平均提升与选择可靠性是两回事**：BH 在 τ2 两个任务上找到最佳单次 harness（MaxLift 分别 23.0 与 20.3 pp），但 WorstLift = −13.5 pp、RelLift95 为负——“强探索者、不可靠选择器”。PRISM 峰值较低但所选尾部为正。
- **中间件表面让每个接收它的优化器都受益**：九个 GEPA/MIPROv2/PRISM 单元格中，从 -PO 到 -MW 的 RelLift95 全部改善。
- **约束与表面同样重要**：BH 的中间件编辑不受约束，在 τ2 两个任务上反而低于其自身的 prompt-only 变体——不受约束的中间件可能引入脆弱运行时行为或改变工具调用语义。
- **消融归因**：失败面路由与编辑模式约束是**唯一在三个任务上均为一阶**的两个组件（移除任一会同时崩塌平均提升与可靠性尾部，且 NoRoute 的置信区间在 Retail 与 BFCL 上与完整 PRISM 不相交）；门控访问与失败矩阵为二阶；交叉在 BFCL 为二阶，但在两个 τ2 域为一阶。
- **失败面分工**：提示词适合全局任务策略（寻求何种信息、如何遵循服务策略、何时升级）；中间件适合工具边界处**可局部观测与校验**的执行约束。在 τ2-Telecom 上 PRISM 正确判断工具边界不是合适表面，产出空中间件、把修复放在提示词。
- **发现的中间件规则是领域特定的、不跨基准迁移**，但发现过程可迁移（三种编辑模式与路由无需手工调参即可按域重新推导规则）。
- **模型角色**：最强的绝对执行模型未必是最佳优化目标（BFCL 上 GPT-5.4 绝对分最高，但 GPT-5.4-mini 以约 1/5 成本匹配平均提升且下尾更强）；提议模型的选择取决于风险偏好——低成本提议模型适合探索，强提议模型在必须“可靠更优”时更安全。

## 7. 优点：方法与实验设计的亮点

- **问题重构有价值**：把“harness 改进”从“能否让某基准分数上升”重构为“自动搜索过程能否被信任”，并给出四轴评估框架，贴近真实部署团队的迭代发布场景。
- **RelLift95(B) 指标设计精巧**：将预算、选择统计量与留出尾部风险统一到一个可计算的诊断量中，明确区分“平均提升”与“所选 harness 在不利情况下的表现”，且刻意置于优化器循环之外避免自利。
- **搜索面与搜索机制解耦干净**：通过 `-PO`

- **搜索面与搜索机制解耦干净**：通过 `-PO`（仅提示词）与 `-MW`（提示词+受约束中间件）两个变体，让四个优化器在同一编辑词汇表下对比，从而把"是否暴露中间件"与"搜索机制优劣"两个混淆因素分开；BH 的中间件变体保持原发表形式（不受约束）则进一步暴露了编辑约束本身的作用。
- **门控纪律的公平处理**：允许不同优化器按其发表形式使用门控（BH 每代查、GEPA/MIPROv2 仅最终接受时查），同时用统一的选择统计量 $G_i$ 与同一划分进行评分，既尊重原方法又保持可比性。
- **对照实验层层递进**：从"表面暴露"（-PO vs -MW）、"搜索机制"（PRISM-MW vs GEPA-MW/MIPROv2-MW/BH）、"组件贡献"（六项消融）、"模型角色"（内层 5 种 × 外层 6 种）四个维度逐步收敛到可归因的结论，逻辑链清晰。
- **失败诊断的可解释产物**：跨代失败矩阵（NEW/RECURRING/PERSISTENT/FIXED）与三槽路由不仅是优化机制，也产出了对"哪类失败适合在哪一表面修复"的可读证据（如 τ2-Telecom 主动判定工具边界不适用而输出空中间件）。
- **成本核算透明**：采用"保守费率卡"（取内部费率与公开价较高者、不应用折扣）并排除评分卡开销，避免了低估搜索成本；同时把成本与 RelLift95 联合报告，直接服务于部署方的预算决策。

## 8. 局限与不足

- **样本量偏小、外部有效性受限**：每个 arm 最多 16 次运行，τ2 评分卡仅 74 例且含模拟器随机性，RelLift95 的下尾估计在小样本下方差较大；作者虽以自助重采样与子采样敏感性分析（n∈{16,12,8}）部分缓解，但仍非覆盖率保证。
- **中间件词汇表覆盖有限**：三种编辑模式（静默修正、错误阻断、前置条件阻断）刻意不覆盖需要跨调用协调、重试、异步状态或控制流变更的修复，因此"中间件无益"的结论只在受约束的编辑面成立，不能外推为"中间件普遍无用"。
- **仅单模型、单执行底座**：主实验固定内层模型与 `create_deep_agent` 底座，harness 收益是否随底座（如不同 agent 框架、不同工具注册方式）迁移未被系统检验；模型角色消融虽扩展了内外层模型，但主要在两个基准上完成。
- **领域特定的规则不可迁移**：论文明确指出发现的中间件规则是领域特定的、不跨基准迁移，可迁移的只是"发现过程"；这降低了单次搜索成果的复用价值，也意味着每个新域都需重新付出搜索成本。
- **优化器与预算的耦合**：RelLift95(B) 依赖可负担运行数 $N_B$ 与成本估计，成本随 token 用量波动，预算包络外的 rollout 记为 stuck，可能使效率指标对运行时波动敏感。
- **门控划分的公平性存在张力**：不同优化器查门控的时机不同（BH 频繁、GEPA/MIPROv2 一次），虽与各自发表形式一致，但这本身会影响搜索轨迹，难以完全消除"门控访问频率"作为混杂因素。
- **成本对比不完全对等**：GEPA 明显更便宜、BH 更贵，论文以 RelLift95 为主指标而非等成本对比，因此"性价比"层面的结论需要读者自行结合 Cost/run 解读。

## 9. 总体评价与启示

- **定位与贡献**：这是一篇"元评估"性质的系统研究，其核心贡献不在于提出一个更强的提示词优化器，而在于把自动 harness 搜索从"分数提升"重构为"资源约束下可被信任的选择问题"，并给出可计算的四轴诊断框架（有效性、修复分布鲁棒性、同协议可重复性、效率）。
- **关键洞见**：平均提升与选择可靠性是两件事——BH 能偶发找到最强单次 harness 却在不利批次下崩溃，PRISM 峰值较低但所选尾部为正；这提示部署团队应关注"最弱批次表现"与"预算内可靠获得的增益"，而非报告的最佳单次成绩。
- **机制层面的可操作结论**：失败面路由与编辑模式约束是唯一在三个任务上均为一线的一阶组件，提示"把失败诊断到正确表面"比"更激进地搜索"更重要；约束（而非仅暴露）中间件是让中间件收益稳定兑现的前提。
- **实践启示**：内层执行模型的最强选择未必是最佳优化目标（成本与下尾需权衡）；外层提议模型的选择应结合风险偏好（探索用低成本模型、求稳用强模型）；新域需重新推导规则，但推导流程可复用。
- **适用边界**：结论最适用于"固定模型 + 多轮工具调用 + 有明确任务策略与状态"的服务型智能体场景；对需要复杂跨调用协调或控制流改写的 harness 改进，其框架与中间件词汇表尚需扩展。
- **可改进方向**：扩大每 arm 运行数、增加多底座与更多真实域验证、把跨调用协调纳入受约束编辑面、以及在等成本口径下重新比较各优化器，将进一步提升结论的稳健性与普适性。
