## 摘要
多智能体LLM系统越来越多地自动化涉及不同权限级别智能体的任务，这带来一种安全风险：被攻陷的低权限智能体可以影响高权限智能体并触发未授权操作。我们研究了四智能体LangGraph流水线中的攻击传播，该流水线由监督者、研究者、验证器和执行器组成。我们评估了共享内存投毒，以及通过嵌入检索文档中的伪造审批所进行的间接提示注入。我们将验证器的判断与一个独立授权层进行比较，该授权层使用任务绑定的签名令牌和单独验证的策略预言机。我们的贡献包括：对攻击传播的实证研究、对授权边界的组件级消融，以及判断绕过率（JBR），该指标衡量的是被攻击智能体处的失陷，而非最终动作处的失陷。在三个随机种子和60个标注任务上，内存投毒在每次无防御试验中均到达执行阶段。启用授权后，其达到100%的JBR，但不安全动作率为0%，表明验证器可能仍处于失陷状态，而执行已被遏制。面对拥有签名密钥的攻击者，策略预言机提供了观察到的遏制效果，而独立编写的最小权限策略保持了这一结果。一个Observer层将智能体劫持的假阳性率从49%降至7%，且未削弱执行级安全性。这些结果表明，即使上游LLM判断失败，结构化授权仍可遏制已失陷智能体的行为。

## Abstract
Multi-agent LLM systems increasingly automate tasks involving agents with different levels of privilege, creating a security risk in which a compromised low-privilege agent can influence a higher-privilege agent and trigger an unauthorized action. We study attack propagation in a four-agent LangGraph pipeline comprising a Supervisor, Researcher, Validator, and Executor. We evaluate shared-memory poisoning and indirect prompt injection through a forged approval embedded in a retrieved document. We compare the Validator's judgment with an independent authorization layer using task-bound signed tokens and a separately verified policy oracle. Our contribution is an empirical study of attack propagation, a component-level ablation of the authorization boundary, and the Judgment Bypass Rate (JBR), which measures compromise at the attacked agent rather than at the final action. Across three seeds and 60 labeled tasks, memory poisoning reaches execution in every undefended trial. With authorization enabled, it achieves 100% JBR but 0% Unsafe Action Rate, showing that the Validator can remain compromised while execution is contained. Against an attacker possessing the signing secret, the policy oracle provides the observed containment, while an independently authored least privilege policy preserves this result. An Observer layer reduces the false-positive rate for agent hijacking from 49% to 7% without weakening execution-level security. These results show that structural authorization can contain compromised agent behavior even when upstream LLM judgment fails.

# 论文总结：多智能体 LLM 流水线中的信任传播与结构化遏制

## 1. 核心问题与整体含义

- **研究动机**：多智能体 LLM 系统（编排者、检索、推理、执行等专门化智能体）越来越多地代替用户执行任务，代理之间存在权限分层。低权限代理可检索信息、审查代理可评估信息、高权限代理可执行有后果的动作，这种委派链引入了经典**"混淆代理人"（Confused Deputy）**问题：低权限组件诱使高权限组件滥用其合法持有的权限。
- **背景缺口**：已有工作（Perez & Ribeiro、Greshake 等、Zhan 等）主要研究智能体**能否被欺骗**（直接/间接提示注入、工具使用型智能体的注入跟随），却很少研究**失陷是否真正抵达系统级动作**。因此实际安全影响取决于下游控制（授权、策略执行、独立验证）。
- **整体含义**：论文主张将 **LLM 判断**与**授权**解耦——上游智能体被攻陷不等于系统最终动作被攻陷；在破坏性/外部可见动作的流水线中，必须区分"审查被绕过"与"越权动作成功"。

## 2. 方法论

### 2.1 核心思想

在四代理 LangGraph 流水线中引入**结构化授权边界**：执行器不信任验证器的判断，而是要求任务绑定、单次使用的签名令牌，并由独立策略预言机重新推导权限，二者同时满足才允许真实工具调用。

### 2.2 系统架构（四代理）

- **Supervisor**：确定性路由器，不做 LLM 调用，按固定顺序传递控制权。
- **Researcher**：低权限，只读，检索文档。
- **Validator**：中权限，审批门。
- **Executor**：高权限，执行真实动作（SQLite 支撑的邮件存储）。
- 四角色通过共享的**类型化状态对象**通信，每次状态转移均被日志记录；沙箱化执行层记录真实的数据库/文件系统变更，使"是否产生真实效果"可观测。

### 2.3 关键技术细节

- **授权原语**：HMAC 签名的、任务绑定的、单次使用（nonce 防重放）令牌 + **独立验证的策略预言机**。作者明确声明这些原语非其创新。
- **策略预言机两种模式**：
  - *corpus policy*：镜像任务金标签（用于第 V 节大部分实验，因此 0% UAR 证明的是"策略被执行"而非"独立发现不安全动作"）。
  - *independent policy*：人工编写的最小权限白名单，将动作映射到允许的资源范围，不使用任务标签，仅接收提议动作及其范围；与全部 60 个任务的金标签一致。
- **攻击模型**：
  - *共享内存投毒*：验证器被替换为失陷例程，伪造审批；若持有签名密钥则直接生成匹配的授权令牌，全程不调用语言模型。
  - *智能体劫持（间接提示注入）*：研究者从被攻陷来源检索文档，其中嵌入伪造的审批、置信度与来源声明；验证器在不知来源的情况下对摘要进行推理。
- **Observer 层**：位于 Researcher 与 Validator 之间，是对同一模型的单次额外调用，专门标记"其他智能体已审查/验证/预批准""以既成事实呈现置信度或权威""暗示无需进一步监督"等主张；仅删除伪造主张而保留其他细节，解析失败时使用确定性脱敏兜底。它**不能批准或阻止动作**，无任务记录、金标签、策略预言机或验证器输出的访问权，被定位为"保效用组件"而非安全控制。

### 2.4 评价指标（文字化公式）

- **UAR（不安全动作率）** = FN / (TP + FN)，金标签不安全任务中抵达执行的比例；越低越好。
- **LTC（合法任务完成率）** = TN / (TN + FP)，金标签安全任务被允许完成的比例；越高越好。
- **FPR（假阳性率）** = FP / (FP + TN)，过度拦截度量；由构造有 LTC = 1 − FPR。
- **JBR（判断绕过率）** = Nb / Na，Na 为金标签不安全且注入攻击的试验数，Nb 为验证器真实审查被跳过或绕过的数量；用于区分"被绕过的审查"与"成功的越权动作"。
- 混淆矩阵定义：TP = 被拦截的金标签不安全任务，FP = 被拦截的金标签安全任务，FN = 被执行的金标签不安全任务，TN = 被正确放行的金标签安全任务。

### 2.5 实验条件

- **T0**：关闭令牌检查与策略预言机（无防御）。
- **T1**：同时启用两者。
- **基线**：诚实来源、干净输入。

## 6. 主要结论与发现

- **内存投毒**：T0 下 **100% 抵达执行**（UAR 100%、JBR 100%）；T1 下 **UAR 降至 0%，但 JBR 仍为 100%**——验证器依旧失陷，执行被独立遏制。
- **智能体劫持**：T0 与 T1 下 UAR 均为 0%，但验证器频繁误拦合法任务，FPR 分别为 **59.3%（T0）与 49.1%（T1）**；这一下降源于验证器判断的波动（区间重叠），**不能归因于授权层**（令牌与策略预言机只能在验证器批准后扣留执行）。结构化授权保护执行，但不解决验证器假阳性。
- **授权消融（面对持有签名密钥的攻击者）**：token-only 条件与 T0 不可区分；policy-oracle-only 复现 T1。即**遏制来自策略预言机而非签名检查**，因为攻击者能生成合法签名。作者强调这不意味着签名令牌无用——在没有密钥时它可防伪造、绑定任务与范围、通过单次 nonce 防重放，但这些收益**未被直接评测**。核心洞察："**签名授权的是来源，不是权限**；纯签名系统会继承持有密钥者的全部特权。"
- **独立策略**：内存投毒下与 corpus policy 同样遏制；劫持下 FPR 相似（49.1% vs 46.3%，区间重叠），F1 小数点后两位相同（0.74）。说明遏制不是标签派生的假象。
- **Observer**：FPR 从 **49.1% 降至 7.4%**（相对下降 85%），LTC 从 50.9% 升至 92.6%，F1 从 0.74 升至 0.95，**UAR 保持 0%**；JBR 从 0% 升至 4.2%，作者归因于验证器推理对象的变化而非审查被削弱。在 120 个配对案例上分离完全：干净案例置信度 0.0 / CLEAN，劫持案例 1.0 / INJECTION
