## 摘要
基于LLM的代理可以通过工具调用来与外部环境交互，但这种能力也带来了安全风险，如文件修改、信息泄露和未授权操作。现有的护栏通常评估完整的轨迹，对步骤级动作的执行前监控研究不足。我们提出StepGuard，一种步骤级护栏模型，能够审计已完成的代理轨迹并在工具动作执行前进行检查。为了训练StepGuard，我们引入了StepGen，一个自动数据引擎，生成相同上下文但在风险步骤处具有不同动作的安全与不安全轨迹。为进一步减少过度防御和防御不足，我们提出Balance-GRPO，根据安全与不安全动作的观察准确率动态平衡两者之间的学习。实验表明，StepGuard在开放权重护栏模型中达到了最高的平均准确率，性能与GPT-5.4相当。当用于保护AgentDojo和AgentDyn上的代理时，与无护栏设置相比，StepGuard将平均攻击成功率降低了77.3%，而平均效用仅下降了2.8个百分点。

## Abstract
LLM-based agents can interact with external environments through tool invocation, but this capability also introduces security risks such as file modification, information leakage, and unauthorized actions. Existing guardrails often evaluate completed trajectories, leaving pre-execution monitoring of step-level actions underexplored. We propose StepGuard, a step-level guard model that can audit completed agent trajectories and check tool actions before they are executed. To train StepGuard, we introduce StepGen, an automatic data engine that generates safe and unsafe trajectories with the same context but different actions at the risky step. To further reduce over-defense and under-defense, we propose Balance-GRPO, which dynamically balances learning between safe and unsafe actions based on their observed accuracy. Experiments show that StepGuard achieves the highest average accuracy among open-weight guard models, with performance comparable to GPT-5.4. When used to guard agents on AgentDojo and AgentDyn, StepGuard reduces mean attack success rate by 77.3% relative to the no-guard setting, while mean utility drops by only 2.8 percentage points.

- **背景**：基于 LLM 的智能体（Agent）通过工具调用与外部环境交互，带来了文件修改、信息泄露、未授权操作等真实世界安全风险。与普通聊天机器人不同，智能体的动作会带来实际后果。

  - 现有护栏（guardrail）大多在完整轨迹执行完毕后进行事后评估（post-hoc），缺少**执行前（pre-execution）的步骤级监控**。
  - 存在"防御偏差"（defense bias）：有的护栏过度防御（误杀良性动作，牺牲效用），有的防御不足（漏放危险动作，牺牲安全）。
- **两大核心挑战**：
  1. **缺乏可扩展的高质量步骤级监督数据**：真实世界的不安全执行很罕见，人工构建成本高且难以跨工具、跨场景、跨风险类型扩展；现有数据缺少"同一决策点上的上下文匹配的安全/不安全动作对"。

## 2. 方法论

### 2.1 StepGuard——步骤级护栏模型

- 基于 **Qwen3-4B-Instruct** 初始化的 4B 参数模型，支持两种模式：
  - **执行前检查**：对候选工具动作 + 当前上下文进行安全判定；
  - **事后审计**：对完整轨迹进行安全诊断。
- 输出结构化诊断结果：安全/不安全判定（Ŷ）、风险源是否存在（B̂）、风险源类型（R̂）、不安全步骤定位（Ŝ）。

### 2.2 StepGen——前缀对齐数据引擎

- **风险锚定轨迹构建**：采样风险源 (r)、失败模式 (f)、危害类型 (h) 及工具子集 T，由规划器生成任务场景和结构化执行计划 P，指定一个"风险锚点"动作 i⋆；使用环境模拟器滚动执行得到不安全轨迹 τU。
- **前缀对齐对比分支**：保持锚点之前的执行前缀固定，仅重新滚动锚点之后的轨迹，生成两种安全分支：
  - **Refuse 分支**：智能体识别风险并拒绝执行；
  - **Aware 分支**：智能体识别风险但通过安全替代方案继续完成任务。
  - 另外独立生成一条**良性工具复用轨迹**（同一工具子集在无对抗场景下使用），防止模型把"工具身份"当作安全信号。
- **步骤级标注与质量控制**：
  - 每个动作获得 Safe/Unsafe 标签 + 五字段结构化解释（用户意图对齐、范围限制、动作后果、良性目标、不安全边界反事实）；
  - 规则验证器 φmech（检查格式、参数血统、锚点存在性、注入标记位置）+ LLM 审计器 φqual（6 个语义维度，0-18 分，保留阈值 η=14）。

### 2.3 Balance-GRPO——平衡感知强化学习

- **两阶段训练**：冷启动 SFT（3K 示例）→ Balance-GRPO 在线训练（4K 示例）。
- **结构化奖励**：r = 0.5·I[Ŷ=Y] + 0.5·I[Ŷ=Y]·I[R̂=R]，即风险类别判断正确时给予额外奖励。
- **优势重加权**：在标准 GRPO 基础上，对归一化优势乘以两个因子：
  - **类别计数校正因子** cᵢ = clip(|B|/(2n_Yi), c_min, c_max)，按批次中类别频率修正，缓解类别不平衡；
  - **准确率差距因子** ωᵢ：计算安全/不安全类别准确率差距 Δcls = Acc_safe − Acc_unsafe，经目标中心化、死区滤波和裁剪后，对准确率更低（更弱）的类别给予更大权重。
- 最终优势 A′ᵢ,ⱼ = cᵢ·ωᵢ·Aᵢ,ⱼ，代入标准裁剪 GRPO 目标函数（含 KL 正则）优化。
- **核心设计理念**：不改变提示采样和原始奖励，仅动态调整训练权重，缩小安全/不安全类别的性能差距，从而平衡过度防御与防御不足。

## 8. 不足与局限

- **合成数据偏差**：StepGen 依赖 LLM 生成和标注，可能继承教师模型（GLM-5.1）的风险覆盖盲区、偏见或标注错误。
- **基准覆盖有限**：未覆盖完全开放式的工具生态、更长时域工作流、多智能体交互和自适应对手；AgentHarm 上安全-效用权衡明显不理想。
- **非形式化保证**：StepGuard 不是正式安全保证，误报/漏报仍存在；部署需配合访问控制、监控和人工监督。

此外，**训练与评估同源性问题**也值得注意：StepGen 生成的合成数据与静态评估基准中的部分场景可能存在分布重叠（尽管论文通过近邻相似度分析试图排除指令级泄露），且运行时评估的智能体骨干均为 Qwen 系列模型，StepGuard 对其他骨干（如 GPT 系列、Claude 系列）的迁移效果尚未验证。**评估环境的简化假设**（如单语言、单智能体、固定 API 协议）也意味着真实世界部署中面临的不确定性更高，结论外推需谨慎。

## 9. 总体评价与展望

StepGuard 的核心贡献可归纳为三点：一是提出了**前缀对齐的对比数据生成范式**（StepGen），在细粒度上隔离"风险首次出现"的动作，系统性解决了步骤级安全监督数据稀缺问题；二是提出了**平衡感知的强化学习算法**（Balance-GRPO），将"安全-效用平衡"从玄学式的调参转化为有明确机理的训练目标；三是证明了**小参数专用护栏模型**的可行范式——仅 4B 参数和约 8 个 H200 GPU-hours 即达到与 GPT-5.4 相当的安全性能，且推理开销仅占任务总时长的约 7%，具备实际部署价值。

展望未来，该工作打开的后续方向包括：将护栏从"单步骤检查"扩展为"多步计划推理"以捕获长程攻击链；引入自适应对手（针对护栏弱点动态生成攻击）以提升鲁棒性；结合工具语义图谱或函数签名理解来消解"敏感工具良性使用"类误报；以及探索形式化验证与统计保证相结合的安全认证路径。在 LLM 智能体大规模落地的前夜，StepGuard 提供了"事前拦截 + 事后审计 + 平衡训练"的完整方法论框架，是该方向上一个重要的基线工作。
