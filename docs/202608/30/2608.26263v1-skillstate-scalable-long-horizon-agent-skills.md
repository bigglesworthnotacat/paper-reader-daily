## 摘要
大语言模型（LLM）日益作为自主智能体执行复杂、长期运行的程序性技能。现有的智能体运行时通过不断将观察、动作和中间推理轨迹追加到不断增长的对话历史中来维持执行，这会导致延迟退化，并在长时间跨度上引发上下文污染失败。我们提出了SKILL.state，一种运行时架构，用显式、可变的执行状态取代只追加的对话历史。在每个执行步骤中，模型仅接收不可变的技能规范、当前结构化执行状态和最新观察。中间推理在产生经过验证的状态更新后立即丢弃，从而防止提示随执行历史增长。在多种数据集、模型和执行环境中，SKILL.state在显著降低累积令牌消耗的同时提高了任务准确性。我们的结果表明，显式执行状态是用于可扩展长时程智能体技能的一种有效且与架构无关的抽象。

## Abstract
Large Language Models (LLMs) increasingly act as autonomous agents executing complex, long-running procedural skills. Existing agent runtimes maintain execution by continually appending observations, actions, and intermediate reasoning traces to an ever-growing conversation history, causing latency degradation and context-poisoning failures over long horizons. We present SKILL.state, a runtime architecture that replaces append-only conversational history with an explicit, mutable execution state. At each execution step, the model receives only the immutable skill specification, the current structured execution state, and the latest observation. Intermediate reasoning is discarded immediately after producing a validated state update, preventing prompt growth with execution history. Across diverse datasets, models, and execution environments, SKILL.state improves task accuracy while substantially reducing cumulative token consumption. Our results demonstrate that explicit execution state is an effective and architecture-agnostic abstraction for scalable long-horizon agent skills.

## 二、方法论：核心思想、技术细节与流程

### 1. 核心思想
- 抛弃传统的追加式（append-only）对话历史，将执行建模为**显式状态转移**过程。
- 每一步，模型只接收三个要素（公式 1）：
  - **P**：不可变的程序性技能规范；
  - **Σt**：当前结构化执行状态；
  - **Ot**：最新的一条环境观察。
- 中间推理轨迹是**临时计算**：只在当前步用于生成状态更新和动作，验证并应用后立即丢弃（"projection"），永不进入后续提示。利用这个机制，不依赖任何总结或压缩，直接阻断历史累积。

### 2. 执行流程（Algorithm 1）
- 初始化状态 Σ0；
- 循环（t = 0, 1, …, T）：
  1. 从环境接收最新观察 Ot；
  2. 构造提示 (P, Σt, Ot)；
  3. LLM 生成三元组 (Rt, ΔΣt, at)——推理轨迹、状态补丁（JSON 字典形式的键值变更与删除）、待执行动作；
  4. 运行时**确定性验证**状态补丁 ΔΣt；
  5. 应用状态更新：Σt+1 = Σt ⊕ ΔΣt（⊕ 为带 null 删除语义的字典合并操作符）；
  6. 执行动作 at；
  7. 丢弃推理轨迹 Rt，进入下一步。

### 3. Schema 编写
- 执行状态使用领域特定的结构化 schema 表达，schema 按领域统一编写，而非按具体任务逐一编写。
- 例子：在 InterCode CTF 的 100 个异构任务中，只需复用同一个 5 字段 schema（discovered_flags、tested_hypotheses、active_files、working_dir、cmd_summary）。

### 4. 复杂度分析
- 传统对话式运行时：提示长度随步数线性增长 → 累计 token 复杂度 **O(T²)**。
- SKILL.state：提示为 |Pt| = O(|P| + |Σ| + |O|)，与已执行的步数 t 无关（O(1) 有界），累计 token 复杂度严格为 **O(T)**。
- 执行语义从"重放历史、重建状态"转为"维护显式、已验证的当前状态"。

### 3. 对比基线
分为两组：

**主运行时范式：**
- **Prompt (ReAct 风格)**：将所有观察、推理、动作追加到持续增长的完整文本中。
- **Memory（摘要风格）**：保留滚动 3 步对话窗口，外加周期性更新的自然语言摘要。

- **Summary-capped**：对自然语言摘要施加硬 token 上限。
- **ReAct + LLMLingua**：基于小型模型困惑度的有损压缩，将完整历史压到目标预算。

## 六、主要结论与发现

1. **显式执行状态优于历史重放**：在全部受控与公共基准上，SKILL.state 的精度匹配或超越所有基于历史的运行时，且提示大小与执行步数无关（O(1) 有界）。
2. **大幅降低 token 消耗**：累计 token 复杂度从 O(T²) 降为 O(T)。在 Warehouse T=200 场景，SKILL.state 消耗约 122K tokens，而 Memory 基线消耗约 6.1M tokens（约 50 倍差距）。
3. **噪声鲁棒性显著增强**：无关干扰被状态补丁生成过程过滤，后续提示永不包含噪声——高噪声条件下依然保持 ≥0.97 精度。
4. **状态恢复能力质变**：外部状态修改能即时反映到下轮决策，零步恢复；历史基线的过时上下文导致 5~14 步幻觉。
5. **小模型主要瓶颈是结构化输出遵从而非推理能力**：错误中 68% 来自状态覆盖/删除失误，为后续用约束解码改进指明了方向。
6. **"短提示"并不等于"结构化状态"**：预算匹配下的滑动窗口和 LLMLingua 压缩导致严重退化，证明优势的本质是精确的符号状态表征，而非单纯的上下文压缩。

## 八、不足与局限

### 1. 核心假设的适用边界
- 方法假设"执行状态是未来执行的充分统计量"——即过去一切与未来决策相关的信息都能在获知当下被投影到结构化状态中。以下三种场景会失效：
  - 场景一：没有预先固定的 schema，状态结构需在运行中动态发现时；
  - 场景二：某早期观察当时未被识别为重要而未入状态，后来又变得关键时；
  - 场景三：任务目标本身定义为历史轨迹（如审计、调试溯源、行为解释）时，历史是目标输出而非开销。

### 2. 实验覆盖的局限
- 公共基准未覆盖所有模型（仅在 Gemini-3-Flash 上评估），开源模型的真实场景表现未知；
- 未与长期记忆系统（MemGPT、Mem0、MemoryBank 等）直接对比，Memory 基线只是简化风格的摘要基线；
- 状态恢复实验场景较少（每环境 4 个），且全是"外部修改后警报通知"的设置，未覆盖更隐蔽的状态损坏（如无通知静默变更）；
- 未深入探讨动态 schema 或嵌套状态下的性能边界。

### 3. 小模型的结构化输出问题
- 开源小模型（Gemma-4-31B、Qwen-3-8B）在长时程上表现仍然较低（最高 0.42 / 0.34），主要由结构化状态补丁错误引发（68% 的状态覆盖/删除错误），说明当前范式对输出格式遵从度要求较高，需要约束解码等附加手段才能完全释放小模型的潜力。

### 4. 多智能体场景未验证
- 论文仅限单智能体执行。虽然论述了向多智能体的自然扩展方向（共享状态作为协调基板），但并发写入时的冲突消解语义（⊕ 的确定性）尚未实现或验证。

### 5. 安全性考量
- 状态补丁验证位于运行时（确定性层），模型无法通过畸形输出破坏持久状态——这是优点；但状态 schema 本身是攻击面——如果环境或提示被注入恶意约束，恶意状态补丁可能通过验证并污染后续决策。论文未讨论此类针对状态层的安全威胁。

## 总结

SKILL.state 是一项面向 LLM 智能体长时程程序性执行的开创性运行时架构工作。它用"显式可变结构状态"取代"追加式对话历史"，将中间推理作为一次性计算即时丢弃，实现了理论上的 O(1) 提示上界与 O(T) 累计复杂度，在多个模型与基准中同时提升准确率和显著降低 token 消耗。其核心贡献在于揭示了"状态维护"而非"历史压缩"是长时程智能体扩展的正确方向。局限在于"状态即充分统计量"假设并非万能，在小模型和多智能体场景仍面临工程与理论挑战。
