## 摘要
编码代理以开发者的权限编辑文件和执行shell命令，这使得恶意请求能够直接转化为有害行为或功能性恶意软件。现有防御措施存在互补的局限性：权重级对齐对仅使用API的部署者不可用，而输入过滤器和执行边界监控器则需要沿代理轨迹的辅助分类或检查组件。因此，我们引入了SkillShield，一种系统提示防御方法，它从已知攻击或记录的代理失败中离线合成安全技能。这些技能在会话开始时注入系统提示，并在整个工具使用循环中保持活跃。与参考监控器不同，它们通过定义模型在执行期间应遵循的安全策略来保护系统。由于系统提示空间有限，我们研究了三种固定预算的配置范围：全类别，一种技能覆盖所有威胁类别；每捆绑，一种技能针对相关子集；每类别，一种技能专用于单一已知类别，并作为上限参考。这些都不需要运行时请求分类或路由。在RedCode上对六个大型语言模型进行的测试中，默认的全类别技能将恶意软件生成的严重性从3.37降至0.58，并实现了43.6%的执行攻击成功率，与Llama Guard 3的42.7%相当，而无需其单独的8B分类器。每捆绑和类别固定的每类别设置进一步将这一比率分别降至36.2%和14.5%。在两种非自适应越狱家族下，SkillShield在恶意软件生成方面继续优于所有基线。在731个良性任务描述中，SkillShield的平均安全拒绝率为0.14%。这些结果表明，提示空间安全技能在防止LLM编码代理产生有害行为和恶意软件生成方面具有潜力。

## Abstract
A coding agent edits files and executes shell commands with its developer's privileges, allowing malicious requests to translate directly into harmful actions or functional malware. Existing defenses have complementary limitations: weight-level alignment is unavailable to API-only deployers, whereas input filters and execution-boundary monitors require auxiliary classification or checking components along the agent's trajectory. We therefore introduce SkillShield, a system-prompt defense that synthesizes security skills offline from known attacks or recorded agent failures. These skills are injected into the system prompt at session start and remain active throughout the tool-use loop. Unlike a reference monitor, they protect the system by defining the security policies the model should follow during execution. Due to the limited system-prompt space, we examine three fixed-budget provisioning scopes: all-classes, with one skill covering all threat classes, per-bundle, with one skill targeting a related subset, and per-class, with one skill dedicated to a single known class and used as the upper-bound reference. None requires runtime request classification or routing. Across six large language models on RedCode, the default all-classes skill reduces malware-generation severity from 3.37 to 0.58 and achieves a 43.6% execution attack success rate, comparable to Llama Guard 3's 42.7% without its separate 8B classifier. The per-bundle and class-fixed per-class settings further reduce this rate to 36.2% and 14.5%, respectively. Under two non-adaptive jailbreak families, SkillShield continues to outperform all baselines on malware generation. Across 731 benign task descriptions, SkillShield yields a mean safety-refusal rate of 0.14%. These results demonstrate the potential of prompt-space security skills to prevent harmful actions and malware generation for LLM coding agents.

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：LLM 编码代理（coding agent，如 Claude Code、Codex、OpenCode）能够自主编辑文件、执行 shell 命令、调用工具，但其操作权限与开发者相同，因此恶意请求可能直接转化为有害行为（如数据外泄、文件加密）或生成功能性恶意软件（如勒索软件、rootkit）。
- **现有防御的不足**：
  - **权重级对齐**：需要模型权重访问和昂贵的重新训练，不适合仅 API 部署（API-only deployers）。
  - **输入过滤器**（如 Llama Guard 3、Prompt Guard 2）：只能在请求进入前拦截，无法处理代理在运行中从仓库内容、工具输出等渠道收到的恶意指令。
  - **运行时监控器**（如 TaskShield、AGrail）：能在执行前检查候选动作，但增加了模型调用或额外检查组件，带来延迟和成本。
- **本文的目标**：研究一个更早的控制点——将安全策略写入系统提示（system prompt），在模型生成每个动作的上下文层面进行引导，在不增加运行时组件、不修改模型权重的情况下，降低有害行为与恶意代码生成的风险。

## 2. 方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 核心思想
- **SkillShield** 是一种**提示空间防御**（prompt-space defense），以“技能”（skill）为封装形式，将安全策略作为自然语言指令文档注入系统提示。
- 技能在**会话开始时一次性注入**，并在整个工具使用循环（tool-use loop）中保持活跃，从而覆盖代理执行的每一步动作生成过程。
- 不需要运行时请求分类或路由，不依赖额外的模型或检查组件。

### 2.2 关键技术细节
- **技能合成（Skill Synthesis）**：
  - **主动挖掘（Proactive Mining）**：从已知攻击语料中提取检测签名（如特定命令、路径、库调用、行为模式），形成技术性、可审计的规则。
  - **反应式学习（Reactive Learning）**：从无防御代理的失败轨迹中提取攻击未被拒绝的原因，归纳为基于意图（intent）的防御原则，便于跨格式泛化。
- **合成算法（Algorithm 1）**：
  - 输入：攻击数据（主动模式）或失败轨迹（反应式模式），以及 chunk 大小、字符限制、合成器 LLM。
  - 对每个攻击/失败案例提取中间项（签名或原则），然后按 chunk 长度（C=2000 字符）分批调用 `REFINE` 逐步整合到技能文档中。
  - 若技能主体达到 0.9L（L=10,000 字符，约 2,400 token）则提前停止，最后统一添加拒绝指令前缀（preamble）。
  - 合成完全离线进行，不需要在请求时调用模型。
- **部署粒度（Provisioning Granularity）**：
  - **all-classes**：一个技能覆盖所有威胁类别（K=全部），适合通用代理。
  - **per-bundle**：一个技能覆盖机制相关的类别子集（K=束大小），适合已知机制族的环境。
  - **per-class**：一个技能只针对单一类别（K=1），作为能力上限参考；若环境预先知道确切威胁类别也可实际部署。
  - 所有配置使用相同预算 L，并需要部署前确定，运行时不进行选择。
- **形式化目标**：
  - 给定编码代理 $A=(M, T, P)$，防御后的代理为 $A_s = (M, T, w \oplus s \oplus P)$，其中 $s$ 是技能主体，$w$ 是固定包装。
  - 目标是最小化恶意输入上的风险 $R_{mal}(s)$，同时保持良性输入上的安全拒绝率 $R_{ref}(s) < \varepsilon$。

## 3. 实验设计

### 3.1 数据集与基准（Benchmark）
- **RedCode**：唯一的公开基准，同时评估有害工具执行（RedCode-Exec）和恶意代码生成（RedCode-Gen）。RedCode-Exec 有 27 个威胁类别，每类 30 个基础案例，每个案例 4 种渲染形式；RedCode-Gen 有 8 个恶意软件家族。数据集以哈希种子分割，一半用于合成训练，一半用于测试，确保无重叠。
- **SWE-Bench Pro**：731 个良性软件工程任务描述，用于测量安全拒绝率（FPR）。

### 3.2 模型与代理框架
- **6 个 LLM**：DeepSeek V3.2、Qwen3-Coder-Next、Seed 1.6 Flash、GPT-oss-120B、Ministral-3-8B、Nemotron-Nano-9B（参数范围 8-9B 到 >100B）。
- **3 种代理 harness**：mini-SWE-agent（主 harness），以及 OpenCode 和 Pi（用于验证跨工具协议的通用性）。

### 3.3 对比方法（Baselines）
- 无防御（no-def）
- **Llama Guard 3**（8B 分类器，输入过滤）
- **Prompt Guard 2**（86M 分类器，输入过滤）
- **Spotlighting**（提示空间法，用分隔符标记不可信内容）
- **TaskShield**（运行时对齐检查）
- **AGrail**（运行时生成安全检查）

### 3.4 评估指标
- 执行攻击成功率（ASR）、恶意软件生成平均分（AvgS，0-10 分，越高越有害）、拒绝率（RR）、良性任务上的安全拒绝率（FPR）、VirusTotal 检测率等。

## 6. 主要结论与发现

1. **有效性（Q1）**：
   - 默认 all-classes 技能将执行 ASR 从 67.4% 降至 43.6%，与 Llama Guard 3（42.7%）相当，但无需 8B 分类器。
   - 恶意软件生成 AvgS 从 3.37 降至 0.58（all-classes），每类设置可进一步降至 0.42。
   - per-bundle 和每类设置分别将执行 ASR 降至 36.2% 和 14.5%。
2. **覆盖范围影响（Q2）**：
   - 较宽的粒度（覆盖更多类别）会损失类特定细节，性能下降；但直接拼接类特定文本可恢复 59% 的差距，说明合成过程中的信息丢失比提示词容量限制更关键。
   - 所有类别技能对未见类别仍有一定迁移效果（ASR 从 79.0% 降至 43.9%）。
3. **越狱鲁棒性（Q3）**：
   - 恶意软件生成保护在 AgentHarm 和 ArtPrompt 下依然强于所有基线。
   - 执行保护在 persona 框架下退化，但每类技能仍比最强基线 Llama Guard 3 低 12 个百分点（31.2% vs 43.2%）。
4. **良性拒绝成本（Q4）**：
   - 在 731 个良性任务上，平均安全拒绝率仅 0.14%，其中主动合成配置最高 0.68%；但反应式合成的 per-bundle 配置在 Qwen3 上达到了 16.3% 的拒绝率，属于个别例外。
5. **综合**：提示空间安全技能可以作为 API-only 部署者的实用第一道防线，可更新、无额外运行时组件，但宽泛配置在越狱下不如运行时验证，应作为分层防御的一部分。

## 7. 优点

- **轻量且部署友好**：无需模型权重访问、无第二个模型调用、无运行时检查，仅需修改系统提示，适合 API-only 场景。
- **策略可审计、可更新**：技能以 Markdown 文档形式呈现，人类可读，操作者可在攻击语料变化后重新离线合成。
- **系统化探讨了提示预算与覆盖粒度的权衡**：明确提出了 all-classes / per-bundle / per-class 三种部署假设，并量化了粒度带来的损失及原因。
- **合成方式双轨互补**：主动挖掘提供即时技术规则，反应式学习提炼意图级原则，可针对不同威胁形态调整。
- **评估全面**：多模型、多基线、多代理框架、多指标，包含统计显著性验证和消融研究，展示了方法的有效性和可信度。
- **无需运行时分类/路由**：所有配置在部署前固定技能，避免了请求时间检测带来的额外延迟和攻击面。

## 8. 不足与局限

- **对自适应攻击的鲁棒性未知**：作者明确说明，白盒优化或针对完整系统提示的攻击不在评估范围内；发布的技能文本可能被攻击者用来寻找遗漏。
- **合成过程可能丢失信息**：预算匹配的拼接控制实验表明，迭代精炼在覆盖更多类别时会丢弃有用的类特定规则，导致性能下降；修改合成策略可能会提升效果。
- **良性任务的评估不完整**：只测量了安全拒绝率，未进行端到端任务完成率评估，无法判断对正常开发效率的影响。
- **部分模型效果差异显著**：如 Seed 在恶意软件生成上即使有防御，AvgS 仍高达 3.08-7.04；Nem 和 Min 在部分 harness 上的表现也不稳定，说明模型能力对防御效果有影响。
- **基准覆盖面有限**：全部实验基于 RedCode 和 SWE-Bench Pro，前者是任务型攻击数据集，后者仅用于良性拒绝测试；真实攻击的多样性和可能性未被完全覆盖。
- **越狱实验非自适应**：只使用了两种固定重写家族，且未针对防御策略优化，实际恶意攻击者可能更复杂。
- **未处理提示注入的来源区分**：RedCode 不隔离指令来源，因此没有单独证明对仓库内容注入的防御能力。
- **缺少运行时验证组合的评估**：作者将 SkillShield 与运行时验证独立比较，但没有测试两者结合时的收益，存在实用场景下的扩展空间。
