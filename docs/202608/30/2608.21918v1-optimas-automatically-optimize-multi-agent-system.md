## 摘要
多智能体系统（MAS）的自动演化在减少设计和优化基于LLM的智能体架构所需的人工工作方面具有巨大潜力。然而，现有的基于搜索的范式面临一个根本性的权衡：更广泛的优化范围会加剧演化不稳定性，而离散的分支-丢弃搜索则隔离了跨谱系的见解。为应对这些限制，我们提出了一种基于统一ReAct基础设施的连续、数据驱动的优化范式，该范式将广泛的优化范围与操作稳定性相协调。在此范式下，我们提出了OptiMAS，一种任务无关的智能体优化器，利用文本交互轨迹和任务反馈作为端到端MAS演化的损失信号。凭借新颖的双轨记忆机制，OptiMAS在更长的优化周期内持续保持性能提升。在四个异构智能体基准测试上，使用三种不同规模和可访问性的LLM骨干网络的评估表明，OptiMAS相对于领域特化的手工构建系统和现有演化方法，均能持续达到具有竞争力或更优的准确率。我们的工作为稳健的自动化MAS演化树立了一个实际里程碑。

## Abstract
Automated evolution of Multi-Agent Systems (MAS) holds significant potential for reducing the manual effort required to design and optimize LLM-based agent architectures. However, extant search-based paradigms face a fundamental trade-off, where an expanded optimization scope exacerbates evolutionary instability, while discrete branch-and-discard search isolates insights across lineages. To address these limitations, we propose a continuous, data-driven optimization paradigm built upon a unified ReAct-based infrastructure that reconciles a broad optimization scope with operational stability. Under this paradigm, we present OptiMAS, a task-agnostic agentic optimizer that leverages textual interaction trajectories and task feedback as loss signals for end-to-end MAS evolution. Equipped with a novel dual-track memory mechanism, OptiMAS sustains performance improvement over extended optimization horizons. Evaluation on four heterogeneous agentic benchmarks with three varying scale and accessibility LLM backbones, demonstrates that OptiMAS consistently achieves competitive or superior accuracy relative to both domain-specialized hand-crafted systems and existing evolutionary methods. Our work establishes a practical milestone toward robust, automated MAS evolution.

## 1. 核心问题与整体含义

**研究动机：** 基于LLM的多智能体系统（MAS）已经广泛用于复杂推理、信息获取和自动软件工程。然而，MAS的构建依然依赖大量人工调整：提示词校准、工具扩展、智能体编排都需要反复试错。尽管已有若干自动化演化研究，其在实际部署中的可靠性和效率仍不如人工设计的系统。

**核心矛盾：**
- **优化范围 vs. 稳定性**：越宽的优化范围（如同时演化提示词、工作流、工具、拓扑）越容易导致演化不稳定；而限制优化范围又会压缩性能提升空间。
- **离散搜索的局限性**：搜索式方法将候选MAS视为树状分支，每次选择最优分支后“丢弃”其他分支，导致各个演化谱系中的经验无法跨分支传递，形成信息孤岛。

**论文的意义：** OptiMAS提出一个通用、任务无关、可连续优化MAS的范式，将MAS演化从“离散随机搜索”转变为“类似深度学习反向传播的连续优化”，为自动化MAS演化提供了一个实用且稳健的方向。

## 2. 方法论

### 2.1 统一基础设施
- 每个智能体采用**ReAct原子执行单元**：迭代生成思考与动作，并用观察更新上下文。
- 使用**主动式Assign-Deliver协议**：父智能体通过工具调用方式将任务委派给子智能体，子智能体以结构化观察形式返回结果；智能体按需被激活而非按固定流程执行，提供灵活性和可扩展性。
- 优化范围E覆盖：
  - 智能体集合A；
  - 编排图G(A)（约束为DAG以保证确定性终止）；
  - 每个智能体的LLM backbone、提示词、技能集、工具集。
- 工具来自预定义宏库，而非从头生成代码，以保证操作稳定性。

### 2.2 连续优化范式
- 数据集划分为Xtrain / Xval / Xtest。
- 每步从Xtrain中利用**自适应采样**（Algorithm 1）抽取批次Bt，该采样优先复现上一步失败样本，并以概率权重平衡探索。
- 当前MAS Et−1在训练集批次和验证集上执行并评估，得到训练准确率Rtrain和验证准确率Rval。
- **反向传播阶段**：优化器（OptiMAS）在保存完整轨迹与中间产物的工作空间中做深度分析，识别失败根因和成功模式，生成“文本梯度”，并直接对MAS配置（提示词、技能、拓扑、工具）进行修改。
- 验证集仅提供标量准确率作为泛化信号，防止过拟合，其轨迹对优化器不可见。
- 完整流程见Algorithm 2，持续迭代至最大步骤T。

### 2.3 OptiMAS：双轨记忆机制
- **短期计划记忆**：在每步优化中维护结构化“计划”，包括状态（waiting/executing/completed/dropped）与操作（add/modify/review/delete）。禁止删除内容，只允许标记为dropped并给出理由；步骤结束时有程序化完整性检查，保证所有指令达到终态，防止遗忘和幻觉导致的不一致。
- **长期假设记忆**：将每个干预记录为可证伪的假设，具有完整生命周期：
  - PROPOSE → ENACT → VALIDATE / REFUTE / SUSPEND / DORMANT
  - 每个修改必须关联假设ID，保持可追溯性。
  - 只有在轨迹级证据（而非仅准确率）确认时才能VALIDATE；被反驳则自动回滚。
- 该机制将MAS演化从无导向的试错转变为“自我修正、有据可循的优化过程”，类比科研实验记录本。

## 6. 主要结论与发现

- **演化有效性**：OptiMAS在所有基准—骨干组合下均优于单智能体初始化E0，最高提升45.4%（WorkBench/GPT5），最低也有正增益。
- **跨域泛化**：同一任务无关的OptiMAS配置在所有四个基准上均有效，甚至超越领域专用的Tongyi-DR（GAIA/BrowseComp）和SWE-Agent（SWE-Bench）。
- **骨干通用性**：对闭源、开源、商用前沿模型均产生一致改进；进化收益与骨干能力负相关（弱模型收益更大），说明OptiMAS的编排和技能可以补偿较弱backbone的推理能力不足。
- **演化动态**：在10个epoch中训练集和测试集准确率均呈近似单调上升，且训练—测试差距保持狭窄，表明连续优化范式可持续累积收益且不易过拟合。
- **消融结果**：
  - 移除假设记忆造成最严重退化（SWE-Bench相对E0下降超过7个百分点）；
  - 移除自适应采样同样大幅损害性能，说明失败样本回访对验证干预效果至关重要；
  - 减小批量大小在弱骨干上产生负收益；
  - 移除验证信号会引入轻微过拟合。

## 7. 优点

**方法论方面：**
- 创新性地将MAS演化从离散搜索重构为连续优化，类比深度学习中的反向传播，提供统一理论视角。
- 双轨记忆机制设计精巧：短期计划防止单步内“遗忘”，长期假设记忆确保跨步骤可追溯和可证伪性，避免无效干预重复。
- 基础设施统一且生产级：基于MCP协议、分阶段上下文管理等机制，使得长视野优化任务可行。
- 任务无关性强，无需针对具体基准手动定制。

**实验方面：**
- 覆盖多样化基准和多种模型类型，公平性设计良好（相同子集、相同验证信号、一致超参）。
- 消融实验细致，能够定位每个组件的贡献；案例研究直观展示了演化产生的结构化智能体拓扑。
- 对数据泄露风险有明确控制：Web类基准禁用shell；代码类禁用web搜索，评价结果可信。

## 8. 不足与局限

**实验覆盖与规模：**
- 大型基准采样子集仅为100条，可能损失统计显著性；测试集/验证集划分（36/4/60）在部分基准上验证信号过于稀疏。
- 每个设置只重复3次，对随机波动敏感的指标（如SWE-Bench）可能需要更多重复。

**偏差风险：**
- 优化器核心采用Gemini-3-Flash，虽验证了Qwen优化器，但统一在Gemini上作为默认设置可能使“任务无关”结论带有特定模型偏好。
- 数据分割使用固定种子一次生成，未做多折交叉验证或多重分割。
- 长轨迹任务（GAIA/BrowseComp）中，Qwen优化器提升有限，说明优化器上下文窗口是演化质量的瓶颈——这一结论属于对当前模型的观测，而非框架本身的固有属性。

**应用限制：**
- 基础设施对backbone的指令遵循和工具调用能力要求较高；对于显著更弱的模型，执行可能不可靠。
- 优化成本较高：每步需要处理百万级token，并且需要在训练批次和验证集上反复运行MAS，工业部署可能面临计算预算压力。
- 当前优化范围虽广，但仍受限于预定义工具库和DAG约束，未纳入如“工具/提示模板从零生成”等更深层设计自由度。
