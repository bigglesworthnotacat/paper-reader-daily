## 摘要
大规模语言模型（LLM）智能体通过强化学习（RL）训练以完成复杂决策任务。然而，大多数经过RL训练的智能体仍然是情景式的，无法跨情景积累可重用知识。近期基于技能的方法（如SkillRL）尝试通过从原始轨迹中提取技能来解决该问题，但将技能库视为仅追加的存储库，未验证存储的技能是否仍然有效。本文提出SkillForge，一个持续技能进化框架，使技能能够通过环境交互进行验证和精炼。通过在智能体交互过程中显式化技能使用，RL可以直接优化环境动作与技能调用决策。SkillForge进一步引入基于证据的技能验证和多路径技能归纳，使技能库在持续增长的同时保持质量。在ALFWorld、WebShop和AppWorld上的大量实验表明，SkillForge始终优于SkillRL，证明了持续验证技能在训练更强LLM智能体方面的有效性。

## Abstract
Large language model (LLM) agents are trained with reinforcement learning (RL) for complex decision-making tasks. However, most RL-trained agents remain episodic and cannot accumulate reusable knowledge across episodes. Recent skill-based approaches, such as SkillRL, attempt to address this issue by extracting skills from raw trajectories, but treat the skill bank as an append-only repository without verifying whether stored skills remain effective. In this paper, we propose SkillForge, a framework for continuous skill evolution that enables skills to be verified and refined through environment interaction. By making skill usage explicit during agent interaction, RL can directly optimize both environment actions and skill invocation decisions. SkillForge further introduces evidence-based skill verification and multi-pathway skill induction, allowing the skill bank to continuously grow while maintaining its quality. Extensive experiments on ALFWorld, WebShop, and AppWorld show that SkillForge consistently outperforms SkillRL, demonstrating the effectiveness of continuously verified skills in training stronger LLM agents.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究起点**：大规模语言模型（LLM）智能体在复杂决策任务中通常依赖强化学习（RL）进行训练（如GRPO）。但绝大多数RL训练的智能体是**情景式（episodic）**的——每个回合从零开始，无法跨回合积累和复用知识，导致重复“重新发现”有效行为，学习效率低下。

- **已有解决方案的不足**：以SkillRL为代表的技能学习方法尝试从原始轨迹中“蒸馏”出可复用技能并注入策略提示，但其将技能库视为**仅追加（append-only）的存储库**——技能只添加、从不检验。这带来三个致命缺陷：
  - **技能使用不可观察**：技能以批量方式注入提示，无法确认智能体是否真正依赖某条技能；
  - **技能有效性难以归因**：成功轨迹可能只是与技能“巧合”，无法判断技能是否起决定性作用；
  - **技能质量不受控制**：过时或错误的技能会无限期驻留，逐渐污染技能库。

- **核心研究问题**：如何让智能体在RL训练过程中**持续积累、验证并精炼可复用知识**，使技能库不但增长而且始终保持高质量？

### 2. 论文提出的方法论（SkillForge）

SkillForge是一个围绕“技能库与策略协同进化”的完整框架，包含三大支柱：

#### 2.1 技能表示与检索（Stage 1）

- **技能模式（Skill Schema）**：每条技能是一个结构化知识单元，包含：
  - `title`：可调用的唯一标识符；
  - `intent`：技能目的的一句话描述；
  - `principle`：核心决策策略（完整内容）；
  - `applicability`：适用条件（何时应用）；
  - `category`：通用技能（general）或任务专属技能（task-specific）；
  - `status`：active / under-review / deprecated 等状态标志。
- **初始化**：用初始指令微调策略模型在目标环境中进行rollout，由教师LLM将成功轨迹蒸馏为策略型技能、将失败轨迹合成为修正型经验，建立两级技能库（通用 + 任务类型专属）。
- **检索与目录注入**：每回合开始时，用embedding语义相似度为当前任务描述检索top-K条技能，但**只注入紧凑目录**（技能名 + 一行触发描述）而非完整内容，保持提示词紧凑。

#### 2.2 显式技能调用与策略优化（Stage 2）

- **显式技能调用**：智能体在每步输出中除环境动作 `a_t^env` 外，还可选输出技能调用 `c_t`。实际操作中，智能体在回复中生成结构化标签 `<skill_call>NAME</skill_call>`，框架解析后返回完整技能内容（意图、原则、适用条件）作为下一观测的额外反馈。

- **核心创新**：技能调用标签本身是生成token序列的一部分，因此**RL可以直接优化“何时调用技能、调用哪条技能”**，而非像SkillRL那样把技能当作被动上下文。

- **策略优化**：采用GRPO目标函数：
  ```
  J(θ) = E[ (1/G) Σ_i min(ρ_i * Â_i, clip(ρ_i, 1-ε, 1+ε) * Â_i) - β D_KL(π_θ || π_ref) ]
  ```
  其中组内相对优势 `Â_i = (R_i - R̄)/σ_R`。由于技能调用是序列的一部分，该目标自动联合优化动作与技能调用决策。

- **轨迹抽象**：每次rollout由LLM压缩为结构化摘要，按成功（T+）/失败（T-）分区存入缓冲，作为后续技能归纳的输入。

#### 2.3 技能进化（Stage 3）

- **多路径技能归纳**：每I=5个训练步执行一次，教师LLM根据轨迹摘要合成新技能，有三种路径：
  - **抽取（Extraction）**：仅从成功轨迹T+提取可泛化的普适策略；
  - **精炼（Refinement）**：仅从失败轨迹T-挖掘重复失败模式并制定纠正策略；
  - **对比分析（Contrastive）**：成功与失败配对，识别关键行为差异。
  - 新技能经过**词汇匹配 + 语义相似度去重**后加入技能库。
- **基于证据的技能验证**：
  - 每次技能被调用并关联到回合结局后，更新**EMA成功率**：`p̂_s ← α·r + (1-α)·p̂_s`（α=0.1）；
  - 综合使用次数计算**欠表现得分**：`conf(s) = (1-p̂_s) · (1 - 0.5^(n_s/h))`（h=20为使用半衰期）；
  - 高欠表现得分（低成功率 + 高使用次数）的技能被优先送交**LLM反思（Reflexion）**：教师模型结合使用上下文判断保持（keep）还是修订（revise），修订会重写原则和适用条件。

- **完整训练循环**：技能增强式rollout → GRPO策略更新 → 轨迹抽象 → 技能统计更新 → 每I步执行归纳+去重+验证+反思 → 更新后的技能库立即用于后续rollout。

### 6. 论文的主要结论与发现

1. **技能库必须持续验证与进化**：将技能库从“仅追加”转变为“可验证、可修订”的活系统，能显著提升RL智能体性能。SkillForge在三个benchmark上一致优于SkillRL，且无需SFT初始化阶段。
2. **显式技能调用带来可归因性**：将技能调用作为token序列中的离散事件，使RL能联合优化环境动作与技能使用策略，并让技能有效性成为可计算的统计量。
3. **技能知识具有跨模型迁移性**：Qwen3-4B训练后期产出的技能，直接应用于更大的Qwen3-30B-A3B后，性能甚至超过大模型自训练产出的技能（AppWorld上31.5 vs 30.4），说明技能确实捕获了与模型无关的可复用策略。
4. **训练效率反升**：技能复用减少冗余探索，SkillForge的总训练时间短于SkillRL，尽管额外承担了技能检索、调用和更新的计算成本。
5. **技能库呈现“受控增长”**：技能总数在训练中稳步增加（如ALFWorld上44→90），但反思机制会及时修订/淘汰失效率高的技能，避免失控膨胀。

### 7. 优点

- **问题定位精准**：准确识别了SkillRL类方法“只增不减、无法验证”的核心缺陷，提出了完整的闭环解决方案。
- **设计优雅且工程可落地**：将技能调用编码为结构化标签，无缝嵌入LLM的生成序列，使RL优化目标与技能归纳/验证形成闭环，且兼容现有GRPO等主流训练框架。
- **证据驱动的质量控制**：EMA成功率 + 使用次数的欠表现得分设计简单有效，既反映技能的即时表现，又避免低使用频率的技能被过早误杀（半衰期机制）。
- **多路径归纳覆盖全面**：不仅从成功中抽模式、从失败中找纠正，还通过“成功-失败对比”挖掘决定性差异，比单一从成功轨迹提取的方法更具信息利用效率。
- **实验分析立体丰富**：从性能表到消融、可视化、迁移性、训练动态、案例研究、效率分解和教师敏感性，形成了多角度的证据链。
- **实际训练时长降低**：这是一个容易被忽视但很有说服力的工程优势。

### 8. 不足与局限（续）

5. **奖励机制的简化**：所有环境均使用二元成功/失败奖励，未利用过程奖励或分步中间信号。技能验证完全依赖回合级最终结果，无法区分“技能本身错误”与“执行过程失误”，可能高估或低估技能的真实质量；同时，在长时程任务中，稀疏奖励会拖慢技能成功率统计的收敛速度，使得早期阶段的技能评价噪声较大。

6. **跨任务泛化性未验证**：技能库目前按单一环境独立演化（ALFWorld的技能不会用于WebShop），并未进行跨环境、跨域的技能迁移实验。虽然附录展示了跨**模型**迁移的能力，但不同任务类型之间是否存在可复用的通用技能、以何种粒度共享，论文尚未给出定量结论。

7. **技能演化过程的可解释性不足**：教师LLM对技能的修订与淘汰虽有统计依据（EMA成功率 + 欠表现得分），但反思环节本身依赖模型“自由文本式”的判断，缺乏结构化审计轨迹（如“何时由谁基于哪些证据将技能置为deprecated”）。在需要安全审查或合规记录的现实部署中，这种黑盒化演化流程可能构成部署障碍。

---

总体而言，SkillForge在问题定位、框架设计、实验编排上均表现出较高完成度，其“可验证、可修订”的技能库思想是对记忆增强型RL智能体的一次有价值修正。然而，其性能上界受限于教师模型，且在多任务泛化、奖励粒度与可审计性方面仍有清晰的研究空间，后续工作值得在这些方向继续深入。
