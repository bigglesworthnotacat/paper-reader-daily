## 摘要
大型语言模型越来越多地在大量工具、函数、API和专用智能体集合上运行。随着候选行动空间的扩大，函数调用模型必须处理更多模式、消耗更多提示词元，并在日益相似或不相关的备选项中进行区分。我们研究了一种互补的系统策略：在语言模型推理之前缩减候选集合，同时保持下游模型不变。我们引入了AgentWeave，一个确定性的推理前路由层，利用资格、需求、能力和路由信号构建一个有界的模型可见行动空间。我们使用冻结的BFCL派生路由压力协议，基于公共MadeAgents/Hammer2.1-1.5b模型评估了AgentWeave。在48个新的BFCL V4多函数任务中，AgentWeave实现了6/48（12.5%）的原生BFCL成功，而所有工具、确定性随机前8和语义前8基线均实现0/48。配对成功差异为+12.5个百分点，10,000次重抽样的配对自举95%置信区间为+4.17至+22.92个百分点，精确McNemar p=0.03125。相对于暴露所有工具，AgentWeave减少了70.18%的工具，使用了61.70%更少的输入词元，并表现出50.95%更低的平均本地模型延迟。结果刻意收窄：这是一项BFCL派生的路由压力研究，而非官方完整的BFCL排行榜分数，绝对任务成功率仍然较低。然而，证据表明候选空间构建能实质性影响固定模型的函数调用行为，并激励将路由作为模型推理之前的独立阶段进行评估。

## Abstract
Large language models increasingly operate over large collections of tools, functions, APIs, and specialized agents. As the candidate action space grows, a function-calling model must process more schemas, consume more prompt tokens, and distinguish among increasingly similar or irrelevant alternatives. We study a complementary systems strategy: reduce the candidate set before language-model inference while leaving the downstream model unchanged. We introduce AgentWeave, a deterministic pre-inference routing layer that constructs a bounded model-visible action space using eligibility, requirement, capability, and routing signals. We evaluate AgentWeave with a frozen BFCL-derived routing-pressure protocol using the public MadeAgents/Hammer2.1-1.5b model. On 48 fresh BFCL V4 multiple-function tasks, AgentWeave achieves 6/48 (12.5%) native BFCL successes, whereas all-tools, deterministic random top-8, and semantic top-8 baselines each achieve 0/48. The paired success difference is +12.5 percentage points with a 10,000-resample paired bootstrap 95% confidence interval of +4.17 to +22.92 points and exact McNemar p=0.03125. Relative to all-tools exposure, AgentWeave presents 70.18% fewer tools, uses 61.70% fewer input tokens, and exhibits 50.95% lower mean local-model latency. The result is deliberately narrow: this is a BFCL-derived routing-pressure study rather than an official full BFCL leaderboard score, and absolute task success remains low. The evidence nevertheless shows that candidate-space construction can materially affect a fixed model's function-calling behavior and motivates evaluating routing as a distinct stage before model reasoning.

# AgentWeave 论文详细总结

## 1. 核心问题与整体含义

- **研究背景**：大型语言模型在工具丰富的环境下进行函数调用时，通常需要面对庞大的候选工具目录（函数、API、智能体）。候选空间越大，模型需要处理的 schema 文本越多，输入 token 消耗越大，且相似或无关工具之间的"竞争"会显著增加选择难度。
- **核心问题**：既然工具目录规模是系统变量，而非固定输入，是否可以在**语言模型推理之前**先缩减候选工具集合，从而既能提升函数调用成功率，又能降低计算开销？
- **整体主张**：函数调用应被分解为**候选空间构建（candidate-space construction）+ 语言模型推理（reasoning）** 两个阶段。路由应作为一个独立的系统阶段来设计和评估，而不应与模型推理混为一谈。
- **核心含义**：论文通过受控实验证明，即使下游模型完全固定，仅仅改变"模型能看到哪些工具"，就可能实质性改变函数调用行为——这意味着候选集合本身就是一个重要的实验变量。

## 2. 方法论

### 2.1 核心思想
- 引入一个**确定性的、模型无关的推理前路由层** AgentWeave，将源工具目录 F 映射为一个有界的子集 F′，再交给下游函数调用模型处理。
- 路由的目标不是追求单一"命中"，而是**在有界候选集内实现高召回**，保留全部必需工具的同时压缩候选规模。

### 2.2 关键技术细节
- **形式化定义**：
  - 传统系统：`y = M(x, F)`
  - 引入路由后：`F′ = R(x, F)`，`y = M(x, F′)`
  - 模型、权重、生成设置、评估逻辑在所有对照条件下均保持不变。
- **三层路由机制**：
  1. **确定性范围与策略过滤**：利用角色、租户、权限、部署环境、司法管辖区、产品面或能力标签等非语义信号，先剔除不可用工具。若过滤后目录已足够小，则无需额外语义路由。
  2. **需求感知路由**：对剩余候选，从请求中提取需求信号，与候选描述、能力和提供方分组进行匹配，并在**有界预算**下只暴露少量工具给模型。
  3. **来源追踪与失败定位**：记录源目录、路由配置、候选数量、被过滤的候选、模型可见候选、选中函数与执行结果，便于区分"被过滤、未选中、被拒绝授权、执行错误"等不同失败环节。
- **安全边界**：路由只优化"模型看到什么"，不能替代授权；系统应在模型选择之后、执行之前保留**确定性 fail-closed 授权门**。

## 3. 实验设计

### 3.1 基准与数据集
- 使用 **BFCL V4（Berkeley Function Calling Leaderboard V4）的多函数类别（multiple-function）任务**。

### 3.2 固定下游模型

## 6. 主要结论与发现

- AgentWeave 是唯一在 48 个任务中产生原生 BFCL 成功的策略：**6/48 = 12.5%**；三个匹配基线（全工具、随机 top-8、语义 top-8）均为 **0/48**。
- 配对成功差异为 **+12.5 个百分点**，10,000 次重抽样配对 bootstrap 95% CI 为 **+4.17 至 +22.92 个百分点**，精确 McNemar 检验 **p = 0.03125**。
- 效率方面（相对全工具暴露）：
  - 工具数减少 **70.18%**（从 16.00 降至 4.77）；
  - 输入 token 减少 **61.70%**（从 124,821 降至 47,805）；
  - 平均本地模型延迟降低 **50.95%**（从 55.92s 降至 27.43s）。
- **关键反直觉发现**：语义 top-8 的原始候选保留率（86.81%）和全保留率（66.67%）均高于 AgentWeave（76.91% / 54.17%），但语义 top-8 零成功。说明**"保留更多原基准候选"并不能解释成功**；候选集的组合结构与干扰项几何（distractor composition）可能才是关键因素。
- **总体结论**：证据支持"候选空间构建能实质影响固定模型的函数调用行为"，但不支持任何"SOTA"或"普遍优于语义检索"的声明。路由应被当作一个独立于模型推理的评估环节。

## 7. 优点

- **问题视角新颖**：将"路由"从模型内部隐式过程显式化为独立的推理前系统阶段，且不要求微调下游模型，工业可实现性强。
- **实验设计严谨**：

## 8. 不足与局限

- **实验规模不足**：48 个任务不足以刻画通用函数调用性能；只涉及一个 BFCL 类别（multiple-function）和一个压力大小（16 工具）。
- **模型覆盖狭窄**：仅使用一个 1.5B 轻量模型，该模型可能对候选压力异常敏感；结论无法外推到更强模型或多模型场景。
- **缺乏机制归因**：AgentWeave 的压缩幅度与选择规则同时变化，无法区分是"少工具"还是"更好的工具组合"带来改善；论文也未做逐特征消融。
- **路由召回并非最优**：语义 top-8 在保留诊断上优于 AgentWeave，说明 AgentWeave 的检索能力本身并不领先，需要与更强密集/稀疏/混合/学习型重排基线对比。
- **效率结论的边界**：延迟降低（50.95%）是本地特定硬件与实现下的测量值，不能外推为通用加速；token 减少也并非线性传递到总延迟。
- **安全问题未解决**：路由不是安全边界，不能替代授权；恶意/重复/注入工具的攻击场景尚未评估。
- **应用限制**：这只是 BFCL 派生的路由压力研究，不是官方完整 BFCL 排行榜分数，绝对成功率（12.5%）仍然很低，不能视为端到端生产级任务成功。
