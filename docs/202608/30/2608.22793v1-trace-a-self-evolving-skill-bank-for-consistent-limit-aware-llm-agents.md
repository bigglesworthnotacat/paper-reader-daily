## 摘要
在面向用户的产品中可靠部署LLM智能体，并不取决于原始的任务解决能力，而在于一致性和极限感知：即在重复试验中表现相同，并能识别出某个请求不能、或尚不能安全地完成。CAR-bench在车载助手领域揭示了这一可靠性差距：一个由LLM模拟的用户发出不完整或模糊的请求，要求智能体通过多轮对话和工具使用来消除不确定性，同时严格遵守领域政策。即使是最先进的模型，在至少一次可解决（Pass@3）与跨试验一致可解决（Pass^k）之间也显示出巨大差距。我们通过TRACE（轨迹对比进化，TRAjectory-Contrastive Evolution）弥合了这一差距，该方法在无需修改模型权重的情况下，迭代改进基于技能的智能体的行为知识。这些知识被组织成一个模块化、可检索的技能库（Skill Bank），每个技能都编码了一套自包含的工具使用规则和行为指南。TRACE通过一个智能体自进化循环来进化这个技能库：在每一轮评估之后，它根据所调用的技能对轨迹进行分组，并通过对比成功与失败的行为来细化每个技能。更新后的技能库随后指导后续轮次，而在部署期间，Actor在每一步都执行状态条件下的技能编排。在GPT-5.5上，TRACE将一致性（Pass^3）提高了34.6个百分点，从59.9%提升至94.5%，同时将潜在性能与可靠性能之间的差距缩小至仅4.0个百分点。在官方隐藏测试集上，TRACE使用GPT-5.6-Sol获得了第一名，Pass^3得分为70%，相对基线提升了40%。这些结果表明，TRACE能将高模型潜力转化为稳定、一致的性能提升。项目主页：https://darwin-agent.github.io/Car-bench-TRACE。

## Abstract
Reliable deployment of LLM agents in user-facing products depends not on raw task-solving ability but on consistency and limit-awareness: behaving the same way across repeated trials, and recognizing when a request cannot, or cannot yet, be safely fulfilled. CAR-bench exposes this reliability gap in the domain of in-car assistants: an LLM-simulated user issues incomplete or ambiguous requests, requiring the agent to resolve uncertainty through multi-turn dialogue and tool use while strictly adhering to domain policies. Even frontier models show a substantial gap between what they can solve at least once (Pass@3) and what they solve consistently across trials (Pass^k). We bridge this gap with TRACE (TRAjectory-Contrastive Evolution), which iteratively improves a skill-based agent's behavioral knowledge without modifying model weights. This knowledge is organized as a Skill Bank of modular, retrievable skills, each encoding a self-contained set of tool-use rules and behavioral guidelines. TRACE evolves this bank through an agentic self-evolution loop: after each evaluation round, it groups trajectories by the skills invoked and refines each skill by contrasting successful and failed behaviors. The updated bank then guides subsequent rounds, while during deployment the Actor performs state-conditioned skill orchestration at every turn. On GPT-5.5, TRACE improves consistency (Pass^3) by 34.6 points, from 59.9% to 94.5%, while shrinking the gap between potential and reliable performance to just 4.0 points. On the official hidden set, TRACE achieved first place using GPT-5.6-Sol, attaining a Pass^3 score of 70%-a 40% relative improvement over the baseline. These results show that TRACE converts high model potential into stable, consistent performance gain. Project homepage: https://darwin-agent.github.io/Car-bench-TRACE.

## 2. 论文提出的方法论：核心思想、关键技术细节、算法流程

### 核心思想
- **TRACE（TRAjectory-Contrastive Evolution）**：通过一个 LLM 驱动的闭环，从评估轨迹中提炼可复用的行为知识，组织为**模块化技能库（Skill Bank）**，并不断迭代优化该技能库。部署时，Actor 依据当前对话状态进行**状态条件技能编排（state-conditioned skill orchestration）**，以指导每一步生成。

### 关键组成
- **两个智能体**：
  - **Actor**：执行任务，与用户对话、调用工具，并根据当前状态激活相关技能。
  - **Curator**：读取 Actor 的评估轨迹，对比成功与失败行为，改写技能库中的行为知识。
- **技能库表示**：每个技能 \(s_i = (d_i, b_i)\)，\(d_i\) 为单行描述（用于路由），\(b_i\) 为自包含的工具使用规则和行为指南（以 Markdown 的 SKILL.md 形式存储）。

### 初始化流程（层次化抽象）
- 从训练集初始轨迹出发，依次进行：
  1. **任务级蒸馏（Task-Level Distillation）**：针对每个任务，对比多次评估轨迹，提取成功行为与常见失败模式。
  2. **类型级聚合（Type-Level Aggregation）**：将同类型任务技能合并，去除任务特有细节，保留类型内共享行为。
  3. **操作级抽象（Operation-Level Abstraction）**：根据底层操作跨任务类型合并，形成可迁移的操作级能力。
  4. **技能分解（Decomposition）**：将宽泛技能拆分为细粒度单一能力，便于精确激活。

### 迭代进化流程（轨迹对比进化）
- 每轮评估后，Curator 执行更新 \(B^{(r+1)} = \Phi(B^{(r)}, \mathcal{T}^{(r)})\)，包含三个关键步骤：
  1. **技能感知分组**：按轨迹中调用的技能将轨迹分到对应技能组；对未命中技能或使用未知技能的轨迹单独放置。
  2. **部署忠实重建**：将轨迹重建为结构化文本，严格区分**部署可见信息**和**仅进化时可用的特权信息**，确保技能更新不依赖 Actor 部署时不可见的知识。
  3. **对比技能细化**：
     - 对已有技能，用该技能的成功/失败轨迹对进行编辑；若技能过于庞大则拆分。
     - 对无技能轨迹，若出现可复用的未覆盖模式，挖掘或修订新技能。
     - 最终进行**去硬编码（de-hardcoding）**校验：移除任务标识、记忆化答案、环境特定值，保证技能的可迁移性。

### 部署时的技能编排（Algorithm 2）
- 每轮对话，Actor 基于当前对话历史 \(h_t\) 和所有技能描述 \(\{d_i\}\)，通过 LLM 评估得到有序技能序列 \(S_t = \sigma(h_t, \{d_i\})\)。
- 将技能体按顺序与历史拼接成上下文 \(c_t\)，随后采样动作 \(a_t\)，获得环境反馈 \(o_{t+1}\)。
- 每轮**重新编排**，上一轮的技能体不保留，确保技能跟踪对话状态演变。

### 算法流程（文字描述）
- 输入：初始轨迹、评估任务、进化轮数。
- 先层次化初始化技能库，然后循环 R 轮：
  - 用当前技能库评估得到轨迹；
  - 按技能分组；
  - 对每个技能，拆分成功/失败轨迹；
  - 重建轨迹并细化或拆分技能；
  - 对无技能轨迹挖掘新模式；
  - 校验并输出下一轮技能库。

## 3. 实验设计：数据集、场景、Benchmark 与对比方法

### 基准 Benchmark
- **CAR-bench**：面向车载助手的可靠性评估基准。包含：
  - 一个 LLM 模拟用户，具有人设和隐藏任务指令，通过文本与智能体交互。
  - 智能体可调用 **58 个互联工具**，必须遵守 **19 条领域政策**。
  - 任务分为三种类型：
    - **基础任务（Base）**：普通任务完成。
    - **幻觉任务（Hallucination）**：删除所需工具、参数或结果，智能体必须承认缺失能力而非编造。
    - **消歧任务（Disambiguation）**：引入受控歧义，要求智能体尽量内部解决，必要时向用户确认。

### 评估指标
- **Pass^i**：任务 i 次试验全部成功（可靠性指标）。
- **Pass@i**：至少一次成功（潜在能力指标）。
- **\(\Delta_i = Pass@i - Pass^i\)**：一致性差距（越小越好）。

### 实验配置
- 两个大模型作为 backbone：
  - **GPT-5.5**（中等推理强度）
  - **GLM-5.2**（高推理强度）
- 对比配置：
  - **baseline**：模型默认 prompt + 原生工具调用。
  - **TRACE**：在 baseline 上叠加自进化技能库 + 状态条件技能编排。
- 训练/测试划分：在 CAR-bench 训练集上自进化，随后用测试集扩展技能库覆盖面，最后在训练+测试合并集上报告结果。
- 技能库仅用 **GPT-5.5 轨迹进化**，然后**原封不动**应用于 GLM-5.2，以验证跨模型迁移性。
- 每个任务运行 3 次，指标按三个任务类型宏平均。

### 隐藏集评估
- 在官方 CAR-bench 隐藏集上，使用 **GPT-5.6-Sol** 作为 backbone，对比 baseline 与 TRACE，验证泛化能力。

## 6. 论文的主要结论与发现

- **基线模型存在显著一致性差距**：GPT-5.5 的 Pass^3 仅 59.9%，Pass@3 为 87.7%，差距 27.8 点；GLM-5.2 差距 19.9 点。模型“能做到”但“不能稳定做到”。
- **TRACE 大幅提升可靠性**：
  - 在 GPT-5.5 上，Pass^3 从 59.9% 提升至 94.5%（+34.6），差距缩小至 4.0 点。
  - 在 GLM-5.2 上，Pass^3 提升至 84.8%（+22.0），差距缩小至 12.0 点。
- **跨模型可迁移**：仅由 GPT-5.5 轨迹进化的技能库应用于 GLM-5.2 同样有效，说明学到的是可移植的行为原则，而非 backbone 特异的响应模式。
- **最难任务改善最大**：消歧任务上 GPT-5.5 的 Pass^3 从 39.3% 提升至 94.6%（+55.3），大幅缩小跨任务类型的性能差异。
- **隐藏集验证泛化**：在官方隐藏集上使用 GPT-5.6-Sol，TRACE 的 Pass^3 从 50.0% 提升至 70.0%（相对提升 40%），获得第一名。
- **代价可控**：可靠性提升 40% 相对增益，而延迟仅增加 22%，但 token 消耗增加 72.4%、成本增加 58.8%，需要权衡。
- **行为改变**：案例显示，TRACE 使智能体在缺少必要工具时诚实拒绝而非编造成功，并且在歧义请求中先检查状态再确认用户意图。

## 7. 优点：方法或实验设计上的亮点

- **不修改模型权重**：通过外部技能库直接增强现有模型行为，适用性广、成本低，无需额外训练。
- **自进化闭环**：利用评估轨迹自动对比成功与失败，持续改进技能库，形成“评估-提炼-更新-再评估”的循环。
- **操作级抽象增强可迁移性**：将技能从具体任务提升到操作层面，使知识能跨任务复用，并跨模型迁移（GPT-5.5 → GLM-5.2）。
- **部署忠实重建**：明确区分部署可见与仅进化可见信息，防止技能过度依赖特权信息，保证部署时可用性。
- **去硬编码约束**：剔除任务特定值和记忆化答案，提升技能库的通用性，避免过拟合到评估集。
- **状态条件技能编排**：每轮重新选择技能、顺序和数量，使知识始终匹配当前对话状态，优于静态检索。
- **评测严谨**：同时报告可靠性（Pass^k）和潜在能力（Pass@k），并用差距衡量一致性的改进，指标体系清晰；隐藏集验证增强了结论的可信度。

## 8. 不足与局限

- **未报告消融实验**：缺少对每个组件（如技能分解、去硬编码、轨迹对比策略、进化轮数）的独立贡献分析，无法确定哪些机制最关键。
- **技能编排瓶颈**：当前编排器由 LLM 对所有技能描述进行逐轮评估，技能库规模小时可行，但随技能增多会带来显著延迟和 token 开销，扩展性有限。论文也承认这一点。
- **部署时无反馈通道**：技能库仅在轮间进化，部署中 Actor 无法从实时执行结果中即时更新技能，缺乏中途纠错能力。
- **成本上升**：隐藏集上 token 消耗增加 72.4%、成本增加 58.8%，实际应用中可能不够经济。
- **实验规模局限**：仅使用两个 backbone，k 值最大为 3，案例研究较少，未报告统计方差，结果的稳健性展示不够充分。
- **领域限制**：所有实验在 CAR-bench 车载环境进行，技能库的领域特定性较强，向其他领域泛化能力未被验证。
- **与强化学习等方法的对比缺失**：未与权重微调、prompt 优化（如 Reflexion）等现有方法进行充分比较，难以定位 TRACE 在方法谱系中的优势边界。
- **潜在偏差风险**：技能库的进化过程中由 LLM 进行判断和改写，可能继承模型自身的偏见或幻觉；去硬编码虽能缓解但无法完全消除。
