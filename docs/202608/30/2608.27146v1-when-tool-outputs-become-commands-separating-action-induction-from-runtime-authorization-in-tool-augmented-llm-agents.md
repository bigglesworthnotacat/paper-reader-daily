## 摘要
工具增强的LLM代理必须依赖不可信的运行时观察来完成开放式任务；然而，当工具输出不再仅仅是提供数据，而是开始指定具体动作时，它们实际上变成了“指令”，可能驱动超出用户意图的真实世界副作用。我们认为，这种风险源于将动作诱导与执行授权混为一谈。为解决这一区别，我们提出了SARA，它将动作诱导和执行授权视为不同的运行时角色，并将动作来源与执行权限分离。在观察侧，上下文隔离的动作探针暴露动作诱导语义，并跨步骤持续记录动作来源作为审查信号；在执行侧，实际工具调用仅针对用户目标和来自授权成功执行的可审计证据进行授权，同时满足目标、执行链和参数级别的支持。为了在多步执行中保持这种分离，SARA应用无历史提升策略，防止历史重复将动作来源洗白为执行权限。在AgentDojo和AgentDyn上，SARA在四种主要评估设置中将ASR限制在不超过0.63%，同时保持竞争性的任务效用，并在额外的Agent骨干网络上持续降低ASR。

## Abstract
Tool-augmented LLM agents must rely on untrusted runtime Observations to complete open-ended tasks; however, when tool outputs no longer merely provide data but begin to specify concrete actions, they effectively become ``commands'' that can drive real-world side effects beyond user intent. We argue that this risk arises from conflating action induction with execution authorization. To address this distinction, we propose SARA, which treats action induction and execution authorization as distinct runtime roles and separates action provenance from execution authority. On the Observation side, a context-isolated Action Probe exposes action-inducing semantics and persistently records action-origin provenance across steps as a review signal; on the execution side, actual tool calls are authorized only against the user objective and audited evidence from authorized successful executions, while satisfying goal, execution-chain, and argument-level support. To preserve this separation across multi-step execution, SARA applies No-History-Promotion to prevent historical recurrence from laundering action origins into execution authority. Across AgentDojo and AgentDyn, SARA limits ASR to no more than \(0.63\%\) across four primary evaluation settings while maintaining competitive task utility, and consistently reduces ASR across additional Agent backbones.

# 论文总结：《When Tool Outputs Become Commands: Separating Action Induction from Runtime Authorization in Tool-Augmented LLM Agents》

## 1. 论文的核心问题与整体含义

**研究动机与背景：**
- 大型语言模型（LLM）正从文本生成器演变为能够通过外部工具在真实世界中执行操作的智能代理（Agent），可执行发送信息、修改对象、提交交易等具有真实副作用的操作。
- 由于开放式任务需要依赖不可信的运行时观察（工具输出、网页内容、邮件等），攻击者可以在第三方资源中嵌入操作指令，通过**间接提示注入（IPI）** 操纵Agent执行未授权操作，产生真实外部后果。
- 现有防御面临**结构性安全-效用权衡**：过度限制不可信内容会削弱开放式任务所需的运行时适应性；放任观察影响后续行为又会让攻击语义传播至真实执行。

**论文核心论点：**
- 工具输出从"提供数据"转变为"指定具体动作"时，本质上成为可驱动真实副作用的"命令"。
- 这种风险的根源在于**混淆了动作诱导（Action Induction）与执行授权（Execution Authorization）**：外部内容可以参与候选动作的形成（运行时实例化），但绝不能因此获得用户未授予的真实执行权限（权限扩张）。
- 该问题在结构上类似于经典安全领域的**"困惑的助手"（Confused Deputy）问题**——拥有合法工具权限的Agent被外部内容诱导行使超出用户意图的权限。

## 2. 论文提出的方法论

### 核心思想
SARA（Separating Action Induction from Runtime Authorization）将**动作诱导**与**执行授权**视为两种不同的运行时角色，部署在Agent与真实工具执行器之间，在真实执行边界上独立重新建立授权支持。

### 关键技术细节

**（1）授权根（Authorization Root）的构建**
- 从用户请求 $U$ 生成任务级授权契约 $K = \text{Contract}(U)$，每个条目包含效果类型、允许操作、作用范围和静态参数。
- $K$ 定义了任务级权威上限，但不预先枚举完整工具调用序列，保留运行时灵活性。

**（2）上下文隔离的动作探针（Context-Isolated Action Probe）**
- 对每个工具输出 $O_t$ 在隔离上下文中执行探针：$(z_t, Q_t, M_t) = \text{Probe}(O_t, T)$。
- $z_t \in \{\text{STATIC}, \text{ACTIONABLE}\}$ 指示是否存在动作诱导语义；$Q_t$ 为工具级动作足迹；$M_t$ 为参数级锚点 $(\tau, p, \text{norm}(v))$。
- ACTIONABLE **不表示恶意或未授权**，仅触发后续持久审查义务。

**（3）持久动作起源集（Persistent Action-Origin Set $F_t$）**
- 轨迹状态 $S_t \in \{\text{CLEAN}, \text{EXPOSED}\}$ 持久追踪是否出现过动作诱导内容。
- 一旦发现ACTIONABLE观察，对应的动作起源 $\phi_t = (Q_t, M_t)$ 被永久（在任务范围内）记录在 $F_t$ 中，不因后续正常执行、上下文传播或时间流逝而自动清除。

**（4）审计执行证据（Audited Execution Evidence $H_t$）**
- 仅记录**被允许且实际成功执行**的工具交互：$H_t = \{(c_i, O_i, \ell_i) | 1 \le i \le t, \text{Allow}(c_i) \land \text{Success}(c_i)\}$。
- $\ell_i$ 分为 DATA_ONLY（仅传播运行时数据）和 GOAL_BOUND（可参与执行链和参数绑定决策）。

**（5）目标、执行链与参数三级支持**
- $\text{Auth}_{t+1}(c) = G_{t+1}(c) \land C_{t+1}(c) \land A_{t+1}(c)$
  - $G_{t+1}(c)$：目标支持（Goal Support）——调用必须保持在用户任务边界内。
  - $C_{t+1}(c)$：执行链支持（Chain Support）——运行时依赖须来自任务一致的成功执行关系。
  - $A_{t+1}(c)$：参数支持（Arg Support）——每个实际参数须分类为 USER_BOUND、HISTORY_BOUND、SAFE_DEFAULT 或 UNSUPPORTED。

**（6）No-History-Promotion（NHP）机制**
- 防止"动作起源 → 历史重复出现 → 权威提升"的**溯源洗白**路径。
- 若参数已在 $F_t$ 中关联动作诱导起源，其后续在 $H_t$ 中的重复出现不能独立赋予 HISTORY_BOUND 支持或通过 SAFE_DEFAULT 绕过约束。

### 运行时控制回路
$$O_t \rightarrow (S_t, F_t) \rightarrow c_{t+1} \rightarrow \text{Auth}_{t+1} \rightarrow \text{Exec} \rightarrow (O_{t+1}, H_{t+1})$$

## 3. 实验设计

**数据集与基准：**
- **AgentDojo**：覆盖Banking、Slack、Travel、Workspace四个可执行套件，含92个良性任务和3,528个攻击实例（4种攻击变体各882个）。

- 四种IPI攻击变体：ignore_previous (IP)、system_message (SM)、important_instructions (II)、tool_knowledge (TK)。

**评估指标：**

## 6. 论文的主要结论与发现

- **SARA显著降低攻击成功率**：在4个主要评估设置中，ASR不超过0.63%（GPT-4o-mini下为0.06%和0.17%，Gemini-2.5-Flash-Lite下为0.62%和0.63%），同时UA不低于Agent-only基线。
- **安全-效用平衡优于现有方法**：相比CaMeL等强执行隔离方法，SARA在保持极低ASR的同时，对良性效用（BU）的损失更小（SARA的BU减少5.79–11.82个百分点，CaMeL减少15.94–39.71个百分点）。
- **跨骨干安全增益一致**：所有8个骨干-基准组合中ASR均显著下降，说明SARA的安全收益不依赖特定模型。
- **四大机制的差异化贡献**：
  - AIT和PSG主要维护安全边界（缺失时ASR升至2.49%–3.37%）。
  - AE提供合法性运行时动态绑定支持（缺失时UA下降约10–13个百分点）。
  - NHP精准阻断溯源洗白路径（缺失时ASR升至0.65%–0.75%）。
- **推理成本换取安全效用**：SARA并非最低token开销的防御，但在安全性、任务效用和运行成本的系统级权衡中形成优势。

## 7. 优点

1. **问题定义清晰且深刻**：将IPI风险揭示为"动作诱导"与"执行授权"的混淆，结合经典"Confused Deputy"问题提供了有力的理论框架。
2. **设计原则简洁有力**：核心原则"动作诱导 ≠ 执行授权"贯穿始终，系统设计与其高度一致。
3. **不依赖不可信内容分析准确性**：与直接检测恶意内容不同，SARA只检测动作诱导语义并触发审查，避免了LLM检测器自身易被对抗操纵的弱点。
4. **不牺牲运行时适应性**：允许动态对象通过审计执行证据合法实例化任务，避免防御退化为性能瓶颈。
5. **可审计性与透明性**：维护三种互补的信息源（$K$、$F_t$、$H_t$），授权决策有清晰的支撑依据，不依赖Agent隐藏的内部推理状态。
6. **消融实验设计合理**：每个关键机制（AIT、AE、PSG、NHP）被独立验证，安全与效用贡献得到分离解析。
7. **跨骨干验证全面**：覆盖多个模型家族与参数规模，安全增益的一致性得到充分验证。

## 8. 不足与局限

1. **不提供正式安全保证**：SARA是运行时授权机制，其语义判断可能产生误报或漏报；被阻塞执行后的恢复依赖宿主Agent的重规划能力，整体效用受限于模型能力和工作流动态性。
2. **威胁模型范围有限**：仅覆盖工具型IPI工作流；不处理绕过授权运行时的直接攻击、纯数据依赖漏洞、或无条件将决策权委托给外部内容的场景。
3. **攻击场景假设受限**：假设用户输入、工具模式、SARA运行时和真实工具执行器可信；若攻击者可修改这些系统组件则防御失效。
4. **推理开销可观**：在AgentDyn上总输入token约为无防御基线的2.21倍，较高的延迟和成本可能限制其在实时或资源受限场景中的部署。
5. **任务效用受骨干能力影响大**：在动态工作流中，BU和UA均有所下降（尤其是Llama3.3-70B和Qwen3-32B在AgentDyn上BU下降超过12个百分点），复杂动态工作流会放大安全干预后维持任务连续性的成本。
6. **开放性任务边界有待探索**：对用户请求中隐含授权的自动准确推断仍然是未完全解决的挑战；参数级支持分类（如SAFE_DEFAULT）的判断可能在不同领域间存在不一致性。
7. **实验局限**：BU的统计基于仅3次独立运行；实验结果可能受所选基准的任务组成影响，向更广泛真实世界场景推广需要进一步验证。
