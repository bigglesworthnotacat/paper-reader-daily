## 摘要
大型语言模型（LLM）代理越来越多地操作不受信任的网页、文档、工具和持久状态，同时对安全敏感的资源行使权限。现有的防御通常只保护规划或单个工具交互，但持久化代理面临更广泛的威胁：攻击者控制的数据可以改变控制流、进入安全敏感的工具参数，或破坏后续查询。我们提出了SPA，一种计划优先的架构，保护规划、执行和跨查询状态重用。SPA每次查询调用一次规划器，以声明式领域特定语言生成完整的可执行计划，然后应用双格信息流控制来跟踪显式数据流和控制依赖关系中的机密性和完整性。为了在支持持久化的同时不将不受信任的有效载荷重新暴露给规划器，SPA将执行结果存储为带标签的工件，并在后续规划中仅揭示语义元数据。我们在AgentDojo和AgentDojo-MQ上评估SPA，后者是我们用于衡量安全状态重用和延迟攻击的多查询扩展。在“工具知识”攻击下，采用信息流控制的SPA将AgentDojo上的攻击成功率降至零，在AgentDojo-MQ上降至0.2%。我们的结果表明，计划优先执行与保留标签的持久化相结合，可以显著增强持久化LLM代理，同时揭示了严格完整性执行所引入的重要安全-效用权衡。

## Abstract
Large language model (LLM) agents increasingly operate over untrusted webpages, documents, tools, and persistent states while exercising authority over security-sensitive resources. Existing defenses typically protect either planning or individual tool interactions, but persistent agents face a broader threat: attacker-controlled data can alter control flow, enter security-sensitive tool arguments, or compromise later queries. We present SPA, a plan-first architecture that secures planning, execution, and cross-query state reuse. SPA invokes the planner once per query to generate a complete executable plan in a declarative domain-specific language, then applies dual-lattice information-flow control to track confidentiality and integrity across explicit data flows and control dependencies. To support persistence without re-exposing untrusted payloads to the planner, SPA stores execution results as labeled artifacts and reveals only semantic metadata during later planning. We evaluate SPA on AgentDojo and AgentDojo-MQ, which is our multi-query extension for measuring secure state reuse and delayed attacks. Under the 'tool_knowledge' attack, SPA with information-flow control reduces attack success to zero on AgentDojo and 0.2% on AgentDojo-MQ. Our results show that plan-first execution combined with label-preserving persistence can substantially strengthen persistent LLM agents, while revealing an important security-utility tradeoff introduced by strict integrity enforcement.

  - **交错式防御**（interleaved defenses，如FIDES、CaMeL）：在规划和工具执行交替时应用隔离或信息流控制，但规划器反复暴露于工具输出，后续决策仍可能被不可信内容影响。
  - **计划优先防御**（plan-first，如F-secure、ACE）：在执行前固定控制流，但固定计划仍可能将攻击者控制的值传给安全敏感工具，且未解决跨查询持久状态重用问题。
- 核心矛盾：**计划优先隔离与持久化重用之间存在根本张力**——要向规划器隐藏持久化负载以保护控制流，但持久化代理又必须判断先前结果是否与后续请求相关；而将全部状态暴露给规划器会重新引入不可信信道。

**核心含义：**
- 该文将持久化LLM代理面临的安全问题定义为跨查询的**信息流问题**（而非单步规划或单次工具调用问题）。
- 提出需要在规划、执行、持久状态三个层面同时实施统一的信息流保护，才能应对"周一注入、周二生效"的延迟攻击。

## 2. 论文提出的方法论

### 2.1 核心思想
SPA（Securing Persistent LLM Agents Across Queries with Plan-First Information-Flow Control）基于两个关键观察：
1. **完整的可执行计划**使未来的数据和依赖在执行前足够显式，可预先验证；
2. **判断先前结果是否可复用**通常只需知道该结果"表示什么"（语义元数据），而不必向规划器暴露其具体负载。

### 2.2 系统架构与流程
SPA 按查询处理管道分为六个步骤（Algorithm 1）：
1. **上下文投影**（Context projection）：仅向规划器暴露工件元数据（Σα），隐藏值（Σω）和安全标签（Σλ）。
2. **计划合成**（Plan synthesis）：规划器仅被调用一次，生成完整DSL计划。
3. **具体化**（Concretization）：抽象模式下绑定抽象工具到已安装工具。
4. **语法校验**（Syntactic validation）：检查DSL良好形式、变量绑定和范围约束。
5. **流验证**（Flow verification）：双格IFC静态传播标签并检查端点策略。
6. **执行与提交**（Execution and commit）：确定性解释器精确按已验证计划执行，持久化带标签工件。

### 2.3 关键技术细节

**DSL（领域特定语言）设计：**
- 计划为JSON结构，仅含六种步骤：`retrieve`（取回持久化工件）、`tool`（调用外部工具）、`q-llm`（检疫LLM处理非结构化文本）、`display`（用户可见输出）、`condition`（条件分支）、`loop`（循环）。
- 值表达式仅限变量引用、投影、字面量和JSON对象/数组构造，禁止模板、算术和自定义函数，使数据依赖在语法中显式化。
- 条件谓词限制在固定运算符集（`eq、neq、lt、lte、gt、gte、in、exists`），复杂逻辑通过嵌套条件表达，保持控制依赖清晰。

**双格信息流控制：**
- 每个值带乘积标签 `λ(x) = (C(x), I(x))`，其中 C 为机密性格（public → private），I 为完整性格（untrusted → trusted）。
- 组合规则：`(c1,i1) ⊔ (c2,i2) = (c1 ⊔ c2, i1 ⊓ i2)`——机密性取上确界、完整性取下确界。
- **流规则**：从源 vs 到目标 vd 的流被允许当且仅当 `C(vs) ⊑ C(vd) ∧ I(vd) ⊑ I(vs)`（Bell-LaPadula机密性 + Biba完整性）。
- 每个工具 f 有输入策略 `λin(f)` 和输出基线 `λout(f)`；显示通道有独立接收策略 `λdisp`。
- 标签传播包括：
  - **显式流**：工具调用、q-llm、取回步骤按变量依赖组合标签；
  - **隐式流**：条件分支和循环体使用程序计数器标签 `pc' = pc ⊔ λ(谓词/集合)`，使控制依赖被纳入限制；
  - 检疫LLM不能"漂白"标签：输出继承输入标签，不可提升完整性或降低机密性。
- 显示违规不导致整个计划拒绝，而是用**编辑标记（redaction marker）**替换违规项。

**标签保留持久化：**
- 每个工件存储为三视图：具体值（Σω）、安全标签（Σλ）、规划器可见语义元数据（Σα，含schema、intent、output_semantics、source_query）。
- 后续查询通过显式 `retrieve` 步骤取回工件，其原始标签被恢复，跨查询保持污点。

**可选抽象规划模式：**
- 工具合成阶段从用户请求单独生成抽象工具模式；规划仅接触抽象工具；执行前由映射阶段绑定到兼容的安装工具；映射代码在受限解释器中执行。

## 3. 实验设计

### 3.1 数据集与基准
- **AgentDojo v1.2.2**：单查询基准，包含四个套件（workspace、slack、travel、banking），共97个用户任务。
- **AgentDojo-MQ**（自建）：将AgentDojo任务转换为多查询片段，带显式跨轮工件依赖注释。对97个任务标注了非排他依赖分类：
  - 顺序依赖（SEQ，97个）；
  - 选择（SEL，77个）；
  - 条件（COND，9个）；
  - 扇出（FAN，12个）；
  - 正交组合（ORTH，11个）。
- 每个任务有手写的工件依赖图，确定性分割为2–5轮，每轮标注 `produces` 和 `depends_on` 工件ID。

### 3.2 攻击设置
- 使用 **tool_knowledge** 攻击：攻击者获得目标任务的真实工具序列，可在工具输出中嵌入对抗内容。
- 单查询：97个基线 + 949个攻击运行（每配置共1081次运行）。
- 多查询：同样规模的运行覆盖AgentDojo-MQ片段。

### 3.3 对比配置（消融）
- **具体规划 vs 抽象规划**（Concrete vs Abstract）；
- **IFC启/停**（IFC vs No IFC）；
- 附加控制：**Concrete No IFC + Values**（开放记忆：持久化工件值直接暴露给后续规划器）。
- 共5个主要配置 × 单/多查询两个场景。
- 规划器和检疫LLM使用 `gpt-5.4-nano`（高推理档）；抽象-具体映射用嵌入相似度（阈值0.6，每种抽象工具至多3个候选）。

### 3.4 评估指标
- **效用**（Utility）：AgentDojo任务检查通过率。
- **攻击成功率**（ASR）：AgentDojo安全检查报告攻击目标成功的比例。
- **管线状态**：达到执行阶段 vs 早期失败（如IFC拒绝、抽象映射失败）。
- **重用率**（AgentDojo-MQ）：soft-hit（仅评分可评分轮）+ strict（缺失生产者工件也计为失败）+ 不可评分率。

## 6. 论文的主要结论与发现

1. **安全有效性**：在tool_knowledge攻击下，启用双格IFC的SPA将AgentDojo攻击成功率降至0.0%（949次攻击运行中0次成功），AgentDojo-MQ降至0.2%（少数判定为攻击成功但计划实为IFC拒绝且任务未完成）。
2. **计划优先隔离已构成第一道防线**：即使无IFC的Concrete No IFC也仅0.4% ASR（全部4次成功都集中在banking的user_task_12任务）；IFC消除了这4次成功。
3. **显著的安全—效用权衡**：
   - 单查询：启用IFC使Concrete模式基线效用从53.0%降至29.0%（约24pp损失）；
   - 多查询：62.5%→35.3%（约27pp损失）。
   - 主要原因为完整性检查拒绝将低完整性工具输出传递给高完整性工具参数（约45–53%的IFC模式运行以 `ifc_failed` 终止）。
4. **跨查询重用保持较好**：Concrete No IFC软命中重用95.4%（严格80.1%），启用IFC为89.9%（严格73.4%），表明标签保留持久化在隐藏负载的同时仍支持高复用率。
5. **抽象规划是挑战而非优势**：约75–77%的抽象运行失败于抽象-具体映射，覆盖极低；当前模型+阈值组合下不可用（travel效用0%）。
6. **开放记忆并非免费午餐**：暴露值给后续规划器使banking效用上升25pp但travel下降20pp，ASR翻倍虽仍<1%。

## 7. 优点

- **问题定义清晰且重要**：将持久化代理安全刻画为跨查询的信息流问题，突破了"单步防御"范式。
- **方法论自洽**：计划优先架构 + 双格IFC + 标签保留持久化三者环环相扣——DSL使依赖显式可验证，IFC使流规则统一前后一致，持久化使标签跨查询存活。
- **形式化严谨**：流规则、标签传播、隐式流处理、显示通道编辑策略均有明确的算法（Algorithm 4）和数学条件；验证是静态、fail-closed的单遍过程，无迭代反馈通道。
- **工程实现务实**：检疫LLM与规划器隔离、工具在容器中执行、映射代码在受限解释器运行（限定global白名单）、JSON Schema全程校验等细节考虑较周全。
- **数据集贡献**：AgentDojo-MQ将跨查询工件的产生/消费和延迟攻击显式建模，为后续持久化代理安全研究提供了可复现的基准。
- **诚实呈现权衡**：不回避安全—效用矛盾，清楚展示IFC的高安全性与高Utility损失的边界。

## 8. 不足与局限

### 实验覆盖不足
- 单一模型（gpt-5.4-nano）评估，未覆盖多个规划器模型，泛化性未知；
- 单一攻击类型（tool_knowledge），且该攻击并非为持久化注入设计的，对"延迟规划攻击"和"延迟执行攻击"的探测薄弱；
- 97个AgentDojo任务的人工依赖图标注可能有主观偏差，未用自动化和多位标注者交叉验证；
- 无对策略错误配置（lattice定义、工具策略）鲁棒性的测试。

### 方法层面局限
- **严格完整性导致高效用损失**：变量级标签过于粗糙，无字段级标签、参数级完整性要求或显式背书（endorsement）机制，使大量合法工作流（依赖外部数据做安全动作）被拒绝；
- **抽象规划当前不可用**：工具映射成功率过低（约25%），且未提供映射失败的根本原因分解和不同阈值敏感性分析；
- **持久化重用的语义基础依赖规划器自述**：intent/output_semantics由规划器撰写，不够可靠时可能导致错误复用。

### 偏差风险
- 多个AgentDojo任务在抽象模式下被判定"效用通过"是因为初始状态即满足检查条件（如banking 5个任务），造成抽象效用虚高；
- 开放记忆和元数据模式的对比并非等量：可见值使规划器可以"复制字面量"而非"retrieve"，导致开放记忆模式的retrieve率偏低，可能低估其复用能力；
- AgentDojo-MQ与单查询AgentDojo的效用对比差异不止来自持久化（同时改变了提示范围、会话历史、评分方式），作者也承认这不是纯持久化消融。

### 应用限制
- 攻击面排除模型级越狱和校准失败（依赖信息流之外的机制）；
- 侧信道未建模；
- 部署配置（lattice、工具策略、绑定）是信任根，策略配置错误可导致安全或可用性问题，论文未给出策略自动推断方案。
