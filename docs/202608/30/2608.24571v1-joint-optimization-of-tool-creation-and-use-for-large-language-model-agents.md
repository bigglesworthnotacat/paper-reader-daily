## 摘要
工具增强的语言模型受限于人类编写的API；现有的工具创建系统通过在推理时提示冻结的LLM来修补这一问题，使得编写工具与使用工具的模型相互脱节，且没有信号表明其生成的模式是它可以调用的。我们提出了SMITH（基于模式的迭代工具打磨多任务学习），这是一种在单一策略内联合训练工具创建与工具使用的强化学习框架。每次展开要么是构建任务（根据少量示例编写工具），要么是使用任务（在保留问题上调用池化工具）。三个独立的奖励轴分别捕获模式、代码和结果失败，使每种失败模式都能贡献其梯度。使用SMITH在13个具有精确验证器的程序性推理任务上训练的4B Qwen3在保留任务上达到了79.8的宏平均准确率，在所有评估方法中表现最佳，并优于未训练的30B-A3B工具编写器。它还在TabMWP-Hard上达到40.4，在域外GQA上达到42.6（较最佳同骨干推理时间基线提高7.6），无需任何视觉或表格训练数据。我们的4B模型编写的工具也提升了LFM-2.5-350M和Qwen3-30B-A3B在相同推理任务上的性能。

## Abstract
Tool-augmented language models are bounded by the APIs humans bothered to write; existing tool-creation systems patch this by prompting a frozen LLM at inference time, leaving the model that writes a tool decoupled from the one that uses it, with no signal that the schemas it produces are schemas it can invoke. We propose SMITH (Schema-grounded Multi-task Iterative Tool Honing), a reinforcement learning framework that jointly trains tool creation and tool use inside a single policy. Each rollout is either a build task (write a tool from a few examples) or a use task (invoke a pooled tool on a held-out question). Three separate reward axes catch schema, code, and outcome failures independently, so each failure mode contributes its own gradient. A 4B Qwen3 trained with SMITH on 13 procedural reasoning tasks with exact verifiers reaches 79.8 macro-average accuracy on held-out tasks, the best across all evaluated methods and ahead of an untrained 30B-A3B tool-writer. It also reaches 40.4 on TabMWP-Hard and 42.6 on out-of-domain GQA (+7.6 over the best same-backbone inference-time baseline), without any visual or tabular training data. Tools written by our 4B models also lifted the performance of LFM-2.5-350M and Qwen3-30B-A3B under same reasoning tasks.

## 1. 核心问题与研究动机

- **背景**：工具增强的语言模型（LLM）通过调用外部接口（计算器、代码解释器、搜索引擎等）突破参数记忆的局限，但现有系统依赖固定、人工设计的 API 工具集，无法覆盖新任务。
- **已有工具创建方案（LATM、CRAFT、Trove、KTCE）的局限**：这些方法通常在推理时通过提示冻结的 LLM 生成工具，然后由另一个模型调用；工具编写者与工具使用者完全解耦，**模型没有信号知道自己生成的 schema 是否可被可靠调用**。
- **核心问题**：如何训练**同一个模型**既成为更好的工具创建者，又成为更好的工具使用者？这正是论文要解决的关键开放问题。
- **整体含义**：如果模型在创建工具时就能预期自己后续如何调用它，那么生成的工具接口会更清晰、更可复用，从而提升模型在新任务上的泛化能力，摆脱对大规模教师模型或复杂人工流程的依赖。

## 2. 方法论：SMITH 框架

### 2.1 核心思想

- **单一策略联合训练**：SMITH（Schema-grounded Multi-task Iterative Tool Honing）在同一个共享策略中同时训练两种互补技能：
  - **构建任务（build）**：根据少量示例生成工具，输出为 Python 函数 + OpenAI 兼容 JSON Schema。
  - **使用任务（use）**：只看到 JSON Schema（不看到代码），调用工具回答保留问题。
- **Schema 作为桥梁**：由于同一个模型既是作者也是调用者，schema 不清晰或不完整会直接在使用阶段失败，从而提供直接的训练信号。

### 2.2 奖励设计（三轴解耦）

构建任务的奖励由三个独立信号组成：

1. **执行准确率（evaluation reward）**：评估模型 `π_eval` 调用生成工具回答 `K=16` 个保留问题，正确比例记为 `r_eval`。只有通过工具调用得到的答案才计分，防止文本推理绕过。
2. **格式奖励（format reward）**：要求响应中恰好包含一个 Python 块和一个 JSON 块，且函数名与参数签名一致；`r_fmt ∈ {0, 0.5}`。
3. **LLM 法官奖励（judge reward）**：一个独立的 LLM 法官对代码正确性、schema 质量、整体质量打分，并对语法错误、schema-code 签名不一致等情况施加惩罚。该信号独立于环境奖励传递，保持“执行”与“语义质量”信号分离。

使用任务的奖励：

- **正确性奖励**：最终答案匹配则 `c=1`，并按回合效率 `η(ρ)` 加权，鼓励用更少的工具调用步数解决问题。

构建任务的两轴 + 使用任务的一轴，共**三个独立奖励轴**，通过 DAPO（GRPO 的 clip-higher 变体）联合优化。

### 2.3 关键机制

- **同步评估器**：`π_eval` 从相同基座初始化，每 5 步复制最新策略权重，避免与在线训练权重同步带来的不稳定性。
- **工具池（Tool Pool）**：缓存 `r_eval>0` 的工具，每类最多 20 个，质量优先、按旧回收；使用任务注入 1 个域内工具 + 2 个无关干扰工具，迫使模型按 schema 选择正确工具。
- **易到难（easy-to-hard）训练协议**：构建上下文取自困难度较低的课程带，而评估集取自最困难的带，强制工具抽象底层算法，而不是拟合简单示例。

## 3. 实验设计

### 3.1 训练与评估数据集

- **训练**：Reasoning-Gym 中 13 个程序化推理任务族，覆盖算术、算法、代数、游戏、逻辑。全部具有精确验证器。
- **域内评估**：
  - `RG (Seen)`：13 个训练任务族在最高难度级别上的宏平均准确率。

- **域外评估**：
  - `TabMWP-Hard`：从 TabMWP 扩展的高难度表格推理基准（表可扩展至 5000 行并添加无关列）。
  - `GQA`：视觉问答数据集，需要视觉工具，模型在 RL 阶段未见任何视觉/表格训练数据。
- **外部工具调用**：BFCL v4（no-web）评估外部函数调用能力。

## 6. 主要结论与发现

- SMITH 在 held-out Reasoning-Gym 任务上达到 **79.8%–79.9% 宏平均准确率**，全面优于所有评估方法，包括 30B-A3B 推理时工具编写器。
- 在 **TabMWP-Hard** 上达到 **40.4%**，在 **GQA** 上达到 **42.6%**（比同骨干最佳推理时基线高 +7.6），且未使用任何表格或视觉训练数据。

- **训练目标泛化**：同样配方在 Qwen3-8B 和 Granite-3.3-8B 上均带来提升，并在 BFCL 外部函数调用上也改善，说明学到的不是单一基准的过拟合。
- 消融证实：联合训练（而非专业化分工）是主要驱动力；分离过程质量与结果质量对跨域鲁棒性至关重要。

## 7. 优点

- **创新性强**：首次在 RL 框架内联合优化工具创建与使用，形成“自举”反馈闭环。
- **奖励设计精细**：三轴奖励解耦 schema、代码、结果失败，避免单一奖励遮蔽错误来源，并在附录中给出设计教训（如硬失败必须全零、法官提示需对齐验证器）。
- **易到难协议**：强制工具抽象化，避免记忆捷径，提升泛化。
- **实验全面**：覆盖多个数据集、多个骨干、跨模型迁移、消融与基线修复，证据链完整。
- **算力门槛低**：单卡可复现，对社区友好。
- **诚实讨论局限**：明确承认 judge 依赖、规模上限、多工具并行缺失等问题。

## 8. 不足与局限

- **规模有限**：所有训练策略最大为 8B，judge 为 30B-A3B；70B 以上是否有效未验证。
- **Judge 依赖**：外部 judge 影响训练信号质量；Self-Judge 会提升 held-out 指标但降低 OOD GQA，说明 judge 规模与偏差存在权衡。
- **安全与可读性**：代码在沙箱中执行，但未形式化证明恶意提示无法诱导不安全工具；未进行 schema 可读性或开发者友好度的人为评估。
- **多工具/并行调用缺失**：训练从未观察到并行工具调用或多工具同时生成，对真实世界“深度研究”式场景支持不足。

- **基线公平性**：部分基线（如 ReTool）在 RG Seen 上比 SMITH 更高，说明蒸馏在熟悉分布上的优势；此外，KTCE/Trove 原始实现中的 bug 修复可能改变其原始性能，但作者已透明说明。
