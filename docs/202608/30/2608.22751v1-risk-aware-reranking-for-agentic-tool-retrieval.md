## 摘要
工具检索决定了对于用户查询或任务，哪些外部工具被暴露给LLM智能体，因此检索成为一个关键的执行前安全边界。与文档检索不同，工具检索暴露了可执行的操作：对一个任务有用的工具可能对另一个任务不必要或有风险。然而，现有的工具检索方法主要优化语义相关性，安全评估往往关注工具执行后的失败，而非检索过程中引入的风险。我们研究风险感知的工具检索，其目标是在检索有用工具的同时，减少对高风险工具的暴露。我们提出了一种轻量级重排序框架，搭建在冻结的第一阶段检索器之上。该框架分别建模查询条件下的相关性和工具级别的暴露风险，通过一个显式参数控制安全性与实用性之间的权衡，在ToolGraph上平滑分数，并可选择性地应用基于规则的安全约束。为了支持检索时的安全评估，我们为UltraTool和Seal-Tools中的6,108个工具标注了五个序数风险级别，并定义了衡量前k个结果中高风险工具暴露度的指标。在UltraTool和Seal-Tools上的实验表明，与仅考虑相关性的检索器和重排序基线相比，我们的方法改善了相关性-安全性权衡，其中规则过滤变体为安全关键型部署提供了一个保守的操作点。这些发现表明，检索阶段的过滤可以在执行前减少暴露给智能体的候选操作空间，补充下游工具使用安全措施。代码和补充材料可在以下网址获取：https://github.com/qli447/risk-aware-tool-retrieval-release。

## Abstract
Tool retrieval determines which external tools are exposed to an LLM agent for a user query or task, making retrieval a critical pre-execution safety boundary. Unlike document retrieval, tool retrieval exposes executable actions: a tool that is useful for one task may be unnecessary or risky for another. However, existing tool-retrieval methods primarily optimize semantic relevance, and safety evaluations often focus on failures after tool execution rather than risks introduced during retrieval. We study risk-aware tool retrieval, where the goal is to retrieve useful tools while reducing exposure to higher-risk tools. We propose a lightweight reranking framework on top of a frozen first-stage retriever. The framework models query-conditioned relevance and tool-level exposure risk separately, combines them through an explicit parameter controlling the tradeoff between safety and utility, smooths scores over a ToolGraph, and optionally applies rule-based safety constraints. To support retrieval-time safety evaluation, we annotate 6,108 tools across UltraTool and Seal-Tools with five ordinal risk levels and define metrics that measure risky-tool exposure in the top-$k$ results. Experiments on UltraTool and Seal-Tools show that our approach improves the relevance--safety tradeoff over relevance-only retrievers and reranking baselines, with the rule-filtered variant providing a conservative operating point for safety-critical deployments. These findings indicate that retrieval-stage filtering can reduce the candidate action space exposed to agents before execution, complementing downstream tool-use safeguards. The code and supplementary materials are available at: https://github.com/qli447/risk-aware-tool-retrieval-release.

## 1. 论文的核心问题与整体含义

**研究动机与背景：**
- 大语言模型（LLM）智能体日益依赖外部工具（API、代码执行器、文件管理器等）完成复杂任务，工具检索决定了智能体在用户查询下可接触的候选工具集，是**执行前的安全边界**。
- 与文档检索不同，工具检索暴露的是**可执行动作**：一个工具对某个任务有用，对另一个任务可能不必要甚至危险。工具检索出错可能导致不可逆后果（如未经授权的数据删除、凭证泄露）。
- 现有工具检索方法主要优化**语义相关性**，检索指标（NDCG、MRR）不区分低风险与高风险工具；安全评测大多关注工具执行后的失败，而非检索阶段引入的风险暴露。

**核心问题：**
> 如何在保持检索有用性的同时，减少检索结果中对高风险工具（可执行的高风险动作）的暴露？

## 2. 论文提出的方法论

论文提出一个**轻量级风险感知重排序框架**，搭建在冻结的第一阶段检索器（ToolRet-BGE）之上，核心思想与关键技术如下：

### 2.1 双头重排序（Dual-Head Reranking）
- **相关性头**（`f_rel(q, t)`）：以查询-工具拼接嵌入为输入，输出查询条件下的相关性分数。
- **风险头**（`f_risk(t)`）：仅以工具嵌入为输入，估计工具级别的暴露风险。
- 两者输出均经 sigmoid 归一化到相同数值范围，组合分数为：
  \[
  s(q,t) = f_{rel}(q,t) - \lambda f_{risk}(t)
  \]
  其中 **λ 为推理时可调参数**，控制安全性与实用性的权衡（λ=0 退化为风险盲重排序）。

### 2.2 训练目标
- 相关性损失：基于三元组（query, positive, negative）的**成对边际损失**，负样本优先从第一阶段 top-100 候选中采样，与重排序场景对齐。
- 风险损失：将序数风险标签归一化为 \(\bar{r}_i = (r_i-1)/4\)，使用**均方误差（MSE）** 监督。
- 总损失：\(\mathcal{L} = \mathcal{L}_{rel} + \mu \mathcal{L}_{risk}\)，μ 用于平衡。

### 2.3 ToolGraph 分数平滑
- 构建离线 ToolGraph，包含四类边：**共现边**、**语义边**、**权限边**、**风险共现边**。
- 在候选工具诱导的子图上进行一次传播平滑，避免过平滑并保持推理轻量。
- 论文明确指出该图主要起**关系平滑**作用，主要安全控制来自风险惩罚与规则过滤。

### 2.4 可选规则过滤器（Rule Filter）
- 面向需要更严格暴露控制的部署（假定有审计过的工具注册表）。
- 三条约束：风险上限（top-K 中高风险工具不超过 1 个）、权限上限（多类高危权限工具不超过 2 个）、冗余抑制（余弦相似度 > 0.9 的候选被拒绝）。
- 无训练参数，贪心扫描，复杂度为 O(NK)，线性可扩展。

### 2.5 风险标注协议
- 对 6,108 个工具标注五级序数风险（L1-L5），由三个 LLM 标注器（Claude Code、Codex、Qwen）独立标注，采用基于 span 的冲突消解规则。

## 6. 论文的主要结论与发现

1. **核心重排序器（Core+Graph）** 在 UltraTool 上取得最佳相关性（NDCG@5 = 0.562），同时将 RVR@5 从 0.176 降至 0.145；规则过滤变体将 RVR@5 进一步降至 **0.073**，SRR@5 低至 **0.019**。
2. **相关性头会加剧风险暴露**：仅训练相关性头使 NDCG@5 从 0.429 提升至 0.558，但 RVR@5 反而从 0.176 上升至 0.188——语义匹配提升可能同时提升高风险工具排名。
3. **风险头有效校正暴露**：加回风险头后 RVR@5 降至 0.138，且 NDCG@5 保持较高（0.551），说明风险监督无需硬规则即可部分修正暴露问题。
4. **λ 是平滑的权衡旋钮**：增加 λ 稳定降低 RVR@5，同时带来中度 NDCG 损失；规则过滤则提供保守部署的固定操作点。
5. **大多风险削减发生在真正存在风险的查询上**：高风险查询子集中 RVR@5 显著下降（0.472 → 0.175），低风险查询上变化较小，说明方法主要去除**不必要**的高风险工具而非一刀切降级。
6. **规则过滤有代价**：NeedRisk-Hit@5 同步下降（0.660 → 0.397），即过度保守可能移除任务真正需要的高风险工具。
7. **模型具有 OOD 泛化能力**：在未见过的测试工具上仍能减少暴露，说明风险头学到了基于工具描述的风险模式。
8. **检索阶段过滤是有效的上游安全边界**：可减少执行前暴露给智能体的候选动作空间，但不能替代下游执行安全机制。

## 7. 优点

- **问题定义精准**：将工具检索明确为"执行前安全边界"而非单纯相关性匹配任务，提出新的风险感知检索范式。

- **显式可调节权衡**：λ 参数让部署方根据需求选择安全-效用操作点，无需重新训练。
- **定义了检索阶段安全度量体系**：提出 RVR、SRR、sNDCG 等指标，填补检索阶段安全评估空白；Safe-RVR 与 NeedRisk-Hit 区分"不必要暴露"与"必要高风险保留"，评价维度更细致。

- **态度审慎**：明确承认规则过滤的安全/实用性代价，未将"安全"一味高于一切，而是给出不同部署场景的选项。
- **开源共享**：提供代码与补充材料，便于复现。

## 8. 不足与局限

- **风险标注质量存在不确定性**：LLM 标注器在 UltraTool 上 Krippendorff's α 仅 0.523，人工复核的 Cohen's κ 只有 0.362（精确一致率 60%），表明风险标签存在可观的主观性与误差，实验结果可能受标签噪声影响。
- **风险建模仅为工具级**：`f_risk(t)` 只基于工具描述估计风险，不建模查询级、用户级或环境依赖危害。论文承认学习 `f_risk(q, t)` 需要逐对监督数据，但当前标注只有工具级。
- **未报告算力资源**：GPU 型号、数量、训练时长未交代，不利于评估方法的实际资源成本。
- **未做执行级评估**：所有指标衡量的是候选集的暴露而非实际的工具调用后果，无法回答"风险感知检索最终是否减少真实安全事故"。
- **λ 和超参数选择依赖验证集**：文中 α、λ、相似度阈值等均从验证集选择，在真实部署中可能面临分布漂移问题。

- **对比公平性细节**：核心配置在全池打分而基线在 top-100 候选上重排序，两者并非完全同条件对比（虽有附录 E.2 的候选匹配评估做补充，但主表呈现方式可能引起误解）。
