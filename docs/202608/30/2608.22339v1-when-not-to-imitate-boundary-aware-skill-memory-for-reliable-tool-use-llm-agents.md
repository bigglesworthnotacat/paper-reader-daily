## 摘要
从过去的成功中提取技能对于大型语言模型（LLM）智能体的高效演化至关重要。当前主流的智能体自我演化范式通常依赖一个核心假设：为LLM配备从成功轨迹中提取的技能记忆将单调地提升其问题解决能力。然而，探测分析揭示，仅从成功轨迹中提取技能会使模型陷入“技能模仿陷阱”（Skill Imitation Trap）。对于与过往成功相似但需要不同工具的任务，检索更多技能反而会提高模型对错误工具调用的置信度——相对于无记忆基线，过程技能将错误工具调用边际提高了47%。为了克服这一局限，我们提出了边界感知技能记忆（Boundary-Aware Skill Memory, BASM），它为每个技能增加了明确的边界字段——适用条件、风险提示、规避规则和恢复说明。这些字段将每个检索到的技能从无条件动作模板转化为状态条件化指导：当条件满足时，智能体应用该技能；当条件不满足时，抑制不适用工具调用；当执行失败时，发出有针对性的修复。在三个智能体基准和四个模型规模上，BASM持续优于从成功中蒸馏的技能记忆基线：在AppWorld上任务成功率提升高达23.8%，在BFCL上准确率提升高达5.0%，在AgentDojo上攻击成功率降低4.6%，同时相对于无记忆基线，AppWorld平均步数减少高达6.6%。

## Abstract
Extracting skills from past successes is critical for the efficient evolution of Large Language Model (LLM) agents. Prevailing agent self-evolution paradigms typically rely on a core assumption: equipping LLMs with skill memories derived from successful trajectories will monotonically improve their problem-solving capabilities. However, probe analyses reveal that extracting skills solely from successful trajectories traps the model in a \textbf{Skill Imitation Trap}. For tasks that resemble past successes but require different tools, retrieving more skills paradoxically increases the model's confidence in wrong tool calls---procedure skills raise the wrong-tool margin by $47\%$ over a memory-free baseline. To overcome this limitation, we propose \textbf{Boundary-Aware Skill Memory} (BASM), which augments each skill with explicit boundary fields---applicability conditions, risk cues, avoidance rules, and recovery notes. These fields transform each retrieved skill from an unconditional action template into state-conditioned guidance: the agent applies the skill when its conditions hold, suppresses inapplicable tool calls when they do not, and issues targeted repairs when execution fails. Across three agent benchmarks and four model scales, BASM consistently outperforms success-distilled skill-memory baselines: it improves task success rate by up to $23.8\%$ on AppWorld, accuracy by up to $5.0\%$ on BFCL, and reduces attack success rate by $4.6\%$ on AgentDojo, while simultaneously reducing average AppWorld steps by up to $6.6\%$ relative to the memory-free baseline.

## 2. 方法论：边界感知技能记忆（BASM）

**核心思想**
- 将每个技能从“无条件动作模板”转化为“状态条件化指导”：技能不再只是“怎样做”的配方，而是同时携带“何时能用、何时不能用、何时出错如何修复”的边界信息。
- 复用流程因此具备三种决策模式：**适用时应用（Apply）、不适用时抑制（Suppress）、失败时修复（Repair）**。

**七槽位技能模式**
每个技能表示为一个结构化记录：
\[
s = (g, \pi, T, A, R, N, F)
\]
其中：
- **过程性组件**：目标 \(g\)、过程规范 \(\pi\)、工具集 \(T\)；
- **边界性组件**：适用条件 \(A\)、风险提示 \(R\)、规避规则 \(N\)、恢复说明 \(F\)。

边界文本定义为 \(B(s) = A \oplus R \oplus N \oplus F\)。

**技能库构建（离线阶段）**
- 以成功轨迹 \(K^+\) 和失败/部分失败轨迹 \(K^-\) 为输入，在**步骤粒度**和**工具粒度**两级提取技能。
- 成功上下文提供目标、过程、工具字段；失败上下文仅作为边界证据（风险、规避、恢复）。
- 经过确定性验证算子 \(\psi\)：强制 JSON 解析、字段完整、边界槽为列表、非空风险提示与规避规则、工具模式合法；不合格候选丢弃，保证库质量。

**检索与提示格式（在线阶段）**
- 多视角检索分数：
\[
\text{score}(x_t, s) = \lambda_{\text{sem}} \cos(e(x_t), e(v_s)) + \lambda_{\text{tool}} J(\mathcal{T}_{x_t}, T_s) + \lambda_{\text{step}} \text{overlap}(x_t, g_s, \pi_s)
\]
- 过程组件始终暴露；边界字段仅当边界相关分数 \(r_B\) 超过阈值 \(\gamma\) 时才选择性包含，且受固定 token 预算 \(\beta\) 约束——这直接回应了“检索越多越危险”的探测发现。

**边界条件化执行与修复**
- **边界检查器**：对模型提出的工具调用 \(a_t\) 做判定，阻塞违反适用条件/匹配规避规则的调用或调用失败模式。
- **运行时修复模块**（状态环境）：观测 \(o_{t+1}\) 信号本地失败时，注入定向恢复提示 \(h_t\)，避免完整重新检索。

## 3. 实验设计

**使用的基准**
1. **BFCL v3**（Berkeley Function Calling Leaderboard）：多轮函数调用，800 实例，含 *base*、*long_context*、*miss_func*、*miss_param* 四个子集。其中 *miss_func* 和 *miss_param* 直接实例化技能模仿陷阱（需要拒绝语义相似但不适用的工具调用）。
2. **AppWorld**：有状态多步任务完成，168 个 *test_normal* 任务，通过 Python 风格 API 在持久应用环境中执行，是运行时修复模块的主要测试床。
3. **AgentDojo v1.2.2**：在 *tool_knowledge* 提示注入攻击下评估效用—安全性权衡，报告 Utility（越高越好）与攻击成功率 ASR（越低越好）。

**模型与基线**
- 模型：Qwen3-8B、Qwen3-14B、Qwen3-32B、Qwen3.5-397B-A17B 四种规模（8B–397B），关闭思考模式、温度 0.001。
- 基线：
  - **Base**：无记忆智能体；
  - **Proc. Skill**：仅检索目标任务/过程/工具（实例化主流“成功蒸馏技能”方法）；
  - **App. Skill**：Proc. Skill + 仅适用条件（对照 RL 中 action precondition / option initiation 思想）；
  - **BASM**：完整边界感知模式。
- 消融变体：**Prompt-BASM**（用 BASM 边界提示但不带运行时修复）、**Repair-Only**（仅运行时修复、无边界提示）、**BASM−Avoid**（去除规避规则）、**BASM−Recovery**（去除恢复说明）。

## 6. 主要结论与发现

1. **技能模仿陷阱真实存在且可量化**：检索深度从 k=0 增至 k=2 时，Proc. Skill 的错误工具边际从 7.31 升至 10.71（+47%），而 BASM 降至 2.26；实现层也观察到了同样模式，说明问题不限于 logit 层面的统计假象。
2. **边界字段是因果性反模仿通道**：同提示 knockout 证明，屏蔽决策 token 到边界文本的注意力，会恢复 69.4% 的模仿陷阱效应；随机同长掩码与过程线段掩码无法复现该效应，排除长度/格式替代解释。
3. **边界读取是状态条件化的**：边界/过程注意力比在适用状态为 0.15，在不适用状态升至 1.23，在修复状态峰值达 1.81；等长对照无法复现，表明模型在“该看边界时”才看边界。
4. **BASM 在主任务上全面优于基线**：
   - AppWorld 成功率最大提升 **23.8pp**（Qwen3-32B：76.19% vs. Proc. Skill 66.07%）；
   - BFCL 准确率最大提升 **5.0pp**（Qwen3-14B：42.50 vs. App. Skill 41.00）；
   - AgentDojo 攻击成功率最低降至 **2.95%**（Qwen3-14B，同时 Utility 最高），实现效用—安全双赢（Pareto 改进）；
   - 平均步数相对无记忆基线减少最多 **6.6%**，说明提升不依赖更长轨迹。
5. **组件互补性明确**：边界提示主导单轮函数选择提升（Prompt-BASM 在 BFCL 接近完整 BASM）；运行时修复在无边界提示时反而有害（Repair-Only 在 AppWorld 低于 Base），须与边界提示配合才有效；规避规则和恢复说明在安全敏感场景不可或缺（移除后 ASR 分别升至 6.95 与 6.85，Utility 降至约 31）。
6. **机制层面的精细发现**：头部级注意力分析显示边界读取集中在特定注意力头（如中间层与后层若干头），而非均匀分布，支持“状态条件化调制器”的解读。

## 7. 优点

- **问题发现新颖且具普遍性**：主动质疑“成功蒸馏 → 正迁移”的默认假设，并用机制级证据证明其可能反向伤害，对自进化智能体领域有方法论警醒价值。
- **机制分析深度突出**：从宏观行为（任务成功率）到微观机制（注意力系数、logit 差值、knockout 干预）形成完整证据链，远超常见“只报分数差”的方法论文。
- **方法与机制严格对齐**：设计的每个组件（边界字段的四个槽、选择性暴露、边界检查器、修复循环）都能在探测实验中找到对应证据，设计决策可溯源。
- **研究范围兼顾性能与安全**：不只关注任务成功率，还系统分析提示注入下的安全表现，并展示了“效用和安全可同时改进”的非平凡结果。
- **实验控制严谨**：等长 token 对照、同提示 knockout、任务不相交线性探针等控制手段排除了多种琐碎替代解释，增加结论可信度。
- **消融设计能分离贡献**：Prompt-BASM vs. Repair-Only 清晰地揭示了“提示引导”与“运行时控制”在不同任务类型上的各自角色。
