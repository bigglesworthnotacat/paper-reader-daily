## 摘要
使用工具的LLM智能体将安全风险从生成的文本扩展到影响外部系统的动作。在多轮分解攻击下，有害目标可以分布在个体看似合理的请求和工具调用中，只有从累积的轨迹中才能显现。现有的防御要么依赖辅助在线推理来恢复长视野安全证据，要么在生成后评估动作，这通常会增加推理成本或依赖于运行时的特定动作表示。我们提出了重组分布式风险（ReDiR），一种生成时防御方法，它根据轨迹级安全证据来条件化动作生成。在每个动作之前，ReDiR将当前轨迹压缩为紧凑的潜在安全表示，并将其注入冻结的基础模型。该表示通过同模型、跨视图监督学习，其中显式任务视图中的安全行为为从原始多轮轨迹中恢复分布式安全证据提供监督。这种设计使ReDiR能够直接在生成过程中整合跨轮安全信息，而无需依赖单独的动作级安全模块。我们在三个模型家族和八个保留工具域上的两个智能体安全基准上评估了ReDiR。ReDiR将攻击成功率降低到8%以下，可迁移到未见过的工具域，并在低计算开销下保持良性保真度。

## Abstract
Tool-using LLM agents extend security risks beyond generated text to actions that affect external systems. Under multi-turn decomposition attacks, a harmful objective can be distributed across individually plausible requests and tool calls, becoming apparent only from the accumulated trajectory. Existing defenses either rely on auxiliary online reasoning to recover long-horizon security evidence or assess actions after generation, often incurring additional inference cost or depending on runtime-specific action representations.   We propose \emph{Reassembling Distributed Risk} (ReDiR), a generation-time defense that conditions action generation on trajectory-level security evidence. Before each action, ReDiR compresses the current trajectory into a compact latent safety representation and injects it into the frozen base model. The representation is learned through same-model, cross-view supervision, where safe behavior from an explicit task view provides supervision for recovering distributed safety evidence from the original multi-turn trajectory. This design enables ReDiR to integrate cross-turn security information directly within the generation process without relying on a separate action-level safety module. We evaluate ReDiR on two agent-safety benchmarks across three model families and eight held-out tool domains. ReDiR reduces attack success rates to below 8\%, transfers to unseen tool domains, and preserves benign fidelity with low computational overhead.

## 1. 核心问题与研究动机

### 背景
- 工具型 LLM 智能体（tool-using LLM agents）将安全风险从"生成的文本"扩展到"对外部系统产生实际影响的动作"。
- 多智能体应用普遍采用多轮执行范式，使得攻击者可以将一个有害目标**分解**到多个单独看似合理的用户请求与工具调用中，风险只有在完整轨迹中才能显现。
  - 示例：第一轮让模型创建返回 `"rm -rf"` 的辅助函数，第二轮让创建返回 `"/"` 的函数，最后一轮才让组合两者并调用 `os.system`，最终执行 `rm -rf /`。仅检查任何单独一步都无法识别风险。

### 现有防御的不足
- **生成后检查（post-generation checking）**：在动作生成后再评估安全性，需要解析运行时特定的工具 schema 和参数格式，难以跨框架迁移，且引入额外在线推理步骤。
- **轨迹感知防御**（如 MAGE、TRACE）：依赖辅助在线推理恢复长视野安全证据，但将轨迹推理与动作生成分离，需要额外的安全组件或在线评判器，推理成本高。
- **表示级防御**（如 JBShield）：能操纵有害概念表示，但未直接解决轨迹条件下动作生成问题。

## 2. 方法论：ReDiR

### 核心思想
在**每次动作生成之前**，将当前多轮轨迹前缀压缩为一个**紧凑的潜在安全表示（latent safety representation）**，注入冻结的基础模型，使累积的跨轮安全证据直接塑造下一步动作的生成——无需依赖特定工具 schema 或动作格式，也无需独立的后置安全模块。

### 三个关键阶段

**阶段一：离线动作监督构建（Offline Action Supervision Construction）**
- 从规范性对抗任务规范 dⱼ 出发，将有害目标分解为多轮良性请求序列，用基础模型执行得到完整轨迹，提取"最终轮用户输入之后、模型响应之前"的轨迹前缀 cᵢ。
- 丢弃已有害结果的前缀（无法挽回），构建轨迹-任务配对集合 C = {(cᵢ, dᵢ)}。
- 通过**同模型跨视图（same-model, cross-view）**策略生成监督目标：将任务规范折叠成显式视图 vᵢ = Collapse(dᵢ; Iᵢ, Tᵢ)，从同一基础模型采样 M 个候选动作，经结构过滤与语义审计，保留安全、可执行且终止有害目标执行的协议有效动作作为监督目标 ỹᵢ。
- 根据学生视图输出与目标差距进行**监督路由（routing）**：已安全 → NONE；决策正确但终止表达无效 → TERMINATE（只监督终止部分）；决策错误 → FULL（全量监督）。

**阶段二：轨迹条件安全训练（Trajectory-Conditioned Safety Training）**
- 安全编码器与基础模型共享同一骨干，以 LoRA（秩 16，α=32，仅最后一层注意力块）和 K 个可学习潜在查询（K=8）适配。
- 将轨迹嵌入序列与潜在查询拼接，编码器输出固定大小的轨迹级安全表示 H_Qᵢ ∈ R^{K×d}。
- 注入前做**归一化重缩放**：将隐状态缩放到与基础模型 token 嵌入的典型量级（以中位数 m_θ 为基准），避免幅度失配。
- 动作接地目标：在路由指定位置 Sᵢ 上做加权 token 级交叉熵损失，入口 token（前 E=16 个推理 token，权重 w_E=4）与决策 token（FINISH 动作名，权重 w_D=4）额外加权。
- **良性行为保持**：对良性轨迹，用 KL 散度正则化潜在条件模型与原始基础模型分布，控制参数 λ_B=3。

**阶段三：潜在引导动作生成（Latent-Guided Action Generation）**
- 推理时每一步重新编码轨迹前缀，获得 Z_t 注入基础模型；LoRA 编码后进行生成（仅一份模型副本驻留内存），生成完成后由运行时按其协议解释为可执行动作。
- 在线仅增加一次编码器前向；安全表示不出现为可见 token，也不写入交互历史。

## 3. 实验设计

### 基准与数据集
- **MT-AgentRisk**（主基准）：365 个任务，8 个攻击子类（Addition/Decomposition × Data Files/Environment States），覆盖 Filesystem、Terminal、PostgreSQL、Notion 及 5 个 Playwright 网页环境。
  - 监督只用 55/70 个 Filesystem 任务；15 个 Filesystem 任务留作域内评估；其余 8 个域共 295 个任务全部保留用于跨工具迁移评估。
- **AgentDojo**（补充基准）：间接提示注入（不可信工具观测），作为分布外鲁棒性测试。
- 智能体框架：MT-AgentRisk 用 OpenHands（FINISH 作为安全终止动作）；AgentDojo 用其原生 pipeline。

### 对比方法
- **Base**（未修改智能体）
- **MAGE**：基于影子记忆的轨迹感知在线防御，辅助策略模型用 Qwen3.5-4B
- **ToolShield**：训练无关的自探索防御，通过执行安全测试用例构建安全经验
- 所有防御的适配均限制在同一 55 任务 Filesystem 子集。

### 评估模型
Qwen3.5-9B、Ministral-3-8B-Instruct、Gemma-4-E4B 三个模型家族。

### 指标
- ASR（攻击成功率，是否最终完成有害目标）
- SSR（安全停止率，是否发出有效终止动作）
- 良性 FPR（良性任务上的不必要拒绝率）
- 额外 GPU 内存、每动作延迟、端到端延迟、离线训练成本（GPU 小时）

## 6. 主要结论与发现

- **有效性**：ReDiR 将 MT-AgentRisk 整体 ASR 降至 **0.0–7.9%**（基础模型 48.2–65.8%，最强基线 MAGE 20.3–34.2%）；SSR 达 82.7–98.6%。在 Ministeral-3-8B 上四个攻击构造全部归零。
- **迁移性**：8 个未见工具域上 ASR 保持 0.0–6.8%，与源域 Filesystem 性能差距最大仅 6.1 个百分点。
- **保真度**：4 个良性任务域上 FPR 均为 0.0%，不引入过度拒绝（MAGE 在 PostgreSQL/Terminal 上分别升至 30%/20%）。
- **效率**：额外内存仅数 MiB；有害任务端到端延迟平均降低 53.3%（Ministral 上从 40.1s 降至 4.4s，降幅约 89%）。
- **AgentDojo**：达到次低 ASR 且基本不损失良性效用；MAGE 虽 ASR 更低但严重牺牲了良性 utility。
- **兼容性是关键**：骨干匹配（同模型编码器）和同模型教师生成的监督目标均优于更大/更强的替代（4B 编码器即使 K=32 仍不及 9B 的 K=8；Kimi-K2.5 教师 ASR 达 36.7% vs 同模型 0.0%）。
- **超参行为**：K≥8 才能零 ASR；入口 token 加权（16×4）同时影响安全与保真；决策权重 ×4 最优，过强（×8）反而退化。
- **自适应鲁棒性**：良性历史稀释攻击不造成系统性安全退化（整体 ASR 保持在 6.7–10.0%）。

## 7. 优点

- **概念创新**：首次将"轨迹条件表示"作为多轮智能体安全的核心抽象，将分布式安全证据直接与动作生成在潜在空间相连，弥合了轨迹推理与动作生成之间的鸿沟。
- **生成时防御**：在动作产出前即施加安全控制，不依赖外部在线评判器或动作重执行，避开运行时表示依赖。
- **极致轻量**：与共享骨干的 LoRA + 8 个潜在查询设计，额外内存仅数 MiB；训练数据需求极小（约几十个样本）。
- **强迁移性**：单一源域监督即可泛化到 8 个未见工具域，跨模型家族一致有效。
- **严格评估**：同时报告 ASR 与 SSR（互补而非互补关系），避免执行失败/超时对安全评估的混淆；对生成后检查、骨干失配、教师不兼容等失败模式有深入分析。
- **自适应攻击考量**：主动评估了良性历史稀释攻击并验证鲁棒性。

## 8. 不足与局限

- **经验性防御**：论文自身承认 ReDiR 是经验性防御，可能漏掉未见过的攻击、可能中断良性任务、可能激发自适应绕过；应配合最小权限、沙箱化和执行监控使用。
- **骨干匹配约束**：编码器与策略模型需共享骨干才能取得最佳效果（4B 编码器即使增加潜在容量也难完全弥补），限制了部署灵活性。
- **AgentDojo 上的表现并非最优**：ASR 高于 MAGE（虽然 MAGE 以大幅牺牲良性 utility 为代价），提示其针对提示注入类威胁的有效性弱于对多轮分解攻击的有效性。
- **数据构建依赖外部审计**：监督目标需借助 GPT-4.1-mini 语义审计，引入对第三方模型的依赖，且审计潜在噪声可能影响监督质量。
- **隐私与伦理风险**：攻击变换与防御感知评估具有双重用途，论文表示省略了不必要的操作细节，但未提及完整防护措施如何落地。
- **长期多轮行为的监督不足**：训练监督仅从"最终轮"前缀构建，推理时每一步都注入表示，但训练分布与在线逐步应用之间存在差距（论文未深入研究这种分布偏移）。
- **计算资源报告不完整**：仅说明 GPU 型号（A100）与 GPU 小时数，未给出 GPU 数量、训练 epoch/迭代次数等细节。
