## 摘要
大型语言模型代理正日益被部署为自主循环。从一个人类目标开始，这样的系统反复发现工作、规划、执行工具调用、验证结果，并在多次无人值守的迭代中持久化状态。然而，广泛使用的代理安全防护是针对单条轨迹定义的，当下一轨迹开始时，其安全状态会重新初始化。我们表明，这是一个组合性失败，而非实现细节。我们的核心结果是分离性：对于一种证据分散在多次迭代中的攻击，每个轨迹级监控器的真阳性率等于其假阳性率，无论其表达力如何，因为它需要的证据永远不会出现在它看到的窗口中，而保留跨迭代状态的监控器则能完美区分两者。我们进一步表明，携带几何衰减风险评分的明显修复是不够的，因为耐心对手必须等待的冷却期是一个不随视野$N$增长的常数。然后我们提出LoopHarness，它在循环级别恢复持久、非衰减的安全状态。在调解提交和仲裁者检测下限$δ_M$下，它将未经授权的不可逆动作的期望数量限制为$B+m-1+m/δ_M$，这是$N$中的常数，其中$B+m-1$项由无模型规则决定，因此在完全串通的验证者下依然有效。我们给出了一个完整的评估协议，包括在原生Agent-SafetyBench任务上的配对干净和攻击情节、一个仅存在于跨迭代中的决定性证据的外层状态攻击套件、逐模块消融，以及自适应白盒红队。

## Abstract
Large language model agents are increasingly deployed as autonomous loops. Starting from one human goal, such a system repeatedly discovers work, plans, executes tool calls, verifies outcomes and persists state across many unattended iterations. The agent safeguards in wide use, however, are defined over a single trajectory, and their safety state is re-initialized when the next trajectory begins. We show that this is a failure of composition rather than an implementation detail. Our central result is a separation: against an attack whose evidence is fragmented across several iterations, every trajectory-scoped monitor has a true-positive rate equal to its false-positive rate, however expressive it is, because the evidence it would need never appears in the window it sees, whereas a monitor retaining cross-iteration state separates the two perfectly. We further show that the obvious repair of carrying a geometrically decaying risk score is insufficient, because the cooling-off period a patient adversary must wait is a constant that does not grow with the horizon $N$. We then present LoopHarness, which restores a persistent, non-decaying safety state at the loop level. Under mediated commits and an arbiter detection floor $δ_M$, it bounds the expected number of unauthorized irreversible actions by $B+m-1+m/δ_M$, a constant in $N$, of which the $B+m-1$ term is decided by a model-free rule and therefore survives a fully colluding verifier. We give a complete evaluation protocol on native Agent-SafetyBench tasks with paired clean and attacked episodes, an outer-state attack suite whose decisive evidence exists only across iterations, per-module ablations, and an adaptive white-box red team.

### 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：大语言模型（LLM）代理正从单轮工具调用转向**自主循环执行**（autonomous loops）。系统从一个人工目标出发，持续发现工作、规划、执行工具调用、验证结果，并在多次无人值守的迭代中持久化状态（如记忆库、任务台账、累积上下文）。典型应用场景包括软件维护、运维、研究辅助和后台金融。

- **核心问题**：现有广泛使用的智能体安全防护机制（输入净化、逐调用分类、权限上限、能力令牌、轨迹内回滚等）都是**针对单条轨迹（trajectory）定义的**，即安全状态在每次新轨迹开始时被**重新初始化（per-trajectory reset）**。作者指出这是一个**组合性失败（failure of composition）**，而非简单的实现缺陷。

- **核心不对称性**：防御者的安全状态按构造在每个轨迹处重置，而攻击者的进度恰恰持续累积在循环所维护的持久通道（记忆、知识库）中。一个残余的逐迭代攻击成功概率ε会被循环放大为1−(1−ε)ᵀ，导致声称95%有效的一次性防御在14次迭代后失效概率超过50%。

- **关键理论结果**：针对一种**证据碎片化（s-fragmented）**的攻击（证据分散在多次迭代中），任何轨迹级监控器都无法有效检测——其真阳性率（TPR）等于假阳性率（FPR）。此外，简单地在会话级别携带几何衰减的风险分数也无法修复该问题，因为对手所需的冷却期是**不随视野N增长的常数**。

### 2. 方法论：核心思想、技术细节与关键公式

#### 2.1 核心思想

**LoopHarness** 是一个循环级防御框架，包裹任意内部轨迹级防御（inner harness），通过维护**持久、非衰减的循环级安全状态**来修复组合性失败。核心设计原则是：将**攻击证据、动作影响和验证者不确定性作为独立信号**处理，只有基于grounded的攻击证据才进入持久风险值，只有规则可判定的循环结构标志才能闩锁（latch）其折扣因子。

#### 2.2 五大持久组件

| 组件 | 功能 |
|------|------|
| **IPM**（Intake and Provenance Monitor） | 唯一的入口监控器，六项准入条件：作用域合规、信任级与通道匹配、非被拒工作重回（除非有新授权）、授权原子性、跨情节血统可委派性、无注入/升级模式 |
| **XRC**（Cross-Iteration Risk Cumulant） | 跨迭代风险累积器，核心更新公式见下 |
| **MIG**（Memory-Integrity Guard） | 基于HMAC哈希链的追加式记忆完整性保护，包含单调信任写门、再水合验证、受限召回策略 |
| **ASA**（Adversarially Robust Stopping Arbiter） | 三层证据仲裁：确定性门（无模型调用）、去相关检查器（每次迭代至多一次模型调用）、窗口化分歧统计量 |
| **CRG**（Compounding-Risk Governor） | 风险调控器：硬预算B（风险计数提交）、B_adv（高级验证调用）、五级能力上限阶梯函数、任务合约执行、强制停止与升级 |

#### 2.3 核心公式

**XRC 更新规则**（关键创新）：

> Ξᵢ = max( rᵢ, γᵢ·Ξᵢ₋₁ )
> 
> γᵢ = 1（若截至第i次迭代有任一结构标志触发，即“闩锁”）
> 
> γᵢ = γ↓ ∈ (0,1)（否则，即“衰减”）

**定理5（主要保证）**：在假定A1（有中介的有界提交，最多m次提交）、A2（仲裁检测下限δ_M）、A3（单调提交计数器）下：
- 合约可见的未授权提交：U^vis ≤ B + m − 1（确定性上界，无需任何模型调用）
- 合约不可见的未授权提交：E[U^inv] ≤ m/δ_M（概率上界）
- 总期望：**E[U₁:N] ≤ B + m − 1 + m/δ_M**——这是一个**与N无关的常数**

**命题2（分离性）**：对任意s≥2的s-碎片化攻击和任意轨迹级监控器M，攻击迭代上的报警概率等于良性迭代上的报警概率，TPR = FPR。而读取跨迭代状态并在碎片共同实例化能力时报警的监控器可达到TPR=1、FPR=0。

**命题3（冷却期击败几何衰减）**：带固定折扣γ、无闩锁的累积器在证据ρ后经k*次迭代重新开放门控，其中k* = ⌊log(ρ/θ)/log(1/γ)⌋ + 1，这是**不依赖于N的常数**。

**命题6（模型无关组件）**：授权代理是通过记录轨迹字段的规则计算的，不涉及模型输出，因此B+m−1项即使验证者完全串通（合谋）也成立。

#### 2.4 算法流程（循环级）

每次迭代按固定阶段顺序执行：**阶段0**（MIG再水合验证）→ **阶段1-2**（IPM准入+CRG门控）→ **阶段3**（在能力上限下执行内部L1-L4防御）→ **阶段4**（ASA仲裁）→ **阶段5**（MIG持久化接受结果）→ **阶段6**（XRC更新+CRG决策继续/停止）。

### 6. 主要结论与发现

1. **轨迹级监控存在根本性盲区**：任何轨迹级监控器对碎片化攻击的TPR = FPR，无论其表达力多强（命题2）。
2. **几何衰减不够**：冷却期是常数（命题3），耐心的对手只需等待固定次数即可重新打开门控，衰减并未从根本上解决跨迭代安全问题。
3. **LoopHarness有效**：B4将Track B的总体攻击成功率降至0.1%（B0-B3为88.4%-97.6%），同时维持96.9%的CleanGC。
4. **持久非衰减状态是核心**：如表3所示，XRC-latch在所有间隔（d=1,2,4）下保持0% ASR，而XRC-off和XRC-decay在较长间隔下分别达到95.5-97.5%和97.0% ASR。
5. **确定性上界稳健**：B+m−1项不依赖模型，即使验证者完全合谋也成立（A-collude总体ASR仍为0.1%）。
6. **各组件缺一不可**：消融任一组件会使对应攻击家族的ASR恢复至96.0-97.5%（表4）。
7. **存在依赖关系**：移除CRG使A14的ASR从0.0%上升至97.0%，表明XRC状态保留与CRG执行之间存在依赖——这一点超出了预先指定的预测。

### 7. 优点

- **理论贡献清晰且有力**：通过分离性定理（Proposition 2）证明了轨迹级监控的固有局限，而非仅仅给出一个经验失败案例；几何衰减的冷却期常数性（Proposition 3）直击常见修复方案的痛处。
- **设计原则明确**：将攻击证据、动作影响和验证者不确定性分离，防止普通高影响工作或模型不确定性错误地劣化后续迭代。
- **保证的明确分工**：确定性部分（B+m−1）不依赖任何模型调用，可抵御完全串通的验证者；概率部分由仲裁检测下限δ_M控制——这种责任划分使保证在对抗性条件下更稳健。
- **评估协议严谨**：配对清理/攻击孪生、外部状态攻击套件、组件消融、自适应白盒红队、开发/tuning分离、同情节配对bootstrap统计分析。
- **模块化与可组合性**：LoopHarness位于内部轨迹级防御之外，可与任何内部防御组合使用，避免重复实现。
- **认识到了自身限制**：例如明确说明有限网格“探测但未建立”（A2）假设，以及闩锁需要明确的认证清除过渡。

### 8. 不足与局限

- **实证输入有限**：检测下限δ_M是唯一经验输入（A2），但在有限网格上探测未得到建立；且红队缓解率是以**挂载尝试**为条件的，并非对δ_M的直接估计。
- **XRC闩锁缺乏恢复机制**：一旦结构标志触发，门控永远不重新打开，无认证清除过渡；这可能导致可用性失败（表5显示闩锁攻击后0% FullGC），作者明确承认这不是安全的重新开放策略。
- **单模型角色分配的泛化问题**：未进行多模型、多种子复制，结果可能存在模型特定偏差。
- **上升路径依赖**：作者承认“一个停止并升级的系统只有其升级路径同样安全才安全”——如果没有配置人工升级通道，安全机制可能变成可用性故障。
- **基准覆盖限制**：综述中讨论了Agent-SafetyBench等基准可能未考虑跨迭代攻击；本工作基于单一基准。
- **外部状态条件有限**：在部署中，发现馈送是竞争的（contested），而测试中的馈送是预定队列，这低估了IPM在真实环境中面临的准入问题。
- **不覆盖多智能体循环**：将状态扩展到多智能体循环留给了未来工作（委派子代理的重置实体）。
- **有效性与安全性的平衡**：A-collude下CleanGC下降至92.9%，表明去相关检查器的冲突与效用存在张力。

### 9. 未来扩展（论文提出）

- 加强检测下限δ_M，即边界中唯一的经验输入。
- 将相同的状态携带到多智能体循环中，其中重置实体是委派的子代理。
- 设计明确的、经过认证的、作用域特定的清除过渡（clearance transition），以避免仅凭时间流逝释放门控。
