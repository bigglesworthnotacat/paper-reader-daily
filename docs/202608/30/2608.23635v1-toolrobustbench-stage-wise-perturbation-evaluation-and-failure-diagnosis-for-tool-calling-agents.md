## 摘要
大型语言模型（LLM）依赖工具调用作为基本智能体能力，使其能够调用外部系统并完成超出文本生成的任务。然而，干净的端到端（E2E）成功无法识别工具使用故障源自何处或如何在调用中传播。我们引入ToolRobustBench，一个用于工具调用代理的分阶段诊断基准，其中工具调用代理是一个LLM系统，它选择工具、提供结构化参数并解释其返回的反馈。ToolRobustBench将四个扰动家族与工具使用流程对齐：工具接口、用户意图、工具输出/观察和运行时环境扰动。它将故障归因于工具选择、模式基础、参数绑定、工具输出/运行时反馈处理以及端到端任务成功。在7个模型、16个抽样本地工具、4个扰动家族和14个子类型的15,456个单家族实例上的实验显示，干净性能高但不统一，且鲁棒性显著下降，其中工具输出/观察扰动是主要瓶颈。混合家族实验揭示了非加性故障模式，这些无法由孤立的单家族结果解释。因此，ToolRobustBench提供了一个确定性的、级联感知的基准，用于诊断超越干净工具调用准确性的鲁棒性；

## Abstract
Large language models (LLMs) rely on tool calling as a fundamental agent capability, enabling them to invoke external systems and complete tasks beyond text generation. However, clean end-to-end (E2E) success cannot identify where a tool-use failure originates or how it propagates through a call. We introduce ToolRobustBench, a stage-wise diagnostic benchmark for tool-calling agents, where a tool-calling agent is an LLM system that selects a tool, supplies structured arguments, and interprets its returned feedback. ToolRobustBench aligns four perturbation families with the tool-use pipeline: tool-interface, user-intent, tool-output/observation, and runtime-environment perturbations. It attributes failures to tool selection, schema grounding, argument binding, tool-output/runtime-feedback handling, and E2E task success. Experiments on 15,456 single-family instances across 7 models, 16 sampled local tools, 4 perturbation families, and 14 subtypes show high but non-uniform clean performance and substantial robustness degradation, with tool-output/observation perturbation the dominant bottleneck. Mixed-family experiments reveal non-additive failure patterns that are not explained by isolated single-family results. Thus, ToolRobustBench provides a deterministic and cascade-aware benchmark for diagnosing robustness beyond clean tool-calling accuracy;

# ToolRobustBench 论文总结

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：大型语言模型（LLM）的工具调用能力是智能体与外部系统交互的关键机制，但现有评估仅关注干净环境下的端到端（E2E）成功率，**无法定位故障究竟源自哪个环节，也无法判断错误如何在调用链中传播**。
- **关键矛盾**：一个最终表现为"参数错误"的失败，可能是参数绑定阶段直接出错，也可能是更早的工具选择阶段因接口混乱而选错工具后引发的下游症状；一个"运行时失败"表象可能源于上游参数被破坏，而非执行环境本身的问题。仅记录最终失败标签会混淆此类因果关系。
- **研究意义**：ToolRobustBench 提出了一个**阶段对齐、级联感知、确定性可复现**的基准，不仅回答"模型在噪声下是否成功"，还回答"行为在哪一阶段首先偏离、错误如何传播"。其整体含义是：工具调用评估应从单一准确率指标转向过程级故障定位与归因诊断。

## 2. 论文提出的方法论

### 2.1 核心思想
将一个工具调用过程分解为**五个诊断能力轴（S1–S5）**，并将**四类扰动族**精确对齐到工具调用管线的不同入口点，通过**确定性回溯程序**将最终失败症状归因到最早的上游根源阶段，而非仅记录表面症状。

### 2.2 五个诊断轴
| 轴 | 能力 | 典型失败 |
|---|---|---|
| S1 | 工具选择 | 不调用、工具误选 |
| S2 | Schema 接地 | 工具误选、格式违规 |
| S3 | 参数绑定 | 参数缺失、参数错误 |
| S4 | 输出/运行时反馈处理 | 参数错误、格式违规、运行时失败 |
| S5 | 端到端任务成功 | 所有失败标签 |

### 2.3 四类阶段对齐扰动族
- **A 工具接口扰动**：工具名称表面替换、描述抽象化、兄弟工具混淆性（3 个子类型 A1–A3）；
- **B 用户意图扰动**：间接表达、欠指定、干扰上下文、内部冲突（4 个子类型 B1–B4）；
- **C 工具输出/观察扰动**：返回结构噪声、证据缺失、证据损坏、证据竞争（4 个子类型 C1–C4）；
- **D 运行时环境扰动**：可用性失败、运行变异性、反馈质量（3 个子类型 D1–D3）。

### 2.4 级联感知错误归因
- 每条记录保存**六个诊断字段**：观测错误标签、主错误标签、最早失败阶段、错误来源阶段、级联指示器、边界违规指示器。
- 归因由**确定性回溯算法**完成，无 LLM 裁判参与：先用固定优先级顺序得出观测错误标签，再将其与扰动族预期的原始失败及允许的下游溢出比较；若观测标签属于允许溢出，则回溯到最早的兼容阶段作为主来源。
- **级联**指最终下游症状与回溯得到的主来源不一致；**边界违规**指归因来源超出该扰动族预期的阶段边界。

### 2.5 指标公式
- `Clean(m) = Succ_m(D_clean)`：干净集成功率
- `Robust_f(m) = (1/3) Σ_z Succ_m(D_f,z)`：家族 f 在轻/中/重三档上的平均鲁棒性
- `Overall(m) = (1/4) Σ_f Robust_f(m)`：总体评分
- `Drop_f(m) = Clean(m) − Robust_f(m)`：鲁棒性下降量
- `CR_f`（级联率）与 `BVR_f`（边界违规率）：在失败实例上统计
- `Δ(m,p,z) = M − W`：混合家庭成功率与较弱构成家族成功率的差值，用于衡量非线性交互

2. **工具输出/观察扰动是主要瓶颈**：家族 C 平均鲁棒性仅 0.455，所有模型均 <0.60；接口扰动最轻（0.918），意图（0.773）和运行时（0.688）居中。
3. **证据缺失与竞争最难**：C2 证据缺失是最难子类型（0.142），C1 结构噪声（0.460）和 D2 运行变异性（0.469）次之；A 族两个子类型最高（约 0.93）。
4. **严重度非线性**：从干净到轻/中/重三档，平均成功率从 0.979 → 0.869 → 0.724 → 0.491；但部分情况下更明确的失败信号反而使分类更易。
5. **级联归因有效且必要**：D 族级联率最高（0.638），A 族中等（0.352），C 族几乎直接失败（0.003）；运行时环境的最终症状常源于上游选择/参数错误。反事实分析表明修复归因的主错误阶段可恢复 72.4% 的失败实例。
6. **后执行诊断不平衡**：模型识别显式运行时标签（retryability 0.949、failure type 0.917）远好于从混合反馈恢复最终结果（result 0.738）。
7. **混合扰动呈非线性失败模式**：混合家族成功率（中档 0.448）显著低于较弱构成家族（0.621）和两者均值（0.754），负交互最强的组合为 A3+C4 与 B4+C4；不能以单一构成家族的最差值来近似混合难度。
8. **诊断标签可指导干预**：S3 参数绑定提示无法修复 S1 根源的 B 族失败（21/30→21/30），而 S1 接口别名澄清可有效修复 A 族误选（21/30→30/30）。

## 7. 优点

- **阶段对齐的扰动分类学**：首次将四类扰动精确对齐到工具调用管线四个独立入口点，使每个扰动的影响边界清晰，避免评估信号在管线中"串扰"。
- **级联感知的错误归因**：将观测症状与根源分离，六字段诊断体系可区分下游症状与上游原因，且归因过程完全确定性、无 LLM 裁判，可复现性强。
- **确定性可复现的数据构造**：不使用外部基准或实时 API，全部由本地确定性工具环境和固定模板生成，金标、扰动、归因标签均可审计，避免实时 API 波动。
- **多维度有效性验证**：C2 可恢复性审计（人类 YES+PARTIAL 率 68.3% vs 最好模型成功率 27.8%）、反事实归因（72.4% 修复率）、定向干预（拒绝错误干预、接受有效干预）和 140 条人类审计共同支撑诊断标签的因果有效性。
- **混合家族设计揭示非线性交互**：明确展示组合扰动不能由单一构成家族"取最弱"来近似，为真实部署场景的评估提供了更贴近实际的参考。
- **透明证据链**：附证据表（Table 15）逐一映射数据来源与结论，便于复现和审计。

## 8. 不足与局限

- **受控环境局限**：40 个本地确定性工具不能完全代表生产 API 生态的复杂性（认证、速率限制、状态副作用、厂商特有错误语义、长期依赖等），绝对成功率、精确级联率和 D 族运行时结论可能不直接迁移到真实部署。
- **混合家族覆盖有限**：仅详述 5 对代表性组合而非穷尽所有成对模板：C-D 组合因逻辑不相容（C 假定存在可污染的观测，而 D 可能替换为错误反馈）被排除，部分全零组合无比较意义；完整 gpt-5.4-mini 矩阵仅存于附录。
- **单步任务限定**：任务只有"在执行/观察后恢复"的单回合完整过程，不测试长期规划、持久状态或多工具依赖链。
- **人类验证样本偏差**：140 条审计样本按子类型分层且刻意包含大量重型失败案例，适合验证评分器行为，但**不等于**全基准困难实例率的无偏估计；协议允许"不清楚"保守判断并排除该类记录，降低了部分标签的有效样本量。
- **评分协议兼容性**：模型通过不同提供商或 OpenAI 兼容后端访问，协议兼容性是残余变异来源；虽然做了归一化和兼容性检查，但仍可能引入表面形式的系统差异。
- **严重度不保证单调性**：静态强度分数单调递增但模型准确率非单调，部分"重档"任务因失败信号更显式而更易分类，可能影响横向比较的直观解读。
