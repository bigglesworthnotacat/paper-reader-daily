## 摘要
具身智能体越来越多地被用于弥补端到端策略模型留下的差距。然而，智能体路径尚未在物理执行中实现闭环学习：现有的操控框架在很大程度上仍然是开环的，在 rollout 过程中遵循固定技能，并且只在回合结束后进行反思。这种事后反思无法在执行过程中进行实时调控，因为物理交互要求决策以超越当今大型智能体模型的频率来跟踪快速变化的机器人-环境状态。我们提出了 Zetta，一个闭环具身操控框架，它在保持基础策略冻结的同时，在线进化基于代码的运行时批评者和恢复技能。通过三个时间尺度分离的循环，Zetta 提供了动作频率治理、rollout 级别的批评者-恢复提案以及验证门控的技能更新。结合 Z-Infra（一种将智能体逻辑与异构执行资源解耦的 rollout 基础设施），Zetta 在我们当前的 rollout 预算下在 LIBERO-Pro 和 RoboCasa 上取得了最先进的成功率，分别达到 90.8% 和 93.6%，并实现了 11.1 倍的推理加速；成功率随着自我探索经验持续提升；学到的技能可以零样本迁移，并且出现了清晰的机器人“顿悟时刻”。这些结果表明，闭环操控框架的自我进化为可靠的物理智能开辟了一条扩展路径。

## Abstract
Embodied agents are increasingly used to close the gap left by end-to-end policy models. Yet the agentic path has not realized closed-loop learning in physical execution: existing harnesses remain largely open-loop, following fixed skills during rollout and reflecting only after an episode completes. Such post-hoc reflection cannot govern execution as it unfolds, because physical interaction requires decisions to track rapidly changing robot-environment states at a frequency beyond today's large agentic models. We present Zetta, a closed-loop embodied harness that evolves code-based runtime critics and recovery skills online while keeping the base policy frozen. Through three timescale-separated loops, Zetta provides action-frequency governance, rollout-level critic-recovery proposal, and validation-gated skill updates. Together with Z-Infra, a rollout infrastructure decoupling agent logic from heterogeneous execution resources, Zetta achieves state-of-the-art success on LIBERO-Pro and RoboCasa under our current rollout budget, reaching 90.8% and 93.6%, with an 11.1x inference speedup; success continues to scale with self-exploration experience; learned skills transfer zero-shot, and clear robotic "Aha Moments" emerge. These results show that closed-loop harness self-evolution opens a scaling path for reliable physical intelligence.

### 1. 核心问题与研究动机

- **背景**：具身智能（Embodied AI）正沿两条路径发展——①训练端到端策略模型（如 VLA、WAM），②利用 LLM 作为具身智能体来编排策略、代码、工具与控制基元。然而，两者均有明显短板。
- **核心缺陷：开环执行**。现有具身智能体 harness（操控框架/脚手架）在物理执行过程中基本是**开环**的：执行一旦开始，智能体不能持续根据机器人-环境状态的变化实时调整决策，而是遵循固定技能或预规划轨迹，仅在回合结束后进行事后反思。
- **开环后果**：事后反思无法干预执行过程，无法在失败时进行在线测试与验证；整个轨迹的信用分配困难；复盘缺乏失败瞬间的精确状态信息；经验难以复用。
- **技术瓶颈**：物理任务要求决策频率达到毫秒级，而当前大型智能体模型（LLM/VLM）无法在该延迟预算下进行实时决策——这是闭环执行长期未实现的根本原因。
- **研究目标**：提出一个**闭环**、**可自进化**的具身智能体 harness，使系统在保持基础策略冻结的前提下，通过环境反馈（自我探索经验）不断提升执行成功率，从而为物理智能的可靠扩展开辟新路径。

### 2. 方法论：Zetta 框架与 Z-Infra 基础设施

#### 2.1 核心思想

- **冻结基座、进化外围**：基础动作策略（VLA/WAM）内部参数保持完全不变（∇θ = 0），进化对象是 **harness H = {C, R, T}**，即：
  - **运行时评论家（Critic, C）**：高频监控函数，扫描轨迹并生成结构化失败提议 P_t = ⟨e_t,σ̂_t⟩，其中 e_t 是可审计的失败证据，σ̂_t 是建议的操作模式。
  - **恢复技能库（Recovery Playbook, R）**：映射特定因果失败机制的策略库。
  - **异构工具集（Toolset, T）**：可执行工具（如规划器、抓取检测器、恢复模块），可在进化中生成、实例化和精炼。

#### 2.2 三时间尺度分离的闭环进化架构

论文设计了三个时间尺度分离的循环：

1. **Loop 1——评论家治理的动作循环（在线）**：以动作频率运行，评论家持续监控执行状态，触发干预和恢复；Orchestrator Agent（固定多模态推理器）负责任何干预的裁决，保证证据驱动的决策。
2. **Loop 2——Rollout 批量的候选优化循环（离线）**：每个迭代批次结束后，对失败轨迹进行聚类与因果诊断，提出评论家/恢复技能的候选补丁。由于技能和代码不可微，借鉴 SkillOpt/EmbodiSkill 构建类似 SGD 的代码空间优化过程。
3. **Loop 3——验证门控的技能更新循环（离线）**：仅当候选评论家/恢复技能在 held-out 数据上提升成功率且可跨 rollout 泛化时，才将其加入技能记忆。

#### 2.3 关键阶段流程（Phase I-III）

- **Phase I——失败画像与基线建立**：
  - 在开发种子集上大规模采样纯 VLA 执行，建立基线。
  - 引入**首个缺失里程碑（First Missing Milestone, m\*）**，用于粗粒度失败聚类。
  - 区分基础设施失败和策略失败，只保留有效 rollout（valid traces）。
- **Phase II——故障聚类与因果诊断**：
  - 基于**最早可观测偏离点（EOD）** 对失败进行机制级聚类，选取 medoid seed 进行深度诊断。
  - 采用**严格单视角接地协议**，避免多视角幻觉。
  - **自顶向下层次化因果诊断**：按 Evaluation → Critic → State → Planning → Recovery → Parameter 优先级逐层排查，找到根因层 L\*，坚持"高层次逻辑能解决就不动低层参数"的**最小干预原则**。
- **Phase III——harness 整合与泛化验证**：
  - 将种子级补丁整合为统一的**版本化 harness 包**（H_merged），包含 SKILL.md、tools/、plans/、params/ 等结构化目录。
  - 通过**历史回归测试**（要求对原失败簇 100% 解决）和**严格隔离的 Held-out 评估**双重验证，确保真正的泛化而非过拟合。

#### 2.4 Z-Infra：具身智能体 Rollout 基础设施

- **核心问题**：资源异构性（模拟环境需 CPU/GPU 混合资源、策略模型需 GPU 推理、轻量感知模型与基础操作 QoS 各不相同）和执行动态性（工具调用序列不可预测、会话生命周期不规则）。
- **关键设计**：将智能体逻辑与硬件资源管理完全解耦，分三层：
  - **Control Plane**：统一 API 入口，负责请求路由、资源配额和故障处理。
  - **Environment Worker Layer**：会话抽象管理环境生命周期；资源共享组通过 ModelTemplate 编译一次、fork 多次的模式，在 MuJoCo 场景中实现多会话并行推进（C++ 高性能控制器 + GIL release）。
  - **Rollout Worker Layer**：GPU 驻留模型服务，实现连续批处理、动态调度；**模型分区**（将 VLA 的 VLM 和动作专家 AE 分离为独立进程，通过 CUDA IPC 传递中间激活，降低 53% 推理延迟）；模块级**量化插件**（W8A8 等，1.18-1.32 倍加速且不损成功率）。
- **编程模型**：Session/Episode/Step 三级抽象，API 支持跨会话透明批处理。

### 6. 主要结论与发现

- **最先进成功率**：在当前 rollout 预算下，Zetta 在 LIBERO-Pro 达 90.8%（Goal 套件综合 92.5%/89.0%，全 40 项平均 71.13%），RoboCasa 达 93.6%（相对纯 VLA 提升 20.00 个百分点），超越现有策略模型和具身智能体基线。
- **缩放性验证**：成功率随进化迭代持续提升——LIBERO-Pro Goal-T 从 31.0%→92.5%，Goal-S 从 38.0%→89.0%，RoboCasa 从 73.56%→93.56%，无需增加模型容量或调参。
- **零样本迁移**：所学技能（预抓取对准、再抓取、稳定放置、目标定位、碰撞感知接近、稳定接触等）可迁移到相关任务，RoboCasa PnP 迁移平均成功率提升 20 个百分点，铰接交互类提升 16 个百分点。
- **"顿悟时刻"涌现**：系统从停滞（症状级修复）到突破（识别根因物理瓶颈，如抓取保持力、接近几何）呈非连续性跳变，说明物理智能的可扩展单元是可复用的物理失败状态→恢复行为的映射。
- **基础设施高效**：Z-Infra 实现 35.1 episodes/min 有效吞吐（20.6 倍提升），推理延迟较 RPent 降低 91%（11.1 倍加速），且延迟增长在并发提升时保持亚线性。

### 7. 优点

1. **方法创新性**：首次实现执行期间闭环治理的自进化具身智能体，三时间尺度分离循环是清晰的系统设计贡献。
2. **保持基础策略冻结**：避免了重训 VLA 的高成本，通过外围 harness 进化提升通用能力，实际部署友好。
3. **"最小有效层干预"原则**：严格的层次化因果诊断避免低层参数过度修改导致的全局性能退化，保证泛化性。
4. **严格的验证协议**：历史回归 + held-out 双评估、动态数据重分类机制，科学严谨。
5. **工程落地完整**：Z-Infra 提供了面向异构资源的高吞吐 rollout 基础设施，解决系统级瓶颈，且模块级量化/模型分区等具体优化深入。
6. **实验系统性强**：覆盖缩放、迁移、顿悟时刻、基础设施效率等维度，并辅以详细的算法伪代码与故障案例（附录 C/D）支撑可复现性。

### 8. 不足与局限

1. **模拟环境局限**：全部结果基于 LIBERO-Pro/RoboCasa 仿真，未在真实机器人上验证 sim-to-real 迁移能力——文中仅在展望中提及下一步计划。
2. **基础策略范围有限**：仅验证了 π0.5 和 GR00T N1.5 两种策略，对其他 VLA/WAM 架构（如 RT-2、OpenVLA）的兼容性未知。
3. **算力规模较小**：8 张 4090/8 张 A100 的规模相对有限，未展示更大集群的扩展曲线；GPU 资源饱和平台期已出现（并发 64 后吞吐不再增长）。
4. **进化人工成本未量化**：虽然自动化了诊断-修复-泛化流程，但每轮进化所需 LLM API 调用量、人工审查工作量等成本未报告。
5. **覆盖偏差风险**：LIBERO-10 (S) 设置中 4/10 任务未提升，说明对位置交换类扰动仍有显著局限；所选任务均是 Manipulation 类，未覆盖导航、移动操作等。
6. **缺少动态环境评估**：所有测试均为静态初始条件采样，未评估物体意外移动、传感器噪声等动态干扰下的鲁棒性。
7. **没有与端到端微调方法公平对比**：虽然声称"无需 VLA 训练"是优势，但未对比同等数据下微调 VLA 的性能基线。
