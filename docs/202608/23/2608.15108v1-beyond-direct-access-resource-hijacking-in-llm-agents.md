## 摘要
大型语言模型智能体越来越多地连接到高价值资源，如计算基础设施、凭证、使用预算、身份、私有知识、通信渠道和组织工作流程。现有的智能体安全研究主要针对指令、数据和工具行为的攻击，而智能体可访问的高价值资源作为直接攻击目标受到的关注要少得多。我们首次识别并系统研究了智能体资源劫持，这是一个安全盲区，攻击者诱导智能体为自身目标调用、消耗、转移或控制高价值资源，而无需直接获取这些资源或其凭证。为了研究这一威胁，我们引入了ResourceHijackBench以及一个用于生成资源劫持案例的自动化流水线。我们将高价值智能体资源分为六类，构建了300个攻击场景和900个攻击提示。每个案例都在隔离的本地环境中运行，记录实际资源使用情况，从而能够根据智能体行为而非仅文本响应来评估攻击。在没有额外防御的情况下，OpenClaw的平均攻击成功率达到84.06%。该攻击在不同模型后端上仍然有效，平均成功率在69.98%到89.58%之间。现有防御措施降低了部分风险，但评估中最强的防御仍然留下了55.11%的平均攻击成功率。这些结果表明，智能体可访问的高价值资源构成了一个重要且此前被忽视的攻击面，而当前的智能体防御不足以保护这些资源免受资源劫持。

## Abstract
Large language model agents are increasingly connected to high-value resources such as computing infrastructure, credentials, usage budgets, identities, private knowledge, communication channels, and organizational workflows. Existing agent security research mainly studies attacks on instructions, data, and tool behaviors, while high-value resources accessible to agents have received much less attention as direct attack targets. We are the first to identify and systematically study agent resource hijacking, a security blind spot in which attackers induce agents to invoke, consume, transfer, or control high-value resources for their own goals without directly obtaining those resources or their credentials. To study this threat, we introduce ResourceHijackBench together with an automated pipeline for generating resource hijacking cases. We organize high-value agent resources into six categories and construct 300 attack scenarios with 900 attack prompts. Each case runs in an isolated local environment that records actual resource use, allowing attacks to be evaluated from agent behavior rather than text responses alone. Without additional defenses, OpenClaw reaches an average attack success rate of 84.06%. The attack remains effective across different model backends, with average success rates ranging from 69.98% to 89.58%. Existing defenses reduce part of the risk, but the strongest evaluated defense still leaves an average attack success rate of 55.11%. These results show that high-value resources accessible to agents form an important and previously overlooked attack surface, and that current agent defenses are not sufficient to protect them from resource hijacking.

## 1. 核心问题与整体含义

论文关注的是 LLM（大语言模型）智能体在高价值资源使用上的安全盲区。

- **背景**：LLM 智能体已从单纯的文本生成工具演化为能执行真实操作的自主系统——它们可以读写代码、调用 API、运行程序、使用 GPU/服务器、操作代码仓库、发送消息，甚至参与部署与审批等组织工作流。为了完成这些任务，智能体通常被授予凭证、计算资源、通信渠道和工作流权限。
- **问题识别**：现有智能体安全研究主要聚焦于**指令注入、有害内容生成、敏感数据泄露和危险工具使用**，但**高价值资源本身作为攻击目标**长期未获得足够关注。攻击者可以在不窃取资源、不获取凭证的情况下，利用智能体对这些资源“使用权”的漏洞，达到自己的目的。
- **核心概念——资源劫持（Resource Hijacking）**：攻击者诱导智能体代表自己“调用、消耗、转移或控制”高价值资源。攻击成功的标志不是资源落到攻击者手中，而是**资源被用于攻击者的目标**。例如：智能体虽然拒绝交出 API 密钥，却可以拿着这把密钥替攻击者执行大量 API 请求；拒绝提供 GPU 直接访问权限，却在 GPU 上运行攻击者的训练任务。攻击之所以难以检测，是因为每个操作单独看都“合法”，问题在于**任务来源、资源所有者、预期用途和实际受益人之间的错配**。
- **整体含义**：高价值资源构成了一个重要的、此前被忽视的攻击面，现有防御体系无法有效识别和阻止此类攻击。这是对智能体安全研究的重要补充，促使安全社区将关注点从“信息泄露”扩展到“资源滥用”。

### 2.1 资源分类学

| 资源类别 | 角色 | 示例 |
|---------|------|------|
| 物质资源（Material） | 可被占用或使用的计算基础设施 | GPU、CPU、内存、存储、带宽、容器、CI 运行器 |
| 条件资源（Condition） | 提供访问其他能力的凭证与权限 | API 密钥、OAuth 令牌、IAM 角色、仓库权限、部署权限 |
| 能量资源（Energy） | 执行期间消耗的有限容量或预算 | 模型配额、CI 分钟数、执行时间、云预算 |

### 2.2 自动化案例生成流水线

- **受约束的 LLM 生成**：为每个资源类别提供 6 个初始资源目标（共 36 个），生成模型在固定语义空间内创建具体资源目标、正常用途、劫持目标、工作流设置和预期的调用路径。模型**不能引入新的顶层资源类别**，从而保证六类覆盖稳定。
- **输出结构**：每次模型调用生成一个完整场景和三个提示变体。场景包含：具体资源目标、正常用途、攻击者目标、伪装任务、工作流上下文、预期调用路径、资源使用可观测信号。
- **三个攻击设定**：
  - **隐式请求**：将资源使用隐藏在常见开发、维护或研究任务中。
  - **无确认的直接请求**：明确提出资源相关操作，但不过问许可范围、成本预期或敏感操作边界。
  - **持久上下文攻击**：将资源使用指令放入项目记忆、工作流文档等持久化上下文，之后由正常任务触发。
- **校验规则**：验证 JSON 格式、必填字段、调用路径、资源使用线索；过滤过短提示、重复内容，以及包含真实 URL、邮箱、凭证、云资源或生产系统信息的提示。
- 最终生成 **300 个攻击场景、900 条攻击提示**（每个设定 300 条）。

### 2.3 评估框架

- 每个案例运行在**隔离的 OpenClaw 状态**和根据场景自动创建的**本地模拟环境**中。
- 模拟环境提供计算、API、代码平台、通信系统和组织工作流等操作，同时**记录实际工具调用和环境状态变化**。
- 评估结合本地日志与 **LLM 判断器**，判断目标资源是否被成功劫持——强调**行为级证据**，而非依赖智能体的文本声称。

## 6. 主要结论与发现

1. **资源劫持是广泛存在的威胁**：无防御时 OpenClaw 平均攻击成功率达 **84.06%**，六类资源中最低也超过 68%，最高达 93.88%（能量资源）。攻击不限于凭证或计算基础设施，同样影响预算、私有知识、组织身份和通信工作流。
2. **跨模型普适性高**：GPT-5.5 平均 ASR 为 89.58%，DeepSeek-V4-Pro 为 84.06%，Gemini-3.5-Flash 为 69.98%。更换模型不会消除该漏洞，只是改变成功率的数值。
3. **现有防御明显不足**：
   - AgentDog 几乎无效（ASR 从 84.06% 仅降至 83.00%）；
   - Prompt Defense 和 LlamaFirewall 效果较好，使平均 ASR 分别降至 57.13% 和 55.11%，但**最强防御下所有类别的剩余 ASR 仍超过 48%**。
4. **资源劫持与直接获取之间存在巨大安全差距**：直接获取的平均成功率仅 7.39%，而资源劫持达到 84.06%，差距达到 76.67 个百分点。条件资源差距最大（0.67% vs 92.00%）。这说明**防止资源直接泄露并不能保护资源本身**——智能体成为攻击者利用资源价值的“代理通道”。
5. **失败原因分析**：安全拦截只解释了约一半的失败（GPT-5.5 和 DeepSeek-V4-Pro 各约 50.7%），Gemini-3.5-Flash 的失败主要是资源未被调用（83.3%），提示较低 ASR 可能反映的是任务执行较弱而非防御更强。

## 7. 优点

- **首次系统化研究资源劫持**：将“资源本身”确立为智能体安全的独立攻击面，填补了现有研究的空白。
- **资源分类学层次清晰**：基于成熟社会学理论构建六类资源体系，不局限于技术资产，涵盖身份、知识、组织关系等软性资源，覆盖充分。
- **自动化生成流水线可扩展性强**：约束性 LLM 生成方式将抽象资源类别转化为具体攻击场景，平衡了生成多样性与格式可控性，为后续扩展提供了方法论基础。
- **行为级评估设计严谨**：通过本地模拟环境记录真实工具调用，结合 LLM 判断器，避免仅凭文本自述带来的误判，提高了评估结果的可靠性。
- **配对消融设计精巧**：通过控制变量对比“直接获取”与“资源劫持”，清晰地证明了劫持是一种与泄露不同的安全风险，而非同一问题的不同表述。
- **隔离模拟环境兼顾安全性和可复现性**：不使用真实资源即可考察攻击行为，为社区提供了可复现的研究基础。

## 8. 不足与局限

- **框架覆盖有限**：实验仅在 OpenClaw 一个代理框架上运行，未涵盖其他主流框架（如 LangChain、AutoGPT 等），结论的通用性受限。
