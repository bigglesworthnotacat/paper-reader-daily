## 摘要
从经验中学习对于开发有能力的、自我改进的大语言模型（LLM）智能体至关重要。现有方法通常通过反思、记忆、规则或技能从累积的轨迹中提取知识。然而，真实环境中的智能体不断遇到新任务，而且往往只有一次改进机会。这些执行过程会产生丰富但高度嘈杂的上下文，将普遍有用的经验与特定任务的人为产物纠缠在一起。关键的是，先前的工作很少在复杂的现实任务上验证其有效性，或隔离改进的根本驱动因素。为解决这些不足，我们提出了在线框架学习（online harness learning），即一个冻结的智能体通过持续更新跨顺序任务的结构化框架来改进。这一表述使我们能够通过所提的Evo-Harness对关键自我改进因素进行系统性研究。其核心是，上下文到框架的技能编译将嘈杂的一次性执行过程提炼为可重用的技能框架，用于跨领域和主题级别的适应。为证明一次性技能编译的有效性，我们在五个现实基准上进行了评估（TerminalBench2、SWE-bench、CL-Bench、-bench、WebArena-Infinity）。我们广泛的分析证明了Evo-Harness的有效性，并对LLM智能体如何快速学习提供了原则性的理解。我们的代码可在 https://github.com/A-EVO-Lab/a-evolve/tree/release/evo-harness 获取。

## Abstract
Learning from experience is critical for developing capable, self-improving large language model (LLM) agents. Existing methods typically extract knowledge from accumulated trajectories via reflection, memory, rules, or skills. However, agents in realistic environments continuously encounter novel tasks, often offering only a one-shot opportunity to improve. These executions yield rich but highly noisy contexts, entangling broadly useful lessons with task-specific artifacts. Critically, prior works rarely validate their effectiveness on complex real-world tasks or isolate the underlying drivers of improvement. To address these gaps, we formulate online harness learning, where a frozen agent improves by continually updating a structured harness across sequential tasks. This formulation enables a systematic study of key self-improvement factors through our proposed Evo-Harness. At its core, context-to-harness skill compilation distills noisy, single-shot executions into reusable skill harnesses for cross-domain and topic-level adaptation. To demonstrate the efficacy of one-shot skill compilation, we evaluate across five realistic benchmarks (TerminalBench2, SWE-bench, CL-Bench, -bench, WebArena-Infinity). Our extensive analysis demonstrates the effectiveness of Evo-Harness and provides a principled understanding of how LLM agents can effectively learn on the fly. Our code is available at https://github.com/A-EVO-Lab/a-evolve/tree/release/evo-harness.

- **现有方法的不足**：
  - 依赖离线累积轨迹（reflection、memory、rules、skills）进行学习，难以直接适配连续在线任务流；
  - 在复杂现实任务上缺乏严格验证；

- **核心见解**：简单检索过去经验（experience reuse）不足以应对新任务，智能体需要主动将原始执行上下文**编译**为可复用的技能指导（skill guidance），供未来任务使用。
- **论文立场**：作者强调不是为了提出又一个"效果更好的 pipeline"，而是将 skill harness 作为**可解释的分析透镜**，系统性地研究"冻结 LLM 智能体如何在线学习"这一根本问题。

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 在线框架学习（Online Harness Learning）形式化

- 任务批次流 {B₁, ..., B_K}，智能体在每批任务前持有当前 harness Hᵢ（一组结构化指导条目）。
- 对每个任务 xᵢ,ⱼ：
  - **Select**：从 harness 中选择至多 b 条相关指导；
  - **Inject**：将指导注入任务上下文；
  - **Solve**：冻结的 solver A 执行任务，得到轨迹 τ、结果 y 和反馈 f；
  - **Reflect**：仅在失败或负反馈时生成候选记忆 r = (lesson, trigger, evidence, scope_hint)；
  - **Evolve**：在批次结束后，evolver 综合分析候选记忆与当前 harness，产出编辑操作 o ∈ {ADD, MERGE, REVISE, SKIP}，更新 harness。

### 2.2 上下文到框架技能编译（Context-to-Harness Skill Compilation）

- **执行反思（Execution Reflection）**：利用完整任务侧上下文（指令、轨迹、工具输出、结果、反馈），从失败中提取失败根因和可复用经验。刻意只聚焦失败执行，因为成功执行往往包含任务特定细节，噪声大。
- **框架演化（Harness Evolution）**：evolver 对候选记忆进行过滤、合并、修正和提升，而非直接追加。编译分为两个互补流程：
  - **CompileTaskType**：保留局部化的"任务类型程序"（topic-level procedures）；
  - **CompileCrossTask**：从跨任务比较中提取通用的"跨任务模式"。

### 2.3 两层 Harness 结构

- **跨任务模式（Cross-task patterns）**：通过比较不同任务的记忆，识别共享的操作结构，适用于跨域迁移。
- **任务类型程序（Task-type procedures)**：针对重复出现的任务格式、接口或领域，保留更局部的操作知识。
- 这两层并非预先定义的标签，而是由 evolver 在过滤、比较、整合候选记忆过程中自然涌现。

### 2.4 模块化设计

- 解耦了 solver、evolver、反馈来源和初始 harness 状态，使得可以**受控地**研究各因素对在线学习效果的影响。

## 6. 论文的主要结论与发现

1. **Evo-Harness 一致优于所有基线**：在 5 个真实基准上均取得最佳成绩，尤其 TerminalBench-2 提升显著（62.92 → 73.03），表明面向可复用程序性结构的在线编译最为有效。
2. **外部经验复用并非自动有益**：多个基线在部分基准上低于 No Evolve，说明未经验证的检索/演化指导可能引入噪声；这强化了系统性研究驱动因素的必要性。
3. **模型能力影响收益**：更强的 solver（Claude 系列）从 harness 演化中获益更大；弱模型（GPT-OSS）获益很小，可能与遵循和解释指导的能力有关。
4. **不同任务需要不同类型的技能**：CL-Bench 上 localized task-type 指导更关键；SWE-bench 上 broad cross-task 指导更关键。两者的好处是互补的。
5. **在线更新优于离线迁移**：Train-Split Transfer 已可获得收益（说明技能可跨模型迁移），但 Online-Updated 进一步提高，因为在线更新更能适配本地测试流分布。
6. **solver-evolver 配对并非"同模型最优"**：Opus solver 受益于 Sonnet 生成的技能，而 Sonnet solver 在演化后甚至低于 No-Evolve——"技能可迁移"取决于下游 solver 是否有能力理解并应用。
7. **Grounded 反馈至关重要**：自生成反馈会导致性能下降；Standard 反馈在 CL-Bench 最优，但 SWE-bench 上 Minimal 反馈稍优，说明详细错误信息可能引入任务特定噪声。

## 7. 优点

- **问题设定切中实际**：在线单次执行场景比离线批量学习更贴近真实部署，且用"冻结 solver + 外部可更新 harness"的形式化清晰地区分了学习介质与执行体。
- **系统性驱动的分析**：将 harness 视为可解释对象，通过模块化解耦实现对 evolver 设计、反馈类型、迁移设置、solver-evolver 配对的逐一隔离分析，超越了单纯报分数。
- **主动编译 vs 被动存储**：区别于检索式记忆库，通过 ADD/MERGE/REVISE/SKIP 的演化操作实现知识的提炼、合并与筛选，具有明确的噪声过滤机制。
- **双层技能结构设计巧妙**：General vs Topic 技能的分离通过消融实验验证了其在不同任务类型中的差异化价值。
- **跨模型转移验证**：验证了"弱模型演化技能可为强模型所用"的跨模型迁移性，拓宽了实际应用场景。
- **反馈来源的严格对比**：直接证明 LLM 自生成反馈不可靠，环境 grounded 反馈更优，对体系设计有重要指导意义。

## 8. 不足与局限

### 8.1 实验覆盖的局限

- **任务类型受限**：仅评估了单智能体、文本/工具/Web/命令行/软件工程环境，未覆盖具身（embodied）智能体和多智能体系统，这些场景中 harness 可能涉及交互、协调等额外形式的反馈。
- **harness 格式单一**：仅使用自然语言指导实例化 harness；可执行代码技能或结构化程序等其他 harness 格式未被覆盖。
- **反馈依赖**：效果高度依赖环境是否提供 grounded、丰富的诊断信号；在只有弱信号的环境中，harness 演化收益可能大幅下降。

### 8.2 方法与分析的局限

- **失败导向的偏差**：只对失败执行进行反思，可能忽略成功执行中蕴含的"什么有效"的正向经验。
- **噪声过滤机制的边界**：对复杂、探索性的任务（如 CL-Bench 的 EDS 类），演化技能可能过于具体反而有害（部分模型出现性能下降）。
- **案例分析的因果性有限**：附录中的 fail-to-pass 案例无法严格证明是某一特定技能的作用（多个技能可能同时注入），作者也承认了这一点。
- **harness 选择器未受控**：默认使用 Sonnet 4.5 做检索，对不同检索模型的影响未做消融。

### 8.3 成本与可复现性

- **计算成本高**：约 10 万美元 API 成本，可能限制可复现性，尤其是预算有限的学术团队。
- **依赖商业模型**：主实验使用 Claude Opus 4.6/4.7，开放权重模型收益较小，泛化到更弱或本地部署模型的效果存疑。

### 8.4 潜在风险

- 技能库作为 prompt 注入内容，若 learned skills 在非沙盒环境中被不当复用，可能引入错误操作或安全风险。
- 论文明确所有实验在沙盒环境运行，无真实数据暴露，但实际部署时的风险控制仍需进一步研究。
