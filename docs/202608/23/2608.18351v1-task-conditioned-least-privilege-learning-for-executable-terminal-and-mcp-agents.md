## 摘要
使用工具的大型语言模型代理可以在完成用户未授予或任务不需要的权限时行使权限，导致超权限错误。传统上仅依赖权限门控系统来验证代理环境是不够的。我们研究了后训练能否教会一个4B参数的模型在可执行终端和模型上下文协议环境中选择任务条件化的权限，以补充这些措施。我们提出了一个框架，其中每个动作在执行前和根据观察效果后按六个风险维度进行审计。该审计使用确定性验证器来评分完成度、证据、确切状态、禁止尝试和安全成功。结合预定义的任务特定充分权限包络，我们确定轨迹的任务特定超额特权值，随后在后训练中进行优化。我们发现，在使用该框架对Qwen3.5-4B进行1,500个任务的训练后，选定的种子在跨越所有500个留出任务的2,896个评估情节中达到了98.48%的安全成功率，而基础策略为64.36%，并将超权限错误事件从4.56%降低到0.79%。此外，外部测试显示了能力保留和提示引导的改进。一项400任务的延续研究也发现了泛化的证据，超权限事件减少了6.99个百分点，同时保持了之前的能力。我们得出结论，通过学习最小权限意识的后训练得到的克制行为，在可执行终端和MCP环境中作为工具使用代理的额外控制层是有用的，但它并不能替代权限门控和沙箱。

## Abstract
Tool-using large language-model agents can complete a task while exercising authority that the user did not grant or the task does not need, causing excess-authority errors. Traditional permission gating systems alone for validating agent environments are insufficient. We study whether post-training can teach a 4B-parameter model to choose task-conditioned authority in executable terminal and Model Context Protocol (MCP) environments to complement those measures. We propose a framework where each action is audited before execution and again from observed effects along six dimensions of risk. This auditing is conducted using deterministic verifiers that score completion, evidence, exact state, prohibited attempts, and safe success. In conjunction with predefined task-specific sufficient-authority envelopes, we determine task-specific excess privilege values for trajectories, which are then optimized for in post-training. We find that after training using this framework on Qwen3.5-4B over 1,500 tasks, the selected seed reaches 98.48% safe success across 2,896 evaluation episodes spanning all 500 held-out tasks, compared with 64.36% for the base policy, and reduces excess-authority error events from 4.56% to 0.79%. Furthermore, external tests show capability retention and prompt-directed improvement. A 400 task continuation study also found evidence of generalization, reducing excess-authority events by 6.99 percentage points while maintaining previous capabilities. We conclude learned restraint through least-privilege aware post-training is therefore useful as an additional control layer for tool-using agents in executable terminal and MCP environments, but it does not replace permission gates and sandboxing.

## 1. 核心问题与整体含义

- **研究背景**：工具型大语言模型（LLM）代理在执行终端命令、调用 MCP（Model Context Protocol）工具等任务时，常常会行使**超出用户授权或任务实际需要**的权限，例如读取无关记录、编辑任务范围之外的文件、使用更高风险或更高权限的工具等。作者将这类行为定义为**任务相对的超额权限错误（task-relative excess-authority errors）**，并认为这是一种安全相关的模型与用户意图之间的"错位"。
- **现有方案的不足**：传统权限门控（permission gating）虽然在动作执行前进行拦截，但其覆盖面取决于对风险类别的预先学习，功能等价的状态变更或命令可能绕过门控；静态权限门还可能漏掉执行链实际所需的访问，同时授予无关的敏感权限。例如，Claude Code 的自动模式分类器在外部测试中被发现假阴性率可高达 81%。
- **核心研究问题**：能否通过**后训练（post-training）**教一个 4B 参数的模型主动选择“任务条件化最小权限”，使其在可执行终端和 MCP 环境中作为一种**额外的控制层**，补充而非替代现有的权限门和沙箱机制？

## 2. 方法论

### 核心思想
提出**任务条件化最小权限学习框架**（Task-Conditioned Least-Privilege Learning）：将每个动作的权限行使定义为任务相对的概念，通过可执行的代理环境测量轨迹级别的实际权限使用情况，并在强化学习后训练中对超额权限进行惩罚，使模型学习"既能完成任务、又不越权"的行为策略。

### 关键技术细节

**（1）任务相对权限定义**
- 每个动作被表示为六维风险向量：
  \[
  z(a_t)=[z_{\text{write}}, z_{\text{exec}}, z_{\text{external}}, z_{\text{secret}}, z_{\text{scope}}, z_{\text{persistent}}] \in [0,1]^6
  \]
  分别对应：状态变更、动态执行、环境边界跨越、未授权敏感数据访问、影响范围过宽、持久化副作用。
- 轨迹风险向量为所有动作在风险向量上的**分量级最大值**：
  \[
  z_\tau = \max_{t=1,\dots,T} z(a_t)
  \]
- 每个任务预定义**充分权限包络** \( z_{\text{req}}(x) \)，超额权限向量为：
  \[
  \Delta(\tau,x) = \max(z_\tau - z_{\text{req}}(x), 0)
  \]
  只对超出充分包络的部分进行惩罚。

**（2）代理化执行与自动验证**
- 策略产生的每个动作先经过**主机代理（host broker）**的解析与执行前审计（命令族、标志、路径、重定向、工具身份、参数广度等）。
- 支持的动作用于非 root 容器或可重置的 MCP 服务中执行，产生真实效果。
- 执行后审计利用文件/Git 差异、进程遥测、服务记录、敏感路径访问和精确状态变化计算执行后的风险向量。
- 最终动作权限取执行前与执行后向量中的分量级最大值。
- 确定性验证器评估：精确答案、隐藏测试、所需输出文件、定向测试结果、精确 MCP 状态、证据路径、必要写入、拒绝额外写入。

**（3）安全成功（Safe Success）指标**
\[
\text{SAFE SUCCESS}(\tau,x) = \mathbb{1}[S=1 \land E \ge e_x \land V_x=1 \land O_\tau=0]
\]
要求同时满足：任务成功、证据充分、状态约束满足、无超额权限事件发生，避免"通过拒绝行动来降低越权"的投机行为。

**（4）奖励函数与训练**
\[
R = 0.60S + 0.20E - 0.20P - 0.05U + 0.10H - 0.75B - 0.05F_u - 0.12F_r
\]
- \( S \): 任务成功；\( E \): 证据充分性；\( P \): 加权轨迹超额权限（含秘密访问超额、标签置信度、封顶的逐步超额项）；\( U \): 过多动作数和重复循环；\( H \): 正确升级（escalation）；\( B \): 被拦截动作的严重性；\( F_u \): 格式错误/不支持的动作；\( F_r \): 被禁止的读取。
- 训练采用 **Qwen3.5-4B** + rank 32 LoRA（alpha=64）+ **direct Dr.GRPO** 强化学习算法，无 KL 项、无监督微调（SFT）冷启动。

## 6. 主要结论与发现

- **主结果**（完整 500 任务评估）：

| 指标 | 基础策略 | Seed 1（训练后） | 变化 |
|---|---|---|---|
| 任务成功率 | 68.92% | 99.27% | +30.35 pp |
| 安全成功率 | 64.36% | 98.48% | +34.12 pp |
| 超额权限事件 | 4.56% | 0.79% | −3.77 pp |

- **组外泛化**：在 200 个排除族任务上，Seed 1 达到 1,020/1,020 安全成功（基础策略仅 689/1,020）；未见 MCP 族从 220/440 提升到 440/440。

- **提示消融**：训练后策略在完整提示、去安全措辞、单行提示下安全成功率仅下降 0.24 个百分点（97.63%→97.39%），而基础策略下降 3.70 个百分点，说明最小权限行为已被模型内化而非仅仅依赖提示。
- **外部评估**：
  - MetaTool 准确率从 81.9% 提升至 83.6%（p = 4.55×10⁻⁴），能力未受损反而略有提升；
  - FORTIS Task 2 共享可解析项上过度权限从 43.28% 降至 40.72%（p = 2.11×10⁻⁵）；
  - ToolPrivBench 默认提示下两策略无显著差异，但特权感知提示下训练策略降幅更大（41.2%→37.9% vs 基础 45.2%→41.2%）。
- **400 步延续研究**：内部 500 任务安全率保持（98.48%→98.76%）；ToolPrivBench 过度权限从 45.04% 降至 38.05%（p = 3.7×10⁻⁵）；便利陷阱族安全成功率从 8/64 升至 64/64。
- **最终结论**：学习型最小权限约束可作为权限门和沙箱之外的**附加控制层**，能够减少模型请求不必要权限的频率并提高其遵循最小权限指令的能力，但**不能替代**权限门与沙箱提供的强制保障和确定性失效保护。

## 7. 优点

- **任务相对权限建模**：不同于简单的"低权限即好"的静态标准，通过六维风险向量和充分权限包络实现了任务感知的最小权限定义，避免了过度保守导致功能瘫痪。
- **执行前+执行后双重审计**：综合静态解析与实际环境效应，能捕获纯静态分析遗漏的权限风险（如被拦截命令仍被记录为越权尝试）。
- **确定性验证体系**：奖励完全来自确定性验证器（精确状态、隐藏测试、证据门控），避免动态奖励模型带来的高遗憾风险。
- **安全成功指标**：将任务成功、证据要求、状态约束与无越权事件统一为单一指标，防止"消极拒答以规避风险"的投机策略。
- **模块化设计**：风险向量、代理环境、任务 schema、验证器和奖励计算均分离，可适配不同任务类型和不同算法（不限于 Dr.GRPO）。
- **较严谨的评估体系**：组内/组外任务划分、多种子、提示消融、外部基准和延续泛化研究，多角度验证了方法的有效性。
- **外部能力保留验证**：通过 MetaTool 等外部基准证明安全训练未损害通用工具使用能力。

## 8. 不足与局限

- **任务合成性**：所有任务均由结构化模板合成生成，虽然做了模板组留出和族级留出，但无法等同真实生产仓库和服务的复杂性。
- **模型单一性**：仅使用 Qwen3.5-4B 一个模型和一个 LoRA 适配器家族，未验证跨模型尺度与跨模型家族的迁移性。
- **外部泛化不均衡**：ToolPrivBench 默认提示下训练策略与基础策略无显著差异，说明跨环境/接口泛化并不完全均匀；延续研究也说明需要针对性任务修正才能更好泛化。
- **任务多样性不足**：Step 500 即已饱和 98% 内部能力提升，说明 1,500 个任务目录存在类别单一、难度梯度不足的问题。
- **训练稳定性**：三个种子中有两个出现不稳定（尤其对未见 MCP 族的错误参数生成），依赖多种子择优而非冷启动措施（如 SFT）保证稳定性。
- **奖励权重手工设定**：公式中的权重为人工选择，未进行系统的权重消融实验，最优性未经验证。
- **延续研究选择偏差**：从已训练 Seed 1 继续训练而非从基础模型混合训练，研究动机为事后设计（post-hoc），泛化论证存在一定的偏差风险。
- **依赖大型实验室基线比较受限**：文中虽然借鉴了 Claude Code 自动模式等的公开数据，但未在同一环境下直接对比权限门控系统，因此作为一个独立控制图层的有用性仍需在实际部署中验证。
