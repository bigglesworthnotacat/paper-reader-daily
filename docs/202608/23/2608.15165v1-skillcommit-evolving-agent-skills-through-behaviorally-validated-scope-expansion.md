## 摘要
大语言模型（LLM）智能体能够通过将历史经验转化为可重用的程序性知识，在无需更新参数的情况下持续改进。然而，现有方法通常基于语义相似性或LLM判断来整合经验，这可能会合并表面上相关但行为上不兼容的策略，从而降低性能。为了解决这一问题，我们提出了SkillCommit，一个在线技能进化框架，它将经验持续转化为可重用技能的层次化库。每个新经验最初被保留为实例特定的补丁，保留其局部上下文中经过验证的行为。随着相关技能的积累，SkillCommit将共享共同行为机制的技能抽象为更高级别的技能。具体来说，对于每个传入的技能，基于嵌入的检索首先识别候选的相关技能。跨实例回放和基于LLM的机制检查确定这些技能是否在案例间迁移以及是否共享共同的潜在机制。通过两项检查的候选技能被抽象为更高级别的技能，且仅当其保留所有组成技能的已验证行为时才被提交。在RuleArena、OpenExempt和KOR-Bench上的实验表明，SkillCommit在不同领域中持续提升了智能体的性能。此外，学习到的技能可跨模型规模和家族迁移，实现跨模型的经验转移。

## Abstract
Large language model (LLM) agents can continually improve without parameter updates by converting historical experience into reusable procedural knowledge. However, existing methods often consolidate experience based on semantic similarity or LLM judgments, which may merge superficially related but behaviorally incompatible strategies and thereby degrade performance. To address the issue, we propose SkillCommit, an online skill evolution framework that continuously transforms experience into a hierarchical library of reusable skills. Each new experience is initially preserved as an instance-specific patch, retaining the behavior validated in its local context. As related skills accumulate, SkillCommit abstracts those sharing a common behavioral mechanism into higher-level skills. Specifically, for each incoming skill, embedding-based retrieval first identifies candidate related skills. Cross-instance replay and an LLM-based mechanism check determine whether these skills transfer across cases and share a common underlying mechanism. Candidates that pass both checks are abstracted into a higher-level skill and committed only if it preserves the validated behavior of all constituent skills. Experiments on RuleArena, OpenExempt and KOR-Bench demonstrate that SkillCommit consistently improves agent performance across diverse domains. Moreover, the learned skills transfer across model scales and families, enabling cross-model experience transfer.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：大语言模型（LLM）智能体可以通过将历史执行经验转化为可重用的程序性知识（即“技能”）来持续自我改进，而无需更新模型参数。这类技能以模块化方式外化领域知识、操作约束和执行流程，帮助智能体在专业场景中更可靠地部署。
- **核心问题**：现有技能进化方法大多依赖**语义相似度**或**LLM 主观判断**来整合和合并经验。然而，语义上相似的补丁可能编码相互冲突的行为策略，而语义表述不同的补丁也可能共享相同的行为机制。这种“语义相似 ≠ 行为兼容”的错位会导致合并后的技能退化，甚至破坏之前已验证的正确行为。
- **隐含需求**：可靠的技能进化必须超越表面相似性，确保每一步范围扩展（从文本候选 → 验证补丁 → 兼容分组 → 高层技能）都有**行为层面的证据支持**，即通过回放（replay）验证其确实保留了局部和整体的已验证行为。
- **整体含义**：本文提出的 SkillCommit 将技能库的构建视为一系列“行为验证的范围扩展”（behaviorally validated scope expansion），为经验驱动的智能体持续学习提供了一个更严谨、可审计的通用框架。

## 2. 提出的方法论：核心思想、关键技术细节与流程

SkillCommit 是一个在线技能进化框架，包含三个连续阶段，每个阶段都引入行为回放验证作为范围扩展的“守门人”。

### 阶段一：反馈引导的补丁归纳（Feedback-Guided Patch Induction）

- **目标**：将一次失败执行转化为可被冻结执行器实际使用的实例级补丁。
- **补丁生成**：当执行器在源实例 \(x_i\) 上失败并产生轨迹 \(\tau_i^-\) 时，提供教师模型 \(x_i\)、标准答案和失败轨迹，教师生成一条正确的参考轨迹 \(\tau_i^+\)，并对比失败与成功行为，输出一段简洁的程序性补丁 \(c_i\)（如行为约束、决策规则或可检查的中间步骤）。
- **防泄漏**：若候选补丁包含最终答案或该实例的特定解法，则直接丢弃。
- **源回放验证**：冻结执行器在仅获得原任务上下文 \(x_i\) 和候选补丁 \(c_i\) 的情况下重新执行该实例，由任务验证器评估结果。成功则补丁被接纳为“源验证实例补丁”；失败则将拒绝信息、新轨迹和验证器反馈回传给技能作者，进行下一轮生成。最多尝试 \(K=3\) 次。
- **补充数据**：88.0% 的失败实例在 3 次尝试内获得验证补丁，其中 91.8% 在 2 次内成功。

### 阶段二：行为兼容性分组（Behavioral Compatibility Grouping）

- **目标**：确定一个已验证补丁可以在多大范围内被复用——要么扩展现有高层技能，要么与残余补丁组成新技能。
- **候选检索**：仅用嵌入检索（余弦相似度）初步筛选相关候选，实际操作中保留 Top \(R=4\) 个候选，后续决策完全依赖行为证据与机制判断。
- **扩展现有技能**：对检索到的技能 \(p\) 与传入补丁 \(q_t\) 做**交叉实例回放**——将 \(p\) 应用到 \(q_t\) 的源实例上，同时将 \(q_t\) 应用到 \(p\) 覆盖的一组实例上，计算行为兼容性得分：

\[
C(p, q_t) = \frac{\rho(p, x_t) + \sum_{x_j \in W(p)} \rho(q_t, x_j)}{1 + |W(p)|}
\]

其中 \(\rho(m, x) \in \{0,1\}\) 表示冻结执行器仅靠记忆 \(m\) 能否解决实例 \(x\)。若 \(C(p,q_t) \ge \gamma\)（\(\gamma\) 为阈值），再交给 LLM 机制评估判断两者是否共享统一的程序性机制，两者都通过才提出扩展版本。

- **形成新技能**：若无现有技能通过检查，则在未被纳入任何高层技能的残余补丁中检索语义相近的候选组，通过跨实例回放寻找“锚点补丁”（anchor patch），要求锚点补丁能迁移到组内所有成员的源实例上，组至少包含 \(m\) 个成员。在合格组中选择行为覆盖最广的组，否则 \(q_t\) 继续作为残余补丁保留。

### 阶段三：源保持整合（Source-Preserving Consolidation）

- **目标**：仅在完整源回放确认候选技能保留其声明范围内所有已验证行为时，才提交（commit）该技能。
- **候选技能归纳**：技能作者在归纳时**看不到源问题、答案、教师轨迹或来源信息**，只接收匿名补丁文本（形成新技能）或当前技能描述（扩展现有技能），以鼓励机制级抽象而非实例记忆。技能描述包含三个字段：`when`（适用条件）、`repair`（可执行程序性指导）、`avoid_when`（排除条件）。
- **全范围源回放**：将候选技能在提议源集合 \(S\) 的每个源实例上回放。若全部成功则进入提交；否则技能作者基于回放轨迹和验证器反馈进行最多 \(L\) 次增量精化，所有版本与回放结果都会保留供审计。
- **三种转换**：
  - **提交（Commit）**：全范围回放成功，作为新技能提交或替换现有技能的活跃版本（旧版本保留可追溯）。
  - **拆分（Split）**：仅部分源实例回放成功时，选取回放支持最强的版本，若其支持的源集包含至少 \(m\) 个实例，则将该版本的声明范围收缩到受支持子集并重新回放，成功后作为独立高层技能提交。
  - **拒绝（Reject）**：无法形成至少 \(m\) 个实例的受支持子集，或缩减后未通过回放，则丢弃候选；现有技能层级不变，相关补丁继续作为实例级技能保留。

## 6. 主要结论与发现

- **一致提升**：SkillCommit 在全部 18 个任务配置对上均优于 No Skill，并在每个任务上取得最佳成绩；六任务均值从 No Skill 的 50.80% 提升至 78.15%。
- **匹配模型设置**：DeepSeek-V4-Flash 下六任务平均提高 19.33 个百分点；Qwen3.6-35B-A3B 下提高 30.02 个百分点；分别超过最强基线 14.48、28.08、28.01 个百分点。
- **基线方法不稳定**：4 种对比方法在 72 个任务级结果中有 31 个低于 No Skill、6 个与 No Skill 持平，说明仅靠语义合并或 LLM 判断获得的经验并不总是有益，甚至可能弊大于利，关键缺口在于缺乏行为验证与范围控制。
- **Help/Hurt 分解**：ExpeL 等基线虽能修复部分失败案例，但常常同时破坏更多原本正确的预测；SkillCommit 在 Airline 上修复 24 例且 0 例回归，在 NBA 上修复 21 例仅 2 例回归，净增益远超基线。这证明了“行为验证”对范围扩展的守门价值。
- **跨模型迁移**：
  - 同族跨规模：Qwen3.6-35B-A3B 撰写的技能使 Qwen3.5-9B 均值从 48.97 提升至 75.25，每个任务均有提升；跨规模迁移有效但并非无损。
  - 跨家族跨规模：GPT-5.4 撰写的技能使 Qwen3.5-9B 均值提升至 69.75，每个任务均有改进，但整体弱于同族迁移（差距 5.50 个百分点），说明程序性知识可跨家族迁移但仍存在表达与执行约定的残留差异。
- **消融结论**：
  - 反馈引导的补丁归纳贡献最大（去掉后下降 17.78 个百分点），说明“生成→验证→精化”的本地修复是性能提升的主要来源。
  - 行为兼容性分组和源保持整合各带来约 4.44 个百分点的边际提升，分别负责“判定安全复用范围”和“防止抽象丢失已验证行为”。
  - 单独运行每个阶段的效果有限，说明三阶段协同才能发挥完整作用。
