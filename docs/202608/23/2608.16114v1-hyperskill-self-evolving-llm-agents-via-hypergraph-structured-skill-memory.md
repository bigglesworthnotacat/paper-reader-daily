## 摘要
随着智能体任务日益复杂，LLM智能体越来越依赖经验记忆来跨任务复用程序性知识。有效的记忆设计必须同时解决存储内容、记忆的结构化与检索方式以及记忆如何演进的问题。现有系统仅部分解决这些问题：它们将轨迹、洞察或工作流存储为孤立条目，丢弃了子任务与可复用技能之间的组合关系；通过忽略关系信号的扁平嵌入相似性进行检索；并在维护记忆时不利用其关系结构。我们提出HyperSkill，一种基于超图的记忆框架，共同改进这三个方面。HyperSkill将记忆表示为具有两种节点类型的超图：子任务步骤和可复用技能，其中每条超边连接单个轨迹中的子任务和技能。双路径检索同时查询子任务和轨迹层级，通过检索轨迹中的共现情况对技能进行排序。周期性的结构感知维护剪除低效用节点，并通过质量加权传播合并冗余技能。在xBench、GAIA和WebWalkerQA上使用GPT-4o和Qwen3-30B-A3B的实验中，HyperSkill优于十种记忆基线，在GAIA上获得高达+11.51的提升，在WebWalkerQA上获得+11.18的提升。

## Abstract
As agentic tasks grow in complexity, LLM agents increasingly rely on experiential memory to reuse procedural knowledge across tasks. Effective memory design must jointly address what to store, how memory is structured and retrieved, and how memory evolves. Existing systems tackle each only partially: they store trajectories, insights, or workflows as isolated entries, discarding compositional relationships among subtasks and reusable skills; retrieve by flat embedding similarity that ignores relational signals; and maintain memory without leveraging its relational structure. We propose HyperSkill, a hypergraph-based memory framework that jointly improves all three. HyperSkill represents memory as a hypergraph with two node types, subtask steps and reusable skills, where each hyperedge links the subtasks and skills from a single trajectory. Dual-path retrieval queries both subtask and trajectory levels, ranking skills by co-occurrence across retrieved trajectories. Periodic structure-informed maintenance prunes low-utility nodes and merges redundant skills via quality-weighted propagation. Across xBench, GAIA, and WebWalkerQA with GPT-4o and Qwen3-30B-A3B, HyperSkill outperforms ten memory baselines, yielding gains of up to +11.51 on GAIA and +11.18 on WebWalkerQA.

## 一、核心问题与整体含义（研究动机与背景）

- **研究背景**：随着LLM智能体在长时间跨度的Web导航、交互式计算机使用和多步科学推理等任务中的应用日益广泛，单次交互往往难以可靠解决复杂问题。经验记忆（Experiential Memory）通过提炼智能体自身的过往轨迹为可复用知识，使智能体具备“自进化”能力。
- **核心痛点**：现有记忆系统存在三个维度的缺陷：
  1. **存储**：孤立地存储轨迹、洞察或技能，丢弃了子任务与技能之间的组合关系；
  2. **结构化与检索**：使用扁平向量数据库或简单二元图，仅依赖嵌入相似性检索，无法表达技能与子任务模式之间的 n 元共现关系；
  3. **演进**：大多数系统无管理地累积知识，少数虽有剪枝或去重但未利用关系结构。
- **关键洞察**：轨迹本质上是子任务、技能与结果之间的 n 元关联，扁平列表和成对边会丢失这一结构。HyperSkill 直接用超图（Hypergraph）原生保留这些关联。

## 二、方法论：核心思想、关键技术细节与算法流程

### 核心思想
将经验记忆组织为超图 G = (V, E)，其中：
- **节点**：分两类——子任务节点（Subtask Nodes, Vu）编码任务分解的流程结构；技能节点（Skill Nodes, Vs）编码可跨任务复用的执行策略（成功策略与失败模式）。
- **超边（Hyperedges）**：每条超边对应一条完整轨迹，连接该轨迹涉及的所有子任务节点和技能节点，并附带任务描述与提炼的教训（lesson）。
- **效用分数**：γ(·) = β·σ(·)/ν(·) + (1−β)·(1 − (T̄ − Tmin)/(Tmax − Tmin))，综合权衡经验成功率与步数效率。

### 双路径检索（Dual-path Retrieval）
1. **子任务路径**：将新任务用 LLM 分解为子任务序列 P0，编码后检索最相似的历史子任务节点，再通过节点所关联的超边扩展出候选轨迹集合 Esub。
2. **轨迹路径**：将完整任务描述与超边表示（任务描述 ∥ 教训）做语义匹配，得到 E_traj，与子任务路径的轨迹集合融合为 E*。

### 技能检索与排序
- 从融合轨迹集合 E* 中的候选技能池中，**按共现计数 κ(v) 排序**（技能在多少条检索到的超边中出现），并辅以语义相似性打破平局，选取 top-ks 技能作为执行指导。这一设计利用了技能节点跨轨迹共享的结构信号。

### 记忆演进（Memory Evolving）
- **质量驱动剪枝**：移除检索次数 ≥ Nmin 且效用分数低于阈值 τ_prune 的节点。
- **结构感知合并**：对技能节点构建**质量加权共现矩阵** W_ij = min(γ(vi), γ(vj))·Σ_{e∈E, vi∈Ve, vj∈Ve} 1/|Ve|，通过 L 步对称传播得到结构嵌入，语义接近且结构重合度高的节点对由 LLM 合并为高阶技能。

### 算法流程（概要）
1. LLM 分解任务 → 子任务路径检索 → 轨迹路径检索 → 融合；
2. 技能共现排序 → 组装上下文 (Sq, Lq) → 执行任务；
3. 完成后抽取新技能与教训，按去重阈值 δ_dedup 决定插入或合并，新增超边并更新效用分数；
4. 每隔 ⌈0.1×N⌉ 个任务触发一次剪枝与合并维护。
