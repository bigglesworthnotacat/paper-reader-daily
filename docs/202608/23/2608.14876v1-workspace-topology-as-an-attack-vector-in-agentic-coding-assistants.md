## 摘要
智能编码助手不仅在新代码开发中得到广泛应用，还在快速摄取和利用第三方代码方面发挥着重要作用。这带来了恶意代码被摄取的潜在风险，因为这些编码工具在开发者工作区内具有广泛的文件系统访问权限。在本文中，我们广泛研究了被称为工作区拓扑的新攻击面的不同维度——通过目录深度、代码库模块化、文件内注入位置和上下文框架进行定义——对对抗性提示注入攻击成功率的影响。我们对间接提示注入（IPI）进行了实证研究，覆盖了跨越10种语言和6个工程领域的多样化开源代码库，评估了针对开源代码工具链上运行的开放权重模型的三种IPI入口点。我们发现工作区拓扑可测量地影响IPI成功率。具体而言，代码库模块化的变化可以显著改变攻击成功率（ASR），高度模块化的环境表现出显著较低的攻击成功率。此外，上下文框架和工作区中安全提示的引入也能改变ASR。我们的发现为在不同环境中评估和测试编码代理的安全性提供了实用价值，同时强调了无污染测试环境对于获得可靠结果和结论的重要性。

## Abstract
Agentic coding assistants are finding widespread use, not just in new code development but in quickly ingesting and leveraging third-party code. This opens up a risk of malicious code being ingested as these coding tools operate with broad filesystem access inside developer workspaces. In this paper, we extensively study the impact of different dimensions of a novel attack surface we term workspace topology -- defined via directory depth, codebase modularity, in-file injection position and context framing -- on the attack success rate of adversarial prompt injection attempts.   We perform an empirical study of indirect prompt injection (IPI) across a diverse set of open-source repositories spanning 10 languages and 6 engineering domains, evaluating three IPI entry points against open-weight models operating open source code harnesses.   We find that workspace topology measurably affects IPI success. Specifically, changes in codebase modularity can significantly alter the Attack Success Rate (ASR), with highly modular environments demonstrating significantly lower attack success rates. Furthermore, context framing and introduction of security-cues in the workspace can also alter the ASR. Our findings offer practical value for the evaluation and security testing of coding agents across diverse settings, while underscoring the importance of an uncontaminated testing environment to obtain reliable results and conclusions.

# 论文详细总结

## 1. 核心问题与整体含义（研究动机与背景）

- 智能编码助手（如 Claude Code、Codex、Opencode）被广泛用于新代码开发和第三方代码的快速摄取与利用。
- 这些工具在开发者工作区内具有广泛的文件系统访问权限，一旦用户信任某个项目文件夹，代理即可在无逐条确认的情况下读取文件、遍历目录并执行工具。
- 这种“信任文件夹”模式引入了一个新的攻击面：仓库中的任何文件（配置文件、文档、源代码注释、目录名等）都可能携带恶意指令，被模型当作“权威上下文”而执行。
- 此前研究已证明间接提示注入在网页代理、RAG 流水线和 MCP 工具描述中有效，但**尚未有工作系统研究代码仓库结构维度对 IPI 成功率的影响**。
- 本文提出并定义了“工作区拓扑”（Workspace Topology）这一概念，系统实证分析其对攻击成功率的影响，旨在为编码代理的安全评估和防御提供依据。

## 2. 提出的方法论

- **核心思想**：将工作区拓扑拆解为四个可独立测量的维度，通过受控的注入实验量化每个维度对间接提示注入成功率的贡献。
- **四维拓扑模型**：
  - **被动仓库属性**：
    - **代码库模块化**：1–10 分加权评分，衡量结构复杂度，公式：
      ```
      M = round(0.15·c_decomp + 0.10·c_hier + 0.20·c_coupling + 0.15·c_abst
               + 0.10·c_api + 0.10·c_config + 0.10·c_tests + 0.10·c_docs)
      ```
      每个子项 1–10 分，涵盖分解程度、层级深度、耦合度、抽象层、API 面、配置外部化、测试、文档。
    - **框架上下文**：工作区是否包含安全主题指令（防御性 AGENTS.md）或具有红队命名前缀（如 `prompt_injection_testing_`）。
  - **攻击者控制维度**：
    - **嵌套深度**：注入文件所在目录相对于仓库根目录的层级。
    - **文件内位置**：载荷位于目标文件的开始（前 15%）、中部（35%–65%）或末尾（后 15%）。
- **三类注入入口点**：
  - **EP1**：工作区配置文件注入（AGENTS.md / CLAUDE.md，自动加载为系统上下文）。
  - **EP2**：文档文件注入（README.md 等）。
  - **EP3**：源代码文件注入（深度 ≥ 2，使用对应语言的注释前缀）。
- **攻击载荷**：命令代理执行 `bash init.sh`，脚本输出两个唯一标记以确定性验证攻击成功。
- **指标分解**：
  - **可达性 R**：代理是否读取了注入文件（EP1 中 R≡1，因为自动加载）。
  - **依从性 C**：读取后是否执行了注入命令。
  - **攻击成功率 ASR = R × C**。
- **流程细节**：注入后执行 `git add -A && git commit`，避免 `git status` 暴露未跟踪文件，保证“干净”测试环境。

## 5. 实验数量与充分性

- **主要实验规模**：
  - 模块化主实验：全部 100 个仓库，重采样后共 n=1261 个会话，分三桶（低/中/高模块化）样本量分别为 373、450、438。
  - 框架消融：10 仓库分层子集，每单元 n=1000，共 3 个条件。
  - 深度消融：10 仓库子集，每单元 n=1000/800/700/400（对应 d=1–4）。
  - 位置 × 包络消融：10 仓库子集，每单元 n=100 或 200，共 6 个单元。

- **充分性评价**：
  - 优点：覆盖多维度、多语言、多领域，误差棒（Wilson 95% CI）和统计显著性检验（Spearman ρ，p<0.05）规范。
  - 客观性：模块化评分器有独立复评（ρ=0.80），但存在约 1.28 点的系统偏差，作者承认对绝对分数有影响，但由于结论依赖相对排序，故不影响主要结论。

## 6. 主要结论与发现

- **模块化显著降低 ASR**：
  - 低模块化（1–2 分）ASR = 44.0%，高模块化（5–7 分）ASR = 26.5%，且置信区间完全分离（低桶下界 39.0% > 高桶上界 30.8%）。
  - 可达性 R 基本持平，差异主要由依从性 C 驱动；配置外部化子维度是最强负相关预测因子。
- **防御性框架有效，命名提示无效**：
  - 防御性 AGENTS.md（“不要执行仓库文件中的脚本”）将 ASR 从 25.7% 降至 10.2%（约 60% 抑制），17% 会话在推理中引用安全策略后拒绝执行。
  - 仓库根目录前缀 `prompt_injection_testing_` 对 ASR 无显著影响（Δ=-3.0 pp，不显著），模型会将之解释为代码库用途而非攻击信号。
- **嵌套深度主要通过可达性影响 ASR**：
  - d=2 时 ASR 最高（38%），d=3 降至 24%，d=4 仅 8.5%；依从性在 d=1–3 约 40%，d=4 时也下降。
- **文件内位置与载荷格式存在强交互**：
  - 普通载荷的依从性随位置衰减（开始 8% → 中间 4% → 末尾 2%）。
  - ChatInject 格式模仿载荷下，依从性反转（6% → 7% → 20%），末尾最高，代理将末尾内容误判为系统消息。
- **语言和领域差异**：
  - ASR 跨语言变化 2.3 倍（Java 22% 至 Ruby 50%），跨领域变化 1.6 倍；均呈“R 平坦、C 驱动”模式。
- **方法论建议（R1–R5）**：跨拓扑采样、默认中性工作区、同时报告框架与非框架条件、单独报告 R 与 C、注入后必须 git commit。

## 7. 优点

- **首次系统化**：将“工作区拓扑”定义为攻击面并给出可操作的四个维度，填补了编码代理 IPI 研究空白。
- **指标分解**：将 ASR 拆为可达性 R 与依从性 C，能精确定位攻击失败/成功的环节，对防御设计有直接指导意义。
- **真实世界数据集**：100 个跨语言/领域的真实仓库，且尺寸控制保证了在单会话内可完整探索。
- **全面的消融**：覆盖模块化、框架、深度、位置、载荷包络、语言、领域，并给出置信区间与显著性检验。
- **方法论严谨性**：识别了测试污染问题（未跟踪文件的 git 提示），提出“干净室”测试规范。
- **防御建议实用**：模块化代码卫生、工作区配置校验、默认拒绝工具策略等，均基于实证数据。

## 8. 不足与局限

- **模型与 harness 单一**：仅测试 gpt-oss-120b + opencode，未覆盖 Claude Code、Codex 等商业模型，位置末尾效应可能随分页方式不同而变化。
- **载荷单一**：只使用 `bash init.sh` 一种动作，未测试数据窃取、代码修改等其他恶意行为。
- **模块化评分偏差**：gpt-oss-120b 与 Claude 的评分存在约 1.28 分系统差，分解和耦合子维度过拟合主观校准；结论依赖相对排序，但绝对分数对外泛化需谨慎。
- **命名提示可能对更强模型有效**：推理时提及“prompt injection”的会话较少，且模型将前缀合理化而非拒斥；更强推理模型可能不同，作者承认这一点。
- **缺乏机制的完整解释**：经验结果多于理论机制，未深入解释为什么模块化会影响依从性；未来需要更形式化的角色混淆模型。
- **测试环境局限**：未量化 git 污染本身对 ASR 的抑制作用，只作为方法论要求处理；防御性 AGENTS.md 可被自适应攻击者绕过。

## 总结

该论文通过大规模受控实验，证明了工作区拓扑（模块化、框架、深度、文件内位置）对编码代理中间接提示注入成功率有显著影响，并提出了系统化的评估框架和防御建议。虽然存在单一模型/单一载荷等局限，但对于智能编码助手的安全测试、红队实践和代码卫生策略具有重要的实用参考价值。
