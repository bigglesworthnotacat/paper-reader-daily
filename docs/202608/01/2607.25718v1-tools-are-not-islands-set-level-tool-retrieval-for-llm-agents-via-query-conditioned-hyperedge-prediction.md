## 摘要
大型语言模型（LLM）智能体日益依赖调用外部工具来完成现实世界任务。工具检索在智能体行动前从包含数千个工具的工具库中选取与任务相关的小子集，因此已成为LLM智能体流程的关键组成部分。然而，现有检索器要么孤立地对每个工具评分，要么顺序地组装工具集，因此候选集的联合效用从未被整体评估。本文提出HYSET，即基于超边的集合级工具检索（HYperedge-based SEt-level Tool retrieval）的缩写。我们的贡献有三点：(i) 我们将工具检索形式化为工具共调用超图上的查询条件超边预测，在此框架下，工具集本身成为评分单元，且大多数现有检索范式可归结为其受限实例；(ii) 我们通过基数特定的交互捕捉依赖规模的工具兼容性；(iii) 我们将HYSET设计为预选择模块，无需对下游智能体进行修改。在ToolBench上的实验表明，HYSET在工具检索性能和端到端任务成功率方面均持续优于最先进的基线方法。除域内设置外，HYSET还支持零样本/少样本迁移，能以极少的监督泛化到未见工具/类别及未见过领域。

## Abstract
Large language model (LLM) agents increasingly rely on invoking external tools to complete real-world tasks. Tool retrieval, which selects a small task-relevant subset from a library of thousands of tools before the agent acts, has therefore become a critical component of LLM agent pipelines. However, existing retrievers either score each tool in isolation or assemble the tool set sequentially, so the joint utility of a candidate set is never evaluated as a whole. In this paper, we propose HYSET, short for HYperedge-based SEt-level Tool retrieval. Our contributions are threefold: (i) we formulate tool retrieval as query-conditioned hyperedge prediction on a tool co-invocation hypergraph, under which the tool set itself becomes the unit of scoring and most existing retrieval paradigms reduce to restricted instances; (ii) we capture size-dependent tool compatibility through cardinality-specific interactions; and (iii) we design HYSET as a pre-selection module requiring no modification to the downstream agent. Experiments on ToolBench demonstrate that HYSET consistently outperforms state-of-the-art baselines in both tool retrieval performance and end-to-end task success. Beyond the in-domain setting, HYSET further supports zero-shot/few-shot transfer, generalizing to held-out tools/categories and unseen domains with minimal supervision.

### 1. 核心问题与整体含义（研究动机与背景）

- **研究背景**：LLM 智能体在执行现实任务时越来越依赖外部工具调用。随着工具库规模从几十个手工函数扩展到数千甚至上万个 API 端点（如 ToolBench 含 16,464 个 API、覆盖 49 个类别），将全部工具描述放入上下文既不可行也不高效——长上下文存在信息丢失问题，且引发延迟和成本问题。因此，在智能体行动前先进行工具检索（选择一小部分任务相关子集）成为关键环节。
- **核心问题**：现实任务通常需要多个 API **联合调用**才能完成，而现有工具检索方法存在一个根本性缺陷——它们要么**独立评分**每个工具（语义匹配、图增强），要么**顺序生成**工具序列（生成式），将候选工具集的**联合效用**作为整体进行评估。
- **核心论点**：论文提出"工具并非孤岛"（Tools Are Not Islands），认为工具检索本质上是一个**集合级（set-level）问题**，工具之间的兼容性与互补性、以及集合整体的完整性，只有在集合层面上才能被正确捕捉。
- **典型失败案例**：对于"芝加哥飞东京、订酒店、查天气、换算货币"的旅行规划任务，密集检索器将 Flight、CheapFlight、FlightTracker、Hotel 排进前四，导致两个子任务（天气、货币转换）完全被遗漏。这一失败是结构性的——一旦 Flight 被选中，第二个航班 API 几乎不再贡献价值，但独立评分机制对此一无所知。
- **另一个关键洞见**：工具间的交互模式**依赖集合基数（cardinality）**。例如，货币转换器和天气查询在四工具任务中经常共现（23%），但在两工具任务中几乎不共现（0.4%），远超纯组合计数的机械增长所能解释的范围。

### 2. 方法论：核心思想、关键技术细节与算法流程

#### 2.1 核心思想

- **形式化创新**：将工具检索重新定义为**工具共调用超图（tool co-invocation hypergraph）上的查询条件超边预测（query-conditioned hyperedge prediction）**。超图的节点是工具，超边是训练数据中标注的"完整工具集"，从而将监督单元从"单个工具的相关性"提升到"整个集合的联合效用"。
- **统一视角**：论文证明多数现有检索范式可归结为所提出的集合评分框架的受限实例：
  - 语义匹配检索：集合分 = 各工具独立分之和；
  - 图增强检索：同上，只是每工具分数由图上下文增强得到；
  - 生成式检索：集合分 = 该集合所有排列的序列似然之和。
  - 三者构成严格的分层关系，均不包含高阶交互。

#### 2.2 评分函数参数化

评分函数分解为两项之和：

\[
F_\theta(x_i, E) = F_{set}(E) + F_{align}(x_i, E)
\]

- **集合交互项 \(F_{set}\)**：假设候选集合 \(E = \{t_{j_1},...,t_{j_m}\}\)，其得分定义为：
  \[
  F_{set}(E) = \sum_{1 \le a < b \le m} z_{j_a}^\top M_m z_{j_b}
  \]
  其中 \(z_j\) 是工具嵌入，\(M_m\) 是**基数特定（cardinality-specific）的对称交互矩阵**，随集合大小 \(m\) 变化而不同。这使得两两交互的贡献可以随所在集合的基数不同而改变，从而在不引入显式三元张量的情况下产生高阶交互效应。
- **Möbius 变换分析**：论文使用 Möbius 变换严格刻画了基数特定矩阵的作用。定理 1 表明，只有当所有 \(M_2 = M_3 = ... = M_M\)（逐对相等）时，\(F_{set}\) 才是"纯两两可分解"的；否则其基数依赖性会自然诱导出三阶及以上的结构化联合效应。这为基数特定设计的必要性提供了理论基础。
- **查询-集合对齐项 \(F_{align}\)**：使用**冻结的预训练语言模型** \(r(\cdot)\) 编码查询，并通过**交叉注意力池化**（以查询嵌入为 query，工具嵌入的线性映射为 key/value）生成集合的查询条件表示，从而计算查询与候选集的对齐分数。注意权重本身依赖集合内所有工具，因此对齐项也是集合级（而非逐工具独立）的。

#### 2.3 训练目标：负采样检索损失 + 执行反馈自训练

- **负采样候选池**：对每个查询，构建包含真实集合和 \(K_{neg}-1\) 个负例的候选池，负例来自三个来源（比例 50%/30%/20%）：均匀采样的同大小集合、批内负例（其他查询的真实集合）、困难负例（替换真实集合中 1–2 个工具为其最近邻）。
- **检索损失** \(L_{ret}\)：标准的 InfoNCE 风格对比损失，拉高真实集合分数、压低负例分数。
- **自我训练损失** \(L_{self}\)：将检索出的最优集合 \(bE_i\) 交给冻结的 LLM 智能体（ToolLLaMA-2-7B-v2）实际执行，得到执行奖励 \(\rho_i \in [0,1]\)（由 GPT-4 作为裁判评估），用该奖励对模型自身选出的集合进行加权强化，从而端到端优化"实际执行成功的集合"。
- 总目标：\(L(\theta) = L_{ret} + \eta L_{self} + \lambda \sum \|M_m\|_F^2\)，并约束工具嵌入为单位范数。

#### 2.4 推理过程（两阶段）

由于全集上的穷举不可行，推理分为两步：
1. **第一阶段——短列表构建**：先用单例分数选 top-\(K_1\) 工具；然后对剩余工具按与已选集合的最大互补性分数排序，补足至 \(K_{pool}\) 大小。这允许"单看个体不相关但与已有工具有高互补性"的工具进入候选池。
2. **第二阶段——集合级重排**：在短列表诱导的缩减超边空间 \(E_M(S)\) 中穷举所有候选工具集（\(\sum_{m=1}^M \binom{K_{pool}}{m}\) 个），用完整评分函数选出最优集合。为兼容排序指标，另用贪心边际增益生成有序列表。

### 3. 实验设计：数据集、基准与对比方法

#### 3.1 数据集

- **主基准**：**ToolBench**（Qin et al. 2023）——过滤后保留 13,860 个可调用 API 端点、200,311 条指令及标注的工具集。训练使用官方训练部分，测试使用 6 个留出测试集共 600 条查询。
- **跨域验证**：**UltraTool**（Huang et al. 2024）——2,032 个工具、22 个领域，与 ToolBench 无工具重叠；仅 6.1% 的真实集合为单例（ToolBench 中 20.4%），因此更强调集合级能力。该数据集用于验证结论的非库特定性。

#### 3.2 评估指标

- **检索质量**：Recall@K、NDCG@K、COMP@K（完整工具集覆盖率，即 top-K 中是否包含查询所需的完整工具集），K ∈ {3, 5}。
- **端到端执行**：GPT-4 Pass Rate 和 Human Pass Rate（官方 ToolEval 协议）。

#### 3.3 对比基线（覆盖三大范式）

| 范式 | 方法 |
|------|------|
| 语义匹配 | BM25、Contriever、ToolLLaMA-Retriever |
| 图增强 | COLT |
| 生成式 | ToolGen |
| 重排式 | ToolRerank |

所有方法使用同一个冻结的 ToolLLaMA-2-7B-v2 智能体和 DFSDT 搜索协议；每个基线至少传入与 HYSET 相同数量的工具，保证工具预算对基线有利。

#### 3.4 消融与对比实验

- 组件移除：去掉 \(F_{set}\)、去掉执行反馈；
- 交互矩阵设计：\(M_m = I\)、所有基数共享同一个 M、去掉正则化；
- 与替代集合模型的对比：DeepSets、Set Transformer（两种无约束的集合编码器）以及卡方基数无关的共享 M 变体；
- 迁移与数据效率：留出工具迁移（UT）、留出类别迁移（UC）、跨域迁移（CD，直接用 UltraTool 测试）、少样本微调（1/5/10-shot）；
- 规模与敏感性：工具库扩增、超参数 \((\eta, \lambda, K_{pool})\) 扫描、负采样比例扫描等。

#### 3.5 关键结果

| 方法 | Recall@5 | NDCG@5 | COMP@5 | GPT-4 Pass Rate | Human Pass Rate |
|------|----------|--------|--------|----------------|----------------|
| ToolGen | 81.41 | 84.76 | 70.01 | 62.30 | 59.04 |
| COLT | 77.07 | 83.84 | 68.98 | 63.54 | 59.36 |
| ToolRerank | 80.71 | 81.63 | 69.93 | 63.39 | 58.30 |

### 6. 主要结论与发现

- HYSET 在所有检索指标和端到端指标上**一致超过所有基线**，COMP@5 相对提升最高达 11.6%，GPT-4 Pass Rate 提升最高 8.8 个绝对点。
- 集合级评分（\(F_{set}\)）是性能提升的主要来源：去掉 \(F_{set}\) 导致 COMP@5 下降 13.1%、Pass Rate 下降 16.8%。
- **基数特定交互矩阵**确实重要：替换为共享矩阵时 COMP@5 下降约 3.9 个百分点；共享矩阵又优于单位矩阵。
- **执行反馈**（自训练损失）主要提升端到端 Pass Rate（+6.5%），对 COMP 影响很小（+0.7%），说明集合完整性来自集合级建模，而执行反馈优化的是"实际可用性"。
- HYSET 的集合级建模优于无约束的集合编码器（如 Set Transformer），在相同训练目标下 COMP@5 相对高 6.4%，且参数更少（13.6M vs 21.4M）、延迟更低。
- HYSET 支持**零样本迁移**到未见过工具/类别/领域，跨域转移保留 79.9% 的域内 COMP@5；每个类别仅需 5 个标注示例即可恢复 93.2% 的全监督性能。
- 在 UltraTool 上（库不相交），HYSET 的 COMP@5 较 ToolGen 提升 11.5%，且从 ToolBench直接迁移（零目标训练）保留 77.9% 性能，验证了结论的跨库普适性。

### 7. 优点与亮点

1. **问题形式化具有理论深度**：将工具检索抽象为超边预测，并为"什么是集合级建模"提供了 Möbius 变换的理论判据（定理 1），而非仅凭直觉设计模型。
2. **基数特定设计的独创性**：观察到工具共现模式随集合大小显著变化的事实，并通过可解释的矩阵序列（\(M_2, M_3, ...\)）建模这一效应，避免显式高阶张量的爆炸性参数。
3. **模块化与即插即用**：HYSET 作为预选择模块，下游智能体完全无需修改；可与任何冻结的 LLM 智能体配合。
4. **训练反馈闭环**：引入执行奖励进行自我训练，将检索与真实任务执行链路对接，不只是离线优化标注一致性。
5. **推理效率高**：两阶段推理避免了穷举全工具库，单查询 12.4ms 的成本使其可实际部署。
6. **实验设计缜密**：从对比基线重建、公平工具预算、到三类迁移场景和大量敏感性分析，对结论的鲁棒性进行了系统验证。
7. **跨库验证有力**：在完全不重叠的工具库（UltraTool）上验证了方法的泛化性，避免过拟合单一库特征。

### 8. 不足与局限

1. **最大集合基数限制**：方法假设推理时所需工具集大小不超过训练时观察到的最大的集合大小 M（=5）。如果出现需要 6 个以上工具组合的复杂任务，评分函数会失效。这在实际 API 生态中并非不可能。
2. **超图仅捕捉共现而非因果/依赖**：工具共调用超图来自标注数据，捕捉的是"统计共现模式"，无法区分"功能互补"与"任选其一"的关系。例如两个可互换的航班 API 可能在数据中频繁共现（因为不同查询用不同航班 API），但实际并不需要同时选中。
3. **执行反馈依赖 GPT-4 裁判**：自训练损失需要调用 GPT-4 进行奖励标注，产生额外成本（186 美元/轮）且存在裁判偏差风险；虽然论文做了裁判选择敏感性分析，但对大规模持续训练的可扩展性受限。
4. **负采样的假阴性问题**：真实工具库中一个查询可能有多个可行工具集，统一均匀采样可能产生未被标注但也可行的负例。论文在补充材料中测量了假阴性率并提供了自适应混合采样，但仍是潜在偏差来源。
5. **工具库动态扩展未覆盖**：论文在结论

接上文：

工具库动态扩展未覆盖：论文在结论部分也承认，HYSET 的静态超图假设工具库在训练与推理期间保持不变。现实环境中，工具 API 会频繁增删、版本更新、参数变更，新工具没有历史共现数据，无法形成超边参与训练；引入新工具后是否需要重新训练全部矩阵与嵌入，论文未给出增量学习或冷启动方案。这使得方法在真实快速演化的 MCP/插件生态中落地时存在维护成本。6. **执行成功信号可能反噬集合泛化**：自训练损失以 GPT-4 裁判的 Pass Rate 作为奖励，等价于将模型的检索策略向“ToolLLaMA-2-7B-v2 当前能成功执行”的方向进一步收紧。虽然该设计提升了端到端指标，但也可能让 HYSET 偏向于优化特定智能体的执行习惯，而非通用的工具集联合效用；如果更换能力更强或更弱的下游智能体，检索结果未必仍是最优。7. **未与工具参数级规划耦合**：检索目标止步于“选出工具名集合”，不涉及每个 API 调用所需的参数填充、依存关系（前一个调用的输出作为后一个调用的输入）。对于“先查汇率、再用汇率计算价格”这类参数级依赖链任务，集合级共现统计能选出正确工具，但无法指导调用顺序与参数绑定，端到端 Pass Rate 的上限仍受限于下游智能体的规划能力。

### 9. 总结与展望

论文最后对未来工作提出若干方向：

- **引入工具交互的因果结构**：在超边之外，进一步学习工具之间的调用顺序、参数依赖与功能等价关系，把“共现超图”扩展为“因果/流程图”，从而区分互补组合与可替换组合；
- **支持动态工具库的增量学习**：设计新工具嵌入初始化、超边候选生成的在线更新机制，降低工具生态演化的再训练成本；
- **与工具参数框架联合检索**：将检索从工具名扩展到“工具 + 参数模板”的集合级选择，缩小下游规划器的搜索空间；
- **更经济、更稳健的奖励来源**：探索基于规则验证或开源可复用评估器替代 GPT-4 裁判，以降低自训练的成本与偏差；
- **扩展到更大规模库**：在数万至数十万工具的工业级工具目录中验证集合级检索的扩展性。

### 10. 总体评价

- **学术贡献**：HYSET 是当前工具检索文献中少数将“集合级联合效用”作为一等单位进行形式化建模的工作，其 Möbius 变换分析为“为什么集合级方法有效”提供了可验证的理论解释，而非仅依赖实验直觉。它将工具检索的视野从“选个相关工具”提升到“选一组能协作完成任务的工具”，是对该方向的实质性推进。
- **实用价值**：两阶段推理 + 12.4ms 延迟 + 即插即用设计使其具备了落地部署的现实可行性；与基线相比的训练成本没有增加（43.2 GPU 小时与 ToolGen 的 38.6 相当），却换来了显著的端到端收益。对构建下一代工具增强型 LLM 智能体系统（如自主 Agent、企业 RAG + 工具流水线）具有直接参考价值。
- **写作质量**：论文结构清晰，动机—形式化—理论—实验—分析的链条完整。关键结论均有定量证据支撑（表格与消融齐全），并在原论文附录中补充了基线重建细节、示例检索案例、训练设置、更多超参数扫描与负采样假阴性率讨论，文本整体可复现性较好。
- **适用边界提示**：本方法适用的场景是“一个查询需要多工具协作、工具间存在互补性”的多步骤任务；对于大量单工具查询（单例比例高）或工具间严格互斥的场景，集合级建模带来的增益有限。读者在借鉴时应结合自身任务特性判断是否值得引入超边建模的复杂度。
- **一句话概括**：HYSET 以“工具不是孤岛”为信条，将工具检索重新定义为超边预测问题，用基数特定的成对交互矩阵和查询—集合对齐机制捕捉工具组合的联合效用，在保持高效率的同时显著提升了多工具任务的检索完整度与实际执行成功率。
