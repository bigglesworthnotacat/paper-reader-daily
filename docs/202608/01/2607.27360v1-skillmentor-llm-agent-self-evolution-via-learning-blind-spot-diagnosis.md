## 摘要
智能体的自我进化主要聚焦于学习如何行动，却忽视了一个同样重要的能力：学习发现智能体不知道什么。现有方法通常假设失败发现是给定的，关注于一旦识别出失败如何进行修复。我们提出疑问：盲点诊断本身是否可以学习。因此，我们将诊断作为一种独立于执行的能力来研究，并排除了两种替代性的进步来源：执行器适应和人类监督。在这些约束下，性能无法通过执行器更新或标注示例来提升，迫使所有改进都源自学习到的诊断能力。我们提出了SkillMentor，通过强化学习训练一个导师策略来生成诊断任务、识别反复出现的失败模式，并将其整理成可复用的纠正技能。在AppWorld和BFCLv3上，SkillMentor将执行器性能平均提升了44.2%。这些结果表明，盲点诊断是一种可学习的能力，使得无需更新执行器权重或依赖人类策划数据即可实现自我进化。

## Abstract
Agent self-evolution has primarily focused on learning how to act, while overlooking an equally important capability: learning to discover what an agent does not know. Existing approaches typically assume that failure discovery is given, focusing on how to repair failures once they are identified. We ask whether blind-spot diagnosis itself can be learned. We thus study diagnosis as an agent capability separate from execution, and exclude two alternative sources of progress: executor adaptation and human supervision. Under these constraints, performance cannot improve through executor updates or annotated examples, forcing all improvements to originate from the learned diagnostic capability. We propose SkillMentor, which trains a Mentor policy via reinforcement learning to generate diagnostic tasks, identify recurrent failure modes, and curate them into reusable corrective skills. Across AppWorld and BFCLv3, SkillMentor improves executor performance by an average of 44.2%. These results suggest that blind-spot diagnosis is a learnable capability, enabling self-evolution without updating executor weights or relying on human-curated data.

## 2. 方法论：SkillMentor

### 2.1 核心思想
- SkillMentor 训练一个 **Mentor 策略** πθ，通过强化学习（GRPO）主动发现执行器的盲点并修复它们，整个过程形成一个自我进化的正反馈闭环：
  - 更好的发现 → 更好的技能 → 更强的执行器 → 暴露新的盲点 → 更深的发现。
- 与传统的"故障修复受限于固定流程"不同，SkillMentor 将诊断本身建模为**顺序决策问题**，利用执行器环境交互获得的学习信号来不断优化诊断策略。

### 2.2 问题定义
- 盲点被形式化定义为元组 **b = (T, c)**，其中 T 是执行器持续表现不佳的任务，c 是能够缓解该失败的纠正性技能。
- 在训练步骤 t，Mentor 策略 πθ 观察环境 E 和当前技能库 Rt，输出动作 **at = (qt, ct)**（诊断任务 + 整理决策）。
- 优化目标为最大化累计期望奖励：

$$\max_{\theta} \mathbb{E}_{\pi_\theta} \left[ \sum_t (r_{disc}(q_t) + r_{curate}(c_t)) \right]$$

- 两个奖励通过不断演化的技能库耦合在一起，形成发现-整理协同的反馈回路。

### 2.3 三阶段流程

#### A) 盲点发现（Blind-Spot Discovery）
- Mentor 在环境中自由探索，形成轨迹 τ = (x₀, a₀, x₁, a₁, …, x_T)，并从轨迹中合成 G 个候选诊断任务 Q = {q₁, …, q_G}。
- 维护一个**多样性缓冲区**（diversity buffer）以惩罚导向已覆盖状态的行动，避免探索行为模式收敛。

#### B) 缺口评估（Gap Evaluation）
- 对每个候选任务进行双轨评估：
  - 强参考模型 M 生成轨迹并打分 sᵐᵢ；
  - 冻结执行器 πE 在技能库 Rₜ 支持下执行同一任务得 sᴱᵢ；
- 发现奖励定义为诊断缺口：

$$r_{disc} = \delta_i = \max(0, s^M_i - s^E_i)$$

- 选取缺口最大的任务进行技能整理；采用**线性衰减阈值**（0.5 → 0.2，每步 −0.002）以适应盲点缺口随技能积累而自然缩小的动态。

#### C) 技能整理（Skill Curation）
- Mentor 针对诊断出的任务及失败轨迹，生成 G 个候选技能，支持三种操作：**ADD**（新增）、**UPDATE**（更新）、**MERGE**（合并）。
- 候选技能需通过两项验证：
  1. **句法有效性**：符合预定义 schema（YAML frontmatter + Markdown 格式）；
  2. **执行器验证实用性**（executor-grounded utility）：执行器携带候选技能重新执行任务，需满足 Δ = s_c − sᴱ_max > 0.5 才能入库。
- 整理奖励：**r_curate = 0.3·f(c) + 0.7·Δ**，其中 f(c) 为格式合规标志。
- 设置 **DELETE 机制**：检索成功率低于 0.05 的技能被淘汰，防止技能库积累过时/无效项。

#### D) 能力边界迁移
- 训练目标：GRPO 联合优化发现与整理奖励：

$$J_{GRPO}(\theta) = J_{disc} + J_{curate} - \beta D_{KL}(\pi_\theta \| \pi_{ref})$$

- **推理阶段**：执行器通过技能描述匹配检索相关技能并预置到提示中。技能库既是诊断的产物，也是自我演化的引擎。

## 6. 主要结论与发现

1. **诊断是可学习的**：RL 训练的 Mentor 在所有三个执行器上均优于所有提示式 Mentor（包括更大规模的 DeepSeek-V4-Flash），有力证明诊断能力能从优化中获益，而非仅仅是模型规模的副产品。
2. **学习胜过规模**：4B 参数的 RL 训练 Mentor 持续优于参数量大得多的提示式模型，说明针对性的强化训练可弥补模型规模劣势。
3. **弱执行器从诊断中获益更多**：DeepSeek-R1-Distill-Qwen-7B 相对提升最大（+46.6%），Qwen3.5-9B 最小（+36.7%），符合盲点公式化对"能力缺口"的预期。
4. **联合优化发现与整理是必要的**：缺少任何一项奖励都会显著降低性能（如表2），且共享参数优于分离参数，说明两者共享表征、彼此强化。
5. **技能具有可迁移性**：弱执行器训练出的技能库对强执行器同样有效（有时甚至超过强执行器的自训练结果），而强执行器的技能库对弱执行器覆盖不足——因为强者暴露的盲点较少。
6. **盲点是动态非平稳的**：修复已有盲点会持续重塑未来诊断的重点方向，需要自适应阈值调度（衰减调度优于静态和上升调度）。
7. **技能库是可解释的**：不同的模型族表现出了不同的盲点模式（如 MiMo-7B 需专用的上下文管理类别），表明技能库是执行器能力缺陷的可检查地图。
8. **对强模型的依赖既轻又稳**：LLM 裁判的角色单一（仅训练期评判），且更换裁判对性能影响有限（0.338~0.361），低成本 Flash 级 API 即可满足需求。
