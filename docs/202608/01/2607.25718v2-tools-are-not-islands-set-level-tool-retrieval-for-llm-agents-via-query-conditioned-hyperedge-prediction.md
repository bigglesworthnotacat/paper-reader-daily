## 摘要
大型语言模型（LLM）代理越来越依赖于调用外部工具来完成现实世界中的任务。工具检索——在代理行动之前从包含数千个工具的库中选择一个与任务相关的小子集——因此已成为LLM代理流程中的关键组成部分。然而，现有的检索器要么孤立地对每个工具进行评分，要么顺序地组装工具集，因此候选集的联合效用从未被作为一个整体来评估。在本文中，我们提出了HYSET，即基于超边的集合级工具检索（HYperedge-based SEt-level Tool retrieval）的简称。我们的贡献有三方面：（i）我们将工具检索表述为工具共调用超图上的查询条件超边预测，在此框架下，工具集本身成为评分单位，且大多数现有检索范式可归结为受限实例；（ii）我们通过基数特定交互来捕获依赖大小的工具兼容性；（iii）我们将HYSET设计为一个预选择模块，无需对下游代理进行任何修改。在ToolBench上的实验表明，HYSET在工具检索性能和端到端任务成功率方面始终优于最先进的基线。除域内设置外，HYSET还支持零样本/少样本迁移，能以极少的监督泛化到未见的工具/类别和未见领域。

## Abstract
Large language model (LLM) agents increasingly rely on invoking external tools to complete real-world tasks. Tool retrieval, which selects a small task-relevant subset from a library of thousands of tools before the agent acts, has therefore become a critical component of LLM agent pipelines. However, existing retrievers either score each tool in isolation or assemble the tool set sequentially, so the joint utility of a candidate set is never evaluated as a whole. In this paper, we propose HYSET, short for HYperedge-based SEt-level Tool retrieval. Our contributions are threefold: (i) we formulate tool retrieval as query-conditioned hyperedge prediction on a tool co-invocation hypergraph, under which the tool set itself becomes the unit of scoring and most existing retrieval paradigms reduce to restricted instances; (ii) we capture size-dependent tool compatibility through cardinality-specific interactions; and (iii) we design HYSET as a pre-selection module requiring no modification to the downstream agent. Experiments on ToolBench demonstrate that HYSET consistently outperforms state-of-the-art baselines in both tool retrieval performance and end-to-end task success. Beyond the in-domain setting, HYSET further supports zero-shot/few-shot transfer, generalizing to held-out tools/categories and unseen domains with minimal supervision.

- **核心问题**：现实任务通常依赖多个API联合调用，工具检索本质上应是“集合级”问题——需要检索一组**联合有用**的工具，而非单独相关工具的有序列表。然而现有检索器存在根本性缺陷：
  - **语义匹配检索**（BM25、Contriever、Sentence-BERT等）对每个工具独立打分，集合得分仅为个体得分的聚合，忽略了工具间的联合效用；
  - **图增强检索**（COLT等）虽然引入协同信号，但训练后推理仍退化为独立top-k排序，集合级一致性仅被近似而非显式评分；
  - **生成式检索**（ToolGen等）通过自回归逐步生成工具标识符，但候选集合从未被整体比较，集合的完整性与一致性只能在生成结束后判断。
- **关键观察**：例如旅行规划查询中，地面真值工具集为{Flight, Hotel, Weather, Currency}，而稠密检索器因飞行词占比高，将Flight、CheapFlight、FlightTracker排在Hotel之前，导致Top-4无法覆盖全部子任务。此外，工具间的共现模式随集合基数（工具数量）显著变化：Currency与Weather在2工具集合中仅共现0.4%，但在4工具集合中共现23%，这种差异远超机械的配对数量增加所能解释。因此论文提出两个问题：
  - **(Q1)** 工具集合能否被整体评分？这样做能否提升检索效果？
  - **(Q2)** 工具共调用模式是否随集合大小变化？建模这种差异是否有帮助？

## 2. 方法论

### 核心思想
论文将工具检索重新表述为**查询条件下的超边预测（query-conditioned hyperedge prediction）**，基于**工具共调用超图（tool co-invocation hypergraph）**。超图节点为所有工具，超边为训练数据中观测到的完整工具集。评分单位为**工具集合本身**，而非单个工具。该方法设计为**预选择模块**，无需修改下游代理。

### 技术细节

- **问题形式化**：定义工具库 V = T，候选超边空间 E_M = {E ⊆ V : 1 ≤ |E| ≤ M}（M为训练集中最大工具集大小）。学习评分函数 F_θ(x, E)，对查询 x 和候选集合 E 评估联合效用。预测时选择使 F_θ 最大的集合。
- **统一视角**：论文证明现有三大类检索范式均可视为该集合评分框架的受限实例：
  - 语义匹配：F(x, E) = Σ_{t∈E} s_match(x, t)（独立和）；
  - 图增强：F(x, E) = Σ_{t∈E} s_G(x, t)（独立和但工具嵌入含图上下文）；
  - 生成式：F(x, E) = log Σ_{π∈S(E)} p_φ(π, EOS | x)（集合的序列概率求和）。
- **HYSET评分函数分解**：
  - **集合交互项** F_set(E) = Σ_{1≤a<b≤m} z_{ja}^T M_m z_{jb}，其中 m = |E|，z_{ja} 为工具嵌入，M_m 是**基数特定（cardinality-specific）的对称交互矩阵**。该设计允许同一对工具的贡献随集合大小变化，从而隐式建模高阶交互（通过Möbius变换证明：若所有M_m相同则退化为固定二阶；不同则能表达高达M阶的结构化交互，且参数量仅O(M d_z²)，远少于显式M阶张量的O(d_z^M)）。
  - **查询-集合对齐项** F_align(x_i, E) = r(x_i)^T s(x_i, E)，其中 r(x_i) 为冻结预训练语言模型对查询的嵌入，s(x_i, E) 通过**交叉注意力池化**生成候选集合的查询条件表示：s(x_i, E) = Σ_k α_k(x_i, E) P z_{j_k}，注意力权重 α_k 取决于集合内所有工具与查询的匹配分数，因此对齐项本身也是集合级评分。
- **训练目标**：
  - **检索损失**：负采样softmax损失，负样本包括大小匹配的均匀采样、批内负样本和难负样本（替换一两个工具为最近邻），比例50%/30%/20%。
  - **执行反馈自训练损失**：用冻结LLM代理（ToolLLaMA-2-7B-v2 + DFSDT过程）限制在候选集合 bE_i 上执行任务，获得执行奖励 ρ_i（ExecScore），并以 ρ_i 作为权重强化成功集合。
  - 总损失 L = L_ret + η L_self + λ Σ||M_m||_F²，约束工具嵌入单位范数。
- **集合级推理**：由于超边空间组合爆炸，采用两阶段近似：
  1. **单工具检索**：对每个工具用 F(x, {t_j}) = r(x)^T P z_j 打分，取Top-K1作为S0；
  2. **短列表扩展**：通过最大互补性 g(t_j) = max_{t_i∈S0} z_j^T M_M z_i 补充低个体相关但高互补性的工具，形成Kpool短列表；
  3. **集合级重排**：在短列表的E_M子空间内穷举所有候选超边，选最高分者作为最终集合输出。

## 6. 主要结论与发现

- HYSET在ToolBench所有检索和端到端指标上均优于所有基线：相对COMP@5提升10.8%（BERT）和11.6%（Qwen），GPT-4 Pass Rate相对提升最高13.1%。
- 集合级整体评分是提升检索完整性的关键：移除F_set后COMP@5下降13.1%，Pass Rate下降16.8%。
- 基数特定交互矩阵有效：使用共享矩阵或恒等矩阵均显著降低性能；证明工具兼容性确实依赖集合大小，且通过Möbius变换形式化了这一设计的高阶交互能力。
- 执行反馈主要改善端到端成功率（Pass Rate +7.0%相对，COMP@5仅+0.7%），而集合级建模主要改善完整性。
- 泛化能力强：跨域（CD）保留域内COMP@5的79.9%；5-shot适配恢复全监督性能的93.2%；在完全未见工具的设置下比最强基线提升13.1%COMP@5；在UltraTool上提升11.5%且直接跨库迁移保留77.9%性能。
- 推理成本可控：12.4 ms/query，远低于ToolGen的378.4 ms，内存占用3.21 GB vs 6.83 GB。
- 结论：将工具集合作为整体进行集合级建模能显著提升LLM代理的工具检索和任务执行能力，并具有良好跨域泛化性。

## 7. 优点

- **问题重新形式化具有理论价值**：将工具检索统一为超边预测框架，并证明现有三大范式是其受限实例，提供清晰的层次关系（补充材料给出交互阶数的严格层级）。
- **方法设计巧妙且高效**：用基数特定成对交互矩阵隐式表达高阶交互，参数量仅O(M d_z²)，避免显式高阶张量的维数灾难；Möbius变换定理提供了理论保障。
- **实用性强**：作为预选择模块，不需要修改下游代理；推理成本低，适合大规模工具库。
- **实验严谨**：不仅性能领先，还主动分析执行反馈带来的不公平优势（通过重新训练基线进行制度均衡）；采用多种显著性检验和误差条；多次设置对照（不同编码器、不同训练制度）来隔离贡献来源。
- **泛化验证充分**：覆盖held-out工具、held-out类别、跨库（UltraTool）、少样本适配，证明方法不仅过拟合单库。
- **揭示重要实证洞见**：工具共现对基数敏感（如Currency与Weather在不同集合大小中共现率差异巨大），为后续研究提供了方向。

## 8. 不足与局限

- **超边空间近似**：训练使用负采样而非完整空间，推理使用两阶段短列表近似，无法保证找到全局最优集合；论文虽在补充材料比较了与穷举最大化的差异，但未完全消除近似误差。
- **假设集合大小有界**：方法预设最大基数M（实验设为5），若真实任务需要超过M个工具则无法处理；动态增长的工具库和可变基数的扩展留作未来工作。
- **执行反馈成本与依赖**：执行反馈需要调用LLM代理和judge，虽然缓存API降低成本，但20,000次rollout和judge调用仍有一定开销；且执行奖励的定义（ExecScore）和刷新机制可能影响结果。
- **跨库迁移性能下降明显**：跨域零样本CD的COMP@5仅61.96%，虽保留域内79.9%，但绝对性能较低；对完全未见工具的场景仍是挑战。
- **基准特殊性**：主实验主要在ToolBench（RapidAPI库）上进行，工具语义和共现模式可能带有平台特性；UltraTool验证了跨域但规模较小。
- **与下游代理交互有限**：HYSET仅输出集合，不决定调用顺序；agent自身策略可能对结果产生较大影响，工具预算分配上虽有说明“对基线宽松”，但不同方法提供的工具数量差异可能影响比较的公平性（论文已讨论但未完全解决）。
- **理论证明依赖假设**：Theorem 1要求|V| ≥ M+2，在极端小库情况下可能不适用。
