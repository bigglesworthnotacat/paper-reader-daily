## 摘要
基于大语言模型的多智能体系统通过任务分解、智能体专业化、信息交换和中间验证来提升复杂问题求解能力。然而，现有系统通常将通信拓扑视为固定的设计选择或离线优化目标。我们提出了MANTA，一种多智能体网络拓扑自适应框架，使得通信结构能够在推理时自进化。在执行前，MANTA根据先前的结构经验初始化任务条件化的拓扑。在部署期间，它监控协作轨迹，并在当前组织变得不足时施加有界的结构更新。这些更新可以修改智能体角色、通信链接、执行顺序、信息可见性和验证路径，同时保留任务接口和智能体预算。我们在涵盖信息检索、工具使用、规划、工作流执行和数学推理的五个基准上，将MANTA与代表性的单智能体和多智能体基线进行了评估。MANTA取得了74.0的最高平均分，超过最强基线5.8个百分点，并在PlanCraft上获得了最佳结果。这些结果表明，推理时的自我改进可以扩展到协作架构本身。

## Abstract
Large language model-based multi-agent systems improve complex problem solving through task decomposition, agent specialization, information exchange, and intermediate validation. However, existing systems typically treat communication topology as a fixed design choice or an offline optimization target. We introduce MANTA, a framework for Multi-Agent Network Topology Adaptation that enables communication structures to self-evolve at inference time. Before execution, MANTA initializes a task-conditioned topology from prior structural experience. During deployment, it monitors collaboration traces and applies bounded structural updates when the current organization becomes insufficient. These updates can modify agent roles, communication links, execution order, information visibility, and validation pathways while preserving the task interface and agent budget. We evaluate MANTA against representative single-agent and multi-agent baselines on five benchmarks spanning information seeking, tool use, planning, workflow execution, and mathematical reasoning. MANTA achieves the highest average score of 74.0, outperforming the strongest baseline by 5.8 percentage points and obtaining the best result on PlanCraft. These results show that inference-time self-improvement can extend to the architecture of collaboration itself.

### 二、方法：MANTA框架

#### 2.1 系统总体架构

MANTA 采用双层嵌套设计：

- **目标多智能体系统**：负责任务求解，通过推理、工具调用和消息交换完成工作；
- **编排层（Orchestration Layer）**：负责选择智能体、设计通信链路、控制信息可见性和验证路径，由三个 LLM 组件（拓扑规划器 Topology Planner、轨迹审计器 Trace Auditor、技能反思考 Skill Reflector）加确定性代码构成。

#### 2.2 拓扑表示

- 每个智能体具有**结构角色**（协调者、工人、验证者、辩论者、投票者）和**阶段角色**（工人或批评者）；
- 智能体可加入预定义的**模式组**（星形、链式、辩论、投票等），组可以**嵌套**，允许智能体将工作委托给子组并综合其报告；
- **上下文策略**控制每个智能体的消息可见性、发送者范围、共享证据访问权限、消息传播距离及报告形式（完整或摘要），由代码在读取信息时强制实施；
- 拓扑规范是**版本化的**，在执行前进行完整结构验证（组成员资格、附加循环、角色、智能体预算），无效提议被拒绝。

#### 2.3 编排循环（Orchestration Loop）

**（1）查询条件化规划（Query-conditioned Planning）**：拓扑规划器接收任务和经验记忆（看不到基准身份或手工设计拓扑），分析任务需求和潜在过程风险，输出紧凑规划（交互模式、智能体数量、可选验证者或嵌套组）。确定性代码将该规划展开为完整拓扑，分配角色和上下文策略，并验证所有结构约束。

**（2）回合执行（Turn Execution）**：按组结构递归执行拓扑。智能体通过**结构化中继包**（relay packets，总结答案、证据、置信度、未解决问题）而非原始对话交流。共享上下文控制器强制执行每个智能体的可见性策略；工具调用去重；追加式**证据账本**（evidence ledger）保存所有分支产生的声明和证据。

**（3）轨迹审计与修复（Trace Auditing & Repair）**：
- 每个回合后，LLM 审计器扫描结构化工件、工具记录、中继包、置信度、未解决问题和证据可见性，报告**可观察的过程风险**而非答案正确性；
- 若至少一个可修复标志具有中/高严重性，则标记该运行需要修复（最多**一次修复、三次操作**）；
- 修复操作包括：添加/扩展智能体、更改组模式、编辑通信边、调整信息可见性；确定性代码将操作应用于拓扑副本并通过完整结构验证后生效；无效提议使用保守修复编译器或跳过。

#### 2.4 双时间尺度记忆

- **短时戏本（Short-term Playbook）**：记录当前运行中每个回合的拓扑、审计标志、建议修复和控制器的决策，使规划器在修复时看到哪些结构已尝试、产生了哪些异常；
- **长时戏本（Long-term Playbook）**：跨运行存储"任务特征→拓扑选择"的通用原则，由技能反思考每 N 次运行（实验中N=12）重写，仅使用过程信号（如过程清洁、决策级一致），**从不接触基准答案或真值标签**。

#### 2.5 关键防作弊设计

- 审计器不能查看基准答案或判决；
- 拓扑规划器看不到基准身份和手工拓扑；
- 长时戏本的反思过程只使用过程派生标签，**基准真值仅用于评估**；
- 审计器要求每个新发现必须引用至少两条不同来源的逐字证据，防止幻觉。

### 六、主要结论与发现

1. **主结果**：MANTA在五个基准上平均得分**74.0**，超过最强基线（ADAS，68.2）**5.8个百分点**，并在PlanCraft上获得最佳结果（76.7）。相对于单智能体基线实现全面超越。

2. **消融结论**：初始拓扑规划贡献最大（去掉后从71.7降至57.5），拓扑修复次之（降至60.8），长时戏本提供额外增益——三者缺一不可。

3. **突变预算**：第一次突变提供大部分收益，后续突变进一步扩展最难任务的覆盖率；四个基准均随预算增大而提升。

4. **跨域迁移**：MANTA是唯一实现跨基准正迁移（+3.3点）的自适应方法；对比ADAS（−3.3）、AgentSquare（−13.3）、MASS（−58.3）均大幅负迁移。原因在于MANTA的长时戏本保存的是可继承的、可操作的结构知识而非针对训练任务优化的固定工作流。

5. **Token效率**：MANTA在多个智能体系统中总token消耗最低（77,652/跑），元级操作仅占推理预算约12%——目标拓扑规划与修复不会引入显著token开销。

6. **拓扑演化的本质**：有效的拓扑修复通常不是增加智能体数量，而是**重新布线通信、改变执行顺序、加入验证能力**——5个案例中只有分支扩展增加了系统规模。

7. **审计的可预测性**：未标记修复的运行有83.2%正确的概率，而标记修复的运行只有62.5%；审计器识别了117个错误运行中的75个。

### 七、方法优点

#### 方法设计亮点

1. **问题新颖性**：首次将"拓扑级自改进"作为独立研究方向，将拓扑从固定的设计选择转变为执行期自适应对象；
2. **过程信号而非正确性信号**：审计器只评估协作过程的可观察异常，不接触基准答案，避免了常见的"作弊"问题；这使得框架不依赖任务特定的评估信号，更具通用性；
3. **有界、保守的拓扑变异**：每次运行最多一次修复、三个操作，且修复必须通过完整结构验证，防止系统失控膨胀；
4. **双时间尺度记忆**：短时戏本支持运行内修复决策，长时戏本支持跨运行经验积累，且反射过程只基于过程信号——体现了真正的"自进化"而非"基准适配"；
5. **上下文管理的无损性**：智能体是无状态的，所有对话状态存储在共享、追加式的包存储、证据账本和候选列表中；变异后仅通过重定向上下文控制器实现可见性变化，状态不迁移、不丢失——设计和实现优雅；
6. **防御性设计完备**：包括工具调用去重、停滞搜索检测、失败断路器、强制最终答案等确定性护栏，保障运行鲁棒性；
7. **防过早承诺**：通过时间投票保留旧回合候选，使变异不会覆盖修复前的更好结果。

#### 实验设计亮点

1. 跨五个不同性质基准的全面评估，避免单一基准过拟合；
2. 跨域迁移实验设计精准（预算为0隔离）且对比充分；
3. token 效率对比分析全面（包含离线搜索成本）；
4. 审计质量的多维度分析（精度、召回、FPR、每种标志的相关性、修复清除率）。

### 八、不足与局限

#### 实验覆盖方面的不足

1. **基准规模偏小**：每个基准仅30个问题，统计功效有限，标准偏差较大（如BrowseComp上MANTA为±4.7），结论的稳健性有待更大规模验证；
2. **单一半导体模型**：所有实验仅使用Gemma 4 31B，未验证方法在其他骨干模型（如GPT系列、Claude系列、DeepSeek等）上的泛化性；
3. **缺乏人工标注的过程失败真值**：审计质量评估用"答案是否正确"作为替代标签，精度/召回等指标存在系统性偏差（如BrowseComp出现90%的FPR——标志多但可恢复）；
4. **未报告统计显著性检验**：5.8个百分点的优势是否显著未通过假设检验确认。

#### 方法本身的局限性

1. **每运行仅一次修复**：对于需要多阶段自我修正的复杂任务，一次修复可能不足；尽管突变预算分析显示后续突变有增益，但默认配置限制了这一点；
2. **审计器精度的天花板**：部分过程标志（如消息压缩丢失、工具调用错误级联）与正确性无正相关甚至负相关；干净轨迹仍可能存在智能体共同犯错的"集体幻觉"风险（14.2%的"严格清洁"运行仍然错误）；
3. **依赖LLM审计器和规划器**：元代理本身受限于骨干模型的推理能力，审计漏斗和规划质量存在上限；
4. **跨域迁移的正向增益有限**：尽管MANTA是唯一正迁移的方法，3.3点的增益较小，且仅测试了规划/工作流域之间的迁移，未覆盖检索、工具、推理等其他域间迁移；
5. **检索类任务的修复策略单一**：检索收缩（retrieval contraction）仅替换为最活跃的搜索者并赋予全局证据访问权，缺乏更细粒度的变异选项。

#### 应用限制

1. 框架引入了额外的元级推理开销（约占总推理预算12%），相对单智能体仍构成明显token开销；
2. 系统复杂度较高：需要实现类型化拓扑规范、确定性验证器、共享上下文控制器等多重机制，部署门槛较高；
3. 长时戏本的反思循环需要积累足够运行次数（12次一批），冷启动阶段效果可能受限；
4. 对任务中存在的固有不可解性（数据源本身无法提供答案）无法通过拓扑变异解决——论文明确指出"更多智能体不能修复源端未返回的数据"。

### 总结

MANTA 提出并验证了多智能体系统通信拓扑的推理时自进化这一新范式，通过拓扑规划、轨迹审计、有界结构修复与经验记忆的结合，在五个异构基准上取得了显著且一致的性能提升，并展现出优于离线自动化设计方法的跨域迁移能力。尽管实验规模和方法稳健性仍有改进空间，但在"推理时自改进可扩展到协作架构本身"这一核心论断上，MANTA 提供了迄今最有力的实证支持，为自进化多智能体系统开辟了新的研究方向。
