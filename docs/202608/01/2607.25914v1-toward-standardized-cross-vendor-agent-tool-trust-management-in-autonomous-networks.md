## 摘要
自主网络级别4-5要求AI代理在无需人工监督的情况下跨供应商边界调用工具，然而现有的管理标准缺乏跨供应商信任可见性的标准化机制。当来自供应商B的工具被攻破时，来自供应商A的代理仍继续调用它——对其信任降级毫无察觉——从而导致级联服务影响。我们提出了AgentToolMO，一个针对代理工具信任管理的拟议3GPP NRM信息模型。该模型包括：一个形式化定义的信任状态机，具有可证明的渐进式执行；具有有界收敛的阻尼级联传播；通过现有管理服务（MnS）接口的跨供应商信任通知；以及通过NRM依赖图遍历进行追溯性影响评估。跨多供应商拓扑的仿真评估表明，标准化的跨供应商通知将爆炸半径从小时级未检测传播减少到以MnS通知交付为界的近实时遏制，同时级联收敛在有界迭代内得到保证，且通知跨供应商域呈亚线性扩展。该框架在现有3GPP管理基础设施内运行，利用现有协议，并为可信的多供应商自主网络管理提供标准化途径。

## Abstract
Autonomous Network Levels 4-5 require AI agents to invoke tools across vendor boundaries without human oversight, yet existing management standards lack a standardized mechanism for cross-vendor trust visibility. When a tool from Vendor B is compromised, agents from Vendor A continue invoking it -- unaware of the trust degradation -- causing cascading service impact. We present AgentToolMO, a proposed 3GPP NRM information model for agent tool trust management. The model comprises: a formally defined trust state machine with provable graduated enforcement, damped cascade propagation with bounded convergence, cross-vendor trust notifications via existing Management Services (MnS) interfaces, and retroactive impact assessment through NRM dependency graph traversal. Simulation-based evaluation across multi-vendor topologies shows that standardized cross-vendor notifications reduce blast radius from hours-scale undetected propagation to near-real-time containment bounded by MnS notification delivery, with cascade convergence guaranteed in bounded iterations and sub-linear notification scaling across vendor domains. The framework operates within existing 3GPP management infrastructure, leverages existing protocols, and provides a standardization pathway for trustworthy multi-vendor autonomous network management.

## 1. 论文的核心问题与整体含义（研究动机与背景）

- **核心问题：跨供应商工具信任可见性缺失（Cross-Vendor Trust Visibility Gap）。** 在自治网络 Level 4–5 场景下，AI 代理会跨厂商边界调用其他供应商提供的工具（如配置分析工具、资源优化工具等）。当供应商 B 的内部监控检测到其工具行为退化（配置漂移、KPI 回归、越权访问等）并限制该工具时，供应商 A 的代理并不知道这一信任降级，仍持续以全量权限调用该受损工具，导致级联服务影响。
- **现有方法的核心不足：**
  - **逐供应商专有信任**：信任状态作为专有内部状态，无法跨域可见；
  - **沙箱式信任**：只限定不可信函数的行为，不暴露跨供应商信任结果；
  - **零信任架构（ZTA）**：只做二元的身份验证与授权决策，不评估持续的行为可信度，也没有渐进式执行强度；
  - **3GPP 现有标准化体系**：NRM 提供了通用 IOC 及 AI/ML 管理对象（MLTrainingFunction、MLEntity），但不存在代理工具信任状态的 IOC，也没有相应的 MnS 通知类型，更缺少形式化安全属性。
- **该问题的本质**：跨供应商依赖关系形成了不可见的信任边界，安全关键信息无法跨边界传播，导致损坏工具的输出持续驱动自治决策，爆炸半径在服务可见影响发生前不断扩大。

## 2. 论文提出的方法论

论文提出一整套基于 3GPP NRM 的标准化信息模型框架，核心组成包括：

- **核心信息对象：AgentToolMO（Agent Tool Managed Object）**
  - 作为 3GPP NRM 中的一等管理对象，代表代理可调用的任何工具；
  - 包含三组属性：**身份属性组**（toolId、toolName、vendorName、toolVersion、networkAccessScope 等）、**生命周期属性组**（onboardingTimestamp、lifecycleState、deregistrationReason 等）、**信任属性组**（trustScore、trustState、anomalyCount、revocationCount 等）；
  - 配套新增 AgentMO（代理对象）、AgentSessionMO（会话跟踪）、AgentActionLogMO（行动审计日志）、AgentPolicyMO（治理策略对象）。
- **信任分数计算模型：**
  - 分数范围 [0, 100]（100 为完全信任），初始值 100，随着惩罚累积而下降；
  - 信任分数 = max(0, 100 − Σ wᵢ·pᵢ(t))，其中 pᵢ 为五类惩罚分量：配置漂移（p_drift）、越权访问（p_scope）、KPI 回归（p_kpi）、推荐不一致（p_inconsistency）、异常事件（p_anomaly，按指数衰减累积）；
  - 引入**因果去重机制**：若多个惩罚源于同一根因（同属一个触发动作且在相关窗口内），只取组内最大值而非求和，避免对单次事件过度惩罚（默认相关窗口为 60 秒）。
- **形式化信任状态机（正式状态机）**：
  - 六个状态：Learning（学习）、Trusted（受信）、Monitored（监控）、Restricted（受限）、Revoked（吊销）、Deregistered（注销）；
  - 十条转换 τ1–τ10，包括：前向降级（τ2/τ3/τ4）、恢复（τ6/τ7/τ8）、学习期旁路（τ9/τ10）等；
  - **安全属性**：不允许从 Trusted 直接跳到 Revoked 或 Restricted，不允许从 Trusted 直达 Revoked，Deregistered 是吸收状态（无出边）；任何从 Trusted 到 Revoked 的路径至少需要 3 次转换（Trusted→Monitored→Restricted→Revoked）；
  - 实现**最短滞留时间**（如 Monitored→Restricted 需至少 24 小时；Restricted→Revoked 至少 4 小时），防止瞬时异常导致过快降级。
- **阻尼级联传播机制（算法1，Damped Cascade Propagation）**：
  - 工具依赖关系形成有向图（确保无环，注册时通过 DFS 检测）；
  - 当工具 Ti 以基础惩罚 P0 降级时，对距离 h 处的依赖工具施加惩罚：ΔS = P0·γ^h（γ 为阻尼因子，默认 0.5）；
  - 传播深度受 Dmax 上限约束（默认 3），BFS 遍历使用 visited 集合确保每个工具至多处理一次；
  - 保证收敛：O(|V|+|E|) 时间内终止；
  - 级联不递归触发新级联，避免级联风暴。
- **追溯性影响评估（算法2/算法3）**：
  - 当工具信任降级时，在可配置追溯窗口 Wlb（默认 72 小时）内，通过 AgentActionLogMO 查询该工具的 Write/Execute 操作；
  - 通过 NRM 依赖图深度优先遍历（serve、dependsOn 关系），从受影响的 ManagedElement 追溯至 NetworkSliceSubnet → NetworkSlice → NetworkService，产生受影响服务和元素集合；
  - 使运营商能精准回滚而非全量回滚。
- **跨供应商信任通知**：
  - 定义了 notifyAgentTrustDegradation 通知类型，通过现有 MnS 通知接口（TS 28.532）传递；
  - 通知载荷包含工具 ID、前一/新状态、触发类型、受影响代理与服务、追溯窗口、建议行动、级联信息等；
  - 任何订阅的管理系统（跨厂商）都能收到通知，无论供应商。
- **策略驱动的动态重评估（算法4）**：
  - AgentPolicyMO 定义全部信任阈值与参数（θ_trusted=80、θ_monitor=70、θ_restrict=50、θ_revoke=20、γ、Dmax、ΔWlb 等）；
  - 策略变更时自动重新评估范围内所有工具，按阈值矩阵逐级触发转换，保持渐进式执行约束。
- **协议无关性**：信任治理在 NRM 层维护，不依赖具体工具调用协议（REST/gRPC/专有协议均可）。

## 6. 论文的主要结论与发现

- **发现1：跨供应商信任可见性具有变革性效果。**
  - 标准化模型将爆炸半径从 7.71（无信任基线）降至 3.01，较专有信任（3.82）降低 21%，并通过单一标准化接口实现，而非 O(n²) 双边集成。
- **发现2：通知开销可控。**
  - 通知数从 2 个供应商时的 1.31/事件 增长到 10 个供应商时的 1.55/事件，呈亚线性增长，远低于理论 O(V) 上界。
- **发现3：阻尼因子 γ 呈现清晰权衡。**
  - 低 γ（0.1–0.3）：级联影响少（0.18–0.29 工具/事件）但假阳性率高（约 37%）；
  - 高 γ（0.7–0.9）：级联影响多（0.55–0.64）但假阳性率低（19.5–25.2%）；
  - 文中提供了按 SLA 分层的 γ 选择指导表（URLLC 选 0.7–0.9、eMBB 选 0.5、mMTC 选 0.1–0.3）。
- **发现4：渐进式执行避免不必要的吊销。**
  - 在全部仿真运行中，未发生工具在信任分数高于受限阈值时被错误吊销的情况，验证了中间状态的过滤作用。
- **形式化保证（理论结论）**：
  - 状态机无不安全转换（定理3）；
  - Trusted→Revoked 最短路径需要 3 次转换（渐进式执行，定理4）；
  - 级联传播有界终止、O(｜V｜+｜E｜) 复杂度、并发级联有界（定理5–7）；
  - 追溯评估在非对抗性设置下零漏检（Lookback 窗口内的全部变更均被识别）。
- **标准化优势**：与双边集成相比，标准化模型的边际优势是 7%（3.24→3.01 受影响服务），主要优势在于 O(n) 集成成本对 O(n²)，规模化可行。

- **诚实与透明**：论文多处明确区分“规范贡献”（状态机结构、级联机制、通知架构）与“示例性细节”（具体属性名、阈值、公式），并明确承认仿真延迟假设是模型化的，建议在试点中测量真实延迟——这种学术诚实提升了可信度。
- **部分采纳的优雅降级**：讨论了非合规供应商场景下的安全维护策略（将未知工具视为 Learning/Monitored 状态），以及合规供应商之间的安全性不受非合规参与者影响。
- **操作性指导**：给出了按 SLA 层级的 γ 选择建议、阈值缺口与权重关系、KPI 采集间隔与相关窗口的映射表，工程可落地性强。

## 8. 论文的不足与局限

- **仿真而非生产验证**：所有定量结果均来自离散事件仿真，未在实际多厂商管理系统中实测；通知延迟的各组成部分（本地评估、MnS 传递、接收处理）是基于典型 REST API 基准的模型假设，非实测值。
- **可靠投递假设**：形式化分析假设 MnS 通知可靠有序投递；网络分区或端点不可达时通知可能延迟，此时退化为逐供应商性能。
- **对抗性信任操纵未处理**：论文明确承认该框架不检测恶意供应商虚报/瞒报信任分数的行为，也未提供机制设计层面的激励对齐；只依赖可审计信任证据（KPI 数据、行动日志）作为事后取证威慑。
- **爆炸半径度量的局限**：度量的是启动级暴露（受损期间的工具调用次数），而非 SLA 级或用户可感知的服务影响——实际服务影响取决于工具关键度、网络负载、代理回退策略等部署特定因素。
- **扩展性验证不足**：仿真最多 1000 工具（12.4ms 级联计算时间），但更大规模图、并发级联、地理分布场景缺乏实际验证。
- **部分设计决策的合理性依赖启发式**：例如相关窗口 60s 由 KPI 采集周期的 95 分位数推导，阈值间距依据“单一惩罚不超过 30 点”的默认参数设定，在自定义权重下需要额外验证。
- **潜在过度保守性**：γ=0.5 时精确率仅 68.3%（假阳性 31.7%），意味着约 1/3 的级联限制实际不必要；尽管作者论证了安全优先的合理性，但这在最佳努力

## 9. 改进建议与未来研究方向

- **真实环境试点验证**：在运营商实验室或小型生产环境中，以最小侵入方式部署 AgentToolMO 与 MnS 通知，实测端到端延迟分布，校准论文中的仿真延迟参数；这是从"规范贡献"走向"标准化落地"最关键的下一步。
- **对抗性与容错机制扩展**：引入信任分数的可验证来源（如远程证明、可信执行环境、操作日志哈希链），并设计激励对齐机制，使供应商虚报信任分数在经济上不划算；同时应研究通知丢失/重排/分区下的降级策略，将可靠投递假设放松为最终一致模型。
- **动态上下文感知的阈值与阻尼**：当前 γ、阈值均为静态策略参数。可研究基于网络切片 SLA 动态调整 γ 与追溯窗口的闭环机制，例如网络拥塞时自动收紧限制、业务低峰时放宽监测，以降低假阳性代价。
- **更丰富的因果建模**：因果去重目前基于时间窗口启发式，对跨工具、跨层次的长链因果（如配置漂移→KPI 回归→越权访问）识别能力有限。引入因果图（causal DAG）或事件关联分析，可进一步提升级联检测的精确率。
- **与现有 3GPP 管理服务的深度融合**：探索 AgentToolMO 与 TS 28.310（SON 管理）、TS 28.104（AI/ML 管理）等既有标准对象的继承关系，以及如何通过 NFV-MANO 的 LCM 接口自动执行"吊销/降级"动作，实现监督闭环。
- **扩展性压力测试**：对数千工具节点、多层供应商（三级以上依赖）、并发级联风暴场景做更全面的仿真，验证算法在更大规模图上的行为（论文当前仅覆盖到 1000 工具）。

## 10. 总体评价与适用场景

**总体评价：** 这是一篇"规范性贡献为主、实验验证为辅"的工程型论文，其学术价值主要在于三点：一是首次在 3GPP 标准化信息模型框架内为跨供应商代理工具信任建立了一等管理对象；二是以形式化状态机与有界级联传播算法构建了可验证的安全骨架；三是以诚实、透明的态度清晰区分了规范设计与示例实现。其定量实验虽然全部基于仿真，但覆盖了对比基准、消融、灵敏度与规模扩展等多个维度，足以支撑"机制有效且开销可控"的核心主张。

**该方案的适用场景：** 适用于多供应商管理平共存的自治网络环境，尤其是那些对级联失败敏感的服务（URLLC/工业控制）、以及难以通过逐对双边集成进行信任共享的 n 供应商网络。需要强调的是，其价值取向是"安全优先"——在假阳性与漏检之间有意偏向保守，因此更适合高风险、可容忍部分误限制的场景，而不适合对可用性要求极端苛刻、误限制代价极高的场景。

**一句话概括论文贡献：** 通过标准化 NRM 信息模型 MnS 通知接口，将原本不可见的跨供应商工具信任状态，转化为可传播、可枚举、可追溯、可治理的显式管理对象，从而压缩了信任降级事故的爆炸半径。
