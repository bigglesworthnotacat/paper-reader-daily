## 摘要
复杂任务通常分解为可并行但相互依赖的子任务，使得编排对多智能体系统（MAS）的性能至关重要。现有评估通常依赖端到端执行，这会将编排计划质量与工作智能体能力、工具可靠性和环境噪声混为一谈。此外，随着工作流规模扩大，真实执行的时间和令牌成本迅速增长，使得系统性评估代价高昂。我们提出了OrchBench，一个基于模拟的基准，用于孤立评估多智能体编排计划。从真实世界任务出发，OrchBench构建编码任务依赖关系的有向无环图（DAG），具有受控的规模和并行度。给定一个DAG、每个智能体的上下文限制和智能体预算，被评估的规划器将子任务分配给智能体，并指定跨智能体信息传递及其保留比率。一个确定性模拟器无需调用工作智能体即可评估生成的计划，并返回结果质量、完成时间和令牌成本的可解释度量。OrchBench产生的模拟得分与Claude Code执行的质量得分高度相关，皮尔逊相关系数达到\\(r=0.816\\)，而仅需\\(1.3\\%\\)的令牌和\\(10.3\\%\\)的墙钟时间。在多种规划器和工作流规模中，我们发现保留任务关键信息比单纯增加智能体数量更重要，且随着协调失败累积，并行化的收益会递减。这些结果确立了OrchBench作为比较和诊断多智能体编排计划的高效且可解释的基准。

## Abstract
Complex tasks often decompose into parallelizable yet interdependent subtasks, making orchestration critical to the performance of multi-agent systems (MAS). Existing evaluations typically rely on end-to-end execution, which conflates orchestration-plan quality with worker capabilities, tool reliability, and environmental noise. Moreover, the time and token costs of real execution grow rapidly with workflow scale, making systematic evaluation expensive. We present OrchBench, a simulation-based benchmark for evaluating multi-agent orchestration plans in isolation. Starting from real-world tasks, OrchBench constructs directed acyclic graphs (DAGs) that encode task dependencies, with controlled sizes and degrees of parallelism. Given a DAG, a per-agent context limit, and an agent budget, the evaluated planner assigns subtasks to agents and specifies cross-agent information transfers and their retention ratios. A deterministic simulator evaluates the resulting plan without invoking worker agents and returns interpretable measures of result quality, makespan, and token cost. The simulated scores produced by OrchBench correlate strongly with quality scores from Claude Code executions, achieving a Pearson correlation of \(r=0.816\), while requiring only \(1.3\%\) of the tokens and \(10.3\%\) of the wall-clock time. Across diverse planners and workflow scales, we find that preserving task-critical information is more important than simply increasing the number of agents, and the benefits of parallelism diminish as coordination failures accumulate. These results establish OrchBench as an efficient and interpretable benchmark for comparing and diagnosing multi-agent orchestration plans.

## 1. 核心问题与研究动机

- **背景**：多智能体系统（MAS）已成为解决复杂任务的关键范式，其性能不仅取决于单个智能体的能力，还取决于**编排策略（orchestration strategy）**——即工作流如何跨多个智能体组织。
- **核心问题**：如何独立地评估编排计划本身的质量？
- **现有评估的缺陷**：
  - 端到端执行将编排计划质量与工作智能体能力、工具可靠性、环境噪声混为一谈，难以归因成败。
  - 端到端评估的 token 和时间成本随工作流规模急剧增长，难以支持系统性比较。
  - 缺乏将编排与执行分离的实用评测框架。
- **核心洞察**：编排可以在**不执行完整多智能体系统**的情况下进行评估——通过确定性模拟器替代真实工作智能体执行，从而在相同条件下公平比较不同编排策略。

## 2. 方法论

### 2.1 问题形式化

- 给定**任务 DAG** \\(G=(V,E)\\)：节点表示子任务，边表示依赖关系（子任务需要上游任务产出的信息）。
- 给定**每智能体上下文限制 \\(L\\)** 和**最大智能体预算 \\(A_{\\max}\\)**。
- 被评估的规划器输出**编排计划 \\(\\pi=(\\alpha, R)\\)**：
  - \\(\\alpha: V \\to \\{1,...,A_{\\max}\\}\\)：子任务到智能体的分配函数。
  - \\(R\\)：跨智能体信息传递规则，\\(R(u,v)=e\\in(0,1]\\) 表示将上游任务 \\(u\\) 的输出按保留比例 \\(e\\) 传递给执行 \\(v\\) 的智能体。
- 每个子任务附带元数据：输入/执行/输出 token 预算、时间预算、压缩敏感度类别（robust/balanced/fragile）。

### 2.2 DAG 构建

- 从真实种子任务出发，经**种子过滤器**筛选、**细化器（refiner）**迭代生成、**结构化判官**与**语义判官**双重校验，构建具有目标子任务数 \\(n\\) 和目标自然并行度的 DAG。
- **自然并行度**定义为 \\(k_{99}/n\\)，其中 \\(k_{99}\\) 为达到关键路径下界 99% 所需的最小工作智能体数：
  \\[k_{99}(G)=\\min\\{k: ms_k(G) \\le C(G)+0.01(W(G)-C(G))\\}\\]
- 数据来源包含四个真实数据集：Finance Agent、DS-1000、Qasper、BIRD-SQL。

### 2.3 确定性模拟器

模拟器遵循真实执行框架的六阶段生命周期：

1. **依赖解析**：子任务必须等待所有父任务完成。
2. **智能体调度**：维护每个智能体的逻辑时钟，同一智能体的任务串行执行，不同智能体可并行。开始时间为：
   \\[s_v = \\max\\left(c_a, \\max_{u\\in\\text{Parents}(v)} f_u\\right)\\]
3. **上下文获取**：追踪父任务结果如何到达目标智能体；同智能体直接复用，跨智能体需声明传递，缺失传递则记录事件并按惩罚系数 \\(\\lambda\\) 降低有效质量。
4. **上下文管理**：智能体内存超过 \\(L\\) 时执行压缩：
   \\[n'_v = \\lceil e n_v \\rceil, \\quad q'_v = \\max(q_{\\min},\\, q_v e^{s_v})\\]
5. **子任务执行**：结果质量为可用父输出质量的几何均值经压缩敏感度调整：
   \\[q_v = \\text{clip}_{[q_{\\min},1]}(\\bar{q}\\,e^{s_v})\\]
6. **状态更新**：记录完成时间、更新智能体时钟、释放不再需要的包。

### 2.4 评估指标

- **总体质量** \\(Q\\)：终端任务质量的宏平均。
- **时间效率** \\(E_{\\text{time}} = \\min(1, C/M)\\)：观测完成时间与关键路径下界的接近程度。
- **Token 效率** \\(E_{\\text{token}} = \\min(1, T_{\\text{single}}/T)\\)：相对单智能体串行基线的 token 节省程度。
- **最终得分**：三者算术平均 \\(\\text{Score} = (Q + E_{\\text{time}} + E_{\\text{token}})/3\\)。

## 6. 主要结论与发现

1. **信息保留比智能体数量更重要**：100 任务规模下，智能体数与质量相关性接近零（-0.021），而传递覆盖率与质量相关性高达 0.614。Gemini 和 Doubao 使用同样约 63 个智能体，缺失传递分别为 0.07 和 22.70，质量分别为 0.690 和 0.443。
2. **编排可靠性在规模增大时急剧分化**：从 500 到 1000 任务，Claude 的传递覆盖率从 0.981 降至 0.441，DeepSeek 从 0.981 降至 0.398，各产生 872/907 个缺失传递；而 Gemini 保持完整覆盖和显著更高的质量。
3. **并行收益递减**：将 \\(A_{\\max}\\) 从 16 增至 64 使智能体数翻倍以上，但得分几乎不变。
4. **多智能体仅在上下文溢出时有增益**：上下文限制为 16k 时，多智能体相对单智能体质量提升 +0.302；到 128k 时仅 +0.007，此时协调成本可能变为纯开销。
5. **模拟器与真实执行高度一致**：皮尔逊相关系数 r=0.816，且对四个不同执行框架均保持正相关。
6. **模拟可指导真实改进**：通过模拟器选择添加跨角色手递交接，真实执行得分从 3.754 提升至 4.150（满分 5）。
7. **无模型在所有规模上全面领先**：GPT-5.5 在 n=10 领先，GLM-5.1 在 n=20 领先，Claude 在 n=50 领先，Gemini 在 n=100 领先，说明编排能力是结构适应性的多维问题。

## 7. 优点

- **概念创新**：首次系统地将编排计划评估与工作智能体执行分离，填补了独立评估编排的空白。
- **效率优势显著**：仅需 1.3% token 和 10.3% 时间即可获得与真实执行强相关的分数。
- **确定性可复现**：模拟器无随机性，同一计划同一问题必得相同结果。
- **可解释诊断**：模拟器显式识别缺失传递、压缩事件、隐式读取等协调失败，可直接指导改进。
- **可扩展性**：支持从 10 到 1000+ 节点的多规模评估，适合压力测试与参数扫描。
- **消融设计严谨**：通过消融验证了关键机制对基准区分度的贡献，证明基准不是"分数饱和"的。

## 8. 不足与局限

- **模拟器对真实执行变量的简化**：无法捕获真实 LLM 推理质量差异、工具执行不确定性、环境噪声等，因此模拟分数不能完全替代真实执行验证。尤其时间与 token 预测受框架强烈影响（跨框架时间相关性仅 -0.104）。
- **DAG 生成依赖 LLM**：语义分解质量受生成模型能力限制，论文报告 34.3% 的 DAG 被判定存在语义问题（过度分解、人工同步、冗余验证等），可能引入系统性偏差。
- **相关验证的统计功效有限**：模型级相关性分析仅 6 个数据点，部分 p 值不显著，需要更多模型或任务验证稳健性。
- **真实执行成本依然存在**：验证模拟有效性和最终部署仍需真实执行，OrchBench 只降低了筛选和诊断阶段的成本。
- **任务域覆盖面有限**：数据源集中在金融、数据科学、论文阅读和 SQL 四个领域，尚未覆盖更广泛的多智能体应用场景（如机器人控制、多模态交互等）。
- **单一终端任务假设**：DAG 生成要求唯一终端任务，不适用于多产出或持续迭代型工作流；任务分解与依赖结构本身作为固定输入，未评估规划器的事前分解能力。
