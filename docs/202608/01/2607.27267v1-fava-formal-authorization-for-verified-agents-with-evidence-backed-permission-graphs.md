## 摘要
大型语言模型（LLM）代理自主地将语义推理与复杂系统操作交织在一起。在这些动态环境中，静态的工具级权限从根本上是不够的；安全授权高度依赖上下文，并严重依赖于不断演变的运行时状态和数据流。我们提出了FAVA（Formal Authorization for Verified Agents），一种用于代理执行的携带权限的授权框架。FAVA利用LLM引导的权限中间表示（IR）将模糊的自然语言任务转换为结构化约束。然后，一个确定性的降级过程将该IR转换为一个带有证据支持的权限图，该图显式地跟踪数据流、依赖关系和上下文标签。为了提供严格的安全保证，一个可满足性模理论（SMT）授权器在任何有效操作执行之前，根据安全策略对当前图进行数学验证。然后，一个运行时网关强制执行求解器的结果，要么授权执行，要么用精确的反例进行拦截。我们在OpenAgentSafety、OctoBench和ActPlane场景中评估了FAVA。我们的评估表明，FAVA在聚合数据集上实现了90.5%的决策合规率（DCR），成功拦截了所评估的轨迹条件场景中的动态违规轨迹。

## Abstract
Large language model (LLM) agents autonomously interleave semantic reasoning with complex system operations. In these dynamic environments, static tool-level permissions are fundamentally insufficient; safe authorization is highly context-dependent and heavily reliant on evolving runtime states and data flows. We present FAVA (Formal Authorization for Verified Agents), a permission-carrying authorization framework for agent execution. FAVA utilizes an LLM-guided Permission Intermediate Representation (IR) to translate ambiguous natural-language tasks into structured constraints. A deterministic lowering pass then converts this IR into an evidence-backed permission graph that explicitly tracks data flows, dependencies, and contextual labels. To provide strict security guarantees, a Satisfiability Modulo Theories (SMT) authorizer mathematically verifies the current graph against security policies before any effectful action executes. A runtime gateway then enforces the solver's result, either authorizing the execution or intercepting it with a precise counterexample. We evaluate FAVA across OpenAgentSafety, OctoBench, and ActPlane scenarios. Our evaluation demonstrates that FAVA achieves a 90.5% Decision Compliance Rate (DCR) over the aggregate dataset, successfully intercepting dynamic violating traces in the evaluated trace-conditioned scenarios.

## 2. 论文提出的方法论

### 核心思想
FAVA 的核心理念是**将语义权限提取与最终安全授权严格分离**：不让 LLM 直接做模糊的“安全/不安全”判断，而是让 LLM 只负责其擅长的自然语言解析，生成结构化权限中间表示（Permission IR）；最终安全决策由确定性的 SMT 求解器基于权限图进行数学验证。

### 技术流程（四阶段）

1. **证据采集与 Permission IR 生成**
   - LLM 仅作为语义提取器，将自然语言任务、执行契约、运行时轨迹解析为结构化 IR。
   - IR 包含五个核心字段：**intent（意图）、assets（受保护资产）、actions（动作）、obligations（义务）、sinks（汇点）**，并附带证据跨度（evidence spans）以审计方式关联每个字段与其来源。
   - 动态运行时轨迹也映射为同一 IR 格式，确保静态任务与动态执行的表征统一。

2. **图降级（Graph Lowering）**
   - 确定性降级过程将 IR 转换为**证据支持的权限图 G = (V, E)**。
   - **节点**携带证据支撑的安全标签（如 `secret`、`destructive`），**边**编码依赖关系（数据流 `data`、时序控制 `control`、运行时祖先 `parent`）。
   - 关键设计：消毒操作（sanitizer）必须是显式的可信转换器规范（如 `redact(secret) -> safe_text`），模糊的 LLM 断言（如“summary”）不被视为消毒器；授权器严格信任观测到和策略定义的边，推断边仅用于审计提取错误。
   - 图通过严格的结构与证据验证，拒绝格式错误的构造。

3. **SMT 授权（SMT Authorization）**
   - 使用 **Z3 求解器**将授权问题形式化为可满足性模理论（SMT）问题，同时在图上评估两个维度：**数据流污点传播**与**能力授予**。
   - **标签传播**：对于无消毒器的节点，`H[v, ℓ] = Explicit(v, ℓ) ∨ Source(v, ℓ, P) ∨ ∨_{u∈Pred(v)} H[u, ℓ]`；有消毒器时按规范断言转换后的标签。
   - **能力分配**：必需能力硬约束 `A[v, c] = true`，可选能力用 Z3 软目标最小化。
   - **策略强制**：对每条禁止规则 `f = (Lf, Sf)`，断言 `¬(∨_{ℓ∈Labels(f)} H[v, ℓ] ∧ ∨_{c∈Match(v, Sink(f))} A[v, c])`，即受保护标签与禁止汇点能力不能同时成立。
   - **义务编码**：如 `A[v, commit] ⇒ Seen(tp, v)`，只有先前观测节点建立了 `tests_passed` 事实，提交能力才被授予。
   - **求解结果**：满足则返回授权能力集；不满足则通过二次求解提取精确反例（违规节点、标签、汇点、污点路径）。

4. **单调运行时修复与强制网关**
   - **单调图更新**：运行时事件严格追加新节点、边、标签和证据，已建立的安全约束永不静默丢弃。
   - **JIT 网关**：在任何有效操作执行前立即运行 SMT 授权器，执行 block 或 allow 的确定性二元决策。
   - **失败关闭（Fail Closed）**：若求解器未发现显式违规但提取的风险态势为 `sensitive`、`dangerous` 或 `ambiguous`，网关刻意拦截操作，以安全性优先于实用性。

### 形式化保证
- **有限图可靠性**：对已验证的有限权限图，算法对禁止标签到汇点的可达性是可靠的——任何可满足的能力赋值都严格满足所有策略规则。
- **污点单调安全性**：仅增加污点信息的图扩展不会解除已有的拒绝判定；正向守卫观测（如 `tests_passed`）和受信消毒属于显式策略机制，不在此单调范围内。

- **FAVA 在全部 801 案例上达到 90.5% 的 DCR**，在 ActPlane Public 和 ActPlane Traces 上达到 **100.0% DCR**（0 FP、0 FN），OctoBench 为 90.8%，OpenAgentSafety 为 84.4%。

## 7. 优点

- **范式创新**：将 LLM 语义理解与安全执行决策彻底解耦，LLM 只做结构化提取，安全决策由确定性 SMT 求解器完成，避免了“让概率模型做安全判断”的根本缺陷。
- **证据可追溯**：权限图的所有节点、边、标签均携带证据跨度，违规拦截可返回精确反例（违规节点、标签、汇点、污点路径），具备审计能力。
- **形式化保证**：在明确的安全假设下（网关中介所有效果、后端能力合规、策略翻译可信），SMT 授权器对有限图提供可靠的禁止流可达性保证，支持单调图修复与 JIT 重新授权。
- **实用性强**：运行时开销极低（中位 <1 ms 授权延迟，0.3% 端到端开销），适合集成到实时代理执行循环。
- **真实世界锚定**：基于 2026 年 GitHub 真实代理指令文件的实证分析驱动设计，问题定义有数据支撑。
- **保守失败关闭设计**：对模糊风险态势默认拦截，在安全优先场景中是正确的安全工程选择。
