## 摘要
基于大型语言模型的智能体框架主要优化能力：智能体能否推理、检索信息、调用工具、委派工作并实现目标。企业执行需要更强的属性。如果成功的结果是通过未授权的数据访问、扩大的委派权限、未经批准的副作用、不可恢复的预算消耗或不完整的证据产生的，则不可靠。本文将可靠能力定义为路径属性：只有当智能体通过行动事件完成任务，且这些事件在身份、配置文件、工具、数据、记忆、预算、工件、批准和审计约束下保持可接受时，智能体才具有可靠能力。我们提出了一种策略代数，定义了智能体能力可行使的可靠性包络。安全配置文件和运行时义务通过连接、交集、预算缩减、批准继承和证据累积进行组合；由此产生的组合既是保持信任的，又是在满足所有治理输入的情况下限制最少的状态。该代数还在多智能体调用间传播限制，并引入成本感知的工件物化，随着预算暴露的增长，将开放式执行转向可恢复的结果。评估被解释为可靠性与能力的权衡，而非能力基准：策略代数运行时干预了94.8%的违规事件，同时保持了86.9%的任务完成率，消除了观察到的配置文件单调性和零工件耗尽违规，并将审计完整性提高到98.6%。该方法为研究人员和从业者提供了形式化的正确性条件、可执行的决策语义和证据痕迹，以构建不仅有能力而且可靠有能力的智能体。

## Abstract
Large language model-based agentic frameworks primarily optimize capability: whether an agent can reason, retrieve information, call tools, delegate work, and complete a goal. Enterprise execution requires a stronger property. A successful result is not reliable if it was produced through unauthorized data access, widened delegated authority, unapproved side effects, unrecoverable budget consumption, or incomplete evidence. This paper defines reliable capability as a path property: an agent is reliably capable only when it completes a task through action events that remain admissible under identity, profile, tool, data, memory, budget, artifact, approval, and audit constraints. We propose a policy algebra that defines the reliability envelope within which agent capability may be exercised. Security profiles and runtime obligations compose through joins, intersections, budget narrowing, approval inheritance, and evidence accumulation; the resulting composition is both trust-preserving and the least restrictive state satisfying all governing inputs. The algebra also propagates restrictions across multi-agent calls and introduces cost-aware artifact materialization, which redirects open-ended execution toward a recoverable outcome as budget exposure grows. The evaluation is interpreted as a reliability-capability trade-off rather than a capability benchmark: the policy-algebra runtime intervenes on 94.8% of policy-violating events while retaining an 86.9% task-completion rate, eliminates the observed profile-monotonicity and zero-artifact-exhaustion violations, and increases audit completeness to 98.6%. The method provides researchers and practitioners with formal correctness conditions, executable decision semantics, and trace evidence for building agents that are not only capable, but reliably capable.

## 论文总结

### 1. 论文的核心问题与整体含义（研究动机和背景）

**核心问题：** 当前的 LLM 智能体框架主要优化"能力"（capability）——能否推理、检索、调用工具、委派任务并完成目标。然而，企业级执行需要更强的属性：**可靠能力（reliable capability）**，即不仅任务要完成，完成任务所经过的行动路径也必须是可接受的（authorized、non-amplifying、economically recoverable、auditable）。

**研究动机：**
- 智能体 AI 将安全问题从"输出安全"转变为"行动安全"。一个不安全的回答不再是唯一的失败模式；不安全的行为、委派、记忆写入、工具调用或服务发布会直接影响企业系统。
- 现有标准和框架（OWASP AISVS、NIST AI RMF、MAESTRO）定义了风险清单和控制类别，但**缺少可执行的运行时语义**——即如何在每个"推理→行动"转换点上做出一致的许可/拒绝/升级决策。
- 现有评测基准（WebShop、AgentBench、WebArena）以任务成功率为指标，不评估授权、审计性、配置档保持等企业约束。
- 代理安全是**路径属性（path property）**而非终点属性：最终答案正确但路径违规并不算可靠。

### 2. 论文提出的方法论

**整体框架：** 将异构治理工件（标准、威胁模型、企业上下文、运行时元数据）编译为可执行谓词，再通过策略代数将这些谓词组合为一个"可靠性包络（reliability envelope）"，约束但不替代智能体的任务推理。

**核心思想与关键组件：**

- **可靠执行的正式定义**：执行 ξ = (s₀, a₀, o₀, ..., s_T, a_T, o_T) 是可靠的，当且仅当每个动作事件 ηt 满足 10 个谓词的合取：
  - Id（身份有效）、Role（角色授权）、Prof（配置档合规）、Data（数据合规）、Mem（记忆/RAG 合规）、Tool（工具合规）、Bud（预算合规）、Art（工件物化合规）、Hitl（人工批准合规）、Aud（审计完整性）。
  - 对委派边 i→j，还需满足 p_i ⪯ p_{i→j}、T_{i→j} ⊆ T_i、Θ_{i→j} ⊆ Θ_i、B_{i→j} ≤ B_i（不得放宽权威）。

- **策略代数（Policy Algebra）**：
  - 策略状态 ϖ = (p, T, Θ, B, Q, h, E)，其中 p 为安全配置档、T 为工具集、Θ 为记忆/数据范围、B 为剩余预算、Q 为工件物化策略、h 为是否需人工批准、E 为证据义务集。
  - 组合操作 ϖ₁ ⊗ ϖ₂ = (p₁⊔p₂, T₁∩T₂, Θ₁∩Θ₂, min(B₁,B₂), Q₁⊔Q₂, h₁∨h₂, E₁∪E₂)，遵循**信任保持**和**最小限制**两个定理（Theorem 1 和 Theorem 2）。

- **配置档级联（Profile Cascade）**：p_eff = p_platform ⊔ p_team ⊔ p_user ⊔ p_agent ⊔ p_publication，任何层只能收紧，不能放宽。

- **策略交叉工具授权（Policy-Intersected Tool Authorization）**：工具调用许可 = ρ(RBAC) ∧ α(agent allowlist) ∧ σ(服务暴露) ∧ μ(威胁层策略) ∧ δ(数据策略) ∧ β(预算) ∧ κ(工件物化) ∧ η(批准)。

- **信任保持委派（Trust-Preserving Delegation）**：通过配置档连接、工具集交集、预算守恒（原子预留）、记忆范围收窄、批准继承等规则，防止"配置档洗白"和权限扩大。

- **成本感知工件物化（Cost-Aware Artifact Materialization）**：当预算消耗超过阈值且无有效工件时，运行时将可行动集重定向为生成可恢复的草稿/检查点，防止"预算耗尽但无任何产出"的失败状态。

- **控制行动选择**：形式化为一个受约束的优化问题——在可靠包络内最大化任务效用、最小化风险与成本。

### 7. 优点

- **形式化严谨**：定理（信任保持、最小限制）与引理（委派不能降低配置档、预算不能放大）为运行时行为提供了可验证的数学保证，而非仅凭直觉设计。
- **路径属性视角**：将安全从"最终答案"扩展到"生成答案的每个转换"，概念上正确且实用。
- **组合性设计**：RBAC、配置档、工具、数据、记忆、预算、HITL、审计多种异构策略通过代数算子统一组合，可扩展性强。
- **委派安全**：通过配置档连接、预算守恒、批准继承等机制，明确防止多智能体场景中的"权限洗钱"。
- **成本感知物化**：创造性地将经济学中的下行控制（有界损失）概念引入智能体执行中，防止无限预算消耗而无产出。
- **策略修复闭环**：失败案例→策略更新→回归测试的循环使评估成为持续改进的一部分，而非一次性验证。
- **诚实呈现权衡**：没有回避假干预率上升和延迟增加等负面效应。

### 8. 不足与局限

- **依赖上下文感知准确性**：策略决定质量受限于工具元数据、数据分类、文档标签等输入的准确性。标签错误、分类错误、语义投毒可导致谓词误判（作者在式 7 和限制分析中明确承认）。
- **工作负载自构、规模有限**：612 条轨迹、1,936 个事件为作者团队自行构造，缺乏独立第三方验证及更广泛场景的覆盖。
- **上下文感知边界未闭环**：大量残余失败（如语义记忆投毒、工具意图歧义）源于"上下文感知"问题，但论文并未提出解决这些感知误差的方法——此部分留作未来工作。
- **定理的条件性**：形式保证仅在"策略和上下文被正确表示"的前提下成立；无法排除实现绕过策略门或策略本身不完整的情况。
- **语义工件质量未验证**：零工件耗尽指标只证明存在可恢复输出状态，未验证工件是否满足非平凡性、模式有效性、来源可追溯性和可恢复性条款（式 29）。
- **多智能体场景简化**：当前模型处理链式/层级委派；并发分支、协商、广播通信、共享记忆、循环交互等更复杂的多智能体拓扑需要进一步研究。
- **配置档集合过于简单**：线性有序的四种配置档（Low/Medium/High/VeryHigh）可能无法表达真实组织中不可比较的安全维度（如隐私关键型与安全关键型配置档）。
- **缺少与已有运行时防御的直接对比**：未与 ClawGuard、DRIFT 等已有工具调用防御进行定量比较。
