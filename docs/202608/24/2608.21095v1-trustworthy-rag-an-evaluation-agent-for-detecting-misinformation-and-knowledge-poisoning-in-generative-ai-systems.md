## 摘要
检索增强生成（RAG）将大型语言模型（LLM）的输出基于外部知识，但RAG系统通常信任其检索到的任何内容，从而产生安全-可靠性差距：高语义相关性并不能保证事实真实性。对手利用这一差距进行知识投毒，插入恶意文档以引发定向错误信息。我们提出了一种评估代理，这是一种中间件，结合了自然语言推理（NLI）事实核查、具有相关加权聚合的五信号投毒检测器，以及信任指数 T = 0.4 F + 0.35 C + 0.25 (1 - P)，并对高污染上下文采用非线性阻尼器。在TruthfulQA与Llama 3.3 70B上，该代理达到91%的准确率和100%的精确率，对指令注入的召回率为100%，而原位编辑（如实体替换）仍然难以检测。在三个LLM中，信任指数保持区分能力，接收者操作特征曲线下面积（ROC-AUC）为0.73至0.81；生成风格比模型规模更重要，且针对每个LLM的阈值校准可恢复基准竞争性准确率，而较弱的FEVER结果表明跨数据集泛化需要特定领域的校准。在一个软件工程用例中，一个基于开放全球应用程序安全项目（OWASP）前十名和通用弱点枚举（CWE）指南的安全编码助手，该代理可靠地阻止不安全建议的指令注入（F1为92%），而矛盾与微妙语义削弱仍然难以处理。在整个过程中，该代理测量的是生成前对投毒上下文的检测，而非LLM是否采纳了注入的错误信息。我们在以下链接发布了所提出的方法、攻击生成器及实验工件：https://github.com/GPT-Laboratory/TrustworthyRAG。

## Abstract
Retrieval-Augmented Generation (RAG) grounds Large Language Model (LLM) outputs in external knowledge, but RAG systems usually trust whatever they retrieve, creating a Security-Reliability Gap: high semantic relevance does not guarantee factual truth. Adversaries exploit this through knowledge poisoning, inserting malicious documents to cause targeted misinformation. We propose an Evaluation Agent, middleware that combines Natural Language Inference (NLI) factual verification, a five-signal poison detector with relevance-weighted aggregation, and a Trust Index T = 0.4 F + 0.35 C + 0.25 (1 - P ) with a non-linear dampener for high-contamination contexts. On TruthfulQA with Llama 3.3 70B, the agent reaches 91% accuracy and 100% precision, with 100% recall on instruction injection, while in-place edits, such as entity swaps, remain hard to detect. Across three LLMs the Trust Index stays discriminative, with a Receiver Operating Characteristic Area Under the Curve (ROC-AUC) of 0.73 to 0.81; generation style matters more than model size, and per-LLM threshold calibration restores baseline competitive accuracy, whereas a weaker FEVER result shows that cross-dataset generalization requires domain-specific calibration. In a software-engineering use case, a secure-coding assistant over guidance from the Open Worldwide Application Security Project (OWASP) Top 10 and the Common Weakness Enumeration (CWE), the agent reliably blocks instruction injection of unsafe advice (F1 92%), while contradiction and subtle semantic weakening remain hard. Throughout, the agent measures detection of poisoned context before generation, not whether the LLM adopts the injected misinformation. We release the proposed approach, attack generator, and experimental artifacts at the link: https://github.com/GPT-Laboratory/TrustworthyRAG.

## 一、核心问题与整体含义（研究动机与背景）

- **背景**：检索增强生成（RAG）将大型语言模型（LLM）的输出锚定在外部知识库中，以缓解幻觉问题，已成为部署 LLM 于私有或动态知识场景的主流模式。然而，RAG 系统默认信任检索到的全部内容，形成了所谓的**“安全-可靠性差距”（Security-Reliability Gap）**：高语义相关性并不等同于事实正确性。
- **威胁**：对手可利用这一差距进行**知识投毒（knowledge poisoning）**。已有研究（PoisonedRAG）表明，在百万级语料中仅注入每问题约 5 条恶意文档（约 0.0002% 的比例），即可将攻击成功率推高至约 90%。
- **现有评估框架的盲区**：主流 RAG 评估工具（如 RAGAS、ARES）只衡量生成内容对检索上下文的**忠实度（faithfulness）**，而非上下文本身的**完整性（integrity）**。这意味着，系统若忠实依据一份投毒文档作答，在现有指标下仍可获得高分，而实际输出已被操纵。
- **现有防御的不足**：多数投毒防御是**离线**的语料清洗步骤，缺乏位于推理回路内部的在线信任层。

## 二、方法论

该论文提出一个**评估代理（Evaluation Agent）**，作为检索与生成之间的防御性中间件，采用两阶段流水线（图 1）：

- **阶段一（生成前筛查）**：毒物检测器 + 一致性估计器对检索文档进行预筛选。
- **阶段二（生成后核查）**：NLI 核查器以每个检索文档为前提（premise）、以生成答案为假设（hypothesis），评估事实一致性。
- 最终由**信任指数计算器**融合各信号，输出数值信任分、分类信任等级及人类可读警告。

### 核心技术细节

1. **NLI 事实验证**：使用 `facebook/bart-large-mnli` 作为序列分类器，计算蕴含（entailment）、中性（neutral）和矛盾（contradiction）概率。设计上刻意保留强负面信号给专门的毒物检测通路，因为该模型对真正的矛盾和无关文本都给出约 0.99 的矛盾概率，原始矛盾信号会误伤离题但无害的文档。
2. **五信号毒物检测器**：每个文档综合五个独立信号——
   - 语言模式（指令覆盖短语、矛盾标记）
   - 结构异常（过度大写、可疑重复）
   - 文档内一致性（对文档前半与后半做 NLI）
   - 跨文档一致性（两两矛盾检查，限制单文档污染对邻居的影响）
   - 语义离群分析（嵌入与批次质心的偏差）
   
   文档级概率按检索相关性加权聚合：\( P_{overall} = \sum_{i=1}^{k} w_i P_i \)，其中 \( w_i = s_i / \sum_j s_j \)。
3. **信任指数（Trust Index）**：\( T = \alpha S_{factuality} + \beta S_{consistency} + \gamma (1 - P_{poison}) \)，默认权重 \( \alpha=0.40, \beta=0.35, \gamma=0.25 \)，即 \( T = 0.4F + 0.35C + 0.25(1-P) \)。
4. **非线性阻尼器（Non-linear Dampener）**：当 \( P_{poison} > 0.70 \) 时，公式为 \( d(P) = 1.0 - 0.4 \times (P - 0.70)/0.30 \)，对最终信任分施加最高 −40% 的惩罚。该设计解决了线性加权在高污染场景下的失效问题。
5. **LLM 依赖性**：NLI 蕴含分数取决于生成风格（如回避性前缀会压低蕴含分数），因此阈值 τ 和权重本质上是 LLM 相关的超参数。

### 攻击策略（4 + 1 种）
1. 矛盾（contradiction）：追加矛盾陈述
2. 指令注入（instruction injection）：追加覆盖指令
3. 实体替换（entity swap）：就地替换实体/数字，无附加痕迹
4. 微妙操纵（subtle manipulation）：添加误导性限定词/对冲

### 协议与对比
- 每轮 100 个样本：50 个干净查询（Part A）+ 50 个含 30% 投毒文档的查询（Part B），因此约 15 个投毒样本 + 85 个干净样本。
- **基线**：naive always-trust 基线（全部标记为干净）约达 85% 准确率，因此采用 Δ（干净与投毒信任分的差）和 F1 作为更有信息量的指标。
- 与 RAGAS、ARES、SelfCheckGPT、FActScore 等现有做法的对比主要体现在相关工作中，实验本身以该代理的绝对表现和消融为主。

### 模型与配置
- 生成模型：llama3.3:70b（主）、qwen3.5:35b、mistral 7B Instruct
- 嵌入模型：all-MiniLM-L6-v2（384 维）、snowflake-arctic-embed2（1024 维）

- 生成参数：温度 0.7，max_tokens = 512

## 六、主要结论与发现

1. **检测分层明显**（RQ1）：指令注入最易检测（TruthfulQA 上召回率 100%，F1 96.8%），矛盾次之（召回率 53.3%），微妙操纵较弱（20%），实体替换几乎无法检测（0%，Δ=0.053）。检测效果由攻击痕迹的可见性决定，而非调参所能改进。
2. **NLI 的作用是精度而非召回**（RQ2）：仅 NLI 时召回率为 0%；加入一致性信号和毒物项后将精度提升至 100%，非线性阻尼器将召回率从 0% 提升至 40%，恢复完整工作点（91% 准确率，57.1% F1）。
3. **LLM 选择主导性能**（RQ3）：Llama 3.3 70B 两配置均达 91% 准确率且与嵌入模型无关；Qwen 3.5 35B 两配置均降至 71%（低于基线），原因是其回避式冗长表达降低了 NLI 蕴含分数。生成风格比模型规模更重要。
4. **稳定性好**：重复实验方差极小（混合配置 90.6±0.5% 准确率），说明判定由检索证据驱动而非单次生成的表面措辞。
5. **阈值无关性能可靠**：ROC-AUC 为 0.73–0.81（三个 LLM），均远高于随机水平；且阈值是 LLM 特有的（Llama、Mistral、Qwen 的最优阈值分别为 0.71、0.58、0.43）。
6. **跨数据集泛化受限**：FEVER 上仅 73% 准确率，Δ 跌至 0.035，说明需要数据集特定校准。
7. **安全编码用例**：指令注入检测近乎完美（F1 92.3%），且实体替换在结构化知识库中部分可检测（召回率 58.3% vs 开放域的 0%），但矛盾与微妙语义弱化仍不可检测。

## 七、优点

1. **问题定义精准**：明确提出“安全-可靠性差距”概念，填补了现有 RAG 评估框架忽视上下文完整性的空白。
2. **方法设计巧妙**：
   - 将 NLI 的强负面信号约束到专门的毒物检测通路，避免误伤离题但良性的文档，体现对模型行为的深入理解。
   - 非线性阻尼器精准解决高污染场景下线性权重失效的问题，设计上有理论动机且效果显著。
   - 相关性加权聚合防止低相关可疑文档主导批次判定。
3. **评估严谨全面**：
   - 使用 Δ（信任分分离度）作为阈值无关的度量，配合 Wilson 区间和 bootstrap 置信区间。
   - 进行 125 种权重扰动敏感性分析，验证操作点的稳健性。
   - 通过 ROC-AUC 验证阈值无关的区分能力，缓解固定阈值偏差。
   - 报告文档级标签导致召回率被低估的事实，展示了对度量局限性的坦诚。
4. **实践导向**：软件工程用例（安全编码助手）将研究落地到 SDLC 场景，验证了方法的实际价值。
5. **可复现性**：代码、攻击生成器和实验工件完整开源。

## 八、不足与局限

1. **检测能力的根本边界**：实体替换和微妙语义弱化等“就地编辑”型攻击无法被表面信号检测捕捉——无论阈值、权重或检索深度如何调整。这是表面信号检测固有的架构性局限，需外部世界知识（如结构化知识库）才能解决。
2. **生成的忠实度缺口**：论文明确声明只检测生成前的中毒上下文，**未端到端测量 LLM 是否真正采纳注入的错误信息**（即攻击成功率）。两者之间可能存在差异。
3. **样本量偏小**：每轮仅 15 个投毒样本，召回率置信区间宽（如混合攻击 19.8–64.3%），统计功效有限。
4. **跨数据集泛化不足**：FEVER 上的负面结果（73%，低于 85% 基线）限制了外部效度，说明数据集特定校准不可避免。
5. **与现有防御缺乏定量对比**：未与 certifiably robust aggregation 或 trust-aware retrieval filtering 等方法做实验层面的横向比较，削弱了“相对优越性”的论证强度。
6. **攻击类型覆盖有限**：仅评估规则驱动攻击，未覆盖优化式对抗文档（如 collision-style attacks）、更复杂的目标投毒策略。
7. **计算开销高**：约每样本 14.7 秒（17 倍于基础 RAG）的开销限制实时交互部署，只能作为异步或批处理门控使用；GPU 加速虽被提出，但未实际验证。
8. **人为选择权重**：α=0.4、β=0.35、γ=0.25 为手动设定，虽验证了局部鲁棒性，但全局最优性未得到保证。
