## 摘要
网络化大型语言模型（LLM）智能体从电子邮件、云存储、日历、交易平台和Web服务中检索信息，以完成会产生持久外部效应的多步骤任务。合法执行所需的内容也可能包含间接提示注入，这些注入会重定向工具使用、篡改敏感参数或破坏任务完成。现有防御主要限制不受信任的内容或单个工具调用，导致用户意图、运行时证据、已实现效果和任务完成之间缺乏充分关联。我们提出了TraceGrant，一种通过显式合同（Contract）管理网络化LLM智能体任务-效果生命周期的安全框架。在执行前，TraceGrant根据可信用户请求建立任务-效果边界。在执行期间，被允许的证据只能实例化合同已建立的权限。在执行后，任务完成情况根据实际工具结果进行验证。在固定基准设置下，针对949个AgentDojo和400个Agent Security Bench攻击案例，TraceGrant在77.32%和83.00%的攻击率下保持了效用，同时未记录到任何攻击成功。我们进一步通过白盒防御感知攻击、合同质量分析、阶段消融、针对性压力测试和运行时开销测量来评估TraceGrant。结果表明，TraceGrant提供了一个统一治理层，将可信用户意图、运行时证据、具体工具执行和验证后的任务完成关联起来。

## Abstract
Networked large language model (LLM) agents retrieve information from email, cloud storage, calendars, transaction platforms, and Web services to complete multistep tasks that produce persistent external effects. The same content needed for legitimate execution may also contain indirect prompt injections that redirect tool use, alter sensitive arguments, or disrupt task completion. Existing defenses mainly constrain untrusted content or individual tool calls, leaving user intent, runtime evidence, realized effects, and task completion insufficiently connected. We present TraceGrant, a security framework that governs the task-effect lifecycle of networked LLM agents through an explicit Contract. Before execution, TraceGrant establishes a task-effect boundary from the trusted user request. During execution, admitted evidence can instantiate only authority already established by the Contract. After execution, task completion is verified against actual tool results. Across 949 AgentDojo and 400 Agent Security Bench attack cases under fixed benchmark settings, TraceGrant recorded no attack successes while retaining utility under attack rates of 77.32% and 83.00%, respectively. We further evaluate TraceGrant through white-box defense-aware attacks, Contract quality analysis, stage ablations, targeted stress tests, and runtime overhead measurements. The results show that TraceGrant provides a unified governance layer that connects trusted user intent, runtime evidence, concrete tool execution, and verified task completion.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM 智能体正从“仅生成回复”转向“实际执行操作”，通过邮件、云存储、日历、支付系统等工具接口产生现实世界影响。
- **核心矛盾**：合法任务常依赖不可信的运行时内容（如邮件、共享文档、网页）来决定后续操作参数；同一内容可能携带间接提示注入，劫持工具调用、篡改接收方/账户/金额等授权参数、扩大资源范围或触发额外操作。
- **现有不足**：已有限制不可信内容（CaMeL、FIDES、IsolateGPT）、工具授权策略（Progent、AgentSpec）和任务对齐（Task Shield）等方法，大多在“单条消息”或“单个工具调用”层面作战，未将用户意图、运行时证据、具体外部效果和任务完成状态串成一条可验证的链。
- **TraceGrant 的价值**：提出以显式 Contract 为中心的任务-效果生命周期治理框架，回答“运行时信息如何补充授权任务所需值、却不得获得重新定义任务效果的权力”这一核心安全问题。

## 2. 方法论：核心思想、关键技术细节与流程

### 2.1 核心思想
- **构建三层阶段治理**：
  1. **执行前**：从可信用户请求和冻结的工具注册表生成 POEC Contract，确定任务-效果边界。
  2. **执行中**：运行时数据只作为“已有权限的证据”而非“新权限的来源”，通过证据接纳、参数证明、预算检查完成状态化授权。
  3. **执行后**：以实际工具结果验证完成情况，区分“授权”“原生执行成功”“任务完成”三个状态。
- **任务-效果边界**：区分权威性参数（决定效果对象、范围，如收件人、账户、金额）和载荷参数（业务内容）。
- **设计原则**：外部数据可提供值，但不可创造、扩大或替换效果权限。

### 2.2 关键技术细节

#### (1) 执行前：合同建立
- **POEC Contract** 由四部分组成：
  - `MAY`（Permission）：允许的工具、操作、目标范围、参数约束、调用预算；
  - `MUST`（Obligation）：将证据获取、外部效果、输出需求组织为依赖感知的义务图；
  - `BIND`（Evidence）：定义每个权威性参数的允许来源、期望类型、约束和推导规则；
  - `VERIFY`（Completion）：规定工具、参数、执行状态、后置条件须满足的可观察要求。
- **静态合同分析**：候选合同经确定性规范化后，依次检查 `WellFormed`、`ControlSafe`（依赖无环且可达）、`FlowSafe`（每个权威性参数有合法 BIND 源）、`ScopeSafe`、`VerifySafe`；任一项失败则拒绝生成可执行合同（Algorithm 1）。

#### (2) 执行中：运行时授权
- **义务账本（Obligation Ledger）** 维护每个义务的状态（PENDING / ACTIVE / VERIFIED / WAIVED）、已接纳证据、剩余预算和证书生命周期。
- **证据接纳**（公式 4）：仅当结果满足 ACTIVE 义务、来源工具匹配、查询匹配、类型匹配和完整性约束时，才被提升为任务证据；否则仅为普通上下文观测。
- **PDP 决策**（公式 5）：对候选效果进行状态化判定，结果为 `ALLOW`、`PROOF-GAP`、`STEP UP AUTH` 或 `DENY`；每种分支都有明确处置（如 PROOF-GAP 返回缺失参数让代理补充查询）。
- **一次性效果证书**（公式 6）：每次 ALLOW 后签发，绑定 Contract ID、当前义务、规范化参数、参数证明和预算状态；PEP 仅在请求与有效证书精确匹配时调度（公式 7），证书消费后不可再用。
- **集值证据**由 LLM 外部的确定性选择器解析，须可复现才能被 PDP 接受。

#### (3) 执行后：接收与任务闭环
- **效果接收**（公式 8）：检查原生执行结果、实际参数与证书匹配、后置条件满足、参数出处仍然有效；成功才推进义务状态。
- **最终答案门**（公式 9）：所有硬义务均处于 VERIFIED 或 WAIVED 才接受任务成功声明；防止“工具失败但声称完成”“部分执行冒充完成”等情况。

### 2.3 条件性安全保证（公式 10）
- 在“合同语义正确、证据字段语义真实、PEP 完整中介、证书与账本原子操作、执行精确符合调度”等假设下，所有可达效果均落在用户授权边界 A(u) 内；跨网络部署还需认证、防重放、限时的效果证书。

## 3. 实验设计：数据集、基准与对比方法

### 3.1 数据集与基准
- **AgentDojo**：
  - 4 个交互环境（Workspace、Slack、Travel、Banking）；
  - 97 个用户任务（良性）、949 个攻击用例（良性任务 × 注入任务组合）；
  - 提供工具模式、效用评估器和攻击目标评估器。
- **Agent Security Bench (ASB)**：
  - 覆盖系统管理、金融分析、法律服务、医疗、教育、心理咨询、电商、航天设计、学术搜索、自动驾驶等 10 个领域；
  - 20 个良性工具、400 个攻击工具、51 个良性任务、400 个攻击指令；
  - 采用间接提示注入场景。

### 3.2 对比方法
- **NoDefense**：无安全层参考；
- **Progent**：策略语言 + 工具调用确定性评估；
- **CaMeL**：可信控制流与不可信数据流分离 + 能力约束；
- **AgentSpec**：可定制行为规范执行；
- **IsolateGPT**：执行隔离架构；
- **FIDES**：信息流控制（仅 AgentDojo，因 ASB 接口/标注不兼容未评测）；
- **Task Shield**：任务对齐（作者重新实现）。

### 3.3 模型配置
- 主配置：任务执行模型统一使用 DeepSeek-V4-Flash。
- 交叉验证：另使用 Gemini 3.6 Flash、Qwen3.7-Plus、GLM-5.2 作为任务执行模型（Semantic Contract Compiler 固定为 DeepSeek-V4-Flash）。

### 3.4 评估指标
- TSR（良性任务成功率）、UUA（攻击场景下合法任务效用）、ASR（攻击成功率）为主指标；
- 附加指标：SVR（规范违反率）、SOOR（步骤乱序率）、FCR（虚假完成声明率）、VCR（合同有效生成率）、MAY / MUST F1、BIND / VERIFY 准确率等。

## 6. 主要结论与发现

- **固定基准下零攻击成功**：AgentDojo（949 个用例）与 ASB（400 个用例）上的攻击成功率均为 0.00%，优于所有现有基线；同时 UUA 分别达 77.32% 和 83.00%，优于多数基线。
- **模型敏感性低**：四个任务执行模型在两个基准上均未出现攻击成功，说明安全保证主要来自结构化治理层而非模型判断。
- **三阶段设计各有必要**：缺少预执行合同使规范违反率升至 64.19%、虚假完成声明升至 42.74%；缺少运行时强制使 ASR 升至 0.76%、对抗候选拒绝率从 100% 降至 11.4%；缺少接收（Receipt）使 TSR 降至 68.42%、错误完成接受率升至 58.2%。
- **合同质量高**：97 个生成合同全部通过静态分析；86 个与参考边界无实质偏差、6 个语义等价、5 个保守（只影响效用）、0 个宽松（未扩大授权边界）。
- **压力测试表现**：运行时强制对错误来源、范围扩张、乱序执行、重复效果的全部对抗候选 100% 拒绝；Receipt 对执行故障、参数漂移、后置条件违背的检出率 100%；最终答案门将错误完成接受率降至 0%。
- **白盒攻击揭示剩余风险**：100 个定向攻击中有 2 个成功（2.0% ASR），根本原因是“证据对象语义真实性”不可用结构验证保证（bill 文件和 landlord 通知被投毒）以及合同编译器对可选权威性参数的 BIND 覆盖不完整。
- **运行时开销可控**：AgentDojo 上平均延迟增加约 1.32 倍、token 增加 1.37 倍；ASB 上延迟增加 1.41 倍、token 增加 1.25 倍。

## 7. 优点

1. **统一的“意图-证据-效果-完成”链**：不是零散地防御某一环节，而是将用户请求、运行时证据、工具调度和任务完成验证串成一个可审计的生命周期，填补了现有工作在“效果层面”缺乏治理的空白。
2. **契约先行、静态可验证**：POEC Contract 在执行前生成并经过四类静态检查（ControlSafe、FlowSafe、ScopeSafe、VerifySafe），将许多安全问题提前暴露并拒绝，而不是完全依赖推理时的模型自觉。
3. **证据与权限分离**：运行时数据被严格限定为“填补参数值”的来源，而不能扩大权限范围，从根上遏制了间接提示注入“借壳授权”的攻击模式。
4. **状态化、原子化授权**：一次性效果证书、义务账本和 PEP 强制中介，确保授权、执行、验证三个动作不可分割，避免“授权后执行走样”的空窗。
5. **实验体系完整且强硬**：涵盖全量基准、白盒防御感知攻击、故障注入、消融分析、多模型交叉验证，且攻击者假设较强（知晓防御结构），结论可信度高。
6. **工程可实现性较好**：不依赖模型微调，可作为通用治理层叠加在现有 LLM 智能体框架之上；运行时开销在可控范围内（延迟约 1.3–1.4 倍）。
7. **诚实披露剩余风险**：白盒实验中报告了 2 个成功攻击案例并分析了根因，而不是只展示“零攻击”的乐观结论，对后续研究者具参考价值。

## 8. 不足与局限性

1. **依赖合同编译器的语义理解**：POEC Contract 需从自然语言用户请求中提取，若编译器（Semantic Contract Compiler）误解请求，则后续所有保证都建立在错误边界之上。论文仅以“合同语义正确”作为假设前提，缺少对编译器失败模式的系统分析。
2. **证据字段语义真实性无法结构化保证**：白盒攻击暴露出的 2 个成功案例表明，即使证据来源、类型和查询匹配，证据的“语义真实性”（如被投毒的 bill 文件）仍可能被颠覆；论文承认这一点，但未给出对应防御机制。
3. **仅覆盖工具调用层的安全**：未涉及输出内容隐私泄露、多智能体间通信投毒、长期记忆污染、供应链（工具本身被篡改）等更广泛威胁。
4. **ASB 上的实验深度不足**：ASB 只报告了总体安全性、效用与开销，并未像 AgentDojo 那样做消融、压力测试和合同质量量化分析，削弱了跨基准的一致性论证。
5. **基线可比性存在局限**：如 FIDES 因接口不兼容未在 ASB 上评测，Task Shield 为作者自行重新实现，可能与原论文行为有差异；部分基线的实际部署配置也可能未达最优。
6. **无端到端可复现物**：未提供代码仓库、数据划分、随机种子、提示模板等复现细节，第三方难以完整复现实验结果。
7. **计算资源信息缺失**：未披露硬件环境与算力开销总量，仅报告了端到端时间与 token 量；对于需要比较成本收益或部署规模的读者不够充分。
8. **“任务完成”定义的固有模糊性**：VERIFY 规则可由合同编译器生成，但“什么算完成”仍受自然语言理解质量影响；且 WAIVED（豁免）机制若使用不当，可能成为攻击者利用的软化点。

## 9. 思考与启发

1. **治理层而非模型层防御是可行方向**：TraceGrant 的零攻击结果不依赖于模型是否“聪明”，而依赖于“外部数据无法触碰授权边界”的结构约束。这与 RLHF、系统提示词加固等模型内防御形成互补。
2. **“效果”是智能体安全的第一公民**：LLM 智能体与传统 RAG 系统的本质区别在于会产生持久外部效果。安全模型应将“效果对象、范围、次数、完成条件”显式建模范式，而非仅关注“回答是否安全”。
3. **契约范式可类比于能力安全（capability security）**：一次性效果证书、细粒度 DCL、PEP 强制中介等概念，与操作系统能力模型（capability-based security）高度相似。将操作系统的成熟安全理念引入 LLM 智能体领域，是高效且可信的路径。
4. **需要进一步研究“证据真实性”**：本工作的剩余风险集中在无法由结构验证保证的语义真实性。未来可结合带签名来源（如 DKIM、数字签名）、多源交叉验证、公钥基础设施等方式强化证据链。
5. **可考虑自动化合同学习与动态更新**：当前合同由人工+编译器生成，若能让系统从历史合法任务中自动归纳合同模板，并在运行中根据用户反馈修正，将提升扩展性。
6. **评测方法值得借鉴**：同时使用良性任务成功率（TSR）与攻击场景下的合法任务效用（UUA）两个维度，避免“牺牲一切换取安全”的无效防御，这一评测范式可以推广到更广泛的智能体安全研究。

## 10. 关键概念术语速查表

| 术语 | 含义 |
|------|------|
| POEC Contract | 执行前生成的显式合同，含 Permission（MAY）、Obligation（MUST）、Binding（BIND）、Verification（VERIFY）四部分 |
| 任务-效果边界 | 区分权威性参数（决定效果对象/范围）与载荷参数（业务内容）的界限 |
| 权威性参数 | 决定外部效果对象、范围、金额等的关键参数（如收件人、账户、金额） |
| 义务账本 | 跟踪义务状态、已接纳证据、剩余预算的运行时账本 |
| 证据接纳 | 仅当外部数据满足义务状态、来源工具、查询、类型、完整性约束时才成为任务证据的过程 |
| PDP | Policy Decision Point，做状态化授权决策（ALLOW / PROOF-GAP / STEP UP AUTH / DENY） |
| PEP | Policy Enforcement Point，仅在请求与有效证书精确匹配时实际调度工具 |
| 一次性效果证书 | 每次 ALLOW 后签发、绑定合同 ID、义务、参数与预算的短时凭证，消费后失效 |
| SVR | Specification Violation Rate，规范违反率 |
| SOOR | Step Out-of-order Rate，步骤乱序率 |
| FCR | False Completion Claim Rate，虚假完成声明率 |
| UUA | Utility under Attack，攻击场景下合法任务的成功效用 |
| ASR | Attack Success Rate，攻击成功率 |
| TSR | Task Success Rate，良性任务成功率 |
| White-box attack | 攻击者知晓防御结构与机制后发起的定向攻击 |

---

**总结**：TraceGrant 以显式合同为载体，把 LLM 智能体的安全治理从“消息级过滤”和“单调用授权”提升到“任务级、效果级、全生命周期治理”，在主流基准上实现了固定设置下的零攻击成功，并系统性地验证了三阶段设计的必要性。其剩余风险集中于合同语义理解与证据语义真实性两个难以结构化保证的环节，为后续研究指明了方向。
