## 摘要
使用工具的LLM智能体仍然容易受到间接提示注入的影响，因为可信指令与不可信观测共享同一上下文，使得恶意内容能够左右关键的输入过滤防御。多路径共识防御仍会留下较高的攻击成功率，因为它们检查的是内容或聚合输出，而非对实际效果进行授权，尤其对于工具内攻击（within-tool attack）而言，这种攻击保留预期的工具但操纵其参数。诸如CaMeL的数据流控制提供了更强的保证，但会带来显著的时间延迟，限制了实际部署。我们提出ToolFence，它在执行前编译带类型的授权蓝图，通过确定性监控器强制执行，并在蓝图不完整时请求裁判授予新能力，而不是对每个具体调用进行裁决。ToolFence具有两个关键优势。第一，其细粒度、溯源感知的授权使系统能够区分用户授权的值与不可信观测，从而有效应对工具内攻击。第二，其确定性快速路径和能力级运行时授权大幅减少了昂贵裁判调用的频率，从而提升运行时效率。在AgentDojo上使用Qwen3-max时，ToolFence将总体ASR降至接近零，仅带来3.80个百分点的干净效用下降以及实际可行的运行时开销。

## Abstract
Tool-using LLM agents remain vulnerable to indirect prompt injection because trusted instructions and untrusted observations share one context, allowing malicious content to steer consequential input-filtering defenses. Multi-path consensus defenses still leave a high attack success rate because they examine content or aggregated outputs rather than authorizing effects, especially for the within-tool attack, which preserves the intended tool but manipulates its arguments. Data-Flow Control such as CaMeL provides stronger guarantees, but incurs substantial time latency that limits practical deployment. We introduce ToolFence, which compiles a typed authorization blueprint before execution, enforces it through a deterministic monitor, and when the blueprint is incomplete asks a judge to grant new capabilities rather than adjudicate each concrete call. ToolFence provides two key advantages. First, its fine-grained provenance-aware authorization enables the system to distinguish user-authorized values from untrusted observations, effectively addressing the within-tool attack. Second, its deterministic fast path and capability-level runtime grants substantially reduce the frequency of expensive judge calls, improving runtime efficiency. On AgentDojo with Qwen3-max, ToolFence reduces overall ASR to near zero with only a 3.80 percentage-point clean-utility drop and practical runtime overhead.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体已从被动文本生成演进为可调用外部工具、检索信息、修改持久状态（发消息、转账、访问私密记录）的执行体。这种能力带来一个根本性安全弱点——**系统策略、用户请求、检索文档、邮件、网页和工具中间输出共享同一模型上下文**。
- **核心威胁**：模型无法可靠区分“承载授权的指令”与“不可信数据”，攻击者可在外部内容中嵌入指令，诱导智能体代其行事，即**间接提示注入（Indirect Prompt Injection, IPI）**。该威胁已从简单的“忽略之前指令”演进为针对工具描述、聊天模板边界、记忆和多步交互循环的结构化攻击，因此仅防御初始提示是不够的——授权必须覆盖完整执行轨迹。
- **现有防御的三类失败模式**：
  - **工具内劫持（Within-tool hijacking）防御不足**：与跨工具攻击（诱导调用未授权工具）不同，工具内攻击保留预期工具但篡改其权威敏感参数（收件人、金额、URL、目标）。RepeatPrompt、ToolFilter、输入过滤器、结构感知方法和 SecInfer 等共识防御均忽视可执行权限，仍对其脆弱。
  - **强隔离开销过高**：CaMeL 通过溯源追踪和能力执行提供强控制/数据流隔离，但需要定制执行流水线，延迟和成本显著增加。
  - **静态工具过滤损害效用**：静态工具过滤器虽避免运行时裁判，但无法预见所有合法能力，导致初始计划之外的良性调用被拒绝，任务无法完成。
- **核心洞察**：安全相关单元既不是单次调用（太细，重复裁判浪费），也不是整个会话（太粗，无法适应），而是**能力（capability）**——授权动作的抽象形态：工具、效果类别、以及权威敏感参数上的溯源约束。“从用户指定的账单文件中提取收件人并发送邮件”是一个能力，它不固定具体收件人字符串，而是固定收件人的来源。授权该形态一次，即可在每次调用时确定性地重检具体值。

## 2. 方法论

### 2.1 核心思想

ToolFence 是一种**推理时防御**，将**能力授权与动作执行分离**。它在智能体消费任何外部内容之前，将已认证的用户查询编译为带类型的授权蓝图；用确定性监控器零 LLM 成本地强制执行；当蓝图不完整时，请求裁判授予新**能力**（而非裁决每次具体调用），并支持跨会话缓存复用。

### 2.2 威胁模型与设计目标

- **威胁模型**：智能体具有基座模型 fθ、已认证用户查询 q、工具集 T 和多步执行轨迹。攻击者可在任意不可信通道（检索文档、工具输出、网页）注入任意文本，目标是诱导智能体执行**未授权动作**（效果或权威敏感参数服务于用户未声明的目标）。不假设基座模型能抵抗注入，仅假设存在位于模型提议动作与工具运行时之间的**可信执行控制器**。
- **三个设计目标**：
  - **确定性优先**：常见情况（蓝图已授权的调用）必须无需 LLM 调用即可执行，使延迟和成本不随工具调用次数增长，安全边界不依赖可能出错的裁判。
  - **无隐藏饥饿**：工具始终对智能体可见，未授权调用是显式、可恢复的拒绝，并带诊断信息，避免规划器遗漏导致能力饥饿而无审查事件。
  - **能力级授权**：静态蓝图不完整时，回退应授权一个能力（工具–效果–溯源约束形态），而非单个具体动作，使判决可复用，影响范围受声明的数据流边限制。

### 2.3 细粒度授权蓝图（Typed Authorization Blueprint）

- **构建者**：策略架构师（Policy Architect）是一个隔离的 LLM 调用，**仅看到 q 和控制器拥有的工具 schema，从不观察不可信内容**。输出为带类型的计划 **P = (M, C)**。
- **工具清单 M**：为每个工具分配效果标签 **e ∈ {READ, LOCAL_COMPUTE, COMMUNICATION, FINANCIAL, EXTERNAL_WRITE, DELETE, …}**，以及每个参数的权威敏感性标志。
- **能力集 C = {c₁, …, cₙ}**：每个能力是元组
  **c = (tool, e, {pⱼ ↦ βⱼ}, κ, r)**
  其中 βⱼ 为参数绑定，κ 为调用预算，r 为可复用标志。
- **四种绑定类型（βⱼ）**：
  - **LITERAL**：值直接来自用户请求 q；
  - **DERIVED**：值来自命名源工具 s 的输出，即 v ∈ Obs(s)；
  - **TEMPLATE**：值匹配基于 q 和源工具认证的模板；
  - **FREE**：参数非权威敏感，可由智能体自选。
- **关键设计**：蓝图记录**溯源约束而非具体值**，这是运行时裁判能独立于具体参数授权能力形态的基础。
- **示例**：传统工具白名单只记录 `send_money ∈ T allowed`，过于粗粒度；ToolFence 授权的是 `send_money : recipient ← read_file("bill.txt"), amount ← q`，即不仅授权使用工具，还约束每个安全敏感参数的来源。

### 2.4 确定性监控器（Deterministic Monitor）

每个提议的工具调用 **a = (tool, x)** 首先由无 LLM 的确定性监控器匹配蓝图，检查三项属性：

1. **能力匹配**：存在 c ∈ C，其 tool 等于 a.tool，且声明的参数覆盖 a 的所有参数；
2. **绑定合规**：对每个 pⱼ ↦ vⱼ，值满足 βⱼ——LITERAL 必须出现在 q 中；DERIVED 必须出现在已执行声明源工具的输出中；TEMPLATE 必须匹配模式且源工具已执行；
3. **预算**：c 的已提交调用数低于 κ（或 r = TRUE 的可复用读能力）。

三项均满足则走**快速路径**立即派发。

- **读自动放行（Read auto-allow）**：所有参数溯源均为 USER 的只读调用不会引入新访问目标，自动放行；但参数来自工具输出或模型的读（如从注入网页提取的 URL）不放行，送裁判。论文试点显示无条件信任读操作会导致 **60% ASR**。

### 2.5 动态运行时能力授予（Dynamic Runtime Capability Grant）

- **触发**：调用未命中蓝图时，不立即拒绝，也不问裁判“这个具体动作是否可接受”，而是请求裁判授予新能力并扩展运行蓝图，使同形态后续调用由确定性监控器处理。
- **授权提案构建**：控制器为每个参数计算溯源标签 **π(pⱼ) ∈ {USER, TOOL, MODEL}**（值出现在 q 中 / 出现在某已执行源工具输出中 / 均不出现），据此构造候选能力 ĉ。**若任何权威敏感参数不可溯源到用户或声明源工具，提案被直接拒绝（ĉ = ⊥）**，在咨询裁判之前就阻断典型注入模式。
- **裁判决策**：裁判收到能力形态（工具、效果、每个参数的溯源约束和权威敏感性标志），**但不接收具体参数值**。决定 **Grant(ĉ) ∈ {GRANT, DENY}**；GRANT 要求能力服务于已认证请求，且每个权威敏感参数约束为 USER 或请求命名的工具源。GRANT 后调用 GrantCapability(ĉ) 将 ĉ 追加到运行计划 C，重新走快速路径派发；DENY 则回退到单次逐调用裁判作为最后手段。

### 2.6 跨会话能力缓存（Cross-Session Capability Cache）

- 能力形态与查询无关，可跨会话重现。维护进程级缓存 G，键为
  **sig(c) = (tool, e, {pⱼ ↦ (βⱼ, source_toolsⱼ)})**
- **缓存仅存储能力形态**（绑定类型和源工具名），**从不存储具体参数值、证据文本或先前工具输出**。新会话复用缓存能力时，每个具体参数仍须针对**当前会话**中声明的源执行重新验证。
- 实验显示该机制将裁判调用减少 **43%**，同时保持 ASR 近零。

### 2.7 安全性质：失效关闭授权（Fail-Closed Authorization）

- **a ∉ C ∪ G ∧ Grant(ĉ) ≠ GRANT ⟹ a 不被派发**
- **∃ pⱼ : AUTH_SENSITIVE(pⱼ) ∧ π(pⱼ) = MODEL ⟹ ĉ = ⊥**（模型发明的权威敏感参数永不到达裁判）
- **PARSE_FAIL(ĉ) ⟹ Grant(ĉ) = DENY**（裁判输出无法解析时默认拒绝）
- 结论：即使模型完全被不可信工具输出控制，也无法执行蓝图和已授予能力范围之外的动作，因为处于权限边界的是控制器而非模型。

### 2.8 算法流程（Algorithm 1 摘要）

1. 架构师编译蓝图 P ← Architect(q, T)；
2. 注入缓存授权 C ← P.capabilities ∪ G；
3. 对每个智能体步骤：接收提议动作 aₘ；
4. 确定性监控器检查 d ← Monitor.prepare(aₘ, C)，若允许则派发；
5. 否则计算溯源 π ← Provenance(aₘ.x, q, Obs)；
6. 若 ReadAutoAllow 则派发；
7. 构造 ĉ ← BuildGrant(aₘ, π)（模型生成权威敏感参数则为 ⊥）；
8. 若 ĉ ≠ ⊥ 且缓存命中，则授予、重备、派发；
9. 若 ĉ ≠ ⊥ 且裁判 GRANT，则授予、写入缓存、重备、派发；
10. 否则回退逐调用裁判，DENY 则返回拒绝消息。

## 3. 实验设计

### 3.1 数据集与 Benchmark

- **基准**：**AgentDojo**，衡量真实工具使用工作流中的安全性和效用，覆盖四个领域：**Workspace、Slack、Travel、Banking**，共 **629 对注入任务**（97 个良性用户任务 × 27 个注入任务）。
- **参数感知划分（Parameter-Aware Split）**：为直接暴露本文研究的授权差距，基于良性和恶意任务的可执行 ground-truth 工具调用构造：
  - **跨工具升级（Escalation）**：攻击需要至少一个良性任务未使用的工具 —— **524 对**；
  - **工具内劫持（Within-tool）**：攻击仅使用良性任务已有工具，但改变权威敏感参数（收件人、目标、URL、文件路径、账户、金额、权限）—— **85 对**；
  - **模糊（Ambiguous）**：无可比可执行恶意工具调用 —— **20 对**（主要为 Travel 套件的非工具拒绝服务攻击），保持为独立层，主分析聚焦 609 对。
- **划分分布**：Workspace 240（222/18/0）、Slack 105（86/19/0）、Travel 140（114/6/20）、Banking 144（102/42/0）。

### 3.2 攻击策略（6 种）

- **Direct**（直接嵌入恶意指令）、**Ignore Previous**（显式覆盖先前指令）、**Important Instructions**（提高注入指令的表观优先级）、**InjecAgent**（面向智能体的间接注入模板）、**System Message**（冒充特权系统级指令）、**Tool Knowledge**（利用工具接口知识操纵工具选择或权威敏感参数）。主表 ASR 为六种攻击的平均。

### 3.
