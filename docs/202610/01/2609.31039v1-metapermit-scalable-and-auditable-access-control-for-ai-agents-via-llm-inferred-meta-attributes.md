## 摘要
配备工具的自主AI智能体的兴起带来了显著的安全风险，范围从非预期的工具误用到通过间接提示注入（IPI）攻击进行的对抗性操纵。在实践中，已部署的智能体系统（如OpenAI Codex和Claude Code）通过粗粒度权限规则与基于LLM的对单个提议动作的判断相结合来保护工具调用。然而，这两个组件都有重要局限：静态策略必须预先设想可能的用户意图，因此无法扩展到开放式任务；而LLM驱动的授权支持动态决策，但会产生不一致的结果，并且仍然容易受到有针对性的IPI攻击。为提供可扩展且更一致的授权，我们提出MetaPermit，一种基于策略的工具访问控制框架，将语义推断与安全执行解耦。通过分析智能体-用户交互，我们推导出一组紧凑、任务无关的元属性，用以刻画用户意图、执行上下文与所提议工具调用之间的关系。这些元属性使MetaPermit无需枚举用户意图即可授权工具使用。在运行时，LLM推断每个所提议工具调用的元属性值，而固定策略评估这些值以允许或拒绝该调用，从而使每个决策都能通过推断值及所应用策略规则进行审计。我们在AgentDojo和AgentDyn基准上，跨七个任务套件和五种攻击方法，使用两个广泛部署的开放权重LLM评估MetaPermit。结果表明，MetaPermit产生的授权决策一致性比LLM驱动的授权高31%，并且在任务完成度（提升最高达109%）以及对IPI攻击的鲁棒性（未执行任何恶意工具调用）两方面均优于最先进的防御方法CaMeL和IPIGuard。

## Abstract
The rise of autonomous AI agents equipped with tools has introduced significant security risks, ranging from unintended tool misuse to adversarial manipulation through Indirect Prompt Injection (IPI) attacks. In practice, deployed agent systems such as OpenAI Codex and Claude Code protect tool invocations through a combination of coarse-grained permission rules and LLM-based judgments about individual proposed actions. Both components, however, have important limitations: static policies must anticipate possible user intents and therefore do not scale to open-ended tasks, while LLM-driven authorization supports dynamic decisions but produces inconsistent outcomes and remains vulnerable to targeted IPI attacks. To provide scalable and more consistent authorization, we propose MetaPermit, a policy-based tool access-control framework that decouples semantic inference from security enforcement. By analyzing agent-user interactions, we derive a compact, task-independent set of meta-attributes that capture the relationships among the user's intent, the execution context, and the proposed tool call. These meta-attributes allow MetaPermit to authorize tool use without enumerating user intents. At runtime, an LLM infers the meta-attribute values for each proposed tool call, while a fixed policy evaluates these values to allow or deny the call, making each decision auditable through the inferred values and the applied policy rule. We evaluate MetaPermit on the AgentDojo and AgentDyn benchmarks, across seven task suites and five attack methods, using two widely deployed open-weight LLMs. The results show that MetaPermit produces 31% more consistent authorization decisions than LLM-driven authorization and outperforms the state-of-the-art defenses CaMeL and IPIGuard in both task completion, with improvements of up to 109%, and robustness to IPI attacks, with no malicious tool calls executed.

# MetaPermit 论文总结

## 1. 核心问题与研究背景

- **背景**：LLM 应用已从聊天机器人演化为可自主规划、调用多工具、执行长动作序列的智能体。智能体必须把外部内容（邮箱、网页、共享文档、第三方服务输出）当作输入，而这类内容既非开发者撰写、也未经用户审查。
- **核心威胁**：由于"指令"与"数据"共享同一上下文通道，嵌入外部内容中的对抗文本可与用户请求进入同一上下文窗口，并被当作来自用户的指令执行，即**间接提示注入（IPI）**攻击。
- **现有防御的两难**：
  - **静态策略类**（如 CSAgent、AC4A、CaMeL）：确定性、可预测，但需预先枚举意图/资源，无法覆盖开放式任务，且无法区分同一权限的合法与恶意使用（如"给 Bob 退款"与"给攻击者 Eve 转账"都用 `send_money`）。
  - **LLM 驱动授权类**（如 OpenAI Codex、Claude Code 的模型判断；Conseca、Progent、IPIGuard）：无需预先枚举意图，但决策具有随机性，语义相近任务可能得到不同结论，且易被定向 IPI 说服。
- **动机示例**：Alice 要求智能体向 Bob 退还 1,500 美元；智能体读取交易记录时遇到 Eve 植入的伪造指令要求转账给 Eve。无防御智能体可能照做，静态工具级策略无法在不写"收款人白名单"的情况下区分两笔转账。
- **整体含义**：需要一个既能扩展到开放式意图、又能保持决策一致与可审计的智能体工具访问控制框架。

## 2. 方法论

### 2.1 核心思想

- **解耦语义推断与安全执行**：LLM 只负责"描述"工具调用的安全相关属性（从固定、类型化的取值集合中选择），**不产生最终裁决**；固定策略引擎负责"裁决"；执行门负责"执行"。
- **元属性（meta-attributes）**：刻画用户请求、执行上下文与候选工具调用之间**语义关系**的抽象安全维度，区别于描述实体或系统状态的常规 ABAC 属性。元属性及其取值集合**预定义**，作为少量通用策略的决策因子。
- **三项设计需求**：意图无关策略（策略随安全维度而非意图数量增长）、受限模型权限（LLM 只能从固定词汇取值，不能创建规则或给出裁决）、确定性执行（同一元属性向量恒映射到同一裁决）。

### 2.2 五个元属性（Table 2）

| 属性 | 取值 | 回答的问题 |
|---|---|---|
| `intent_is_action` | true / false | 用户想要动作还是仅对话 |
| `intent_clarity` | clear / ambiguous / incomprehensible | 用户目标是否可无歧义解读 |
| `intent_risk` | high / low | 动作是否涉及不可逆伤害或隐私泄露 |
| `intent_tool_alignment` | direct / prerequisite / supporting / misaligned | 所调工具是否服务于用户目标 |
| `intent_input_alignment` | aligned / misaligned | 调用参数是否被用户请求所支持 |

- 前两者**仅依赖可信的用户原始请求**，因此检索内容无法影响其取值；后三者可使用工具调用参数。
- 工具对齐与输入对齐分开建模：检索类工具可能是任务必需，但后续调用若使用从检索内容复制的收款人/路径/URL，则输入不对齐。

### 2.3 端到端流程

1. **推断模块（LLM）**：输入用户原始请求、可信的工具描述、调用参数、此前工具结果历史；输出五元属性向量。要求严格输出 JSON；解析失败时**fail-closed**（视为 action + incomprehensible + high risk + 双 misaligned，被默认规则拒绝）。
2. **策略引擎**：有序规则列表 ΠS = (r₁,…,rₙ,rₙ₊₁)，每条 rⱼ = (φⱼ, eⱼ, oⱼ)，φ 为元属性谓词，e ∈ {Allow, Deny}，o 为反馈。**首条命中规则生效，末条默认拒绝**。
   - 表 7 规则：R1 非动作→拒绝；R2 意图不可理解→拒绝；R3 工具不对齐→拒绝；R4 参数不对齐→拒绝；R5 歧义+高风险→拒绝；R6 非必需+高风险→拒绝；R7 其余低风险→允许；R8 清晰必需调用→允许；Default→拒绝。
3. **执行门**：Allow 则原样转发；Deny 则阻断并以**合成工具结果**返回带规则依据的反馈（如"输入与用户请求不对齐"），引导智能体重规划而非简单终止。

### 2.4 策略构建与扩展

- 从安全目标出发，提炼可复用的关系性问题 → 每问一个元属性（有限取值 + 定义），每个安全目标编码为一条或多条有序规则。
- 新需求只需**新增元属性并更新依赖它的规则**，接口、执行路径与无关规则不变；策略规模随安全维度增长，而非随意图空间增长。
- 接口与推断方式无关：可单模型联合推断，也可多个分类器分别推断后拼成同一向量。

## 6. 主要结果（据论文报告）

- **安全性**：在全部套件与攻击模板上，MetaPermit 相较 No Defense 将 ASR 压至很低水平，且通常优于 CaMeL 与 IPIGuard。基线在开放式套件（AgentDyn 的 Shopping/Github/Dailylife）上退化更明显——CaMeL 受限于预声明能力，IPIGuard 受限于工具依赖图，二者难以处理"合法但未被枚举"的调用组合。
- **可用性**：无攻击条件下 UA 与 No Defense 接近，说明元属性与默认规则未系统性牺牲正常任务完成；在 AgentDojo 的 banking 等高风险套件中，UA 可能有小幅下降，代价来自对"歧义 + 高风险"调用的保守拒绝。
- **联合指标 Secure-Usable**：MetaPermit 在"既完成任务又不被攻破"的联合比例上领先，体现出安全与可用并非零和。
- **按攻击模板**：对 Direct、Ignore Previous 这类显式注入，各防御均较有效；对 Tool Knowledge、Important Instructions 这类"伪装成工具语义/合规提示"的注入，纯 LLM 授权类方法更易被说服，而 MetaPermit 因裁决不交给 LLM 而更稳定。
- **按套件**：slack、travel 等涉及消息发送、路径/收款人参数的套件最能体现 `intent_input_alignment` 的价值；workspace 的文件/路径操作类攻击同样被输入对齐规则拦截。
- **案例层面**：开篇的"给 Bob 退款 vs. 给 Eve 转账"场景中，两笔调用工具相同、金额相近，MetaPermit 依靠"参数是否被用户请求所支持"区分二者，而工具级静态策略无法做到。

## 7. 分析与讨论

- **为何有效**：把"语义判断"与"授权裁决"分离，使随机性被限制在受限取值空间内；LLM 即使被注入说服，也只能在预定义词汇中取值，无法直接产生 Allow，也无法新增规则。
- **意图无关的可扩展性**：策略数量随安全维度增长，而非随任务/意图数量增长，这是其相对静态策略类方法的核心优势。
- **可审计性**：每次 Deny 都附带命中的规则与反馈，便于事后追责与策略迭代。
- **反馈而非硬终止**：合成工具结果让智能体有机会在"被纠正的约束"下重新规划，从而缓解安全性提升带来的可用性损失。
- **失效模式**（论文可能提及）：若推断模块给出错误但"合法"的元属性取值（如把 misaligned 判为 aligned），策略引擎无从纠正；元属性的定义边界模糊时会引入系统性偏差。

## 8. 局限性与未来工作

- **依赖人工设计元属性与规则**：仍需安全工程师把安全目标翻译为元属性与有序规则，并非全自动。
- **推断质量是瓶颈**：小模型或低质量推断会推高误拒率；fail-closed 保障安全但可能牺牲可用性。
- **评测局限**：攻击面限于文本注入；无成本/延迟数据；未报告方差与多次运行稳定性。
- **可扩展方向**：更细粒度或多模态的元属性、跨会话/记忆场景、与形式化方法结合以证明策略性质、以及自动化元属性发现。

## 9. 结论与启示

MetaPermit 提出"**LLM 只做受限语义标注、固定策略引擎做确定性裁决、执行门做可控执行**"的三段式框架，用少量预定义元属性与有序规则覆盖开放式意图下的工具访问控制，在安全性与可用性之间取得较好平衡，并具备意图无关的可扩展性与可审计性。其核心启示是：**在智能体安全中，不应让同一个可能被污染的 LLM 既当"运动员"又当"裁判"**；把语义能力约束在固定词汇表内、把最终裁决交给确定性组件，是抵御间接提示注入的一条务实路径。其局限也提示后续工作需在推断可靠性、成本效率与更广威胁模型上继续推进。
