## 摘要
LLM 智能体在编码能力上的进步，使其能够检查和修改自身的指令、工具和执行流程。现有方法利用这一能力，通过反复进行下游评估来搜索改进后的智能体，但这会带来高昂成本，并将搜索与所评估的任务绑定。我们提出 SelfSearch，一种无奖励搜索流程，其中智能体利用先前自我改进回合的记录来修改自身。这些记录包含早期修改尝试的推理、工具操作和结果，为改进任务求解与自我修改提供了具体经验。在搜索过程中无需下游奖励信号的情况下，SelfSearch 在全部六个模型—基准设置中都提升了相对于初始智能体的群体平均成功率，其中单个智能体在 Terminal-Bench 2.1 上最高提升 11.2 个百分点。在 SWE-bench Multilingual 上，对于初始智能体和进化后智能体均能解决的任务，一个智能体将成功率提升 5.0 个百分点，同时将执行成本降低 38.5%。SelfSearch 以更低的搜索成本，取得了与评估引导搜索基线相当的任务成功率。仅需 4.03 美元的搜索成本，它便生成了一个 harness，在公开的九种 harness 对比设置下，使用 DeepSeek V4 Flash 解决了 82.0% 的 Terminal-Bench 2.1 任务，与得分最高的 harness——Codex——持平。这些结果表明，通过自我修改获得的经验可以提升智能体的下游能力与效率。

## Abstract
Advances in the coding capabilities of LLM agents allow them to inspect and modify their own instructions, tools, and execution procedures. Existing approaches use this ability to search for improved agents through repeated downstream evaluation, which incurs substantial costs and ties the search to the evaluated tasks. We introduce \textbf{SelfSearch}, a reward-free search procedure in which agents modify themselves using records of previous self-improvement episodes. These records capture the reasoning, tool actions, and outcomes of earlier modification attempts, providing concrete experience for improving both task solving and self-modification. Without downstream reward signals during search, SelfSearch improves population-mean success over the initial agent in all six model--benchmark settings, with individual agents gaining up to 11.2 percentage points on Terminal-Bench 2.1. On SWE-bench Multilingual, an agent improves success by \textbf{5.0} percentage points while reducing execution cost by \textbf{38.5}\% on tasks solved by both the initial and evolved agents. SelfSearch achieves competitive task success with evaluation-guided search baselines at lower search cost. With only \textbf{\$4.03} in search cost, it produces a harness that solves \textbf{82.0}\% of Terminal-Bench 2.1 tasks with DeepSeek V4 Flash under the settings of a public nine-harness comparison, matching the top-scoring harness, Codex. These results suggest that experience gained through self-modification can improve agents' downstream capabilities and efficiency.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM 智能体的编码能力已足以检查并修改自身的指令、工具、执行逻辑乃至代码组织。既有工作（如 DGM、HGM、Hyperagents 等）利用这一能力，通过"提出修改 → 下游评测 → 依反馈继续搜索"的循环来进化智能体。
- **核心痛点**：
  - 评估引导式搜索需要**反复执行候选智能体**，成本随任务数量与重复次数线性增长；
  - 改进信号被**绑定在特定任务分布**上，搜索过程与评测任务耦合，难以泛化；
  - 现有方法多把"经验"定义为任务求解结果，而忽略了**修改过程本身**产生的经验。
- **论文主张**：一次自我修改不仅产生一个后继智能体，还产生一份**修改过程记录**（episode record），其中包含智能体如何发现自身局限、构造修订、验证效果的信息。这种"元认知式"经验（援引 Flavell 1979 的元认知概念）可以反过来指导后续自我改进。
- **整体含义**：论文提出 SelfSearch，实现**搜索期间不使用任何下游奖励信号**的智能体自我进化，将"候选生成"与"下游评估/选择"彻底解耦。其假设是：自我修改所调用的能力（阅读陌生代码、诊断失败、实施改动、验证效果）与下游任务所需能力高度重合，因此自我改进经验本身即可作为改进依据。

## 2. 方法论

### 2.1 核心思想

- 智能体以**仓库（repository）**形式实现，包含指令、工具、执行逻辑与策略库，**整个仓库可编辑**，但**模型权重固定**。
- 同一个智能体实现既负责下游任务求解，也负责自我修改；修改自身工具与流程会同时影响这两类能力。
- 每个 episode 中：智能体获得自身仓库的**可编辑副本**与**只读的历史 episode 记录**，据此做出修改并验证，产出后继智能体与新的 episode 记录。

### 2.2 关键技术细节

- **Episode 形式化**：$(B_{k+1}, e_k) = \text{SelfImprove}(B_k; E_k, d)$，其中 $B_k$ 为第 $k$ 代智能体，$E_k$ 为历史 episode 记录集合，$d$ 为搜索方向，$e_k$ 为本回合记录（含推理轨迹、工具动作、结果与代码 diff）。
- **搜索方向（两条 lineage）**：
  - **Capability（能力扩展）**：识别由低效行为、失败动作或难以完成的操作暴露出的任务求解局限，开发**可复用工具或流程**；
  - **Adaptive（自适应推理）**：改进"当动作失败、证据与假设矛盾或出现更优策略时如何调整方案"的能力。
  - 两个方向仅规定"调查什么"，**不对修改结果打分**。
- **记录共享机制**：两条 lineage 每代互相共享上一代的 episode 记录，使各自能吸收对方方向的发现，同时保持各自实现独立演进。
- **冷启动**：第 0 代让初始智能体在两个方向各跑一次，产生初始记录 $E_0$，但**丢弃其编辑后的实现**，使两条 lineage 均从同一 $B_0$ 出发。
- **固定 runtime**：模型–工具交互循环位于可编辑仓库之外，固定模型、推理强度、输出上限与执行预算；智能体通过 `respond(message)` 调用，可修改其外围的工具、指令与编排，但不能篡改推理设置与记录机制。这保证了执行稳定性与轨迹可记录性（附录 A）。
- **搜索提示词设计**：包含共享模板 + 模型特定 goal + 方向说明；提示词在正式实验前通过 pilot 搜索（观察 improver 轨迹与代码变更）固定，**未在下游基准上评估 pilot 智能体**（附录 B）。

### 2.3 算法流程（文字描述）

1. 初始化 $W$ 条 lineage 均为 $B_0$，候选档案 $C \leftarrow \{B_0\}$；
2. 对每一代 $k = 0,\dots,K-1$：并行地让每条 lineage 的智能体 $B_k^w$ 读取共享记录 $E_k$ 与自身方向 $d^w$，执行自我修改，得到后继 $B_{k+1}^w$ 与本回合记录 $e_k^w$；
3. 汇集所有 lineage 本回合记录为 $E_{k+1}$，将新智能体加入候选档案 $C$；
4. 共运行 $K=10$ 代、$W=2$ 条 lineage，最终评估两条 lineage 的**最终智能体**（不做基于下游分数的 checkpoint 选择），并报告**群体均值**。

## 6. 主要结论与发现

- **成功率全面提升**：在全部 6 个模型–基准设置中，群体平均成功率均超过初始智能体；单智能体最高提升 **11.2 个百分点**（Terminal-Bench 2.1）、6.7（SWE-bench Multilingual）、5.0（SWE-bench Verified）。
  - Terminal-Bench 2.1：GPT 43.8% → 55.1%（capability）/ 44.9%（adaptive）；DeepSeek 65.2% → 73.0% / 71.9%。
  - SWE-bench Verified：DeepSeek 两条 lineage 均从 81.7% → 86.7%。
- **效率提升**：Terminal-Bench 2.1 上 DeepSeek 两条 lineage 成功率提升的同时平均成本下降 12.1% 与 16.9%；SWE-bench Multilingual 上 DeepSeek adaptive 在共享成功任务上成本降低 **38.5%**；SWE-bench Verified 上共享成功任务成本降低 19.7–36.1%（DeepSeek）与 8.7–13.6%（GPT）。
- **无奖励搜索可与评估引导搜索竞争**：搜索成本比基线低 13.4–47.2%（GPT）与 49.0–53.2%（DeepSeek），成功率在多数设置下持平或更优。
- **跨模型迁移**：搜索得到的实现换用另一模型执行时，两条 lineage 均优于初始智能体（如 DeepSeek V4 Flash 从 81.7% → 83.3%/85.0%），说明改进不是模型特定伪影。
- **外部对比**：以 $4.03 搜索成本得到的 harness 在 Terminal-Bench 2.1 上解决 73/89（82.0%）任务，与九 harness 对比中最优的 Codex 持平（66 个任务两者共同解决，各另有 7 个独有）。
- **消融结论**：去掉历史 episode 记录使群体均值下降 2.1（GPT）/ 2.9（DeepSeek）个百分点；固定 improver 下降 1.7 / 2.9 个百分点——**历史记录与"会进化的改进者"二者都贡献增益**。
- **机制发现**：改进沿代际累积并在两条 lineage 间横向传播。例如 GPT 中 capability lineage 第 6 代加入带输出限制的文本搜索、adaptive lineage 加入轨迹读取器，第 7 代各自吸收对方的工具，第 8–10 代继续细化输出限制、过滤、工具调用与结果的关联；DeepSeek 中则出现搜索输出截断导致匹配文本被隐藏、由另一 lineage 修复为中心化摘录的"失败—修复"链条。
- **工具在下游被复用**：文本搜索工具在 GPT/DeepSeek 智能体上分别于 8.6% / 23.6% 的下游任务中被调用，行范围文件查看为 40.3% / 33.8%；轨迹读取器未被用于下游任务。图 3 展示了 Sphinx 任务中复用文本搜索工具定位调用方代码与测试的过程。

## 7. 优点

- **问题设定有新意**：首次系统性地把"自我修改过程本身"当作经验来源，实现真正的**无下游奖励**搜索，将候选生成与评估解耦，避免了评估成本随任务规模膨胀。
- **方法设计简洁且自洽**：单智能体同时承担任务求解与自我修改，全仓库可编辑，配合固定 runtime 保证可执行性与记录完整性；双 lineage（能力/自适应）设计以低成本引入探索多样性，并支持跨 lineage 经验共享。
- **实验覆盖多维**：3 个主流编码/终端基准 × 2 个模型家族，外加双向跨模型迁移、两组消融、逐代变更追踪、下游工具使用统计以及外部 harness 横向对比。
- **成本分析细致**：区分搜索成本与执行成本，并在"共享成功任务"上单独比较效率，避免成功率变化造成的成本混淆；成本公式与定价

- **透明度较高**：报告了搜索成本明细（调用数、输入/输出 token、总费用）、逐代变更清单、消融结果以及未生效的机制（如轨迹读取器未被下游复用），对负面/中性发现不回避。
- **迁移性验证**：跨模型双向迁移实验直接回应了"改进是否只是对特定模型过拟合"的质疑，这是同类自我改进工作中较少见的检验。

## 8. 局限与不足

- **无奖励搜索缺乏选择机制**：由于搜索期间不使用下游信号，方法无法区分"有益修改"与"有害修改"，只能在搜索结束后评估各 lineage 的最终实现。这意味着**搜索路径中的最优候选可能被丢弃**，且当某条 lineage 走入局部劣化时没有纠偏手段，只能依赖另一条 lineage 或历史记录间接缓解。
- **样本量与统计证据不足**：每个 lineage 仅一次搜索运行，群体均值仅由 2 个智能体构成，未报告方差、置信区间或显著性检验；SWE-bench Multilingual 的 60 个任务使单点提升约对应 3 个任务，结论的稳健性有待更大规模重复实验确认。
- **与评估引导基线的对比不完全公平**：作者已声明二者非预算匹配（基线额外承担开发集评估与候选选择成本）。虽然这恰恰是 SelfSearch 想消除的开销，但读者需注意"成功率持平或更优"的结论是在不同计算投入结构下得到的。
- **搜索过程本身仍有不可忽略的成本**：GPT 配置搜索耗资 $6.52、DeepSeek 配置 $4.03，且每代 episode 允许 513 次模型调用与 4 小时容器时间。当目标基准规模较小或任务难度较低时，搜索成本可能超过其带来的执行端收益。
- **依赖人工设计的搜索提示词与方向划分**：提示词虽未在下游基准上调优，但"capability / adaptive"两条 lineage 的划分与 goal 表述是人为设定的先验，其对新任务域、新模型是否同样有效缺乏系统性分析。
- **元认知经验的可解释性有限**：episode 记录以自然语言轨迹与代码 diff 形式共享，智能体如何从中提取可复用知识仍是黑箱，论文的机制分析以变更清单描述为主，未提供定量归因（如某一工具贡献了多少成功率提升）。
- **应用边界受限**：方法要求智能体以"可编辑仓库 + 固定 runtime"形式实现，对无法用代码表达其行为、或不允许运行时自改的智能体系统不适用；同时模型权重固定，因此无法覆盖需要参数层面学习的改进。
- **模型可复现性依赖外部发布**：论文使用的版本化模型命名与定价需要读者自行核对，第三方独立复现的难度较高。

## 9. 对读者的启示与可借鉴点

- **把"过程"当作一等资产**：在智能体系统中，除最终产物外，将搜索/调试/修改轨迹结构化记录下来并在后续轮次中回放，是一种低成本的自我改进信号来源，可迁移到提示词优化、工具库构建、工作流编排等场景。
- **解耦候选生成与评估**：当评估代价高昂或评估分布与部署分布不一致时，放弃在搜索环内使用奖励、转而依赖"自我修改能力与任务能力同源"的假设，是一条值得在特定条件下尝试的路线。
- **多 lineage + 经验横向共享**是廉价的多样性机制：两条独立演进的实现通过共享记录互相借鉴，既保持了探索多样性，又避免了重复踩坑，可作为通用设计模式。
- **固定 runtime 的工程价值**：把模型–工具循环、预算与记录机制置于可编辑范围之外，是保证自改系统可执行、可比较、可审计的关键约束，值得在自建智能体框架中借鉴。
- **成本度量应区分口径**：分别报告搜索成本与执行成本，并在"双方都成功"的任务子集上比较效率，能有效剥离成功率变化对成本指标的干扰，是评估自我改进系统时值得沿用的做法。

## 10. 一句话总结

SelfSearch 提出了一种将"自我修改过程记录"作为唯一经验来源的无奖励智能体搜索范式，通过能力扩展与自适应推理两条共享记录的 lineage 在固定 runtime 下迭代演进，在 SWE-bench Verified/Multilingual 与 Terminal-Bench 2.1 上以数美元的搜索成本取得最高 11.2 个百分点的成功率提升与最高 38.5% 的执行成本下降，验证了"用改进经验驱动改进"的可行性，但其候选选择缺失、统计证据薄弱与提示词先验依赖等问题仍有待后续工作解决。
