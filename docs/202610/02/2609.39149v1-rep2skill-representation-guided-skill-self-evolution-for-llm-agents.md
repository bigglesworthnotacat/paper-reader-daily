## 摘要
文本技能使基于大语言模型（LLM）的智能体能够在不更新模型参数的情况下积累可复用的过程性知识。然而，现有的技能演化在很大程度上仍局限于文本空间：优化器必须仅依据长执行轨迹和稀疏的任务结果来诊断成功与失败模式，并修订技能。这种纯文本范式将智能体的内部表示——其中包含其不断演化的执行状态的丰富记录——置于技能优化循环之外。我们提出疑问：智能体能否通过反思自身内部表示来改进其外部文本技能？我们提出Rep2Skill，一个表示引导的智能体技能自演化框架。具体而言，在收集到的智能体执行轨迹上，Rep2Skill对其内部模型表示轨迹进行建模，以定位偏离成功执行动态的轮次，并进一步将这些信号与执行上下文一起解释为可操作的文本反馈，用于有针对性的技能修订。在两个智能体环境、两个开源LLM上的实验表明，在自演化设置中，Rep2Skill始终优于纯文本方法；在该设置中，同一LLM同时充当执行器和优化器，且没有更强的外部模型。这为将智能体自我改进推进到纯文本反思之外确立了一个有前景的方向。

## Abstract
Textual skills enable large language model (LLM) based agents to accumulate reusable procedural knowledge without updating model parameters. Yet existing skill evolution remains largely confined to the text space: an optimizer must diagnose success and failure patterns, and revise skills solely from long execution trajectories and sparse task outcomes. This text-only paradigm leaves the agent's internal representations, which contain rich records of its evolving execution state, outside the skill optimization loop. We ask whether an agent can improve its external textual skills by reflecting on its own internal representations. We introduce Rep2Skill, a representation-guided framework for self-evolution on agent skills. Specifically, upon the collected agent rollouts, Rep2Skill models their internal model representation trajectories to localize turns that deviate from successful execution dynamics, and it further interprets these signals alongside the execution contexts as actionable textual feedback for targeted skill revision. Experiments on two agent environments with two open-source LLMs show that Rep2Skill consistently outperforms text-only approaches in the self-evolution setting, where the same LLM serves as both executor and optimizer without a stronger external model. This establishes a promising direction moving agent self-improvement beyond text-only reflection.

## 1. 核心问题与研究动机

- **背景**：基于 LLM 的智能体通过"文本技能"（可复用的文本指令、过程规则、任务策略）积累经验，无需更新模型参数即可提升多步长程任务的执行能力。
- **核心痛点**：现有技能演化方法几乎完全局限于**文本空间**——优化器只能依据长执行轨迹文本和稀疏的任务级成败结果，去推断"哪一步出错、为什么出错、技能应如何改"。这种"纯文本反思"范式存在两个根本困难：
  - **粗粒度反馈**：最终成败信号几乎无法指示具体哪一轮交互应获得信用分配；
  - **轨迹多样性**：同一任务、同一技能下采样的 rollout 差异巨大，单条轨迹的修订容易受偶然行为干扰。
- **被忽视的资源**：智能体的**内部表征**（hidden states）记录了其演化中的执行状态，包含对可观测轨迹的互补信息（如工具使用决策、执行失败状态等），但此前完全游离于技能优化循环之外。
- **核心研究问题**：*智能体能否通过反思自身的内部表征来改进其外部文本技能？*
- **整体含义**：本文首次将智能体轨迹的内部表征引入技能演化，提出 Rep2Skill，推动智能体自我改进从"纯文本反思"走向"表征空间分析 + 文本空间演化"的耦合范式。

## 2. 方法论：Rep2Skill 框架

### 2.1 核心思想
将智能体执行时的内部表征轨迹视为额外证据源，通过"分组 rollout + 表征轨迹建模"定位偏离成功执行动态的关键轮次，再将其**言语化**为文本反馈，指导文本技能的定向修订。全流程由同一个冻结 LLM 同时充当执行器、分析器与优化器。

### 2.2 问题形式化（预备知识）
- 冻结智能体 $\pi_\theta$，文本技能 $s$，任务 $x$，执行轨迹 $\tau=(o_1,a_1,\dots,o_T,a_T)$，任务得分 $r(\tau)\in[0,1]$。
- 技能期望性能：$J_D(s)=\mathbb{E}_{x\sim D}\mathbb{E}_{\tau\sim\pi_\theta(x;s)}[r(\tau)]$。
- 标准文本技能演化：$s_{n+1}=\mathcal{O}(s_n,\tau)$，仅依赖可观测轨迹与任务结果。
- 内部表征轨迹：每轮提取固定层的隐状态 $h_t\in\mathbb{R}^d$，得 $H(\tau)=(h_1,\dots,h_T)$。

### 2.3 关键技术流程（三阶段）

**（1）表征空间归因（Attribution in Representation Space）**
- **分组 rollout 采样**：对每个任务实例 $x$ 和当前技能 $s_n$，采样 $K=4$ 条轨迹构成组 $G(x,s_n)=\{\tau^{(k)}\}_{k=1}^K$，利用组内差异作为结构化诊断证据。
- **潜在投影**：将高维隐状态经 PCA 投影到 64 维并进行逐维标准化，投影与归一化统计量仅在成功轨迹上拟合。
- **轨迹建模**：采用**神经受控微分方程（Neural CDE）**建模潜在轨迹，用前 $t-1$ 轮表征历史预测第 $t$ 轮表征 $\hat{h}_t$。模型**仅在成功执行轨迹上训练**（约 50 条，来自与技能演化划分不重叠的训练任务），从而学到"成功执行的动态"。
- **归因分数**：$c_t^{(k)}=\|h_t^{(k)}-\hat{h}_t^{(k)}\|_2^2$，分数越高表示越偏离成功动态。取 top-$K_c=3$ 作为关键轮次集合 $C^{(k)}$。第一轮不参与打分。

**（2）表征到文本的言语化（Representation-to-Text Verbalization）**
- 由分析器 $M_a$（同一冻结 LLM）接收：当前技能 $s_n$、任务 $x$、完整轨迹 $\tau^{(k)}$、全部轮次归因分数以及关键轮次集合 $C^{(k)}$。
- 输出反馈 $F^{(k)}=M_a(s_n,x,\tau^{(k)},\{(t,c_t^{(k)})|t\in C^{(k)}\})$，包含摘要与至多 3 条诊断。
- 每条诊断须归入五种类型之一：`suspect_rule`（规则缺条件/误导）、`rule_conflict`（规则冲突）、`execution_deviation`（行为偏离正确规则）、`missing_rule`（缺失必要规则）、`insufficient_evidence`（证据不足）。
- **程序化校验**：引用的技能规则必须是 $s_n$ 的精确子串，证据必须引用合法步骤并逐字出现；`execution_deviation` 与 `insufficient_evidence` 不得建议修改技能；不通过校验的响应被丢弃。

**（3）文本空间技能演化（Skill Evolution in Text Space）**
- 优化器整合组内所有 rollout 与其反馈，生成候选技能：$s_{n+1}=\mathcal{O}(s_n,\{\tau^{(k)},F^{(k)}\}_{k=1}^K)$。
- 沿用 SkillOpt 的**整合 + 验证门控更新**流程：分层合并补丁（每 4 条递归合并，失败驱动优先）、编辑选择（编辑预算 $L=4$ 作为"文本学习率"）、精确字符串匹配应用编辑、在留出验证集上评估。
- **门控**：候选技能仅在验证得分严格高于当前技能时才被接受，否则保留 $s_n$；同时维护"步骤缓冲区"避免重复无效修订。

## 3. 实验设计

- **Benchmark（两个智能体环境）**：
  - **ALFWorld**：文本化具身家务环境，覆盖 6 类任务（pick & place、examine in light、clean、heat、cool、pick two & place），在 `valid_unseen` 的 134 个任务上报告成功率。
  - **WebShop**：模拟电商购物环境，测试集为官方 test split 前 100 条指令，报告平均任务得分（0–100）与成功率。
- **模型**：Qwen3-4B 与 Qwen3.5-9B（覆盖不同规模与注意力架构：全注意力 vs 混合注意力）。
- **对比方法**：
  - No Skill（无技能基线）
  - Trace2Skill（聚合轨迹经验为可迁移技能文档）
  - EvoSkill（将失败归因于缺失能力并修订模块化技能）
  - SkillOpt（将技能视为可训练文本状态，有界编辑 + 验证选择）
- **设置**：统一在**自演化设定**下评估——同一模型兼任执行器与优化器，不借助更强的外部模型；每组采样 4 条 rollout；三个随机种子（42/43/44）重复取均值与标准差；每个技能运行 3 个 epoch。

## 6. 主要结论与发现

- **性能提升（RQ1）**：Rep2Skill 在两个 benchmark、两个模型上均取得最优平均性能。
  - ALFWorld：Qwen3-4B 达 **52.24%**（超最强文本基线 4.98 分），Qwen3.5-9B 达 **69.90%**（超最强基线 7.77 分）。
  - WebShop：成功率 **16.33% / 23.33%**，任务得分 **49.79 / 53.56**；Qwen3.5-9B 上超最强基线 4.66 分（成功率）与 1.44 分（得分）。
- **更可靠的演化**：纯文本方法有时会劣于 No Skill（如 Qwen3-4B 上 SkillOpt 的 WebShop 得分 39.04 < 41.86；Qwen3.5-9B 上 Trace2Skill/EvoSkill 在 WebShop 双指标均低于 No Skill），而 Rep2Skill 在 No Skill 基础上稳定提升。
- **表征提供可靠细粒度信用分配（RQ2）**：纯文本归因 AUROC 仅 0.494（几乎无判别力），仅用表征分数提升到 0.592，而"文本 + 表征引导"达 **AUROC 0.838 / AUPRC 0.876 / P@Top-3 88.22%**；Precision@K 与 Recall@K 在全部 K 上均最优。
- **组内多样性显著**：同任务同技能下，第 5 轮时 82.7% 的动作对不一致，98.5% 的 rollout 在第 10 轮已有唯一动作前缀；表征空间余弦距离从第 1 轮 0.040 增长到第 5–10 轮的约 0.15——证明分组采样与相对比较的必要性。
- **消融结论**：三个组件互补——去表征言语化 ↓4.48，去表征归因 ↓5.22，去分组证据 ↓5.47（均相对完整版 52.24%）。
- **定性结论**：纯文本优化器只看到"耗尽步数"的终端症状，给出泛化建议（"更彻底搜索"）；表征归因则定位到 17–29 轮反复搜索橱柜、从不扩展至其他容器，从而产出具体可复用规则（"若橱柜未找到，检查台面、抽屉或水槽"），使任务从 30 步失败变为 8 步成功。

## 7. 优点

- **视角新颖**：首次将智能体轨迹的**内部表征**引入技能演化循环，突破纯文本反思范式，是"白盒化智能体自改进"的有益探索。
- **机制设计巧妙**：
  - 利用"仅用成功轨迹训练"的 Neural CDE 建模成功动态，把预测误差天然转化为"偏离成功"的归因分数，思路简洁而自洽；
  - 引入分组 rollout 与组内相对比较，缓解单条轨迹的偶然性问题；
  - 表征信号经**言语化 + 程序化校验**后才进入文本优化器，保证反馈可落地、可验证、不易幻觉。
- **实用性强的自演化设定**：执行器、分析器、优化器为同一冻结模型，不依赖更强外部模型，契合低成本自改进场景。
- **增益在弱模型上更显著**：印证了"当优化器能力有限时，表征引导的细粒度证据价值更大"的假设，具有实际指导意义。
- **实验论证链条完整**：性能对比 → 归因质量验证 → 组件消融 → 多样性分析 → 案例研究，层层递进地支撑主张。
- **实现细节披露较充分**：附录给出了算法伪代码、提示词模板、超参数表与校验规则，复现友好度较高。

## 8. 不足与局限

- **白盒依赖**：方法必须访问模型内部隐状态，无法直接用于黑盒 API 模型；作者提出可用可访问的代理模型提供表征信号，但未做验证。
- **模型覆盖有限**：实验仅限 Qwen 家族（Qwen3-4B / Qwen3.5-9B），跨架构（如 Llama、Mistral）与更大规模的泛化性未验证。
- **额外开销**：表征轨迹建模带来约 50 条额外 rollout 与一个轻量训练阶段；此外每轮需额外一次因果前向传播提取隐状态，长任务场景下成本会累积。
- **算力披露缺失**：未给出 GPU 型号、数量与训练/演化时长，硬件成本难以评估。
- **超参数敏感性未知**：关键设计参数（组大小 $K$、关键轮次 $K_c$、编辑预算 $L$、PCA 维度、层选择 24）的选择依据与敏感性分析不充分；固定层 24 的选择尤其缺乏解释。
