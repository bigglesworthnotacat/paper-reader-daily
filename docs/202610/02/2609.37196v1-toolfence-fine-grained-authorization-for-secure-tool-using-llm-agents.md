## 摘要
使用工具的LLM智能体仍易受间接提示注入攻击，因为可信指令与不可信观测共享同一上下文，使恶意内容得以左右关键的输入过滤防御。多路径共识防御仍会导致较高的攻击成功率，因为它们检查内容或聚合输出，而非对操作效果进行授权，尤其对于工具内攻击而言更是如此，该攻击保留预期工具但操纵其参数。诸如CaMeL的数据流控制提供了更强的保证，但会带来显著的时间延迟，限制实际部署。我们提出ToolFence，它在执行前编译带类型的授权蓝图，通过确定性监视器强制执行，并在蓝图不完整时请求裁判授予新能力，而不是对每次具体调用进行裁决。ToolFence具有两个关键优势。第一，其细粒度且具有来源感知的授权使系统能够区分用户授权的值与不可信观测，从而有效应对工具内攻击。第二，其确定性快速路径与能力级运行时授权大幅降低了昂贵裁判调用的频率，从而提升运行时效率。在AgentDojo上使用Qwen3-max时，ToolFence将总体ASR降至接近零，同时仅有3.80个百分点的干净效用下降和可接受的运行时开销。

## Abstract
Tool-using LLM agents remain vulnerable to indirect prompt injection because trusted instructions and untrusted observations share one context, allowing malicious content to steer consequential input-filtering defenses. Multi-path consensus defenses still leave a high attack success rate because they examine content or aggregated outputs rather than authorizing effects, especially for the within-tool attack, which preserves the intended tool but manipulates its arguments. Data-Flow Control such as CaMeL provides stronger guarantees, but incurs substantial time latency that limits practical deployment. We introduce ToolFence, which compiles a typed authorization blueprint before execution, enforces it through a deterministic monitor, and when the blueprint is incomplete asks a judge to grant new capabilities rather than adjudicate each concrete call. ToolFence provides two key advantages. First, its fine-grained provenance-aware authorization enables the system to distinguish user-authorized values from untrusted observations, effectively addressing the within-tool attack. Second, its deterministic fast path and capability-level runtime grants substantially reduce the frequency of expensive judge calls, improving runtime efficiency. On AgentDojo with Qwen3-max, ToolFence reduces overall ASR to near zero with only a 3.80 percentage-point clean-utility drop and practical runtime overhead.

# ToolFence 论文深度总结

## 一、核心问题与研究动机

- **根本问题**：使用工具的 LLM 智能体（tool-using LLM agents）易受**间接提示注入（indirect prompt injection）**攻击。根本原因在于：系统策略、用户请求、检索文档、邮件、网页以及工具中间输出**共享同一个上下文**，模型无法可靠地区分"承载授权的指令"与"不可信数据"，攻击者可将指令嵌入外部内容，诱导智能体执行用户从未请求的操作（发邮件给新收件人、访问攻击者 URL、向不同账户转账等）。
- **威胁演进**：攻击已从简单的"忽略先前指令"扩展到针对工具描述、聊天模板边界、记忆、多步交互循环的结构化攻击（ToolHijacker、ChatInject、ASB 等），因此仅防护初始提示不足，**授权必须覆盖完整执行轨迹**。
- **现有防御的三类失效模式**：
  1. **工具内劫持（within-tool hijacking）防御不足**：攻击保留合法工具，仅篡改其权限敏感参数（收件人、金额、URL、目标等）。RepeatPrompt、ToolFilter、输入过滤（DataSentinel、PiGuard、PromptArmor）、结构感知方法（StruQ）、共识防御（SecInfer）均只关注工具选择或内容，忽略可执行授权。
  2. **强隔离开销高**：CaMeL 通过溯源追踪与能力强制执行实现强控制/数据流隔离，但需要定制执行流水线，延迟与成本显著（12.95×）。
  3. **静态工具过滤损害效用**：静态过滤器无法预见所有合法能力，导致计划外的正当调用被拒绝，任务无法完成。
- **关键洞察**：安全相关单元既非"单次调用"（过细，重复裁决浪费），也非"整个会话"（过粗，无法适应），而是**能力（capability）**——即"工具 + 效果类别 + 权限敏感参数的溯源约束"这一抽象形状。形状可复用，具体值不可复用。

## 二、方法论

### 2.1 核心思想
ToolFence 是一种**推理时防御**，将"能力授权"与"动作执行"分离：执行前编译授权蓝图，执行中由确定性监视器零 LLM 成本强制执行，蓝图不完整时请求裁判授予**能力形状**（而非裁决单次调用），并通过跨会话缓存摊销裁判成本。

### 2.2 四个核心组件

- **① 类型化授权蓝图（Typed Authorization Blueprint）**
  - 由策略架构师（隔离的 LLM 调用，仅见用户查询 q 与控制器持有的工具 schema，**从不接触不可信内容**）编译。
  - 输出类型化计划 P = (M, C)：
    - M：工具清单，为每个工具分配效果标签 e ∈ {READ, LOCAL_COMPUTE, COMMUNICATION, FINANCIAL, EXTERNAL_WRITE, DELETE, …} 及每参数权限敏感标志。
    - C：能力集合，每个能力为元组 **c = (tool, e, {pj ↦ βj}, κ, r)**，含工具、效果、参数绑定、调用预算 κ、可复用标志 r。
  - 参数绑定 βj 声明来源约束（**记录溯源约束而非具体值**）：
    1. **LITERAL**：值来自用户请求 q；
    2. **DERIVED**：值来自指定源工具 s 的输出，即 v ∈ Obs(s)；
    3. **TEMPLATE**：值匹配以 q 和源工具为依据的模板；
    4. **FREE**：非权限敏感，可由智能体自选。
  - 示例：`send_money(recipient ← read_file("bill.txt"), amount ← 用户查询 q)`。

- **② 确定性监视器（Deterministic Monitor，快速路径）**
  - 对每个提议调用 a = (tool, x) 无 LLM 检查三项：
    1. **能力匹配**：存在 c ∈ C 覆盖所有参数；
    2. **绑定合规**：LITERAL 必须出现在 q 中；DERIVED 必须出现在已执行的指定源工具输出中；TEMPLATE 须匹配模式且源工具已执行；
    3. **预算**：已提交调用数低于 κ（或 r = TRUE 的可复用读能力）。
  - 全部通过则立即派发。
  - **读自动放行**：仅当所有参数溯源均为 USER 时自动放行；若读参数来自工具输出或模型（如从被注入网页提取的 URL），不自动放行，须送裁判（消融显示无条件信任读会带来 60% ASR）。

- **③ 动态运行时能力授予（Dynamic Runtime Capability Grant，慢速路径）**
  - 调用未命中蓝图时，控制器为每个参数计算溯源标签 π(pj) ∈ {USER, TOOL, MODEL}，构造候选能力 ĉ（绑定镜像这些标签）。
  - **结构性拒绝**：若任何权限敏感参数的溯源为 MODEL，则 ĉ = ⊥，**在咨询裁判之前即被阻断**（式 6）。
  - 裁判仅收到**能力形状**（工具、效果、每参数溯源约束与敏感标志），**不接收具体参数值**，输出 Grant(ĉ) ∈ {GRANT, DENY}；解析失败默认拒绝（式 7）。
  - GRANT 后调用 GrantCapability(ĉ) 扩展运行中计划 C，原调用重新走快速路径派发；DENY 则回退到单次调用裁判作最后手段。

- **④ 跨会话能力缓存（Cross-Session Capability Cache）**
  - 以无值签名 sig(c) = (tool, e, {pj ↦ (βj, source_tools_j)}) 为键存储已批准形状。
  - **只存形状，不存具体值、证据文本或历史工具输出**；复用时每个具体参数仍在当前会话中重新校验绑定，故授权不会跨会话转移。

- **安全属性：失效关闭（fail-closed）**
  - 式 (5)：能力 ∉ C ∪ G 且 Grant(ĉ) ≠ GRANT ⟹ 不派发。
  - 式 (6)：权限敏感参数为 MODEL 生成 ⟹ ĉ = ⊥。
  - 式 (7)：裁判输出解析失败 ⟹ DENY。
  - 即使模型完全被污染，控制器（而非模型）位于授权边界，注入问题被归约为带安全默认值的能力授权问题。

### 2.3 算法流程（Algorithm 1 概要）
编译蓝图 → 注入缓存授权 → 循环：接收动作 → 监视器确定性检查（通过即派发）→ 计算溯源 → 读自动放行 → 构造授予提案（模型生成敏感参数则 ⊥）→ 缓存命中则直接授予 → 否则裁判裁决 → GRANT 则扩展计划并派发；DENY 则单次调用裁判兜底 → 拒绝则返回拒绝消息。

## 六、主要结论与发现

- **安全性**：
  - Qwen3-max 上 ToolFence 总体 ASR **0.20%**（跨工具 0.10%、工具内 0.80%），对比 No Defense 21.20%、CaMeL 0.42%、Tool Filter 1.67%；
  - GPT-4o 上 0.90%（跨工具 0.70%、工具内 2.10%）；
  - Mistral 上 0.13%（跨工具 0.05%、工具内 0.60%）。
- **工具级防御的盲区被证实**：Tool Filter 在 Qwen3-max 上将跨工具 ASR 降至 0.45%，但工具内 ASR 仍高达 9.18%（Mistral 上 0.39% vs 7.69%），说明限制工具可用性无法控制权限敏感参数。
- **效用与开销**：
  - Qwen3-max：Clean U. 38.90%、U@A 32.45%，相对 No Defense（42.70%）仅下降 3.80 个百分点，运行时 1.63×；
  - GPT-4o：Clean U. 82.70%、U@A 73.80%，运行时 3.79×；
  - CaMeL 虽安全（0.42%）但效用损失明显且运行时 10.67×/12.95×；SecInfer 效用较高但 ASR 高（14.31%）。
- **消融结论**：
  - 纯静态蓝图安全但过度限制（U@A 仅 25.60%）；
  - 加运行时能力授予将 U@A 提升至 30.40%，验证能力级扩展能恢复良性动作；
  - 跨会话缓存基本不改变安全与效用，但将裁判调用从 1.84 次/任务降至 1.05 次（**减少 42.9%**）；
  - 读自动放行进一步将 U@A 提升至 32.45%，裁判调用降至 0.82 次/任务，完整系统 0.20% ASR、1.90× 开销。
- **域泛化**：四套件 ASR 均低且相对表现一致，说明溯源与参数级授权不依赖特定工具集或领域。
- **残余风险**：当攻击**完全落在已授权能力形状内部**时仍可能成功（如合法餐馆列表输出中，注入影响模型在多个合法候选中做选择），说明溯源只验证"值从哪来"，不验证"模型的选择是否忠实反映用户意图"。

## 七、优点

- **问题刻画精准**：明确提出并系统刻画 **within-tool hijacking** 这一被低估的威胁类别，并用参数感知划分（基于可执行 ground-truth 工具调用）定量暴露工具级防御的盲区，方法学上有独立贡献。
- **授权粒度创新**：从"逐调用裁决"重新定义为"能力级授权"，把授权单元设为（工具、效果、溯源约束）形状，兼顾可复用性与爆炸半径有界性，巧妙弥合静态蓝图与逐调用裁判之间的鸿沟。
- **零 LLM 快速路径**：确定性监视器使

- **零 LLM 快速路径**：确定性监视器使绝大多数已授权动作零 LLM 成本执行，把昂贵的裁判调用压缩到"未命中蓝图"的长尾，配合跨会话能力缓存进一步摊销，使安全增益不必然以成倍延迟为代价（Qwen3-max 仅 1.63×，远低于 CaMeL 的 12.95×）。
- **失效关闭的安全设计**：把授权边界从"模型"移到"控制器"，以式 (5)(6)(7) 三条 fail-closed 规则（未授权不派发、MODEL 溯源敏感参数直接 ⊥、裁判解析失败默认 DENY）将提示注入问题归约为带安全默认值的授权问题，即使模型完全被污染也不会越权。
- **关注点分离干净**：策略架构师（只见查询与 schema）、确定性监视器、运行时裁判、能力缓存职责清晰，裁判只看"能力形状"不看具体值，既降低泄漏面又减少裁判被上下文污染的风险。
- **缓存设计克制而正确**：只缓存无值签名、复用时重新校验绑定，避免了"授权跨会话转移"这一常见隐患，是安全设计上的细节亮点。
- **实验方法学扎实**：参数感知划分基于可执行 ground-truth 工具调用而非表面文本，跨工具/工具内 ASR 分离报告，固定种子 + 95% bootstrap 置信区间 + 同骨干同任务的公平对比，结论可信度较高。
- **对读操作的审慎处理**：明确区分"参数溯源全为用户"的读（自动放行）与"来自工具输出/模型"的读（须送裁判），并用消融（无条件信任读带来 60% ASR）量化这一判断，避免把读操作当作天然无害的简化假设。

## 八、局限性

- **残余风险未根除**：溯源只验证"值从哪来"，不验证"模型在合法候选中的选择是否忠实反映用户意图"。当攻击完全落在已授权能力形状内部（如在合法餐馆列表输出中诱导模型挑选某个合法选项）时仍可能成功，这类"选择劫持"是参数级溯源的原理性盲区。
- **未评估自适应攻击**：论文自身引用 Nasr et al. 指出攻击者可能适应防御。当前实验使用固定的六种攻击策略，攻击者若知晓 ToolFence 的能力形状机制（例如刻意构造溯源合法但语义恶意的参数组合、或专门规避 MODEL 溯源标签），防御是否仍稳健尚不清楚。
- **蓝图层依赖策略架构师质量**：类型化授权蓝图由隔离 LLM 一次性编译，若架构师对工具语义理解不足或用户查询本身歧义，蓝图可能过宽（漏放恶意）或过窄（压制良性动作）。论文未系统分析架构师失败率及其对整体安全/效用的敏感度。
- **跨会话缓存的长期对抗性安全性未压力测试**：缓存只存形状，理论上不转移授权，但长期运行下形状集合是否会因反复授予而单调膨胀、进而逼近"事实上的过宽蓝图"，缺少对抗性长期实验。
- **效用仍有损失**：Qwen3-max 上 Clean Utility 从 42.70% 降至 38.90%，U@A 32.45%；GPT-4o 上 Clean Utility 82.70%、U@A 73.80%。相对 No Defense 的效用下降虽小，但在部分领域/任务类型上仍存在误拒，论文未深入分析被拒良性调用的分布特征。
- **依赖可执行 ground-truth 划分**：参数感知划分需要恶意任务的可执行 ground-truth 工具调用，20 个模糊样本（多为非工具 DoS 攻击）被排除主分析，意味着对"非工具类"攻击的覆盖不足。
- **硬件与工程细节披露不足**：未报告硬件平台、GPU 型号，效率数据（如 10.3 s/样本）跨平台可比性受限，复现成本难以预估。
- **效果类别（effect label）体系需人工定义**：READ/LOCAL_COMPUTE/COMMUNICATION/FINANCIAL/EXTERNAL_WRITE/DELETE 等标签及其"权限敏感参数"判定由谁、以何标准给出，论文着墨较少，这直接决定授权的粗细与正确性。

## 九、对领域与后续研究的启示

- **授权单元的重定义具有一般性**：把安全单元从"调用"或"会话"改为"能力形状（工具 + 效果 + 溯源约束）"，这一抽象可能推广到多智能体系统、代码执行智能体、浏览器智能体等更广场景——凡"参数即权限"之处，形状级授权都可复用。
- **"溯源而非语义"是当前可工程化边界**：论文诚实地把无法验证的"意图忠实性"列为残余风险，提示后续工作需要引入更强的意图对齐验证（如用户确认、多候选溯源、选择级审计），而非仅靠数据流溯源。
- **能力缓存作为成本摊销范式**：只存形状、复用时重校验的设计，为"安全机制如何做到低开销"提供了可借鉴模板——把昂贵裁决结果抽象为可复用形状而非可复用结论。
- **自适应攻击与长期安全性是下一步必答题**：随着防御机制公开，攻击者会针对能力形状设计规避策略，动态博弈下的鲁棒性评估、形状集合膨胀监控、裁判自身的抗注入性，都是明确的后续方向。

## 十、总体评价

ToolFence 针对 tool-using LLM 智能体的间接提示注入，提出了一个定位清晰、机制自洽的推理时防御。其核心贡献有二：**概念上**，用"能力（工具 + 效果 + 权限敏感参数的溯源约束）"作为授权单元，弥合了静态蓝图过粗与逐调用裁判过细之间的鸿沟；**方法上**，以"确定性监视器快速路径 + 能力形状级慢速裁判 + 跨会话形状缓存 + fail-closed 安全默认值"四件套，在几乎不损失效用、开销可控（1.63×）的前提下，将总体 ASR 压至 0.20%–0.90%，显著优于工具级过滤与逐调用共识防御。其对 **within-tool hijacking** 的系统刻画与参数感知划分，本身就是对威胁建模的独立贡献。局限主要在于原理性的"选择劫持"盲区、未测试自适应攻击与架构师/效果标签体系的敏感性分析。总体而言，这是一篇在问题定位、机制设计与实验方法学上均较扎实的工作，为"参数即权限"类智能体安全提供了可复用、可推广的授权范式。
