## 摘要
复杂任务天然耦合了工作流结构、智能体职责、协作与记忆访问：任务区域界定了职责与工具范围，跨区域依赖产生交接，所有权边界则界定了私有记忆与选择性共享记忆。现有方法能够联合优化智能体结构与通信结构，但这种优化本身并不要求职责、交接与记忆边界始终与任务依赖保持一致。我们将这一要求称为拓扑一致性。我们提出 TOCOMAS，一种拓扑一致的多智能体系统。TOCOMAS 将任务图建立在工具接口之上，把相互兼容的任务节点组织为可复用的职责域，并推导出由依赖引发、由画像条件化的协作关系，以及受边界调控的记忆可见性。在线自演化过程中，TOCOMAS 提出对智能体策略、协作策略与记忆策略的耦合变更，并且仅保留满足结构约束且在评估奖励上有所提升的候选方案用于后续任务。在 BBEH、WorkBench、SWE-Bench-Verified 与 CoMemBench 上，TOCOMAS 在不同骨干模型上均较基线提升了任务成功率。CoMemBench 还显示，其在验证进度、交接与记忆隔离方面相较自演化基线有所提升。

## Abstract
Complex tasks inherently couple workflow structure, agent responsibility, collaboration, and memory access: task regions delimit responsibility and tool scope, cross-region dependencies give rise to handoffs, and ownership boundaries delimit private and selectively shared memory. Existing methods can jointly optimize agent and communication structures, yet such optimization does not by itself require responsibility, handoff, and memory boundaries to remain consistent with task dependencies. We term this requirement topological coherence. We introduce TOCOMAS, a Topology-Coherent Multi-Agent System. TOCOMAS grounds a task graph in tool interfaces, organizes compatible task nodes into reusable responsibility domains, and derives dependency-induced and profile-conditioned collaboration together with boundary-regulated memory visibility. During online self-evolution, TOCOMAS proposes coupled changes to agent, collaboration, and memory policies, retaining for subsequent tasks only candidates that satisfy structural constraints and improve evaluated reward. Across BBEH, WorkBench, SWE-Bench-Verified, and CoMemBench, TOCOMAS improves task success over baselines across backbones. CoMemBench also shows gains over the self-evolving baseline in verified progress, handoffs, and memory isolation.

## 2. 方法论

### 2.1 核心思想

- 不从预定义角色或自由文本标签出发，而是以任务图 \(T_q=(U_q,D_q)\) 和公共工具图 \(K\) 为共同组织参照。
- 通过工具 grounding 将任务节点映射到工具接口，形成可执行拓扑 \(H_q\)。
- 将操作兼容的任务节点合并为可复用的 **责任域**，再把这些责任域分配给具备相应工具能力的智能体。
- 协作边和记忆边界都由同一套责任划分和所有权映射推导，而不是独立设计。
- 在线演化时提出结构变更，并检查候选是否满足拓扑一致性约束和奖励提升条件。

### 2.2 关键流程

- **工具 grounding**：用映射 \(\Psi_q: T_q \rightarrow 2^T\) 为每个任务节点选择最小有效工具包 \(\Gamma(u)\)，受能力覆盖、边语义兼容、副作用约束和提供者连续性等限制。
- **责任域与商拓扑**：通过满射 \(\pi_q: U_q \rightarrow S_q\) 把任务节点划分到责任域 \(S\)。对 \(H_q\) 按 \(\pi_q\) 收缩得到商拓扑 \(\bar{H}_q=H_q/\pi_q\)，保留跨区域依赖、隐藏区域内依赖。区域合并需保持商拓扑无环，并满足任务与工具容量。
- **兼容性依据**：任务节点对的兼容性由工具重叠、输入输出兼容、依赖邻接和语义相似度共同衡量。
- **所有权映射**：\(\phi_q: S_q \rightarrow V_q\)，要求区域所需能力 \(\Gamma(S)\) 被所分配智能体的工具集覆盖。一个智能体可拥有多个兼容区域；无合适智能体时可新增专门化智能体。
- **协作编排**：把跨区域任务依赖推送到所有权映射，得到必需通信边 \(E^{req}_q\)；再结合基于画像相似度、查询相关性和工具互补性的空间边 \(E^{sp}_q\)，形成运行时协作图 \(G_q\)。
- **交接与验证**：区域执行产生 artifact，交接通过路由策略只暴露下游所需 artifact，必要时触发验证者升级。
- **记忆协调**：每条记忆记录关联产生者、任务区域和 provenance。可见性策略 \(\Lambda_q\) 先执行所有权与边界过滤，再进行语义检索和 typed graph expansion。语义相关性不能覆盖所有权和共享边界。
- **记忆迁移**：当区域所有权变化时，相关私有记忆随区域迁移，并更新访问权限和 provenance，避免经验孤立或意外全局共享。
- **演化机制**：结构投影为 \(\Omega_q=(\pi_q,\phi_q,G_q,\Lambda_q)\)。执行反馈和积累经验用于提出结构提案，可能改变责任划分、工具范围、通信边或记忆策略。候选需通过结构检查，即每个任务节点有唯一且有能力的所有者，跨区域交接和记忆可见性符合边界；随后执行并按奖励是否超过父代决定接受或保留原结构。
