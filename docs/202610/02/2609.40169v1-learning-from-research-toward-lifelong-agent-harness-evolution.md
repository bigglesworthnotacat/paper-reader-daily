## 摘要
语言智能体被期望解决日益复杂的任务，因此对持续改进的需求不断增长。一种有前景的方法是演化智能体运行框架，即在保持底层语言模型不变的情况下，改进这一管理工具使用、记忆管理和任务执行的软件。近期方法通过使用元编码智能体，基于执行反馈修改该框架，从而实现这一过程的自动化。然而，依赖该智能体已有知识和观察到的失败会限制探索，并使适应过程呈现被动性。受人类专家从研究文献中学习新解决方案的启发，我们提出 ScholarEvolve，一个自动利用前沿研究来指导运行框架演化的框架。ScholarEvolve 将运行框架演化方向组织为功能模块，并使用主题建模为每个模块识别不同的改进策略。它实现这些策略并评估其组合，以提升任务性能。此外，该框架旨在随时间纳入新发表文献，使研究进展能够驱动主动的终身演化。实验表明，在 AppWorld 和 Tau2-Bench 上均取得改进。在 AppWorld Challenge 上，ScholarEvolve 将 Qwen3.5-27B 的任务目标完成率从 49.6% 提升至 63.6%；在 Tau2-Bench Telecom 上，将 GPT-5.4-mini 的 pass@1 从 72.7% 提升至 81.9%。

## Abstract
Language agents are expected to solve increasingly complex tasks, creating a growing need for continual improvement. One promising approach is to evolve the agent harness, the software that governs tool use, memory management, and task execution, while keeping the underlying language model fixed. Recent methods automate this process by using a meta coding agent to modify the harness based on execution feedback. However, relying on that agent's existing knowledge and observed failures can restrict exploration and make adaptation reactive. Inspired by how human experts learn from the research literature for new solutions, we introduce ScholarEvolve, a framework that automatically draws on state-of-the-art research to guide harness evolution. ScholarEvolve organizes the harness evolution directions into functional modules and uses topic modeling to identify distinct improvement strategies for each module. It implements these strategies and evaluates their combinations to improve task performance. Moreover, the framework is designed to incorporate new publications over time, allowing research advances to drive proactive lifelong evolution. Experiments demonstrate improvements on AppWorld and Tau2-Bench. ScholarEvolve raises Qwen3.5-27B task goal completion from 49.6% to 63.6% on AppWorld Challenge, and raises GPT-5.4-mini pass@1 from 72.7% to 81.9% on Tau2-Bench Telecom.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：语言智能体需要处理越来越复杂的任务，持续提升能力成为刚需。相比反复重训大模型（算力昂贵），更实用的路径是**演化智能体运行框架（agent harness）**——即围绕固定模型管理工具使用、上下文、技能、记忆与执行工作流的软件层。
- **现有方法的局限**：当前主流的 harness 演化方法使用**元编码智能体（meta coding agent）**，依据执行反馈自动修改 harness 代码。但这类方法存在三大挑战：
  - **❶ 探索受限**：虽然拥有广泛改代码的权限，但往往陷入狭窄的局部修改（如反复添加验证轮次、多智能体辩论），可能反而阻塞必要的工具调用。

  - **❸ 适应滞后**：演化证据来自已发生的轨迹，弱点可能先影响用户，等证据积累足够再更新已为时过晚。
- **核心洞察**：人类专家（研究者/ML 工程师）会**查阅研究文献**，学习他人如何解决类似问题，并将其适配到新场景。这相当于把整个研究社区的集体经验注入到设计过程中。
- **论文含义**：提出 **ScholarEvolve**，一个自动从最新研究中汲取机制、驱动 harness 演化、并能随新论文持续演进的**终身演化框架**，同时保持底层语言模型参数不变。

## 2. 方法论

### 2.1 核心思想

- 将 harness 演化组织为**"功能模块 × 研究主题"**两个正交维度：
  - **模块（Module）**：指定要修改的执行职责；
  - **方法主题（Method Topic）**：指定要在其中实现的研究机制。
- 通过**主题建模**把论文聚类为语义正交的机制族，让候选生成散布在不同干预点与不同解决方案上，再用**模块交叉（crossover）**组合并评估完整 harness。

### 2.2 问题形式化

- 固定骨干为 $f_\theta$（参数不变）。任务 $x \sim P_{tar}$，harness $H$ 诱导轨迹 $\tau = (o_0, a_0, \dots, o_T)$，奖励为 $R(x, \tau)$。
- 演化目标：
  $$H^\star \in \arg\max_{H \in \mathcal{H}} J(H), \quad J(H) = \mathbb{E}_{x \sim P_{tar}} \mathbb{E}_{\tau \sim p_\theta(\cdot | H, x)} [R(x, \tau)]$$
- **数据划分严格互斥**：$D_{evo}$（失败分析、研究查询、构建持久化 artifact）、$D_{val}$（候选评估与冠军选择）、$D_{test}$（仅最终报告，选择冻结后使用）。

### 2.3 模块化代码空间

harness 表示为 $H = \mathrm{Compose}(m_1, \dots, m_5)$，五个模块各实现定义好的接口：

| 模块 | 职责 | 典型变异方向 |
|---|---|---|
| ❶ Tool interface | 控制可用动作、把提议翻译为可执行调用 | 工具选择、工具组合、调用验证 |
| ❷ Context management | 从指令/历史/记忆/技能组装模型输入 | 上下文选择、压缩、排序 |
| ❸ Skills | 维护可复用过程 | 技能归纳、检索、维护/整理 |
| ❹ Memories | 维护经验 | 记忆形成、检索、巩固 |
| ❺ Agentic workflows | 组织规划与动作生成 | 任务分解、智能体协调、子智能体委派 |

变异时**只改一个模块、其余固定**以隔离效果；模块间协调在交叉阶段通过评估完整 harness 来处理。

### 2.4 研究池构建

1. 在 $D_{evo}$ 上收集轨迹；
2. **审计器**将失败归因于智能体或环境，保留反复出现的、智能体可归因的失败及支撑证据；
3. **研究模型**把 benchmark 特定证据抽象为**能力缺口（capability gaps）**，剔除 benchmark 名、领域实体、具体工具/字段名；
4. 为每个模块生成**宽泛能力查询 + 聚焦机制查询**两组 query；
5. 经 arXiv 检索、按标题归一化去重，形成模块池 $P_j$。

### 2.5 主题建模（正交探索）

采用 TopicGPT 框架（Pham et al., 2024）做提示式主题生成、精炼与分配：

- **分类体系归纳与精炼**：
  $$T_j^{(b)} = T_j^{(b-1)} \cup G_\phi(B_{j,b}, T_j^{(b-1)}, d_j), \quad T_j = F_\phi(T_j^{(B_j)}, d_j)$$
  生成函数 $G_\phi$ 在机制匹配时复用已有名称，未覆盖时新增类别；精炼函数 $F_\phi$ 合并同义/重叠类别、吸收过细变体、剔除含糊或无关主题，以标准化机制粒度。
- **证据支撑的分配**：每篇论文获得有序主题列表 $L_j(p) = (\ell_{j,p,1}, \dots, \ell_{j,p,q_{j,p}})$，主主题 $z_j(p) = \ell_{j,p,1}$ 决定其选择簇 $C_{j,t}$；每个分配附带摘要片段以便审查。
- **机制族覆盖**：筛除已由当前 harness/骨干覆盖的主题，对剩余非空簇按规模降序**轮询选文**，预算 $K_j$ 篇论文可覆盖 $\min(K_j, |T_j^+|)$ 个不同主题。

- 编码智能体据蓝图实现 $m_j^{(p)}$，构造 $H_j^{(p)} = H^{(0)}[j \leftarrow m_j^{(p)}]$。
- **轻量健康探针**检查可导入性、接口兼容性、artifact 构建与重载、有效动作生成；失败则修复直至通过或预算耗尽。
