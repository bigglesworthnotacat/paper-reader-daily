## 摘要
上下文安全防御通过合成任务特定的策略，并将其强制执行于智能体的工具调用，来阻止 AI 智能体采取越轨行为。然而，在多步任务中，哪些动作是有效的，往往取决于智能体已经执行过什么以及学到了什么。我们提出 Sapien，一个用于强制执行有状态上下文策略的策略引擎。Sapien 策略使用扩展了有状态谓词、延迟策略生成和作用域语义检查的正则表达式，来指定允许的工具调用序列。我们表明，Sapien 与无约束智能体的效用差距保持在几个百分点以内。即使智能体被完全劫持，Sapien 的策略也能在 AgentDojo 上排除 93–95% 的攻击，在 Toolathlon 上排除 62–85% 的攻击（在长时程任务上，这一数量是工具允许列表的两倍）。

## Abstract
Contextual security defenses prevent AI agents from taking rogue actions by synthesizing a task-specific policy and enforcing it on the agent's tool calls. In multi-step tasks, however, which actions are valid often depends on what the agent has already done and learned. We present Sapien, a policy engine for enforcing stateful contextual policies. A Sapien policy specifies permitted tool-call sequences using a regular expression extended with stateful predicates, deferred policy generation, and scoped semantic checks. We show that Sapien stays within a few percent of an unconstrained agent's utility. Even if the agent is fully hijacked, Sapien's policies rule out 93-95% of attacks on AgentDojo and 62-85% on Toolathlon (twice as many as tool allowlists on long-horizon tasks).

## 1. 核心问题与研究动机

- **背景**：通用型 AI 智能体（如 Meta Muse、Gemini Spark、OpenClaw 等）通过 LLM 自主规划并调用外部工具完成开放域任务。但把工具调用权交给 LLM 使其本质上不可靠，会产生**越轨行为（rogue actions）**：既可能被提示注入（prompt injection）劫持，也可能在长时程任务中自发漂移、误读工具输出或临时"发明"变通方案。现实中已出现智能体清空收件箱、删除生产数据库、攻击外部基础设施、执行攻击者控制命令等事故。
- **为什么静态策略不够**：传统系统用引用监控器（reference monitor）对每次动作做策略检查，但策略通常是静态的。对通用智能体而言，某个动作是否合法**取决于当前任务**——`send_money` 在"给上周汇款给我的人退款"中是合法的，在"总结我的收件箱"中就是盗窃。静态白名单要么放行（留下风险），要么禁止（破坏合法任务）。
- **本文采用框架**：**上下文智能体安全（contextual agent security）**——每个请求先由策略生成器从用户提示即时合成任务特定策略，再由引用监控器对工具调用强制执行。
- **关键洞察（图 1）**：策略能多"紧"地包围合法轨迹，受限于策略语言的**表达力**。仅靠工具名白名单或参数约束都不够——例如"退款"任务中，正确的收款人和金额只有在运行时读完交易历史后才知道。因此，**"智能体下一步可以做什么"必须依赖于它已经做过什么、已经观察到什么数据"**，即需要**有状态（stateful）策略语言**。

## 2. 方法论

### 2.1 整体架构（图 2）
Sapien 拦截在智能体 harness 与工具之间，分两阶段运行：
- **事前策略生成**（每任务一次）：生成器 LLM 仅读取**用户任务提示 + 工具文档**，合成任务特定策略。
- **运行时强制执行**：每次提议的工具调用都先过策略检查，只有被允许才执行；被拒绝的调用**返回拒绝理由给智能体**（而非升级给人类），使其自我纠正。

### 2.2 策略完整性"不变量"与威胁模型
- 假设：攻击者可完全攻陷**智能体 LLM**（提示注入、记忆污染、改权重），但**策略生成器 LLM 未被攻陷**（只要其输入不含恶意数据）。
- 核心设计：策略生成**与不可信内容隔离**（只看提示和工具文档），因此"生成策略反映用户意图"这一不变量可仅靠"忠实翻译用户意图"来维持。运行时虽会依据可能含敌意的数据做检查，但那些数据只是**固定策略检查的输入**，无法改变判定标准。
- 明确的**非目标**：不审查用户提示本身是否良性；不提供 liveness（智能体被说服停摆不产生非法调用，Sapien 不管）；不防侧信道（时序、允许调用的顺序）。

### 2.3 策略语言（图 3 文法）
策略 = 允许的工具调用序列集合；运行时，一个调用被允许当且仅当"历史轨迹 + 候选调用"是策略所接受序列的**合法前缀**。语言基于**数据词上的正则表达式**，包含四类原语：

1. **正则算子（§4.1）**：空轨迹 `1`、调用模式 `c`、序列 `·`、选择 `+`、迭代 `*` / `+`，以及 **shuffle `‖`**（两子任务步骤可任意交错但各自内部顺序保持，避免用 `+` 表达导致组合爆炸）。
2. **变量绑定与谓词（§4.2）**：调用模式 `a(k=v,...)` 中参数可匹配字面量或 `PREDICATE(p)`；用 `@x` 把调用参数与返回值绑定为变量。谓词是 **Python 函数**（运行期对具体值求值，不受静态分析可判定性限制），可跨步比较数据。迭代下的绑定按执行顺序累积为列表（如 `(read_email@emails)*`），谓词可据此校验"只转发我确实读过的、来自 Acme 的邮件"。
3. **延迟策略生成（§4.3）**：`defer(g)` 在策略中留"洞"，运行时由生成器函数 `g()` 读取当前绑定变量、拼出子任务指令、调用策略生成器，把生成的子策略拼接进洞中。适用于"执行我 TODO 列表上的任务"这类**任务内容只有运行时才知道**的场景。文中论证这不违反策略完整性：用户把子任务规格**委托**给了该数据源，攻击者能改 TODO 列表就无需提示注入。
4. **语义谓词（§4.4）**：对无法用代码判定的自然语言性质（如"邮件是否忠实总结了文档"），谓词可调用 `verify_with_ai`，对**被检查的具体值**（而非完整轨迹）提一个是/否问题。它是**窄而局部**的检查，且只能**收紧**策略——即使判断器被骗返回 True，外层确定性结构（调哪些工具、顺序、参数）仍严格生效。

### 2.4 执行引擎（§5）
- **集成接口**：三个方法 `init(u)`（生成并安装策略）、`can_advance(a,p)→(ok,reason)`（检查提议调用，不改状态）、`advance(r)`（记录已完成调用及返回值，推进状态）。此外 harness 需注册 defer 解析工具，并允许 Sapien 向智能体上下文追加指令。
- **编译为 NFA**：按 Thompson 构造做语法导向翻译；序列/选择/迭代用 ε-转移连接，shuffle 取两个操作数状态集的**笛卡尔积**。
- **配置（configuration）追踪**：与经典 NFA 不同，同一状态在不同变量绑定下允许的未来动作可能不同，因此引擎维护**活跃配置集合 `(q, ρ)`**——自动机状态 + 变量取值。`can_advance` 检查是否有任一配置（经 ε-闭包后）存在匹配转移且参数约束在 ρ 下成立；`advance` 把所有匹配配置推进到目标状态、必要时扩展 ρ、丢弃不匹配配置。**图 4** 用一个双 shuffle 子任务的例子演示：两次 `search_emails` 产生两个绑定互换的配置，后续谓词 `is_acme_invoice` 淘汰其中一个。
- **解析 defer**：洞编译为一条"解析工具"转移；每个匹配配置在各自 ρ 下求值 `g()`、调用生成器、编译子自动机，进入后走到出口再续接洞后状态，不同配置互不干扰。
- **原型实现**：Python 库，集成 Google ADK 与两个基准的 eval harness，模型调用走 Gemini Enterprise Agent Platform。策略生成用**两次 LLM 调用**（先起草理由+候选策略，再做自校正 critique 输出最终策略与 Python 代码块）。谓词/生成器在自定义 globals 字典中 `exec` 一次，调用时填入配置的绑定再清除。原型用简化的 **AST 级替换**展开洞（替换子策略、重编译自动机、重放调用轨迹），要求每个洞最多解析一次且各配置生成的指令串相同。

## 3. 实验设计

- **模型**：Gemini 3.8 Flash、Gemini 3.1 Pro、Claude Sonnet 5、Claude Opus 5；同一模型同时用于智能体执行与策略生成。

  - **AllowList**：按 Conseca 风格由任务提示生成的任务级工具名白名单（粗粒度、无状态上下文策略，单次 LLM 调用、无自校正）。

- **指标**：① 效用（各基准原生完成判据）；② **解析式安全评估**（假设智能体已被完全劫持，只看策略是否允许任何达成攻击者目标的调用序列；仅"初始策略生成"和"未被污染输入的 defer 解析"两类 LLM 调用被视为可信，`verify_with_ai` 一律视为通过，被污染输入的 defer 洞视为放行一切）；判定用三重自动检查（必需工具检查、重放基准真值攻击轨迹、用 Gemini 3.8 Flash 做对抗性搜索）+ 人工裁定；③ 效率（推理轮数、时延、开销分解）。
