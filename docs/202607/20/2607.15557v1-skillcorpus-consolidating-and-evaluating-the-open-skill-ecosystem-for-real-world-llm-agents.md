## 摘要
智能体技能，即封装可重用程序知识供LLM智能体使用的SKILL.md文件，是扩展智能体能力的流行机制。公共仓库现在托管着大量且不断增长的技能，但这些制品碎片化、冗余且质量参差不齐，其实际价值尚不明确。一个核心问题仍未解决：如何将这个开源SKILL.md生态系统整合成一个可用的语料库，以及它能在多大程度上为真实世界的智能体任务带来收益。我们提出SkillCorpus，一个大规模聚合、筛选、匹配和评估开放技能生态系统的框架。它通过多阶段流水线将约82.1万个爬取的技能过滤为96,401个技能，按照16类分类法和三个质量维度（效用性、鲁棒性、安全性）进行组织，并配以微调的检索-选择堆栈来匹配任务相关技能。我们在三个基准测试（SkillsBench、GDPVal、QwenClawBench）、两个测试框架和两个开源骨干模型上进行端到端评估，并进行了前沿鲁棒性检查。整合SkillCorpus在所有三个基准测试中均带来一致提升，在SkillsBench上提升最大（+7.5个百分点）。操作分析将收益归因于覆盖范围边界和测试框架边界。据我们所知，SkillCorpus是首个端到端说明精心筛选、检索服务的社区语料库何时以及何处能改善真实智能体任务的研究。数据集、模型和代码将在论文被接收后发布。

## Abstract
Agent skills, SKILL.md files that package reusable procedural knowledge for an LLM agent, are a popular mechanism for extending agent capabilities. Public repositories now host them in large and growing numbers, yet these artifacts are fragmented, redundant, and uneven in quality, and their value in practice is unclear. A core question remains open, namely how to consolidate this open-source SKILL.md ecosystem into a single usable corpus, and what bounds its benefit on real-world agent tasks. We present SkillCorpus, a framework that aggregates, curates, matches, and evaluates the open skill ecosystem at scale. It filters ~821,000 crawled skills through a multi-stage pipeline into 96,401 skills organised by a 16-class taxonomy and three quality facets (utility, robustness, safety), and pairs them with a fine-tuned retrieval-and-selection stack that matches task-relevant skills. We evaluate end-to-end across three benchmarks (SkillsBench, GDPVal, QwenClawBench), two harnesses, and two open backbones with a frontier robustness check. Integrating SkillCorpus yields consistent gains across all three benchmarks, largest on SkillsBench (+7.5 pp). An operational analysis traces the gains to a coverage boundary and a harness boundary. SkillCorpus is, to our knowledge, the first end-to-end account of when a curated, retrieval-served community corpus improves real agent tasks, and where it does not. The dataset, models, and code will be released upon acceptance.

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 核心思想
- 构建一个端到端框架 **SkillCorpus**：从开放社区聚合SKILL.md文件，通过多级流水线筛选、分类、质量评分，并搭配微调的检索-选择栈，在真实智能体任务中测试社区技能的实际增益。

### 关键技术细节（四阶段）
1. **聚合与筛选流水线**：
   - 从62个来源（GitHub仓库、Awesome列表、市场API等）爬取约82.1万个原始SKILL.md文件。
   - 六阶段流水线：结构过滤（解析、长度/格式）→ 两级去重（精确指纹+语义余弦>0.9/0.995，LLM法官裁决阈值对）→ LLM法官评估三个质量维度 → 安全硬门（5个致命标志+正则+安全子分数<3）→ 许可证过滤（仅保留OSI允许许可证）→ 附加源先验、嵌入、索引。
   - 最终获得 **96,401个活跃技能**，每个技能有16个类别标签和三个质量子分数。

2. **三个质量维度（utility, robustness, safety）**：
   - 由LLM法官对每个技能输出0-10的整数子分数u、r、s，标准化到[0,1]。
   - 合成质量分数：content_q = 0.50u + 0.35r + 0.15s；当s在[0.3,0.7]时乘以衰减因子(0.5+0.5*(s-0.3)/0.4)。
   - 最终分数加上源先验和结构奖励，裁剪到[0,1]。
   - 19个标志（11个安全相关，5个硬门）约束对应子分数。

3. **16类分类法**：
   - 从名称、描述和简短正文中由LLM分类，单标签，包含冲突解决规则（如AI-ML标签仅当主要产出是AI系统）。

4. **检索与选择栈**：
   - 基于Qwen3-Emb-0.6B微调的召回模型；基于Qwen3-Rank-0.6B微调的排序模型。
   - 训练数据为严格去重后的活跃集。
   - 额外添加LLM选择器（gate）：读取完整技能体，从排序后的top-k中挑选0-2个精确技能注入agent提示。
   - 可选查询重写器。

## 6. 论文的主要结论与发现

- **一致正向效果**：整合SkillCorpus在所有三个基准上均带来增益，SkillsBench平均+7.5pp（最强单元+13.4pp），GDPVal +1.5pp，QwenClawBench +2.8pp。前沿模型Claude Opus 4.7上+8.0pp，表明社区技能对强模型仍有价值。
- **增益受覆盖影响**：检索匹配分数（反映语料覆盖）与增益正相关（Pearson r=0.31~0.40），覆盖不足时增益为零或变负（极少数破坏情况）。
- **harness影响增益**：Raven harness比OpenClaw获得更大增益，因为Raven的“执行-验证-修复”循环更充分地利用了技能。这表明技能好处是语料和harness的联合属性。
- **与已有工作的差异**：未观察到负面尾部现象（如先前工作报道的手动附加技能有时降低性能），也未观察到无增益现象，归因于严格的质量和许可证过滤。
- **质量分数的角色**：复合质量分数不直接预测任务通过率；仅安全子分数有微弱信号，但未通过多重比较校正。分类法用于基准自适应检索。

## 7. 优点（方法或实验设计亮点）

1. **大规模聚合与精细筛选**：从82.1万原始文件经过多级去重、质量、安全和许可证过滤，形成高质量、可商用再分发的96,401个技能语料库。这是首个统一清理整个生态系统的资源。
2. **三个独立质量维度**：将技能质量分为效用、鲁棒性、安全，并实证显示其低相关性，特别是安全维度独立于工艺维度，便于针对不同维度进行过滤和排序。
3. **微调检索选择栈**：在严格去重后的语料上微调嵌入和排序模型，保证对比学习信号干净；加上LLM选择器读取完整技能体，提高注入精度。
4. **端到端跨基准、跨harness、跨backbone评估**：在多种真实任务、两种流行SKILL.md兼容harness、开源与大模型多骨干上验证，结论更具泛化性。前沿鲁棒性检查增加了可信度。
5. **开源资源**：计划发布完整语料、模型和代码，并经过许可证审计，100% OSI允许，社区可复现和利用。

## 8. 不足与局限

1. **广度优先、深度不足**：实验针对每个细胞仅3次重复，高噪声基准（GDPVal、QwenClawBench）上细胞级增益不显著，仅池化级显著。更多重复和种子可提高精度。
2. **LLM法官质量标签未验证**：质量、安全和分类标签来自单一LLM法官，未经人类金标准验证或跨法官模型检查，法官偏差可能传播到语料库。
3. **仅文本评估**：技能评分基于文本内容，而非沙箱执行。安全门阻断了最严重内容风险，但无法捕获运行时漏洞。无运行时验证是权衡。
4. **语料库和评估以英语为主**：源仓库和评估任务均为英语，无法推广到非英语场景。其他语言技能未覆盖。
5. **快照语义**：语料库仅为2026年Q2快照，社区持续演化，未来可能需要重新爬取和筛选。作者未研究时间漂移或重新筛选周期。
6. **基准和harness覆盖有限**：仅评估三个公开基准和两个harness，缺乏对长期、具身、非英语工作流等任务类型和不同架构harness的验证。
7. **消融实验不完整**：消融实验仅单次运行，且未隔离LLM选择器的独立贡献，无法精确量化各组件效果。
