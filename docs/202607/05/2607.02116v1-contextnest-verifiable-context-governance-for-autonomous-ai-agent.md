## 摘要
自主AI智能体日益依赖外部知识存储，然而大多数检索管道仅提供相关性，却无法提供关于来源、版本标识、完整性、可追溯性或时间点重建的持久保证。我们将此问题形式化为“上下文治理”，并提出了ContextNext——一个面向受治理的AI消费知识库的开放规范与参考实现。ContextNext并非替代检索增强生成（RAG），而是为检索提供底层治理层，在检索系统操作之前，确定哪些工件是经过批准、当前有效、可溯源且完整性经过验证的。
该规范结合了带元数据的类型化Markdown文档、确定性集合代数选择器、contextnest:// URI引用、SHA-256哈希链版本历史、图级检查点、通过模型上下文协议（MCP）接入实时数据的源节点，以及智能体上下文消费的审计追踪。这些机制使组织能够重建哪些知识版本影响了智能体的输出，以及这些版本在被消费时是否符合AI使用资格。
我们报告了两个受控实验的首批实证结果。在一个隔离治理与检索失败模式的“过时版本攻击”实验中，受治理的选择严格帕累托支配了BM25稀疏检索，在输入词元成本约为三分之一的情况下，实现了更高的回答质量通过率（97% 对比 93-90%）。在一个包含1060篇文档的检索确定性实验中，确定性选择器和BM25在重复相同查询时返回稳定的文档集（Jaccard系数为1.0），而密集+HNSW基线在80%的查询上呈现非确定性（平均Jaccard系数0.611，最差情况0.210）。这些结果表明，上下文治理能够解决仅靠检索质量无法设计的失败模式。我们以开放许可形式发布了核心引擎、命令行界面（CLI）和MCP服务器。

## Abstract
Autonomous AI agents increasingly depend on external knowledge stores, yet most retrieval pipelines provide relevance without durable guarantees of provenance, version identity, integrity, traceability, or point-in-time reconstruction. We formalize this as context governance and present ContextNext, an open specification and reference implementation for governed AI-consumable knowledge vaults. ContextNext does not replace Retrieval-Augmented Generation (RAG); it supplies the governance layer beneath retrieval, determining which artifacts are approved, current, attributable, and integrity-verified before retrieval systems operate over them.   The specification combines typed Markdown documents with metadata, deterministic set-algebraic selectors, contextnest:// URI references, SHA-256 hash-chained version histories, graph-level checkpoints, source nodes for live data through the Model Context Protocol (MCP), and audit traces of agent context consumption. These mechanisms let organizations reconstruct which knowledge versions informed an agent output and whether those versions were AI-eligible when consumed.   We report first empirical results from two controlled experiments. In a stale-version attack isolating the governance-versus-retrieval failure mode, governed selection strictly Pareto-dominates BM25 sparse retrieval, with higher answer-quality pass rate (97% versus 93-90%) at about one-third the input-token cost. In a retrieval-determinism experiment over a 1,060-document corpus, deterministic selectors and BM25 return stable document sets across repeated identical queries (Jaccard 1.0), while a dense+HNSW baseline is non-deterministic on 80% of queries (mean Jaccard 0.611, worst case 0.210). These results suggest that context governance addresses failure modes retrieval quality alone is not designed to resolve. We release a core engine, CLI, and MCP server under open licenses.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：自主AI智能体（autonomous AI agents）在操作化角色中日益依赖外部知识存储（如文档库），但现有检索管道（RAG、向量检索等）**仅提供相关性（relevance）**，无法提供**持久的上下文治理保证**——包括来源（provenance）、版本身份（version identity）、完整性（integrity）、可追溯性（traceability）、时间点重建（point-in-time reconstruction）。  
  作者将此定义为 **“上下文治理鸿沟（Context Governance Gap, CGG）”**：给AI系统提供信息与确保所消费的信息是经批准、当前有效、可归属、可审计、可验证之间的差距。

- **整体含义**：随着AI代理从文本生成转向操作角色（政策问答、决策起草、工作流协调、工具调用），知识**治理**而非模型能力成为可信企业AI的约束条件。论文认为**检索不是治理（retrieval is not governance）**，RAG的抽象层不提供治理属性，必须由专门的治理层来补充。

## 2. 论文提出的方法论

### 2.1 核心思想
ContextNest是一个开放规范与参考实现，定义了一种**位于RAG之下的治理层**。它不替代检索，而是预先筛选哪些工件（文档、版本）是**经批准、当前有效、可归属、完整性已验证**的；RAG等检索系统仅在该治理子集上操作。

### 2.2 关键技术细节

- **类型化Markdown文档**：文档带YAML前注，包含`type`（如document、snippet、glossary、persona、prompt、source、tool、reference）、`status`（draft/published）、`author`、`version`等元数据。  
- **确定性选择器语法（Selector Grammar）**：基于集合代数（交集`+`、并集`|`、差集`-`）的查询语言，可组合标签、类型、状态等条件。计算是纯函数的，满足**属性4（确定性选择）**。  
- **可寻址URI scheme**：`contextnest://path[@checkpoint][#anchor]`，支持版本固定（pinned）和浮动的解析。  
- **版本历史与完整性验证**：每个文档维护SHA-256哈希链（chain hash），绑定内容哈希、作者、时间戳、序号。采用**关键帧+差异（keyframe+diff）**存储模型，默认每10个版本存一个完整快照。  
- **检查点系统**：每次发布事件生成图级检查点，记录所有已发布文档的版本与哈希，实现跨文档一致性和时间点重建。检查点也有哈希链，与文档链交叉绑定。  
- **源节点（Source Nodes）**：通过MCP协议声明式集成实时数据（如API调用），水合结果仅在会话作用域，可配置**暂存状态（staged state）**以闭环审计缺口。  
- **审计追踪**：每次上下文注入生成结构化记录，包括URI、版本、检查点、作者、时间戳等，满足属性5（可追溯性）。  
- **管理模型（Stewardship）**：分级责任制（Viewer/Editor/Reviewer），在托管模式下强制职责分离——作者不能批准自己的版本进入发布状态。

**形式化定义**：论文给出了6个上下文治理属性（命题1），并证明标准RAG抽象不提供其中任何一个。威胁模型涵盖4种敌手（内容篡改者、历史重写者、检查点伪造者、过时版本诱导者）。

## 6. 论文的主要结论与发现

1. **过时版本攻击中，受治理的Selector严格帕累托支配BM25**：  
   - Selector通过率97%，BM25 leaky 93%，BM25 clean 90%；  
   - Selector平均输入token 215，远低于BM25的655/725（约1/3成本）。  
   - 发现两种BM25失败模式：**过时版本中毒**（检索到已归档的错误版本）和**检索遗漏**（相似度匹配不到正确文档）。

3. **核心主张**：上下文治理解决的是检索质量本身无法设计的故障模式（版本时效性、审计可重复性、确定性）。检索与治理是互补功能，应分层组合。
