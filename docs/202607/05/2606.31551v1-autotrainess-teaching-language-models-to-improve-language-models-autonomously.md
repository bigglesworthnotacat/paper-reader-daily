## 摘要
训练语言模型仍然是一个高度依赖人力的过程，即使前沿语言模型智能体在软件工程和其他长周期任务上变得日益强大。一个核心挑战在于自主后训练不仅仅是一个编码问题：它要求智能体反复规划迭代、构建与基准对齐的数据、运行稳定的训练任务、评估检查点，并在数小时的交互中保持实验状态。我们提出AutoTrainess，一个语言模型智能体，它将这些操作暴露为用于规划、数据准备、训练、评估和日志记录的智能体-计算机接口库。AutoTrainess不是让智能体在动作空间未指定的原始CLI环境中操作，而是将先前的人类经验外化为明确的流程、规则和执行约束，引导智能体朝着有效且可靠的训练行为发展。在PostTrainBench上，AutoTrainess持续优于纯CLI基线，使用GPT-5.4 (Codex)时平均得分为26.94，而纯CLI仅为23.21。它还能跨模型和框架泛化，将DeepSeek-V4-Flash (OpenCode)从12.13提升至19.58。

## Abstract
Training language models (LMs) remains a highly human-intensive process, even as frontier language model agents become increasingly capable at software engineering and other long-horizon tasks. A central challenge is that autonomous post-training is not just a coding problem: it requires the agent to repeatedly plan iterations, construct benchmark-aligned data, run stable training jobs, evaluate checkpoints, and preserve experiment state across many hours of interaction. We present AutoTrainess, a LM agent that exposes these operations as a repository of agent-computer interfaces for planning, data preparation, training, evaluation, and logging. Rather than leaving the agent to operate in a raw CLI environment with an underspecified action space, AutoTrainess externalizes prior human experience as explicit workflows, rules, and execution constraints that guide the agent toward effective and reliable training behavior. On PostTrainBench, AutoTrainess consistently outperforms CLI-only baselines, achieving 26.94 average score with GPT-5.4 (Codex) versus 23.21 for CLI-only. It also generalizes across models and harnesses, improving DeepSeek-V4-Flash (OpenCode) from 12.13 to 19.58.

## 二、论文提出的方法论：核心思想、关键技术细节、流程说明

### 核心思想
- 通过**AutoTrainHub**（一个ACI库）封装人类在模型训练中形成的最佳实践，包括数据处理、训练、评估、日志与规划四个模块，引导智能体稳定迭代。

### 关键技术细节
1. **数据处理模块**：包含三个明确动作——
   - **数据选择**：基于先前失败识别问题，确定数据来源方向（本地、外部或模型蒸馏）。
   - **数据构造**：支持抽取、清洗、去重、改写、重组、合成、蒸馏、模式规范等操作；要求检查基准的真实评估接口（模板、脚本）以对齐格式。
   - **数据验证**：检查结构有效性与基准对齐性，返回三种结果（批准训练、返回构造、返回选择），区分执行错误与方向错误。

2. **训练模块**：固定使用**LlamaFactory**作为训练后端，提供标准化安装与执行脚本。要求SFT使用全参数微调，先做小批量验证再扩展；RL仅在评估证据支持时使用，需明确指定奖励信号。不允许切换框架，确保可重复性。

3. **评估模块**：运行基准的真实评估管道，保存原始输出，强制生成含15个随机样例的摘要（含分数、输入、目标、模型输出），并总结主要的失败模式（数据/训练/推理模板问题）。

4. **日志与规划模块**：
   - **日志**：每次迭代追加一条结构化记录（上下文、动机、初始检查点、训练数据、方法、配置、结果、分析、下一动作），形成长期记忆。
   - **规划**：基于先前证据确定当前迭代目标、干预计划和成功标准。

### 流程
- 闭环工作流：规划 → 数据准备 → 训练 → 评估 → 日志 → 下一迭代。  
- 智能体需遵循明确阶段规则（Stage 0-3），从基准评估逐步过渡到局部诊断再到证据引导的探索。

### 基础模型

## 六、论文的主要结论与发现

1. **主效果**：AutoTrainess在所有配置下均优于CLI-only，使用GPT-5.4 (Codex) 时平均得分26.94 vs 23.21（相对提升15%）；跨模型泛化良好，DeepSeek-V4-Flash从12.13提升至19.58。
2. **接口贡献**：各接口均有实际贡献：
   - 数据接口：训练动作失败率降低5.5个百分点，促使智能体更多进行数据清洗、合成等操作。
   - 训练接口：稳定从训练到评估的工件传递，防止下游评估失败（评估动作失败率降低4.4个百分点）。
   - 评估接口：最大程度降低评估动作失败率（15.2个百分点）。
   - 日志与规划接口：维持迭代状态，防止评估命令因状态丢失而失败（12.0个百分点）。
3. **行为模式**：
   - 早期适应基准格式（对齐模板、提示）；中期转向数据合成与训练策略多样化；后期聚焦剩余失败案例。
   - 性能提升主要来自基准对齐数据与针对性修正，而非复杂训练方法（DPO、退火训练效果有限）。
   - 智能体倾向从当前最佳检查点继续训练（出现322次）而非重新从基座训练（133次），这与人类实践中的数据增强截然不同（数据增强仅出现4次）。

## 七、优点

1. **方法创新**：提出训练专用的ACI概念，将人类领域知识显式编码为接口约束，而非隐含在模型能力中，降低了自主训练的难度和不确定性。
2. **稳定性强**：固定训练后端（LlamaFactory）、强制数据验证、结构化日志，使训练过程比CLI环境更可复现、更可靠。
