## 摘要
数据科学旨在从异构原始数据中提取可操作洞见，释放现代社会产生海量数据的价值。自动化这一过程对于减少数据科学家的劳动密集型工作并实现可扩展的数据驱动应用至关重要。近期，基于大语言模型的数据智能体成为自动化数据科学工作流程的一种有前景的解决方案。然而，该领域缺乏全面的基准，无法以细粒度在多种场景下严格评估这些智能体。为填补这一空白，我们提出AgenticDataBench，一个包含跨多个领域真实任务且带有细粒度真实标签的综合基准。这使得评估能够捕捉数据科学工作流程的多样性和复杂性以及智能体的详细表现。首先，为覆盖不同领域，我们从15个垂直领域收集了真实数据集和任务，其中包括一家领先金融科技公司的5个真实B2B用例。其次，为去除真实任务中的冗余，并为缺乏真实数据的领域生成高质量任务，我们引入了数据科学技能、重复出现的数据中心操作模式，并通过包含的技能数量量化基准覆盖率。代表性技能通过使用技能对齐的层次聚类从Stack Overflow上的大规模任务解决方案中提取。第三，对于真实业务任务，我们选择技能组成多样性最大化的任务-解决方案对，确保广泛覆盖实际场景。第四，为没有真实任务的领域生成逼真任务，我们提出一种系统性的基于LLM的任务生成方法，根据这些技能创建工作流程和任务。最后，我们使用带注释的基准和开源测试平台评估了最先进的数据智能体，提供了详细的技能层面洞见。

## Abstract
Data science aims to derive actionable insights from heterogeneous raw data, unlocking the value of the massive amounts of data generated in modern society. Automating this process is essential to reducing labor-intensive efforts for data scientists and enabling scalable data-driven applications. Recently, large language model (LLM)-based data agents have emerged as a promising solution to automate data science workflows. However, the field lacks comprehensive benchmarks to rigorously evaluate these agents across diverse scenarios with fine-grained granularity. To address this gap, we propose AgenticDataBench, a comprehensive benchmark featuring realistic tasks spanning diverse domains with fine-grained ground-truth labels. This enables evaluations to capture the diversity and complexity of data science workflows and the detailed performance of agents. First, to cover diverse domains, we collect real datasets and tasks from 15 vertical domains, including 5 real-world B2B use cases from a leading fintech company. Second, to remove redundancy in real-world tasks and generate high-quality tasks for domains lacking real data, we introduce data science skills, recurring data-centric operational patterns, and quantify benchmark coverage by the number of skills included. Representative skills are extracted from large-scale task solutions on Stack Overflow using skill-aligned hierarchical clustering. Third, for real-world business tasks, we select task-solution pairs that maximize diversity in skill composition, ensuring broad coverage of practical scenarios. Fourth, to generate realistic tasks for devise domains without real tasks, we propose a systematic LLM-based task generation approach to create workflows and tasks based on these skills. Finally, we evaluate state-of-the-art data agents using our annotated benchmark and open-sourced testbed, providing detailed skill-level insights.

## 2. 论文提出的方法论

### 核心思想
- 将数据科学任务分解为可复用的**数据科学技能**（如“处理缺失数据”、“特征工程”），类似于原子操作模式。
- 通过层次化技能提取、技能多样性驱动的任务选择和覆盖驱动的任务生成，系统性地构建基准实例。

### 关键技术细节
#### 层次化技能提取（Hierarchical Skill Extraction）
1. **初始技能提取**：从Stack Overflow采集6510个高质量数据科学任务解答，用LLM将每个解答分解为逐步技能描述，共得29602条。
2. **嵌入聚类**：用Qwen3-Embedding将技能描述编码为向量，经UMAP降维后用GMM软聚类，形成初始集群（控制每个集群内技能数）。
3. **LLM精炼**：对每个集群，用LLM进一步分割为子集群，对齐更高层技能边界；用DBSCAN合并同义技能。
4. **递归抽象**：将得到的技能汇总后递归进行 聚类-精炼 过程，直到顶层技能数低于阈值（最终获得433个顶层技能）。
5. **人工审查**：由专家检查并修正技能层级中的缠绕（过泛或子技能归属问题）。

#### 基准构建（Skill-based Benchmark Creation）
- **真实业务任务选择**：
  - 从蚂蚁集团收集600个任务，由专家标注每个任务涉及的技能。
  - 采用贪心算法（最大覆盖子模函数优化）选择102个技能多样性最大的任务，确保覆盖所有技能。
  - 专家完善任务描述、评估函数和数据集隐私审查。
- **公开数据集任务生成**：
  - 构建**技能图**：合并Stack Overflow和真实案例中的技能使用轨迹，节点为技能，边为连续使用顺序，权重为频率。
  - **任务原料准备**：从技能图中采样一条路径作为任务所需技能组合；根据技能相关性从现有解答中检索few-shot示例。
  - **LLM生成流程**：
    1. **结构化数据画像**：提取每个数据文件的基本信息、格式特定结构和跨文件关联关系。
    2. **基于技能的工作流生成**：按采样顺序逐步生成动作步骤，集成到工作流中，验证步骤可执行性和依赖一致性。
    3. **任务描述生成**：根据工作流生成自然语言任务描述，并经过六项质量检查（可解性、技能必要性、简洁性等）。
  - **动态采样惩罚**：对已覆盖的技能和已用示例降低采样概率，提升多样性。
  - 最终生成242个任务，经专家注解形成完整实例。

#### 评估管线（Pipeline）
- 每个基准实例包含：任务描述、数据集、**真实解法**、技能标注、评估函数。
- 评估分两步：(1) 任务级评分（表匹配、建模MSE、JSON匹配、图表匹配、文本匹配）；(2) 技能级分析：用LLM对比智能体输出与真实解法，基于技能标注定位错误根因。

## 6. 主要结论与发现

1. **总体性能**：通用智能体框架CodeX（搭配Kimi-K2.5）得分最高（48.8%），但成本也高；轻量级框架Smolagents和DA-Agent可实现更优的成本-性能权衡。
2. **LLM与框架适应性**：不同LLM在不同框架中表现差异显著（例如Claude 4.6在DA-Agent中最佳，Kimi-K2.5在CodeX中最佳），表明框架与LLM的匹配至关重要。
3. **技能级表现**：
   - 数据分析和跨阶段技能（如数据对齐、缺失值处理）是所有智能体的共同薄弱环节。
   - 不同领域有不同挑战性技能（如营销领域“性能指标与优化”得分低）。
   - 技能级评分与任务级评分总体一致，支持技能分析的有效性。
4. **失败模式**：数据分析错误占比最高，全局超限/单步超时/自修复失败主要反映LLM与框架的失调；领域差异明显（如医疗领域自修复失败率高因文件解析错误）。
5. **消融**：增加全局或单步超时预算未能显著改善任务得分，反而可能延长无效循环或误导推理。

## 8. 不足与局限
