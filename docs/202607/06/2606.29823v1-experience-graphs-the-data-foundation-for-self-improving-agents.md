## 摘要
数据库社区通过认识到新工作负载需要新系统架构，反复推动了技术进步。我们认为，长期智能体任务——代码生成、科学发现、硬件设计——正是这样的工作负载。这些智能体进行探索：它们生成工件、执行工具、观察失败、分支并修复，跨越数百步。这种搜索产生了一个我们称之为经验图的结构化对象：可执行工件、工具输出、奖励、兄弟比较和因果谱系。然而，现有的智能体框架将这种体验视为一次性状态——JSON检查点和会话日志，崩溃后无法恢复，无法跨用户查询，也无法物化为训练数据。我们提出Trellis：一个将经验图视为一等、可管理、可查询的数据库状态的数据基础。核心洞察是，在经验图上的搜索是一种数据库访问模式。前沿选择是一种查询，跨会话复用是向量种子图检索，训练数据提取是物化视图，而重建智能体在任一过去步骤所知道的内容是一种时间旅行查询。当数据库拥有经验图时，智能体变成无状态计算，而崩溃恢复、水平扩展和闭环训练飞轮作为架构副产品出现。我们将设计立足于KernelEvolve，Meta的一个生产加速器内核优化器，其中跨会话复用实现了约10倍的目标加速，同时降低了52%的令牌成本。更广泛地说，Trellis将推理时搜索从一次性计算转变为持久的机构资产：日志使数据库可靠；经验图可能使智能体具有累积性。

## Abstract
The database community has repeatedly advanced the state of the art by recognizing that new workloads demand new system architectures. We argue that long-horizon agentic tasks -- code generation, scientific discovery, hardware design -- are such a workload. These agents explore: they generate artifacts, execute tools, observe failures, branch, and repair over hundreds of steps. This search produces a structured object we call an experience graph: executable artifacts, tool outputs, rewards, sibling comparisons, and causal lineage. Yet existing agent frameworks treat this experience as disposable state -- JSON checkpoints and session logs that cannot be recovered after a crash, queried across users, or materialized into training data. We propose Trellis: a data foundation that treats the experience graph as first-class, governed, queryable database state. The core insight is that search over experience graphs is a database access pattern. Frontier selection is a query, cross-session reuse is vector-seeded graph retrieval, training-data extraction is a materialized view, and reconstructing what an agent knew at any past step is a time-travel query. When the database owns the experience graph, agents become stateless compute, and crash recovery, horizontal scaling, and a closed-loop training flywheel emerge as architectural byproducts. We ground the design in KernelEvolve, a production accelerator-kernel optimizer at Meta, where cross-session reuse reaches a target speedup roughly 10x faster at 52% lower token cost. More broadly, Trellis turns inference-time search from disposable computation into a durable institutional asset: logs made databases reliable; experience graphs may make agents cumulative.

## 1. 核心问题与整体含义（研究动机和背景）

- **研究动机**：现有长期智能体任务（代码生成、科学发现、硬件设计、安全研究）通过迭代搜索产生丰富的结构化信息——即“经验图”（包含可执行工件、工具输出、奖励值、兄弟比较、因果谱系等）。然而，当前主流智能体框架（如Claude Code、Codex）和底层存储（Python对象、JSON检查点、文件式记忆）将这种经验视为一次性状态，崩溃后无法恢复、无法跨用户查询、难以物化为训练数据。
- **整体含义**：论文提出，应将经验图作为数据库中的一等公民——持久化、可查询、可治理的数据库状态，从而使得推理时搜索从一次性计算转变为可累积的机构资产。这一思想推动智能体系统从孤立、会话级执行转向可组合、自改进的社区级学习。

## 2. 方法论：核心思想与关键技术细节

### 核心思想
- **双循环架构**：
  - **内循环**：单一智能体会话（如Claude Code），接收任务和上下文，生成候选工件、执行工具、评估并持久化结果。内循环是无状态的，状态完全外化到数据库。
  - **外循环**：搜索策略（One-shot、线性、贪心、MCTS、进化搜索）决定下一步扩展哪个前沿节点。外循环通过读取数据库中的经验图（节点、奖励、统计量）来决策，与具体技能无关。
  - **持久数据基座**：所有探索状态（经验图）存入持久化、可查询的数据库中。智能体成为无状态计算，崩溃恢复、水平扩展、闭环训练飞轮成为架构副产品。

### 关键技术细节
- **逻辑数据模型**：四层分层关系模式：
  - **任务**：规范说明、目标环境、成功指标。
  - **会话**：谁在搜索、使用什么算法、进度。
  - **节点**：每个尝试：父链接、生成的工件、执行输出、适应度分数、算法特定元数据（MCTS的UCB、进化的世代与岛屿）。
  - **提示历史**：LLM看到的和产生的确切消息（用于训练轨迹回放）。
- **物理架构**：分离存储与计算。使用Axiom成本优化器、Velox向量化执行引擎，支持SQL、Cypher（图遍历）、向量检索统一规划，路由到不同后端（操作存储、向量索引、列式仓库）。
- **上下文即管理状态**：通过`prompt_history`表实现子节点继承父节点会话或通过祖先查询重构上下文，实现可恢复、可共享的上下文。
- **向量种子图检索**：给定新任务，先通过嵌入向量检索语义相似的历史任务，再通过图遍历找到对应的高适应度节点子图，注入到当前会话中。检索模式融合向量相似度、关系连接、可变长图遍历。
- **并发多智能体搜索**：多个智能体并行探索同一棵树，插入节点需要原子性，MCTS反向传播时统计量更新容忍最终一致性。
- **多版本状态与时间旅行**：节点不可删除，但某些字段（visit_count、UCB）会被就地更新。Trellis通过变更日志记录字段级变化，以逻辑步骤号（而非时钟时间）作为版本键，实现任意过去状态的重建（AS-OF查询），避免训练数据泄露未来信息。
- **训练数据即物化视图**：
  - **SFT轨迹**：根到叶的无bug高适应度路径。
  - **DPO偏好对**：同父母兄弟节点，适应度差异显著者。
  - **GRPO组**：从持久缓冲区采样状态，生成N个候选，计算组内优势，然后追加一个规范节点。多步展开成本降为单步扩展。
- **值模型**：可利用经验图特征（祖先奖励、兄弟多样性、失败签名、检索分数等）来学习控制外循环的搜索策略。

## 6. 主要结论与发现

1. **跨会话记忆显著加速搜索**：相比冷启动（51步达到1.2×加速比），p=0.1和p=0.5只需约5步即可达到相同阈值——**10倍加速**。
2. **降低错误率与token成本**：
   - 基线55%节点有bug；p=0.1降至34%；p=0.5降至21%。
   - 每个有效节点的token成本降低52%（因避免bug触发昂贵的debug-retry循环）。
3. **存在探索-锚定权衡**：
   - 高注入率（p=0.5）导致搜索多样性下降（仅8种策略组合 vs. 冷启动20种），最佳最终解不如冷启动（1.36× vs. 1.49×）。
   - 平衡设置（p=0.1）在收敛速度与最终质量之间取得最佳折中（产生最多高质量≥1.3×的解）。
4. **训练数据无需重新展开**：生产会话自动生成完整的轨迹，SFT/DPO/GRPO可通过数据库查询直接提取，DRL中的多步展开耗时从数小时降至单步扩展。
5. **领域通用性展示**：将KernelEvolve从内核优化重新应用于MTIA硅验证（bug发现），仅改变适应度函数和技能描述，其余基础设施不变。
