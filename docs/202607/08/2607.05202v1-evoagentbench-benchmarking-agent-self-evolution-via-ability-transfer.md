## 摘要
在长周期LLM系统中，智能体自我进化本质上是程序性的：有用经验不仅仅是存储的信息，而是用于搜索、调试和验证的可重用程序。然而，当前的评估并未区分这种形式的迁移。智能体基准测试测试单轮任务解决；记忆基准测试针对信息保留而非程序复用。我们引入了EvoAgentBench，这是一个通过能力引导迁移跨越四个智能体领域（网络研究、算法推理、软件工程和知识工作）的智能体自我进化基准。EvoAgentBench从智能体执行中提取基于轨迹的能力，将它们规范化为操作单元，并构建特定领域的能力图，连接共享程序重叠的任务。通过设计，每个测试任务都得到经过验证的训练侧能力支持。在528/267的训练/测试划分、两个脚手架和三个骨干模型上，精心策划的能力内容在模型系列之间可靠地迁移，但当前没有任何自动方法在所有设置中保持正向增益。EvoAgentBench将自我进化评估从总体准确性比较转变为对经验编码、路由和吸收的细粒度诊断。该基准可在https://huggingface.co/datasets/EverMind-AI/EvoAgentBench公开获取。

## Abstract
Agent self-evolution in long-horizon LLM systems is largely procedural: useful experience is not merely stored information, but reusable procedures for searching, debugging, and verification. Yet current evaluations do not isolate this form of transfer. Agent benchmarks test single-episode task solving; memory benchmarks target information retention rather than procedural reuse. We introduce EvoAgentBench, a benchmark for agent self-evolution via Ability-guided transfer across four agentic domains: web research, algorithmic reasoning, software engineering, and knowledge work. EvoAgentBench extracts trace-grounded Abilities from agent executions, canonicalizes them into operational units, and builds domain-specific Ability Graphs linking tasks that share procedural overlap. By design, every test task is backed by verified training-side Ability support. Across a 528/267 train/test split, two scaffolds, and three backbones, curated Ability content transfers reliably across model families, but no current automatic method sustains positive gain in all settings. EvoAgentBench shifts self-evolution evaluation from aggregate accuracy comparison to fine-grained diagnosis of experience encoding, routing, and uptake. The benchmark is publicly available at https://huggingface.co/datasets/EverMind-AI/EvoAgentBench.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：现有智能体评估体系无法捕捉智能体自我进化中的关键能力——从先前执行中提取可重用程序（如搜索策略、调试方法、验证流程）并迁移到新任务。当前基准要么只测单回合任务解决（如GAIA、SWE-bench），要么只测信息记忆（如LongMemEval），均未隔离“轨迹到程序”的迁移。
- **总体含义**：作者提出一个原则——自进化基准必须“能力支持但实例不重叠”。即测试任务必须与训练任务共享可迁移的程序性能力，但实例本身不重复。以此构建EvoAgentBench，实现对智能体经验编码、路由和吸收的细粒度诊断。

## 2. 论文提出的方法论

### 核心思想
- 将智能体自我进化形式化为一个受控的“经验→迁移”评估问题。
- 定义**能力 (Ability)** 为基于智能体执行轨迹的可重用操作单元，包含触发条件、可重用过程、边界和角色（方法/防护/工作流）。
- 通过构建领域**能力图 (Ability Graph)** 来保证测试任务有训练侧能力支持，从而隔离测量程序迁移的效果。

### 关键技术细节
1. **多骨干轨迹收集**：使用三个构建骨干（Kimi-K2.5、GLM-5.1、DeepSeek-V3.2）在两个脚手架上执行无技能基线任务，得到轨迹池。
2. **基于轨迹的能力提取**：对每个任务，提取器Eϕ（Claude Sonnet 4.6）联合读取任务、目标及多骨干轨迹，生成原始能力卡片（raw Ability cards），每条卡片包含触发条件、过程、证据、边界和角色。
3. **能力规范化**：通过嵌入阻塞、三LLM裁决和领域专家审查，将等价原始卡片合并为规范能力单元，形成共享能力词汇。
4. **能力图构建**：每个领域构建无向图，节点为任务，边连接共享至少一个边合格能力（被至少两个任务支持且操作具体）的任务。使用Louvain社区检测划分局部程序重叠区域。
5. **能力感知的划分**：在社区内约束采样，保证每个测试任务至少与一个训练任务共享边缘合格能力，同时优先选择基线得分有提升空间的任务。最终得到528/267训练/测试划分，零个不支持测试任务。

### 评估指标
- 主要指标为平均迁移增益：∆m = (1/|Dtest|) ∑ (rm(x) - r0(x))
- 同时报告交互成本变化（智能体回合数变化百分比）。

## 3. 实验设计

### 使用的数据集/场景（Benchmark）
- 四个长周期智能体领域：
  - **网络研究**：BrowseComp-Plus（830个任务）
  - **算法推理**：LiveCodeBench V6（1055个问题）
  - **软件工程**：SWE-Bench Verified（500个实例）
  - **知识工作**：GDPVal黄金子集（220个任务）
- 总源池2605个任务，EvoAgentBench从中构建528/267训练/测试划分。

### 对比的方法
- **Vanilla**：无进化状态基线。
- **Memento**：通过嵌入相似性检索最近保留的训练案例。
- **ReasoningBank**：从蒸馏推理记忆池检索。
- **GEPA**：在训练集上进化一个提示并广播到所有测试任务（无检索）。
- **Anchor Skill**（诊断参考）：使用策划侧能力标签检索从训练侧构建的能力技能，非部署方法但作为内容可迁移的上界。

- 两个智能体脚手架：OpenClaw（全功能模块化）、Nanobot（超轻量）
- 三个骨干模型：Qwen3.5-27B、Qwen3.5-397B、Gemma-4-31B
- 共6个脚手架-骨干组合，每个组合内固定任务、工具、超时和评分合同。

## 6. 论文的主要结论与发现

1. **能力内容跨模型家族可迁移**：Anchor Skill在所有24个单元格（6设置×4领域）均产生正∆，证明能力图支持足够驱动跨家族迁移。
2. **自动方法脆弱**：每个自动方法在至少一个单元格出现负迁移（Memento在Nanobot/Qwen3.5-27B上SWE降低36.3分）。无自动方法在所有设置保持正增益。
3. **瓶颈在于方法侧提取和路由**：自动方法无法像Anchor那样从训练轨迹中提取等价内容并准确路由。
4. **成本不能替代准确性**：许多方法在已解决任务上增加回合数（如Memento在OpenClaw/Qwen3.5-27B增加39.4%），成本与准确性解耦。

## 7. 优点

- **创新性评估框架**：首次实现“能力支持但实例不重叠”的受控迁移评估，分离了内容质量、路由和吸收。
- **细粒度诊断能力**：通过能力图和Anchor参考，可以定位失败原因是缺少训练能力、提取失败还是路由错误。
- **跨领域多骨干覆盖**：四个不同智能体领域，两种不同规模脚手架，减轻单一设置偏差。
- **成本联合度量**：同时报告准确率和交互成本变化，提供更全面的进化效果画像。
- **公开可用**：基准和代码公开，促进后续研究。

## 8. 不足与局限

- **实验覆盖有限**：仅涵盖文本型长周期任务领域的四个基准，未涉及多模态或具身智能体；仅使用了三个开源评估骨干（Rwen3.5和Gemma），未测试更大或闭源模型（如GPT-4）。
- **能力提取单一性**：提取器使用单一LLM（Claude Sonnet 4.6），规范虽有三裁决和人审，但不同提取器可能产生不同能力词汇。
- **潜在数据污染**：评估骨干可能在预训练中见过源基准数据，但所有方法共享该骨干，绝对分数影响不影响相对比较。
- **测试集采样偏差**：测试任务偏好选择有提升空间的任务（低基线得分），导致平均增益∆大小不等同于随机样本的期望增益，仅适用于方法间相对比较。
- **规模较小**：每个领域测试集56-86任务，对某些领域可能不足以进行鲁棒统计分析。
- **未见领域定义**：未明确如何将能力概念扩展到非结构化或开放式任务（如开放式对话）。
