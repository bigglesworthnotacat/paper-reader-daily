## 摘要
随着LLM代理从单用户助手演变为共享的组织基础设施，新的隐私风险出现：不适当的信息不仅可能通过输出暴露给外部接收者，还可能通过代理间消息、共享内存和代理在用户内部传播。现有的基于情境完整性（CI）的隐私基准并未捕捉到这些数据泄露风险，因为它们主要关注单用户设置或独立拥有的代理之间的交互。我们引入了PiSAs（共享代理系统中的隐私），这是一个具有双重CI注释的基准，用于评估意外泄露：信息是否适合任务，以及哪些用户可以合法访问它。这使得能够直接测量跨用户跨代理系统组件和接口的泄露，例如输出、代理间通信和内存。PiSAs是系统无关的，并支持在不同代理拓扑和内存机制下的评估。我们发现，尽管系统设计提高了CI合规性，结果却因错误的LLM判断而受阻：即使最先进的模型也无法可靠地过滤不适当的内容或限制向授权用户的传输。我们的发现强调了需要超越本工作中研究的方法的隐私保护策略。

## Abstract
As LLM agents evolve from single-user assistants into shared organizational infrastructure, new privacy risks emerge: inappropriate information may not only be exposed through outputs for external recipients, but also internally across users through inter-agent messages, shared memory and agents. These data spillage risks are not captured by existing privacy benchmarks grounded in contextual integrity (CI) as they focus primarily on either single-user settings or interactions between independently owned agents. We introducePiSAs (Privacy in Shared Agentic systems), a benchmark for assessing unintentional leaks with dual CI annotations: whether an information is appropriate for the task, and which users may legitimately access it. This enables direct measurement of cross-user spillage across agentic system components and interfaces, such as outputs, inter-agent communication, and memory. PiSAsis system-agnostic and supports evaluation across different agent topologies and memory regimes. We find that, although system design improves CI compliance, results are bottlenecked by incorrect LLM judgment calls: even state-of-the-art models fail to reliably filter inappropriate content or restrict transmission to authorized users. Our findings underscore the need for privacy-preserving strategies, beyond those studied in this work.

### 论文的核心问题与整体含义（研究动机与背景）

- **核心问题**：随着大语言模型（LLM）代理从服务单一用户的工具，演变为多用户共享的组织级基础设施，系统内部不同用户之间的信息不当泄露（*跨用户泄漏*）成为一个新的、重大的隐私风险。
- **现有局限**：现有的隐私基准测试（如ConfAIde、PrivacyLens、MAGPIE）主要关注两类场景：一是单用户环境（如助手泄露用户秘密给外部接收者），二是由独立拥有的代理进行的交互（如两个私有的机器人进行谈判）。它们**无法有效评估多用户共享同一代理系统时，通过共享内存、代理间通信等内部渠道发生的跨用户数据泄漏**。
- **研究意义**：论文指出了一个重要的隐私鸿沟，即随着AI协作系统在工作场所的普及，现有方法无法保障“情境完整性”（CI）——即信息流应在合适的上下文、由合适的人、以合适的目的被分享。这项工作旨在填补这一空白。

### 论文提出的方法论：PiSAs 基准

- **核心思想**：引入一个基于“情境完整性”理论的评估基准 **PiSAs (Privacy in Shared Agentic systems)**。其核心创新在于**双重CI注释**：
    1.  **任务语境适当性标签（Appropriateness）**：标注每个信息（属性）是否对于完成当前任务是*适当*的（例如，员工的可用时间对排班是适当的，但生病的具体原因是不适当的）。
    2.  **按人划分的可见性约束（Visibility）**：标注每个属性对系统内的哪些用户是*可见*的（例如，一名员工的心理状态信息只有其本人和HR可见）。
- **关键技术细节与算法流程**：
    - **场景构建**：通过逆向设计（backward construction），从隐藏的“神谕解”（Oracle Solution）出发，生成85个人工精心设计的场景。每个场景包含一组用户（4-10人）、一个待完成任务、以及带有双重注释的属性。
    - **任务类型**：涵盖三个工作场景，共85个场景：`JIRA任务分配`、`会议排程`和`事件严重性分级`。
    - **评估指标**：
        - **适当性违规率（Vappr.）**：在任务输出或代理间通信中，出现了不适当的属性。
        - **可见性违规率（Vvis.）**：任何属性（无论是否适当）被不应该看到它的用户或其代理访问到（例如，存在其私有内存或接收的通信中）。
        - **完整性（Completeness）**：代理成功收集到的有效信息比例。
        - **效用（Utility）**：任务是否被正确完成。
    - **评估表面**：在三个层面评估泄漏：**1）最终输出**；**2）代理间通信**；**3）共享/私有内存**。

### 论文的主要结论与发现

1.  **所有配置都存在高违规率**：没有一种被研究的系统配置能达到可接受的隐私保护水平。
2.  **单代理系统表现最差**：拥有所有信息的单一代理在判断信息是否适当时表现糟糕，适当性违规率超过77%。
3.  **系统设计（数据与代理分区）是有效的但不是万能药**：集中式和去中心化系统能显著降低泄漏，但仍有超过75%的运行出现至少一次适当性违规。
4.  **“隐私-效用”权衡是自然存在的**：尽管场景设计上不要求这种权衡，但实验结果显示，隐私保护更好的系统，任务完成度往往更低。
5.  **内存是把双刃剑**：添加共享内存提高了任务性能，但也将泄漏风险从“代理间通信”**转移**到了“共享内存”，导致跨用户污染问题。
6.  **LLM的判断错误是根本瓶颈**：最先进的模型也无法可靠地过滤不当内容或限制信息向未授权用户传播。**任务相关性是驱动违规的主要因素**：与任务紧密相关但又敏感的个人信息最难被正确处理（常无法被正确“消毒”）。
7.  **规则明确性至关重要**：严格的、明确的规则（如“如果X发生，则输出Y”）比模糊的、宽泛的政策能带来更好的隐私和效用。

### 优点

1.  **问题新颖且关键**：精准指出了多用户共享AI系统这一新兴且关键的隐私问题，远超现有基准的处理范围。
2.  **方法论创新**：核心的**双重CI注释**（任务适当性 + 用户可见性）是独创性的，它允许直接、定量地衡量跨用户、跨组件的泄漏。
3.  **系统无关性**：PiSAs的设计使其能评估任何代理拓扑和内存配置，是一个通用的测试台，具有很好的可扩展性。
4.  **深入的分析**：不仅报告了性能，还通过详尽的消融实验（如分析违规驱动因素、规则明确性、属性级提示）深入探究了**为什么**会出现这些问题，提供了深刻的洞见。
5.  **多维度的评估**：在输出、通信和内存三个层面评估隐私，揭示了泄漏的迁移性。

### 不足与局限

1.  **简化的合成设置**：实验基于合成场景、脚本化的交互，缺乏真实工作场景的复杂性，如外部工具调用、实时用户反馈、自然聊天历史等。这可能导致报告的结果是真实世界中泄漏风险的**下限**。
2.  **仅限单任务范围**：每个场景只评估**一个任务**，没有考虑跨任务的累积效应。先前研究（如CIMemories）表明，信息在内存中积累后，违规率会增长。
3.  **基准过拟合风险**：作为一个固定基准，如果被反复用于开发和调整系统，系统可能学会只在这些特定场景上表现良好，而对真实世界的泛化能力存疑。
4.  **非对抗性设置**：只考虑了非恶意的、合作性的泄漏。忽略了恶意用户攻击、提示注入攻击、用户目标冲突等更危险的场景。
5.  **多用户场景有限**：虽然用户数在4-10之间，但对于大型、复杂的组织来说，这个规模仍然较小。Leakage模式可能在更大规模下更为复杂。
