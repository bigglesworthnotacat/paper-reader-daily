## 摘要
最近的LLM智能体能够处理越来越长周期、开放式的任务，而外部技能（提供给智能体的可重用程序性知识）进一步扩展了这一能力。然而，固定的、手动编写的技能很少是最优的，并且无法适应智能体遇到的任务多样性。自我改进的智能体通过从执行轨迹中重写自己的技能文件来解决这个问题，在具有挑战性的基准测试上取得了有意义的增益。然而，这种自我进化仍然是非递归的：它只改进了任务技能（智能体做什么），而改进过程（如何改进）是一次性编写并保持不变的。我们引入了MetaSkill-Evolve，这是一个双时间尺度框架，使智能体的技能改进变得递归：每个分支都携带一个任务技能$s$和一个分支本地元技能$m=(ψ,σ,α,π,\varepsilon)$，其五个组件分别参数化了改进流程的分析器、检索器、分配器、提议器和进化器智能体。任务技能在快速循环中进化，而元技能在较慢的循环中通过相同的流程应用于自身而进化，无需额外的模型或目标。所有五个流程智能体共享一个固定的基础模型，MetaSkill-Evolve在三个智能体基准测试（OfficeQA、SealQA、ALFWorld）上超越了无技能、静态技能和单层进化基线，分别将原始基础模型的保留测试准确率提高了+23.54、+16.09和+1.92个百分点。

## Abstract
Recent LLM agents tackle increasingly long-horizon, open-ended tasks, and external skills, reusable procedural knowledge supplied to the agent, further extend this capability. However, a fixed, hand-authored skill is rarely optimal, and cannot adapt to the diversity of tasks an agent encounters. Self-improving agents address this by rewriting their own skill files from execution traces, yielding meaningful gains on challenging benchmarks. Yet such self-evolution remains non-recursive: it improves only the task skill (what the agent does) while the improvement procedure (how it improves) is authored once and held fixed. We introduce MetaSkill-Evolve, a two-timescale framework that makes agentic skill improvement recursive: every branch carries both a task skill $s$ and a branch-local meta-skill $m=(ψ,σ,α,π,\varepsilon)$ whose five components parameterise the Analyzer, Retriever, Allocator, Proposer, and Evolver agents of the improvement pipeline. Task skills evolve on a fast loop while the meta-skill evolves on a slower one under the same pipeline applied to itself, with no additional model or objective. With all five pipeline agents sharing a single frozen backbone, MetaSkill-Evolve outperforms no-skill, static-skill, and single-level evolution baselines on three agentic benchmarks (OfficeQA, SealQA, ALFWorld), improving held-out test accuracy over the raw backbone by +23.54, +16.09, and +1.92 points respectively.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题**：当前 LLM 智能体通过外部“技能”（可复用的程序性知识）来增强长时、开放式任务处理能力。但固定编写的手工技能无法适应任务多样性。已有的自我改进系统（如 EvoSkill、GEPA、SkillWeaver）通过“分析→提议→进化”管道从执行轨迹重写技能，但改写的**对象是任务技能**（智能体做什么），而**改进过程本身**（如何诊断、检索、分配、提议、执行）是手工固定且全局保持一致，无法随分支经验或失败模式自适应调整。这导致“自改进”但非“递归自改进”，进化容易陷入停滞。
- **整体含义**：论文试图将改进过程本身也作为可进化的一类对象（元技能），使得智能体不仅能改进自身行为，还能改进改进自身的方式，从而实现一种**有限度的递归自改进**。

## 2. 方法论：核心思想、关键技术细节、公式或算法流程

- **核心思想**：引入双时间尺度的进化框架，每个分支携带状态 $b = (s, m, h)$，其中 $s$ 是任务技能，$m = (\psi, \sigma, \alpha, \pi, \varepsilon)$ 是分支本地的元技能，$h$ 是迭代历史。任务技能在**快循环**（每次迭代）进化，元技能在**慢循环**（每 $H$ 次快迭代）进化，且二者共享同一五智能体管道（分析器、检索器、分配器、提议器、进化器）。
- **关键技术细节**：
  - 元技能的五个组件各自是一个 Markdown 格式的 LLM-agent 程序，与任务技能格式相同，因此同一管道可以递归地应用于元技能自身，无需额外模型或目标函数。
  - 快循环（Algorithm 1）：选择前沿父节点 → 恢复分支状态 → 在训练集上评估找出最差样例 → 调用五智能体管道生成 $K$ 个候选子技能 → 每个子技能在验证集上评估获得增益 $\Delta U$ → 每 $H$ 次插入慢循环 → 提交子节点到 DAG 并同步前沿。
  - 慢循环（Algorithm 2）：聚合最近 $H$ 个后代的 $\Delta U$ 得到元生产力估计 $\hat{P}(m|s)$ → 构建元失败轨迹 $f_m$ → 对元技能的五组件进行全量改写（渐进式累积子代）。
  - 前沿选择公式：$v^* = \arg\max_{v\in\mathcal{F}} \left[ \eta_1 U_v + \eta_2 \hat{P}_v + \eta_3 N_v \right]$，其中 $U$ 是任务效用（验证精度），$\hat{P}$ 是平均子代增益，$N$ 是节点被选次数惩罚（$\frac{1}{1+\text{times\_selected}}$）。
- **算法流程文字说明**：
  - **快循环（一次任务技能迭代）**：
    1. 从前沿选择父节点，恢复其任务技能和元技能快照到磁盘。
    2. 用父任务技能在训练集上评估，选得分最低的样例作为诊断目标。
    3. 分析器（$\psi$）输出问题标签 $\phi$ 和自由形式分析 $a$。
    4. 检索器（$\sigma$）根据 $\phi$ 从 DAG 中提取同分支和跨分支灵感。
    5. 分配器（$\alpha$）根据分支历史和分析选择子代数量 $K$。
    6. 提议器（$\pi$）为每个子代生成一个编辑 $\delta$；进化器（$\varepsilon$）将编辑写入磁盘并验证。
    7. 在验证集上评估每个子代技能，计算增益 $\Delta U$。
    8. 若当前是 $H$ 的倍数，触发慢循环更新元技能。
    9. 将所有子代节点提交到持久化 DAG，同步前沿。
  - **慢循环（元技能更新）**：
    1. 计算最近 $H$ 个子代增益的平均值 $\hat{P}$。
    2. 将 $H$ 个迭代的标签、诊断、结果构建为元失败轨迹。
    3. 用同一五智能体管道（目标文件改为元技能文件）对元技能五个组件进行全量改写，渐进式累积子代。
- **公式**：任务效用 $U(s)=\mathbb{E}_{(x,y)\sim\mathcal{T}}[r(A_s(x),y)]$；元生产力 $P(m|s)=\mathbb{E}[\frac{1}{K}\sum_{k}(U(s'_k)-U(s))]$；前沿选择得分 $=\eta_1 U_v+\eta_2 \hat{P}_v+\eta_3 N_v$。

## 7. 优点

- **递归自改进的实践落地**：将元技能与任务技能格式统一，无需新增架构或目标函数，借用同一管道实现限制递归。
- **双时间尺度设计**：快循环分离了任务技能更新与元技能更新，避免元技能被单步噪声干扰，保持稳定性和效率。
- **前沿选择融合多指标**：同时考虑效用、元生产力和节点新奇度，平衡探索与利用，防止搜索陷入局部最优。
- **模块化元技能**：五个组件分别控制分析、检索、分配、提议、执行，每个组件可独立进化，解释性强。
- **实验设计全面**：包含主结果、消融、超参数敏感性、训练/验证比例分析，且使用保留测试集保证公平比较。
- **跨分支共享机制**：通过检索器实现跨分支经验传递，加快进化速度。

## 8. 不足与局限
