## 摘要
自我进化框架通常优化任务解决方案，同时将周围框架视为固定不变。我们提出感知框架的自我进化（HASE），一种智能体强化学习框架，其中单一模型可以在多轮行动空间中生成任务解决方案或编辑选定的框架组件。HASE使得单一Qwen3-8B模型能够匹配使用Claude Code作为框架提案者的GPT-OSS-120B模型在文本分类上的性能。在阿尔法因子挖掘中，HASE超越了已报告的GPT-OSS-120B基线。HASE还能修复不完善的评估组件，并在圆形打包算法发现中收敛至最先进性能。这些结果表明，HASE通过统一的智能体过程改进了框架和解决方案。

## Abstract
Self-evolving frameworks usually optimize task solutions while treating the surrounding harness as fixed. We introduce Harness-Aware Self-Evolving (HASE), an agentic reinforcement-learning framework in which a single model can generate task solutions or edit selected harness components in a multi-turn action space. HASE enables a single Qwen3-8B model to match the text-classification performance of a GPT-OSS-120B model that uses Claude Code as the harness proposer. In alpha factor mining, HASE outperforms the reported GPT-OSS-120B baseline. HASE also repairs imperfect evaluation components and converges to state-of-the-art performance in circle-packing algorithm discovery. These results show that HASE improves the harness and the solution through one unified agentic process.

### 1. 论文的核心问题与整体含义

-   **研究动机：** 现有的自我进化（Self-Evolving）系统（如用于代码生成的AlphaEvolve、FunSearch等）通常假设外部环境或“框架”（Harness）是**固定不变的**，只专注于优化任务解决方案（Object-level Solution）。“框架”包含所有中介组件，例如提示词（Prompts）、记忆（Memory）、检索机制（Retrieval）、上下文管理、评估器（Evaluators）等。这种固定假设存在两个主要局限：
    1.  **有缺陷的评估器：** 人工编写的评估器可能不完整，与真实环境不一致。在基于分数的优化下，模型可能会“奖励黑客”（Reward Hacking），利用评估器的漏洞而非真正解决问题。
    2.  **低效的引导：** 即使评估器正确，引导框架（如提示词、记忆检索策略）可能提供较差的搜索先验信息，限制了模型的探索能力。
-   **核心问题：** 如何让一个AI系统不仅能自主优化任务解决方案，还能自主优化其自身运行所依赖的“框架”，从而实现更深度的自我进化？

### 2. 论文提出的方法论

-   **核心思想：** 提出**感知框架的自我进化（HASE，Harness-Aware Self-Evolving）** 框架。HASE是一种**智能体强化学习（Agentic Reinforcement Learning）** 框架，它将**模型权重、任务解决方案和选定框架组件**三者置于同一个进化过程中，实现协同进化。
-   **关键技术细节：**
    1.  **两种框架组件：**
        -   **引导组件（Guidance Components）：** 如提示词、记忆格式、上下文检索脚本等，用于改进搜索质量。HASE可以自由改进这些组件。
        -   **评估组件（Evaluation Components）：** 如验证器和评分器，用于定义解决方案的有效性和任务指标。HASE仅在本地代理评估器与外部“真实评估器”（Real-World Evaluator）结果不一致时，才对其进行修复。这防止了无约束的“奖励黑客”行为。
    2.  **统一动作空间（Unified Action Space）：** 模型在同一个多轮动作空间中，既可以“提交解决方案”，也可以使用`sandbox`工具（如`cat`， `replace`等）来检查和修改可编辑的框架文件。
    3.  **HASE算法流程（Agentic RL View）：**
        -   算法围绕**阶段（Phase）** 组织，每个阶段包含多个**GRPO（Group Relative Policy Optimization）** 轮次。
        -   在每个轮次中，模型执行多轮交互（Trajectory Rollout），生成解决方案或编辑框架。轨迹的奖励仅由最终解决方案的质量决定，不直接奖励框架编辑行为本身（避免对“探索”的奖励）。
        -   在**阶段边界（Phase Boundary）**，HASE执行**阶段级评审（Phase-level Review）**：
            -   **引导组件：** 收集本阶段所有通过“概念验证（PoC）”的候选编辑，然后在验证集上进行排序，只提交能稳定提升性能的最佳编辑。
            -   **评估组件：** 当本地评估器的代理分数（Proxy Score）与真实评估器的真实分数（Oracle Score）产生分歧时，将出现不一致的案例加入“不一致集（Mismatch Set）”。只有能修复更多不一致案例，且不破坏现有功能的评估器补丁才会被接受。
    4.  **奖励设计：** 避免直接奖励框架访问行为。一个轨迹的奖励只由其最终提交的解决方案质量决定。对于评估组件编辑，奖励仅与解决代理和真实评估器之间的分歧（即修复不一致案例）成正比。

5.  **收敛保证：** 框架编辑和学习理论上的收敛性未得到明确保证，尽管实验上显示了有效收敛。
