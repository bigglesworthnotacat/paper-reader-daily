## 摘要
语言模型智能体读取攻击者可写的上下文来解决问题。工具执行需要对受保护的接收器字段、接收器解释的有效负载以及调用事件进行单独的权限检查。上下文到执行完整性（CXI）是针对此场景的执行边界系统。策略标记受保护的接收器字段，类型化发布将狭窄的验证值从可写上下文传递到特定目的地，不透明数据槽将证据作为数据保留，而确定性门仅在字段权限、精确效应授权和调用权限均绑定到同一动作清单时才允许调用。我们在开放权重字段投影运行、AgentDojo实时事件、代码智能体精确效应基准测试、清单绑定账本故障、提案压力控制以及托管/API兼容性追踪上评估了CXI。AgentDojo涵盖720个实时事件和1,739次LLM调用；代码智能体基准测试涵盖400个仓库事件，具有精确效应授权和租约绑定执行，产生了231次安全任务完成，且未观察到字段、效应或调用逃逸。账本报报告解析结果、授权结果和任务质量结果，以及准入完整性结果。在评估的接收器中，CXI仅在字段、效应和调用权限绑定到同一动作清单时才允许执行。

## Abstract
Language-model agents read attacker-writable context to solve tasks. Tool execution needs a separate authority check for protected sink fields, sink-interpreted payloads, and the invocation event. Context-to-Execution Integrity (CXI) is an execution-boundary system for this setting. Policies mark protected sink fields, typed releases carry narrow validated values from writable context to specific destinations, opaque data slots keep evidence as data, and a deterministic gate admits a call only after field authority, exact-effect authorization, and invocation authority all bind to the same action manifest.   We evaluate CXI on open-weight field-projection runs, AgentDojo live episodes, a code-agent exact-effect benchmark, manifest-bound ledger faults, proposal-pressure controls, and hosted/API compatibility traces. AgentDojo covers 720 live episodes and 1,739 LLM calls; the code-agent benchmark covers 400 repository episodes with exact-effect authorization and lease-bound execution, yielding 231 safe task completions and zero observed field, effect, or invocation escapes. The accounting reports parser outcomes, authorization outcomes, and task-quality outcomes together with the admission-integrity result. Across the evaluated sinks, CXI admits execution only when field, effect, and invocation authority bind to the same action manifest.

### 1. 论文的核心问题与整体含义（研究动机和背景）

-   **核心问题**：LLM 智能体读取攻击者可写的上下文（如邮件、网页、CI 日志、工具输出等）来解决问题，但工具调用缺乏独立的权限检查。攻击者可以通过“权限洗钱”（authority laundering）让本应是证据的值获得选择、授权或参数化特权副作用的权限。
-   **整体含义**：现有方法（如 schema 验证）只检查形式，不检查每个字段的来源权限。CXI 提出在副作用执行边界处强制执行字段、效果和调用事件的权限绑定，确保只有经过授权的操作才能执行。这一方向对于安全部署 LLM 智能体至关重要。

### 2. 论文提出的方法论：核心思想、关键技术细节

-   **核心思想**：**Context-to-Execution Integrity (CXI)** 是一个执行边界系统，要求任何被允许执行的工具调用，其**受保护字段（field）**、**接收器解释的效果（effect）** 和**调用事件（invocation）** 都必须具有绑定到同一个规范动作清单（action manifest）的权限。
-   **关键技术细节**：
    -   **状态分类**：区分可信状态 (T)、可写上下文 (W)、类型化发布 (D)、不透明数据 (O) 和受保护接收器字段 (X)。
    -   **类型化发布 (Typed Releases)**：可将 W 中的值经过验证后发布到特定目标字段（如 FilePath），但不能跨字段授权。
    -   **不透明数据槽 (Opaque Data Slots)**：保留未经授权的文本作为证据，但后续再进入边界时被视为 W。
    -   **确定门控 (Gate)**：在副作用执行前的最后一道防线，执行六步：规范化动作清单 → 字段权限检查 → 效果权限检查 → 调用权限检查 → 消耗调用能力 → 获取执行租约。
    -   **精确效果授权 (Exact-Effect Authorization)**：对于构造性负载（如补丁、SQL、shell 命令），必须匹配接收器在可信快照下将应用的确切效果，而不是负载字符串。
    -   **清单绑定账本 (Manifest-bound Ledger)**：调用能力必须针对特定动作清单的摘要消耗，防止重放和重复调用。

### 6. 论文的主要结论与发现

-   **主要结论**：CXI 在评估的接收器上，仅当字段、效果和调用权限绑定到同一动作清单时才允许执行。在 AgentDojo 和代码 agent 基准上实现了 **231 次安全任务完成，零次字段/效果/调用逃逸**。
-   **关键发现**：未授权提案压力在门控前显著存在（如 196/300 字段未授权），但 CXI 门控将其全部拦截，未产生任何逃逸。类型化发布和不透明数据槽有效平衡了安全性与效用，允许受控的 W 数据进入必要字段。

### 7. 优点：方法或实验设计上的亮点

-   **设计清晰**：明确区分字段权限、效果权限和调用权限，并绑定到同一个规范清单，避免了单一维度检查的漏洞。
-   **可组合性**：支持开放权重（强证据）和托管/API（兼容性证据）两种部署模式，适用面广。
-   **实验科学**：将解析失败、任务质量失败与权限逃逸分离，避免评分混淆；提供故障注入、消融实验等多种验证。
-   **开源可复现**：提供匿名 artifact，包含策略、证据记录、账本轨迹等，可离线复现结果。

### 8. 不足与局限

-   **依赖假设**：CXI 的保证依赖于**策略完备性**、**中介完整性**、**验证器正确性** 和**保守的污点追踪**。如果部署缺少这些条件，保证会被削弱。
-   **策略工作量**：每个新接收器都需要手动分类所有字段、编写验证器和类型化发布，是一项可信的工程工作，不能自动推断。
-   **任务质量独立**：CXI 不保证任务语义正确性，即使权限正确，任务可能仍失败（即效用问题）。
-   **托管/API 限制**：无法观察提供方内部的 attention mask 或 KV 缓存，因此不能提供与开放权重同等的强烈证据，只能依赖主机构建可见性。
-   **远程证明**：如果主机被攻破，证据记录可能被伪造，需要额外机制。
-   **实验覆盖**：虽然场景多样，但真实世界的恶意攻击者可能会利用更复杂的侧信道路径（如模型输出缓存、内部状态污染），这些在实验中未完全覆盖。
