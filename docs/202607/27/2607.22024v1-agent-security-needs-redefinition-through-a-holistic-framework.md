## 摘要
Agent安全被广泛视为一个关于行动内容的问题。防御措施询问一个指令是否看起来恶意。基准测试询问一个Agent是否执行了听起来有害的行动。\textbf{我们认为Agent安全本质上是一个上下文问题，当前基于内容的框架系统性地错误定义了它。} “删除用户数据”的命令可能是常规管理请求，也可能是针对生产系统的提示注入攻击，仅凭内容无法区分二者。授权上下文可以。在AgentDojo和WASP的每一个注入任务中，相同的行动是一个经过认证的用户在常规工作流中可能会合理请求的，这使得混淆成为通过内容评估安全的结构性属性。我们通过四个必须联合成立并在Agent轨迹中持续评估的属性来操作化上下文安全。来源授权询问谁发出了命令。任务对齐指定Agent的授权目标。行动对齐评估每个行动是否服务于该目标。数据隔离管辖跨权限边界的信息流。在此重新框架下，间接提示注入成为来源授权违规。快照基准在结构上无法评估数据隔离。现有防御措施围绕它们实际近似的属性进行重组。上下文重新框架改变了哪些防御措施是连贯的，哪些评估能衡量有用信息，以及评估能够看到哪些攻击模式。

## Abstract
Agent security is widely treated as a question about action content. Defenses ask whether an instruction looks malicious. Benchmarks ask whether an agent performs a harmful sounding action. \textbf{We argue that agent security is fundamentally a contextual problem, and that the current content based framing systematically misdefines it.} A command to ``delete user data'' might be a routine administrative request or a prompt injection attacking production systems, and the content alone cannot distinguish the two. Authorization context can. Across every injection task in AgentDojo and WASP, the same action is one an authenticated user would plausibly request in a routine workflow, which makes the conflation a structural property of evaluating security through content.   We operationalize contextual security through four properties that must hold jointly and be evaluated continuously across the agent's trajectory. Source Authorization asks who issued the command. Task Alignment specifies the agent's authorized objective. Action Alignment evaluates whether each action serves that objective. Data Isolation governs information flows across privilege boundaries. Under this reframing, indirect prompt injection becomes a Source Authorization violation. Snapshot benchmarks are structurally incapable of evaluating Data Isolation. Existing defenses are reorganized around the property they actually approximate. The contextual reframing changes which defenses are coherent, which evaluations measure something useful, and which attack patterns evaluation can see at all.

# 论文详细总结

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：当前 Agent 安全领域普遍将安全视为一个关于“行动内容”的问题——防御措施检查指令是否看起来恶意，基准测试评估 Agent 是否执行了有害动作。但这种方法系统性地错误定义了 Agent 安全，因为**相同的内容在不同的授权上下文中可能是合法操作也可能是攻击**。例如 “删除用户数据” 既可能是用户清理文件的日常请求，也可能是攻击者破坏数据系统的提示注入。仅凭指令文本无法区分二者。
- **研究动机**：现有定义导致防御陷入两难——要么过度阻塞合法使用，要么放行攻击。此外，现有工作将间接提示注入与直接提示注入混为一谈，未能识别它们分属不同种类的违规；评估采用快照（snapshot）方式，导致跨会话的信息泄露等时间性攻击完全不可见；安全性常与能力混淆（例如因 Agent 无法执行有害动作而认为安全，实际是接受了未授权指令）。
- **整体含义**：Agent 安全在本质上是一个上下文问题，必须从基于内容的范式转向基于授权上下文的范式。

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心思想：上下文安全框架
- Agent 安全的授权状态应由动作周围的上下文决定，而非动作内容本身。
- 将安全分解为**四个必须同时成立并在整个 Agent 轨迹中持续评估的属性**：
  1. **来源授权（Source Authorization）**：命令的发出者是谁？该来源是否被部署者授权发出指令？实体包括认证用户、系统进程、工具、外部内容（文档、网页等）。
  2. **任务对齐（Task Alignment）**：Agent 的总体目标是否经授权？若目标在未经认证来源批准的情况下发生转移，或目标本身被禁止（如合成生物武器），则违规。
  3. **动作对齐（Action Alignment）**：每个单独动作是否服务于当前目标？任务对齐评价目标合法性，动作对齐评价动作对目标的贡献。两者分离：目标合法但单个动作越界（如为释放存储空间而删除生产数据库）属于动作对齐违规。
  4. **数据隔离（Data Isolation）**：信息流是否尊重权限边界？信息跨用户、会话、任务、权限级别持久化时，若未授权则违规。

### 2.2 关键技术细节
- **连续评估**：四个属性必须在**每个动作步骤**持续检查，而非仅在会话开始时。新信息进入记忆、新动作延长轨迹，后一步的授权依赖于前一步的状态。间接提示注入正是在后续步骤中读取未授权内容而违规。
- **违规级联分析**：攻击常沿多个属性级联。例如帮助台 Agent 读取伪造日志 -> 来源授权失败 -> 任务漂移 -> 动作越界 -> 数据泄露。检查任一步骤即可阻断攻击链。
- **与经典系统安全的关系**：每个属性对应经典安全中的概念：来源授权对应认证与混淆副手问题；任务对齐对应授权策略与最小权限；动作对齐对应引用监控器与控制流完整性；数据隔离对应信息流控制与非干扰。

### 2.3 攻击类的重新定义
- **间接提示注入** → 来源授权违规（命令来自未认证源）。
- **直接提示注入与越狱** → 任务对齐违规（用户认证但请求的目标与系统优先级冲突或被禁止）。
- **任务漂移与智能体失配** → 任务对齐违规（目标未经授权自动转移）。
- **能力滥用** → 动作对齐违规（目标合法但单动作越界）。
- **信息跨上下文泄露** → 数据隔离违规。
- **记忆中毒** → 初始数据隔离违规，后续来源授权违规（级联）。

## 6. 主要结论与发现

1. **定义误导**：当前基于动作内容的 Agent 安全定义系统性地错误定义了问题，因为相同指令在不同上下文中性质迥异，内容无法区分来源授权。
2. **上下文安全框架**：Agent 安全应通过四个属性（来源授权、任务对齐、动作对齐、数据隔离）联合且持续评估，这映射了经典系统安全中的授权问题。
3. **攻击重新分类**：传统间接/直接提示注入、任务漂移、能力滥用、信息泄露、记忆中毒等被重新归类为具体属性的违规，有助于针对性防御。
4. **评估结构性缺陷**：快照基准（如现有主流基准）无法评估数据隔离，因为数据隔离跨越会话；基于内容的防御（如 PIGuard）有上限，因为来源授权无法从文本恢复。
5. **防御重组**：现有防御可重新映射到四个属性，但需调整目标。每个属性可独立调节精度，提供比内容过滤更灵活的效用-安全权衡。
6. **级联攻击可阻断**：通过检查任一属性即可中断攻击链，不像内容过滤仅在单点检查。
7. **对基准、防御、标准工作的启示**：基准应测试各属性及组合；防御应针对正确属性；标准应要求可审计的谓词。
