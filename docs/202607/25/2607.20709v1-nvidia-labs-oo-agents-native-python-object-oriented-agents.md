## 摘要
传统的智能体开发分散在提示模板、工具模式、回调和流程图中。我们提出NVIDIA面向对象智能体（NOOA），一个与模型无关的Python框架，用于构建可靠的AI智能体。NOOA采用更简单的方法：智能体是一个Python对象。其方法是模型可以执行的动作，字段是其状态，文档字符串是其提示，类型注解是契约。代码体由“...”组成的方法在运行时由LLM驱动的智能体循环完成，而具有正常体的方法仍然是标准确定性Python。这为开发者和智能体提供了相同的接口，因此智能体行为可以像其他软件一样被测试、追踪、重构和改进。 本文有三个贡献。（1）我们提出了智能体作为Python对象的编程模型及其背后的设计原则。Python已有抽象的地方，我们直接采用。智能体特定能力——上下文、事件、状态渲染、长期记忆和经过验证的LLM循环——通过简单的Python式API暴露，因此开发者和智能体共享一个熟悉的编程模型。（2）我们确定了六个面向模型的思想，据我们所知，NOOA是第一个将它们结合在单一界面上的：类型化输入/输出、对活动对象的引用传递、代码作为动作、可编程循环工程、显式对象状态以及模型可调用的上下文和事件工具API。我们发现社区已经在其中几个思想上趋同——通常作为实验性或部分特性——并进行了比较以鼓励进一步采用。（3）我们证明当前模型有效地使用这个界面，无论是在针对性能力测试中，还是在诸如SWE-bench Verified、Terminal-Bench 2.0和ARC-AGI-3等智能体和推理基准测试中。

## Abstract
Traditional agent development is split across prompt templates, tool schemas, callback code, and workflow graphs. We present NVIDIA Object-Oriented Agents (NOOA), a model-agnostic Python framework for building reliable AI agents. NOOA takes a simpler approach: an agent is a Python object. Its methods are the actions the model can take, fields are its state, docstrings are its prompts, and its type annotations are contracts. A method whose code body consists of "..." is completed at runtime by an LLM-driven agent loop, while methods with normal bodies remain standard deterministic Python. This gives developers and agents the same interface, so agent behavior can be tested, traced, refactored, and improved just like other software.   This paper makes three contributions. (1) We present the agent-as-a-Python-object programming model and the design principles behind it. Where Python has existing abstractions, we adopt them directly. Agent-specific capabilities--context, events, state rendering, long-term memory, and validated LLM loops--are exposed through simple Pythonic APIs, so both developers and agents share one familiar programming model. (2) We identify six model-facing ideas that NOOA is, to our knowledge, the first to combine on a single surface: typed input/output, pass-by-reference over live objects, code as action, programmable loop engineering, explicit object state, and model-callable harness APIs for context and events. We find the community already converging on several of these ideas--often as experimental or partial features--and present the comparison to encourage further adoption. (3) We demonstrate that current models use this interface effectively, both in targeted capability tests and on agentic and reasoning benchmarks such as SWE-bench Verified and Terminal-Bench 2.0 and ARC-AGI-3.

## 2. 方法论：核心思想、关键技术细节

### 核心思想
- **智能体即Python对象**：代理是一个Python类，其方法是模型可调用的动作，字段是状态，文档字符串是提示，类型注解是契约。
- **方法体区分**：
  - 正常方法体：代码体完整，为确定性Python代码，由开发者编写。
  - 代理方法体：代码体为“...”（省略号），由LLM驱动的代理循环在运行时填充完成。
- **策略（Strategy）**：代理方法通过装饰器声明策略，控制执行方式：
  - **PredictStrategy**：单次调用，用于分类/提取，渲染上下文后调用LLM，验证输出。
  - **CodeActStrategy**：迭代式Python REPL循环，模型可执行Python代码、调用内部方法、访问对象状态，直到调用`return_result`返回结果并验证。

### 关键技术细节
- **上下文管理**：上下文分为三个区域：
  - 静态上下文（static context）：系统提示等稳定信息。
  - 事件历史（event history）：执行轨迹，每个事件是带标签的Python对象。
  - 动态上下文（dynamic context）：每轮重新计算的动态信息（如状态、待办列表）。
- **按引用传递**：代理方法的输入是活Python对象，模型仅看到类型、长度和边界预览，但可通过代码直接操作完整对象，从而突破上下文窗口限制。
- **代码即动作**：模型通过编写Python代码（包括控制流、`asyncio`、库调用）来行动，而非使用JSON工具调用。
- **可编程循环工程**：控制流（单代理和多代理编排）用普通Python实现，开发者与代理均可编写。
- **显式对象状态**：持久状态存储在代理对象的字段中，每轮渲染到提示中，而非仅存在于对话历史。
- **工具API暴露**：上下文、事件历史、状态等通过Pythonic API暴露给开发者和模型。

### 算法流程（文字说明）
1. 代理方法调用。
2. 上下文渲染：静态+事件历史+动态。
3. 调用LLM，获取模型动作（PredictStrategy要求返回类型化值；CodeActStrategy要求选择`execute_python`或`return_result`）。
4. 若选择`execute_python`，在受限Jupyter-like会话中执行代码，结果捕获为结构化事件。
5. 更新事件和状态。
6. 若模型调用`return_result`，验证返回值类型，有效则返回给调用者；无效则返回错误消息让模型重试。

## 6. 主要结论与发现

1. **当前模型能有效使用NOOA界面**：能力测试整体通过率97.9%，大型前沿模型99.2%，证明模型零样本即可理解类型化方法调用、按引用传递、代码执行等抽象。

3. **基准性能领先**：

4. **接口设计优势**：按引用传递、代码即动作、显式对象状态、验证终止等特性，使NOOA在相同模型下使用更少token和调用次数达到更高性能。

## 7. 优点

- **统一编程模型**：将代理开发与普通Python开发对齐，降低学习成本，提升测试与重构可行性。
- **模型即用性**：界面基于Python主流抽象，模型零样本即能理解，无需额外训练。
- **创新组合六项能力**：类型化I/O、按引用传递、代码即动作、可编程循环、显式状态、工具API暴露，据论文称首次在单一框架中同时实现。
- **解耦确定性逻辑与LLM逻辑**：通过方法体区分“...”和实代码，开发者可将精确规则、算术等移出循环，减少LLM负担。
- **高效上下文管理**：静态/动态/事件三区域设计最大化KV缓存复用，按引用传递减少上下文膨胀。
- **记忆子系统**：模型自主管理长期记忆，提供ACT-R激活检索、异步整合、类型化引用，显著提升ARC-AGI-3性能（+11.8 RHAE）。
- **验证终止**：强制模型返回类型化结果，防止过早或无效声明完成。
- **扩展性**：策略可插拔，记忆可安装/卸载，上下文和事件API开放给模型。
