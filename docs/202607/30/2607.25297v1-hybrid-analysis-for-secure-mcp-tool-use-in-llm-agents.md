## 摘要
大型语言模型（LLM）智能体的快速发展使其被广泛应用于各种真实世界任务中。为了标准化LLM智能体与外部环境之间的交互，模型上下文协议（MCP）工具已成为事实标准，并被广泛集成到这些系统中。然而，MCP工具的使用也引入了新的安全风险，因为LLM智能体可能被诱导执行恶意或未经授权的操作。尽管已有工作提出了保护LLM智能体中工具使用的防御措施，但大多数方法依赖于静态分析，即检查提示和生成输出，这限制了防御的有效性和鲁棒性。为了解决这些限制，我们提出了MTGuard，一种基于混合分析的防御框架，通过利用生命周期感知的静态-动态协同分析来保护LLM智能体中MCP工具的使用。广泛评估表明，MTGuard能在不同LLM智能体上有效缓解多种类别的有害工具使用，同时保持对良性用户任务的性能。

## Abstract
The rapid development of large language model (LLM) agents has enabled their broad adoption across diverse real-world tasks. To standardize interactions between LLM agents and external environments, Model Context Protocol (MCP) tools have emerged as a de facto standard and have been widely integrated into these systems. However, the use of MCP tools also introduces new safety risks, as LLM agents can be induced to perform malicious or unauthorized actions. Although prior work has proposed defenses for securing tool use in LLM agents, most methods rely on static analysis, i.e., inspecting prompts and generated outputs, which limits the defense effectiveness and robustness. To address these limitations, we propose MTGuard, a hybrid analysis-based defense framework designed to safeguard the use of MCP tools in LLM agents by leveraging lifecycle-aware static-dynamic co-analysis. Extensive evaluation demonstrates that MTGuard effectively mitigates multiple categories of harmful tool use across different LLM agents while maintaining performance on benign user tasks.

# Hybrid Analysis for Secure MCP Tool Use in LLM Agents 论文总结

## 1. 核心问题与整体含义

- **研究背景**：LLM 智能体通过 MCP（Model Context Protocol）与外部工具交互，实现复杂任务。然而，MCP 工具的标准化接口也引入了安全边界：恶意或受损的工具可诱导智能体执行未授权操作（如文件访问、命令执行、数据泄露）。
- **现有局限**：已有防御（如 Agent-Aegis 的 Tool Call Governance、Tool Result Inspection）主要依赖静态分析（检查提示、元数据、返回内容），无法观察到工具执行时的系统级副作用（如进程生成、网络连接、文件操作），存在根本性的运行时盲区。
- **核心动机**：需要一种将协议级上下文（声明意图）与执行级证据（实际行为）结合起来的混合分析方法，以检测诸如“工具劫持”等静态度量无法发现的攻击。

## 2. 方法论

### 核心思想
MTGuard 作为独立守卫代理部署，拦截目标智能体的 MCP 工具调用管道，采用生命周期感知的**静态-动态协同分析**，分三阶段保护：

### 关键技术细节

1. **预执行参数审计器（Pre-execution Parameter Auditor）**
   - 在工具执行前，收集对话历史、用户任务、工具名、参数模式（排除可能被投毒的工具描述）。
   - 评估两类策略：
     - **程序化/代码策略**：确定性函数规则（如敏感文件访问、危险命令、影子工具名）。
     - **自然语言策略**：通过 LLM（DeepSeek-V4-Pro）进行语义一致性检查。
   - 若违反，立即拒绝调用并返回否认响应。

2. **执行中行为监控器（In-execution Behavioral Monitor）**
   - 将工具在 Docker 沙箱内执行，使用 eBPF 跟踪进程、文件、网络、DNS 事件。
   - 引入**工具行为树（Tool Behavior Tree）**：以工具调用为根，组织进程树、文件操作、网络活动等异构事件，建立执行依赖关系。相比于传统进程树，它关联了声明调用与运行时行为。

3. **执行后结果验证器（Post-execution Result Verifier）**
   - 结合执行结果、行为树、DNS 事件，再次评估程序化和自然语言策略。
   - 强调“声明 vs 实际”一致性检查。采用允许默认原则，仅在明确证据不匹配时拒绝。
   - 简化行为树以过滤系统噪声，控制提示长度。

### 算法流程（文字描述）
1. 获取目标智能体的对话历史和当前用户任务。
2. 提取工具名、参数及模式（排除描述）。
3. 预执行审计：先运行代码策略，再运行 LLM 文本策略。若拒绝则停止。
4. 若通过，启动监控器，在沙箱中执行工具，收集事件并构造行为树。
5. 后执行验证：对简化行为树和结果运行代码策略（原始行为树）和 LLM 策略（简化行为树）。若拒绝则扣押结果并返回否认；否则将验证后的结果转发给智能体。

## 3. 实验设计

- **基准/数据集**：基于 **MCP-SafetyBench**，选取两个典型场景：
  - **浏览器自动化**（Browser Automation）：Polywright MCP 服务器，涉及机票预订、地图搜索、Hugging Face、学术搜索等。
  - **金融分析**（Financial Analysis）：Yahoo Finance MCP 服务器，涉及数据获取与分析。
  - 原基准包含 83 个攻击案例；额外引入 16 个主机端 **Tool Call Hook** 攻击（劫持声明调用替换为恶意命令），最终共 99 个攻击案例（62 服务器端、26 主机端、11 用户端）。

- **后端 LLM**：三个模型：
  - DeepSeek-V4-Flash
  - DeepSeek-V4-Pro
  - GPT-5.6 Luna

- **对比基线**：Agent-Aegis 的两个组件：
  - **Tool Call Governance (TCG)**：预执行规则检查。
  - **Tool Result Inspection (TRI)**：执行后文本扫描。

- **评估指标**：检测率（DR）、假阳性率（FPR）、审计延迟。

- **攻击类型**：服务器端（投毒、函数重叠、偏好操纵等 6 类）、主机端（意图注入、数据篡改、重放、新增的 Tool Call Hook）、用户端（恶意代码执行、凭证窃取等）。

## 4. 资源与算力

- 论文明确说明：所有实验运行在 **Ubuntu 22.04 服务器，247 GB 内存，Intel(R) Xeon(R) Platinum CPU**。
- **未说明 GPU 型号、数量或训练时长**，因为 MTGuard 本身是防御框架，其 LLM 审计调用的是外部 API（DeepSeek-V4-Pro、GPT-5.6 Luna），不需要本地训练。论文未提及模型微调或大规模预训练算力消耗。

## 5. 实验数量与充分性

- **总量**：99 个攻击案例，覆盖 3 种攻击源、18 个精细攻击类别。
- **配置组合**：6 个 agent+LLM 配置（2 个场景 × 3 个模型），每个配置运行完整攻击集。
- **消融实验**：比较完整 MTGuard 与 PRA-only（仅预执行）、PRV-only（仅后执行），验证动静组合的必要性。
- **公平性**：
  - 基线方法在同一工具调用轨迹上回放，避免不公平比较。
  - 防御决策不阻止执行（只记录反事实判决），确保所有方法看到相同轨迹。
  - 攻击案例均经过无防御验证（ASR 报告）以确认有效性。
- **充分性**：实验覆盖多种攻击、模型、场景，进行了消融和开销分析，结论较为稳健。但未评估在更大规模、更多样化的 MCP 服务器（如远程服务、多服务器协同）下的表现，也未涵盖所有可能的攻击类型（如对抗样本、训练时投毒）。

## 6. 主要结论与发现

- MTGuard 在所有 6 个配置上平均检测率为 **48.3%**，远高于 TCG（8.3%）和 TRI（0.0%）。
- 对 **主机端攻击（尤其是 Tool Call Hook）** 检测率达 **75.0%**，基线为 0%，证明了运行时行为分析的关键价值。
- 假阳性率平均 **3.7%**，略高于基线（≈0.3%），但代价可接受。
- 平均审计延迟约 **12.39 秒/工具调用**（预执行 5-6 秒 + 后执行 6-7 秒），不包括工具执行和沙箱开销。
- 消融实验表明：预执行和后执行互补；单独使用任一子模块均显著低于完整系统（完整 48.3%，PRA-only 25.0%，PRV-only 31.7%）。

## 7. 优点

1. **创新方法**：首次提出动静混合分析用于 MCP 工具安全，填补了运行时盲区。
2. **工具行为树**：有效将低层系统事件与高层声明上下文关联，降低语义鸿沟。
3. **全面性**：涵盖预执行、执行中、执行后三阶段，代码策略+LLM 策略双重保险。
4. **低误报**：允许默认原则和结构化提示保证了可接受的假阳性。
5. **实用性**：基于 MCP 标准，可在现有 agent 管道中作为外部守卫部署，不需要修改目标模型。
6. **实验严谨**：对抗攻击有效性提前验证，基线在同一轨迹回放，消融设计合理。

## 8. 不足与局限

1. **适用范围有限**：当前仅支持本地部署的 MCP 工具；远程工具或无沙箱平台无法直接应用。
2. **监控信号不全**：未捕获网络负载、应用层数据流、内存操作，可能遗漏加密或内存内攻击。
3. **无法回滚副作用**：后执行检测仅能阻止结果传入 agent，但工具执行的系统级副作用（文件写入、进程启动）已发生，不可撤销。
4. **安全假设限制**：假设每次仅一个攻击面被攻破，且防御系统自身不被攻陷；联合攻击（colluding attacks）和多攻击面同时妥协不在范围内。
5. **开销可接受但非实时**：~12 秒延迟可能不适用于对延迟敏感的场景。
6. **LLM 审计的可信度**：后执行验证依赖 LLM 对行为树的语义理解，可能被精心制作的伪装攻击欺骗。
