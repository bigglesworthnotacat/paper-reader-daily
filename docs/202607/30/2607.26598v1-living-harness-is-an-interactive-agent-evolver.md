## 摘要
大型语言模型（LLM）智能体可能在一个回合内或重试后从失败中恢复，但相同的执行失败可能在后续任务中再次出现，因为回合后的反馈很少修改指导未来交互的持久性缰绳。静态缰绳通过固定的工具、上下文、记忆和工作流结构提高可靠性，但在部署后保持不变。我们提出了$\textbf{活体缰绳}$（Living-Harness），一种自我演化的智能体缰绳，它将每个完成的轨迹及其评估器信号转化为有界缰绳更新的后验证据。在领域级别的$\textbf{演化标准操作流程}$（$\textbf{Evolution-SOP}$）指导下，活体缰绳提取回合抽象和结构化更新证据，并写入两种互补的程序性知识：记录触发条件、失败模式和恢复动作的情景记忆，以及记录状态节点、修复边和转换规则的状态图。更新后的缰绳状态被检索以指导未来交互，而工具和基础上下文保持不变，允许程序性修复在演化周期中累积。在源自$τ^2$-Bench和MultiWOZ-2.4的八个交互式环境中，活体缰绳分别比最强的交互式基线提高了10.07和9.91个百分点的平均Pass@1，并支持跨模型骨干仅通过检索重用演化后的缰绳状态。

## Abstract
Large language model (LLM) agents may recover from a failure within an episode or after a retry, yet the same execution failure can recur in later tasks because post-episode feedback rarely revises the persistent harness that guides future interactions. Static harnesses improve reliability through fixed tools, context, memory, and workflow structures, but remain unchanged after deployment. We propose $\textbf{Living-Harness}$, a self-evolving agent harness that converts each completed trajectory and its evaluator signals into posterior evidence for bounded harness updates. Guided by a domain-level $\textbf{Evolution-SOP}$ ($\textbf{S}$tandard $\textbf{O}$perating $\textbf{P}$rocedure), Living-Harness extracts an episode abstraction and structured update evidence, and writes two complementary forms of procedural knowledge: episodic memory that records trigger conditions, failure patterns, and recovery actions, and a state graph that records state nodes, repair edges, and transition rules. The updated harness state is retrieved to guide future interactions, while tools and base context remain frozen, allowing procedural repairs to accumulate across evolution cycles. On eight interactive environments derived from $τ^2$-Bench and MultiWOZ-2.4, Living-Harness improves average Pass@1 over the strongest interactive baseline by 10.07 and 9.91 percentage points, respectively, and supports retrieval-only reuse of the evolved harness state across model backbones.

## 1. 核心问题与整体含义（研究动机和背景）
- **问题**：现有LLM智能体（agent）依赖**静态缰绳（static harness）**——即固定的工具、上下文、记忆和工作流结构。虽然智能体能在单回合内或通过重试从失败中恢复，但由于回合后反馈很少修改指导未来交互的持久性缰绳，相同的执行失败会在后续任务中反复出现。
- **背景**：
  - 智能体系统通过外部缰绳（harness）组织提示、工具、上下文、记忆、工作流和评估接口来提高可靠性。
  - 现有方法分为两类：一是缰绳设计与工作流优化（预部署后固定，无法吸收新观察到的失败模式）；二是反思与经验记忆（存储批评或总结，但文本教训缺乏触发条件、所需工具动作和工作流转换等可执行细节）。
  - 缺失的能力是**持久性程序修复（persistent procedural repair）**：将评估器驱动的失败证据转化为可重用的“何时失败→缺少什么动作/转换→后续如何恢复”的关系。
- **核心目标**：使智能体能够将回合后失败转化为可持久的程序性修复，并跨回合积累。

## 2. 方法论：核心思想、关键技术细节与流程
### 2.1 核心思想
- 提出**活体缰绳（Living-Harness）**，一种自我演化的智能体缰绳，将每个完成的轨迹及其评估信号转换为有界缰绳更新的后验证据。
- 工具和基础上下文保持冻结，只有**情景记忆（Episodic Memory）**和**状态图（State Graph）**演化。
- 演化由领域级别的**演化标准操作流程（Evolution-SOP）**引导。

### 2.2 关键技术细节
- **缰绳状态表示**：
  - \( H_d^{(n)} = \langle C_d^{\text{act}}, \psi_d, S_d^{(n)} \rangle \)，其中：
    - \( C_d^{\text{act}} \)：固定的执行资源（工具、基础上下文、领域规则）。
    - \( \psi_d \)：固定的Evolution-SOP，控制回合后更新。
    - \( S_d^{(n)} = \langle R_d^{(n)}, G_d^{(n)} \rangle \)：演化状态。
      - \( R_d^{(n)} \)：情景记忆，存储触发条件、失败模式、恢复动作。
      - \( G_d^{(n)} \)：状态图，存储状态节点、修复边、转换规则。
- **演化流程（Rollout–Evaluate–Update循环）**：
  1. **检索**：从当前情景记忆和状态图中检索与当前任务相关的上下文 \( \kappa_n \)。
  2. **交互（Rollout）**：智能体使用固定资源和检索到的上下文执行任务，生成轨迹 \( \tau_n \)。
  3. **评估**：评估器产生评估信号 \( y_n \)。
  4. **后验生成**：Evolution-SOP驱动后验抽象 \( e_n = \text{Post}(x_n, \tau_n, y_n, C_d^{\text{act}}) \)，提取任务目标、已验证事实、关键失败/恢复点。
  5. **证据提取**：将抽象转换为结构化候选更新证据 \( u_n = \langle u_n^R, u_n^G \rangle \)。
  6. **有界更新**：通过模式门、范围门、证据门、约束门、合并门检查后，将更新写入情景记忆和状态图，生成 \( S^{(n+1)} \)。
- **程序状态POMDP视角**：引入回合级程序状态 \( z^{(n)} \)，与环境状态 \( s_t \) 联合信念更新，证明增加程序状态信息可以收紧贝叶斯误差界。

## 6. 主要结论与发现
1. **显著性能提升**：Living-Harness在τ²-Bench上平均Pass@1达83.09%（超过最强旗舰Gemini 3 Pro的82.92%），在MultiWOZ-2.4上达65.50%，分别比最强交互式基线提高10.07和9.91个百分点。
