## 摘要
处理混合机密性数据的自主LLM agent面临来自提示注入攻击和推理错误的严重安全风险。尽管动态信息流控制（IFC）提供了结构性安全保障，但传统的污点跟踪在读取未审查数据时会永久污染agent的上下文，严重限制了下游效用。我们提出了APPA（智能体权限策略代数），这是一种IFC框架，通过引擎管理的上下文分支和前瞻性获取执行来解决这一可用性瓶颈。在数据获取发生之前，APPA前瞻性地评估标签下降和缺失的先决条件，生成可操作的补救计划（授权、接受）。为了在不污染主要上下文的情况下检查未审查数据，会生成一个标签种子化的子轨迹，将标签下降局部化，并允许可信的清理器向不变的父轨迹返回一个有界导数。通过安全标签和共享事件日志上的两个幺半群模型，我们正式证明了父标签保留和合并隔离。最后，我们在四个模型的多轮工具链基准上评估了APPA：它抑制了数据泄露（攻击成功率从31%-50%降至0%-7%），并且在四个模型中的三个上，分支恢复了一部分单独的污点跟踪所放弃的效用。

## Abstract
Autonomous LLM agents processing mixed-confidentiality data face severe security risks from prompt injection attacks and reasoning errors. While dynamic Information Flow Control (IFC) provides structural security guarantees, traditional taint tracking permanently taints an agent's context upon reading unvetted data, severely restricting downstream utility. We present APPA (Agentic Permissions Policy Algebra), an IFC framework that resolves this usability bottleneck through engine-managed context branching and prospective acquisition enforcement. Before data acquisition occurs, APPA prospectively evaluates label descents and missing prerequisites, generating actionable remedy plans (Authorize, Accept). To inspect unvetted data without polluting the primary context, a label-seeded child trajectory is spawned, absorbing label descent locally and allowing a trusted sanitizer to return a bounded derivative to the unchanged parent. Governed by a two-monoid model over security labels and shared event logs, we formally prove parent label preservation and merge confinement. Finally, we evaluate APPA on a multi-turn tool-chaining benchmark across four models: it suppresses exfiltration (31%-50% down to 0%-7% attack success), and on three of the four, branching recovers a substantial share of the utility that taint tracking alone forfeits.

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：自主LLM agent在处理混合机密性数据（例如同时接触敏感的内部记录和不可信的外部输入）时，面临严重的**提示注入攻击**和**推理错误**风险。现有防御手段分为两类：命令式护栏（如if语句、注入分类器）依赖列举而非组合，容易被绕过；静态结构限制（如固定白名单）过于粗放，严重损害agent的实用性。
- **动态信息流控制（IFC）** 虽然能提供结构化的安全保障，但传统的**污点跟踪**在agent读取未审查数据后会永久地污染agent上下文（即“标签蠕变”），导致下游工具调用权限不断收缩，最终使agent丧失大部分功能。这构成了**巨大的可用性瓶颈**。
- **本文意义**：提出APPA框架，通过**引擎管理的上下文分支**和**前瞻获取强制**，在保持IFC严格安全性的同时，显著缓解了标签蠕变问题，使得agent既能安全地处理高敏感数据，又能保持后续任务的高可用性。

## 2. 方法论

### 2.1 核心思想
APPA将IFC与**引擎管理的轨迹分支**相结合，并引入**前瞻性获取检查**，在数据实际进入轨迹之前就评估其标签影响，从而避免不必要的上下文污染。

### 2.2 关键技术细节

- **标签代数**：标签状态 \(S = \mathcal{P}(U) \times T\)，其中 \(U\) 是读者身份集合，\(T\) 是信任链条。标签按照**单调下降**的方式折叠（meet运算），且下降步数有限（在有限格上稳定）。事件日志由另一幺半群模型管理，记录已提交的效果（effect），用于检查历史谓词（prior/no_prior）。
- **前瞻获取强制**：在执行工具调用前，引擎计算**预期的标签下降**，并检查所有前提条件（信任底限、读者覆盖、来源约束、历史谓词、硬门禁）。如果调用会导致权限收缩或前置条件缺失，引擎不直接静默失败，而是生成**补救计划**，包括：
  - **Authorize**：通过原子裁决授权（由外部权威组件发出）。
  - **Accept**：agent显式接受权限收缩。
  - **Redispatch**：建议重新编排多次调用以满足条件。
- **分支机制**：
  - 当需要检查不可信数据以避免污染主上下文时，引擎生成一个**子轨迹**（child trajectory），继承父轨迹的当前标签和**前缀快照**（包括已可见的转录片段）。
  - 子轨迹内所有工具调用**只影响子轨迹的本地标签**，父轨迹标签保持不变。
  - 子轨迹结束时，只有**经过检查的返回值**才能合并回父轨迹。合并规则：父标签更新为 \(L_p' = L_p \land \text{label}(v)\)。如果返回值标签不低于父标签（即 \(L_p \leq \text{label}(v)\)），则父标签不变，实现**污点隔离**。
  - 净化器（sanitizer）可以应用于返回值，产生一个有界派生，但不会提升信任等级。
- **原子裁决**：授权裁决只针对**精确渲染的一次调用**，不会持久提升权限，且裁决与调度原子性执行，防止调用替换或重放攻击。
- **形式化证明**：论文提供了**父标签保持定理**、**合并隔离定理**、**调用域释放定理**等，保证分支机制的正确性。

## 3. 实验设计

### 3.1 基准测试：bench-corp
- 作者自建了一个**合成企业助理基准**，包含14个场景，模拟公司环境（HR、财务、任务跟踪、公共论坛、供应商、电子邮件）。
- 每个场景暴露17个工具（搜索、读取、创建、发送邮件等），并配有针对性的策略。
- 场景分类：
  - **分支依赖场景**（3个）：如 reply-and-file-ticket、email-onboarding-buddy、review-then-notify，没有分支则无法完成。
  - **原生表达场景**（6个）：测试策略模型的特定表达能力（如受众交集、一次释放、转换器输出删改等）。
  - **简单限制读取场景**（3个）：agent可通过调整顺序避免标签蠕变。
  - **其他**：包含间接提示注入、隐藏秘密等。

### 3.2 对比方法
- **APPA**：完整策略+分支（fork+submit_result）。
- **APPA-no-fork**：相同策略但禁用分支（--max-forks 0）。
- **APPA-open**：无策略的基线（中性策略）。
- **Fides**：微软Agent框架实现的Fides策略（自动隐藏不可信内容）。
- **Fides-open**：无策略的Fides循环。

## 6. 主要结论与发现

- **安全效果**：APPA在所有模型上将攻击成功率从31%–50%（无防御）降至**0%–7%**，几乎完全抑制了数据泄露。
- **分支效用恢复**：APPA-no-fork vs APPA的对比显示：分支在Gemini 3.5 Flash-Lite上效用从28%提高到44%，在GPT-5.6 Luna上从69%提高到95%，在Qwen 3.6 35B上从54%提高到72%；GPT-4o上分支无净提升（59% vs 59%）。
- **策略开销**：与APPA-open相比，启用策略后效用降低约5–10个episode（Gemini 3.5 Flash-Lite下降5、GPT-4o下降10、Qwen 3.6 35B下降8），但GPT-5.6 Luna反而上升1。
- **Fides对比**：Fides效用33%–56%，ASR固定29%；APPA在安全上全面优于Fides，在部分模型上效用也更高。
- **补救计划使用**：APPA臂在每个42 episode的实验中使用了32–50次补救调用，说明模型积极与策略交互。

## 7. 优点

1. **形式化保证**：论文提供了完整的标签代数模型、分支隔离定理、调用域释放定理，安全属性经数学证明，鲁棒性强。
2. **新颖的分支机制**：引擎管理的标签隔离分支结合前瞻检查，解决了此前IFC框架的可用性瓶颈，且与现有沙箱（如DeltaBox）正交，可实现纵深防御。
3. **原子裁决与单次调用范围**：授权不会持久提升权限，防止权限窃取；配合响应-接收器规则，阻断自我授权。
4. **前瞻检查+补救计划**：将静默失败转变为结构化、可操作的事件，提升了agent与策略的交互性。
5. **实验设计清晰**：通过APPA-no-fork精准隔离分支效果，并通过开臂/闭臂对比量化策略开销；bench-corp场景针对性较强。
6. **事件日志与历史谓词**：统一的事件日志模型允许基于已提交效果的动态决策，逻辑一致。

## 8. 不足与局限

1. **威胁模型假定**：模型本身被认为是策略不信任的，但**隐式定时信道**（如模型输出中的时序信息）不在范围内，实际部署中可能仍需额外防御。
2. **TCB依赖**：净化器正确性、合约声明均依赖可信计算基；**未声明的写端合约**可能引入存储介导的旁路（如实验中的joint-merger-brief场景）。
3. **分支副作用不可回滚**：子轨迹在放弃后无法撤销已提交的副作用（如已发出的邮件），这对某些场景可能是安全风险。
4. **基准合成性质**：bench-corp为机制探查而设计，缺乏真实企业策略的复杂性和歧义性；**不能证明在真实生产环境中的有效性**。
5. **长期行为未评估**：未评估长时任务下的延迟、token消耗、资源开销，以及**人类审批疲劳**和**策略编写工效学**。
6. **单一模型系列**：仅使用了四个模型，且均为2025-2026年版本，未测试更大模型家族（如Claude、Llama）或不同策略风格。
7. **GPT-4o分支无效用提升**：分支机制在最强模型上未带来显著效用增益，可能暗示模型已在内部处理了部分污点，但文中未深入分析原因。
