## 摘要
大型语言模型（LLM）代理易受安全风险攻击，例如来自不可信上下文的提示注入攻击，这些攻击会操纵下游推理和工具使用。现有的设计安全方法通过将不可信观察与特权执行分离并谨慎控制信息流来减轻此风险，但通常会降低效用并需要大量特定于任务的工程工作。因此，我们提出了双代理（Twin Agent），一种受代理上下文中的残差编码启发的通用特权分离设计模式。双代理由两个几乎对称的代理组成：一个检查不可信信息的探索代理（Explore Agent）和一个执行特权操作的安全代理（Safe Agent）。探索代理以安全代理的当前上下文为条件，仅向安全代理传递关于下一步动作的紧凑提示。这种设计减少了保留任务效用所需的信息，从而实现了更好的安全-效用权衡，我们通过衡量效用和攻击成功率随提示长度变化的情况进行了实证验证。我们在SWE-bench Lite上对长周期软件工程任务以及在AgentDojo和DecodingTrust-Agent上对异构多工具交互任务进行了评估。在两个基准测试中，双代理在防止提示注入攻击的同时保持了高任务效用，性能优于未防御的代理和特权分离基线。

## Abstract
Large language model (LLM) agents are vulnerable to security risks, such as prompt injection attacks from untrusted context that manipulate downstream reasoning and tool use. Existing secure-by-design approaches mitigate this risk by separating untrusted observations from privileged execution and careful control of information flow, but often degrade utility and require extensive task-specific engineering. We thus propose Twin Agent, a general privilege separation design pattern inspired by residual coding in the agent context. Twin Agent consists of two nearly symmetric agents: an Explore Agent that inspects untrusted information and a Safe Agent that executes privileged actions. The Explore Agent is conditioned on the Safe Agent's current context and communicates only compact hints to the Safe Agent about the next action to take. This design reduces the information needed to preserve task utility and thus achieves a better security--utility tradeoff, which we empirically verify by measuring how utility and attack success change as the length of hints varies. We evaluate Twin Agent on long-horizon software engineering tasks with SWE-bench Lite and on heterogeneous multi-tool interaction tasks with AgentDojo and DecodingTrust-Agent. Across both benchmarks, Twin Agent preserves high task utility while preventing prompt injection attacks, outperforming both undefended agents and privilege separation baselines.

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

- **核心思想**：基于**残差编码**（Residual Coding）的灵感，将代理拆分为两个几乎对称的子代理：
  - **Explore Agent（探索代理）**：可以访问全部不可信信息（如问题描述、工具输出），但不能执行特权操作。其职责是向 Safe Agent 发送紧凑的**提示（Hint）**。
  - **Safe Agent（安全代理）**：可以执行特权操作（如 bash 命令、文件修改），但不能直接观察不可信信息。它只接收来自 Explore Agent 的受限提示，并结合自身的交互历史做出决策。
- **关键技术细节**：
  - **残差压缩**：Explore Agent 并非压缩整个不可信上下文，而是**仅提供 Safe Agent 下一步动作所需的剩余信息**。因为 Explore Agent 已知 Safe Agent 的当前轨迹，所以只需传递**未被共享的部分**。
  - **可调安全-效用权衡**：通过设定 **提示长度上限**（如 100、200 字符）来控制可攻击面的容量。长度越短，安全性越高，但可能降低效用；长度增加，则攻击风险上升。
  - **安全加固**：在 Safe Agent 提示中加入提醒文本，并额外增加一个**提示注入检测器**，对提示进行过滤，阻止可疑内容。

## 6. 论文的主要结论与发现

1. **Twin Agent 在保持高任务成功率的前提下，将攻击成功率降至接近 0%**（例如 SWE-bench-injected 上 ASR=0.0%，AgentDojo 上 ASR=0.1%），优于基线方法。
2. 通过控制**提示长度预算**，可以灵活调节安全与效用的权衡；预算过小会牺牲效用，预算过大会提升攻击风险。
3. 即使面对**自适应攻击**（两阶段攻击，包括 PAIR 优化的载荷），Twin Agent 的 ASR 仅为 4.7%，且这部分失败主要是由于语言模型随机性导致的偶发成功。
4. 提示能帮助 Safe Agent **更好地保留原始未防御代理的推理轨迹**，从而提升效用（甚至在个别场景中超过未防御代理）。
5. Twin Agent 是一种**通用、即插即用**的防御模式，无需大量任务特定的工作流改造，适用于不同代理系统。

## 7. 优点（方法或实验设计亮点）

- **方法创新**：将安全代理设计重新理解为**压缩信息流**问题，提出了残差编码的通信方式，理论新颖且实用。
- **实用性强**：Twin Agent 可以与现有的 ReAct 模式无缝集成，仅需插入一层轻量级的残差通信层，工程成本低。
- **可控性**：通过调整提示预算，可以动态控制安全-效用权衡，便于部署时根据风险评估选择合适配置。
- **实验充分**：在多个异构基准上验证了泛化能力，并设计了自适应攻击和消融实验，结论可靠。
- **成本适中**：虽然 Twin Agent 需要两次 LLM 调用（Explore + Safe），但单次成本仅约为基线的两倍，对于安全需求的场景是可接受的。

## 8. 不足与局限（包括实验覆盖、偏差风险、应用限制）

- **应用局限**：仅在软件工程和多工具交互两个领域验证，未测试更多领域（如医疗、金融决策等）。不同领域的攻击面和信息需求可能不同，泛化性有待进一步验证。
- **安全保证**：虽然实验显示强鲁棒性，但论文明确声明**没有提供形式化保证**。理论上更强的自适应攻击可能绕过检测（例如更长的注入或更巧妙的混淆），安全依赖于现有模型的脆弱性和检测器的有效性。
- **成本偏差**：Twin Agent 的 API 调用成本是基线的两倍，对于要求极低延迟或大量调用的场景可能构成瓶颈。
- **自适应攻击的局限性**：自适应攻击中只有单轮攻击，实际攻击者可能进行多轮交互，长期攻击效果未知。
- **随机性依赖**：部分失败案例源于 LLM 的随机性（如 Safe Agent 偶尔会执行恶意动作），表明在高安全要求下可能需要额外的归约机制（如多数投票）。
