## 摘要
设计规则检查（DRC）闭合仍然是先进节点物理设计中的一个主要瓶颈。尽管详细布线器具有规则感知能力，但残留的设计规则违例（DRV）通常需要人工工程变更订单迭代。自动化此过程具有挑战性，因为修复必须考虑复杂的几何相互作用、保持电路连通性并避免引入新的违例。我们提出了EvoDRC，一种用于智能体级模块级DRC修复的技能演化框架。EvoDRC利用从无关参考设计中提取的知识初始化特定层的修复技能，并通过从目标设计中收集的可追溯修复经验不断演化这些技能。EvoDRC将布局分解为有界的修复区域，并为每个区域分配一个LLM修复智能体。局部DRC分析、连通性检查和影响预览工具对提议的修改提供反馈。修复操作及其导致的DRV变化存储在知识数据库中，并用于演化修复技能。在DAC26 DRC基准测试的七个模块级设计上的实验表明，与报告的基线相比，EvoDRC实现了73.5%的整体减少。

## Abstract
Design rule check (DRC) closure remains a major bottleneck in advanced-node physical design. Although detailed routers are rule-aware, residual design rule violations (DRVs) often require manual engineering change order iterations. Automating this process is challenging because repairs must account for complex geometric interactions, preserve circuit connectivity, and avoid introducing new violations. We present EvoDRC, a skill-evolution framework for agentic block-level DRC repair. EvoDRC initializes layer-specific repair skills using knowledge distilled from an unrelated reference design and continuously evolves these skills using traceable repair experience collected from the target design. EvoDRC decomposes the layout into bounded repair regions and assigns an LLM repair agent to each region. Local DRC analysis, connectivity-checking, and impact-preview tools provide feedback on proposed modifications. Repair operations and their resulting DRV changes are stored in a knowledge database and used to evolve the repair skills. Experiments on seven block-level designs from the DAC26 DRC Benchmark show that EvoDRC achieves a 73.5\% overall reduction compared to the reported baseline.

- **挑战**：DRC修复必须考虑复杂的几何相互作用（如金属宽度、间距、包围、对齐等），同时保持电路连通性，并避免引入新违例。修复操作可能产生连锁反应。
- **现有局限**：已有的LLM智能体工作主要集中于放置、布线、时序优化，或仅处理标准单元级小规模DRC修复，难以扩展到块级复杂设计。依赖手写技能文件，缺乏自动演化能力。
- **核心问题**：如何让LLM智能体自动进行块级DRC修复，并能从过往修复经验中持续学习和演化，减少人工干预。

## 2. 方法论：核心思想与关键技术细节

### 总体框架
EvoDRC是一个**自演化智能体框架**，包含三个主要阶段：
1. **布局分解**（Stage 1）：将大规模布局划分为有界修复区域（repair crops）。
2. **智能体修复**（Stage 2）：为每个修复区域分配LLM修复智能体，使用预览工具辅助修复。
3. **评估与记录**（Stage 3）及**技能演化**：将修复操作-结果对存入知识库（Knowledge DB），通过两个演化路径（Skill Refiner和DB Summarizer）生成新技能文件，经机械检查和Skill Judge选择后更新。

### 关键技术细节
- **布局分解**：根据DRV分布和布线类型，先形成一阶crop（大小限制为k×k μm²），合并重叠的crop为二阶crop，再按标准单元行合并得到最终修复crop。每个crop独立分派智能体，提升可扩展性。
- **对象可编辑性分类**：将金属和通孔分为四类（A：通孔结构可整体移动/删除/添加；B：完全在crop内的多边形可任意操作；C：被crop截断的多边形只能伸缩开口端；D：标准单元内部和属于其他布线类型的对象不可修改），防止跨crop的意外影响。
- **预览工具**：提供三个工具供智能体在ReAct循环中使用：
  - **局部DRC分析**：在沙箱中快速运行DRC，返回违例变化。
  - **连通性检查**：验证操作是否会破坏电路逻辑（禁止断网）。
  - **影响预览**：返回与编辑对象接触或重叠的邻近对象信息。
- **知识库**：按金属层组织，存储设计规则、技能文件、历史修复记录（操作-局部DRV变化对）、crop几何。仅保留每个智能体的最终提议操作，丢弃中间探索记录，确保可追溯性。
- **技能演化**：
  - **Skill Refiner**：读取当前层的设计规则、技能文件及本轮收集的记录，增量式精炼技能。
  - **DB Summarizer**：读取该层全部历史记录，从零重构技能文件。
  - **机械检查**：通过脚本检查引用来源、断言性语句的引用、无模糊用语。
  - **Skill Judge**：根据引用完整性、覆盖率、写作质量三个指标投票选择优胜技能文件；若均无法通过则保留现有技能。
