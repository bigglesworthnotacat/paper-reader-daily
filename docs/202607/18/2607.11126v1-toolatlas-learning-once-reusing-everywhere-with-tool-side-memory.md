## 摘要
大型语言模型（LLM）代理越来越依赖由共享提供者提供并被异构下游代理访问的外部工具。现有方法通过参数更新、提示优化或代理侧记忆来改进代理端的工具使用，这使得工具知识难以共享，并且仅限于过去任务中观察到的行为。我们认为可复用的工具知识应由工具提供者维护。我们引入ToolAtlas，一种基于图的框架，通过执行验证的探测构建持久的提供者侧工具记忆，包括工具能力、失败边界和跨工具组合。在推理时，代理通过自适应图遍历查询工具记忆。在跨越八个服务的两个基于MCP的基准测试中，ToolAtlas在pass@1和pass@4上分别比现有的工具侧优化和代理侧记忆基线高出最多21.61%和18.61%。相同的工具记忆还能在无需重新训练或任务时探索的情况下跨环境实例和代理框架迁移，分别在pass@1/pass@4上获得高达24.16%/16.22%和17.49%/14.27%的相对提升。消融研究表明，这些收益来自于将工具中心的记忆组织与能力引导的执行探测相结合。这些结果确立了提供者侧工具记忆作为工具服务器的一种有效且可复用的范式。我们的代码位于：https://github.com/PuppyKnightUniversity/ToolAtlas。

## Abstract
Large language model (LLM) agents increasingly rely on external tools served by shared providers and accessed by heterogeneous downstream agents. Existing approaches improve tool use on the agent side through parameter updates, prompt refinement, or agent-side memory, making tool knowledge difficult to share and limited to behaviors observed in past tasks. We argue that reusable tool knowledge should instead be maintained by the tool provider. We introduce ToolAtlas, a graph-based framework that builds a persistent provider-side tool memory of tool capabilities, failure boundaries, and cross-tool compositions through execution-verified probing. At inference time, agents query the tool memory via adaptive graph traversal. Across two MCP-based benchmarks spanning eight services, ToolAtlas outperforms existing tool-side optimization and agent-side memory baselines by up to 21.61% in pass@1 and 18.61% in pass@4. The same tool memory also transfers across environment instances and agent frameworks without retraining or task-time exploration, yielding up to 24.16%/16.22% and 17.49%/14.27% relative gains in pass@1/pass@4, respectively. Ablation studies show that these gains arise from combining tool-centered memory organization with capability-guided execution probing. These results establish provider-side tool memory as an effective and reusable paradigm for tool servers. Our code is in: https://github.com/PuppyKnightUniversity/ToolAtlas.

## 1. 核心问题与整体含义（研究动机和背景）

- **研究动机**：现有LLM代理在使用外部工具（如文件系统、GitHub、Notion等MCP服务）时，对工具知识的优化主要发生在**代理端**，即通过微调模型参数、优化提示、或积累代理侧记忆来提升工具调用效果。这导致两个结构性问题：
  - **泛化困境（Generalization Dilemma）**：代理侧记忆无法跨代理共享，每个代理必须独自重新学习相同的工具知识，即使底层工具行为未变化。
  - **能力盲区（Capability Blindness）**：代理侧记忆仅记录过去任务中调用过的工具行为，无法系统覆盖工具的完整能力、失败边界和与其他工具的协作方式，因此对工具的认知是稀疏且被动的。
- **核心论点**：可复用的工具知识应被放置在**工具提供者侧**，而非每个代理内部。通过一次构建、多次复用的方式，工具提供者可以系统性地探索并记录工具的能力边界、失败模式和协作策略，从而为所有下游代理提供即时的、经验证的知识。
- **整体意义**：提出了一种新的范式——“提供者侧工具记忆”，将工具知识从代理的绑定中解放出来，提升了工具使用的效率、迁移性和可维护性，可广泛应用于共享MCP服务器场景。

## 2. 方法论：核心思想、关键技术细节

**核心思想**：构建一个基于图的、持续演化的工具侧记忆框架，包含三层图结构，并通过主动的“能力探索”循环来扩展知识，在推理时通过动态图遍历提供任务指导。

- **Memory Bootstrapping（内存引导）**：为每个工具生成种子任务（k=3），结合Web检索的真实使用片段，执行N=4次并验证结果。将原始轨迹通过**Memory Induction**转化为三类图：
  - **Tool-Trace Graph（工具-轨迹图）**：节点为“轨迹节点”，包含任务描述、去代理化的工具-理由序列、任务级提示。边为语义相似度边。
  - **Tool-Capability Graph（工具-能力图）**：节点为工具，每个工具维护三个条目集：可用性（affordance）、边界（boundary）、共用法（co-usage）。跨工具边记录协作模式。
  - **Tool-Strategy Graph（工具-策略图）**：节点为策略节点，从多个相似任务中提炼的高层编排原则。
- **Capability Exploration（能力探索）**：循环进行，每轮从当前能力图中采样一个局部子图，由LLM提议者生成两个方向的探测任务：
  - **边界任务**：测试工具在极限条件下的行为（如大规模输入、循环依赖）。
  - **可用性任务**：暴露未被覆盖的有效用法和协作模式。
  - 每个任务执行并验证后，结果写回图中，持续扩张知识边界。
- **Dynamic Memory Traversal（动态内存遍历）**：推理时，给定新任务，从最近邻的轨迹节点开始，通过四种操作（ReadTrace, Expand, ReadTool, ReadStrategy）自适应地遍历图，直到上下文充分或预算耗尽。最终将收集的信息压缩为任务指导，注入到用户代理的记忆槽中。

- **关键技术细节**：
  - 去代理化：轨迹被转换为“工具-理由”对序列，移除特定代理的动作语法、重试模式、推理风格。
  - 执行验证：所有种子任务和探测任务都通过实际调用工具并利用验证器（verifier）来确认成功/失败，确保记忆的可靠性。
  - 图结构：允许跨层链接（轨迹↔工具、轨迹↔策略），便于多维度检索。

## 6. 论文的主要结论与发现

1. **有效性**：在相同环境分割下，ToolAtlas在MCPMark上以GPT-5.4为骨干时，超过最强基线8.15%（pass@1）和10.48%（pass@4）；在GPT-5.4-mini上提升10.06%和18.61%；在Grok-4上提升21.61%和16.11%。在MCP-Universe上也取得一致优势。
2. **泛化性**：
