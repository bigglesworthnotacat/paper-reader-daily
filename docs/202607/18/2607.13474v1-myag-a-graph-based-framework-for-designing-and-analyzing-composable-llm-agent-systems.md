## 摘要
我们提出了MyAG，一个基于图的可组合LLM智能体系统设计与分析框架。我们的框架将智能体系统构建分为三个图抽象：组件图（用于智能体、环境和模块）、工作流图（用于执行控制）以及搜索图（用于运行时执行）。这种分离允许用户灵活地重用相同组件于不同策略。我们进一步通过递归系统节点支持层次化组合，并提供监控和可视化工具用于检查智能体执行。在代表性智能体应用上的实验表明，我们的框架支持灵活的智能体系统设计，并有助于分析性能-效率权衡。我们的框架是公开可用且完全开源的。

## Abstract
We present MyAG, a graph-based framework for designing and analyzing composable LLM agent systems. Our framework separates agent system construction into three graph abstractions: a component graph for agents, environments, and modules; a workflow graph for execution control; and a search graph for runtime execution. This separation allows users to flexibly reuse the same components with different strategies. We further support hierarchical composition through recursive system nodes and provide monitoring and visualization tools for inspecting agent execution. Experiments on representative agent applications show that our framework supports flexible agent system design and helps analyze performance-efficiency tradeoffs. Our framework is publicly available and fully open-source.

## 2. 论文提出的方法论：核心思想、关键技术细节
- **核心思想**：使用三种图抽象来分离智能体系统的不同结构层面：
  1. **组件图（Component Graph）**：描述系统可用的组件（智能体节点、环境节点、系统节点等），以及它们之间的访问关系。类似于程序中的变量声明。
  2. **工作流图（Workflow Graph）**：指定组件如何按顺序执行，包括控制流（分支、循环）和停止条件。类似于程序逻辑。包含起点和终点节点，维护工作流级变量映射，节点通常关联组件图中的智能体节点。
  3. **搜索图（Search Graph）**：记录运行时执行过程，支持探索替代路径（如贪心搜索、束搜索、最佳优先搜索）。通过保存状态节点并允许从选定节点恢复执行来实现不同搜索策略。
- **关键技术细节**：
  - **层次化组合**：通过“系统节点”实现递归封装，一个子系统可包含自己的组件图、工作流图和搜索图，并作为组件被上层系统调用。提供**无状态模式**（每次调用重置，类似工具）和**有状态模式**（保留记忆和运行时状态，支持多智能体协作）。
  - **效率分析**：定义两种成本度量：
    - **LLM推理成本 \(C_L\)**：\(C_L = \sum_{t=0}^{T-1} (\alpha \cdot L_t^{in} + \beta \cdot L_t^{out})\)，其中 \(L_t^{in}, L_t^{out}\) 为输入/输出token数，\(\alpha,\beta\) 为可配置权重（如API价格或延迟）。
    - **环境交互成本 \(C_E\)**：\(C_E = \sum_{t=0}^{T-1} w(s_t, a_t)\)，其中 \(w\) 为用户定义或经验测量的动作成本（如延迟）。
  - 提供监控和可视化仪表盘，展示逐步执行过程、图可视化、变量状态、成本分布等。

- **数据集/场景**：

- **对比方法**：在框架内实现了四种工作流/搜索策略：
  1. **Greedy**：ReAct式单轨执行。
  2. **Best-first**：维护搜索树，每次扩展评分最高的节点。
  3. **Rollback**：允许智能体在下一步行动前决定是否回退到之前状态。
  4. **Best-of-N**：并行运行多个轨迹，用额外LLM评判选择最佳。

## 6. 论文的主要结论与发现
- **主要结论**：MyAG框架通过三层图抽象有效分离了组件、工作流和搜索，支持灵活重用和系统分析。在实验中：
  - Greedy策略最节省计算资源；Rollback策略在足够预算下取得最佳性能，但效率略低于Greedy；Best-first和Best-of-N能通过更多计算提升性能但带来较大开销。
  - 不同环境动作的延迟差异显著：如scroll动作便宜（占11%时间但29%调用），wait动作最昂贵。
  - 不同底层LLM对性能-效率权衡影响大：MoE模型（如35B-A3B）在相对成本模型下表现更好，但需考虑内存占用。
- **框架价值**：使得系统比较和效率分析变得直接方便。
