## 摘要
Agentic AI系统日益通过异构运行时环境运作：本地编码钩子、SDK工具、浏览器自动化、托管智能体轨迹、API网关和工作流引擎。因此，一个单一的操作行为（如发布代码、更改身份状态、转移资金或导出数据）可能由多个不兼容的运行时记录表示。这使得一个基本的治理问题难以回答：究竟批准了什么操作？什么证据将批准绑定到执行？独立验证者能否在之后重现相同的操作身份？本文提出规范动作验证与证明（CAVA），这是一个运行时语义层，用于将异构智能体活动转换为规范的运行时动作对象。CAVA位于携带证明的智能体动作（PCAA）之下：PCAA定义了部署者拥有的路线审查证明治理过程，而CAVA定义了该过程所治理的稳定动作对象。本文形式化了规范动作身份、语义模式检测、批准绑定、收据完整性、运行时可移植投影以及可选的证明基底。我们通过一个包含96个种子、384个变体的基准测试研究了参考实现，涵盖了语义等价性、语义分离、包装器绕过、假阳性控制、批准绑定、收据可重现性、证明篡改检测、运行时可移植性、语义模式检测、策略退化以及Azure部署演练。其贡献在于将动作级规范化和策略可寻址语义模式作为部署者侧AI治理的必要基础进行系统化阐述。

## Abstract
Agentic AI systems increasingly act through heterogeneous runtimes: local coding hooks, SDK tools, browser automation, managed-agent traces, API gateways, and workflow engines. A single operational act such as publishing code, changing identity state, moving money, or exporting data may therefore be represented by many incompatible runtime records. This makes a basic governance question difficult to answer: what action was actually approved, what evidence binds the approval to execution, and can an independent verifier reproduce the same action identity later?   This paper presents Canonical Action Verification and Attestation (CAVA), a runtime-semantics layer for converting heterogeneous agent activity into canonical runtime action objects. CAVA is positioned below Proof-Carrying Agent Actions (PCAA): PCAA defines the deployer-owned route-review-prove governance process, while CAVA defines the stable action object that process governs. The paper formalizes canonical action identity, semantic pattern detection, approval binding, receipt integrity, runtime-portable projection, and optional attestation substrates. We study a reference implementation through a 96-seed, 384-variant benchmark covering semantic equivalence, semantic separation, wrapper bypass, false-positive control, approval binding, receipt reproducibility, attestation tamper detection, runtime portability, semantic pattern detection, policy degradation, and Azure deployment drills. The contribution is a systems formulation of action-level canonicalization and policy-addressable semantic patterns as a necessary substrate for deployer-side AI governance.

# 论文详细总结

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：Agentic AI 系统通过多种异构运行时执行动作（如 shell 命令、SDK 调用、浏览器自动化、托管智能体轨迹等）。同一业务操作在不同运行时下会产生完全不同的记录格式，导致治理问题：无法确定“到底批准了什么动作”、批准与执行之间的证据无法绑定、独立验证者无法跨运行时重现同一动作的身份。
- **整体含义**：当前缺乏一个稳定的、可跨运行时持久的动作语义对象，使得基于原始文本或运行时专有痕迹的治理（如策略匹配、批准、审计）存在根本缺陷——等价重写可绕过批准，包装器可隐藏高风险操作，不同运行时的记录不可比较。CAVA 旨在填补这一空白，为部署者侧 AI 治理提供必要的规范化基层。

## 2. 方法论

- **核心思想**：将异构的原始运行时事件转换为规范运行时动作对象（Canonical Runtime Action），并用确定性哈希指纹作为治理决策的对象，而非原始字符串。CAVA 是 PCAA（携带证明的智能体动作）的下层基础，PCAA 负责治理循环（路由-审查-证明），CAVA 负责提供稳定的动作身份。
- **关键技术细节**：
  - **规范动作对象**：包含 schema 版本、运行时家族、可执行文件/工具身份、规范化操作、风险类别、触及的系统集合、可逆性、目标/主体上下文、适配器元数据等字段。
  - **规范指纹**：对选定规范字段进行确定性序列化后取哈希（如 SHA-256）。策略、批准收据、审计证据都绑定到该指纹。
  - **CAVA 协议（七阶段）**：捕获原始事件 → 标准化为规范动作 → 解释语义模式 → 计算指纹 → 绑定策略/批准 → 关闭（附加结果、证据） → 可选证明（签名、凭证、账本锚定）。
  - **语义模式层**：在规范化之后、策略路由之前，将规范动作与边界上下文、数据上下文映射为策略可寻址的模式（如公共持久性出站、安全控制削弱、凭证暴露、工作流下沉风险等），而非客户特定规则。每个模式是版本化的证据对象，包含标识、标签、严重性、置信度等。
  - **可选证明基底**：支持本地收据哈希、签名、可验证凭证、供应链证明、账本锚定等，但区块链为可选而非必需。
## 3. 实验设计

- **数据集/场景**：使用一个公开的基准测试套件，包含 **96 个代表性种子场景**，每个种子扩展为 **384 个运行时变体**，覆盖四个运行时家族：Shell 钩子、MCP 风格工具、浏览器自动化、托管智能体轨迹。此外还包括 Azure CLI 动作演练、红队案例等。
- **Benchmark 测试的属性**：语义等价性、语义分离性、包装器绕过捕获率、假阳性控制、批准绑定正确性、收据可重现性、证明篡改检测、运行时可移植性、语义模式检测、策略退化覆盖、云动作投影覆盖。
- **对比方法**：简单但常用的基线：
  - **原始文本策略**：绑定到运行时的原始字符串。
  - **首令牌规则**：根据第一个可执行文件和相邻令牌分类。
  - **CAVA 运行时**：使用规范化的包装器、别名、类别和收据材料进行决策绑定。

## 5. 实验数量与充分性

- **实验数量与结构**：主基准包含 96 个种子 × 384 变体；此外有消融研究（7 组消融，评估各组件对保留能力的贡献）、红队案例（24 个攻击模式）、Azure 部署演练（6 个语义案例）、策略退化案例（8 个结构化案例）等。每种属性均有单独的计分检查。
- **充分性评价**：作者明确承认当前基准是**代表性公开语料**，而非企业动作的完整分布。基准设计是**结构化**的，允许添加新的运行时适配器和客户批准轨迹而不改变度量词汇。同时包含了红队案例、消融研究，并公开了可重复的哈希和收据机制，增加了可信度。但局限性在于生产解析器包、企业策略阈值和客户连接器规则被保留在托管层中，限制了完全第三方复现；基准规模仍远小于企业现实环境，存在**过拟合风险**（但作者有计划扩展第三方轨迹）。

## 6. 主要结论与发现

- 在代表性语料上，**原始文本和首令牌基线在所有关键指标上均失败**（语义等价召回率、包装器绕过捕获率、批准绑定正确性等均为 0.0 或 0.333）；而 **CAVA 在所有指标上达到 1.0**（在公开基准分数上）。
- CAVA 的优势来自于将决策绑定到规范动作语义而非显示文本或首令牌启发式。
- 最关键的结果不是分数本身，而是基准系统性地暴露了市场面对组件必须克服的失败模式（包装器、等价重写、假阳性、收据篡改等）。
- CAVA 与 PCAA 的组合提供了完整的治理闭环：CAVA 提供稳定动作对象，PCAA 提供权威和证明。

## 7. 优点

- **问题定义清晰**：精准识别了异构运行时环境下动作身份不稳定的关键治理瓶颈，而非泛泛地讨论“智能体安全”。
- **系统级解决方案**：不仅提出概念，还给出了完整的协议、规范动作对象模式、语义模式层、可选证明基底，并与现有标准（PCAA、OWASP、NIST）对齐。
- **结构化且可重复的基准**：96 种子 384 变体的基准涵盖多种攻击模式和属性，且公开了确定性哈希和收据验证，支持第三方复现。
- **红队案例与消融研究**：超出了普通基准，包含攻击者视角的 24 个案例和 7 个消融，验证了每个组件的必要性（特别是规范指纹和收据验证器）。
- **开放核心边界**：公开了架构、哈希、收据和适配器接口，同时保留商业层，既避免了锁定又提供了商业可持续性。
- **诚实披露局限性**：论文多处以系统卡形式列出了已知差距、残留风险、滥用分析，增强了学术可信度。

## 8. 不足与局限

- **语料覆盖不足**：基准仍然是一个代表性公开语料，不是企业实际动作的完整分布。生产环境中的私有脚本、方言化工具、多动作复合命令等未充分覆盖。
- **解析器依赖性**：规范化强度完全取决于适配器覆盖范围。私有企业系统可能需要自定义解析器包，解析失败可能导致遗漏升级或不必要的审查。
- **披露边界**：生产解析器包和客户连接器规则被保留在托管层，无法由第三方完全复现托管行为，限制了实验的完全公平性。
- **证明范围有限**：收据哈希和签名仅证明完整性和绑定，不能证明业务决策的智慧。一个正确证明的动作仍然可能是糟糕的商业决策。
- **运行时深度差异**：某些运行时支持内联阻断，某些仅提供观察模式。CAVA 必须披露这种差异，而非声称统一的强制力——在实验中通过“强制执行深度”字段处理，但未在所有场景中严格验证。
- **基准偏置风险**：公开的语料可能被作者有意或无意地优化，虽然计划引入第三方轨迹和对抗性提交，但当前仍存在过拟合风险。
- **无 GPU 规模报告**：实验算力细节缺失，无法评估系统效率或可扩展性。
