## 摘要
人工智能代理正在从答案引擎演变为持久的团队，它们使用工具、委派工作、从经验中学习，并修改塑造其未来行为的人工制品。部署的关键问题不再仅仅是代理能做什么，而是谁控制它们被允许成为什么。我们引入了logos，一个用于自我进化与治理的可插拔层，它增强了现有的多代理框架而非取代它们。logos将异构的多模态输入（包括文档、图像、音频、表格、数据库、API以及人类指令）编译成版本化的代理包，其中包含代理、工具、知识、测试、权限和策略。在运行过程中，它将代理活动转化为可移植、可审计的事件轨迹，并在框架和后端之间应用故障关闭验证。每一个学到的提示、记忆、技能、工具、角色或工作流程都仍然是不可信的候选版本，直到保留的执行证据、人类控制的策略以及明确的授权允许其晋升。这种架构实现了“可验证的人-代理循环工程”：代理可以行动、询问、学习和提出改进，而人类可以引导目标、权限、批准和不可逆操作，而不中断持续运行。logos为可问责的自动化提供了一个生活逻辑。代理可以以机器速度进化，但只有证据和人类权威才能闭合循环。

## Abstract
AI agents are evolving from answer engines into persistent teams that use tools, delegate work, learn from experience, and modify the artifacts that shape their future behavior. The defining question for deployment is no longer merely what agents can do, but who controls what they are allowed to become. We introduce logos, a pluggable layer for self-evolution and governance that strengthens existing multiagent frameworks rather than replacing them. logos compiles heterogeneous multimodal inputs, including documents, images, audio, tables, databases, APIs, and human instructions into versioned agent packs containing agents, tools, knowledge, tests, permissions, and policies. During operation, it transforms agent activity into portable, auditable event traces and applies fail-closed verification across frameworks and backends. Every learned prompt, memory, skill, tool, role, or workflow remains an untrusted release candidate until held-out execution evidence, human-controlled policy, and explicit authorization permit its promotion. This architecture enables "verifiable human-agent loop engineering": agents can act, ask, learn, and propose improvements, while humans can steer objectives, permissions, approvals, and irreversible actions without interrupting continuous operation. logos provides a living logic for accountable automation. Agents may evolve at machine speed, but only evidence and human authority can close the loop.

## 2. 方法论：核心思想、关键技术细节

### 2.1 总体框架：Compile → Operate → Evolve 生命周期

- **Compile（编译）**：将多模态输入（文档、图像、音频、数据库、API、人类指令等）编译为版本化 **Agent Pack**。Pack 包含初始团队 Π₀、基因组 G（路由/记忆/验证/推广/安全/沙箱/工具/注意力预算）、验证器声明 V、有限验证探针 C、清单元数据 M。
- **Operate（运行）**：通过适配器在兼容后端上执行 Pack，将后端事件标准化为通用轨迹 Z（含任务、计划、动作、观察、路由决策、验证器裁决、人类交互、成本、风险等）；验证器组合硬约束与可接受验证器，输出 `pass/fail/not-applicable/error`。
- **Evolve（进化）**：从轨迹中提取候选变化（提示、记忆、技能、工具、角色、工作流），每个候选与当前基线在保留集上配对执行，通过 **配对晋升门控** 决定是否替换。门控要求平均增益 ≥ δ_min 且观察到的回归数 ≤ R_max（默认零回归）。可选 anytime-valid 门控使用 e-process 添加流式错误控制。

### 2.2 编译器细节

- 采用 **fail-closed** 接口：返回 `ProbeValidatedPack`（通过有限探针）或 `DiagnosticPack`（无执行权限）。
- 输入经适配器生成工具规范（带 JSON Schema、效果分类、认证、幂等性等）、技能规范、知识/数据制品、来源记录。
- LLM 首先生成蓝图，有三个退化模式（结构化团队 → 单剧本代理 → 确定性模板），保证可编译性。
- 校验-修复循环：对声明的探针 C 运行工具可调用性检查，失败时自动修复规范，最多 N 轮。可以附加 anytime-valid 过程对真实可调用率给出统计保证。

### 2.3 路由与验证引擎

- **静态成本路由**：预声明复杂度分类映射到模型层。
- **学习路由**：使用 REINFORCE 更新每个上下文下的动作概率，基线为滞后平均效用。
- **验证门控级联**：按廉价→强大顺序尝试，只有当验证器拒绝时才升级；学习每个维度下各阶段的通过概率，自适应入口选择。在完美验证器下，级联准确率不低于总是使用最强模型。
- **集体路由**：维护一个包含多个工作者的集束，通过离线蒸馏、进化优化和在线 bandit 更新学习选择策略；当路由边际不确定性高时自动转入深度工作流。
- **验证器栈**：硬约束（模式、语法、安全）全部必需；可接受验证器（单元测试、执行、回归、学习、法官）要求至少一个通过；法官验证通过结构化证据图增强（节点为类型化声明，边为支持/矛盾），使可审计性更强。

### 2.4 自进化机制

- **门控记忆**：三层存储（原始 → 验证 → 持久技能）；召回采用价值感知排序（相似性与学习 Q 值混合）；进入验证层要求稳定通过率；持久技能需多次成功使用。
- **技能优化**：通过文本反馈循环（Rollout → Reflect → Apply → Gate）优化，类比 TextGrad/OPRO；配对门控决定是否晋升。
- **工作流进化**：基于 AFlow 的种群搜索和 MaAS 的超网方法，带成本感知策略梯度。
- **配对执行门控**：每个候选与基线在分离的保留集上配对执行，计算差异，要求平均增益 ≥ δ_min 且回归数 ≤ R_max（安全回归默认为零容忍）。可选项为 anytime-valid 门控（使用 e-process 的 portfolio 构造）。
- **外循环停止规则**：基于自适停止时间（充分证据、无效、预算耗尽、人类停止）。

### 2.5 人类-代理循环

- 代理可询问人类（预运行澄清、运行时提问），通过预算的 **Ask-F1** 指标衡量质量。
- 人类可发布非正式指令，经 **指令合成** 与记忆融合成为门控候选。
- **根策略** 不可由代理修改，固定目标、评估器、持有集、凭证边界、批准规则、外部效果策略、审计目标。
- 风险层根据影响分类，高风险变更需额外验证/人类批准。

- **偏倚控制**：负控制策略确保契约失败会被发现；门控保留集与提议/选择集分离。

## 4. 资源与算力

论文**未明确说明**使用的 GPU 型号、数量或训练时长。所有实验基于托管模型 API（如 gpt-4o-mini, gpt-4.1, gpt-5.1）和本地 CPU/内存运行（编译器、门控、故障注入）。因此，算力细节无法从论文中获取。

## 5. 实验数量与充分性

- **编译器**：48,000 个生成业务包，覆盖 6 个领域。
- **门控共性回放**：2,500 + 5,000 确定性决策（5 个候选家族，多种子）。
- **门控消融**：多种子（3），非饱和套件（HotpotQA, MATH-500）。
- **记忆**：合成语料库、LongMemEval（500）、LoCoMo（1540）。
- **路由**：120 seeds × 900/900 训练/保留；20 seeds × 2000 任务（验证器压力）。
- **安全委托**：400,000 模拟任务。
- **验证器压力**：200,000 生成决策。
- **合规性测试**：Q9–Q22 每个数千至 8,192 个生成案例。
- **外部基准**：完整官方评估（如 BFCL 1281、MMLU-Pro 12032）。

总体而言，实验数量充足、覆盖广泛，且注意了分离证据类、控制偏倚。但由于大量数据为生成（非真实用户交互），外部泛化能力仍待验证。

## 6. 主要结论与发现

1. **门控自进化**：配对门控在共同候选回放中将有害采纳率从 60% 降至 0%，而代理信号门控仍采纳 40% 有害。anytime-valid 门控更保守但完全消除有害。在多种子非饱和套件中，配对门控显著减少回归。
2. **编译器**：LOGOS 编译 C3/C4/C5 率分别为 0.882/0.720/0.757，优于 one-shot LLM 和框架模板，接近手写代理（0.923/0.808/0.829），且超额权限远低于基线。
3. **验证门控级联**：在 HumanEval 和 MBPP 上显著超越廉价模型（p < 0.001），与单一强大模型相比略高但未显著。级联节省成本，且在硬维度上入口自适应进一步降低成本 20%。
4. **集体路由**：成本感知策略在保持准确率相近的同时降低 47% 成本（0.913 vs 0.937，但成本从 2.5 降至 0.44）。
5. **门控记忆**：在训练信号存在时提升 LongMemEval 4.0 百分点，在无信号时不退化；无门控记忆会导致有害回归。
6. **操作控制**：在 14 个合规性测试中，Logos 未观察到违反编码规则（如不安全导入、错误晋升、数据泄露、恶意记忆使用等），而负控制策略均出现显著失败。
7. **人类交互**：安全委托实验显示 Logos 在阻止未授权外部影响的同时将人类干预从 100% 降至 39%，准确率 0.940 接近全手动 0.961。

## 7. 优点

- **统一治理契约**：将构建、路由、验证、适应、人类监督整合为可审计的发布流程，避免局部优化忽视全局风险。
- **“提议≠晋升”原则**：从根本上防止代理自我授权，分离证据与权威。
- **可插拔设计**：不强制替换现有多代理框架（如 AutoGen、OpenAI Agents），而是通过适配器增强。
- **配对门控**：直接基于保留执行证据，避免代理自我评估偏差；支持零任务回归策略，适用于高风险场景。
- **可选 anytime-valid 门控**：流式错误控制，允许早期停止而不过度浪费预算。
- **多模态编译器**：从异构操作输入直接生成可探针验证的 Pack，含 fail-closed 退化路径。
- **证据类分离**：实验设计科学，分别验证不同性质的主张。
-

- **验证门控级联**：通过廉价→强大的自适应验证器级联，在保持准确率的同时大幅降低成本，且入口自适应进一步优化。
- **遗忘与记忆门控**：防止有害记忆的持久化，同时保持有益记忆的渐进晋升。
- **人类-代理循环的细粒度预算**：允许人类控制代理的询问频率和授权级别，平衡效率与安全。
- **全面的合规性与安全测试**：通过负控制策略和故障注入，系统性地验证了契约规则的失效检测能力。

## 8. 不足/局限

1. **外部泛化性存疑**：大量实验基于生成数据（模板化业务简报、合成记忆语料等），与真实世界用户交互的噪声和复杂性存在差距。外部基准（如 SWE-bench）仅用于参考而未直接评估 LOGOS 整体性能。
2. **算力与部署成本未量化**：虽然通过路由和级联降低了 API 调用成本，但 LOGOS 本身（编译器、门控、验证器栈）的计算开销未报告，特别是多模态输入处理和配对执行重复计算可能显著增加延迟。
3. **配对门控的保留集依赖**：配对执行需要独立的保留集，在数据稀缺场景下可能不适用；且保留集与训练集分离要求可能增加系统复杂度。
4. **人类监督的抽象假设**：论文假设人类有能力且愿意在必要时审批变更，但实际中人类可能因疲劳、偏见或缺乏领域知识而误判。Ask-F1 指标仅衡量询问质量，未评估人类最终决策的准确性。
5. **路由验证的静态假设**：成本分类和验证器优先级基于预定义规则，未完全适应运行时动态变化（如模型价格波动、新工具可用性）。
6. **自进化有限性**：根策略不可变更，但长期部署中根策略本身可能需要适应组织目标变化；论文未讨论根策略的治理机制。
7. **安全委托实验的局限性**：模拟任务基于规则，未涵盖恶意代理欺骗人类授权的高级对抗性场景。

## 9. 待解决问题/未来方向

- **扩展至真实用户部署**：在持续运行的业务系统中评估 LOGOS 的实用性和鲁棒性，收集人类反馈以改进治理规则。
- **多代理治理的横向扩展**：当前架构聚焦于单个组织内的代理团队，未来可研究跨组织代理协作时的信任与治理（如联邦式治理契约）。
- **动态根策略更新**：设计可安全更新根策略的流程（如通过委员会投票或领域特定监管）。
- **更高效的门控计算**：减少配对执行的计算开销，例如使用代理模型或重要性采样近似。
- **增强人类决策支持**：为人类审批提供可解释的证据摘要和置信度估计，降低认知负荷。
- **自动化证据生成**：编译器当前需要手动输入验证器声明和探针，未来可探索从文档自动提取验证需求。
- **离线强化学习优化**：利用积累的轨迹数据，优化路由策略和验证器选择，减少对在线 bandit 的依赖。

## 10. 综合评价

LOGOS 提出了一套系统化的代理治理框架，通过编译-运行-进化的生命周期和“提议≠晋升”原则，有效解决了多代理系统中自我进化的风险控制问题。其关键贡献在于将分散的验证、路由、记忆、人类监督等机制统一到可审计的发布契约下，并为每个变更环节提供了可组合的门控策略。实验设计科学，证据类分离清晰，尤其配对门控和验证级联表现出显著优势。尽管存在泛化性不足和计算成本未量化等局限，但该框架为构建可信赖的持续性 AI 代理系统奠定了坚实基础，对工业落地和学术研究均有重要参考价值。
