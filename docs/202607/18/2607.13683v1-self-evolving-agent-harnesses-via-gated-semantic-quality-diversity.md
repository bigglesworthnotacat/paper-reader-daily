## 摘要
LLM智能体的实际任务性能既受其模型周围框架（包括提示、注入知识、运行时控制和配置）的影响，也受冻结模型本身的影响。在部署中，框架通常是唯一可用的杠杆，因此自动改进它是提升性能的自然方式，而无需修改权重。难点不在于生成变更，而在于确定哪些变更真正有用。自我生成的反馈存在噪声，表面上的提升可能是测量伪影或仅仅过拟合于调优任务的编辑。我们提出了一种自演化智能体框架，将提议变更与归因变更分离：语言模型诊断故障并提议补丁，而所有采样、测量和显著性检验均由确定性代码负责，因此每次归因的改进在结构上都是可信的。补丁填充了一个门控的分类质量多样性档案（GSME），其键值基于补丁解决的（何处×为何）病理，而非其修复的任务，这是一种抗过拟合的归纳偏置；泛化能力仅在演化后通过密封测试进行评分。在七个领域中使用冻结的开源模型，框架通过训练选择并在密封测试中评分一次；其归因增益为+9至+15.5个百分点，并保留了训练增益的86-147%，这表明泛化而非过拟合。获胜补丁追踪模型的主导病理，而非模型大小或家族：改变模型可能会改变病理和补丁，而相同的病理-补丁匹配在两个模型家族中重复出现。真正可迁移的是诊断-归因循环，而非任何特定框架。

## Abstract
An LLM agent's real-task performance is shaped as much by the harness around its model as by the frozen model itself: its prompts, injected knowledge, runtime control, and configuration. In deployment the harness is often the only lever available, so improving it automatically is the natural way to raise performance without touching the weights. The hard part is not generating changes but knowing which one truly helped. Self-generated feedback is noisy, and an apparent gain can be a measurement artifact or an edit that merely overfits the tasks it was tuned on. We present a self-evolving agent-harness framework that separates proposing changes from crediting them: a language model diagnoses failures and proposes patches, while all sampling, measurement, and significance testing are owned by deterministic code, so every credited improvement is trustworthy by construction. Patches populate a gated, categorical quality-diversity archive (GSME) keyed on the (WHERE x WHY) pathology an edit addresses rather than the tasks it fixes, an anti-overfitting inductive bias; generalization is measured on a sealed test scored only after evolution. Across seven domains with a frozen open-weight model, the harness is train-selected and scored once on a sealed test; its credited gains there are +9 to +15.5pp and retain 86-147% of the training gain, evidence they generalize rather than overfit. The winning patch tracks the model's dominant pathology, not its size or family: changing the model can change the pathology and the patch, while the same pathology-to-patch match recurs across two model families. What transfers is the diagnose-and-credit loop, not any specific harness.

#### 1. 论文的核心问题与整体含义（研究动机和背景）

-  LLM智能体在实际任务中的性能不仅取决于其模型本身，还同样取决于围绕模型的「harness」（框架）：包括系统提示、注入知识、运行时控制与恢复逻辑、工具定义和配置等。在部署中，模型权重通常是固定的（租赁、闭源或再训练成本过高），因此harness是唯一可调节的杠杆。

-  本文旨在回答：在什么条件下，智能体自我生成的反馈是足够可靠的，其搜索结构足够合理，使得 harness 改进能够**累积且泛化**，而不是漂移或过拟合。

#### 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想：将修改提议与可信归因分离（Propose-vs-Credit Separation）**。一个更强的演化器（Evolver，例如 Claude Opus 4.8）负责诊断冷冻任务智能体的故障、设计补丁；但所有采样、测量和显著性检验均由**确定性代码**执行，LLM 从不进行数值判断。
- **关键技术细节：**
  - **GSME（Gated Semantic MAP-Elites）**：一个分类的质量多样性归档库，其索引不是具体的任务，而是补丁所针对的**病理**（pathology）坐标：`(where × why)`。where 表示修改的杠杆（prompt, knowledge, runtime, config），why 是诊断出的失败类型（如“思考飞轮导致空输出”、“过早终结未验证”）。每个病理单元只能保留一个精英补丁（通过门控后），并支持跨单元重组（交叉细胞重组）。这种基于病理的键值是一种抗过拟合的归纳偏置。
  - **三扇门（Three Gates）**：补丁需依次通过三关才能被归因：
    1. **有效性门（Validity Gate）**：环境健康检查（沙箱、网络、依赖）和基础设施故障处理（重跑最多2次，失败的任务计为0但保留在分母中）。
    2. **激活门（Activation Gate）**：补丁必须确实被触发（通过激活信标记录），未触发时其效果不被归因。
    3. **显著性门（Significance Gate）**：使用配对2σ显著性检验（z ≥ 1.96），比较相同任务集上进化前后通过率的配对差异，消除任务间难度方差。仅用于最终归因报告；导航阶段使用K=3均值。
  - **密封测试（Sealed Test）**：进化过程中从不接触测试集，最终的最佳 harness 仅被评分**一次**在密封测试上，避免多重比较膨胀。
  - **评估漏斗**：候选补丁经过三层递增成本的评估：锚定子集（anchor tasks）初筛（K=1）、完整训练集确认（K=3）、三扇门判定。
  - **Git 树结构**：每个候选补丁为一个 git 分支+提交，包含完整的决策账目，可审计、可去重。

- **主要结论**：

  2. **跨模型匹配律（Pathology-to-Patch Matching Law）**：获胜补丁追踪模型的**主导病理**（例如 27B 的“空输出/放弃”→verify-finalize；397B 和 Gemini 的“粗心错误”→submit-verify checklist），而非模型大小或家族。当模型改变时，病理和补丁都改变；但当病理相同时（如粗心→checklist），该匹配在两个模型家族（Qwen 和 Google）中重复出现。
  3. **真正可迁移的是诊断-归因循环，而非任何特定 harness**：一个模型上有效的 harness 对另一个模型不一定有效（除非病理匹配），但循环本身可以应用于任何新模型。

  5. **三扇门可检测并拒绝有害或无活性的候选**（如 TB2 上拒绝了一个显著负向的候选，以及一个从未触发的补丁）。

#### 7. 优点：方法或实验设计上的亮点

- **分离提议与归因**：从根本上解决了自生成反馈不可靠的问题；LLM 负责创造性部分，确定性代码负责所有数值评判，保证了可信度和可重复性。
- **GSME 归档的病理键值设计**：是一种巧妙的抗过拟合归纳偏置——搜索由失败类型组织，而非训练任务列表，迫使补丁针对通用病理而非特定任务。
- **三扇门流水线**：既克服了测量噪声（有效性门、显著性门），又避免了虚假的归因（激活门），确保每次归因的提升都是真正的、可解释的改进。
- **密封测试+单次评分+配对显著性**：彻底杜绝了多重比较膨胀，且配对检验比独立检验更敏感，能在较小样本下检测出真实增益。
- **跨模型实验**：不仅验证了方法的通用性，还揭示了深层规律（匹配律），为理解“什么在迁移”提供了理论见解。
- **可审计的 Git 树结构**：每个编辑、每次决策都有完整记录，便于复现和审查。
- **树感知评分借用（Theorem 1）**：在保证不翻转决策的前提下显著降低评估成本，有理论和实证支持。

#### 8. 不足与局限

- **依赖性**：
  - **严重依赖可靠验证器**：所有归因保证仅相对于验证器的测量信号；如果验证器可被操控或本身无效，方法可能归因于投机取巧的 harness，而非真实能力提升。
  - **依赖反复的基准测试评分**：每个候选都需要重新评分，成本高，限制了在无评分器、稀疏反馈或开放式场景中的适用性。
- **目标短视**：优化的是每个任务的成功率，而非长期鲁棒性、可维护性、有用性或创新性等模糊目标。
- **实验覆盖限制**：
  - 仅与 vanilla 基线比较，未与竞争方法（如 Self-Harness, HarnessFix, AHE, Meta-Harness, HarnessX）在相同设定下进行端到端定量对比，削弱了相对优势的说服力。
  - SWE-bench 因 held-out 样本量小（26个）未达显著性，限制了在复杂仓库级任务上的结论强度。
  - 跨模型实验仅在一个领域（AppWorld）上进行，对其他领域是否同样存在匹配律未验证。
- **模型条件性**：方法对中端能力的模型（如 27B）效果最好，对前沿模型（失败少）的头空间有限。论文承认此限制。
- **缺乏单调性保证**：算法不保证每一轮均单调提升，而是依赖父代保持和重试机制；进化终止依赖于训练集上的持续无改进，但训练集上的无改进不一定意味测试集无潜力。
- **标签噪声容忍度**：why 由 LLM 分配，可能有噪声；虽然论文声称其只引导探索，不决定可信归因，但错误诊断可能导致低效搜索，增加成本。
