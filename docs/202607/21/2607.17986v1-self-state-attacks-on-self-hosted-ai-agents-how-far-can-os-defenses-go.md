## 摘要
自托管AI智能体通过读写自身的内存和配置文件来运行。智能体可能因其自身状态被破坏而受损——这种破坏是通过合法的操作系统系统调用实现的。我们将此类威胁称为自状态攻击。在本文中，我们研究了操作系统对此类攻击的恢复能力。形式上，我们描述了一个四轴攻击空间（目标、机制、粒度、时间）；探讨了预防、检测和恢复的结构性限制；并引入了一种工作负载条件下的可检测性视图。为了实例化该框架，我们从一个运行在不同工作负载画像下的代表性自托管智能体中收集实时活动轨迹，并将攻击空间实现为一个23个单元格的矩阵，对真实自状态文件执行43种具体操作，并将其注入这些轨迹中。然后我们评估了标准和工作负载条件下的防御策略。实证结果表明，分层防御堆栈（在指令和配置层进行访问控制预防，在内存层进行工作负载条件下的检测，以及定期备份用于恢复）对大多数攻击单元格有效，而一小部分残留攻击面在操作系统层面上结构上难以区分。这些发现表明，针对新建立的自状态攻击类别，操作系统层面的防御需要重新考虑，可能为该领域开辟新的研究方向。

## Abstract
Self-hosted AI agents read and write their own memory and configuration files to function. An agent may get compromised via corruption of its own state -- a compromise realized via legitimate OS system call invocation. We refer to this class of threats as self-state attacks. In this paper, we investigate the OS resilience to this class of attacks. Formally, we characterize a four-axis attack space (Target, Mechanism, Granularity, Temporal); investigate the structural limits of prevention, detection, and recovery; and introduce a workload-conditioned view of detectability. To instantiate the framework, we collect live activity traces from a representative self-hosted agent running across distinct workload profiles, and realize the attack space as a 23-cell matrix, 43 concrete operations on real self-state files, and injected into those traces. We then evaluate both canonical and workload-conditioned defense strategies. The empirical results show that a layered defense stack (access-control prevention on the instruction and configuration layers, workload-conditioned detection on the memory layer, and periodic backup for recovery) is effective on most attack cells while a small residual attack surface remains structurally indistinguishable at the OS level. These findings suggest that against the newly established class of self-state attacks, OS-level defense needs to be reconsidered, potentially opening new research directions in the field.

- **研究动机**：随着大型语言模型（LLM）赋能的AI智能体从云端托管转向本地自托管（如Claude Code、OpenClaw），它们需要持续读写自身状态文件（内存、指令、配置）以保持记忆和适应场景。这种“自修改”能力虽然带来了灵活性，却也引入了一类新型安全威胁——**自状态攻击（Self-State Attacks）**：攻击者通过间接提示注入等技术，诱使已受损的智能体利用其自身合法的操作系统权限和系统调用，篡改自身状态文件（如添加恶意记忆、修改配置阈值、删除关键指令）。这种攻击与经典“困惑代理问题”类似，但更难防御，因为合法写操作与恶意写操作在操作系统（OS）层面产生完全相同的文件系统事件（如`write`、`unlink`），无法通过传统的访问控制机制区分。

- **核心问题**：操作系统防御（预防、检测、恢复）对自状态攻击到底能起到多大作用？是否存在结构性的局限性？哪些攻击面是OS层面无论如何也无法封闭的？

- **整体含义**：论文首次系统化分析OS防御在自状态攻击面前的极限，揭示出即使采用分层防御（预防+检测+恢复），仍有一小部分攻击（约4/23个细胞）在OS层面结构上不可区分，必须依赖更高层（语义层）的防护。这为AI代理安全领域指明了新的研究方向。

### 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：将自状态攻击抽象为一个四轴攻击空间（Target, Mechanism, Granularity, Temporal），每个攻击实例对应一个⟨目标文件路径, 事件类型, 字节偏移, 权限变化, 事件间隔⟩的特征元组，这正是OS级监控（如inotify）能观测到的全部信号。然后从理论上分析OS三种防御维度的结构性限制，并引入“工作负载条件异常检测”来部分缓解检测局限。

- **关键技术细节**：
    1. **四轴攻击空间**：
        - **D1 目标 (Target)**：指令层（Instruction）、内存层（Memory）、配置层（Config）。
        - **D2 机制 (Mechanism)**：修改（Modify）、添加（Add）、删除（Delete）、拒绝访问（Deny，即改权限）。
        - **D3 粒度 (Granularity)**：整文件（G1）、大增量（G2）、小增量（G3）、最小增量≤4字节（G4）。
        - **D4 时间模式 (Temporal)**：单次、突发对齐、安静间隙、缓慢滴落。
    2. **23个单元格的规范攻击矩阵**：基于上述四轴（部分组合因逻辑排除），形成23个Target×Mechanism×Granularity单元格，每个单元格对应1~3个具体目标文件，共43个攻击实例。
    3. **结构限制分析**：
        - **预防限制**：因为攻击操作集是合法操作集的子集（A(R) ⊆ L(R)），OS访问控制无法在写同一文件时区分恶意与合法。
        - **检测限制**：特征元组只记录操作元数据，不含内容，一次写事件无法判断写入内容是否恶意。
        - **恢复限制**：需要检测作为前提，且无法确定何时开始受污染，滚回可能丢失数据。
    4. **工作负载条件检测**：不同工作负载下合法写操作的分布不同，因此可以为每个负载剖面学习基线，标记偏离基线的事件。将检测分为三类：可见（V，TPR≥0.8）、条件依赖（C，0.5≤TPR<0.8）、不可区分（I，TPR<0.5）。
    5. **检测器设计**：使用基于z-score的统计异常检测器B2（工作负载条件版本），评分函数为`score(e) = max( |δs-μs|/σs, |logΔt-μt|/σt )`，阈值为2.0。对比两种基线：B0（基于哈希的FIM）和B1（全局统计异常检测）。

### 6. 论文的主要结论与发现

- **预防**：通过L3级别（锁定指令和配置层）可在几乎没有功能损失下阻挡大部分自状态攻击（保护率0.61，功能0.70）。但内存层的合法写操作无法被预防，必须依赖检测。
- **检测**：工作负载条件检测（B2）比全局盲检测（B1）更准确：B2下23个细胞分为11V、8C、4I；B1下为13V、4C、6I。B2将两个小配置编辑从I提升到C，但同时也暴露了B1掩盖的两个内存大增量攻击（从V降至C）。**4个I类细胞全部位于内存层**，因为它们的特征元组落在运维剖面（W3）合法的内存写分布内。
- **恢复**：在检测触发的情况下，恢复能100%补救V/C/I类攻击，数据丢失与备份间隔正相关（约14%~15%事件丢失）。唯一结构性失败是攻击针对备份存储本身。
- **分层防御最终效果**：推荐配置（L3预防 + B2检测 + 15事件备份间隔）下，每个剖面的封闭率：W1 20/23，W2 21/23，W3 17/23，W4 18/23。**4个I类细胞在所有剖面上均不可被OS层防御封闭**，主要涉及内存层的小修改和最小附加操作（例如翻转布尔值、追加短写等）。
- **核心洞察**：OS防御在自状态攻击面前具有**结构性不可区分性**：当攻击操作与合法操作在特征空间完全重叠时，没有任何OS层面的机制能检测。这要求更高的语义层防护（如LLM作为法官、信息流控制）补充。

### 7. 优点

- **系统性与形式化**：首次为自状态攻击提供形式化定义和四轴攻击空间，为后续研究奠定结构基础。
- **理论与实践结合**：从VFS特征元组推导理论限制（预防、检测、恢复），并通过详实实验验证，确认边界。
- **引入工作负载条件检测**：认识到单一全局统计基线不适用于多样化部署，提出剖面专用基线，显著改善检测（但未消除I类）。
- **实验架构可复现性高**：开源了完整平台（OpenClaw-core、攻击脚本、任务语料、驱动器），一键复现所有结果，便于社区验证和扩展。
- **客观展示局限**：不夸大OS防御能力，明确标识4个I类细胞及原因，并指出其需要上层防御。

### 8. 不足与局限

- **工作负载代表性有限**：仅四种剖面，且均为常规代理任务，未涵盖恶意环境或极端多样化场景。不同模型（如GPT-4、Claude）的写分布可能不同，但论文认为V/C/I逻辑依赖特征分布而非模型，仍需验证。
- **检测器特征简单**：仅使用(|δs|, Δt)两个特征，未利用轨迹级统计（如多事件模式）。作者在附录中承认可扩展至滑动窗口轨迹评分，可能回收部分I类。
- **未考虑语义层防御**：论文只评估OS层，未与AgentSpec、GuardAgent等语义层方法对比，也没有讨论组合防御。这是有意为之（聚焦OS极限），但读者可能希望了解跨层协同效果。
- **时间模式覆盖不全**：虽考虑了T1-T4中的三种（T4慢滴注被排除），但未实验T4（因为单个事件已低于阈值），也无法在OS层检测累积效应。
