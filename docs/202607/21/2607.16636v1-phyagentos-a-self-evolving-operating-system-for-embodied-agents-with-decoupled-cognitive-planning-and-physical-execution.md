## 摘要
视觉-语言-动作模型、世界模型和智能体规划器各自推进了物理智能，但在异构具身体上，它们的组合缺乏共同的执行抽象、共享状态、语义验证和持久经验。我们提出了PhyAgentOS，一个提供调度、验证、记忆、基准测试和安全性作为系统级服务的运行时基础。其会话中心运行时将会话（而非动作）作为调度、兼容性预检、监督执行、证据收集和接受的最小单元。为了将认知与物理执行解耦，认知-物理边界是一个文件系统：状态即文件协议将跨层状态具体化为带有YAML的Markdown，产生可检查、可版本化的记录，而无需在智能体和运行时层之间产生代码依赖。这些视图形成了一个统一的认知状态空间，协调意图、能力、环境、执行和经验。会话验证器通过基于证据的成功、失败或重新规划的判定，区分执行终止与语义任务完成。验证后的结果通过认知记忆整合为可重用知识和纠正经验，无需重新训练即可闭合试错循环。基准测试复用部署会话和验证路径，因此结果可追溯到真实执行。分层安全性约束了策略驱动和智能体驱动的执行：预检、动作桥接、安全守卫、心跳监控和目标局部约束。验证是逐步进行的：游戏测试认知规划，模拟增加动力学和控制，真实机器人增加硬件噪声，而认知层保持不变。PhyAgentOS在Optimus-67、StarDojo和DST-Dojo上进行了基准测试，在19个以上的模拟和物理具身上进行了验证，并在多个VLA模型上在LIBERO、Calvin和RoboCasa365上取得了提升。

## Abstract
Vision-language-action models, world models, and agentic planners each advance physical intelligence, yet their composition lacks a common execution abstraction, shared state, semantic verification, and persistent experience across heterogeneous embodiments. We present PhyAgentOS, a runtime foundation delivering scheduling, verification, memory, benchmarking, and safety as system-level services. Its Session-Centered Runtime treats a session, not an action, as the minimum unit of scheduling, compatibility preflight, supervised execution, evidence collection, and acceptance. To decouple cognition from physical execution, the cognition-physics boundary is a file system: the State-as-a-File protocol materializes cross-layer state as Markdown with YAML, yielding inspectable, versionable records without code dependencies between Agent and Runtime layers. These views form a unified cognitive state space aligning intent, capabilities, environment, execution, and experience. The SessionVerifier distinguishes execution termination from semantic task completion via evidence-grounded verdicts of success, failure, or replan. Verified outcomes are consolidated through epistemic memory into reusable knowledge and corrective lessons, closing a trial-and-error loop without retraining. Benchmarking reuses the deployment session and verification path, so results trace to real execution. Layered safety constrains both policy-driven and agent-driven execution: preflight, action bridges, SafetyGuard, heartbeat monitoring, and target-local constraints. Validation is progressive: games test cognitive planning, simulation adds dynamics and control, real robots add hardware noise, with the cognitive layer held constant. PhyAgentOS is benchmarked on Optimus-67, StarDojo, and DST-Dojo, validated on 19+ simulated and physical embodiments, and gains on LIBERO, Calvin, and RoboCasa365 across multiple VLA models.

## 1. 核心问题与整体含义（研究动机与背景）

现有具身AI系统（视觉-语言-动作模型、世界模型、智能体规划器）各自在感知-动作映射、未来预测和高层推理上有所突破，但它们组合时存在三个结构性缺陷：
- **缺乏统一执行抽象**：各层使用异构表示（像素、潜在状态、符号工具），无法共享状态；
- **无语义验证**：执行终止被误认为任务完成，但实际环境状态可能未达预期；
- **无持久记忆**：一次会话中学到的经验在会话结束时丢失，无法实现持续改进。

根本原因在于缺少一个跨层的**操作系统**来提供调度、验证、记忆和安全性等系统级服务。现有的ROS仅提供通信中间件，不具备这些功能。PhyAgentOS正是为解决这一缺口而设计。

## 2. 方法论：核心思想与关键技术细节

### 核心思想
- **认知-物理解耦**：将高层认知规划与底层物理执行分离，通过**文件协议**（State-as-a-File）作为边界。所有跨层数据（目标、技能、会话、观察、教训、知识）都以人类可读的Markdown+YAML格式存储，无需代码依赖。
- **会话为中心运行时**：以**会话**（session）为最小调度、预检、执行和验证单元，而非单个动作。
- **自我进化**：通过验证结果整合到经验记忆（LESSONS.md、KNOWLEDGE.md），实现跨会话的闭合试错循环，无需重训神经网络。

### 关键技术细节
1. **Session-Centered Runtime**：
   - **WatchdogSupervisor**：负责会话调度、预检（兼容性检查）、心跳监控、超时处理结果写回。
   - **SessionRunner**：协调具体执行流程，观测-推理-动作循环。
   - **两种执行流**：PolicySkillRuntime（连续控制策略，如VLA）和BuiltinSkillRuntime（智能体直接调用工具）。
2. **State-as-a-File协议**：
   - 五个核心文档：SESSIONS.md（会话事务）、SKILLRUNTIME.md（执行方法）、TARGETS.md（执行目标）、ENVIRONMENT.md（环境感知）、LESSONS.md（经验记录）。
   - 配合YAML配置文件（sensors.yaml, perception.yaml, runtime_contract.yaml, safety.yaml）。
3. **SessionVerifier**：
   - 将执行终止与语义接受分离，输出 success / failure / replan 三种判定。
   - 利用初始状态、终止状态、执行轨迹和历史经验进行基于证据的判断。
4. **Epistemic Memory（认知记忆）**：
   - 三级抽象：情节级（单个会话）、语义级（跨会话规律）、方法级（可重用技能）。
   - KNOWLEDGE.md 存储成功模式，LESSONS.md 存储失败教训，通过情境检索注入新会话。
5. **分层安全架构**：
   - 兼容性预检 → 动作桥（坐标变换、限幅）→ SafetyGuard（NaN检查、关节/工作空间限制）→ 心跳监控 → 目标本地约束。
6. **渐进验证范式**：
   - 游戏环境（消除物理噪声，测试纯认知）→ 模拟（加入刚体动力学、延迟）→ 真实机器人（硬件噪声、传感器不确定性），认知层保持不变。

## 6. 主要结论与发现

1. **认知-物理解耦可行**：通过文件协议可以将高层智能与底层执行完全分离，Agent不接触硬件，Runtime独立执行会话。
2. **会话验证器可区分执行结束与任务完成**：避免“执行成功但任务未完成”的系统性自欺。
3. **经验记忆带来持续改进**：在游戏环境中，失效模式减少（如Don't Starve黑暗致死率降低），长时任务成功率提升（Optimus-67 RedStone组达到30%）。
4. **模拟和真实机器人上的通用增益**：在所有模拟基准上，PhyAgentOS均能提升最终成功率（在RoboCasa365上整体提升7.2~9.2个百分点），并且零样本迁移到多种真实机器人平台。
5. **分层安全有效**：预检拒绝了不兼容配置，SafetyGuard拦截了所有违规动作，急停延迟在安全范围内。
6. **渐进验证范式成功**：认知策略先通过游戏验证，再在有物理动力学的模拟中验证，最后部署到真实机器人，认知层不变，证明了可移植性。

## 7. 优点（方法/实验设计亮点）

- **创新性文件协议**：将跨层状态用Markdown+YAML具体化，自然具备可检查性、版本控制和语言无关性，无需内通信设施。
- **会话为中心的设计**：以会话为最小单元，使预检、执行、验证、记录都可以在完整生命周期内统一处理，简化了故障隔离。
- **证据驱动的语义验证**：SessionVerifier基于初始状态、终止状态、轨迹和历史进行判断，而非简单返回值，更接近真实任务完成度。
- **闭合试错循环**：验证结果自动进入经验记忆，未来会话可检索，形成持续进化，无需重训模型——这是与多数现存系统最大的区别。
- **分层安全架构**：从预检到目标本地约束，每一层独立失效保护，避免单点故障。
- **渐进验证实验设计**：逐步引入物理复杂性，确保认知层可独立测试，结果可追溯至具体层。
- **广泛的跨具身验证**：19+平台覆盖工业臂、桌面臂、双足、四足等，展示了架构的泛化能力。

## 8. 不足与局限

1. **轮询协议引入延迟**：当前文件协议基于轮询（Watchdog定期读取SESSIONS.md），导致调度延迟与轮询间隔成正比。事件驱动方案可降低延迟，但需保证原子写语义。
2. **经验记忆无压缩边界**：LESSONS.md和KNOWLEDGE.md随会话数单调增长，检索选择策略（任务类型匹配+近期加权）缺乏理论最优性保证，且技能推广质量依赖人工设定阈值。
3. **真实机器人评估覆盖有限**：实验集中于安全特性（预检、SafetyGuard、急停）和零样本迁移演示，未开展大规模任务完成率统计（如模拟中的数百次试次）。这受限于硬件可用性和物理风险，但理论上架构支持更大规模评估。
4. **Goal Graph与Session Compiler未完全实现**：架构中提到的DAG级任务分解与跨会话依赖跟踪尚未落地，限制了多机器人和复杂长时任务的协调能力。

6. **未报告算力需求**：论文未提供GPU型号、数量、训练时长等资源信息，难以评估可复现性和实际部署成本。
